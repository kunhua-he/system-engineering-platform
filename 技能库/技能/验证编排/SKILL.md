# 验证编排

把一次验证做完整：**反馈门禁 → 命令白名单校验 → 受控执行验证命令 → 统一判定 → 通过才记账 → 唯一发布命令再要发布证据**。
本技能负责「编排 + 准入 + 判定 + 记账」，命令的真实执行由调用方经**底座原子能力**完成
（受控执行沙箱的 AST 审计禁止技能脚本 `subprocess` / `os` 命令执行，技能脚本不能自己起进程）。

## 什么时候用它

- 要跑一次**受控验证命令**并留下可复用证据：开发期精确 unittest 模块（`python3.14 -m 测试中心.<模块>`）、
  HTML 黑盒（`python3.14 -m 开发工具.HTML验证.验证器 --制品 <根内相对目录> --并发 N`）、
  唯一发布入口（`python3.14 开发工具/发布门禁/运行发布门禁.py`）。
- 需要「无 MCP 反馈不记账」的强门禁：开工id 没有使用反馈记录时直接 `未反馈阻断`。
- 需要「零测试 / 收集错误 / 未解释跳过」不被当成通过：退出码 0 不等于验证通过。

## 六步（固定顺序，不跳步）

| 步 | 做什么 | 谁做 |
|---|---|---|
| ① 反馈门禁 | 按 开工id 查 MCP 使用反馈 jsonl；没有记录 → `未反馈阻断`，后面全不做 | 技能脚本 |
| ② 命令白名单校验 | 只放行三形态命令；禁 shell 元字符、绝对路径、`..`、非法并发、根外制品 —— **口径调底座能力 `测试支持库.验证命令白名单`**（本技能不再自持副本） | 技能脚本调能力 |
| ③ 受控执行验证命令 | 经 `系统核心支持库.进程管理.沙箱执行命令`（或 `执行命令`）执行，取回 退出码/标准输出/标准错误 | **调用方** |
| ④ 统一判定 | 退出码 → 收集错误 → 零测试（精确 unittest 模块还必须有真实执行证据）→ 未解释跳过 → 缓存假绿/导入失败当跳过 —— **口径调底座能力 `测试支持库.验证结果判定`**；命令==唯一发布命令时再加判末行 `发布状态: 通过`（MCP 会话约定，留在技能侧） | 技能脚本调能力 |
| ⑤ 通过才记账 | 判定通过且给了 `账本路径` 才追加账本记录；未通过只回判定与阻断原因，不落账 | 技能脚本 |
| ⑥ 发布证据分支 | 判定通过且命令==唯一发布命令 → 返回发布证据请求，由调用方交底座唯一发布证据写入方落账 | 技能脚本出请求，调用方落账 |

## 口径来源（一处口径，本技能不复刻）

白名单形态与判定链**只在 `支持库/后端/测试支持库`** 维护：本技能脚本经平台注入的合成模块
`技能底座能力` 走唯一网关调这两条原子能力，脚本内不再有同名正则、常量副本与判定分支。

- `测试支持库.验证命令白名单` → 本技能 `校验命令`（返回形状仍是 `{成功, 错误码, 消息}`，由能力的 `允许/错误码/消息` 装配）
- `测试支持库.验证结果判定` → 本技能 `判定验证结果`（由能力的 `判定/阻断码/理由/检出/真实执行证据` 装配；
  能力的 `阻断码` 就是本技能返回里的 `错误码`，如 `命令拒绝` / `零测试` / `未解释跳过` / `缓存假绿` / `导入失败当跳过`）
- `测试支持库.验证计划` 本技能不调：本技能不生成验证计划（计划由调用方按目标范围按需调该能力）

## 调用约束（必须由调用方满足）

调用 `技能库.受控执行.运行技能包` 时**必须传 `可调能力白名单`**：

```text
可调能力白名单 = ["测试支持库.验证命令白名单", "测试支持库.验证结果判定"]
```

- 不传（或传空）：脚本 `from 技能底座能力 import 调用底座能力` 被沙箱 AST 审计拦 → 运行级 `脚本审计未通过`，失败在入口，不会静默降级。
- 传了但缺项：缺的那条能力在脚本内层被拒为 `能力不在白名单`，判定字段回 `{成功: false, 错误码: 能力不在白名单, 消息: ...}`。
- 网关凭证由平台注入子进程环境（`系统库网关凭证`），技能脚本不读、不写、不回传凭证。

## 参数

- `名称`（文本型，必填）：本次验证的名称，写进账本
- `命令`（列表型，必填）：验证命令数组；只允许底座唯一白名单三形态（精确 unittest 模块 / HTML 黑盒验证器 / 唯一发布入口）
- `退出码`（整数型，必填）：验证命令真实执行后的退出码（由调用方经底座能力执行后回传）
- `项目根目录`（文本型，必填）：白名单实存校验与相对路径解析的根（绝对路径）
- `开工id`（文本型，必填）：开工标识；必须已有 MCP 使用反馈记录才允许记账
- `标准输出`（文本型，选填）：验证命令真实执行后的标准输出（判定零测试/收集错误/未解释跳过的证据）
- `标准错误`（文本型，选填）：验证命令真实执行后的标准错误
- `反馈路径`（文本型，选填）：MCP 使用反馈 jsonl 路径（空=项目根目录/开发文档/项目证据/MCP使用反馈.jsonl；相对路径按项目根目录解析）
- `账本路径`（文本型，选填）：验证账本 jsonl 路径（空=判定通过也只回记录不落盘；相对路径按项目根目录解析）
- `超时秒数`（整数型，选填）：执行验证命令时的超时上限（只记账，执行由调用方做）
- `指纹参数`（字典型，选填）：账本指纹补充：{提交, 工作区指纹, 指纹}；留空则三项为空串（技能脚本不起进程，git 指纹由调用方给）
- `发布参数`（字典型，选填）：唯一发布命令时组装发布证据请求：{提交, 工作区指纹, 制品摘要, 来源指纹, 能力覆盖, 场景覆盖, 真实结果}
- `记账时间`（文本型，选填）：账本时间戳（留空=取当前 UTC 时间；填写值原样入账，用于确定性验证用例）

## 返回形状

```text
值 = {
  技能标识, 名称, 命令,
  阻断, 阻断原因,                    # 门禁/白名单/判定任一未通过即 阻断=true
  门禁:   {成功, 错误码, 消息},
  白名单: {成功, 错误码, 消息},
  判定:   {成功, 错误码, 消息},
  账本:   {已落盘, 路径},
  账本记录: {...} | null,             # 仅判定通过时是对象（含 判定/输出末尾/错误末尾/指纹）
  发布证据: {需要, 唯一发布命令, 请求, 说明}
}
```

## 用法

调用 `技能库.受控执行.运行技能包`，`技能根目录` 传本技能所在根目录，
`能力标识` 传 `技能.验证编排`，参数放在 `参数` 里，**并传 `可调能力白名单`**（见上节）。

```text
① 调用方经底座能力执行白名单命令 → 退出码/标准输出/标准错误
② 运行本技能包（技能.验证编排，可调能力白名单=测试支持库两条判定能力）
   → 门禁 + 白名单(调能力) + 判定(调能力) + 记账
③ 需要时把 发布证据.请求 交底座唯一发布证据写入方
```

## 验证用例

- 正向：精确 unittest 模块 + 已反馈开工id + 退出码 0 + 「Ran 7 tests」→ 门禁/白名单/判定全通过，账本落盘并回记录
- 负向：非白名单命令（`bash -c ls`）→ `命令拒绝` 阻断，不判定、不记账
- 负向：开工id 无 MCP 使用反馈记录 → `未反馈阻断`，连白名单都不进入

三条用例的 `预期` 与真实受控执行返回**逐键一致**（见 `验证声明.json`）。
