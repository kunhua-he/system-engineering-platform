# 交付收尾 改造记录：技能脚本绕网关直连底座库（I-4）

**日期**：2026-09-19 ｜ **技能版本**：1.0.0 → 1.1.0 ｜ **类型**：修缺陷

## 症状与判据

原 `scripts/交付收尾.py` 自己开库改表，绕过唯一网关：

```
:21   import sqlite3
:53   运行库相对 = Path("工程缓存") / "运行数据" / "底座运行.db"
:54   控制面库相对 = Path("工程缓存") / "平台控制面" / "权威状态.db"
:148  连接 = sqlite3.connect(str(库路径), timeout=超时秒)
:161  SELECT * FROM 协作状态 WHERE id = ? OR work_id = ?
:215  UPDATE 协作状态 SET 生命周期 = ?, 收口结论 = ?, 状态 = ?, 更新时间 = ?, 载荷 = ?
:234  SELECT 租约id FROM 占用租约 WHERE 状态 = ? AND 领域 = ? AND {匹配列} = ?
:242  UPDATE 占用租约 SET 状态 = ?, 释放证据 = ? WHERE 租约id = ? AND 状态 = ?
:271  INSERT INTO 能力占用 (...) ON CONFLICT(id) DO UPDATE SET ...
```

**撞条款**：平台第 7.4 条（只允许走 `调用能力(能力id, 参数)`）、第 7.8 条（上层一律经 HTTP 请求
底座执行）、第 8.2 条（能力唯一权威杜绝旁路）。

**根因（不是「为了性能」）**：把受控执行的**沙箱约束**当成了**架构许可**。脚本头注释自述
「只依赖标准库（受控执行 AST 审计只放行标准库）」——AST 审计放行 `sqlite3` 只说明「这条导入不会被
沙箱拦」，不等于「这样调库合规」。而 `技能库/后端/技能库/说明/设计说明.md` 第 77-94 行早写明
「**可调能力白名单（技能脚本唯一的底座能力调用腿）**…技能脚本默认只能纯标准库」：
平台给技能脚本开的唯一底座能力腿是合成模块 `技能底座能力`，不是 `sqlite3`。

**具体代价**：网关视野外（网关看不到是谁释放的租约、无证据账本条目）；租约释放口径
（幂等清单/释放原因/改动流水）与库表结构（列名/迁移序列表）各存在第二份实现，改一处必漂移。

## 修法与依据

**选 ①：改走网关**（非「有意设计」——见下「为什么不选 ②」）。四条已注册能力，全部实测存在：

| 动作 | 经唯一网关调的能力 | 依据 |
| --- | --- | --- |
| 读协作状态 / 写终态 | `数据库连接支持库.SQLite数据库.查询运行态` / `写入运行态` | 契约 `域` 说明逐字含「协作状态、能力占用」；写入侧自身拦测试标识、自己管列白名单与事务 |
| 读占用租约 | `平台控制面.平台状态.查询记录`（表=`占用租约`） | 表名在 `读取记录` 契约的允许表清单里；条件片段走该能力的既有词法校验 |
| 释放租约 | `平台控制面.能力目录.释放文件租约` | 唯一释放口径：幂等 + 释放原因 + 改动流水；按 `租约id` 在租约存储里找键，未找到回 `未找到且已幂等` |

`占用租约` 表列的**唯一写入方**仍是 `平台控制面.平台状态`（`查询记录` 只读）；
技能侧不再有 `UPDATE`/`INSERT`，也不再知道表结构。

### 为什么不选 ②（不是有意设计）

- `技能库/后端/技能库/说明/设计说明.md` **明文**规定技能脚本的唯一底座能力腿是白名单合成模块，
  直连库不在任何「允许」清单里；
- 原脚本落在**默认档**（`可调能力白名单` 空 = 只能纯标准库），直连库是事实上的越权，
  不是被设计允许的档位；
- 审计件 I-4 与 `开发文档/方案/跨平台部署与审计维修方案_20260919.md:修-4c` 均已把它当缺陷登记。

## 现场实测（真实退出码与输出）

**正向用例**（经 40007 真实调用，夹具隔离）：

```
POST /网关/调用  操作=调用能力  能力id=技能库.受控执行.运行技能包
  → 值.值.成功=true  权限等级=2（白名单能力：注入网关凭证与合成模块）
  → 文件租约: 释放数量=1（b2c10de0-文件-0001）
  → 能力占用: 租约id=[b2c10de0-能力-0001]  幂等清单=[未找到且已幂等]
夹具落库核对：
  文件租约 b2c10de0-文件-0001  所有者=b2c10de000000001 → 已释放（释放原因：收口：…）
  文件租约 b2c10de0-他人-文件  所有者=a1a1a1a1a1a1a1a1 → 活跃     ← 反向断言：别人的没被碰
  协作状态 b2c10de000000001 → 生命周期=完成 / 状态=完成 / 收口结论=…
  能力占用 文件系统支持库.文本读取.读取文本 → 已释放
```

**门禁用例**（全部经网关真实跑，回执逐条）：

| 用例 | 开工id | 真实回执 |
| --- | --- | --- |
| 未反馈阻断 | b2c10de000000002 | `错误码=未反馈阻断`，`阻断标记=[未反馈]` |
| 证据不匹配 | b2c10de000000003 | `错误码=证据不匹配`，`证据指纹=deadbeefdeadbeef` / `当前指纹=86e56ebdf6776093` |
| 未登记 | b2c10de000000004 | `错误码=任务不存在`，`阻断标记=[未登记]` |
| 释放关闭 | b2c10de000000005 | `生命周期=完成`，`资源释放.跳过=释放资源=false，未释放占用租约` |
| 非法开工id | XYZ | `错误码=开工id无效` |

**反向验证（白名单缺项）**：只传两条白名单（缺 `查询记录` 与 `释放文件租约`）

```
资源释放.成功=false
文件租约: {"跳过": "读取失败，未释放"}
能力占用: {"跳过": "读取失败，未释放"}
错误说明: 占用租约读取失败：能力不在白名单（能力 平台控制面.平台状态.查询记录 不在本次可调能力白名单内…）
```

旧直连形态**不会**产生这个错误（它读表不经过网关）。这条反验证明技能侧**真的只剩网关这一条腿**：
把网关腿拆掉，动作就失败，不回落到任何旁路。

## 能力面缺口（如实登记，未自造）

`占用租约` 表里 **`领域='能力'`** 的租约**没有按能力id 的申请/释放注册能力**：
`平台控制面.能力目录` `能力定义.json` 只注册了文件租约一族（申请/续租/释放/回收过期/查询/留言）。
能力占用租约的申请与释放只有同层 `能力目录/服务.py` 的类方法（`申请占用` / `释放占用`），未开能力。

按平台 7.7 条「能力不足就补底座，不许收窄约束」，正解是**补能力**；本技能**不自造第二执行腿**，
只做能力面允许的两件事：经 `查询记录` 只读取清单、把租约id 交给 `释放文件租约`（按 id 找键，
未命中即幂等），并在回执 `资源释放.能力面缺口` 逐次如实回带。

> 补齐能力占用租约的申请/释放能力属**底座能力面任务**，不在本次允许修改目录内，登记待排。
