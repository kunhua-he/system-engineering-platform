# 交付收尾

工作包收口的多步工作流（原 MCP 工具 `delivery_closeout` 的语义落点）：
先校验入参，再读协作状态，**反馈门禁 → 验证证据指纹校验** 两道门禁都通过后**才**写终态，
最后释放该开工id 持有的全部占用租约（文件 + 能力）。全程 fail-closed：未反馈、证据指纹不匹配、
未登记一律阻断，**不写终态、不释放资源**。

## 调用腿（唯一，2026-09-19 从「直连库」改为「经唯一网关」）

技能脚本**不自开数据库、不 import 任何项目模块/支持库实现、不拼 SQL**：全部动作经平台注入的
合成模块 `技能底座能力` 走唯一网关 `POST http://127.0.0.1:40007/网关/调用`（操作=调用能力）。

调用方**必须传 `可调能力白名单`**（四条，缺一即内层 `能力不在白名单`，fail-closed，不降级）：

```text
可调能力白名单 = ["数据库连接支持库.SQLite数据库.查询运行态",
                  "数据库连接支持库.SQLite数据库.写入运行态",
                  "平台控制面.平台状态.查询记录",
                  "平台控制面.能力目录.释放文件租约"]
```

原形态（`import sqlite3` 自己 `sqlite3.connect()` 直改 `协作状态`/`占用租约`/`能力占用` 三张表）
撞平台 7.4 / 7.8 / 8.2 条，已按 `技能库/后端/技能库/说明/设计说明.md` 的「可调能力白名单
（技能脚本唯一的底座能力调用腿）」收口；详见本目录 `说明/改造记录.md`。

## 参数

- `开工id`（文本型，必填）：16 位十六进制开工id（协作状态主键 `work_id`）
- `五件套路径`（文本型，必填）：交付证据/五件套路径，原样写入收口记录
- `结论`（文本型，必填）：收口结论，原样写入收口记录
- `项目根目录`（文本型，选填）：输入路径解析根与证据指纹计算根；默认当前工作目录
- `反馈文件`（文本型，选填）：MCP 反馈 JSONL 路径；默认 `<项目根>/开发文档/项目证据/MCP使用反馈.jsonl`
- `验证历史文件`（文本型，选填）：验证证据 JSONL 路径；默认 `<项目根>/开发文档/项目证据/验证历史.jsonl`
- `释放资源`（逻辑型，选填）：是否在写终态后释放占用租约，默认 `true`
- `运行库路径` / `控制面库路径`（文本型，选填）：**隔离用**（技能验证夹具 / 临时库试跑）；
  不传即由底座能力按平台唯一解析器定位到 `工程缓存/运行数据/底座运行.db` 与
  `工程缓存/平台控制面/权威状态.db`。**生产调用不传**——库位置是平台事实，不是调用方可配项。

相对路径按 `项目根目录`（缺省为当前工作目录）解析。

## 用法

调用 `技能库.受控执行.运行技能包`，`技能根目录` 传本技能所在根目录（`技能库/技能`），
`能力标识` 传 `技能.交付收尾`，参数放在 `参数` 里，**并传 `可调能力白名单`**。典型生产调用：

```json
{"技能根目录": "<项目根>/技能库/技能", "能力标识": "技能.交付收尾",
 "可调能力白名单": ["数据库连接支持库.SQLite数据库.查询运行态",
                    "数据库连接支持库.SQLite数据库.写入运行态",
                    "平台控制面.平台状态.查询记录",
                    "平台控制面.能力目录.释放文件租约"],
 "参数": {"开工id": "e41a3a15531c467e", "五件套路径": "<项目根>/开发文档/交付记录/<批次>",
         "结论": "<一句话收口结论>", "项目根目录": "<项目根>"}}
```

返回（脚本 stdout，经沙箱后位于 `值.值`；沙箱外层 `成功` 恒为 true，**看 `值.值.成功`**）：

```json
{"成功": true, "值": {"技能标识": "技能.交付收尾", "开工id": "...", "生命周期": "完成",
  "五件套路径": "...", "收口结论": "...", "代码指纹": "16 位摘要", "反馈门禁": "通过",
  "证据指纹": "匹配", "证据条数": 1, "收口时间": 1789469459.17,
  "资源释放": {"成功": true,
    "文件租约": {"成功": true, "释放数量": 1, "租约id": ["..."], "幂等清单": []},
    "能力占用": {"成功": true, "释放数量": 0, "租约id": ["..."],
               "幂等清单": [{"租约id": "...", "结果": "未找到且已幂等"}]},
    "能力面缺口": "能力占用租约的申请与释放尚无按能力id 的注册能力…"}}}
```

阻断/失败回执：脚本 stdout 为 `{"成功": false, "错误码": "...", "错误说明": "...", "阻断标记": [...]}`。

**受控执行（`运行技能包`）把脚本回执摊平后放进 `值`，且强制把外层 `成功` 置为 `true`**（实测 2026-09-15）：

```json
{"错误码": "未反馈阻断", "错误说明": "未提交 MCP 反馈，阻断收口",
 "开工id": "b2c10de000000002", "阻断标记": ["未反馈"], "耗时秒": 0.035, "权限等级": 2}
```

即：**成功看 `值.值.成功`；失败看 `值.错误码`（此时 `值` 里没有 `值` 键）**。
调用方判定口径：`值` 里出现 `错误码` → 阻断，按 `阻断标记` 处理；否则读 `值.值`。

## 工作流（顺序不可换）

1. **校验入参**：`开工id` 必须 16 位十六进制，`五件套路径`/`结论` 非空 → 否则 `参数不合法` / `开工id无效`
2. **读协作状态**：经 `数据库连接支持库.SQLite数据库.查询运行态`（域=`协作状态`，条件 `work_id=开工id`）
   取记录（`载荷` JSON 还原清单字段）→ 未登记 `任务不存在`
3. **反馈门禁**：`MCP使用反馈.jsonl` 必须存在该开工id 记录 → 未反馈 `未反馈阻断`（不写终态）
4. **证据指纹校验**：取 `验证历史.jsonl` 该开工id 最后一条的 `指纹`（缺则回退 `工作区指纹`），
   与记录 `worktree路径` 的目录内容摘要比对 → 不一致 `证据不匹配`
5. **写终态**：经 `数据库连接支持库.SQLite数据库.写入运行态`（域=`协作状态`）写
   `生命周期=完成` + `五件套路径` + `收口结论` + `收口时间`，同一次写入回写全部真实列与 `载荷` JSON
   → 失败 `登记失败`
6. **释放资源**：先经 `平台控制面.平台状态.查询记录`（表=`占用租约`）只读取本开工id 的活跃租约
   （文件按 `所有者`、能力按 `任务`），再经 `平台控制面.能力目录.释放文件租约` 释放；
   能力租约释放后经 `写入运行态`（域=`能力占用`）同步账本终态
7. **回执**：stdout 打印 JSON 收口回执

顺序为什么不能换：门禁不通过就不写终态（否则「完成」是假的）；终态没落账就不释放资源
（否则租约放了、任务还挂在「创建」，无法追责）。

## 边界与落点（全部经唯一网关，技能侧零直连）

| 项 | 口径 |
| --- | --- |
| 调用腿 | **唯一**：合成模块 `技能底座能力.调用底座能力(能力id, 参数)` → 唯一网关 `POST /网关/调用` |
| 终态落点 | 底座运行库 `协作状态` 域（主键 `work_id`），经 `数据库连接支持库.SQLite数据库.写入运行态`（唯一 SQLite 写入口） |
| 释放落点 | 平台控制面权威状态库 `占用租约` 表（`状态='已释放'` + 释放原因），经 `平台控制面.能力目录.释放文件租约`（唯一释放口径：幂等、留证据、可立即重新申请） |
| 账本联动 | 能力租约终态经 `写入运行态`（域=`能力占用`）的正常写入方向；账本写失败只进 `资源释放.同步错误`，不改判定 |
| 指纹算法 | 目录内容 sha256 前 16 位，排除 `__pycache__`/`工程缓存`/`测试中心缓存`/`.git`/`完整性摘要.json`/`项目证据`/`临时文件` 路径段（与 `计算代码指纹` 同口径） |
| 依赖 | 标准库（`json/sys/re/hashlib/time/pathlib/datetime`）+ 注入模块 `技能底座能力`；`依赖.json` 的 `可调能力` 四条与脚本内常量逐字一致 |
| 不释放的情形 | `释放资源=false`（回执 `资源释放.跳过` 如实说明，不静默） |

## 已知能力面缺口（如实回报，不假装已释放）

`占用租约` 表里 **`领域='能力'`** 的租约**没有按能力id 的申请/释放注册能力**：
`平台控制面.能力目录` 只注册了「文件租约」一族（申请/续租/释放/回收过期/查询/留言）。
本技能**不自造第二执行腿**去改它，只做两件能力面允许的事：

1. 经 `查询记录`（表=`占用租约`）**只读**取本开工id 的能力租约清单（回执里 `能力占用.租约id`）；
2. 把租约id 一并交给 `释放文件租约`——该能力按 `租约id` 在**文件租约存储**里找键，
   未找到即回 `{结果: 未找到且已幂等}`，**不会误放别人的租约、也不报错**。

**能力占用租约的释放补齐属底座能力面任务**（平台 7.7 条：能力不足就补底座，不许收窄约束）。
补能力前，回执 `资源释放.能力面缺口` 逐次如实回带该缺口，调用方可见。

## 验证用例

参数里的夹具路径**相对技能根目录**（受控执行把工作目录设为技能根目录）；夹具在 `验证夹具/`。

- 正向：已登记 + 已反馈 + 证据指纹匹配 → 生命周期置完成，文件租约释放 1 条、账本标终态 1 条（b2c10de000000001）
- 未反馈 → `未反馈阻断`，不写终态（b2c10de000000002）
- 证据指纹不匹配 → `证据不匹配`，不写终态（b2c10de000000003）
- 未登记 → `任务不存在`（b2c10de000000004）
- `释放资源=false` → 写终态但不释放（b2c10de000000005）
- 非法开工id → `开工id无效`（XYZ）
- 白名单缺项 → 内层 `能力不在白名单`，`资源释放.成功=false` 且 `错误说明` 回带缺哪条（反向验证）

夹具说明：正向用例只动属于本开工id 的记录，**另一个所有者（a1a1a1a1a1a1a1a1）的活跃租约
必须保持「活跃」**（这是释放口径的反向断言）。正向用例跑过后终态已写入，重跑仍通过
（终态幂等，文件租约 `释放数量` 变 0、进 `幂等清单`）；如需还原夹具原始态，按同一布局重建
夹具库（DDL 从真实库 `sqlite_master` 取）、`文件租约.json` 与两份 JSONL 即可，
指纹源固定为 `验证夹具/工作区/已通过/交付物.md`。
