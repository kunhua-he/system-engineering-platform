## 这是什么

技能（Skill）是给 **Agent 消费**的可复用工作流能力包。它由五份声明文件加一个脚本目录组成：

```text
技能包/
  SKILL.md          Agent 读的提示词（YAML 头 + 说明）
  契约.json          参数契约（Agent 据此组参，执行器据此校验）
  工作流.json        流程步骤（只给执行器，不返回给 Agent）
  依赖.json          依赖的支持库能力清单
  验证声明.json      无副作用声明与验证方式
  scripts/入口.py    桥接脚本（stdin JSON 进，stdout JSON 出）
```

技能**不另开 HTTP 入口**，就是一条能力走底座唯一执行入口。

## 四个能力

| 能力 id | 用途 |
|---|---|
| `技能库.技能包.校验技能包` | 校验技能包六件套是否齐全（1-10） |
| `技能库.受控执行.运行技能包` | 受控执行技能脚本（1-9） |
| `技能库.技能索引.扫描技能包` | 扫描技能索引，列出全部技能与结构问题 |
| `技能库.技能索引.生成索引` | 扫描技能根目录，从各技能 `契约.json` 派生并（可选）写回 `索引.json` |

## 怎么调（HTTP）

统一走底座唯一执行入口：

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -H 'Authorization: <系统库网关凭证>' \
  -d '{"操作":"调用能力","能力id":"技能库.技能索引.扫描技能包",
       "参数":{"技能根目录":"/绝对路径/到/技能根目录"}}'
```

执行一个技能：

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -H 'Authorization: <系统库网关凭证>' \
  -d '{"操作":"调用能力","能力id":"技能库.受控执行.运行技能包",
       "参数":{"技能根目录":"/绝对路径/到/技能根目录",
               "能力标识":"_示范.纯文本统计",
               "参数":{"文本":"hello world"},
               "禁止导入前缀":["功能模块","后端服务"]}}'
```

## 为什么必须传「技能根目录」

技能库是**通用**的：它不认识任何具体项目。技能根目录（含 `索引.json` 的目录）由调用方传，
因此同一个能力既能执行 V3 的技能，也能执行别的项目的技能。
「禁止导入前缀」同理——项目级的禁入边界由调用方声明，底座内置的安全硬约束（绕过解释器、
shell 执行、动态加载、第三方库、路径逃逸、超时、输出上限、环境白名单）始终生效。

## 安全边界（全部 fail-closed）

| 边界 | 做法 |
|---|---|
| 解释器 | 固定为本进程解释器，调用方不能指定命令或解释器 |
| 参数传递 | 经 stdin JSON 进，stdout JSON 出 |
| 超时 | 超时后 `killpg` 连孙进程一并回收 |
| 输出 | stdout 超上限立即终止，返回 `输出超限` |
| 环境 | 只透传白名单变量；传白名单外变量直接拒绝 |
| 路径 | 技能目录、入口脚本、工作目录必须在技能根目录内 |
| 资源 | `RLIMIT_CPU` / `RLIMIT_FSIZE` |
| 导入审计 | AST 静态审计：禁 `shell=True`、`eval/exec/compile`、`__import__/importlib`、`subprocess/os` 命令执行、第三方库 |

## 可调能力白名单（技能脚本唯一的底座能力调用腿）

技能脚本**默认只能纯标准库**：脚本要用的外部结果由调用方执行完当参数传进去。当调用方确需
让脚本自己取底座数据时，`运行技能包` 接受可选参数 `可调能力白名单`（元素是能力 id）：

- **默认空 = 行为零变化**：不注入任何东西，导入审计仍是非标准库一律拦截，`禁止导入前缀`
  照常生效，第三方与进程派生一律不放。
- **非空时**：平台把一个合成模块（`技能底座能力`）写进临时目录、随子进程启动注入，
  并且**只对这一个模块名放行导入**（放行名单由平台生成，调用方无法扩面）。脚本经该模块的
  `调用底座能力(能力id, 参数)` 走**唯一网关** `POST /网关/调用`（操作=调用能力）真实调用
  白名单内的底座能力；白名单在注入时冻结进模块源码，**白名单外的能力 id 一律拒绝**
  （返回码 `能力不在白名单`），不改走别的通道、不静默降级。
- **凭证只经环境变量**：合成模块从环境变量读到网关凭证后才发起 HTTP；缺凭证时平台在启动
  脚本前就明确失败（`能力调用凭证缺失`），凭证值不写进代码、不回传、不打日志。
- **刻意不放的**：第三方库、`subprocess`/`os` 命令执行与进程派生、项目模块导入
  （含调用方 `禁止导入前缀`）——白名单只开「调哪几个底座能力」，不开别的口子。

因此技能包**不再各自复刻底座能力判定逻辑**：能不能调、能调什么，全部由这一个注入点决定。
