# 运行状态监督（运行核心.运行状态监督）设计说明（设计权威）

> 本文是本包的**设计哲学与边界权威**：它为什么存在、管什么、不管什么、失败如何表达、
> 判据为什么只有一份。调用口径——能力、参数、返回结构、错误码与调用示例——以同目录
> `使用说明.md` 为准。
> 两份说明都计入包指纹，任何改动都要升包版本。

## 为什么有这个包

`运行核心` 是**正式根**，但在本包之前全仓 `find 运行核心 -name 包声明.json` 只有它自己，
也就是说：**运行核心层最关键的两套判定实现，在能力面上完全看不见**——

- `运行核心/权威状态.py`：结构版本口径（`状态结构版本`）、迁移序列表、`校验规则表` 与逐项判定实现。
  调用方想回答「权威状态库是什么结构版本 / 结构完整没有」，只能 `import 运行核心.权威状态` 自己写一份判断，
  而 `import 运行核心实现` 正是依赖防火墙要拦的事（`越界前缀表`：「运行核心实现直连」）；
- `运行核心/依赖防火墙.py`：层向审计唯一实现（`允许依赖表` / `强制拒绝` / `审计依赖`）。
  发布门禁要的是「审计结论」，而能力面上一度没有任何一条依赖审计能力。

后果：`平台控制面/平台状态（包）` 这类子类库、门禁与运维脚本都只能**绕过能力面直接 import 实现**，
**同一件事出现第二份判断**（版本比较、表/列是否齐全）——这正是第 1 条 3 项「结果唯一即收口」
要治的病。本包按第 10 条「缺什么补什么」把它收成三条只读能力：**判据不动，只补边界**。

## 本包是什么

运行核心只读/判定面的**对外动作收口**，三条能力都是「问结论」，没有一条写盘：

| 能力 | 覆盖的既有动作 | 事实/判据落点 |
| --- | --- | --- |
| `查询状态结构版本` | 读 `元信息.结构版本` + 与 `状态结构版本` 比对 | `运行核心/权威状态.py`（只读连接） |
| `校验状态完整性` | `权威状态._校验版本结构`（表/列/`integrity_check`） | `运行核心/权威状态.py::校验规则表` + 逐项判定实现 |
| `审计依赖` | `依赖防火墙.审计依赖` | `运行核心/依赖防火墙.py`（层向表与规则全在该文件） |

**为什么是三条、不是更多**：

- 「需要迁移」是 `查询状态结构版本` 返回里的一个字段，不单列成第四条能力；
- 不把 `权威状态` 的每个方法各做一条能力（那是类的方法表，不是调用方需要的动作）；
- `校验规则表` 逐项明细收在 `问题列表` 里（一条能力返回全部原文明细），
  不拆成「查缺失表 / 查缺失列 / 查完整性」三条。

## 本包不是什么

- **不重写判定**：哪些表必需、哪些列必需、完整性怎么判、哪些导入算越层，全部仍只有一份实现
  （`权威状态.校验规则表` 与 `_校验表存在`/`_校验列`/`_校验版本结构`；`依赖防火墙.审计依赖`）。
  本包只做：参数边界校验、相对路径按系统根解析、异常→稳定错误码归一、结果字段归一。
- **不改被审计/被探查对象**：不改 `运行核心/权威状态.py`、`运行核心/依赖防火墙.py`，
  不改任何被审计源码文件，不迁移状态库结构、不注册进程身份（`权威状态.__init__` 会建库+升级 schema，
  所以**绝不构造权威状态实例**）。
- **不建第二套口径**：不在本包硬编码「必需表/必需列/层向表」清单，也不自写版本比较
  （一律用 `权威状态.版本元组`）；`依赖防火墙.系统根` 是本包解析相对路径、判定域内域外的唯一基准。
- **不做静默降级**：目标目录域外、不存在、参数形状不对，一律明确失败并给错误码，
  不「退回审计整个系统根」，也不把异常文本冒充审计结论。

## 三条边界口径（为什么这么定）

1. **「库不存在」是结论不是错误**：`查询状态结构版本` 报 `库文件存在=false` + `是否需要迁移=true`，
   `校验状态完整性` 报 `成功=true` + `值.完整=false` + 问题列表。理由：库不存在是**正常现场**
   （新环境、隔离目录、临时目录），把它当失败会让调用方分不清「没库」和「库坏了」；
   真正的 `读取失败` 只留给「文件在但打不开 / 不是数据库 / 库忙超时」。
2. **审计有违规也算调用成功**：信封 `成功` = 「审计执行成功」，`值.成功` = 「零违规」。
   两层语义必须在文档里写清，否则调用方会把「检出违规」误读成「能力坏了」。
3. **`完整` 只管结构、不判版本**：`权威状态.校验规则表` 是**基础结构**口径，
   `平台控制面.平台状态` 这类子类库扩展了 `迁移序列表` 与 `校验规则表`；
   本能力如实报基础结构结论 + 两侧版本字段，**版本是否一致由调用方判断**——
   这样既不给子类库造出恒假的红，也不越权替调用方做迁移决策。

4. **相对路径必须规范化后再交给审计（实测踩过的坑）**：`依赖防火墙.审计依赖` 按
   「文件相对 `系统根` 的路径段」定层名。若把未规范化的等价路径（如
   `<根>/../系统工程平台`）直接传下去，相对路径以 `..` 开头 ⇒ **所有文件都被定成「其他」层**，
   实测在 668 个文件上产出 **713 条假违规**（真实答案是 0 条）。
   所以本包一律 `(_解析目录 → resolve())`：返回的 `审计目录` 是规范化绝对路径，
   `<根>`、`<根>/../系统工程平台`、`<根>/运行核心/../运行核心` 三种写法给出**逐条一致**的 `违规表`
   （已实测）。这是「边界吃干净形态差异」（第 2 条 4 项翻译器原则）在本包的具体落点。

## 只读是怎么保证的（本包最硬的一条）

- **唯一构造口径**：只读连接 = `sqlite3.connect(路径.as_uri() + "?mode=ro", uri=True)`，
  在 `finally` 里必关，不持有跨调用连接（`实现/只读状态库.py::只读连接`）。
- **判定实现按「不需要实例状态」借用**：`权威状态._校验表存在` / `_校验列` / `_校验版本结构`
  只吃 `连接` 参数、只读类级 `校验规则表`。因此用 `object.__new__(权威状态)` 造一个**未初始化**的校验器：
  它不进 `_活动状态实例`、不建库、不注册进程、不迁移结构（`__del__` 与连接表访问全程 `getattr` 兜底）。
  这是「一份判据 + 零写盘」的落点，不是绕过结构校验。
- **审计只解析源码**：`审计依赖` 只调 `依赖防火墙.审计依赖(目录)`；后者只 `ast.parse` 源码，
  连被审计文件的 `__pycache__` 都不生成。

## 失败语义与稳定错误码

| 错误码 | 触发 | 语义 |
| --- | --- | --- |
| `参数不合法` | `存储目录` 空/非文本；`目标目录` 非文本、不存在、不在系统根内 | 调用方输入问题，不可重试 |
| `读取失败` | 库打不开/不是数据库/库忙；读源码 OSError | 服务端/环境问题，**可重试**（失败结果带 `可重试=true`） |

- 只登记实现里真实存在的失败码（`结果.失败("…")` 字面量），不虚列；
- 不把底层 `Exception` 文本当结论：一律换成上表稳定码，原文只放在说明里辅助定位。

## 版本与漂移

`包声明.json` / `能力定义.json` / `完整性摘要.json` 三者版本必须一致；
改参数、改返回结构或改说明都要升包版本，并重跑契约编译器（`能力定义.json` 是唯一可编辑事实源）
与 `python3.14 -m 开发工具.全量重算摘要`。
`__init__.py` 是**手写入口**（含 `注册能力`，编译器不覆盖），改动同样要计入摘要。
