# 限流边界说明（运行核心.统一网关.限流器）

> 本文是 `运行核心/统一网关/限流器.py` 的**边界权威**：它到底能做到什么、做不到什么、
> 为什么不做、谁来补。措辞以 `限流器.py` 模块说明为准，两者必须一致。
> 核对时间：2026-09-17。文中行号会随编辑漂移，**核对以符号名（`状态表` / `_状态` / `进入请求`）为准**。

## 一句话边界

**本限流器是「进程内固定窗口限流 + 进程内并发计数」，只对单进程网关 + 本机私有部署成立。**
它**不跨重启**、**不跨进程**、**不跨实例**，也**没有持久维**。
多实例 / 多进程 / 分布式部署必须外接**共享限流**——**本平台当前不提供**，也没有替身。

## 名字与实现对照（五维 vs 机制）

| 维度 | 在代码里是什么 | 判定在哪 | 跨重启 | 跨进程/多实例 |
| --- | --- | --- | --- | --- |
| 项目 | `状态表` 里 `("项目", 项目id)` 的一个 `限流状态` | `进入请求` 逐键比对 | 不保留 | 不生效 |
| 用户 | `状态表` 里 `("用户", 用户id)` 的同一个结构体 | `进入请求` 逐键比对 | 不保留 | 不生效 |
| 能力 | `状态表` 里 `("能力", 能力id)` 的同一个结构体 | `进入请求` 逐键比对 | 不保留 | 不生效 |
| 任务 | `状态表` 里 `("任务", 任务id)` 的同一个结构体 | **仅 `进入请求`**；`进入任务` 不比对维度 | 不保留 | 不生效 |
| 提供者 | `状态表` 里 `("提供者", 提供者)` 的同一个结构体 | **仅 `进入请求`** | 不保留 | 不生效 |

| 两轴 | 实况 |
| --- | --- |
| 固定窗口 / 滑动窗口 | **固定窗口**（`_状态`：`现在 - 窗口开始 >= 窗口秒` 时 `窗口开始 = 现在`、`窗口计数 = 0`，整窗清零）。窗口边界前后两波可合计到上限的两倍——固定窗口的固有语义，不是 bug，但调用方排期时要知道 |
| 进程内 / 持久 | **进程内**。状态全在 `限流器` 实例属性上（`状态表` / `请求并发` / `任务数` / `流式连接数`），文件里没有任何 `sqlite3` / `pickle` / `open(` 落盘痕迹；权威状态库（`工程缓存/*/权威状态.db`）里**没有限流相关表**（2026-09-17 用 `sqlite_master` 实测，表清单共 22 张，无「限流」类目） |
| 锁 | 一把 `threading.RLock`，**只管线程**，不管进程。多进程下两把锁等于没有锁 |

## 「五维」这个词该怎么读

- 五个维度**不是五套机制**，是**同一套「固定窗口计数 + 并发计数」换了五个维度键**：
  五维共用同一个 `限流状态` 结构体、同一把 `锁`、同一份 `频率上限表`（只是上限数字不同）。
- 维度键**只在传了非空值时建键**：调用方不传 `提供者`，「提供者维」这一维就不存在，不是「放行」也不是「拒绝」。
- `进入请求` **才是**比对五维的唯一入口（网关核心每个请求调一次）。
- `进入任务` / `进入流式` 收了五个维度参数但**不参与判定**，只比对全局 `任务数` / `流式连接数`；
  这两个闸门**全仓当前没有调用方**（`rg "进入任务|进入流式"` 只命中定义处）。不要把它们的参数表当成「任务维/能力维已在生效」。
- `状态快照()["五维状态"]` 只是「当前活着的维度-键计数器」清单，键名沿用既有契约，不代表五维各自独立生效。

## 为什么这样够了（不改造的理由）

平台的安全边界是**本机私有部署、单进程网关**：一个 `网关核心` 实例持有一个 `限流器`
（`运行核心/统一网关/网关核心.py`：`self.限流器 = 限流器实例 or 限流器()`）。
在这个边界内，「进程内」不是缺陷——它正是这套限流的目标形态：进程内零 IPC、零网络、零一致性代价。

真正的缺陷是**过去这句话没写下来**：模块首行只写「五维限流与并发治理」，抽象等级高于实现可靠性等级，
调用方会误以为它跨重启/跨实例生效，从而在扩容或双开时静默拿到 N 倍配额。**本轮收口的就是这一句。**

**触发升级的条件**（出现任一，就必须落地共享限流，不得只用本限流器顶着）：

1. 网关要以多进程 / 多实例方式部署（含 supervisor 拉起两份、或容器多副本）；
2. 限流配额要跨重启延续（例如「当天调用总量」这类累计口径）；
3. 限流要作为对外 SLA / 计费口径，需要跨实例一致且可审计。

## 对外契约（不得改）

- 拒绝返回错误码 **`限流`**，网关映射 **HTTP 429**（`开发文档/当前流程图.md`：「限流(429)」）。
- 错误说明文案固定：`限流: 并发请求数超过上限 N` / `限流: {维度}并发超过上限` /
  `限流: {维度}调用频率超过上限` / `限流: 任务数超过上限 N` / `限流: 流式连接数超过上限 N`。
- 并发保护（`最大并发请求` / `单维度并发` / `最大任务数` / `最大流式连接`）**是能力不是措辞**，
  收口文档时不得一并删掉或放宽。

## 可复跑核对（在项目根执行）

```bash
export PATH=/Library/Developer/CommandLineTools/usr/bin:$PATH; unset PYTHONPATH
/opt/homebrew/bin/python3.14 开发文档/临时文档/20260917_限流边界收口/核对限流边界.py
```

该脚本做两件事，任一不满足即**红**：

1. **行为取证**：五维确实落在同一个 `状态表`、窗口是整窗清零（固定窗口）、新实例计数归零（不跨重启）、
   双实例互不影响（不跨实例）、两个真实子进程各自从零开始（不跨进程）、并发保护仍然生效。
2. **文档断言**：`限流器.py` 里必须出现「进程内 / 固定窗口 / 不跨重启 / 不跨实例 / 外部共享限流 / 单进程」，
   且模块首行必须直接写明「进程内固定窗口」；本文件必须存在且写明边界。删掉任何一句措辞即变红。

反向验证（证明断言不是恒真）：把 `限流器.py` 复制到临时路径、把边界措辞改回「五维限流与并发治理」，再指向它跑：
