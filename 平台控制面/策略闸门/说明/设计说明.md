## 为什么有这个包

债务清单 **C-1**（2026-09-16 实测）：`策略中心` 原是一份**平铺文件** `平台控制面/策略中心.py`
（`平台控制面/统一入口.py:35` 直连），无 `包声明.json`、无任何能力 id ——
全仓包声明含「策略」= **0**。

后果是三条主链的策略闸门（**创建组件 / 提交候选包 / 签名与发布**）**只能进程内自查**：
调用方无法经网关复现「这个动作被策略允许/拒绝了吗、为什么」，策略判定成了**假绿风险源**。

## 本包是什么

把 `策略中心` 的**只读判定语义**（复用/依赖/签名/发布/资源五类）切成可经网关调用的原子能力。
判定语义唯一实现在 `平台控制面/策略中心.py`，本包只做**边界校验与结果归一**，
**不复制一份判定逻辑**。

| 能力 | 覆盖的既有动作 | 事实落点 |
|---|---|---|
| `查询策略类型` | `策略中心` 的策略类型表与判定键表 | 纯静态表（不建库、不落盘） |
| `判定复用策略` | `_执行判定("复用", 能力id, {})` | 只读能力注册表/复用决策 |
| `判定依赖策略` | `_执行判定("依赖", 包id, {依赖})` | 只读依赖关系 |
| `判定签名策略` | `_执行判定("签名", 包id, {已签名, 签名失效, 签名者})` | 只读信任目录 |
| `判定发布策略` | `_执行判定("发布", 包id, {候选版本, 需求id})` | 只读需求/发布表 |
| `判定资源策略` | `_执行判定("资源", 包id, {资源预算})` | **纯计算**（不建库不落盘） |

## 管什么 / 不管什么

**管**：五类策略的**判定结论**（允许/拒绝 + 理由 + 稳定错误码），以及策略类型与判定键的查询。

**不管**（本轮明确排除）：

- **判定不写证据**：判定类能力**不向证据账本写结论**（证据写入属写类动作，不在本轮只读/判定能力面）；
- **不做写类动作**：注册执行单元、提交任务、排空、优雅停止等写类动作仍走各自既有链路；
- **不替代调用方的判断**：本包回答「策略允不允许」，不替调用方决定「要不要做」。

## 失败如何表达

- 入参不合法（`包id`/`能力id` 为空、`依赖` 非列表、`已签名` 非逻辑型、`资源预算` 非字典型）→ `参数不合法`。
- 判定器初始化失败 / 查询信任目录失败 / 发布表查询失败 → `存储目录不可用` / `查询记录失败`。
- **判定结论用返回值表达，不用错误码表达**：`允许=false` 是**成功的判定结果**（`成功=True`），
  只有「判不了」才是失败。这条严格区分「策略拒绝」与「判定故障」。
- **对外错误码一律中文**（决策记录 `0003`）：判定结论里的 `错误码` 字段若为拒绝原因码，
  必须是中文码，不得出现英文枚举。

## 与旧实现的关系

`平台控制面/策略中心.py` **保持不变**（唯一语义实现）。本包是它的能力面。
`平台控制面/统一入口.py` 的直连调用是否切到本能力面，属于调用方收口，单独立项。
