# 快照校验（平台控制面.快照校验）设计说明（设计权威）

> 本文是本包的**设计哲学与边界权威**：它为什么存在、管什么、不管什么、失败如何表达。
> 调用口径——能力、参数、返回结构、错误码与调用示例——以同目录 `使用说明.md` 为准。

## 为什么有这个包

债务清单 **C-3**（2026-09-16 实测）：`核心快照管理` 原来是一份**平铺文件** `平台控制面/核心快照.py`
（`平台控制面/统一入口.py:39` 直连），目录里没有 `包声明.json`、没有任何能力 id，
于是「版本三元组 + 签名 + 磁盘摘要 + 状态兼容范围」这套回滚前置判定**在能力注册表里完全看不见**——
全仓搜含「快照」的能力 id = 0。

后果是真实的：`提供者/版本兼容*.py` 与回滚链路只能**进程内直连对象**自查，
任何「快照是否可回滚」的结论都**无法经网关复现**，属于典型的假绿风险源（哲学 1.4「空转即杀」的反面：
判定没有真实可复现的调用面）。

## 本包是什么

把 `核心快照管理` 的**只读与判定语义**切成可经网关调用的原子能力。事实唯一落
`平台控制面/核心快照.py`（快照记录 + 磁盘目录 + 签名），本包只做**边界校验与结果归一**。

| 能力 | 覆盖的既有动作 | 事实落点 |
|---|---|---|
| `查询核心快照` | `核心快照.查询快照` | 权威状态库「核心快照」表（只读） |
| `校验核心快照` | `核心快照.校验快照`（磁盘摘要 + 签名） | 只读磁盘 + 只读记录 |
| `校验状态兼容范围` | 回滚前置判定（目标版本是否落在 `状态兼容` 范围内） | 只读记录，纯版本区间判定 |
| `查询快照清单` | `核心快照.查询快照清单`（新，只读） | 只读记录表 |

## 管什么 / 不管什么

**管**：快照记录的读取与命中判定；快照的磁盘摘要/签名校验结论；目标状态结构版本是否落在快照声明的兼容范围内；快照清单（带限制）。

**不管**（本轮明确排除，不是遗漏）：

- **创建快照 / 签名快照 / 健康检查（影子启动）** 属写类与执行类动作，依赖进程内实例状态与真实启停，不在本轮只读/判定能力面；
- **回滚动作本身**：本包只回答「允不允许回滚、为什么」，**不执行回滚**（回滚只切不可变旧制品与激活指针，走发布管理链路）。

## 失败如何表达

- 入参形状/取值不合法 → `参数不合法`（含 `限制` 越界、`快照id` 为空）。
- 存储目录不可用、记录读取失败 → `存储目录不可用` / `读取记录失败` / `查询记录失败`，
  **不吞异常、不用空值伪装成功**。
- **没命中不是失败**：`查询核心快照` 未命中返回 `成功=True` + `是否命中=false` + `记录=null`，
  与「读取失败」严格区分（这正是 A-1 要治的「内部故障与被测缺陷不可区分」）。

## 与旧实现的关系

`平台控制面/核心快照.py` **一个字没改、也没删**——它是唯一语义实现。本包是它的**能力面**，
不是第二套实现。平铺文件是否包化（D-6）单独立项，不在本包范围。

## 设计哲学依据
