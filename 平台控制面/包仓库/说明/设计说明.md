## 为什么有这个包

决策记录 `0012_装配根声明式化与平台治理能力面` 的待办「波2：给平台控制面/运行核心的功能面补正规包」
未完成时，`平台控制面` 下 0 个 `包声明.json`：治理层功能面进不了装配表，能力注册表里调不到，
于是治理工具（`开发工具/发布门禁`、`开发工具/组件合规`）只能**直接 import 本目录实现**
（依赖防火墙按层判定即为越层）。本包是这一治理动作的**批次 B1**：把包仓库面补成**正式包**。

正式根清单的唯一事实源是 `公共契约/正式根.py`：`平台控制面` 已在其中，根内**含 `包声明.json`
才参与发现**，所以补包本身就是「进装配」的动作，不需要改发现器、不需要把 `平台控制面`
加进任何允许依赖表（那是被明确禁止的捷径）。

## 本包是什么

包仓库与制品链路治理面的**对外动作收口**，事实唯一落 `平台控制面/包仓库/` 既有实现：

| 能力 | 做什么 | 事实落点 |
|---|---|---|

| `校验平台客户端稳定路径` | 激活指针/安装目录/制品目录三方摘要一致性 | `平台客户端制品.py` |
| `安装候选包` | 候选包安装到不可变版本目录（同版不可覆盖、原子替换、失败清理） | `版本仓库.py` |
| `校验已安装包完整性` | 重算安装目录摘要并与期望摘要比对 | `版本仓库.py` |
| `校验可重复构建` | 同输入双工作区摘要一致 + 变化输入摘要对照 | `可复现构建器.py` |
| `校验可信仓库元数据` | 根信任/目标/快照验签 + 替换攻击必须阻断 | `可信仓库元数据.py` |

## 本包不是什么

- **不是第二套仓库**：本包不新增任何仓库语义，只把既有实现的公开方法收成能力，
  一条能力对应调用方原来做的同一件事，返回值把它需要的事实一次给全。
- **不是制品入库/安装到环境/激活指针 CAS 的全套门面**：`入库`（内容寻址+签名+信任元数据
  一步到底）、`安装到环境`（发布管理 CAS 激活 + 稳定路径）、`激活指针` 切换这些动作
  按波次留给后续批次；本批把**制品生产主链的原子步**——
  `登记发布者 → 构建制品 → 签名制品 → 校验签名 → 安装制品`（另加 `撤销发布者`）——
  收成可调能力，使「未签名制品拒绝安装」这类判定能在能力面表达而无需调用方直连实现。
- **不暴露实现内部状态**：`制品根目录` 这类对象属性不再由调用方直取拼字符串——路径口径
  经只读能力 `查询制品布局` 给出（默认根目录为绝对路径，与工作目录无关）。
- **不校验契约/权限**：包结构与契约合法由组件规范与契约编译器负责，本包不做重复判定。

## 失败如何表达

- **输入类失败**：错误码 `参数不合法` + 点名具体参数（空值、路径已存在但不是目录、缺 文件表、
  非公钥块/非私钥块、有效期秒非正数、制品摘要长度非内容寻址口径）。
- **业务结论类**：`通过` / `有效` / `校验成功` / `签名有效` / `替换攻击阻断` / `已撤销` 为 `false`
  一律走**成功结果**——「校验不通过」是能力的正常答复，不是调用失败；消息逐字沿用实现层原文，
  调用方据此映射自己的错误码（例如发布治理把不通过映射为 `参数无效`），口径逐字保持。
- **安装类失败**：错误码 `候选包安装失败`，或生产链的 `制品构建失败` / `制品签名失败` /
  `制品安装失败` + 实现层原文说明（如「安装被拒: 未签名制品」）。
- **不存在类失败**：`发布者不存在`（撤销从未登记的发布者）、`发布者登记未落盘`（登记后重读无记录）。
- **禁止兜底**：不静默降级、不用默认值掩盖失败、不把实现层异常吞成成功。

## 资源与释放

制品接入对象每次调用独立构造并在 `finally` 中关闭其状态库连接；一次性工作区与临时目录
在 `finally` 中整目录清理；不可变版本目录与制品目录由实现层管理。签名与验签经受管
密码签名提供者的隔离子进程完成，子进程在单次调用内退出。
