# 授权 设计说明

- 包id：平台控制面.授权
- 类型：支持库（平台控制面 正式根下的治理能力面）
- 能力数：9

## 归属与分层

- 授权是 `平台控制面` 正式根下的治理能力面，不与 支持库/模块库 混层。
- 角色授予事实唯一落 平台控制面.平台状态（权威状态库的角色授予表 + 证据账本），本包不另立事实源。
- `平台控制面/授权.py` 是授权语义唯一实现（五角色/等级表/操作最小角色/会话表/判定）；本包 `实现/能力入口.py` 只做边界校验与统一结果映射。

## 为什么这条能力面必须有正式包

治理层原先 0 个 `包声明.json` → 能力注册表里调不到 → 治理工具只能 import 实现，形成越层依赖。补正式包后，授权动作经能力 id 调用，越层依赖随之消失（决策记录 0012「波2：给治理层功能面补正规包」）。

## 不可能力化的部分（不硬凑）

- 会话表是进程内状态机（令牌→身份/角色/过期时间），不对外暴露为独立能力；对外只暴露 注册/切换/刷新/校验 四个动作。
- `_授予`（内部写入原语）不单独切能力，它是 引导授予/授予角色 的共用实现步骤。

## 受信引导的凭证边界（B-04 安全加固，2026-09-17）

审计发现：CLI 分支原先只比一个硬编码字符串（`授予者=系统引导`），任何本机进程执行
`统一入口.py 引导 <自己> 发布者` 即可自我提权。现在凭证改成**一次性引导令牌文件**，
判定**唯一落在** `平台控制面/授权.py` 的 `引导令牌文件/平台已初始化/发放引导令牌/引导授予`
四处（本包不复制判定，只透传与错误映射）：

- 凭证形态：每次引导一份随机令牌，落 0600 文件（默认 `<存储目录>/引导令牌.txt`，
  可用参数或环境变量 `系统工程平台_引导令牌文件` 改址）；**不引入长期密钥**。
- 发放门槛：令牌文件不存在（不重复发放）+ 平台未初始化（无有效 平台维护者/发布者 授予）；
  已上线平台因此无法再凭空铸造引导凭证。
- 使用规则（存在即用、用完即删）：令牌文件在 → 任何入口缺令牌一律拒绝、令牌不符拒绝、
  用后立即删除；文件不在而携带令牌 → 也拒绝（防"自带令牌"绕过）。
- CLI：`统一入口.py 引导令牌` 发放、`统一入口.py 引导 <身份id> <角色> <令牌>` 使用；
  无令牌参数直接 `引导受限` 拒绝。令牌不进证据/日志，证据只记 `{角色, 凭证}` 与令牌文件路径。

**已知残留边界（本地私有部署下的相对安全，不硬凑绝对边界）**：未配置令牌文件时，
"未携带令牌 + `授予者=系统引导`"的**进程内直调**仍按原契约放行——这是既有夹具/门禁/
示例的受信引导路径，改严会连锁改动域外调用方。部署时先发放一次性令牌即可关闭该路径；
同账号攻击者可写存储目录这一点本身超出本层边界（属主机账号安全）。

## 兼容性（不改调用方）

本包目录与既有 `授权.py` 同名，包目录优先导入。入口按文件路径显式载入`../授权.py` 并原样再导出全部公开名字（授权服务/五角色常量/角色等级/操作最小角色/稳定错误码），平台内既有 `from 平台控制面.授权 import …` 继续可用，行为逐字不变。
