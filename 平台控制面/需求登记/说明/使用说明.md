## 稳定错误码映射（中文域错误码 → 平台稳定码）

| 中文域错误码 | 平台稳定码 | 含义 |
| --- | --- | --- |
| 参数不合法 | INVALID_PARAMETER | 参数形状/取值不合法（非文本目标、非对象快照、限制越界等） |
| 需求id不能为空 | REQUIREMENT_REQUIRED | 空需求id——**需求闸门空需求id阻断**（与 `统一入口.py` 4 处同码） |
| 需求不存在 | REQUIREMENT_NOT_FOUND | 目标需求快照**查不到**（与 `统一入口.py:184` 的真实返回同词） |
| 需求未确认 | REQUIREMENT_UNCONFIRMED | 需求存在但未确认——**未确认需求阻断开发/发布放行**（与 `统一入口.py:186/235/389` 的真实返回同词） |
| 需求登记失败 | REQUIREMENT_REGISTER_FAILED | 快照/确认状态写平台权威状态库失败 |
| 需求查询失败 | REQUIREMENT_QUERY_FAILED | 需求/工作包查询失败 |
| 装配计划生成失败 | ASSEMBLY_PLAN_FAILED | 波次1内部能力占用冲突，或装配计划落盘失败 |
| 工作包登记失败 | WORK_PACKAGE_REGISTER_FAILED | 装配计划已落盘、工作包落盘失败 |

> 映射表的唯一事实源是同目录 `需求错误码.py`。失败结果的 `详细信息.稳定错误码` 也会带上稳定码，
> 调用方无需自己再猜一次。
>
> **读点（B-17 收口「死表」）**：`实现/能力入口.py` 的 `_稳定码` / `_失败` 实际读本表生成
> `详情.稳定错误码`，能力分支内不得再写稳定码字面量（新增失败分支必须先补本表，否则当场抛
> `KeyError`）。修前该文件只 import 了本表却 0 处使用、稳定码全写死，实测改表行为逐字不变；
> 现改本表必然改变返回值，发布门禁的稳定码判定随之变化。
