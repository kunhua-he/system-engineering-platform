# 能力目录 设计说明（设计权威）

> 调用口径（能力、参数、返回结构、错误码、调用示例）以同目录 `使用说明.md` 为准；本文只讲**设计**：为什么这样切、管什么、不管什么、失败如何表达。
> 包id：`平台控制面.能力目录` ｜ 类型：支持库 ｜ 版本：1.0.0

## 本包是什么

平台控制面的**能力目录面**，把两件事切成可经唯一网关调用的公开能力：

1. **消费者契约注册表**——能力被谁消费、消费方要求什么（请求/响应约束、错误码、超时、释放要求），以及当前契约相对登记契约是否漂移；
2. **文件租约**——多会话/多子代理并行改同一仓库时，按项目根相对路径原子认领文件，防止两个写者改同一个文件。

事实唯一落盘在包内的存储文件（消费者契约表、租约表），本包只做边界校验、原子写读与结果归一。

## 本包不是什么

- **不实现契约校验算法与发布门禁的判定逻辑**：本包只回答「有没有漂移」「是否阻断」，真正的门禁接线在 `开发工具/发布门禁/`。
- **不做文件锁**：租约是**协作式约定**（登记 + 心跳 + 过期回收），不是操作系统级排他锁；绕过租约直接改文件，本包无法阻止。
- **不管项目业务语义**：只处理「路径 / 能力 id / 消费者 id」这类通用标识，不认识任何业务项目。
- **不管能力的注册与路由**：能力注册表在 `运行核心`，本包只登记「消费者对能力的契约」。

## 管什么 / 不管什么

| 管 | 不管 |
|---|---|
| 消费者契约的登记、查询、删除（覆盖写、幂等） | 契约内容的合法性判定标准从哪来（那是消费者自己的事） |
| 契约漂移判定与门禁判定（只给结论 + 漂移列表） | 漂移后怎么修、要不要阻断发布（发布门禁决定） |
| 文件租约的申请、续租、释放、过期回收、查询 | 进程存活探测（由 `系统核心支持库.进程管理` 提供） |
| 路径越界拒绝（项目根为界） | 项目根由谁指定（调用方传参） |

## 为什么这样切

**理由一：契约漂移必须是「可查询的事实」，不能只存在于发布时的一次性检查。**
把「登记契约」与「判定漂移」拆成两个能力，是为了让漂移可以**随时查**（查询是只读、幂等、零副作用），而不必等到发布门禁跑起来才知道违约。发布门禁只用 `判定契约门禁` 这一个出口取结论。

**理由二：文件租约与消费者契约同包，因为二者共用同一套「单文件互斥存储」。**
两者都需要「同一时刻只有一个写者、写读可并发」，共用 `单文件互斥存储.py`，避免各写一套原子写。**注意这不是把两件事混为一谈**：契约表按「消费者id + 能力id」索引，租约表按「路径」索引，互不干扰。

**理由三：空 id 一律失败，不许返回空结果。**
`查询消费者契约` 空 id 会命中空表，`判定契约门禁` 空 id 会得到「不阻断」——两者都是**假证据**（看起来正常，实际什么都没查）。因此本包对必填标识一律硬失败，宁可报错也不给空结论。这是「失败即失败，不静默成功」在本包的具体落法。

## 失败如何表达

统一结果（成功 / 值 / 错误码 / 错误说明）。本包的错误码只列实现里真实存在的：

| 错误码 | 触发条件 |
|---|---|
| `参数不合法` | 必填参数缺失、类型不符、契约结构不齐备 |
| `契约非法` | 契约结构不齐备（缺请求/响应约束等必需项），错误说明回带问题原文 |
| `未登记` | 删除一个未登记的消费者契约绑定（失败即失败，不静默成功） |
| `路径越界` | 租约申请中包含项目根之外的路径，**整批硬失败**，不做部分认领 |
| `文件已被占用` | 租约申请中任一文件被活跃租约占用，**整批失败**，回带占用者与占用开始时间 |
| `租约不存在` | 续租已过期或已释放的租约（已结束的租约不能复活） |

**幂等口径**：释放与回收是幂等的——重复释放回「已结束且已释放」，重复回收第二次回带空清单且不报错。**续租不是幂等的**：对已结束租约续租必须失败，否则会出现「复活一条假活跃租约」的脏状态。

## 生命周期覆盖

- **存储初始化**：首次调用时惰性创建存储文件，不要求预先初始化。
- **登记/删除**：覆盖写与幂等删除，不留半成品记录。
- **租约过期**：`回收过期文件租约` 按心跳超时判定并置为已过期；**不自动后台回收**（无守护线程），需调用方按周期显式调用——这是刻意的：本包不持有任何长驻资源。
- **进程退出**：无句柄、无子进程、无线程，退出不留下需要释放的运行态。

## 验证与取证

- 能力清单与真实注册以 `包声明.json` 的 `能力` 与网关返回为准；
- 租约行为有包级验证场景 `验证场景/文件租约.json`；
- 契约漂移的真实消费方判定见 `开发工具/发布门禁/`；
- **不要**用「说明书写了几个能力」当作能力数，一律以正式包索引与网关实查为准。
