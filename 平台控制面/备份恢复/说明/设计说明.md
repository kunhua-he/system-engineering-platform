## 本包是什么

平台控制面的**数据保全面**：把三类权威数据的备份与恢复，切成可经唯一网关调用的公开能力。

三类权威数据固定为：

| 类 | 内容 |
|---|---|
| 权威状态 | 平台运行态数据库 |
| 包仓库 | 已安装制品与其激活指针 |
| 证据账本 | 验证历史、反馈账本等机器账本 |

提供四个能力：**声明备份契约**（只读）/ **执行备份** / **校验备份** / **恢复备份**。真实语义（恢复点、恢复时限秒、保留周期、恢复顺序、三类真实校验方法）唯一落包内既有实现，本包只做边界校验与结果归一。

## 本包不是什么

- **不做定时备份调度**：本包只提供动作，不持有定时器、不起守护进程；谁来周期调用由运维层决定。
- **不做异地/对象存储**：备份目标是本机目录，不上传远端。
- **不替代版本控制**：这是**运行态数据**的保全，与源码的 Git 历史是两回事（源码归档口径见 `开发文档/规范/Markdown 文档体例规范.md` 第八节）。
- **不负责灾难判定的策略**：什么情况该恢复、恢复到哪个时间点，是运维决策，不是本包能替调用方决定的事。

## 管什么 / 不管什么

| 管 | 不管 |
|---|---|
| 三类权威数据的契约声明（恢复点/时限/周期/顺序） | 恢复点与保留周期该取什么值（由调用方按 `覆盖表` 覆盖） |
| 真实备份：WAL 先合并 → 逐类复制 → 逐类算摘要 → 落 `备份清单.json` | 数据源本身是否健康（源缺失就如实标记缺失） |
| 备份校验：摘要核对 + 逐类真实校验方法 | 校验失败后怎么办（本包只给结论，不做补救） |
| 恢复：按契约顺序恢复 + 恢复后逐类真实校验 | 目标目录该是谁（调用方传参） |

## 为什么这样切

**理由一：先声明契约，再执行——`声明备份契约` 必须独立且只读。**
恢复点与恢复时限是**承诺**，不是副作用。把它做成独立只读能力，才能让运维在没有磁盘写入的前提下先看到「这套备份体系承诺什么」，也才能被别的检查项引用。

**理由二：缺失必须如实标记，不许补默认值。**
`执行备份` 遇到某类数据源缺失时，在清单里写「缺失」而不是伪造一份空备份，并且**该校验会被 `校验备份` 判失败**。这是刻意的闭环：让「以为备好了、其实没备」这种最危险的假安全，在备份阶段就暴露，而不是等到需要恢复的那一刻。

**理由三：恢复必须带顺序，且必须能给回退警告。**
三类数据之间有依赖（例如包仓库依赖权威状态的激活指针），无序恢复会产出不一致的中间态。同时：**如果目标目录现有的权威状态比这份备份更新，恢复必须带回退警告**——旧快照重放是真实风险，调用方必须看见，不能被静默执行。

**理由四：校验方法以「方法名」对外。**
契约为保证返回值可 JSON 化，只回带 `校验方法名` 而不回带函数对象。这样契约可以跨进程/跨协议传输，不引入序列化逃逸。

## 失败如何表达

统一结果（成功 / 值 / 错误码 / 错误说明）。本包错误码只列实现里真实存在的：

| 错误码 | 触发条件 |
|---|---|
| `参数不合法` | 必填参数缺失、类型不符；`覆盖表` 不是对象 |
| `备份不存在` | 备份目录内不含任何备份（`校验备份` / `恢复备份`） |

**关键口径：`通过 = False` 不是失败。**
`校验备份` 返回 `通过=False` 是**正常的校验结论**（说明备份内容有问题），与「调用失败」是两件事——调用失败才用错误码。同理，数据源缺失在 `执行备份` 阶段是**如实记录**，不是报错；它会在校验阶段被判定为不通过。

**关键口径：`恢复备份` 的 `成功` 是三态，不是二值。**
`恢复备份` 另带 `状态`（`通过` / `未核验` / `失败`）、`是否未核验`、`结果条数`、`状态说明` 四键。
**空表 = 没有可核验对象 = 未核验**：既不算「通过」（哲学 1.4 空集 ≠ 通过），也不该被笼统报成
「失败」——它是平台五态结论里的「未核验」。此时 `成功` 仍为 `假`（只看布尔的调用方
不可能把空集读成通过），要分辨未核验与失败必须读 `状态` / `是否未核验`。
门禁与演练均已按此口径处置：`开发工具/发布门禁/第十四阶段门禁.py` 遇未核验明确报
「恢复未核验」并判红，`开发工具/备份恢复演练.py` 报告里单列 `恢复状态` / `恢复未核验`。

## 生命周期覆盖

- **无持有态**：本包不持有连接、句柄、子进程或长驻线程；每次调用自建、自释放。
- **WAL 合并**：备份时先合并 WAL 再复制，避免「主库备了、WAL 没备」导致恢复后丢最近写入。
- **原子落盘**：备份落时间戳快照子目录，同一次备份独占一个目录，不覆盖既有快照。
- **恢复的中间态**：恢复按契约顺序推进；任何一类失败即按统一错误返回，不回滚已恢复的类（由调用方据错误码与恢复顺序决定下一步）——这是刻意的**不做隐式回滚**，避免半途回滚造成比原状更差的中间态。

## 验证与取证

- 三类数据的恢复点/时限/周期/顺序以 `声明备份契约` 的真实返回为准；
- 校验方法的具体实现见包内 `校验函数.py`（`sqlite integrity_check` / 证据哈希重放 / 制品逐文件 sha256）；
- **不要**把说明书的条目数当能力数，一律以正式包索引与网关实查为准。
