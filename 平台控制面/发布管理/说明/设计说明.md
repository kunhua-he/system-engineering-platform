## 为什么有这个包

决策记录 `0012_装配根声明式化与平台治理能力面` 的待办「波2：给平台控制面/运行核心的功能面补正规包」
未完成时，`平台控制面` 下 0 个 `包声明.json`：治理层功能面进不了装配表，能力注册表里调不到，
于是开发工具门禁只能**直接 import 实现**（依赖防火墙按层判定即为越层）。本包是这一治理动作的
批次 A4：把发布治理面补成**正式包**，让发布动作可从能力注册表调到。

正式根清单的唯一事实源是 `公共契约/正式根.py`：`平台控制面` 已在其中，根内**含 `包声明.json`
才参与发现**，所以补包本身就是「进装配」的动作，不需要改发现器、不需要把 `平台控制面` 加进
任何允许依赖表。

## 本包是什么

发布治理面的**对外动作收口**，事实落 `平台控制面/平台状态（包）`（权威状态库，含发布表与激活指针表）：

| 能力 | 做什么 | 事实落点 |
|---|---|---|
| `登记发布期望` | 发布流程起点：落一条期望发布记录 | 发布表 |
| `开始灰度发布` | 期望 → 灰度：写候选版本与比例 | 发布表 |
| `激活发布版本` | 准备 → 指针 CAS → 完成（目标一致幂等复用） | 发布表 + 激活指针 |
| `切换激活指针` | 通用指针切换：版本+栅栏令牌 CAS，陈旧令牌被拒 | 激活指针 |
| `回滚发布` | 指针 CAS 到回滚目标，历史记录保留 | 发布表 + 激活指针 |
| `恢复未完成发布` | 重启恢复：准备/灰度 收敛到明确版本，无半激活 | 发布表 |
| `对账发布状态` | 期望（发布记录）vs 实际（激活指针）逐项核对并修复 | 发布表 |
| `执行互斥迁移` | 真实 sqlite 写锁 + 状态位的并发互斥迁移 | 迁移状态库 |
| `校验幂等恢复` | 二阶幂等恢复校验：重复恢复稳定 + 证据只追加 | 发布表 + 证据表 |
| `开始发布事务` | 事务容器：临时文件 + 原子替换持久化 | 事务目录 |
| `查询未完成发布事务` | 崩溃后接管与诊断的只读查询 | 事务目录 |
| `扫描未完成操作` | 操作日志未完成扫描 + 半成品判定（只读） | 事务目录 |

十二条能力对应的是**治理面对外需要的发布动作**，不是按目录或函数拆的：每条能力都等于调用方
真正需要的一个完整动作（登记/灰度/激活/切换/回滚/恢复/对账/迁移/校验/事务），不把状态机里的
每个状态做成一条能力，也不为凑数拆能力。

## 本包不是什么

- **不重写发布语义**：字段校验、状态机、指针 CAS、栅栏令牌、迁移写锁、证据只追加仍留在
  `服务.py` / `迁移互斥编排器.py` / `二阶恢复.py` / `发布事务/*.py`；本包只加一层「能力边界」——
  参数校验、存储目录缺省、状态实例装配、统一结果归一。
- **不暴露连接对象与函数对象**：`迁移互斥编排器` 内部持一条连接的显式事务（BEGIN IMMEDIATE 跨
  多条语句、事务内回读状态），能力边界只给「执行互斥迁移(任务id, 存储目录)」这一完整动作，
  不把连接或半截事务语义透出去。
- **不做静默降级**：状态库不可用、发布不存在、指针 CAS 失败、缺必填参数一律返回明确错误码
  （`参数不合法` / `发布不存在` / `激活指针冲突` / `陈旧栅栏令牌切换被拒` / `无激活指针可回滚` /
  `幂等恢复校验失败`），绝不退回「不校验即放行」或假成功。

## 存储目录与状态实例的归属

- **存储目录由调用方按部署配置传入**：能力参数 `存储目录` 显式暴露，缺省才取平台默认目录
  （`工程缓存/平台控制面`）。这样门禁与网关能把自己的部署目录继续传进来，不把调用方的缓存根
  硬编进能力层。
- **状态实例按 (存储目录, 项目id) 复用**：同一目录同一项目共用一份 `平台状态`，避免每次调用
  重建状态库连接；状态库连接随进程退出由 SQLite 关闭，调用路径不持有跨调用句柄。
- **必填参数不做默认兜底**：`存储目录` 声明为必填的能力（如 `执行互斥迁移`）缺参即 `参数不合法`，
  不回落到默认目录 —— 否则「缺必填」与「显式传入」会得到同一条成功路径，失败语义失真。

## 版本与漂移

`包声明.json` / `能力定义.json` / `完整性摘要.json` 三者的版本必须一致；
新增能力、改参数或改返回结构都要升包版本、重跑契约编译器并重算完整性摘要。
`__init__.py` 是**手写入口**（编译器识别到含 `注册能力` 即不覆盖），改动同样要计入摘要。
