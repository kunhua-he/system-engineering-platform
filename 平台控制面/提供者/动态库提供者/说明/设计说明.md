## 为什么这样切
系统动态库（libsqlite3 / libc / libSystem）是**环境依赖**（运行级依赖），
按第 6 条「第三方与环境依赖＝最底层的翻译层」封在本提供者里：只翻译平台真正用得上的
最小接口，不照搬第三方全量功能。

## 管什么
- `调用动态库`：真实 `ctypes.CDLL` 加载 + 真实函数调用；只允许**签名登记表**内的函数
  （当前登记 sqlite3_libversion / sqlite3_libversion_number / strlen / getpid）。
- `可用库列表`：真实探测 sqlite3 / c / system 的库名、真实路径与可用状态。
- `宿主可用性`：真实探测宿主能否提供动态库调用（缺 ctypes → 宿主不可用）。

## 不管什么
- 不猜签名：未登记函数直接 `签名未登记` 失败，绝不放行——猜错签名会直接崩宿主。
- 不做能力发现替代：动态库可用性 ≠ 平台能力可用性，两者不混。
- 不做默认值兜底、不静默降级：库缺失/加载失败/函数不存在一律明确失败。

## 失败如何表达
`宿主不可用`（库缺失或宿主不支持）、`签名未登记`、`函数不存在`、
`参数不匹配`、`调用失败`、`参数不合法`。后端不可用即失败，不返回假值。

## 相对安全口径
提供者允许调用宿主动态库，这是**相对安全**而非绝对边界：护栏只拒绝「未登记签名」
这类会改变宿主状态的风险面，已登记接口本身由调用方自主选择；不宣称绝对隔离。
