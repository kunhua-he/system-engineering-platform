# 动态库提供者 使用说明

- 包id：平台控制面.提供者.动态库提供者
- 版本：1.0.0

> 本文是本包的**调用权威**：能力、参数、返回结构、错误码与调用示例。
> 设计与边界（为什么这样切、管什么、不管什么、失败如何表达）以同目录 `设计说明.md` 为准。

## 包说明

动态库真实提供者：ctypes 真实加载系统动态库并调用最小登记签名接口（sqlite3/c/system），库缺失或宿主不支持返回 `宿主不可用`，未登记签名拒绝调用。

## 平台控制面.提供者.动态库提供者.调用动态库（调用动态库）

**说明**：真实加载动态库并真实调用函数：只允许调用签名登记表内的函数，未登记即拒绝（不猜测签名导致崩溃）。

**参数表**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 库名 | 文本型 | 是 | None | 逻辑库名或真实文件名（sqlite3/libsqlite3.dylib/libc/System 等，自动归一化） |
| 函数名 | 文本型 | 是 | None | 函数名，**必须在签名登记表内**（如 sqlite3_libversion） |
| 参数表 | 列表型 | 否 | None | 按登记签名顺序排列的实参列表；无参函数留空 |

**返回结构**：结果型（统一结果：成功/值/错误码/错误说明/可重试/详细信息）

| 值字段 | 说明 |
| --- | --- |
| 值 | 按登记返回类型真实转换的值（文本型/整数型） |

**实测真实返回**（2026-09-16 进程内装配真调，装配能力数 645）：

已登记函数真调：
```json
{"值": "3.51.0"}
```

**反向验证——未登记签名必须被拒**（换成签名登记表外的 `sqlite3_open`）：
```text
失败 错误码=「签名未登记」 说明=函数 sqlite3_open 未登记签名，拒绝猜测调用
```

**错误码表**：

| 错误码 |
| --- |
| 参数不合法 |
| 宿主不可用 |
| 签名未登记 |
| 函数不存在 |
| 调用失败 |
| 参数不匹配 |

**调用示例**：

```python
后端.调用("平台控制面.提供者.动态库提供者.调用动态库",
          {"库名": "sqlite3", "函数名": "sqlite3_libversion"})
```

## 平台控制面.提供者.动态库提供者.宿主可用性（宿主可用性）

**说明**：探测当前宿主能否真实提供动态库调用：不可用时状态为 宿主不可用（如缺少 ctypes）。

**参数表**：本能力**无参数**。

**返回结构**：结果型

| 值字段 | 说明 |
| --- | --- |
| 可用 | 逻辑型，true = 宿主可提供动态库调用 |
| 状态 | 文本型，可用 或 宿主不可用 |
| 平台 | 文本型，sys.platform 真实值 |
| 说明 | 文本型，不可用原因 |

**实测真实返回**：

```json
{"可用": true, "状态": "可用", "平台": "darwin", "说明": ""}
```

**错误码表**：

| 错误码 |
| --- |
| 参数不合法 |

**调用示例**：

```python
后端.调用("平台控制面.提供者.动态库提供者.宿主可用性", {})
```
