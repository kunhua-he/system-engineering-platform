# 平台状态 设计说明（平台控制面.平台状态）

## 为什么这样切
`平台控制面` 的六个权威服务（需求登记 / 能力目录 / 包仓库 / 策略中心 / 发布管理 /
证据账本）共用一份权威事实：SQLite 权威状态库。若每个服务各自维护 JSON 真相，
就会出现多套事实源。故本包只做一件事：**平台权威状态存储**（结构 1.4.0），
由 `运行核心.权威状态` 子类化复用连接管理 / WAL / 迁移器 / 栅栏令牌 / CAS，
本包只扩展平台表与六服务通用读写。

## 管什么
- 记录读写：`读取记录` / `查询记录` / `写入记录`（同主键按字段合并，不丢其他字段）。
- 证据账本：`追加证据`（仅追加，旧证据不可覆盖）/ `查询证据`。

## 不管什么
- 不管六个服务各自的业务语义与状态机（各服务包自己管，写入口唯一）。
- 不登记 `保存句柄` / 租约 / 锁 / 栅栏令牌一类**底层机制能力**：它们由
  `运行核心.权威状态` 承载，重复登记就是同一机制两套能力（重复即缺陷），
  因此保留为越层收口的未覆盖项，本包不重复实现。
- 不做默认值兜底、不做静默降级：存储目录不可用、表不存在、参数形态不符一律明确失败。

## 失败如何表达
统一返回 `成功/值/错误码/错误说明/可重试`；失败必须带稳定中文错误码
（`参数不合法` / `存储目录不可用` / `读取记录失败` / `查询记录失败` /
`写入记录失败` / `查询证据失败`），禁止伪造成功。

## 相对安全口径
存储目录由调用方显式传入；留空取平台默认目录 `工程缓存/平台控制面`。
本包不对表名与列名做白名单限制（治理层内部使用需要按真实表结构取数），
风险由调用方与权限契约约束，不宣称绝对安全边界。
