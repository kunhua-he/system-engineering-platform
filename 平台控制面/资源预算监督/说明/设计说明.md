## 为什么有这个包

债务清单 **C-2**（2026-09-16 实测）：`资源监督` 原是一份**平铺文件** `平台控制面/资源监督.py`
（`平台控制面/统一入口.py:38` 直连），无包、无能力 id —— 全仓含「监督」的能力 id = **0**。

后果：`资源监督器.必需预算键` 这套**预算声明判定**（任何新组件/新执行单元开工前的强制前置）
无法经网关证明，等于「预算的真实执行」只存在于进程内自查。

## 本包是什么

把 `资源监督器` 的**预算声明判定语义**切成可经网关调用的只读/判定原子能力。
必需项与预算判定的唯一实现是 `平台控制面/资源监督.py`，本包只做**边界校验与结果归一**。

| 能力 | 覆盖的既有动作 | 事实落点 |
|---|---|---|
| `查询必需预算项` | `资源监督器.必需预算键` | 纯静态表（不打开文件与连接） |
| `校验预算声明` | 「预算是否含全部必需项」判定 | 纯计算 |
| `校验预算阈值` | 「逐项取值本身是否有效」判定 | 纯计算（量纲/正整数/非负整数/超时） |

## 管什么 / 不管什么

**管**：必需预算项清单；一份预算声明**是否完整**（缺哪些项，逐项点名）；
预算**取值本身是否合法**（逐项给非法原因）。

**不管**（本轮明确排除）：

- **写类动作**（注册执行单元 / 提交任务 / 排空 / 优雅停止）与**运行中采样**：它们依赖进程内实例状态，不在本轮能力面；
- **不替调用方补默认值**：本包只判定「你给的预算合不合法」，不给默认预算、不做兜底。

## 失败如何表达

- `资源预算` 非字典型 → `参数不合法`（含明确说明「资源预算必须是字典型」）。
- **「预算不完整」与「阈值非法」是判定结论，不是失败**：返回 `成功=True`，用 `值.有效=false` +
  `缺失项` / `非法项` 逐项点名，让调用方能一次看全所有问题。
- 只有「判不了」（入参形状错）才是失败。这条与 `校验核心快照` 同一口径：
  **判定结论走返回值，故障走错误码**，两者不混。
