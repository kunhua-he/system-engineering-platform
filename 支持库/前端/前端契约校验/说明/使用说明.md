## 这个包是干什么的

`前端核心` 只定义契约（窗口/页面/组件/状态/事件/路由/调用/渲染），不绑定任何框架；
本包把它的**字段口径**做成可经唯一能力调用入口调用的**只读校验面**：调用方把一份
前端描述（页面定义 / 渲染请求 / 执行单元声明）传进来，拿回「结构是否合法 + 逐条问题」。

- 想校验自己的页面/窗口描述写得对不对：调 `校验页面定义` / `校验渲染请求`。
- 想校验执行单元声明（宿主类型、渲染方式、资源与后端能力依赖）：调 `校验执行单元声明`。
- 想知道字段与枚举取值有哪些（自检、做编辑器提示、生成表单）：调 `查询前端契约清单`。
- **不要**为了这件事去 import `前端核心/`：它是 0 个 `包声明.json` 的非正式目录
  （`开发文档/未完成事项.md` 条目 C-6），正式调用方只走能力面。

字段口径的唯一来源是 `前端核心/前端核心.py` 的五个数据类（组件定义 / 页面定义 /
窗口定义 / 执行单元声明 / 渲染请求）；本包与之一一对应，**不自创字段、不改默认值、
不扩枚举取值**。两处不一致时以 `前端核心.py` 为准。

## 怎么调用

只经唯一能力调用入口，按能力 id 调用（进程内装配见下；HTTP 见 `POST /网关/调用`）：

| 能力 id | 入参 | 返回 `值` |
|---|---|---|
| `支持库.前端.前端契约校验.校验页面定义` | `页面定义`（字典型，必填） | `有效` / `说明` / `问题列表` / `组件数` |
| `支持库.前端.前端契约校验.校验渲染请求` | `渲染请求`（字典型，必填） | `有效` / `说明` / `问题列表` |
| `支持库.前端.前端契约校验.校验执行单元声明` | `执行单元声明`（字典型，必填） | `有效` / `说明` / `问题列表` |
| `支持库.前端.前端契约校验.查询前端契约清单` | 无入参 | `契约清单` / `枚举表` / `数量` |

`有效=真` 表示结构合法（`问题列表` 为空数组）；`有效=假` 时 `问题列表` 逐条给出
「字段路径 + 原因」（如 `页面定义.组件列表[0].类型: 取值 '轮播' 不在 [...] 内`）。

## 成功与失败怎么分

**两条判据，互不混淆**：

1. **调用方传错** → 统一结果失败，错误码 `参数不合法`（网关侧 HTTP 400）：
   - 入参不是 JSON 对象（给文本、数字、列表、null）；
   - 入参含无法序列化为 JSON 的值；
   - 入参序列化后超过 256 KB（`能力定义.json` 的 行为.输入上限）。
2. **描述写错** → **不是失败**：返回成功结果 + `值.有效=假` + `值.问题列表`。
   结构不合法是**校验结论**，不是异常；用失败码顶替会让调用方分不清
   「我参数传错了」和「我的页面描述写错了」。

数量上限（`能力定义.json` 行为.输入上限）：单层列表项数（组件条数 / 页面条数 /
各资源与依赖项数）≤ 1000，超限按问题逐条报出（不静默截断）。

## 各字段的合法形态（口径来自 前端核心.py）

| 契约 | 必填 | 可选（缺省即取数据类默认值） |
|---|---|---|
| 组件定义 | `组件id` | `类型`（文本/输入框/按钮/列表/状态区，默认「文本」）、`属性`（字典型）、`事件`（文本列表） |
| 页面定义 | `页面id` | `路由`、`标题`（文本型）、`组件列表`（组件定义列表） |
| 窗口定义 | `窗口id` | `标题`、`页面列表`（页面定义列表）、`资源需求`、`后端能力依赖`（文本列表）、`状态`（已创建/已打开/已关闭，默认「已创建」） |
| 执行单元声明 | `执行单元id` | `宿主类型`（测试/浏览器HTML/桌面）、`渲染方式`（纯文本/HTML/原生）、`输入资源`、`导出窗口`、`导出事件`、`后端能力依赖` |
| 渲染请求 | `窗口id` | `标题`（文本型）、`状态表`（字典型）、`宿主类型`（测试/浏览器HTML/桌面） |

- **渲染请求的 JSON 形态只有一种**：`前端核心.渲染请求.转字典` 的四个扁平键
  （`窗口id` / `标题` / `状态表` / `宿主类型`）。`前端核心` 没有给 `窗口定义` 定义
  `转字典`，所以本包**不收**嵌套写法（同一字段两种合法形态就是口径漂移）；
  传了 `窗口定义` 之类的额外键会被逐条报成「不在前端核心 口径内（拒绝自创字段）」。
- 未知字段一律报问题，不静默忽略——前端描述的额外键通常正是口径漂移的证据。

```bash
PY
```

- 独立脚本里**不能**直接 `获取能力调用器()`：未装配会报 `E未装配`；进程内必须经
  `后端核心(系统根).启动()`（见 `开发文档/项目说明.md`「唯一调用腿」）。

- 本机没有 `timeout`/`gtimeout`；要限时用 `python3.14 subprocess(timeout=…)`。

## 错误码表

| 错误码 | 触发条件 | 网关 HTTP |
|---|---|---|
| `参数不合法` | 入参不是 JSON 对象 / 含非 JSON 值 / 超过 256 KB / 必填参数缺失 | 400 |

结构不合法**不产生错误码**（走成功结果 + `值.有效=假`），因此本包声明的错误码只有
`参数不合法` 一个（见 `能力定义.json` 的 `错误码`）。
