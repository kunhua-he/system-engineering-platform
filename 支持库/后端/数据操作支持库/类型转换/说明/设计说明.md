## 类型校验的唯一事实源（2026-09-16 修 P0；2026-09-19 E-8 收口至 16 型全覆盖）

`校验类型` 是「只检查，不转换」的原子能力，但它**不拥有任何类型边界**：16 个正式
类型的判据**全部**委托 `公共契约`，本包一行边界都不写（`委托校验表` 12 键 + 数值四型）。

| 目标类型 | 判据来源（唯一事实源） | 本包代码 |
| --- | --- | --- |
| 整数型 / 长整数型 / 单精度数型 / 双精度数型 | `公共契约/基础类型/数值类型.py::校验数值类型`（32/64 位边界、IEEE 754 binary32 可编码、拒绝布尔混入整数） | 仅转发 |
| 逻辑型 | `公共契约/基础类型/逻辑类型.py::校验逻辑类型` | 仅转发 |
| 文本型 | `公共契约/基础类型/文本类型.py::校验文本类型` | 仅转发 |
| 列表型 / 字典型 | `公共契约/基础类型/集合类型.py::{校验列表类型, 校验字典类型}` | 仅转发 |
| 字节型 / 字节集型 | `公共契约/基础类型/二进制类型.py::{校验字节类型, 校验字节集类型}` | 仅转发 |
| 日期时间型 | `公共契约/基础类型/时间类型.py::校验日期时间类型`（ISO-8601 可解析，任意文本不算） | 仅转发 |
| JSON值型 | `公共契约/基础类型/JSON类型.py::校验JSON值类型`（拒绝 NaN／Infinity／非文本键） | 仅转发 |
| 空值型 | `公共契约/基础类型/空值类型.py::校验空值类型`（唯一合法值 = `空值`） | 仅转发 |
| 资源引用型 | `公共契约/基础类型/资源引用类型.py::校验资源引用类型` | 仅转发 |
| 结果型 | `公共契约/基础类型/结果类型.py::校验结果类型` | 仅转发 |
| 句柄型 | `公共契约/句柄体系.py::校验句柄型`（六位数字句柄 或 进程内可调用句柄；唯一强度判定） | 仅转发 |

**E-8 收口前后对比（实测）**：收口前 `委托校验表` 只有 2 项 ＋ 数值 4 型 = **6/16**，
其余 10 型一律回「缺公共契约校验层」（带 `详情={"目标类型":…,"缺口":"公共契约缺校验层"}`）。
收口后 **16/16 全覆盖**，那 10 型现在给出真实判定。

失败口径：**只有非正式类型名会失败**，返回 `参数不合法`（HTTP 400），说明为
`未知目标类型：X`（空文本 / 非文本另报 `目标类型必须是非空文本`）。
`详细信息.缺口 = 公共契约缺校验层` 这一形态**已不存在**——不再有为它留的分支。

验收：`测试中心/支持库/核心/测试_类型校验十六型覆盖.py`（16 型逐型正例放行 +
反例拒绝，并断言 `案例表` 与 `公共契约/基础类型/类型表.py:正式类型表` 等宽）。

`值` 参数的声明类型从 `字典型` 改为 `JSON值型`：`字典型` 会让网关 HTTP 边界先按
字典校验，把 `2**40`、`1e300`、`真` 这类待校验值在入参处就拒掉，形成
「HTTP 拒、进程内放行」的第二套强度；`JSON值型` 是正式类型表里「任意 JSON 值 + 有校验」的类型，
与「校验任意值」的语义一致，参数名/顺序/必填/返回形状全部未变。

> 历史缺陷（已修）：本包曾自带一张 `{类型名: Python 类型}` 表，数值四型只做
> `isinstance` 无边界 → `校验类型(2**40, "整数型")` 判 `真`，而网关 HTTP 边界与
> `公共契约.基础类型.数值类型.校验数值类型` 判 `假` → 同一个正式类型名两套强度，
> 走 HTTP 被拒的值走能力调用却放行，等于契约被绕道。
