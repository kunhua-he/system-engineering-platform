## 为什么这样切（设计哲学与边界权威）

本包由原 `开发工具/组件规范/`（7 文件 / 1501 行）**整体下沉**而来，2026-09-16 落地。

**下沉的理由**：这 7 个文件只依赖 `json/pathlib/typing/hashlib/uuid/re/sys/os` +
`公共契约`（`正式根.存在根名`、`结果类型`、`版本规则.契约版本`）+ 同层 `支持库.适配层.内容摘要`，
**零第三方、零上层依赖**；但它原先挂在 `开发工具/`（层表里的终端层——没有任何层能依赖它），
于是：

- `模块库/组件生成/实现/组件生成.py` 只能**反向越层**（生产层 → 终端层），是全平台唯一一条这种方向的越层；
- 8 个下游被它栓在终端层，其中「唯一摘要生成器」还被生成链、契约编译器、发布门禁、依赖生命周期审计共 8 处引用。

落点选在 `支持库/后端/组件规范支持库/`（与 `正则表达式支持库`/`编码转换支持库` 同形的单层支持库包），
依据是**能力最小归属**：本包做的是「组件包的结构规范校验 + 文件清单完整性摘要 + 模板生成」，
全部是对**文件与文本**的最小原子动作，不含业务逻辑，不组装别的原子能力，符合「支持库＝最小原子能力」。
不选 `模块库`：本包不组合任何其他能力；不选 `支持库/适配层`：本包零第三方，没有要翻译的外部接口。

## 管什么

- **完整性摘要（唯一口径）**：`实现/完整性摘要.py` 是**全平台唯一**的文件清单 sha256 生成器与校验器，
  格式 `{包id, 版本, 摘要算法, 文件清单[{路径, sha256}]}`（+由能力定义派生的 能力数/能力清单/能力定义摘要）。
  `生成完整性摘要` **只计算不写盘**，写盘由调用方决定；`校验完整性摘要` 拒绝旧格式、算法缺失、
  截断摘要（必须 64 位十六进制）、路径越界与清单不闭合。
- **九要素组件规范校验**：`实现/组件规范.py` 校验 包声明/能力契约/依赖契约/配置契约/权限契约/执行单元/
  验证场景/说明书/完整性摘要，类型只认 `支持库|基础模块|功能模块|项目代码`。
- **模板生成**：`实现/模块模板生成器.py`（模块包 + 定向测试骨架，经 `获取能力调用器().调用能力` 组合支持库能力）、
  `实现/支持库模板生成器.py`、`实现/技能模板生成器.py`、`实现/核心快照模板.py`（快照清单/摘要/激活指针骨架）。
- **说明书生成**：`实现/说明书生成器.py` 由包内数据源生成 `<输出根>/说明/使用说明.md`，拒绝覆盖已有文件。

## 能力面划分判据（2026-09-16 补齐 C-13 前半，能力面 3 → 10 条）

`实现/` 里的对外函数按下面三条判据决定**切不切成能力**，不为文件数凑能力、也不留半边能力面：

1. **只读/纯计算类且生产侧有真实消费方 → 必切**。
   `校验组件规范`（消费方：`开发工具/组件合规/合规测试包.py`、`开发工具/复用审计/反向破坏/破坏验证.py`）
   与 `校验快照模板` 属这一类。判据是「调用点真的在跑」，不是「函数看着有用」。
2. **文件产出类若已有同类先例能力 → 必切**（同类不齐 = 半边能力面）。
   先例是 `生成模块模板`，故同族的 `生成支持库模板`、`生成技能模板`、`生成快照清单模板`
   一并切；写盘型 `生成并写入完整性摘要` 是只读 `生成完整性摘要` 的写盘配对（生产消费方：
   `开发工具/全量重算摘要.py` 等终端层工具走同一落点），`生成说明书` 与债务 C-13 的第二半
   （`开发工具/MD文档生成/说明书/` 第二套入口）直接相关，两条都切。
3. **纯内部原子 → 保持内部不切**（仍从入口导出为 Python 函数，只是不注册成能力）。
   未切 5 条与理由：
   - `是否应当收录` / `计算文件摘要`：`生成完整性摘要` 的**内部步骤**，独立调用没有独立语义
     （谁调用谁都得自己拼摘要格式），切出去等于把唯一生成器拆成两半。
   - `读取数据源` / `收集能力`：`生成说明书` 的**内部步骤**，返回的是中间数据结构，
     契约无处可依（形状随数据源变化），切出去会把内部形状冻成对外契约。
   - `校验输出目标`：`生成说明书` 的**前置校验步骤**（拒绝覆盖 + 拒绝路径逃逸），
     它的失败语义已由 `生成说明书` 的 `已存在`/`路径逃逸` 两个码覆盖，独立能力只会复制同一判定。
   - `扫描正式包`（可选判据项，**决定不切**）：虽然纯只读且语义独立，但它的消费方只有
     `开发工具/MD文档生成/说明书/完整性摘要生成器.py`（该目录属 C-13 第二半，与包内同名
     `实现/说明书生成器.py` 的关系属 D-13「两个同名 `说明书生成器.py` 并存」，现行裁决
     = **单独立项、本轮不动**，出处 `开发文档/方案/结构债处置方案_20260916.md` D-13；
     两套生成器的输入/产出/落点分工见 `开发文档/规范/说明书权威分工与维护规约.md` 第三节），
     一旦该目录不再有生产消费方，切出来会立刻变成**零引用能力**（违反判据 1 的「有真实消费方」）。
     等第二半落定，若仍有调用方需要，再按判据 1 补切。同族的 `迁移旧格式摘要` 同理不切
     （它是全仓一次性迁移工具，非调用面）。

## 不管什么

- 不写业务逻辑、不组合其他支持库能力、不持有句柄与跨调用状态（见 `生命周期契约.json`）。
- **不写盘型摘要**：`生成完整性摘要` 返回数据、不落盘；需要落盘的调用方自行 `write_text`
  （写盘配对已能力化为 `生成并写入完整性摘要`，供终端层工具与模板生成器使用）。
- **能力面已按判据切齐（3 → 10）**：`生成说明书` 与 `校验组件规范` 之后有终端层消费方，
  在同一批切出（能力面判据与未切内部原子的理由见上节「能力面划分判据」；两套说明书
  生成器的权威分工见 `开发文档/规范/说明书权威分工与维护规约.md`）。
- 不导入任何上层（`模块库/运行核心/平台控制面/开发工具`），不导入第三方；第三方相关（`支持库.适配层.内容摘要`）
  是同层既有依赖，保持原样。

## 失败如何表达

能力层（`实现/组件规范支持库.py`、`实现/模板能力.py`、`实现/说明书能力.py`、`实现/包装辅助.py`）
统一返回 `结果`：`参数不合法` / `包目录不存在` / `包无正式文件` / `已存在` / `路径逃逸` / `写入失败` /
`摘要生成失败`；模板生成失败码（`类型不合法`/`能力重复`/`无提供者`/`路径逃逸`/`已存在`）由内部实现原样透传，
不吞异常、不降级、不伪造成功。

**内部实现自带码的收敛规则（错误码硬约束）**：包装层返回的码必须已存在于网关
`公开错误码状态映射`，否则网关回落 500（六环门禁「能力定义声明码 ⊆ 状态映射码」会红）。
内部实现里几个**未登记**的历史码在 `实现/包装辅助.py::统一失败码表` 做等义收敛，不新增网关码：

| 内部实现自带码 | 收敛后的登记码 | 语义 |
|---|---|---|
| `同名能力` | `能力重复` | 同名能力重复 |
| `文件已存在` / `已存在文件` | `已存在` | 目标已存在、拒绝覆盖 |
| `参数无效` | `参数不合法` | 调用方输入非法 |
| `快照损坏` | `写入失败` | 快照写入失败（可重试） |
| `未实现` | `能力不存在` | 骨架占位实现尚未落地 |
