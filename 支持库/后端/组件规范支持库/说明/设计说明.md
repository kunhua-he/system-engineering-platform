# 组件规范支持库（支持库.后端.组件规范支持库）

## 为什么这样切（设计哲学与边界权威）

本包由原 `开发工具/组件规范/`（7 文件 / 1501 行）**整体下沉**而来，2026-09-16 落地。

**下沉的理由**：这 7 个文件只依赖 `json/pathlib/typing/hashlib/uuid/re/sys/os` +
`公共契约`（`正式根.存在根名`、`结果类型`、`版本规则.契约版本`）+ 同层 `支持库.适配层.内容摘要`，
**零第三方、零上层依赖**；但它原先挂在 `开发工具/`（层表里的终端层——没有任何层能依赖它），
于是：

- `模块库/组件生成/实现/组件生成.py` 只能**反向越层**（生产层 → 终端层），是全平台唯一一条这种方向的越层；
- 8 个下游被它栓在终端层，其中「唯一摘要生成器」还被生成链、契约编译器、发布门禁、依赖生命周期审计共 8 处引用。

落点选在 `支持库/后端/组件规范支持库/`（与 `正则表达式支持库`/`编码转换支持库` 同形的单层支持库包），
依据是**能力最小归属**：本包做的是「组件包的结构规范校验 + 文件清单完整性摘要 + 模板生成」，
全部是对**文件与文本**的最小原子动作，不含业务逻辑，不组装别的原子能力，符合「支持库＝最小原子能力」。
不选 `模块库`：本包不组合任何其他能力；不选 `支持库/适配层`：本包零第三方，没有要翻译的外部接口。

## 管什么

- **完整性摘要（唯一口径）**：`实现/完整性摘要.py` 是**全平台唯一**的文件清单 sha256 生成器与校验器，
  格式 `{包id, 版本, 摘要算法, 文件清单[{路径, sha256}]}`（+由能力定义派生的 能力数/能力清单/能力定义摘要）。
  `生成完整性摘要` **只计算不写盘**，写盘由调用方决定；`校验完整性摘要` 拒绝旧格式、算法缺失、
  截断摘要（必须 64 位十六进制）、路径越界与清单不闭合。
- **九要素组件规范校验**：`实现/组件规范.py` 校验 包声明/能力契约/依赖契约/配置契约/权限契约/执行单元/
  验证场景/说明书/完整性摘要，类型只认 `支持库|基础模块|功能模块|项目代码`。
- **模板生成**：`实现/模块模板生成器.py`（模块包 + 定向测试骨架，经 `获取能力调用器().调用能力` 组合支持库能力）、
  `实现/支持库模板生成器.py`、`实现/技能模板生成器.py`、`实现/核心快照模板.py`（快照清单/摘要/激活指针骨架）。
- **说明书生成**：`实现/说明书生成器.py` 由包内数据源生成 `<输出根>/说明/使用说明.md`，拒绝覆盖已有文件。

## 不管什么

- 不写业务逻辑、不组合其他支持库能力、不持有句柄与跨调用状态（见 `生命周期契约.json`）。
- **不写盘型摘要**：`生成完整性摘要` 返回数据、不落盘；需要落盘的调用方自行 `write_text`
  （唯一例外是同包 `生成并写入完整性摘要`，供模板生成器内部使用）。
- 不提供「生成说明书」能力化（现有下游只用函数，未走能力调用），故**只能力化 3 个真正对外要用的原子动作**，
  不为 7 个文件凑 7 个能力。
- 不导入任何上层（`模块库/运行核心/平台控制面/开发工具`），不导入第三方；第三方相关（`支持库.适配层.内容摘要`）
  是同层既有依赖，保持原样。

## 失败如何表达

能力层（`实现/组件规范支持库.py`）统一返回 `结果`：`参数不合法` / `包目录不存在` / `包声明不可读` /
`包无正式文件`；模板生成失败码（`类型不合法`/`能力重复`/`无提供者`/`路径逃逸`/`已存在`）由内部实现原样透传，
不吞异常、不降级、不伪造成功。
