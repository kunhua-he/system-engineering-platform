## 安全口径：敏感值默认脱敏

**为什么**：列/读类能力若把 `os.environ` 与任意 `.env` 明文回显，就让「持有网关
凭证的调用方」能一次调用把网关凭证本身原文取回来（凭证自举），并把宿主进程里
全部密钥横向带走。安全边界不能只靠调用方自觉，必须由能力自身兜底。

**口径**（默认脱敏、显式索取才给明文）：

- **敏感键白名单**：键名（忽略大小写、含子串即命中）命中 `敏感键关键词表`
  ——`KEY / TOKEN / SECRET / PASSWORD / PASSWD / PWD / CREDENTIAL / AUTH /
  凭据 / 凭证 / 密钥 / 私钥 / 口令 / 密码`——即视为敏感键。含中文凭据命名，
  覆盖平台自有的「系统库网关凭证」这类非英文键名。
- **默认掩码**：敏感键的值以 `***`（`默认掩码`，与适配层密钥提供者同口径）
  回显；空值原样返回空串，不伪造「有值」。
- **可选项**：`包含敏感值: 逻辑型 = False`（非必填、缺省 False）。缺省即脱敏，
  需要明文时由调用方显式传 `包含敏感值=True`；不传不影响旧调用。
- **只脱敏回显，不影响语义**：`读取环境文件(写入进程=True)` 写入 `os.environ`
  的仍是文件里的真实值——加载 `.env` 的功能不因脱敏而失效。
- **命中范围**：`获取环境变量` / `列出环境变量` / `读取环境文件`；键名照常列出
  （可见性不变），只掩掉值。`设置环境变量` 回显的是调用方自己传入的值，不涉泄露。

**边界与残余风险**（本包不自称解决）：

- 只按**键名**判断，键名不敏感但值恰是密钥的场景不覆盖（如 `FOO=<sk-...>`）；
- `包含敏感值=True` 本身仍是一条明文出口——真正的收口要由网关/权限契约按调用方
  身份决定是否放行该参数，本包只提供「默认安全、显式放开」的机制；
- 键名可见意味着「哪些密钥存在」仍会暴露，这是白名单口径的取舍。

**验证口径**：脱敏是纯函数行为（`是敏感键` / `_回显值`），不依赖外部服务；
场景验证见同包 `验证场景/正向HTTP场景.json`（键名 `P20_GROUP7_TEST_ENV_7F3A91`
不含敏感关键词，断言值不受脱敏影响）。
