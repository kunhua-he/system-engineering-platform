## 安全阻断决策记录（批次1-1 · S-01 / S-12 / S-06）

> 本节是本次安全修复的口径权威：为什么这样改、边界在哪、逆向验证怎么复现。改动随包版本 1.1.3 生效。

### S-01 · 沙箱 profile 注入（SBPL 注入）—— 已修

- **结构化拼装**：`实现/进程管理.py::_sbpl字面量` 是 profile 内唯一转义点
  （`\` → `\\`、`"` → `\"`、换行/回车 → 转义序列）；`_构建沙箱配置` 只用「已转义字面量」
  拼 `(subpath …)` / `(literal …)` 子句再逐行 join，函数体内不再把原始路径插值进 profile 文本。
- **入口拒绝（fail-closed）**：唯一校验点 `沙箱执行命令` 在 `resolve()` 之后拒绝含
  `"` `\` `\n` `\r` `)` 的工作目录，返回 `参数不合法`。
  代价：合法但含 ASCII `)` 的目录名也被拒（换取 profile 结构不可能被路径改写）。
- **边界**：`启动进程` / `执行命令` 不经沙箱，不受本条约束。

### S-12 · profile 语法错仍报成功 —— 已修

- **早失败**：非法字符在构造 profile 之前就被拒，不再让 `sandbox-exec` 退出 65 后由调用方猜。
- **编译预检**：`_预检沙箱配置` 在跑真实命令前先用 `/usr/bin/true` 编译一次 profile；
  编译失败 → `执行失败`（fail-closed），绝不让「根本没执行」被报成 `成功=True`。
- **口径不变**：命令自身非零退出码仍以 `值.成功执行=False` + `值.退出码` 如实表达，
  `结果.成功` 只表示「能力执行完成」。

### S-06 · 检测危险命令未接线 —— 选择「接入执行路径」

- **选择接线、不删除**。理由：实现落在 `命令安全` 包（不在本包属主域），删除要跨包动实现与
  能力注册；而该检测是平台自述的高风险前置策略，接线才兑现设计意图。
- **接法**：经唯一能力调用服务取 `系统核心支持库.命令安全.检测危险命令`
  （`公共契约.能力契约.调用器`）——不在支持库之间直接 import、不导入任何 `实现/` 目录，
  不引入新的依赖方向违规。能力级依赖登记在该包 `包声明.json` 的 `依赖`
  （`{"能力": "系统核心支持库.命令安全.检测危险命令", "版本": ">=1.0.0"}`）。
  **注意**：重新编译本包时必须把该依赖一并传给 `编译能力定义`，否则会被 `依赖: []` 覆盖。
- **接线点**：`执行命令`（参数校验后、起进程前）、`沙箱执行命令`（工作目录校验后、构造 profile 前）；
  命中返回 `危险命令`。
- **不接线**：`启动进程`——argv 直启、不经 shell，没有「命令文本」可判，按落点建议不默认拦截。
- **降级口径**：检测器不可用时留痕放行（模块级 `危险命令检测问题`），不回退成拦截。
  理由：检测是纵向加固层，边界是内核沙箱与进程组回收；未经加载器装配的直连场景
  （单测/脚本/工具链）取不到调用器，若这里 fail-closed 会打断既有正常调用。
- **网关映射待登记（跨域）**：`危险命令` 尚未出现在网关 `公开错误说明表` /
  `公开错误码状态映射`（与 `目录不存在` / `沙箱不可用` / `执行失败` 同属能力级表外码），
  经网关调用当前落 HTTP 500。待网关域登记 `危险命令 → 403` 时，**同一提交**把
  `验证场景.json` 中「危险命令前置拦截」步骤的预期状态码从 500 改为 403。

## 句柄生命周期能力统一口径（#93）

全仓「句柄续租」有 2 条实现腿、「句柄释放」有 7 条实现腿 —— 同一件事在各包各写一遍。
形状不一致时，调用方必须按包名分支处理，同一个动作在多包各记一套口径。本包按 #93 收口，
**只保留一套对外形状**。

> 下面是**设计口径**（为什么这样定、边界在哪）。参数表 / 返回结构 / 错误码的机器权威是
> `能力定义.json`，调用口径以同目录 `使用说明.md` 为准 —— 本文不复制调用口径。

| 族 | 口径名 | 参数 | 成功值键 | 错误码 |
| --- | --- | --- | --- | --- |
| 句柄续租 | `续租句柄` | `句柄`、`租约秒` | `句柄`、`已续租`、`超时秒` | `参数不合法` / `句柄失效` |
| 句柄释放 | `释放句柄` | `句柄` | `句柄`、`状态`、`已释放` | `参数不合法`（领域码另计） |

**为什么选「续租」这个词**（少数服从多数，不新造第三套）：全仓既有租约能力用「续租」
（`平台控制面.能力目录.续租文件租约`、`资源续租`、权威状态 `续租租约`、`资源句柄服务.续租`），
用「续约」的只有 `会话存储` 一条腿 —— 故语汇统一到「续租」。释放一族的 6 条能力腿本就同名
`释放句柄`（`组件控件`／`会话存储`／`模型连接器`／`并发控制`／`进程管理`／`数据结构`），
统一的是**参数名**（历史上一处写 `句柄id`）与**返回键集合**。
**同形状同词表者一并收敛**：`浏览器自动化.关闭会话`（返回键与 `状态` 取值与释放族逐字相同）、
`语义索引.嵌入` 的本地转调函数（由 `释放句柄` 改名 `释放模型句柄` 消歧，它只转调、不复制实现）。
`状态` 词表两值：真正释放 `已释放`，幂等空转 `未找到且已幂等`；旧值 `已结束并已释放` 本轮全仓收敛。

**能力名（能力 id 末段）本轮不归一，理由与解封条件**：
能力 id 受「只增不改」冻结门禁保护（`开发工具/能力id冻结基线门禁.py`：基线里有、当前没有的 id
＝被删或被改名 ⇒ 判红），而编译器把**实现函数名绑定到能力 id 末段**
（`能力契约编译/能力定义编译器.py:418` `函数名 = 能力id.split(".")[-1]`）——
即能力 id 一改，实现函数名、`__init__` 生成入口、注册表同步全动。
`开发文档/项目证据/能力id冻结基线_交付说明.md` §5 明文：本门禁**只冻结存在性、不裁决命名**，
「id 命名规范定稿后按 `--冻结` 重建基线一次」。故能力名的归一**登记为待办**，
待「id 命名规范」落地后随基线重建一并做；本轮只统一形状与语汇。

**语义边界**：
- 续租只重置最后活动时间；`租约秒 > 0` 时同时覆盖超时秒，缺省只重置倒计时。
  对已失效（超时/已释放）句柄**拒绝复活**，回 `句柄失效` —— 不许把「续租」当复活手段。
- 释放是**幂等**的：句柄不存在或已释放一律成功，`状态` 取 `未找到且已幂等`；
  本次真正释放时 `状态` 取 `已释放`。只有句柄不是 1–999999 的整数才回 `参数不合法`。
- 释放的「没收敛」不算成功：领域内若资源账本必须保留（如线程池/本地模型进程未退），
  回 `资源未收敛`（可重试）并**保留账本**，不许改判成功。
- 本包的续租/释放**只作用于本包自己的句柄表**，不跨包代办。跨包的统一门面
  （按句柄类型分派的续租/释放入口）是 `模块库/测试资源/说明/待补能力清单.md` 第 3 项
  登记的底座缺口，不在本包职责内。

**本包落点**：`释放句柄` 值结构由 `{句柄, 已释放}` 补齐为 `{句柄, 状态, 已释放}`。
本包是**强制终止残留进程**的领域腿（进程组 `killpg`），语义比通用释放更重，
但对外形状与同族完全一致，调用方无须按包分支。
