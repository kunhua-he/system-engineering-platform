# 统一检索 · 使用说明

## 这是什么

把平台已有的多路检索（能力层 / 符号层 / 文本层）用 **RRF 倒数排名融合**合成**一个入口**，
只返回你要的条数。纯算术、不用模型、可复现。

## 为什么要它

单路各有毛病（实测）：

| 路 | 性格 | 证据 |
|---|---|---|
| 能力层·搜索能力 | 又准又克制 | 期望 1 条时精确率/首条/召回均 1.0 |
| 符号层·代码地图 | 找得到但爱给多 | 召回 0.8→0.93 时精确率 0.8→0.45 |
| 文本层·正则搜索 | 克制但漏 | 精确率 0.9、召回仅 0.6 |

RRF 只看**排名**不看分数，把「在多路里都排前面」的条目顶上来，
正好是你要的那一个；各路分数量纲不同也不用归一化。

## 怎么调

```json
{
  "能力id": "检索支持库.统一检索.统一检索",
  "参数": {"关键词": "读取文件", "期望条数": 1}
}
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| 关键词 | 是 | — | 检索词；能力层按说明匹配、符号层按名称子串、文本层按正则 |
| 期望条数 | 否 | 1 | **调用方本来想要几条（1~50）** |
| 候选深度 | 否 | 50 | 每路取多少候选再融合（1~200） |
| 路权重 | 否 | 默认表 | 覆盖各路权重，如 `{"文本层": 0.3}` |
| 项目根 | 否 | 自动推断 | 项目根绝对路径 |
| 代码地图路径 | 否 | 项目根/.codegraph/codegraph.db | 代码地图 SQLite 路径 |
| 网关地址 / 凭证 | 否 | 默认 40007 / 读网关配置 | 一般不用传 |

## ★ 精确率口径（2026-09-21 华哥定，最重要的一条）

> 搜得出来是一回事，搜出来了、哪一个才是你想要的。
> 返回 10 条里只有 1 条是你要的，准确率是 **10%**，不是 100%。
> 只返回 1 条且就是你要的，才是 **100%**。

所以 **精确率 = 命中题数 / 全部返回条数**，「给几条」是硬参数：
默认 1 条；确实需要多个选择时才调大（相当于「1 个决策 + N 个附属」）。

## 返回

| 字段 | 说明 |
|---|---|
| 命中列表 | 有序 `[{身份, 摘要, 得分, 命中路数, 各路排名}]` |
| 命中数 | 融合去重后总数（不随期望条数变） |
| 已截断 | 命中数 > 返回条数 时为真 |
| k常数 | 本次生效的 RRF k（默认 60） |
| 路权重 / 各路候选数 / 各路明细 | 便于定位「哪一路没出东西、为什么」 |

`命中路数` 与 `各路排名` 告诉你**为什么它排第一**：在多路里都靠前的条目得分自然高。

## 出错怎么看

- 单路失败**不中断整轮**：该路候选为空，原因在 `各路明细.<路名>.错误码/错误说明` 里。
- 关键词为空 → `参数不合法`；网关不通 → `网关不可达`。

## 已知边界

- 文本层用的是正则，不是全文检索：关键词里带正则特殊字符会被当元字符解释。
- 符号层依赖代码地图已建；地图不存在时该路候选为 0（不报错）。
- 本能力**不重复实现任何一路**，只做召回与融合；新增一路只需改 `实现/召回.py`。
