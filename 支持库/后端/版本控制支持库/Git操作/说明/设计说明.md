## 定位与边界

一个第三方外部命令（git）只对应一个独立支持库、一个受管提供者：本库只提供**原子能力**
（单条 git 命令 + 参数/返回/错误转换 + 资源释放），不做仓库业务组合（多步流程由模块库组装）。

- 管：worktree 建/查/关、提交、**推送**、回滚、挑拣合入、切换分支、合并分支、状态摘要、提交哈希、分支名工具。
- 不管：业务分支策略、评审/合并审批、跨仓编排。**远端交互只做 `推送` 一条**（2026-09-21 补：
  此前只到本地 `提交`，「提交到 GitHub」的第二步永远只能回终端 —— 一半在能力里、一半在终端外，
  是最典型的半截子封装；补上后 改文件→提交→推送 整条链路都留在能力面内）。**fetch/pull 仍不做**
  （拉取会把远端变更混进本地工作区，属「谁来裁决合并」的编排问题，归模块库，不在原子能力层）。
- `回滚` = git revert、`挑拣合入` = git cherry-pick，**都不冒充** `合并分支`（git merge）
  与 `切换分支`（git switch）——后者是本轮补的独立原子能力。

## 安全边界（唯一实现点）

1. **结构化参数白名单**（`实现/白名单.py`）：分支名/起始点/提交哈希/路径/消息/超时全部先过白名单，
   拒绝 空格/换行/`;|&连续反引号$` 等 shell 元字符；路径必须是绝对路径，且提交路径必须解析后落在仓库内。
2. **仓库根白名单**（`实现/仓库根白名单.py`）：`提交`、`切换分支`、`合并分支` 三个变更类能力在
   执行前先校验**仓库根**，白名单外一律 `路径越界`。事实源是 `MCP工具箱/工作区管理.py:55-86`
   （`_提交根白名单`/`_校验提交根`）——该处注释（`工作区管理.py:73-77`）写明修复前的漏洞：
   入口把调用者传入的 path 直接当项目根，可对**任意** Git 仓执行 `git add -A` + `commit`、
   `switch` + `merge`。按哲学第 34 条「安全边界必须落在能力层」，该防护必须由能力层自己持有，
   只留在工具层的话，换门（AI 直调能力）即把漏洞重新打开。
   白名单 = 底座仓库根 + 环境变量 `工作区允许提交根`（`os.pathsep` 分隔，人工显式加白）
   + 系统临时目录（`工作区严格提交根`=1/true/yes/on 时关闭该放行）。
3. **分支名双校验**：新能力（`切换分支`/`合并分支`）在参数白名单之外再过 `实现/分支名安全.py`
   （git check-ref-format 常用子集：拒 `..`、`/.`、尾 `/`、尾 `.lock`、`-` 开头），
   任一道不过 → `参数不合法`。
4. **受管执行**（`实现/受管执行.py`）：全部 git 调用为 `subprocess` 参数列表（**禁 shell**），
   独立进程组 + 超时 SIGTERM→SIGKILL 回收 + 输出上限 4MB。

## 本轮补齐的 5 项缺口（G1–G5）

| 缺口 | 处置 | 口径 |
| --- | --- | --- |
| G1 切换分支 | 新增能力 `切换分支` | `git switch 分支名`，只切已存在的本地分支（不新建/不强制/不丢弃修改）；按真实探针确认切换后分支，返回 `{分支, 切换前分支}` |
| G2 合并分支 | 新增能力 `合并分支` | `git merge --no-edit 来源分支`；`目标分支` 缺省=当前分支，给值且不同则先切换再合并（等价 MCP `workspace` 的 switch+merge 一步口径）；冲突自动 `merge --abort` → `冲突` |
| G3 提交全量暂存 | `提交` 支持 `路径列表` 空/未给 | 空列表或未给 = `git add -A`（新增/修改/删除全部纳入），返回 `全量暂存=真`、`路径列表=[]`；非空仍逐条过越界校验 |
| G4 关闭工作区强制 | `关闭工作区` 增 `强制` | `强制=真` → `worktree remove --force`（显式承担丢弃未提交修改）；默认 `假` 保持「有未提交修改即拒绝」 |
| G5 仓库根白名单 | `提交`/`切换分支`/`合并分支` 前置校验 | 见上「安全边界」第 2 条，白名单外 → `路径越界` |

## 错误码口径

- 参数问题（含白名单/分支名格式）→ `参数不合法`；越界提交/合并/切换 → `路径越界`；
  仓库不存在 → `仓库不存在`；git 非零退出 → `命令失败`；revert/cherry-pick/merge 冲突 → `冲突`
  （且已自动中止恢复干净状态）；未提交修改拒绝关闭 → `未提交修改`；
  git 缺失 → `提供者不可用`；超时 → `超时`；输出超限 → `超出限制`。
- **不新造错误码**：白名单拒绝复用契约已登记、网关已定级的 `路径越界`（400），避免出现
  「网关侧未登记的码 → HTTP 500 + 错误说明泛化」这类半成品。
