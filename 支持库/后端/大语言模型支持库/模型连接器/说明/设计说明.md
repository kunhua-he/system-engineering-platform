## 大语言模型支持库.模型连接器.探测模型端点（探测模型端点）

**说明**：探测一个模型端点是否可用、走哪种协议。目的：调用方只给 url 与 api_key 即可，缺的参数自动补齐——第一步向端点取模型清单（未给模型时，用 `GET {url}/models`），第二步拿模型试协议（给了协议只打这一个；未给则按 chat_completions → codex_responses → anthropic_messages 依次试，命中即停）。可用性判据是响应体特征字段（choices / output / content+type），不看状态码。有一个成功即返回成功并列出其余协议的失败原因；三个全失败则如实返回三项失败原因。

**参数表**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| url | 文本型 | 是 | | 端点地址，如 http://127.0.0.1:11434/v1（原样使用，不自动改写根路径） |
| api_key | 文本型 | 否 | | 密钥；缺省用 123 占位（本地服务常不校验） |
| 模型 | 文本型 | 否 | | 模型名；缺省自动向端点取模型清单并用第一个 |
| 协议 | 文本型 | 否 | | 取值 chat_completions / codex_responses / anthropic_messages；缺省自动依次试三种、命中即停 |
| 超时秒 | 整数型 | 否 | 15 | 单次请求超时秒 |

**返回结构**：{'类型': '结果型', '值结构': {'可用': '逻辑型', '命中协议': '文本型', '模型': '文本型', '模型清单': '列表型', '响应毫秒': '双精度数型', '逐项结果': '列表型', '诊断': '列表型'}}（统一结果：成功/值/错误）

**错误码表**：

| 错误码 |
| --- |
| 参数不合法 |

**调用示例**：

```python
大语言模型支持库.模型连接器.探测模型端点(url="http://127.0.0.1:11434/v1", api_key="123")
```

**设计要点（实测钉死，改实现前必读）**：

1. **第一步取模型必须用 GET**：llama-server 对 `POST /v1/models` 返回 404（它的 POST 走 chat 路由）。
2. **判协议不能看状态码**：本地 llama-server 是「宽容服务器」，`/chat/completions`、`/responses`、`/messages` 全回 200；只有响应体特征字段能区分（choices / output / content+type）。
3. **`/models` 通 ≠ 该端点能聊**：实测某中转端点 `/v1/models` 返回 200，但 `/v1/chat/completions` 是 404。故两步结果分开如实报，不因第一步成功就报可用。
4. **不猜根路径**：url 原样使用；全失败时把试过的完整路径列在 `逐项结果.请求路径`，由调用方换 url 重试。
5. **失败必须分类**：连接失败（端点不可达）/ 鉴权失败（401、403）/ 路径不存在（404）/ 200 但无该协议特征（可能不是模型端点），不许笼统报「不通」。

**验证状态**：已纳入验证场景：验证场景.json（包级场景文件）
## 大语言模型支持库.模型连接器.记录模型调用（记录模型调用）

**说明**：记录一条模型调用，作为打分燃料。★ 本能力**不消耗任何 LLM 额度**——记录的是「已经发生过的调用」，模型调用由调用方自己完成后再把结果告诉本能力。

**目的**：底座原先没有任何「模型用量」记录（实测：会话表 0 行、成本统计非空 0 行、运行态六域无用量域），
而「哪个模型适合做什么任务、性价比、效率最高」必须有历史数据才算得出来。
本能力就是那个入口：先有记录，打分才有燃料。

**存储**：本包专用库（`运行数据根/大语言模型支持库.模型用量.db`），照 `会话存储`/`嵌入缓存` 同口径。
保留 `sqlite3` 直连的技术必要：连接按库路径缓存并跨线程复用；写入只能经事务执行，
而它的契约是「SQL 文本列表、无参数绑定」，模型名属调用方数据，拼进 SQL 会引入转义与注入面。

**参数**：`模型`（必填）、`成功`（必填，逻辑型）、`任务类型`、`耗时毫秒`、`输入令牌`、
`输出令牌`、`成本`、`端点`、`备注`、`记录id`、`数据库路径`。

**返回**：`已记录`/`记录id`/`累计条数`。

**错误码**：`参数不合法`（必填缺失、类型不符、负数）、`写入失败`。

**行为**：有副作用（落库）、幂等（按 记录id）、**不消耗额度**、可重试。

**边界**：只记录与统计，不调用任何模型；模型调用是调用方的职责。

## 大语言模型支持库.模型连接器.汇总模型表现（汇总模型表现）

**说明**：把用量记录汇总成可比较的表现指标（纯统计，**不消耗任何额度**）。

**为什么要单列**：华哥要的「性价比 / 效率最高」是可算量。把它单独成能力，
路由的排序才能被独立验证（固定数据 → 固定分数，可复现）。

**参数**：`候选清单`（必填）、`任务类型`（不给则汇总全部）、`最少样本数`（默认 3）、`数据库路径`。

**返回**：`汇总`（每项：模型/样本数/成功率/平均耗时毫秒/平均令牌/平均成本/是否样本充足）、
`数据条数`、`说明`。

**错误码**：`参数不合法`、`读取失败`。

**行为**：只读、幂等、纯统计不消耗额度。

**边界**：样本不足（低于最少样本数）**不给分**，只如实标注——不编造、不默认满信心。

## 大语言模型支持库.模型连接器.选择模型（选择模型）

**说明**：按历史实测表现把候选模型排序，给出建议与理由（**只读建议，不自动切换**）。

**三层设计（★ 默认只走前两层，零额度）**：

```text
第一层 硬门槛（永远执行）
    · 上下文超限 → 排除（依据：实测本地窗口 32768）
    · 候选端点不可达 → 排除（复用 探测模型端点）
第二层 统计打分（仅启用智能路由时）
    读用量记录 → 四维加权（成功率/效率/性价比/匹配度）→ 排序 + 理由
    ★ 不消耗额度：读的是本地记录，不调用模型
第三层 LLM 辅助标注（本版不实现，留参数位）
    若实现必须标注消耗
```

**打分口径**：

```text
对候选 m 在任务类型 t 下：
  样本数 n(m,t)   低于「最少样本数」→ 不给分，只标「样本不足」
  成功率 S = 成功次数 / n
  效率   E = 1 - min(平均耗时 / 基准耗时, 1)
  性价比 C = 1 - min(平均成本 / 基准成本, 1)
  匹配度 M = 该任务类型下的样本占比
  分数 = 0.4×S + 0.2×E + 0.3×C + 0.1×M
基准耗时/基准成本取「本次候选集合内」的中位数 —— 相对比较，不写死绝对值。
```

**参数**：`候选清单`（必填，字符串或 `{模型, 上下文长度, 端点}`）、`任务描述`、`任务类型`、
`上下文长度`、`启用智能路由`（默认假）、`参考路径`、`启用额度标注`（默认真）、`权重`、
`最少样本数`、`数据库路径`。

**返回**：`建议`、`排除`、`模式`（保守/智能）、`打分依据`、`额度说明`、`诊断`。

**错误码**：`参数不合法`、`读取失败`。

**行为**：只读、幂等、默认不消耗额度、可重试。

**两条边界（华哥 2026-09-18 口径）**：

1. **底座不做隐私/安全判断**（哲学 9.3）。`参考路径` 只是「用户自带规则的可选输入」：
   底座把该路径下的词原样取出当匹配模式，**不定义「什么是敏感」**。
   判据：换成任意普通词表（如品牌禁用词）机制完全一样可用 —— 说明它不是隐私专用件，
   而是通用的「外部规则输入」机制。
2. **候选清单由调用方传**，底座不存模型台账（否则成第二事实源）；
   只给建议，**不自动切换**正在用的模型。

**额度说明为什么默认开启**：华哥要求「这个会后台消耗 LLM 额度，需要给用户备注上」。
默认返回说明，避免调用方被消耗却不知情；只有显式传 `启用额度标注=假` 才清空。
（实测坑：写成 `if not 启用额度标注` 会让默认 `None` 也被判成假、说明恒为空，已修。）

## 句柄生命周期能力统一口径（#93）

全仓「句柄续租」有 2 条实现腿、「句柄释放」有 7 条实现腿 —— 同一件事在各包各写一遍。
形状不一致时，调用方必须按包名分支处理，同一个动作在多包各记一套口径。本包按 #93 收口，
**只保留一套对外形状**。

> 下面是**设计口径**（为什么这样定、边界在哪）。参数表 / 返回结构 / 错误码的机器权威是
> `能力定义.json`，调用口径以同目录 `使用说明.md` 为准 —— 本文不复制调用口径。

| 族 | 口径名 | 参数 | 成功值键 | 错误码 |
| --- | --- | --- | --- | --- |
| 句柄续租 | `续租句柄` | `句柄`、`租约秒` | `句柄`、`已续租`、`超时秒` | `参数不合法` / `句柄失效` |
| 句柄释放 | `释放句柄` | `句柄` | `句柄`、`状态`、`已释放` | `参数不合法`（领域码另计） |

**为什么选「续租」这个词**（少数服从多数，不新造第三套）：全仓既有租约能力用「续租」
（`平台控制面.能力目录.续租文件租约`、`资源续租`、权威状态 `续租租约`、`资源句柄服务.续租`），
用「续约」的只有 `会话存储` 一条腿 —— 故语汇统一到「续租」。释放一族的 6 条能力腿本就同名
`释放句柄`（`组件控件`／`会话存储`／`模型连接器`／`并发控制`／`进程管理`／`数据结构`），
统一的是**参数名**（历史上一处写 `句柄id`）与**返回键集合**。
**同形状同词表者一并收敛**：`浏览器自动化.关闭会话`（返回键与 `状态` 取值与释放族逐字相同）、
`语义索引.嵌入` 的本地转调函数（由 `释放句柄` 改名 `释放模型句柄` 消歧，它只转调、不复制实现）。
`状态` 词表两值：真正释放 `已释放`，幂等空转 `未找到且已幂等`；旧值 `已结束并已释放` 本轮全仓收敛。

**能力名（能力 id 末段）本轮不归一，理由与解封条件**：
能力 id 受「只增不改」冻结门禁保护（`开发工具/能力id冻结基线门禁.py`：基线里有、当前没有的 id
＝被删或被改名 ⇒ 判红），而编译器把**实现函数名绑定到能力 id 末段**
（`能力契约编译/能力定义编译器.py:418` `函数名 = 能力id.split(".")[-1]`）——
即能力 id 一改，实现函数名、`__init__` 生成入口、注册表同步全动。
`开发文档/项目证据/能力id冻结基线_交付说明.md` §5 明文：本门禁**只冻结存在性、不裁决命名**，
「id 命名规范定稿后按 `--冻结` 重建基线一次」。故能力名的归一**登记为待办**，
待「id 命名规范」落地后随基线重建一并做；本轮只统一形状与语汇。

**语义边界**：
- 续租只重置最后活动时间；`租约秒 > 0` 时同时覆盖超时秒，缺省只重置倒计时。
  对已失效（超时/已释放）句柄**拒绝复活**，回 `句柄失效` —— 不许把「续租」当复活手段。
- 释放是**幂等**的：句柄不存在或已释放一律成功，`状态` 取 `未找到且已幂等`；
  本次真正释放时 `状态` 取 `已释放`。只有句柄不是 1–999999 的整数才回 `参数不合法`。
- 释放的「没收敛」不算成功：领域内若资源账本必须保留（如线程池/本地模型进程未退），
  回 `资源未收敛`（可重试）并**保留账本**，不许改判成功。
- 本包的续租/释放**只作用于本包自己的句柄表**，不跨包代办。跨包的统一门面
  （按句柄类型分派的续租/释放入口）是 `模块库/测试资源/说明/待补能力清单.md` 第 3 项
  登记的底座缺口，不在本包职责内。

**本包落点**：`续租句柄` 本已是口径名，本轮只把说明文案统一到同一句；
`释放句柄` 的 `状态` 取值收成 `已释放` / `未找到且已幂等` 两值
（原写 `已结束并已释放`，与同族不一致），值结构申报补齐为 `{句柄, 状态, 已释放}`
（原申报漏了 `状态`，属申报漂移 —— 实现早已返回它）。
