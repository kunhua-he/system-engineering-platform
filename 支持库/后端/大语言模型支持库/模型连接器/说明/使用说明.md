# 模型连接器（支持库.后端.大语言模型支持库.模型连接器）

- 类型：支持库
- 版本：1.2.8
- 说明：模型连接器：LLM/向量/重排连接器 + 本地模型启动器，各返回六位句柄；其他能力持句柄调用模型。句柄默认 1800 秒无人使用自动释放，可续租/显式释放；系统内存占用超阈值（默认 80%）拒绝新连接（防撑爆内存）。本地（路径/启动器）与云端（url/api_key/模型/上下文长度）统一为连接配置。
- 入口：__init__.py
- 权威分工：**调用口径以本文为准**（能力/参数/返回/错误码/调用示例，由能力契约生成）；
  该库的设计哲学与边界见同目录 `设计说明.md`（设计权威）。

- 版本：1.0.0

- 所属支持库或模块：支持库.后端.大语言模型支持库.模型连接器

- 必填参数：重试模式

### 探测模型端点（`大语言模型支持库.模型连接器.探测模型端点`）
- 版本：1.0.0
- 一句话说明：探测一个模型端点是否可用、走哪种协议。目的：调用方只给 url 与 api_key 即可，缺的参数自动补齐——第一步向端点取模型清单（未给模型时，用 `GET {url}/models`），第二步拿模型试协议（给了协议只打这一个；未给则按 chat_completions → codex_responses → anthropic_messages 依次试，命中即停）。可用性判据是**响应体特征字段**（choices / output / content+type），不看状态码——宽容服务器对任意路径都回 200。有一个成功即返回成功并列出其余协议的失败原因；三个全失败则如实返回三项失败原因。不猜根路径：url 原样使用，全失败时列出试过的完整路径。
- 所属支持库或模块：支持库.后端.大语言模型支持库.模型连接器
- 参数列表：url:文本型, api_key:文本型, 模型:文本型, 协议:文本型, 超时秒:整数型
- 必填参数：url
- 可选参数：api_key, 模型, 协议, 超时秒
- 返回结构：{'类型': '结果型', '值结构': {'可用': '逻辑型', '命中协议': '文本型', '模型': '文本型', '模型清单': '列表型', '响应毫秒': '双精度数型', '逐项结果': '列表型', '诊断': '列表型'}}（统一结果：成功/值/错误码/错误说明）
- 错误码：参数不合法
- 调用示例：大语言模型支持库.模型连接器.探测模型端点(url=http://127.0.0.1:11434/v1, api_key=123)
- 依赖能力：无

**逐项结果字段说明**（用于诊断失败原因）：

| 字段 | 类型 | 说明 |
|---|---|---|
| 协议 | 文本型 | chat_completions / codex_responses / anthropic_messages |
| 请求路径 | 文本型 | 实际请求的完整地址（全失败时按此列表换 url 重试） |
| 状态码 | 整数型 | HTTP 状态码；连接层失败时为 null |
| 可用 | 逻辑型 | 该协议是否命中 |
| 判据 | 文本型 | 命中或失败的判定依据（连接失败 / 鉴权失败 / 路径不存在 / 无该协议特征 …） |
| 响应毫秒 | 双精度数型 | 该次请求耗时 |
| 回带模型 | 文本型 | 仅命中时出现，端点回包里的模型名 |

**判据要点（实测钉死）**：① 第一步取模型**必须用 GET**，`POST /models` 在 llama-server 上返回 404；② 判协议**不能看状态码**，本地 llama-server 对 `/chat/completions`、`/responses`、`/messages` 全回 200，只有响应体特征字段能区分；③ `/models` 返回 200 **不等于**该端点能聊——两者结果分开如实报，不因第一步成功就报可用。
