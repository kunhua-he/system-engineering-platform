## 能力

- `连接`：创建 SQLite 文件并完成 `SELECT 1` 探针。
- `查询`：执行参数化只读查询，返回 `行列表`。
- `事务执行`：按列表执行 SQL；任一语句失败全部回滚。
- `关闭`：声明调用内连接已释放。
- `初始化运行数据库`：创建底座运行库的六个运行态域表（任务、作业、协作状态、能力占用、灰度观测、灰度状态）与高频索引，重复调用幂等。
- `写入运行态`：按域写入一条运行态记录（`记录` 为字典型，`状态` 可由载荷自带），返回记录 `id` 与 `已写入`。
- `查询运行态`：按域查询运行态记录（可带 `条件` 与 `限制`），返回 `行列表` 与 `总数`。

## 约束

每次能力调用自包含连接生命周期，不返回连接对象或游标。调用者只能通过包级入口使用，不能导入 `实现/`。数据库路径由调用方提供，敏感 SQL 和路径不写入日志。

**运行库口径（华哥 2026-09-14 定盘）**：底座运行态一律入库，不再各写 JSON/JSONL；库文件统一放 `工程缓存/运行数据/`（默认 `底座运行.db`），支持库确需隔离时可有自己的库文件，但位置同样在该目录下，且**一律经本支持库访问**——禁止任何包自己 `sqlite3.connect` 直连。不可变证据（HTML 验证证据、发布证据、清理失败证据）仍按文件保存，不入库。

**域清单只收「有真实生产写入侧」的域（2026-09-15 审计删域）**。`_创建运行库表` 按 `运行库表定义` 全量建表，而三处能力（`初始化运行数据库` / `写入运行态` / `查询运行态`）只要打开运行库就会建表 → **表存在不等于有人在写**。审计实测 4 张恒空表，写入侧都在别处，故从定义中删除：

| 删掉的域 | 真实写入侧 | 判据 |
|---|---|---|
| `会话` | `大语言模型支持库.会话存储.db`（专用库） | 全仓无代码向本库 `会话` 域写入 |
| `检查点索引` | `检查点.db`（专用库） | 同上 |
| `缓存索引` | `大语言模型支持库.嵌入缓存.db`（专用库） | 同上 |
| `发布` | 平台控制面权威状态库（`平台控制面/平台状态（包）` 的 `发布` 表） | 同名双义，收口后「发布事实」唯一权威 = 平台控制面 |

保留 `灰度状态`：已接线（`运行核心/加载器/版本系统/灰度指标.py` 读写），0 行只是**尚未发生灰度发布**，不是未接线。

删域**不回溯删表**：改定义只止新增，已有库里的旧表**不强制 DROP**（历史库/制品副本各有保留口径，DROP 属单独动作）。所以「库里还有旧表」是预期状态，不是漏删。

**写入侧防复发**：`写入运行态` 拒绝验收/测试标识行（id 以 `验收-`/`测试-`/`test-` 开头，或 `能力id` 以 `验收`/`测试.` 开头 → `参数不合法`）。起因是一次性验收命令直接写了正式库（`灰度观测` 留了一行 `验收-灰度-1`），而 `灰度指标.聚合()` 是「从库重算」，假行会污染按表统计的灰度结论且事后无法与真实数据区分。**验收/测试一律用 `tempfile` 临时库**（范例：`测试中心/运行核心/测试_灰度指标入库.py`）。
