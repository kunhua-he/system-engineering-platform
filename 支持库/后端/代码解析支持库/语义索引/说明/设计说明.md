## 一、本包是什么

代码语义索引子包：把代码目录切块 → 生成嵌入 → 落 SQLite（块文本 + 向量 + 文件路径 + 起止行），并按 向量召回 + 关键词精排 返回候选块。切块复用 代码解析支持库.按规则切块，嵌入复用 大语言模型支持库.模型连接器 与 嵌入缓存；本包只做召回补充，不以向量相似度当事实，最终位置必须回 读取文件 按行区间取真实内容。

- 能力面：@@能力表@@
- 一件什么东西被它收口成唯一实现（一句话）：**「自然语言 → 代码位置」这一层召回**。
  此前全仓只有两条检索腿：`代码解析支持库.代码地图`（要**精确符号名**才查得到）与
  `项目文档支持库`（只索引 Markdown 文档）。「用大白话描述一段逻辑、想知道它在哪个文件的哪几行」
  这件事没有承载，故由本包收口成唯一实现。
- 它在分层里的位置（支持库=原子能力／适配层=第三方翻译／模块=能力组合）：**支持库（原子能力）**。
  只把「切块 → 嵌入 → 落库 → 召回精排」四步各自收口成原子能力，不做编排、不做业务判定；
  切块/嵌入/缓存全部**复用上游**，本包不复制任何一套。

## 二、本包不是什么（不许被当成的用法）

| 不许被当成 | 为什么 | 正确落点 |
|---|---|---|
| 万能工具包（什么都往里塞） | 一个包只做一件事才能被无数模块复用；塞第二件事就开始分叉 | 另立支持库；同目的已有的按「结果唯一即收口」蒸馏进最全的那个 |
| 业务编排层 | 编排是模块的活（只经 `获取能力调用器().调用能力` 组合） | `模块库/` |
| 第三方库的门面 | 支持库内出现第三方英文 API 就是越界 | `支持库/适配层/<提供者>`，本库只消费其中文原语 |
| **被当成「答案」直接用**（本包最容易被误用的用法） | 向量相似度只是**召回排序**，不是事实；`分数` 是相对排序值、不保证跨查询可比。把分数高当成「这段代码就是干这个的」证据，会拿错文件还理直气壮 | **必须回 `读取文件`**，按返回的 `起始行`/`结束行` 取真实内容再引用 |

## 三、管什么

- 输入口径（收哪些参数、边界值、超限怎么报）：`建代码索引` 收 `目录`（必须存在且是目录）、
  `模型名`（须在 `解析本地模型路径` 的映射内）；`查代码块` 收 `查询`（非空）、`顶部数量`
  （**1..100**，超限回 `参数不合法`）。**不收单文件** —— 单文件切块请直接用 `按规则切块`。
  空目录**成功返回**（`已索引块数=0`），不是失败。
- 输出口径（返回什么、排序是否稳定、空值怎么表达）：`候选列表` 按 `分数` 降序、
  **同分按 `文件路径` 字典序**（故排序稳定），附 `召回数`/`精排数`/`是否截断`。
  **空结果不是失败**：`候选列表=[]` + `成功=真`。截断时如实回报 `是否截断=真`，不静默丢。
- 幂等与副作用（可重复调用吗、改不改输入、动不动外部状态）：**可重复调用** ——
  对同一目录是**覆盖更新**（同 `文件路径` + `起始行` 覆盖，不留旧版本）；**不改输入目录、
  不删源文件**。副作用只落在索引库 `工程缓存/语义索引/语义索引.db`。

## 五、为什么这样切（架构对比，必须留痕）

按 `开发文档/项目说明.md`「做新功能时必须先问架构」：新能力/模块/链路落地前，
必须对比「现状做法 ↔ 候选架构」两列（更少层／更少 IO／更少重复实现／失败面更小／边界更清晰），
结论写在这里——**一两句也算数，但必须留下；「不做」的结论同样是结论**。

| 维度 | 现状做法 | 候选架构 | 裁决与理由 |
|---|---|---|---|
| 层数与边界 | 只有 `代码地图`（按精确符号名查，查不到自然语言描述）与 `项目文档支持库`（只索引 md） | 在 `代码解析支持库` 下新增 `语义索引` 子包，切块/嵌入/缓存全部复用上游 | **采纳**：不新立顶层包、不复制切块与嵌入，只补「自然语言召回」这一层 |
| IO / 重复实现 | 调用方若要自然语言检索，得各自切块 + 调模型 + 存向量 | 复用 `按规则切块` + `模型连接器` + `嵌入缓存`；句柄长驻复用 | **采纳**：切块/嵌入/缓存零复制；查询侧句柄复用后单次查询省约 6 秒（2026-09-22 实测） |
| 失败面 / 可回退 | 整批失败（一个文件坏就整趟白跑） | 单文件失败隔离进 `跳过清单`，其余照常入库 | **采纳**：索引是**可重建**的派生数据，坏一个文件不该让整趟白跑 |

## 六、失败如何表达

- 一律返回统一结果结构（成功/值/错误码/错误说明/来源/可重试）；**不抛裸异常给调用方**。
- 错误码只写实现里真实存在的（`结果.失败("…")` 字面量），不许虚列；实现有失败路径的能力，
  契约必须声明对应错误码——组件合规「契约」「失败语义」两项按实现逐函数比对。
- 可重试与不可重试必须分清：**可重试** = `资源繁忙` / `模型不可用` / `资源未收敛`
  （退避 1 秒、上限 3 次，与网关 `Retry-After` 同口径）；**不可重试** = `参数不合法` /
  `路径不存在` / `目录不可读` —— 重试不会变好，重试只是浪费。
- 「没命中」「查无结果」与「失败」不得压成同一个码：**没命中** = `成功=真` + `候选列表=[]`
  + `召回数=0`（检索类能力「查无结果」是正常业务结果）；**失败** = `成功=假` + 错误码
  （模型连不上、库打不开等）。二者**绝不同码**。
- 部分成功（批量里个别项失败）如何表达：**隔离进 `跳过清单`** —— `建代码索引` 逐个文件处理，
  单文件失败（解析不了/切不出块）只记 `跳过清单` 并继续，整批仍 `成功=真`；
  `跳过清单` 非空时**不算全绿**，调用方必须自己看这一项，不许只看 `成功`。

## 七、被否决的做法（写在这里防止重犯）

| 做法 | 为什么被否决 |
|---|---|
| 在实现里 import 第三方库 | 第三方必须由适配层翻译成中文原语；支持库直连会被依赖门禁判「第三方直连」 |
| 在实现里 import 其它包的 `实现/` 目录 | 跨包实现依赖被依赖防火墙拒；只能经公开入口或能力调用器 |
| 复制第二套同类实现 | 同一目的已有实现就蒸馏进最全的那个（结果唯一即收口） |
| **「每次查询临时取句柄、用完必释放」** | 初衷是防遗留本地模型进程，但句柄体系本就是**长驻**设计（`包声明.json` `句柄超时秒: 1800`，超时由体系回收），每次建拆实测让单次 `查代码块` 多付约 6 秒，且**第二次同查询仍 6.5 秒**（只快 12%）—— 把长驻资源当短连接用。改为模块级复用 + 失效重取一次，且**释放时同步清缓存**（否则会把已释放的死句柄还回去） |

## 句柄生命周期能力统一口径（#93）

全仓「句柄续租」有 2 条实现腿、「句柄释放」有 7 条实现腿 —— 同一件事在各包各写一遍。
形状不一致时，调用方必须按包名分支处理，同一个动作在多包各记一套口径。本包按 #93 收口，
**只保留一套对外形状**。

> 下面是**设计口径**（为什么这样定、边界在哪）。参数表 / 返回结构 / 错误码的机器权威是
> `能力定义.json`，调用口径以同目录 `使用说明.md` 为准 —— 本文不复制调用口径。

| 族 | 口径名 | 参数 | 成功值键 | 错误码 |
| --- | --- | --- | --- | --- |
| 句柄续租 | `续租句柄` | `句柄`、`租约秒` | `句柄`、`已续租`、`超时秒` | `参数不合法` / `句柄失效` |
| 句柄释放 | `释放句柄` | `句柄` | `句柄`、`状态`、`已释放` | `参数不合法`（领域码另计） |

**为什么选「续租」这个词**（少数服从多数，不新造第三套）：全仓既有租约能力用「续租」
（`平台控制面.能力目录.续租文件租约`、`资源续租`、权威状态 `续租租约`、`资源句柄服务.续租`），
用「续约」的只有 `会话存储` 一条腿 —— 故语汇统一到「续租」。释放一族的 6 条能力腿本就同名
`释放句柄`（`组件控件`／`会话存储`／`模型连接器`／`并发控制`／`进程管理`／`数据结构`），
统一的是**参数名**（历史上一处写 `句柄id`）与**返回键集合**。
**同形状同词表者一并收敛**：`浏览器自动化.关闭会话`（返回键与 `状态` 取值与释放族逐字相同）、
`语义索引.嵌入` 的本地转调函数（由 `释放句柄` 改名 `释放模型句柄` 消歧，它只转调、不复制实现）。
`状态` 词表两值：真正释放 `已释放`，幂等空转 `未找到且已幂等`；旧值 `已结束并已释放` 本轮全仓收敛。

**能力名（能力 id 末段）本轮不归一，理由与解封条件**：
能力 id 受「只增不改」冻结门禁保护（`开发工具/能力id冻结基线门禁.py`：基线里有、当前没有的 id
＝被删或被改名 ⇒ 判红），而编译器把**实现函数名绑定到能力 id 末段**
（`能力契约编译/能力定义编译器.py:418` `函数名 = 能力id.split(".")[-1]`）——
即能力 id 一改，实现函数名、`__init__` 生成入口、注册表同步全动。
`开发文档/项目证据/能力id冻结基线_交付说明.md` §5 明文：本门禁**只冻结存在性、不裁决命名**，
「id 命名规范定稿后按 `--冻结` 重建基线一次」。故能力名的归一**登记为待办**，
待「id 命名规范」落地后随基线重建一并做；本轮只统一形状与语汇。

**语义边界**：
- 续租只重置最后活动时间；`租约秒 > 0` 时同时覆盖超时秒，缺省只重置倒计时。
  对已失效（超时/已释放）句柄**拒绝复活**，回 `句柄失效` —— 不许把「续租」当复活手段。
- 释放是**幂等**的：句柄不存在或已释放一律成功，`状态` 取 `未找到且已幂等`；
  本次真正释放时 `状态` 取 `已释放`。只有句柄不是 1–999999 的整数才回 `参数不合法`。
- 释放的「没收敛」不算成功：领域内若资源账本必须保留（如线程池/本地模型进程未退），
  回 `资源未收敛`（可重试）并**保留账本**，不许改判成功。
- 本包的续租/释放**只作用于本包自己的句柄表**，不跨包代办。跨包的统一门面
  （按句柄类型分派的续租/释放入口）是 `模块库/测试资源/说明/待补能力清单.md` 第 3 项
  登记的底座缺口，不在本包职责内。

**本包落点**：`实现/嵌入.py` 的 `释放模型句柄` 是**转调件**（转调 `大语言模型支持库.模型连接器.释放句柄`），
不是第 8 条实现腿 —— 但它与同族能力同名，读代码时会被误当成一条腿。
按「同一件事只留一条腿」把它改名为 `释放模型句柄`，名字里写明**转调目标**，
避免与 `释放句柄` 一族撞名。它返回 `逻辑型`（不遮主流程的错）是刻意的：调用点都在
`finally` 里，失败只能吞下并留痕，不许把清理失败升级成主流程失败。

**句柄复用口径（2026-09-22 新增）**：本包 `取句柄` 带**模块级缓存**（`_句柄表`，按 `模型名` 索引），
`嵌入查询` 与 `建代码索引` 都复用同一句柄、**不再每次释放**（由句柄体系按 `句柄超时秒` 回收）。
`释放模型句柄` 保留但**必须同步清缓存** —— 不清就会把已释放的死句柄还回去，
调用方拿到「句柄失效」却查不出为什么。失效重取**只重试一次**（避免死循环）。
