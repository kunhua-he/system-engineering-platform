## 它解决什么

问「这个仓里有哪些文件、每个文件里有哪些符号」时，不必把源码整个读进来：
先把仓建成一张**加权有向图**落 SQLite，再按 token 预算取一张「文件 + 符号签名」的紧凑地图。

## 两步用法

### 1. 建符号图（写库，幂等）

```
代码解析支持库.仓库地图.建符号图(
    仓库根="/path/to/repo",
    排除目录=[],            # 空 = 平台默认排除
    语言集=[],              # 空 = 自动（.py 走 ast，.ts/.vue 走 tree-sitter）
    库文件=""               # 空 = <平台根>/工程缓存/仓库地图/<仓名>.db
)
```

返回：`节点数`、`边数`、`文件数`、`耗时秒`、`跳过清单`。
单文件读取/解析失败只进 `跳过清单`，不影响其余文件。

### 2. 取仓库地图（只读）

```
代码解析支持库.仓库地图.取仓库地图(
    仓库根="/path/to/repo",  # 与建图时同一个仓根
    锚点=[],                # 空 = 全局排名；可给文件路径或符号名
    token预算=4096,
    库文件=""
)
```

返回：`地图文本`、`收录文件数`、`收录符号数`、`预算`、`已用预算`、`是否截断`。

## 三个必须知道的口径

1. **token 口径 = 字符数 / 3（向上取整）**。不是业界常见的 4 字符/token：
   本平台标识符与注释以中文为主，中文在 BPE 里普遍 1~2 字符/token，按 4 估会系统性低估。
2. **`是否截断=true` 时地图文本仍是完整行**。二分的是「能容纳多少个完整渲染单元」
   （粒度=符号），不会把某一行或某个签名截成半截。
3. **建图与取图必须用同一个 `仓库根`（或同一个 `库文件`）**。默认库文件名取仓根目录名，
   同名仓会互相覆盖；多仓共存时显式传 `库文件`。

## 与 代码地图 的关系

本包的 `nodes`/`edges` 表与 `代码解析支持库.代码地图` **同构**（edges 另加一列 `weight`），
因此 `代码地图.查询节点` / `代码地图.查询关系` 可以直接读本包建出来的库：

```
代码解析支持库.代码地图.查询节点(代码地图路径="<库文件>", 关键词="取仓库地图")
```

## 常见错误码

| 错误码 | 状态码 | 什么时候出现 |
|---|---|---|
| 参数不合法 | 400 | 仓库根 缺失/类型不符；语言集 含不认识的值；token预算 越界 |
| 目录不存在 | 400 | 仓库根 不是目录 |
| 解析失败 | 500 | 仓库根下没有可建图的源码文件，或全部文件都解析失败 |
| 写入失败 | 500 | SQLite 落盘失败（目录不可写、磁盘满等） |
| 文件不存在 | 404 | 取仓库地图时库文件不存在（还没建图，或路径写错） |
| 查询失败 | 500 | 库文件不是仓库地图库（缺 nodes/edges 表），或库内无节点 |
