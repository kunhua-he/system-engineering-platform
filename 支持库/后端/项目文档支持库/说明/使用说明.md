## 项目文档支持库.查询索引（查询索引）

**说明**：按项目名与关键词查询块索引（大小写不敏感子串匹配）。支持四档返回粒度（标题/简介/内容/完整，默认档与改前逐字段兼容）、多组搜索词择优（各组独立打分取最高）、以及零命中组经「未命中词」表自动扩词（只读，只对零命中的那一组生效）。

**参数表**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 项目名 | 文本型 | 是 | None | 项目名 |
| 关键词 | 文本型 | 否 | None | 查询关键词（空白分隔多词，全命中优先）；与 搜索词 至少给一个 |
| 返回条数 | 整数型 | 否 | 20 | 返回上限 |
| 库文件 | 文本型 | 否 | None | 库文件绝对路径；留空取默认 |
| 返回粒度 | 文本型 | 否 | 简介 | 标题/简介(默认)/内容/完整 四档；默认档与改前返回逐字段兼容 |
| 搜索词 | 列表型 | 否 | None | 候选词组列表，如 [["开通","流程"],["签约","步骤"]]；各组独立检索打分，只返回评分最高的一组。传了它 关键词 只原样带回不参与检索 |
| 截断上限 | 整数型 | 否 | 0 | 内容/完整档下块文本最大字符数；0 或负 = 不截断 |

**返回结构**：结果型（统一结果：成功/值/错误）；值含 项目名／关键词／命中列表／命中数／是否截断／返回粒度／生效搜索词／搜索词组数／扩词记录

**错误码表**：

| 错误码 |
| --- |
| 参数不合法 |
| 索引库不可用 |

**调用示例**：

```python
# 四档粒度（默认「简介」档与改前逐字段兼容）
项目文档支持库.查询索引(项目名="系统工程平台", 关键词="热接入 流程", 返回粒度="标题")
# 多组搜索词择优：只返回评分最高的一组
项目文档支持库.查询索引(项目名="系统工程平台", 搜索词=[["热接入"], ["热接入", "流程"]])
```

**验证状态**：已纳入验证场景：支持库.资产验证（资产）、支持库.能力契约验证（契约）

## 项目文档支持库.校验清单（校验清单）

**说明**：校验 markdown 表格清单（编号唯一性、编号格式、必填列非空、表格结构完整/缺列），返回通过与问题列表；编号格式口径由调用方以 编号模式 传入（不给则不判格式，防对合法清单误报——体例规范第七节的四位口径只约束决策记录）；非表格文本如实报「非表格正文」并判不通过。

**参数表**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 正文 | 文本型 | 是 | None | 清单正文文本（非空） |
| 必填列 | 文本型 | 否 | None | 必填列名列表或逗号分隔列名 |

## 踩坑条目总览（开工上下文三条能力共用）

> 起因（华哥 2026-09-18）：「类似于豆包的那种，先弄开工上下文。等于说你现在做什么，
> 你就先 HTML 请求一下，看看有没有历史的坑，搜一下。**而不是全量载入**。」
> 目的：把踩过的坑从散落的 md 散文收成**可检索的结构化条目**，
> 让调用方在开工或撞报错时**一次请求就查到历史坑**，不必载入 126KB 项目说明与 1065 行哲学正文。

**与项目记忆的分界**：项目记忆（`工程缓存/任务记忆/<开工ID>.md`）是一次派发的**事实包**、用完即弃；
本组的 `坑条目` 表是**长期累积的踩坑经验**、带状态机演进。两者**并存**，不合并、不互相替代。

**状态机**（每条坑的生命周期，命中即自动推进）：

```text
草稿 ──命中≥1──> 已用 ──命中≥3──> 已固化 ──> 已封存
  └──────────────── 前提失效 ────────────────> 已失效（检索不再返回）
```

- `草稿`：刚记下，还没被检索命中过；
- `已用`：被 `查开工上下文` 命中过；
- `已固化`：命中 ≥3 次（该坑已稳定，可考虑升级为门禁）；
- `已封存`：已升级为判据 / 门禁，条目只留索引（防回潮）；
- `已失效`：前提已不成立（如相关能力已删除）——**不再返回**，避免旧结论误导。
