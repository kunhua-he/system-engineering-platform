# 项目文档支持库 设计说明（设计权威）

> 本文是该库的**设计哲学与边界权威**：它为什么这样切、管什么、不管什么、失败如何表达。
> 调用口径——能力、参数、返回结构、错误码与调用示例——以同目录 `使用说明.md` 为准（由能力契约生成）。
> 两份说明都计入包指纹，任何改动都要升包版本。

- 包id：支持库.后端.项目文档支持库
- 版本：1.0.0
- 类型：支持库（原子能力层）
- 执行方式：**进程内**（无子进程入口、无受管提供者、无子进程模板骨架）

## 一、为什么有这个库（需求来源）

需求id `d8066e8b479f495c`（平台控制面.需求登记）。要解决的原始问题：

> 针对不同项目能快速查询该项目自己的开发文档；文档要按规范写，**符合规范才落盘**，不符合规范单独返回违规范方式；本地保存一份 md，同时入库一个小 db 便于快速检索；后台单独拉一个线程入库。

拆成原子动作后落到本库：**切块 / 校验规范 / 建索引库 / 写入索引 / 查询索引 / 登记项目 / 查询项目**。

## 二、边界：管什么、不管什么

| 管 | 不管（归模块层 `项目文档`） |
|---|---|
| 把正文切成有序块（纯计算） | 判断某个项目值不值得登记 |
| 按**判据数据文件**逐条校验正文 | 校验项目根目录、规范文件是否真实存在 |
| 建表、写索引、按关键词查索引 | 编排「先校验再落盘再入库」的流程 |
| 登记表的幂等写读 | 起后台线程、决定入库时机与重试策略 |
| 索引的覆盖更新 | 记忆检索（直接复用 `记忆支持库`，本库不重造） |

**为什么这么切**：支持库只提供原子动作，不判业务边界；项目根目录是否存在、规范文件是否就位属于「项目边界校验」，是模块层的活。本库的 `登记项目` 是**纯存储动作**，因此不校验目录存在性——这是刻意的，不是漏做。

## 三、检索口径：纯 SQLite + 字符串匹配，不调大模型

与 `记忆支持库` 的「仅关键词」同哲学：**结构化查项目文档不该付一次 LLM 调用的代价**。默认实现为大小写不敏感子串匹配，按命中密度与行号稳定排序；将来要语义检索再加向量列，不预先造。

**为什么不做向量**：本库是文档索引的原子层，不是检索引擎。加向量会把「可预测、可复现、零成本」的检索变成「依赖模型、有幻觉、按次计费」的调用，且会让检索结果无法用「文件路径 + 行号」回溯核对——而**可回溯**正是这个能力存在的理由。

## 四、判据数据化：规范改一句只改数据，不改代码

`校验规范` 的判据来自 **JSON 数据文件**（`开发文档/规范/Markdown 文档体例判据.json`），不硬编在 Python 里。

- 唯一的真源是 `开发文档/规范/Markdown 文档体例规范.md`，判据文件顶部声明「唯一真源」指向它。
- 判据文件不存在 / 不可解析 / 结构不符 → **明确失败**（错误码 `判据文件不存在`），绝不假装通过。这一点是刻意的：校验器「静默放行」比「报错」危险得多，它会让不合规文档一路落盘。

## 五、库文件位置与幂等

- 库文件：`<运行数据根>/项目文档库.db`，经 `公共契约/运行时/运行缓存.解析运行数据根` 解析，**禁止裸拼 `工程缓存`**。
- `库文件` 参数给值必须是**绝对路径**；相对路径一律拒绝（防止把库写到进程当前目录）。
- 三张表 + 两个高频索引全部用 `CREATE TABLE IF NOT EXISTS`，`建索引库`、`写入索引` 重复调用幂等；`写入索引` 按 `(项目名, 文档相对路径)` 覆盖更新。
- 写库连接一律 `PRAGMA journal_mode=WAL`，连接随调用结束关闭，**不跨调用持有句柄**。

## 六、失败如何表达

- 参数不合法 → 错误码 `参数不合法`，说明里给出具体字段。
- 库不可用（SQLite 错误）→ 错误码 `索引库不可用`。
- 判据文件缺失 → 错误码 `判据文件不存在`。
- 切块是纯计算，内部异常不吞：转成明确失败并带原始异常文本（不做「宽 except 伪装成成功」）。
- 查不到 → 成功结果 + 空列表 + 数量 0，**不返回假命中、不报错**。

## 七、为什么不放进薄壳

薄壳（`开发工具/薄壳/`）在 `AGENTS.md` 里的定位是「只做协议翻译，不实现业务逻辑，不是第二条执行腿」。把文档治理写进薄壳会让它带上业务语义，并随能力改名漂移。Agent 走 `capability_search` 找这些能力、`capability_call` 执行，与其余能力同一条腿。

## 八、被否决的做法（防后患）

| 做法 | 否决理由 |
|---|---|
| 把手写入口 `__init__.py` 交给编译器覆盖 | 编译器遇 `def 注册能力` 的手写入口已判为合法并保留；本库能力多，手写注册表可读性更好 |
| 把判据写进 Python 常量 | 规范改一句就要改代码、重编译、重测，判据必然与规范漂移 |
| 用向量 / 大模型做默认检索 | 见第三节 |
| 入库失败回滚已落盘文件 | 文件是权威、索引是派生；派生失败不该毁掉用户可见结果（由模块层「先落盘、后后台入库」承接） |
| 本库起后台线程 | 支持库层不起线程（`资源预算.json` 线程上限 0）；线程归模块层的组合流程 |
