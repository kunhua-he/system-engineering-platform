# PDF 隔离提供者使用说明

## 定位

把 PDF 原生第三方库（pdfplumber / PyMuPDF）隔离到**独立子进程**执行。
平台主进程、测试器、后端和发布门禁绝不直接加载 fitz/_extra.so，从而
彻底隔离 PyMuPDF SWIG 绑定在 Python 3.14 解释器关闭阶段的段错误。

## 架构

```text
主进程调用者
  → PDF隔离提供者.解析PDF隔离 / 校验PDF隔离 / 检查提供者版本
    → 启动一次性子进程（独立进程组，cwd=平台根）
      → 子进程入口.py（内部才 import pdfplumber/fitz）
        → stdin 一行 JSON 请求，stdout 一行 JSON 响应
        → 完成后 os._exit(0) 跳过 SWIG 模块销毁
```

## 生命周期覆盖

| 场景 | 行为 |
|---|---|
| 启动失败 | 返回 提供者不可用（可重试） |
| 正常调用 | 返回统一结果，值为通用文档字典/页数/版本 |
| 执行超时 | 进程组 SIGTERM→SIGKILL 强杀，返回 超时（可重试） |
| 子进程崩溃/非零退出 | 返回 提供者崩溃（可重试），下次调用重新启动 |
| 无有效响应 | 返回 提供者崩溃 |
| 停止/残留清理 | 每次调用结束后确保进程组终止，无残留进程/文件 |

## 模拟提供者不可用（测试用依赖注入）

禁止修改 sys.modules。通过环境变量让子进程按需禁用库：

```bash
PDF隔离提供者_禁用库=fitz   # 子进程内不加载 fitz（图像降级为坐标）
PDF隔离提供者_禁用库=pdfplumber  # 子进程内不加载 pdfplumber（提供者不可用）
PDF隔离提供者_禁用库=fitz,pdfplumber
```

测试中使用 `mock.patch.dict(os.environ, {...})` 注入即可，不触碰 sys.modules。

## 错误码

| 错误码 | 含义 |
|---|---|
| 提供者不可用 | 子进程启动失败或第三方库被禁用/缺失 |
| 提供者崩溃 | 子进程异常退出或返回无效响应（可重试） |
| 超时 | 子进程执行超过超时秒（可重试） |
| 文件不存在 / 文件加密 / 文件损坏 / 超出限制 | PDF 文件状态 |
