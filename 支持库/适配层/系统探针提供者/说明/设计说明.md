## 一、本包是什么

系统级提供者健康探针（psutil 系统内存读取）：把「这台机器还有多少内存」与
「某个外部应用/系统工具在不在、版本是多少」两件事收口成**适配层中文原语**，
让支持库不必直连第三方、也不必自己起子进程。

- 能力面：**检查提供者**（提供者自身可用性真实探针，唯一登记为公开能力的能力）。
- 一件什么东西被它收口成唯一实现（一句话）：**「psutil 系统内存读取」** ——
  在此之前 psutil 只在 `支持库/适配层/系统探针.py` 这一个根下平铺件里出现，
  它**没有自己的目录、没有 `依赖锁.json`、不进依赖生命周期审计**，第三方依赖
  只能挤在 `内部件依赖声明.json` 这条豁免通道里（#96）。
- 它在分层里的位置：**适配层（第三方翻译）**。psutil 是 PyPI 第三方包，
  本包把它翻译成中文原语；支持库（模型连接器 / 硬件画像探针）经
  `支持库.适配层.系统探针` 取汉化返回值，**不得直接 import 第三方**。

### 为什么必须存在（本次包化的根因，#96）

`支持库/适配层/模型服务.py` 与 `支持库/适配层/系统探针.py` 此前是**根下平铺内部件**：
直连第三方、无 `依赖锁.json`、不进依赖生命周期审计。审计的「非标准提供者」跳过分支
正是为这类件准备的（`开发工具/依赖生命周期审计/审计核心.py:269`：无 `包声明.json` 即跳过），
后果是**第三方依赖的存在性只靠人写的一行声明**，没有任何机器判据持有它。
包化后：`包声明.json` + `依赖锁.json` + `生命周期契约.json` 三件齐全，
依赖生命周期审计按标准提供者逐项审计（锁独立版本声明 / 混装 / 摘要重算 / 健康探针 / 停止释放入口）。

## 二、本包不是什么（不许被当成的用法）

| 不许被当成 | 为什么 | 正确落点 |
|---|---|---|
| 万能工具包（什么都往里塞） | 一个包只做一件事才能被无数模块复用；塞第二件事就开始分叉 | 另立支持库；同目的已有的按「结果唯一即收口」蒸馏进最全的那个 |
| 业务编排层 | 编排是模块的活（只经 `获取能力调用器().调用能力` 组合） | `模块库/` |
| 第三方库的门面 | 支持库内出现第三方英文 API 就是越界 | `支持库/适配层/<提供者>`，本库只消费其中文原语 |
| **被探工具自身的可用性判据** | soffice/textutil 是否可用是**它们各自提供者**的事实（`LibreOffice提供者` / `textutil提供者` 的生命周期契约里各有真实探针）。并入本包会让「本包挂了」与「soffice 没装」共用一个错误码 | 被探工具的提供者 |

## 三、管什么

- 输入口径（收哪些参数、边界值、超限怎么报）：公开能力 `检查提供者` **无参数**；
  内部原语 `检查系统工具` 收 名称/命令列表/超时秒/版本参数，四者各自校验
  （空名称、空命令列表、非正超时、空版本参数一律 `参数不合法`，不猜默认）。
- 输出口径（返回什么、排序是否稳定、空值怎么表达）：一律统一结果结构；
  成功值 = `{可用, 探针, 版本, 内存总量字节, 内存可用字节, 内存占用率, 说明}`，
  读不到发行包版本时如实留空串（**不编造版本**）。内部原语的返回是 `探针结果`
  dataclass（字段名与包化前逐字一致，既有 5 个调用方零改动）。
- 幂等与副作用（可重复调用吗、改不改输入、动不动外部状态）：幂等、只读、
  不修改输入、不落盘、无跨调用状态。

## 四、不管什么（明确交出去的责任）

| 不管的事 | 交给谁 |
|---|---|
| 路径/参数合法性以外的业务语义判定 | 调用方（支持库/模块） |
| 跨模块依赖与装配顺序 | `运行核心/加载器` |
| 权限与配额的真实拦截 | `平台控制面` |
| 内存不足时的降级策略（限流、拒绝启动模型） | 调用方（`模型连接器` 等）——本包只如实回报真值，不替调用方决策 |
| 被探外部工具是否「应该」装 | 被探工具自己的提供者（探针只回答在不在、版本多少） |

## 五、为什么这样切（架构对比，必须留痕）

| 维度 | 现状做法 | 候选架构 | 裁决与理由 |
|---|---|---|---|
| 层数与边界 | 根下平铺件 `适配层/系统探针.py`（无目录、无锁、不进审计） | ① 目录化 `系统探针提供者/` + 根下平铺件保留为自举入口 ② 直接删平铺件、只留目录 | **取①**。`支持库/适配层/` 根下平铺 `.py` 与同名/相关包并存是**既有合法形态**（自举 + 等价再导出），且 5 个运行时调用方 + 4 个测试文件按 `支持库.适配层.系统探针` 导入；删平铺件要改 9 处调用点，属「改动面 > 收益」且违反「对外 id/路径不变」 |
| IO / 重复实现 | psutil 只在平铺件里出现一次 | 把内存读取下沉到 模型连接器 | **不取**。支持库直连第三方会被依赖门禁判「第三方直连」；适配层是唯一合法落点 |
| 失败面 / 可回退 | psutil 缺失时静默 `可用=假` | 让 `检查提供者` 也返回 `可用=假` 的成功信封 | **不取**。提供者可用性必须走失败信封（`提供者不可用`），否则「提供者挂了」会被调用方当成「成功且可用=假」 |

## 六、失败如何表达

- 一律返回统一结果结构（成功/值/错误码/错误说明/来源/可重试）；**不抛裸异常给调用方**。
- 错误码只写实现里真实存在的（`结果.失败("…")` 字面量），不许虚列：公开能力只产
  `提供者不可用` 一个码（`参数不合法` 因无参数而不可能出现，故不声明）。
- 可重试与不可重试必须分清：`提供者不可用` 标记 `可重试=真`（psutil 未装/环境态可修复）。
- 「没命中」「查无结果」与「失败」不得压成同一个码：内部原语的
  `工具缺失`（工具不在）/`探针超时`（暂态）/`退出码非零`（工具在但报错）三码分立。
- 部分成功：不适用（本包无批量能力）。

### 内部信封码（`探针超时` / `退出码非零`）为什么不在网关错误码表里

`探针超时` 与 `退出码非零` 是**适配层内部信封码**：它们只出现在 `探针结果.错误码`
这个**值字段**里，由 健康监督 / 环境指纹 / 文档转换 读取后自行收敛，**不跨唯一网关**，
因此不在 `运行核心/统一网关/本地网关.py` 的公开错误码状态映射（362 个 HTTP 面码）里。
把内部码塞进公开映射，等于对外宣称「调用方能拿到这个 HTTP 结果」，那是失真。
实现里用模块常量（`错误码_探针超时` / `错误码_退出码非零`）表达，与
`密钥提供者/密钥提供者.py` 的 `错误码_钥匙串不可用` 同形制——**常量表达 + 本文如实写明**，
不是把码藏起来：`公开调用完整性门禁` 的实现侧信封渠道（关键字实参 / `结果.失败` 首参 /
失败包装函数）对本包仍全绿，因为本包不把这些码当公开结果返回。

## 七、被否决的做法（写在这里防止重犯）

| 做法 | 为什么被否决 |
|---|---|
| 在实现里 import 第三方库（除适配层本包） | 第三方必须由适配层翻译成中文原语；支持库直连会被依赖门禁判「第三方直连」 |
| 在实现里 import 其它包的 `实现/` 目录 | 跨包实现依赖被依赖防火墙拒；只能经公开入口或能力调用器 |
| 复制第二套同类实现 | 同一目的已有实现就蒸馏进最全的那个（结果唯一即收口） |
| **删掉根下平铺件、只留目录** | 会让 9 处既有调用点（含 4 份测试）在同一轮里集体改路径，改动面远超收益，且 `本地启动准备与守卫` 对平铺件是**按路径**取用的（`取系统根(__file__) / 支持库/适配层/模型服务.py`） |
| **把 `读取系统内存` 登记成公开能力** | 它是内部原语（依赖防火墙口径：不注册能力契约、不发布）；登记会让支持库有第二条腿去取内存真值，绕过「适配层独占第三方」 |

## 八、第三方边界

- 第三方依赖：**psutil 7.2.2**（PyPI，BSD-3-Clause），落 `依赖锁.json`（第三方库）。
- 声明落点迁移：原登记在 `支持库/适配层/内部件依赖声明.json` 的「系统探针」条目，
  包化后**已删除**——它有正式落点了（件自身目录的 `依赖锁.json`），
  不再走内部件豁免通道（豁免存在的前提是「依赖锁无落点」）。
- 环境依赖：**无**（本包不调用任何外部命令；外部工具探针由内部原语起子进程，
  被探工具属于调用方的事实，不是本包的依赖）。
