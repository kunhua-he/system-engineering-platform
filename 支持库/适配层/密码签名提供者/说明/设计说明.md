# 密码签名提供者 设计说明（设计权威）

> 本文是该库的**设计哲学与边界权威**：它为什么这样切、管什么、不管什么、失败如何表达。
> 调用口径——能力、参数、返回结构、错误码与调用示例——以同目录 `使用说明.md` 为准（由能力契约生成）。
> 两份说明都计入包指纹，任何改动都要升包版本。

## 定位

cryptography（Rust 原生扩展）的**独立提供者**：Ed25519 密钥生成、签名、
验证、公钥指纹与 AES 对称加解密（GCM/CBC）全部隔离到**独立子进程**执行。
平台主进程、测试器和发布
门禁绝不加载 cryptography；每次调用启动一次性子进程，子进程内才 import
cryptography，执行完 `os._exit(0)` 直接退出，跳过解释器关闭阶段的原生
模块销毁，从根上消除崩溃与残留。

## 为什么 AES 也放在这一个包里

底座决策 0006（同一职责全平台只保留一套实现）：对称加解密与非对称签名
是**同一个第三方库（cryptography）的同一个提供者边界**，同域同库就该扩展
这一个包，不新建第二个密码学包——否则会出现两个子进程边界、两套依赖锁、
两份主进程零加载证据。新增只扩能力，不改既有五个能力的语义/参数/返回。

## 架构

```text
主进程调用者
  → 密码签名提供者.生成密钥对 / 签名 / 验证签名 / 公钥指纹 / 内容摘要 /
    对称加密 / 对称解密
    → 提供者管理器.py（主进程侧，绝不 import cryptography）
      → 启动一次性子进程（独立进程组，cwd=平台根，sys.executable）
        → 子进程入口.py（完全自包含，只以同级模块导入 密码操作.py）
          → 密码操作.py 内才 import cryptography（先查环境变量再导入）
        → stdin 一行 JSON 请求，stdout 一行 JSON 响应
        → 完成后 os._exit(0) 跳过原生模块销毁
```

子进程**不经过 `支持库.适配层` 包链**：该包链会连带导入底座其余模块（`公共契约`
等），把子进程的「缺环境」从稳定的 `提供者不可用` 变成导入期崩溃；自包含导入只加载
`密码操作.py`，缺 cryptography 时照样返回稳定错误码。

## 能力与参数

| 能力id | 参数 | 成功值 |
|---|---|---|
| 密码签名.生成密钥对 | 超时秒（可选，默认 30） | {私钥PEM, 公钥PEM} |
| 密码签名.签名 | 私钥PEM, 数据b64 | 十六进制签名（128 位 hex） |
| 密码签名.验证签名 | 公钥PEM, 数据b64, 签名hex | bool（不匹配=False，不抛异常） |
| 密码签名.公钥指纹 | 公钥PEM | sha256(公钥PEM) 前 16 位 |
| 密码签名.内容摘要 | 数据b64 | sha256(数据) 完整 64 位 hex |
| 密码签名.对称加密 | 明文b64, 密钥b64, 模式（可选，默认 AES-GCM）, 初始向量b64（可选）, 附加数据b64（可选）, 超时秒（可选，默认 30） | base64 密文包（未给向量=向量前缀+密文+GCM 标签；显式给向量=纯密文） |
| 密码签名.对称解密 | 密文b64, 密钥b64, 模式（可选，默认 AES-GCM）, 初始向量b64（可选）, 附加数据b64（可选）, 超时秒（可选，默认 30） | base64 明文 |

## AES 对称加解密口径（新增能力）

- 模式：`AES-GCM`（默认，带 16 字节认证标签，支持 `附加数据b64` 附加认证）
  与 `AES-CBC`（PKCS7 填充，不支持 `附加数据b64`，传了直接 参数不合法）。
- 密钥长度：16/24/32 字节（AES-128/192/256），其它长度一律 参数不合法。
- 密文包外壳**两端同一条规则**，往返必然自洽：
  - 不传 `初始向量b64`：提供者随机生成向量并写入密文包前缀
    （GCM 12 字节 / CBC 16 字节），解密端自动解析前缀；
  - 显式传 `初始向量b64`：向量由调用方保管，密文包是**纯密文**——这是
    对接外部固定向量数据的口径（例如数据库页级 AES-CBC 密文）。
- GCM 注意：显式复用同一个随机数会破坏 GCM 安全性；显式向量只用于对接
  已有的外部数据，平台内部新加密一律不传向量（随机数自动生成并随包携带）。
- 失败不静默：密钥不匹配、密文被篡改、附加数据不一致、填充非法一律
  `解密失败`；空明文/空密钥/非法 base64/未知模式是 `参数不合法`。
- 标准兼容证据：AES-256-CBC + PKCS7 的产出与 `openssl enc -aes-256-cbc`
  对同一密钥/向量/明文逐字节一致（本包实测比对）。

- 所有能力返回统一 `结果`（成功=值 / 失败=错误码+错误说明）。
- 内容摘要 仅用标准库 hashlib，**留在主进程**，不经过子进程；
  其余密钥类能力全部经过隔离子进程。
- 各函数可直接调用（如 `签名(私钥PEM, 数据b64)`），也可传可选关键字
  `超时秒` 覆盖默认 30 秒；注册能力契约不含该参数，经注册表调用时不传。

## 生命周期覆盖

| 场景 | 行为 |
|---|---|
| 启动失败（无法拉起子进程） | 返回 提供者不可用（可重试） |
| 正常调用 | 返回统一结果 |
| 执行超时 | 进程组 SIGTERM→SIGKILL 强杀，返回 超时（可重试） |
| 子进程崩溃/非零退出 | 返回 提供者崩溃（可重试），下次调用重新启动 |
| 无有效响应 | 返回 提供者崩溃 |
| 停止/残留清理 | 每次调用结束确保进程组终止、管道全部关闭，无残留进程/文件 |

## 模拟提供者不可用（测试用依赖注入）

禁止修改 sys.modules。通过环境变量让子进程按需禁用库：

```bash
密码签名提供者_禁用库=cryptography   # 子进程内不加载 cryptography → 提供者不可用
```

测试中使用 `mock.patch.dict(os.environ, {...})` 注入即可。注入后密钥类
能力全部返回 提供者不可用；内容摘要（主进程 hashlib）不受影响。

## 错误码

| 错误码 | 含义 |
|---|---|
| 参数不合法 | PEM/hex/base64 输入无法解析或为空 |
| 提供者不可用 | 子进程启动失败，或 cryptography 被禁用/缺失（可重试） |
| 超时 | 子进程执行超过超时秒（可重试） |
| 提供者崩溃 | 子进程异常退出或返回无效响应（可重试） |
| 生成失败 | 密钥生成阶段 cryptography 异常 |
| 加密失败 | AES 加密阶段 cryptography 异常 |
| 解密失败 | 解密阶段认证/填充/密钥不匹配（不可重试，需调用方核对密钥与密文） |
| 超出限制 | 子进程输出超过 1MB 上限 |

## 接线注意

平台 `支持库/适配层/__init__.py` 包级 import 的是本包（`密码签名提供者`），
主进程侧止于 `提供者管理器.py`（本包自身代码绝不 import cryptography）——
**任何**导入 `支持库.适配层` 的进程都零加载 cryptography（实测：导入后
`sys.modules` 无 cryptography）。旧 `密码适配`（直连 cryptography 的历史
兼容文件）已删除，不存在第二条加载路径。

加载器经包级入口的 `注册能力(注册表)` 注册全部 7 个能力（分组 密码签名）。
