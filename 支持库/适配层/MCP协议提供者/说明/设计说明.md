# MCP协议提供者 设计说明（设计权威）

> 本文是该库的**设计哲学与边界权威**：它为什么这样切、管什么、不管什么、失败如何表达。
> 调用口径——能力、参数、返回结构、错误码与调用示例——以同目录 `使用说明.md` 为准（由能力契约生成）。
> 两份说明都计入包指纹，任何改动都要升包版本。

## 为什么有这个包

项目哲学第 2 条 2.2/2.3：第三方库分两类——「外部工具/受管」可以按命令行调用，
「代码级依赖」（必须在 Python 里 import 的包）必须落在 `支持库/适配层/` 的提供者里，
由包级中文入口对外。`mcp` 是代码级依赖（薄壳必须 import 才能收发 MCP 协议），
所以它不能留在 `开发工具/薄壳/薄壳服务.py` 里直接 import，必须收进适配层。

## 本包是什么

`mcp` 官方 SDK 的**翻译层**，也是全仓库唯一允许 `import mcp` 的文件
（`实现/协议.py`）。它把薄壳真正用到的 5 个协议动作翻译成中文函数：

| 中文入口 | 翻译的第三方对象 |
|---|---|
| `构造服务(名称)` | `mcp.server.Server` |
| `构造初始化选项(服务名, 服务版本)` | `mcp.server.models.InitializationOptions` + `ServerCapabilities(tools={})` |
| `构造工具定义(名称, 说明, 参数结构)` | `mcp.types.Tool` |
| `构造文本内容(文本)` | `mcp.types.TextContent(type="text")` |
| `标准输入输出上下文()` | `mcp.server.stdio.stdio_server()` |

## 本包不是什么

- **不实现任何 MCP 协议逻辑**：不解析消息、不做工具分发、不写业务规则。
  协议行为由第三方 SDK 负责，本包只做命名与边界收口。
- **不注册翻译函数为能力**：这 5 个函数返回的是第三方对象（Server / Tool / TextContent /
  上下文管理器），不可契约化、不可序列化，没法过统一结果契约，所以它们只是
  **包级入口导出的函数**，不是能力。注册为能力的只有 `检查可用性` 这一个探针。
- **不做静默降级**：`mcp` 导入失败时把原因记在模块级变量里，探针如实返回
  `可用=False` 并写原因，工厂函数抛 `MCP依赖不可用`，绝不返回 `None` 让上层崩在别处。

## 相对安全口径

这是**相对安全口径下的协议适配**，不是"绝对零第三方"：

- 依赖是事实，藏在薄壳里只会让依赖审计看不见它；收进适配层后，
  版本被 `依赖锁.json` 精确锁定（1.28.1，来源 PyPI，许可证 MIT），
  能力被 `能力定义.json` 声明，边界被 `生命周期契约.json` 约束。
- 单一 import 点（`实现/协议.py`）让"第三方只能出现在适配层"这条铁律**可被 grep 验证**，
  而不是靠人工记忆。全仓复查一条命令即可（见 `使用说明.md`）。
- 许可证按 SDK 实际声明记录：`mcp-1.28.1.dist-info` 的 License 字段与
  Classifier 均为 MIT。

## 版本与漂移

`包声明.json` / `能力定义.json` / `完整性摘要.json` 三者的版本必须一致；
新增翻译函数或调整探针口径都要升包版本并重算完整性摘要。
