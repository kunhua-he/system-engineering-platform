## 一、本包是什么

底座内部的 HuggingFace 模型服务：一个**独立进程**里的 HTTP 服务，把本地权重目录
翻译成四个中文接口（模型列表 / 嵌入 / 重排 / 决策），供 `模型连接器` 经 HTTP 调用。
本包同时持有该服务的**运行栈可用性探针**。

- 能力面：**检查提供者**（运行栈定位探针，唯一登记为公开能力的能力）。
- 一件什么东西被它收口成唯一实现（一句话）：**「本地模型权重的进程内推理」** ——
  平台此前没有第二个模型服务实现（决策：不引入第二条腿，见
  `开发文档/方案/决策模型接入底座方案_20260920.md`「复用 `适配层/模型服务.py` 单一腿」）。
- 它在分层里的位置：**适配层（第三方翻译）**。torch/transformers/fastapi/uvicorn
  是 PyPI 第三方包，本包把它们翻译成中文 HTTP 面；支持库（`模型连接器`）只经
  HTTP + 启动链取用，**不得直接 import 第三方**。

### 为什么必须存在（本次包化的根因，#96）

`支持库/适配层/模型服务.py` 此前是**根下平铺内部件**：直连四个第三方、无 `依赖锁.json`、
不进依赖生命周期审计。审计的「非标准提供者」跳过分支（`审计核心.py:269`：无 `包声明.json` 即跳过）
使它的第三方依赖只靠人写的一行声明持有。包化后 `包声明.json` + `依赖锁.json` +
`生命周期契约.json` 三件齐全，依赖生命周期审计按标准提供者逐项审计。

## 二、本包不是什么（不许被当成的用法）

| 不许被当成 | 为什么 | 正确落点 |
|---|---|---|
| 万能工具包（什么都往里塞） | 一个包只做一件事才能被无数模块复用；塞第二件事就开始分叉 | 另立支持库；同目的已有的按「结果唯一即收口」蒸馏进最全的那个 |
| 业务编排层 | 编排是模块的活（只经 `获取能力调用器().调用能力` 组合） | `模块库/` |
| 第三方库的门面 | 支持库内出现第三方英文 API 就是越界 | `支持库/适配层/<提供者>`，本库只消费其中文原语 |
| **公开能力（可经唯一入口调用的模型推理）** | 调用方**无法经能力调用入口把 `模型路径` 传进来** —— 那等于把「执行任意模型仓库自带代码」的能力公开出去（#179 相对安全声明的立论基础） | `模型连接器`（支持库，走 HTTP + 受管启动链） |
| **一个可被主进程 import 的模块** | 本包 `实现/模型服务.py` 在模块级 import torch 等原生扩展；主进程导入会污染「原生扩展不在主进程加载」的既有结论 | 只由子进程按路径拉起；探针走 `实现/提供者.py`（只定位不导入）；`模型服务/创建应用/停止服务/主程序` 经包入口的**模块级 `__getattr__` 延迟导出**，`import 支持库.适配层.模型服务提供者` 本身不拉原生扩展 |

## 三、管什么

- 输入口径（收哪些参数、边界值、超限怎么报）：公开能力 `检查提供者` **无参数**；
  服务进程的输入是命令行（`--model-path` 必填、`--model-type` ∈ {LLM,向量,重排,决策}、
  `--port` 必填、`--host` 默认 `127.0.0.1`），由启动方给出，本包不解析业务语义。
- 输出口径（返回什么、排序是否稳定、空值怎么表达）：探针返回统一结果结构，
  成功值 = `{可用, 探针, 依赖[{名称, 发行包, 版本}], 缺失, 说明}`；
  读不到发行包版本时如实留空串（**不编造版本**）。HTTP 面按 OpenAI 兼容形状返回
  （`/v1/embeddings` 的 `data[].embedding`、`/v1/rerank` 的 `results[]` 按分数降序、
  `/v1/decision` 的 `answers`）。
- 幂等与副作用（可重复调用吗、改不改输入、动不动外部状态）：探针幂等、只读、
  不落盘；HTTP 面的嵌入/重排是纯函数式推理（不改输入、不写状态），决策同。

## 四、不管什么（明确交出去的责任）

| 不管的事 | 交给谁 |
|---|---|
| 路径/参数合法性以外的业务语义判定 | 调用方（`模型连接器` 等） |
| 跨模块依赖与装配顺序 | `运行核心/加载器` |
| 权限与配额的真实拦截 | `平台控制面` |
| 模型来源可信度（`trust_remote_code` 会执行权重包自带代码） | **用户自选模型的可信度** + 启动方三层校验（存在性→字节数→sha256），见 `模型连接器/实现/本地启动准备与守卫.py` |
| 对外鉴权与网络隔离 | 上层业务（本服务**不做鉴权**，默认只绑回环） |
| 进程级停止（SIGTERM/回收进程组） | 启动方 `模型连接器` |

## 五、为什么这样切（架构对比，必须留痕）

| 维度 | 现状做法 | 候选架构 | 裁决与理由 |
|---|---|---|---|
| 层数与边界 | 根下平铺件 `适配层/模型服务.py`（无目录、无锁、不进审计） | ① 目录化 `模型服务提供者/` + 平铺件保留为自举入口 ② 只留目录、删平铺件 | **取①**。启动链是**按路径**取用平铺件的（`取系统根(__file__) / 支持库/适配层/模型服务.py`），删平铺件要同步改启动链与全部文档/证据引用，属「改动面 > 收益」且违反「对外路径不变」 |
| IO / 重复实现 | 服务与探针混在一个件里 | 把探针也写进 `实现/模型服务.py` | **不取**。该件模块级 import torch，探针若与它同模块就必然导入原生扩展；探针单列 `实现/提供者.py`（只 `find_spec` + `importlib.metadata`）才能既回答可用性又不违反「原生扩展不在主进程加载」 |
| 失败面 / 可回退 | 运行栈缺件时服务启动即崩（`ModuleNotFoundError`） | 探针返回 `可用=假` 的成功信封 | **不取**。缺件必须走失败信封（`提供者不可用`）+ 缺件名单，否则「装没装齐」会被当成「装齐了但不可用」 |

## 六、失败如何表达

- 一律返回统一结果结构（成功/值/错误码/错误说明/来源/可重试）；**不抛裸异常给调用方**
  （探针路径不抛；HTTP 面的异常由 uvicorn/FastAPI 表达为 5xx，属服务进程内部）。
- 错误码只写实现里真实存在的（`结果.失败("…")` 字面量）：公开能力只产
  `提供者不可用` 一个码（`参数不合法` 因无参数而不可能出现，故不声明）。
- 可重试与不可重试必须分清：`提供者不可用` 标记 `可重试=真`（缺件是环境态，装齐即可重试）。
- 「没命中」「查无结果」与「失败」不得压成同一个码：本包无查询类能力，不适用。
- 部分成功：不适用（探针要么四项齐备，要么报缺件名单，不返回部分成功）。

## 七、被否决的做法（写在这里防止重犯）

| 做法 | 为什么被否决 |
|---|---|
| 在实现里 import 第三方库（除适配层本包） | 第三方必须由适配层翻译成中文原语；支持库直连会被依赖门禁判「第三方直连」 |
| 在实现里 import 其它包的 `实现/` 目录 | 跨包实现依赖被依赖防火墙拒；只能经公开入口或能力调用器 |
| 复制第二套同类实现 | 同一目的已有实现就蒸馏进最全的那个（结果唯一即收口） |
| **把 `模型路径` 做成能力参数** | 那等于把「执行任意模型仓库自带代码」公开化，直接推翻 #179 相对安全声明的立论（本服务是内部件，调用方传不进来） |
| **把 4 个第三方合并成一个 `发行包` 归属** | 只为了让「混装」判据变绿 —— 那是**包装成绝对边界**式的失真；本包选择如实申报并留下审计红与裁决点（见第八节） |
| **让探针 import torch 来读版本** | 会让底座主进程加载原生扩展，污染既有结论（版本一律读发行包元数据） |

## 八、第三方边界

- 第三方依赖：**torch 2.13.0**（BSD-3-Clause）、**transformers 5.8.1**（Apache-2.0）、
  **fastapi 0.136.3**（MIT）、**uvicorn 0.46.0**（BSD-3-Clause），全部落 `依赖锁.json`。
- **如实申报为 4 个不同发行包**：它们都是 `实现/模型服务.py` 的**直接 import**，
  不是传递依赖 —— 因此既不合并成一个发行包归属，也不只锁一项而把其余塞进 `依赖闭包`。
  后果：依赖生命周期审计的「混装」判据（`审计核心.py:322 检查依赖锁`，口径
  「一个提供者只锁一个第三方」）会对本提供者判红，与既有 `MLXWhisper提供者`
  （mlx-whisper + faster-whisper）、`转写`（faster-whisper + torch）同形。
  **是否拆分提供者由所有者裁决**；本包不伪造归属、不放宽判据。
- 非 PyPI 的代码级依赖：**rl_agent_api**（决策模型推理代码，随权重包发布，不在本仓）。
  它是**运行期按权重目录定位**的（`_加载决策` 把包根插入 `sys.path` 后 import），
  发行渠道不是 PyPI、无 `importlib.metadata` 版本可读，故不进 `依赖锁.json`
  （登记在 `支持库/适配层/依赖登记.json` 的对应条目里，如实标注「无独立版本号」）。
- 声明落点迁移：原登记在 `支持库/适配层/内部件依赖声明.json` 的「模型服务」条目，
  包化后**已删除**（它有正式落点了：件自身目录的 `依赖锁.json`）。
- 环境依赖：**无**（本包不调用任何外部命令）。
