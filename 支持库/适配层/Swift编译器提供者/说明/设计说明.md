## 一、本包是什么

swiftc/codesign 独立提供者（macOS Xcode 命令行工具）：编译 Swift 源码、adhoc 签名、签名校验。

- 能力面：@@能力表@@
- 一件什么东西被它收口成唯一实现（一句话）：**把『调 swiftc 编译 Swift 源码』与『调 codesign 做 macOS 代码签名/校验』收口成底座唯一实现** —— 此前全仓零处调用这两个工具（取证：`rg -rln "swiftc|codesign" --glob '*.py' .` 排除 工程缓存/制品仓库/__pycache__ 后为空），"真出原生软件"的能力缺口就在这里。
- 它在分层里的位置：**适配层=第三方翻译**。上游是 `swiftc`/`codesign` 两个外部工具，下游供模块组合；本包只做翻译与受控调用，不含业务判断。

## 二、本包不是什么（不许被当成的用法）

| 不许被当成 | 为什么 | 正确落点 |
|---|---|---|
| 万能工具包（什么都往里塞） | 一个包只做一件事才能被无数模块复用；塞第二件事就开始分叉 | 另立支持库；同目的已有的按「结果唯一即收口」蒸馏进最全的那个 |
| 业务编排层 | 编排是模块的活（只经 `获取能力调用器().调用能力` 组合） | `模块库/` |
| 第三方库的门面 | 支持库内出现第三方英文 API 就是越界 | `支持库/适配层/<提供者>`，本库只消费其中文原语 |
| **应用包组装器（.app 目录结构、Info.plist、图标、版本号）** | 那是**产物规格**，不是第三方工具调用；混进来会让「编译」与「打包规格」两件事分叉 | 模块层（组装 `.app` 后调本包 `签名制品`） |
| **公证 / 开发者证书签名** | 本机 `security find-identity` 实测 0 个签名身份、现网网关实测 `Signature=adhoc`；这套档位在可用环境里是**死腿** | 不进依赖、不预留；将来真有证书再就地补能力（哲学 1.2：不留没人走的腿） |

## 三、管什么

- 输入口径：`源文件清单`（非空文本列表，逐项必须是**已存在的绝对路径**，否则 `参数不合法`）；`输出路径`（绝对路径）；`目标架构`/`优化级别`/`附加参数`（可选透传）；`超时秒`（默认 300，探针 30，签名 120，校验 60）。
- 输出口径：统一结果信封。`编译源代码` 的 `值` 含 `{可执行文件, 字节数, 编译耗时秒, 标准错误摘要}`；编译失败时 `错误说明` 含 **文件/行/列/信息**（逐条结构化），不吞错。排序稳定（源文件按传入顺序）。
- 幂等与副作用：**非幂等**（每次编译都重写输出文件、时间戳变化），`修改输入=False`（只读源码）。副作用限于「生成制品」；失败时清理临时产物。并发安全（每次调用独立进程组，互不共享状态）。

| 维度 | 现状做法 | 候选架构 | 裁决与理由 |
|---|---|---|---|
| 层数与边界 | 底座零处调 swiftc/codesign，要出原生应用只能靠外部命令 | ① 塞进 `平台控制面/包仓库`；② **适配层新增第三方提供者**；③ 让提供者去调 `进程管理.执行命令` 拼字符串 | **选 ②**。①把第三方边界塞进平台控制面（越层）；③把参数边界交给 `拆分命令文本`（POSIX shlex 拆词），而编译器参数必须精确成对（`-framework`+值、含空格路径）→ 徒增失败面；且同层 `textutil提供者` 已是「提供者自持受控子进程」形态，两种写法并存即同层分叉 |
| IO / 重复实现 | `包仓库.构建制品` 是内容寻址落盘、`签名制品` 是 Ed25519 密码学签名 —— **均不调编译器**；`进程管理.执行命令` 是通用命令执行（字符串入参） | 复用上述任一 | **都不成立**：前者职责不同域（产物落盘 vs 调编译器），后者入参形态不匹配（见上）。逐条证据见 `复用决策.json` 的「逐条核证」 |
| 失败面 / 可回退 | — | 提供者层直调 `subprocess.Popen(参数列表)` + `受限通信` | 与同层先例完全一致：独立进程组、超时强杀、输出上限、`shell=False`。删除本包不影响其它任何包（零引用） |

## 六、失败如何表达

- 一律返回统一结果结构（成功/值/错误码/错误说明/来源/可重试）；**不抛裸异常给调用方**。
- 错误码只写实现里真实存在的：`参数不合法`、`编译失败`、`签名失败`、`校验失败`、`超时`、`提供者不可用`。
- 可重试与不可重试必须分清：`超时`/`提供者不可用` **可重试**（瞬时环境问题）；`参数不合法` **不可重试**（改参数才行）；`编译失败`/`签名失败`/`校验失败` **不可盲目重试**（源码/制品问题，重试结果相同）。无内建退避，退避由调用方（模块）决定。
- 「没命中」「查无结果」与「失败」不得压成同一个码：本包无「查无结果」语义；探针**工具不存在**报 `提供者不可用`（不是 `参数不合法`），工具存在但探针退出异常也报 `提供者不可用` 并附原文摘要 —— 不谎报成功。
- 部分成功（批量里个别项失败）如何表达：`源文件清单` 是**整批编译**语义，swiftc 有一处错即整批失败（swiftc 行为），本包**如实报出全部诊断**（不是只报第一条），不伪装成部分成功。

## 七、被否决的做法（写在这里防止重犯）

| 做法 | 为什么被否决 |
|---|---|
| 在实现里 import 第三方库 | 第三方必须由适配层翻译成中文原语；支持库直连会被依赖门禁判「第三方直连」 |
| 在实现里 import 其它包的 `实现/` 目录 | 跨包实现依赖被依赖防火墙拒；只能经公开入口或能力调用器 |
| 复制第二套同类实现 | 同一目的已有实现就蒸馏进最全的那个（结果唯一即收口） |
| **让本包去调 `进程管理.执行命令` 拼命令字符串** | 编译器参数必须精确成对，字符串拆分把参数边界交给 shlex 拆词器 = 引入失败面；且与同层 `textutil提供者` 形态不一致 |
| **在 `包仓库` 里加『编译原生应用』** | 平台控制面不该承载第三方工具边界（越层） |
| **预留开发者证书/公证档位** | 本机 0 个签名身份，是死腿（哲学 1.2）；真需要时再就地补能力 |
| **照抄模板的 `提供者.py` + `子进程入口.py` 子进程架构** | 本包外部命令已由 `受限通信` 收口，再套一层子进程就是第二条进程边界 |
| **探针给 `codesign` 传 `--version`** | 实测 `codesign: unrecognized option '--version'`（退出码 2）→ 会把「可用」误报成「不可用」；正确做法是 `--help` |

## 八、第三方边界

- swiftc（外部工具，Xcode 命令行工具 `/usr/bin/swiftc`）：缺失即 `提供者不可用`；探针 `swiftc --version`；**实测版本 Apple Swift 6.4（swiftlang-6.4.0.34.1）**
- codesign（外部工具，macOS 系统签名工具 `/usr/bin/codesign`）：缺失即 `提供者不可用`；探针 `codesign --help`（**不认 `--version`**）；随 macOS 版本更新，实测 macOS 26.6.2
- `notarytool` **不进依赖**（无证书 → 公证是死腿）
- 版本取值口径：真实探测得到并写入 `依赖锁.json`；不写「取本机」这类不可判定值（哲学第 13 条：判据必须可判定）
