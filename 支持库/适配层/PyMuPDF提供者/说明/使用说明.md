# PyMuPDF 提供者使用说明

## 定位

把 PyMuPDF（fitz，原生 SWIG 扩展）隔离到**独立子进程**执行。
平台主进程、测试器、后端和发布门禁绝不直接加载 fitz/_extra.so，从而
彻底隔离 PyMuPDF SWIG 绑定在 Python 3.14 解释器关闭阶段的段错误。

只封装当前真实需要的 4 个能力（分组 **PDF渲染**），不翻译 SDK：

| 能力id | 功能 | 成功值 |
|---|---|---|
| PDF渲染.检测加密页数 | fitz 打开检测加密与页数 | {已加密, 页数} |
| PDF渲染.渲染整页 | 整页渲染为 PNG | 图像字节 base64 |
| PDF渲染.提取图像 | 提取页内嵌入图像 | [{xref, 字节b64, 尺寸}] |
| PDF渲染.校验PDF | 重新打开验证 | {页数} |

## 架构

```text
主进程调用者
  → PyMuPDF提供者.检测加密页数 / 渲染整页 / 提取图像 / 校验PDF
    → 启动一次性子进程（独立进程组，cwd=平台根）
      → 实现/子进程入口.py（内部才 import fitz）
        → stdin 一行 JSON 请求，stdout 一行 JSON 响应
        → 完成后 os._exit(0) 跳过 SWIG 模块销毁
```

页序号一律 **1 起始**（与平台 来源位置.页码 语义一致），fitz 内部按
页序号-1 索引。

## 生命周期覆盖

| 场景 | 行为 |
|---|---|
| 启动失败 | 返回 提供者不可用（可重试） |
| 正常调用 | 返回统一结果，值为 加密页数/图像字节/图像列表/页数 |
| 执行超时 | 进程组 SIGTERM→SIGKILL 强杀，返回 超时（可重试） |
| 子进程崩溃/非零退出 | 返回 提供者崩溃（可重试），下次调用重新启动 |
| 无有效响应 | 返回 提供者崩溃 |
| 停止/残留清理 | 每次调用结束后确保进程组终止，无残留进程/文件 |
| 文件状态 | 文件不存在/文件加密/文件损坏/超出限制 逐类映射稳定错误码 |

## 模拟提供者不可用（测试用依赖注入）

禁止修改 sys.modules。通过环境变量让子进程按需禁用库：

```bash
PyMuPDF提供者_禁用库=fitz   # 子进程内不加载 fitz → 提供者不可用
```

测试中使用 `mock.patch.dict(os.environ, {...})` 注入即可，不触碰 sys.modules。

## 错误码

| 错误码 | 含义 |
|---|---|
| 参数不合法 | 路径/页序号/字节 非法（主进程或子进程判定） |
| 提供者不可用 | 子进程启动失败或 fitz 被禁用/缺失（可重试） |
| 提供者崩溃 | 子进程异常退出或返回无效响应（可重试） |
| 超时 | 子进程执行超过超时秒（可重试） |
| 文件不存在 | 文件路径不存在 |
| 文件加密 | 疑似加密（needs_pass）或打开报加密相关错误 |
| 文件损坏 | fitz 打开/渲染/提取失败且非加密 |
| 超出限制 | 子进程输出超过上限 |
