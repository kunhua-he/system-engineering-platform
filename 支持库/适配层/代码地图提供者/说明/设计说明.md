# 代码地图提供者 设计说明（设计权威）

> 本文是该库的**设计哲学与边界权威**：它为什么这样切、管什么、不管什么、失败如何表达。
> 调用口径——能力、参数、返回结构、错误码与调用示例——以同目录 `使用说明.md` 为准（由能力契约生成）。
> 两份说明都计入包指纹，任何改动都要升包版本。

- 包id：支持库.适配层.代码地图提供者
- 版本：1.0.0

## 一、本包是什么

代码地图外部命令（codegraph CLI）提供者：对指定项目重建/同步代码地图索引、查询索引状态。
**传项目根目录即可**，支持任意项目，不写死本仓；缺少外部命令返回 提供者不可用，不伪装成功。

- 能力面：**检查提供者**（可用性探针）／**查询项目地图状态**（只读，含待同步变更）／**重建项目地图索引**（保鲜）。
- 一件什么东西被它收口成唯一实现（一句话）：**「代码地图索引的保鲜」** ——
  在此之间平台**有查询能力、无保鲜能力**，`.codegraph` 只能靠人手工跑外部 CLI 维护。
- 它在分层里的位置：**适配层**（第三方翻译）。codegraph CLI 与 node 是外部应用，
  本包把它们翻译成中文原语（检查／查询状态／重建），供上层按能力 id 调用。

### 为什么必须存在（本次新建的根因）

实测（2026-09-18）：`.codegraph/codegraph.db` **陈旧 28 天**，`运行核心/资源协调/句柄服务.py`、
`运行核心/统一网关/协议表.py` 等关键文件在地图里 **0 节点**。后果是子代理查符号命中 0，
只能退回 `grep` 满地找 —— 实测 13 路子代理**探索占 76% 的调用、修改只占 24%**，
单路墙钟 20–30 分钟。查清后确认这是**底层缺能力**：查询侧做成了原子能力，保鲜侧没人管。

## 二、本包不是什么（不许被当成的用法）

| 不许被当成 | 为什么 | 正确落点 |
|---|---|---|
| 万能工具包（什么都往里塞） | 一个包只做一件事才能被无数模块复用；塞第二件事就开始分叉 | 另立支持库；同目的已有的按「结果唯一即收口」蒸馏进最全的那个 |
| 业务编排层 | 编排是模块的活（只经 `获取能力调用器().调用能力` 组合） | `模块库/` |
| 第三方库的门面 | 支持库内出现第三方英文 API 就是越界 | `支持库/适配层/<提供者>`，本库只消费其中文原语 |
| **代码查询本身** | 查询已由 `代码解析支持库.代码地图.查询节点/查询关系` 收口（只读直读 SQLite）；本包管的是**索引文件的保鲜**，不是查询 | `代码解析支持库.代码地图` |
| **符号解析/语法解析** | 那是 `代码解析支持库.语法索引` 的职责（ast / tree-sitter） | `代码解析支持库.语法索引` |

## 三、管什么

- 输入口径：`项目根目录` 必填（文本型，必须真实存在且是目录，否则 `参数不合法` 并点名）；
  `重建方式` 仅接受 `同步`／`全量`（不认识即 `参数不合法`）；`超时秒` 为双精度数型（默认 120／1800）。
- 输出口径：一律返回**重命名清晰的中文字段**（`之前规模`／`之后规模`／`是否刷新`／`索引时间`／`待同步变更`），
  字段顺序稳定；`之前规模` 在库不存在时返回 `存在=false` 而不是报错（**「还没建索引」不是失败**）。
- 幂等与副作用：**查询状态只读**（`mode=ro&immutable=1` 打开，不在索引目录建 side 文件）；
  **重建索引有副作用**（会写 `<项目根>/.codegraph/`），但**幂等** —— 无变更时 `codegraph sync` 报 0 变更，
  结果一致；不修改调用方入参。

## 四、不管什么（明确交出去的责任）

| 不管的事 | 交给谁 |
|---|---|
| 路径/参数合法性以外的业务语义判定 | 调用方（模块） |
| 跨模块依赖与装配顺序 | `运行核心/加载器` |
| 权限与配额的真实拦截 | `平台控制面` |
| **索引内容的质量判定**（图里符号对不对、调用关系准不准） | codegraph CLI 本身；本包只做**机制性保鲜**与规模核对，不评索引质量 |
| **把地图当事实源做业务结论** | 调用方；地图是**派生物**，`.codegraph/.gitignore` 明确「local to each machine, not for committing」 |

## 五、为什么这样切（架构对比，必须留痕）

| 维度 | 现状做法 | 候选架构 | 裁决与理由 |
|---|---|---|---|
| 层数与边界 | 无平台能力：人工在终端跑 `codegraph sync`（还要自己发现 PATH 缺 node） | 在 `代码解析支持库.代码地图` 包内加重建能力 | **否决**：该包声明「只依赖标准库 sqlite3、只读、不写库」，加重建会同时破坏它的只读边界与零依赖口径 |
| 层数与边界 | 同上 | **新建适配层提供者，调外部 CLI** | **采纳**：codegraph 与 node 是外部应用，按仓内铁口径「第三方只进适配层」；依赖锁.json 声明真实版本 |
| IO / 重复实现 | 各会话各自 `grep` 符号（实测 76% 调用是探索） | 复用 `查询节点` + 本包保鲜 | **采纳**：查询腿不重造，本包只补保鲜；两条腿职责正交（查 vs 保鲜），不是重复实现 |
| 失败面 / 可回退 | 手工跑失败没人知道 | 能力内 fail-closed + 探针 | **采纳**：缺可执行即 `提供者不可用`、超时即 `超时`（可重试），返回前后规模供调用方**核实是否真刷新**，而不是只看退出码 |

## 六、失败如何表达

- 一律返回统一结果结构（成功/值/错误码/错误说明/来源/可重试）；**不抛裸异常给调用方**。
- 错误码只写实现里真实存在的（`结果.失败("…")` 字面量），不许虚列。
- 可重试与不可重试：**可重试**＝`超时`／`提供者不可用`（外部命令缺失或超时，环境修好即可重试）；
  **不可重试**＝`参数不合法`（调用方入参问题，重试同样结果）。
- 「没命中」与「失败」区分：**地图不存在 = 成功**（`存在=false`、各项计数 0），
  只有**外部命令跑失败/超时/缺可执行**才算失败 —— 不把「还没建索引」压成错误码。
- 部分成功：本包**无批量语义**，每次调用只针对一个项目，失败即整体失败并原样回带原因。

## 七、被否决的做法（写在这里防止重犯）

| 做法 | 为什么被否决 |
|---|---|
| 在实现里 import 第三方库 | 第三方必须由适配层翻译成中文原语；支持库直连会被依赖门禁判「第三方直连」 |
| 在实现里 import 其它包的 `实现/` 目录 | 跨包实现依赖被依赖防火墙拒；只能经公开入口或能力调用器 |
| 复制第二套同类实现 | 同一目的已有实现就蒸馏进最全的那个（结果唯一即收口） |
| **把重建能力加进 `代码解析支持库.代码地图`** | 该包以「只读、零第三方依赖」为边界；加重建会同时破坏两条边界。正解＝另立适配层提供者 |
| **把 codegraph 索引文件纳入仓库** | `.codegraph/.gitignore` 明确「local to each machine, not for committing」；地图是派生物，入库等于把生成物当事实源 |
| **让 Agent 每次开工先手工跑 sync** | 属**第二执行腿**（仓外命令绕开平台契约），且没人保证执行。正解＝做成原子能力，由平台统一维护 |

## 八、第三方边界

- **有**：`codegraph` CLI 1.5.0（npm 全局包）与 `node` 24.15.0（运行时），均为**外部应用**，非 pip 包。
- 已按规范落 `依赖锁.json`（字段：包／直接依赖／依赖闭包／环境／生成时间／说明）。
- **实测踩坑（已入锁）**：`node` 在 **`/usr/local/bin`**，不在 `/opt/homebrew/bin`；
  PATH 漏掉它会报 `env: node: No such file or directory`，因此实现内**主动前置兜底目录**
  （`/usr/local/bin`、`/opt/homebrew/bin`）再调外部命令。
- 本包只负责**调用**它，不把索引文件当自身产物；索引质量不由本包背书。
