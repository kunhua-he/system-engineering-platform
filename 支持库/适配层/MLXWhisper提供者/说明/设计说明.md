## 定位

把**语音转写**隔离到**独立子进程**执行，并按平台选择后端（**一份实现 + 模式变量**，
设计哲学第 8 条②「底子不同但格式一样 → 同一份实现 + 模式变量」）：

| 平台 | 转写后端 | 库 | 为什么 |
|---|---|---|---|
| Apple Silicon（macOS + arm64） | `mlx` | `mlx_whisper` | MLX 运行时走 **Metal**，Apple Silicon 专有 |
| Windows / Linux（含非 arm64 的 macOS） | `faster-whisper` | `faster_whisper` | `ctranslate2` 后端，不依赖 Metal |

**平台判定只有一处**：`公共契约/运行时/平台适配.转写后端()`（跨平台收口铁律：
平台差异只允许在 `平台适配.py` 与 `进程终止.py` 两处判断，**调用点不许自己写平台分支**）。
本包任何文件都不出现 `sys.platform` / `os.name`。

平台主进程、测试器和后端绝不加载任何转写库；转写库只在
实现/子进程入口.py 的隔离子进程内加载，崩溃不影响主进程。

只封装真实需要的 3 个能力（分组 **转写**）：

| 能力id | 功能 | 成功值 |
|---|---|---|
| 转写.检查可用性 | 模型是否配置/转写是否可用 | {可用, 模型名, 模型版本} |
| 转写.转写音频文件 | 音频文件转写为文本 | {文本, 语言, 模型名} |
| 转写.获取模型版本 | 模型与库版本 | {模型名, 模型版本} |

## 为什么这不是「第二条腿」（第 1.2① / 2.4①）

**内部第二执行腿：禁止**。本包只有**一条**转写链路：包入口 → 实现/提供者.py →
受管子进程 → 实现/子进程解析.py。后端选择发生在子进程解析内部，表现为
**同一份实现里的一个模式变量**：

- 对外返回结构（`值.文本` / `值.语言` / `值.模型名` / `值.分段`）与全部错误码**逐字不变**；
- 调用方（`模块库/媒体转写`、`模块库/直播逐字稿`）**零改动**，也不感知自己用的是哪个后端；
- 两个后端的**调用差异**（下述）全部吸收在子进程解析内部，不外溢到契约层。

若为 Linux 另开一个 `FasterWhisper提供者` 包并注册同名能力，那才是第二条腿（同 id 两处实现
= 哲学 1.2④ 明令禁止）；`适用平台` 的引入正是为了让它**不需要**发生。

## 后端调用差异（吸收点：实现/子进程解析.py）

| 差异项 | `mlx_whisper` | `faster_whisper` |
|---|---|---|
| 调用 | `mlx_whisper.transcribe(路径, path_or_hf_repo=目标)` | `WhisperModel(目标).transcribe(路径, **参数)` |
| 返回 | **dict**（`text` / `language` / `segments`） | **(segments 生成器, info)**；文本在 `info.text`、语言在 `info.language` |
| 分段 | list[dict]，字段在键上 | **惰性生成器**，字段在 `Segment` 对象属性上（须物化，否则分段恒空） |
| 附加术语 | `initial_prompt=` | `initial_prompt=`（语义对齐） |

适配后统一产出 `(文本, 语言, 原始分段)`，再经**同一段解析逻辑**（`_取字段` 兼容
dict 与对象两种形态）压成 `序号`/`开始秒`/`结束秒`/`文本`/`平均对数概率`/`压缩比`/`无语音概率`
——**键名与改动前逐字一致**。

## 模型配置（禁止硬编码）

模型路径/模型名来自配置，优先级：**配置对象 > 环境变量**：

| 环境变量 | 含义 |
|---|---|
| MLXWhisper提供者_模型路径 | 本地模型目录绝对路径 |
| MLXWhisper提供者_模型名 | 模型名（如 `mlx-community/whisper-tiny`；faster-whisper 支亦接受其模型名/仓库名） |

配置对象传参示例（转写/检查/版本 通用）：

```python
转写音频文件("音频.wav", 配置={"模型路径": "/路径/模型目录"})
```

两者都为空 → **未配置模型**（如实返回，绝不伪装可用、绝不模拟转写成功）。

## 依赖与平台适用

依赖锁的 `包` / `直接依赖` / `依赖闭包` 条目带可选字段 **`适用平台`**：

- `mlx-whisper`（+ `mlx`/`torch`）标 `["macOS"]`；`faster-whisper`（+ `ctranslate2`/…）标 `["Windows","Linux"]`；
- **不写该字段 = 全平台适用**（向后兼容：旧锁不改也能读，判定行为零变化）；
- 装配期（`运行环境管理器`）与强制校验（规则 3/4/6）**只处理当前平台适用的条目** ——
  这是 Windows/Linux 装配不再被 mlx 整体阻断的关键。

`mlx` 在非 Apple Silicon 上是**结构性不可用**（不是装不上依赖）：阿里云 Linux x86_64 /
Python 3.14 实测 `pip install mlx-whisper==0.4.3` 能装完整个闭包（含 torch 526MB），但
`import mlx.core` 恒报 `ImportError: libmlx.so: cannot open shared object file`
（wheel 内只有 1 个 `.so`：`mlx/core.cpython-314-x86_64-linux-gnu.so`，不存在 `libmlx.so`）。
反向实测：`faster-whisper==1.2.1` 在 Linux x86_64 + Python 3.14 可装可用。

## 架构

```text
主进程调用者
  → MLXWhisper提供者.检查可用性 / 转写音频文件 / 获取模型版本
    → 主进程判定 未配置模型/模型缺失（配置与目录检查）
    → 启动一次性子进程（独立进程组，cwd=平台根）
      → 实现/子进程入口.py（内部才按平台加载 mlx_whisper 或 faster_whisper）
        → stdin 一行 JSON 请求，stdout 一行 JSON 响应
        → 完成后 os._exit(0)
```

转写循环内轮询：超时、取消判断（转写参数 取消判断 返回真 → 取消）、
输出上限（16MB）、进程退出；进程组 SIGTERM→SIGKILL 强杀回收，无残留。

## 生命周期覆盖

| 场景 | 行为 |
|---|---|
| 未配置模型 | 返回 未配置模型（如实，不伪装可用） |
| 模型目录缺失 | 返回 模型缺失 |
| 启动失败/库被禁用/本平台后端库装不上 | 返回 提供者不可用（可重试；错误说明带**当前平台选中的后端**与模块名） |
| 执行超时 | 进程组 SIGTERM→SIGKILL 强杀，返回 超时（可重试） |
| 取消判断为真 | 进程组强杀，返回 取消 |
| 子进程崩溃/非零退出/无效响应 | 返回 进程崩溃（可重试） |
| 转写库报错/无文本 | 返回 转写失败 |
| 输出超限 | 返回 超出限制 |
| 停止/残留清理 | 每次调用结束后确保进程组终止，无残留进程/文件 |

## 模拟提供者不可用（测试用依赖注入）

禁止修改 sys.modules。通过环境变量让子进程按需禁用库（**对两个后端都成立**）：

```bash
MLXWhisper提供者_禁用库=mlx_whisper      # Apple Silicon：子进程内不加载 → 提供者不可用
MLXWhisper提供者_禁用库=faster_whisper   # Windows/Linux：同上
MLXWhisper提供者_禁用库=转写库            # 与后端无关的通用写法
```

测试中使用 `mock.patch.dict(os.environ, {...})` 注入即可。

## 错误码

| 错误码 | 含义 |
|---|---|
| 未配置模型 | 模型路径与模型名均为空（如实返回，禁止模拟成功） |
| 模型缺失 | 配置了模型路径但目录不存在 |
| 转写失败 | 转写库报错或未返回文本 |
| 超时 | 子进程执行超过超时秒（可重试） |
| 取消 | 调用方取消判断为真，转写被终止 |
| 进程崩溃 | 子进程异常退出或返回无效响应（可重试） |
| 提供者不可用 | 子进程启动失败，或**本平台选中的后端库**不可用（可重试） |
| 超出限制 | 子进程输出超过上限 |
| 参数不合法 | 文件路径等参数非法 |
| 文件不存在 | 音频文件不存在 |
