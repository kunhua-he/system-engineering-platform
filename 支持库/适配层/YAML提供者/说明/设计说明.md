# YAML提供者 设计说明（设计权威）

> 本文是该库的**设计哲学与边界权威**：它为什么这样切、管什么、不管什么、失败如何表达。
> 调用口径——能力、参数、返回结构、错误码与调用示例——以同目录 `使用说明.md` 为准（由能力契约生成）。
> 两份说明都计入包指纹，任何改动都要升包版本。

第三方 PyYAML 的唯一边界封装。上层支持库通过本提供者解析/序列化 YAML。

- `检查可用性`：探针，报告 PyYAML 依赖是否可导入及版本（供健康检查与依赖审计使用）。

## 依赖缺失的表达（容忍式导入，2026-09-19 修）

- **导入容忍**：模块级 `import yaml` 走 `try / except`，**缺包不抛**。
  本包是**纯 Python 库**，按 `运行核心/运行环境管理器/提供者生命周期.py` 的
  「提供者隔离边界」（原生扩展与不可控全局状态第三方不得在主进程导入）属于
  允许主进程导入的一类，因此**装配不得因缺依赖被阻断** —— 否则在干净机器
  （未装 PyYAML 的 Linux / Windows / 新 macOS）上本包会被记成
  「入口装配｜装配失败」并整包跳过，装配冒烟的「无跳过包」断言随之失败。
- **调用时明确失败**：依赖缺失只在**调用时**体现，错误码固定为 `依赖不可用`
  （`解析YAML` / `序列化YAML` / `检查可用性` 三条能力都如此），
  **绝不静默降级**（不返回空值、不返回空文档冒充成功、不假装可用）。
- **探针的两段判定**：提供者层 `检查可用性()` 缺依赖时**如实返回** `可用=假` 与
  留痕的导入失败原因（探针的「不可用」是判定结果，不是异常）；把 `可用=假`
  翻成中文错误码 `依赖不可用` 的收口落在能力边界 `__init__.py`。
- **异常类型**：`YAML解析错误` 在依赖可用时**就是**第三方 `yaml.YAMLError`
  （既有类型口径逐字不变，调用方 `except YAML解析错误` 原样成立）；依赖缺失时
  退化为 `YAML依赖不可用`，两种环境下都可捕获。
