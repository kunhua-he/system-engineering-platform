第三方 `tree-sitter` + `tree-sitter-typescript` 的唯一边界封装：**一个第三方发行包只归属
一个独立支持库与一个受管提供者**。上层支持库（`支持库.后端.代码解析支持库.语法索引`）
只经本提供者拿语法树，全仓除本目录外不得出现 `tree_sitter*` 的直接导入。

## 为什么把「遍历」留在调用方

本层只做**翻译**：第三方语法树 → 底座**中性语法树**（节点种类、字段名一律中文）。

- 第三方强制的英文（grammar 节点类型名 `import_statement` / `member_expression`、
  field 名 `source` / `function`，以及 `Parser` / `Language` 对象）**只活在本目录内**，
  与 AGENTS.md「第三方强制英文只留在支持库适配层」一致；
- 「哪些节点算导入、哪些算符号、哪些算调用、要不要字符串常量」是**业务语义**，
  属调用方（语法索引）的领域判断，本层不代替它决定，也不为它预先裁剪节点；
- 因此本层不是「tree-sitter 的薄壳转发」：调用方拿到的是中文种类 + 中文字段名的
  普通 dict，第三方节点对象与英文类型名都不越界。

## 中性语法树结构

每个节点是一个可 JSON 化的平铺 dict：

| 键 | 含义 |
|---|---|
| 种类 | 中文种类；未登记的一律 `其他` |
| 起始行 / 结束行 | 行号 1 起算 |
| 起始字节 / 结束字节 | utf-8 字节区间，供调用方按原字节切文本（引号内字符串值等） |
| 字段 | 中文字段名 → 子节点下标；与第三方 `child_by_field_name` 同口径（同名字段取第一个） |
| 子节点 | 全部子节点，顺序与第三方 `children` 一致（含标点 / 关键字等未命名节点） |

已登记种类：导入语句、导出语句、函数声明、函数表达式、箭头函数、词法声明、变量声明符、
类声明、方法定义、调用表达式、字符串字面量、模板字符串、标识符、成员访问。
已登记字段名：来源、名称、值、正文、调用目标、实参、对象、属性。
**未登记的种类/字段名不导出**——底座要用新字段时在这里登记，这是刻意的收口：
第三方英文不允许靠「原样透传」漏出去。

## 失败如何表达

| 场景 | 行为 |
|---|---|
| tree-sitter 未安装 / 版本不兼容 / 语言工厂缺失 | 抛 `TreeSitter解析错误`；能力边界返回 `提供者不可用`，不伪装成功 |
| 语言名不在支持集 | 能力边界返回 `参数不合法`（400） |
| 源码有语法错误 | **不抛异常**：第三方按错误恢复继续出树，错误区照常翻成中性节点（调用方据此产出它已声明的事实） |
| 探针（检查可用性） | 依赖不可用时返回 `可用=false` + 原因，不抛异常 |

降级（例如语法索引退回正则）是**调用方的策略**，本层不自作主张降级——本层只如实报不可用。

## 关键实现决策

- 解析器按语言在进程内复用（双检锁，只构造一次）；`Language` 构造昂贵，不按调用重建。
- 语言集 `typescript` / `tsx` 都来自同一发行包 `tree-sitter-typescript`，不额外引入第三方。
- 依赖导入做成**惰性**（函数内 import）：包入口在依赖缺失时也能导入，探针才能如实报告不可用。
