# 网关调用最小示例

本文件只说明外部程序如何通过 HTTP 调用支持库和模块。完整参数、返回字段、错误码和资源预算，以 `能力详情` 返回的能力契约为准。

## 地址

```text
http://127.0.0.1:40007
```

网关默认只监听本机回环地址。远程部署时使用实际网关地址和端口，不使用代理端口 `4780`。

## 第一步：读取目录

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -d '{"操作":"能力目录","参数":{}}'
```

首次只返回支持库、模块库、包名称、简介和能力数量，不加载全部命令正文。目录默认分页，每页 20 个包；返回 `总包数`、`偏移`、`限制`、`下一偏移` 和 `是否完成`，把 `下一偏移` 传回即可继续读取。

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -d '{"操作":"能力目录","参数":{"偏移":20,"限制":20}}'
```

也可以用 `GET /健康` 检查网关状态。

## 第二步：查看包和能力

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -d '{"操作":"包详情","参数":{"包id":"模块库.文档读取"}}'
```

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -d '{"操作":"能力详情","参数":{"能力id":"文档读取.结构化读取"}}'
```

只有真正准备调用时，才读取单项能力的参数、返回、错误码、依赖和调用示例。

## 第三步：调用能力

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -d '{
    "操作":"调用能力",
    "能力id":"文档读取.结构化读取",
    "参数":{"文件路径":"/tmp/a.md"}
  }'
```

`/网关/调用` 是唯一执行入口；项目不做 `/网关/请求` 兼容。模块和支持库都使用同一套入口，不直接暴露各自端口。

## JavaScript 调用

```js
const response = await fetch("http://127.0.0.1:40007/网关/调用", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    操作: "调用能力",
    能力id: "文档读取.结构化读取",
    参数: { 文件路径: "/tmp/a.md" }
  })
});
const result = await response.json();
```

统一返回信封固定包含以下键（**只增不改不删**，调用方按需取键即可）：

```json
{
  "请求id": "0e53af5a91c1414c",
  "操作": "调用能力",
  "成功": true,
  "值": {},
  "错误码": "",
  "错误说明": "",
  "句柄": null,
  "耗时毫秒": 0.14,
  "请求版本": "",
  "当前版本": "2.0.0",
  "版本差异": ""
}
```

## 调用方只需记住的四条兼容口径

1. **多传字段不会失败**：顶层字段、操作参数、能力入参里的**未知字段一律忽略**（网关在边界剔除，不会转给实现）。
   上游先升级、底座后升级都不影响。
2. **只有两类会报错**：**必填参数缺失** 与 **参数类型不符**（错误码 `参数不合法`，错误说明点名字段与期望类型）。
   其余情况都放行。
   - 类型校验按**平台正式类型表**（`公共契约/基础类型/类型表.py`）**等宽执行**，在网关**唯一校验点**做，能力实现里不重复写：
     `文本型` 只收文本，`整数型` 只收整数（`3` 不是 `"3"`，布尔不算整数），`双精度数型` 收 `30.0` 不是 `30`，
     `字节集型` 收 `bytes` / 冻结字节集对象 / base64 文本，`空值型` 只收 `null`。
   - **显式 `null` 不等于「未提供」**：要省略参数就**不要传这个键**，传 `null` 按类型不符拒绝。
   - 参数**声明了平台不认识的类型**时一律 `参数不合法`（fail-closed）：宁可明确报错，也不静默放行成「谁都不校验」。
3. **版本不一致不失败**：请求可带 `请求版本`（旧名 `契约版本` 仍永久可用）；返回里会告诉你
   `请求版本` / `当前版本` / `版本差异`。**只有强制约束（如依赖声明 `>=x.y.z`）不满足才失败**。
4. **信封只增不减**：新增字段只会**追加**，旧的键语义永不变；调用方不用跟着改。

## 长任务：提交 → 轮询 → 取消

超过十几秒的活不要用同步调用硬扛，走任务三操作：

```bash
# 提交（当场拿任务id）
curl -X POST http://127.0.0.1:40007/网关/调用 -H 'Content-Type: application/json' \
  -d '{"操作":"任务提交","能力id":"模块库.直播逐字稿.全自动精校","参数":{"源文件路径":"/abs/a.mp4"},"超时秒":1800}'

# 轮询（状态：等待中/运行中/成功/失败/已取消/超时/崩溃）
curl -X POST http://127.0.0.1:40007/网关/调用 -H 'Content-Type: application/json' \
  -d '{"操作":"任务查询","参数":{"任务id":"0fbdd772a0784792"}}'

# 取消
curl -X POST http://127.0.0.1:40007/网关/调用 -H 'Content-Type: application/json' \
  -d '{"操作":"任务取消","参数":{"任务id":"0fbdd772a0784792"}}'
```

任务状态与账本由底座内部维护（运行态落在底座运行库里），**调用方不需要知道底座怎么存、怎么跑**。

## 句柄

首次成功调用由网关生成整数句柄并写入权威状态账本；后续请求只能填入此前返回的整数句柄。句柄不是模块内部对象；释放或沉默超时后账本标记为已失效，再次调用直接返回 `句柄已过期`。

查询句柄状态：

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -d '{"操作":"资源状态","句柄":428101,"参数":{}}'
```

关闭句柄：

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -d '{"操作":"资源关闭","句柄":428101,"参数":{}}'
```

`资源续租` 的参数为 `{"句柄":428101,"租约秒":300}`。句柄必须是整数且来自网关返回值；过期、跨项目或跨所有者时，网关明确拒绝。网关只返回生命周期状态，不替代模块业务查询。

## 凭证

启用凭证后，在请求头携带：

```text
Authorization: Bearer <网关凭证>
```

凭证只从受控环境变量加载，不写入 HTML、代码仓库或日志。
