# 系统工程平台 · 底座能力命令规范（冻结草案）

> 本文件是进入代码开发前的命令、参数、返回值和生命周期冻结单。它回答“调用什么、传什么、返回什么、失败如何表示、资源何时释放”。
> 本文件批准后，才允许把条目编译为各包的 `包声明.json`、`能力契约/参数契约.json` 和包级入口。代码不能反过来发明第二套命令。
> 当前版本先冻结数据库、LLM、ASR 三个高风险能力族；其余既有包尚未因“已有代码或测试通过”而自动批准。未补齐本文件字段的能力，状态为“未冻结、不得新增调用方”。

## 1. 总流程

```text
需求确认
  → 能力搜索（命令 id 唯一性检查）
  → 选择支持库原子命令 / 模块组合命令
  → 查看本文件冻结的参数、返回、错误码、状态机
  → 申请能力版本与资源预算
  → 生成包声明和参数契约
  → 实现包级公开入口（注册能力）
  → 运行核心装配、提供者路由、租约与资源监督
  → 真实调用验证（返回值 + 错误 + 释放证据）
  → 进入正式能力目录
```

调用时只有一条路径：

```text
调用方
  → HTTP 能力网关：能力id + 契约版本 + 参数
  → 唯一能力注册表
  → 模块公开命令（可组合多个原子命令）
  → 支持库公开命令
  → Provider/系统/第三方执行单元
  → 统一结果 + 状态 + 释放证据
  → 调用方
```

禁止网关、本地协议、测试脚本分别再实现一套同名业务命令。命令的唯一身份是 `能力id`，脚本只是传输入口。

## 2. 统一外壳

### 2.1 请求

```json
{
  "能力id": "数据库.mysql.连接",
  "契约版本": "1.0.0",
  "请求id": "调用方生成的幂等标识",
  "参数": {},
  "截止时间": "可选 ISO-8601",
  "取消令牌id": "可选"
}
```

参数只属于具体命令；不能因为同属数据库、LLM 或 ASR 就强行共用参数。

### 2.2 返回

```json
{
  "成功": true,
  "值": {},
  "错误": null,
  "来源": "支持库.适配层.mysql提供者",
  "可重试": false,
  "资源": {
    "执行单元id": "可选不透明句柄",
    "租约id": "可选不透明句柄",
    "状态": "已释放",
    "残留": []
  },
  "证据": {"调用记录id": "可选"}
}
```

失败时 `成功=false`、`值=null`，错误必须包含稳定 `错误码` 和 `错误说明`；不得把空列表、空文本、默认数字包装成成功。统一错误码分类：`参数不合法`、`未配置`、`提供者不可用`、`资源不存在`、`超时`、`取消`、`冲突`、`执行失败`、`进程崩溃`、`超出限制`、`句柄过期`。

### 2.3 有状态能力

```text
未创建 → 已创建 → 可用 → 执行中 → 可用 → 关闭中 → 已释放
                         └→ 失败/崩溃 → 回收中 → 已释放
```

句柄是固定六位数字字符串（保留前导零，例如 `004281`），是不透明的外部精准查询键，不跨模块共享模块内部对象。调用方不得接触连接对象、模型对象、进程号、游标、线程或第三方实例。重复关闭必须幂等；租约过期后所有命令返回 `句柄过期`。每个模块仍在自己的 owner 内维护增删改查和领域状态。

## 3. 支持库与模块边界

| 类型 | 负责 | 不负责 |
| --- | --- | --- |
| 支持库 | 一个外部边界或一个纯原子动作；参数转换、错误转换、资源释放、版本探针 | 领域流程、跨库业务状态、第二套网关 |
| 模块库 | 组合多个公开能力；定义步骤顺序、领域状态、幂等和产物 | 直接 import 第三方、直接持有 Provider 对象 |
| 运行核心 | 注册、路由、租约、超时、取消、回收、证据 | 业务 SQL、提示词、ASR 文本整理 |

一个服务/驱动/协议一个支持库。`mysql`、`postgresql`、`sqlite` 是不同支持库；`Ollama`、`Chat Completions`、`Responses`、`Anthropic Messages` 是不同 LLM 提供者支持库；ASR 也是独立支持库族。上层模块只依赖抽象能力 id，不依赖具体提供者包 id。

### 3.1 基础类型归属

易语言式的 `逻辑型`、`整数型`、`长整数型`、`单精度数型`、`双精度数型`、`文本型`、`字节集型`、`列表型`、`字典型`、`日期时间型`、`资源引用型`、`句柄型` 和 `结果型` 由 `公共契约/基础类型/类型目录.md` 统一定义。它们属于系统核心的契约类型，不再为每个支持库复制一套类型。

支持库只做边界转换：例如 MySQL 驱动整数转换成 `整数型/长整数型`，HTTP JSON 转换成 `字典型`，模型流转换成 `文本型/字节集型`。转换失败返回统一错误，不允许把第三方对象直接暴露给模块。

### 3.2 核心支持库与子支持库

```text
支持库/
└── 核心/                    ← 能力域，不直接承载业务流程
    ├── 类型转换/             ← 原子转换子支持库
    ├── 类型校验/             ← 原子校验子支持库
    ├── 数据编码/             ← JSON/CSV/字节编码原子能力
    ├── 错误处理/             ← 错误结构和稳定错误码原子能力
    └── 资源引用/             ← 资源摘要、引用和释放原子能力
```

“核心支持库”是物理能力域；“子支持库”才是实际注册和调用的包。每个子支持库必须有独立包 id、版本、能力契约、参数、返回和验证场景，但只允许提供原子动作。它和模块的区别是：子支持库不能编排业务步骤、不能维护领域状态、不能把多个外部服务拼成流程。

因此 `类型转换.文本转整数` 是核心支持库原子命令；`文档读取.读取正文` 是模块命令；前者可以被多个模块复用，后者负责完整领域流程。

## 4. 数据库支持库命令

数据库提供者统一返回 `数据库句柄`，但各连接命令可拥有不同参数。连接串不得写入日志或证据正文。

### 4.1 MySQL 提供者

包：`支持库.适配层.mysql提供者`。公开命令：

| 命令 id | 必填参数 | 可选参数 | 成功值 | 资源状态 |
| --- | --- | --- | --- | --- |
| `数据库.mysql.连接` | `地址` 文本、`端口` 整数、`账号` 文本、`密码引用` 文本、`数据库` 文本 | `连接超时秒`、`字符集` | `{数据库句柄,服务器版本,事务状态:"未开始"}` | `可用` |
| `数据库.mysql.断开` | `数据库句柄` | `截止时间` | `{已断开:true}` | `已释放` |
| `数据库.mysql.执行SQL` | `数据库句柄`、`SQL` 文本 | `参数` 列表、`最大行数`、`截止时间` | `{列:[...],行:[...],影响行数,最后插入id}`；无结果集时 `列`、`行` 为空 | 仍为 `可用` |
| `数据库.mysql.开始事务` | `数据库句柄` | `截止时间` | `{事务状态:"进行中"}` | `可用/事务中` |
| `数据库.mysql.提交事务` | `数据库句柄` | `截止时间` | `{事务状态:"已提交"}` | `可用` |
| `数据库.mysql.回滚事务` | `数据库句柄` | `截止时间` | `{事务状态:"已回滚"}` | `可用` |
| `数据库.mysql.探针` | `地址`、`端口` | `超时秒` | `{可用,服务器版本}` | 一次性，自动释放 |

错误码至少包括：`参数不合法`、`连接失败`、`认证失败`、`数据库不存在`、`SQL语法错误`、`事务状态错误`、`句柄过期`、`超时`、`提供者不可用`。SQL 必须参数化；禁止字符串拼接和跨请求共享游标。

### 4.2 PostgreSQL 与 SQLite

PostgreSQL 使用同一组语义命令，将前缀替换为 `数据库.postgresql`，连接参数为 `连接串` 或结构化 `地址/端口/账号/密码引用/数据库`，不得同时要求两套。SQLite 使用 `数据库.sqlite.连接`，必填 `文件路径`，不接受账号密码；三者都只提供一个 `执行SQL` 命令，SQL 是否产生结果集由返回值表达，不再另设“查询”命令。三者都必须注册到公共能力注册表，不能继续留在 `平台控制面/提供者/` 旁路。

## 5. LLM 支持库族

LLM 不是一个巨型包。协议、传输和模型后端各自独立，但上层抽象能力保持稳定。

LLM 是可选依赖，不是底座默认依赖。只有节点的行为确实需要生成、理解、分类、抽取、重排或语义判断时，才能在能力条目中声明 `需要能力: 对话.*`、`Embedding.*` 或 `重排.*`。文件读写、数据库执行 SQL、确定性格式转换、哈希、时间计算、状态流转、资源释放等节点禁止为了“以后可能用到”而声明 LLM。

依赖判定顺序固定：

```text
输入是否能由确定性规则处理？
  ├─ 是 → 不需要 LLM
  └─ 否
       是否需要生成/语义理解/分类/抽取/重排？
         ├─ 否 → 不需要 LLM，寻找专用支持库或模块
         └─ 是 → 声明最小抽象能力（对话/Embedding/重排）
                    → 由运行核心选择一个已配置 Provider
```

节点不得直接声明“依赖 LLM 包”；必须声明具体能力 id 和是否必需：`必需` 时 Provider 不可用就阻断，`可选` 时只能按契约定义的确定性回退运行，禁止用空结果假装完成。

### 5.1 共同抽象能力

模块只依赖以下能力 id：

| 能力 id | 参数 | 成功值 |
| --- | --- | --- |
| `对话.检查可用性` | `模型引用`、`截止时间` | `{可用,模型名,模型版本,能力}` |
| `对话.生成` | `消息列表`、`模型引用`、`最大输出token`、`温度`、`截止时间` | `{文本,模型名,用量,是否截断}` |
| `对话.流式生成` | `消息列表`、`模型引用`、`最大输出token`、`截止时间` | `{流句柄}`，后续读取事件 |
| `对话.读取流事件` | `流句柄` | `{事件类型,文本增量,工具调用,完成原因}` |
| `对话.关闭流` | `流句柄` | `{已关闭:true}` |
| `对话.获取模型信息` | `模型引用` | `{模型名,版本,上下文上限,能力}` |

`消息列表` 是 `{角色,内容}` 数组；工具调用、图像和结构化输出通过可选字段声明，不允许把某个协议的原始请求体泄漏到模块契约。

### 5.2 协议提供者

| 包 | 负责命令 | 额外参数/边界 |
| --- | --- | --- |
| `支持库.适配层.Ollama提供者` | 注册共同抽象能力 | `服务地址`、`模型名`；本地进程/HTTP、模型加载和取消由执行单元管理 |
| `支持库.适配层.Chat协议提供者` | 注册共同抽象能力 | `服务地址`、`API密钥引用`、`模型名`；兼容 Chat Completions 的字段映射 |
| `支持库.适配层.Responses协议提供者` | 注册共同抽象能力 | `服务地址`、`API密钥引用`、`模型名`；维护 response/output/tool 事件转换 |
| `支持库.适配层.Anthropic协议提供者` | 注册共同抽象能力 | `服务地址`、`API密钥引用`、`模型名`；维护 content block/stop reason 转换 |
| `支持库.适配层.云端LLM协议` | 注册共同抽象能力 | 只负责统一云端协议边界；具体厂商作为独立 Provider，不把厂商名混进模块流程 |

提供者特有错误先映射为统一错误码，再把原始状态放入受控详细信息。未配置模型、缺少密钥、协议不支持、上下文超限、限流、服务端错误必须分别可诊断；禁止返回空文本成功。

## 6. ASR 支持库族

ASR 与对话 LLM 完全分离。包级原子命令：

| 命令 id | 参数 | 成功值 |
| --- | --- | --- |
| `语音识别.检查可用性` | `模型引用`、`截止时间` | `{可用,模型名,版本,语言}` |
| `语音识别.转写文件` | `文件引用`、`模型引用`、`语言`、`时间戳级别`、`截止时间` | `{文本,语言,分段,模型名}` |
| `语音识别.开始流式转写` | `音频格式`、`模型引用`、`语言` | `{流句柄}` |
| `语音识别.写入音频块` | `流句柄`、`音频块引用` | `{已接收字节数}` |
| `语音识别.结束流式转写` | `流句柄` | `{文本,分段}` |
| `语音识别.取消` | `流句柄` | `{已取消:true}` |

Whisper、MLX Whisper、云 ASR 只替换支持库提供者，不复制“媒体转写”模块。`模块库.媒体转写` 负责视频抽音频、转写、产物落盘和业务状态；它不得直接导入 Whisper 实现。

## 7. 模块命令样例

模块命令必须表达完整流程，而非重新暴露底层驱动：

| 模块命令 id | 参数 | 成功值 |
| --- | --- | --- |
| `媒体转写.转写视频文件` | `文件引用`、`语言`、`模型引用`、`超时秒` | `{文本,分段,产物摘要,提供者}` |
| `文档读取.读取` | `文件引用`、`格式提示`、`最大字节数` | `{标题,段落,表格,来源摘要}` |
| `知识检索.建立索引` | `文档集合引用`、`Embedding能力id`、`索引版本` | `{索引版本,文档数,向量数}` |
| `知识检索.查询` | `索引引用`、`查询文本`、`数量`、`重排能力id` | `{命中列表,索引版本}` |
| `Agent.执行` | `任务描述`、`对话能力id`、`工具集合`、`最大步骤数` | `{最终结果,步骤摘要,终态}` |

模块失败必须保留步骤和资源收口证据；不能因为某个子能力失败就把缺失字段填成空值后返回成功。

## 8. 命令目录字段（编译输入）

每条命令最终必须具备以下字段，缺一不可：

```json
{
  "能力id": "唯一中文命令id",
  "版本": "1.0.0",
  "所有者包id": "唯一支持库或模块",
  "类型": "支持库原子能力/模块组合能力",
  "参数": [{"名称":"","类型":"","必填":true,"默认值":null,"约束":""}],
  "返回": {"类型":"结果","值结构":{}},
  "错误码": ["稳定错误码"],
  "状态机": {"初始":"","允许流转":[]},
  "资源预算": {"超时秒":0,"最大输出字节":0,"最大并发":0},
  "调用示例": {"能力id":"","参数":{}},
  "真实验证": {"命令":"","期望退出码":0}
}
```

命令撞车判定：同一 `能力id` 不允许不同参数/返回/所有者；不同 Provider 可以注册同一抽象能力，但必须通过提供者路由选出唯一实现，不能同时把两个实现写进正式注册表。

命令条目是唯一编辑源。`包声明.json`、参数契约、能力搜索数据、注册入口和验证引用均应由契约编译器生成；手工修改派生文件必须被摘要校验拒绝。严格校验还必须拒绝缺少顶层契约版本、空错误码、`任意`类型、缺调用示例或缺资源预算的条目。

## 9. 开发前阻断清单

在规范转代码前，以下事项必须完成：

1. 将 SQLite、PostgreSQL 和待新增 MySQL 从控制面旁路迁移为正式支持库包。
2. 新建云端 LLM 协议支持库，冻结 Chat、Responses、Anthropic、SSE 的统一请求/返回，再按厂商建立 Provider。
3. 为所有数据库、LLM、ASR 命令补齐版本、错误码、资源预算和真实调用场景。
4. 把所有公开入口统一转换为公共 `结果`，禁止裸字典和私有 dataclass 穿过边界。
5. 先运行命令唯一性检查和契约编译，再开始实现；任何未列在本文件的命令一律视为未批准能力。
6. 每个有状态支持库必须补齐创建、使用、过期、关闭、崩溃回收和零残留验证。
7. 现有 `平台控制面/提供者/` 数据库旁路和缺顶层契约版本的能力条目，均列为规范阻断，不得以定向测试通过替代修复。

本清单完成前，不进入“补功能”开发；只允许修复阻断规范的契约和目录结构。
