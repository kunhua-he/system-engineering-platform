# 剩余风险

1. **归属判定依赖「已发现包 id 集合」而非目录结构**。若某子包因缺 `能力定义.json`
   未被发现器收录，其能力仍会被算作父包「注册未声明」——这与旧行为一致，
   属预期语义，但对使用者是隐性约束，已在 `_校验热接入包` 文档串里写明。

2. **父包与子包版本各自独立**。父包 `完整性摘要.json` 现覆盖子树全部 24 个文件，
   子包自身 8 个文件。子包改动会同时导致父包摘要变化（父包走「变更」热接入，
   实际不重载子包能力，仅刷新摘要），性能影响可忽略（0.2~0.6s）。

3. 本次修改已使平台「活父包 + 独立子包」配置可行；该配置此前无任何包使用，
   除 `代码解析支持库.语法索引` 外尚无第二个实例，长期多实例共存未做压力验证。

4. **本工作包收口（delivery_closeout）被平台既有缺陷阻断**，与本修复无关：
   `verify_and_record` 写入的 `工作区指纹` 是 `sha256(git status --porcelain)`
   （64 位），而 `收口登记` 比对的是 `计算代码指纹`（文件内容摘要前 16 位），
   二者恒不相等 → 任何带证据的工作包都报 `EVIDENCE_MISMATCH`。
   已登记为旁路 **B8**（`开发文档/归档/202609_系统工程平台审计/旁路问题_待下一批.md`），
   修复需重启共享的 8766 MCP 服务进程，按批次顺延。
   本工作包的反馈与验证证据均已真实入账，仅"生命周期置完成"一步未能落库。
