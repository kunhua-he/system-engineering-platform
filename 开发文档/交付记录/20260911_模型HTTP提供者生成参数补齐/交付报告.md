## 背景

40007 执行网关冷启动后，任何 LLM 生成调用一律失败：

```
{"成功": false, "错误码": "模型调用失败",
 "错误说明": "LLM 调用异常: 调用对话() got an unexpected keyword argument '温度'"}
```

`连接LLM` 正常返回句柄，`生成对话` 必挂；V3 `底座提供商.对话` 因此恒返回错误信封。

## 根因

```
生成对话(句柄, …, 温度, 最大令牌数, 工具, 响应格式, 附加请求头)   ← 8 个键
  → _调用模型 → 调用函数表["LLM:云端"]        ← 注册模型HTTP提供者() 写入
  → 模型HTTP提供者.调用对话(配置=…, **参数)   ← 签名只收 5 个键 → TypeError
```

`注册模型HTTP提供者()` 于 `大语言模型支持库/__init__.py` 导入时执行，把
`模型HTTP提供者.调用对话` 注册为 LLM 本地/云端调用器，**优先级高于连接器自带的
`_HTTP调用模型` 兜底**。两者本应「同一协议契约」（`_HTTP调用模型` 文档串自称），
实际签名与返回键集长期分叉。

**为既有提交缺陷，非本次引入**：`git diff d7a7bcb a155e4e -- 支持库/适配层/模型HTTP提供者.py`
显示 `调用对话` 原签名即缺这四个生成参数。

## 为什么长期被掩盖

`运维脚本/热接入.py` 重载 `支持库/后端` 会重新执行 `模型连接器/实现/模型连接器.py`，
把模块级 `调用函数表` 重置为 `{}`，但**不会**重跑 `大语言模型支持库/__init__.py`
（注册发生在该文件导入时）。热接入后 `调用函数表` 为空，`_调用模型` 落回完整的
`_HTTP调用模型` 兜底 —— 热态一切正常，**首次冷启动即引爆**。

## 方案

把 `调用对话` 补齐到与 `_HTTP调用模型` 同一协议契约：

1. 签名补 `温度 / 最大令牌数 / 工具 / 响应格式` 并加类型校验；
2. 载荷按协议映射：

   | 参数 | chat_completions | codex_responses |
   |------|------------------|-----------------|
   | 温度 | `temperature` | `temperature` |
   | 最大令牌 | `max_tokens` | `max_output_tokens` |
   | 工具 | `tools` | `tools` |
   | 响应格式 | `response_format` | `text.format` |

3. 新增 `_归一化响应()`，函数内延迟导入连接器公开的 `归一化对话响应`（避免环形导入），
   产出 `内容/思考/工具调用/结束原因`，与既有 `回复/用量` 并存 —— 成功值键集与
   `_HTTP调用模型` 逐键一致；
4. `流式输出=True` 仍返回「流式能力未装配」失败（流式走 `流式调用对话` 独立通道），
   不伪造完成结果。

不动 `_HTTP调用模型`，不改连接器签名，不改 `注册模型HTTP提供者`。对外契约零改动。
