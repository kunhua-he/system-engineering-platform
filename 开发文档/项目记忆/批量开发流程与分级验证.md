系统工程平台开发采用分级验证，禁止每个小改动重复跑全量。流程固定为：1）先调用 project_context，核对项目名称、根目录、MCP 实例、代码地图、当前 Git 指纹和最近成功验证；2）用 codegraph_explore 定位符号、调用链和影响范围；3）按同一目标冻结工作包，先登记临时开发文档，明确允许修改目录和回退方式；4）小改动只跑受影响测试文件（工作包），无共享资源的测试才并行；一批工作包合并后只跑受影响阶段（合并波次）；所有工作包完成后才跑一次常规全量（阶段收口）；正式发布前再编译制品、提交制品后只跑一次发布门禁；5）测试必须经项目统一入口，区分真实 HTTP、契约、功能、慢速和缓存复用，不能用缓存或文本命中冒充真实通过；6）收工先提交 mcp_feedback 五字段，再由 verify_and_record 记录退出码为0且判定通过的证据；代码指纹变化后只复验受影响范围。资源释放统一遵循：请求结束→有界等待→必要时强杀→确认进程/线程已结束→关闭管道和临时资源→删除权威记录；未收敛必须保留账本，禁止伪装成功、先删记录或先启动替代进程。
