# 节点层级规范（2026-08-26 华哥口径）

> 底座能力分层：支持库 → 模块 → 业务层。
> 每一层向下依赖，不跨层调用；同层之间不互相依赖。

---

## 一、支持库：唯一原子能力

**定义**：能力边界固定最小化的原子能力。不实现任何业务逻辑。

**特点**：
- 每个支持库只做一件事，且唯一（如 `嵌入缓存` 只做缓存，不调模型）
- 输入输出固定，契约冻结，接口不随业务变
- 内核可独立升级（小版本），不改变传参
- 无业务逻辑、无组合、无流程编排

**归属**：`支持库/后端/<能力域>/`（五件套：包声明 + 能力定义 + 契约 + 实现 + 摘要）

**示例**：
```
删除守卫.检查删除(目标表, 删除比例, 过滤条件) → {通过, 原因}
协议白名单.校验端点(api类型, base_url) → {通过, 原因}
幂等消息.生成id(会话id, 内容) → {幂等id}
嵌入缓存.查询嵌入(文本, 模型名, 提供者) → {命中, 向量}
模型连接器.连接向量模型(模型, 提供者, 部署形态, ...) → {句柄}
模型连接器.生成嵌入(句柄, 文本) → {向量}
```

---

## 二、模块：功能唯一性封装

**定义**：按功能保持唯一性的能力封装。接收完整传参，内部组合支持库原子能力完成功能，不包含完整业务逻辑。

**特点**：
- 功能唯一（如 `知识检索` 就是唯一一个，没有多个变体）
- 只接收传参，一次性传完所有参数（模型用哪个、url 是什么、路径在哪等）
- 内部组合多个支持库原子能力，通过 `获取能力调用器().调用能力()` 组合
- 后续最新版本内核可单独更新，但功能只保持一个
- 无完整业务逻辑，只是功能封装
- 失败不伪绿：子能力失败必须透传

**注意**：模块不是"中间层"——它只是功能的封装层，不是业务层。业务层（V3）直接调模块，传参到位。

**归属**：`模块库/<模块名>/`（五件套 + 依赖声明依赖哪些支持库能力）

**示例**：
```
知识检索.检索知识(
  查询,                    # 检索内容
  知识库路径,               # 文件系统路径
  模型名, 提供者, 部署形态,  # 模型配置（谁来做嵌入和重排）
  url, api_key,             # 云端模型配置
  顶部数量                   # 结果限制
) → {来源, 相关文档, 重排结果, 缓存命中, 总数}
```

**调用链路**：
```
模块.功能(模型参数, 路径参数, 条件参数 ...)
  └─ 经 能力调用器.调用能力(支持库.能力, 子参数)
  └─ 经 能力调用器.调用能力(支持库.能力, 子参数)
  └─ 组合结果 → 返回
```

## 三、业务层（如 V3）：业务逻辑层

**定义**：使用模块或支持库完成具体业务场景的层级。接收业务请求，组织传参，处理结果。

**特点**：
- 使用支持库 → 传参（如用 LLM → 传 LLM 模型配置）
- 使用模块 → 传参（如用知识检索 → 传 查询/知识库路径/模型配置/url 等）
- 传参一次性到位，不拆成多次调用
- 业务逻辑（如：用户输入 → 判断用哪个模型 → 调知识检索 → 格式化输出）全在业务层

**归属**：各业务项目（如 `华世王镞_v3/`）的 后端服务/功能模块

**示例**：
```
# V3 业务层调知识检索模块
知识检索.检索知识(
    查询=用户输入,
    知识库路径=知识库配置,
    模型名=环境配置.默认向量模型,  # Qwen3-Embedding-8B
    提供者="本地",
    部署形态="本地",
    顶部数量=10
)
```

## 四、完整调用链

```
V3 业务层（业务逻辑、传参组装）
  │ 一次性传参（模型配置、路径、条件等）
  ↓
模块（功能唯一性封装，组合支持库原子能力）
  │ 经 能力调用器.调用能力()
  ↓
支持库（原子能力，无业务逻辑）
  │ 经 网关/能力调用器
  ↓
适配层/第三方（外部服务、系统工具）
```

**纪律**：
- 业务层不直接调支持库实现（经模块或经调用器）
- 模块不直接 import 支持库实现（经能力调用器）
- 支持库不调业务层、不调其他支持库（只经网关/调用器）
- 支持库之间不依赖、不独立传参（参数统一在 env 定义）
