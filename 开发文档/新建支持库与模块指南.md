# 新建支持库与模块指南

> 结论先给：**代码模板有三个（必须用），专门讲流程的 md 原来没有，这份就是**。
> 模板：`开发工具/组件规范/支持库模板生成器.py`、`模块模板生成器.py`、`核心快照模板.py`。
> 三个都是「Python 函数调用」，**没有命令行参数**；生成即完整骨架，不手搓。

## 一、先判断该建什么（分层归属固定，哲学第 12 条）

| 你要做的东西 | 落到哪 | 判据 |
| --- | --- | --- |
| 最小原子能力（连接池、句柄、重试、编码转换…） | `支持库/后端/<某支持库>/<包名>` | 一个包只做一件事，可被无数模块复用 |
| 把第三方库翻译成中文能力（psycopg、ffmpeg…） | `支持库/适配层/<提供者>` | 支持库内部调用提供者＝门面→提供者，不算跨模块 |
| 独立进程/服务/动态库/外部接口（PostgreSQL、FFmpeg、Git） | 声明为**环境依赖**（适配层声明层分段） | 需要版本+入口+端口+健康探针+启停+降级 |
| 组装能力（多能力组合成一个业务动作） | `模块库/<模块名>` | 只经 `获取能力调用器().调用能力(能力id, 参数)` |
| 固定工作流（先做什么后做什么） | `技能库` 或 Agent 技能 | 不新增底座能力 |
| 前端描述类 | `支持库/前端/<描述>` | 只描述，不执行 |

**结果唯一即收口（哲学第 10 条）**：同一个目的已经有支持库了，就别新建第二个——保留最全面的那个，把其余的蒸馏进去。

## 二、支持库模板（九要素一次到位）

```python
unset PYTHONPATH
python3.14 -c "
import sys; sys.path.insert(0, '.')
from 开发工具.组件规范.支持库模板生成器 import 生成支持库模板
结果 = 生成支持库模板(
    输出目录='支持库/后端/示例支持库/示例包',
    包id='示例支持库.示例包',
    名称='示例包',
    能力清单=[{
        '能力id': '示例支持库.示例包.示例能力',
        '中文名称': '示例能力',
        '说明': '一句话说清这个能力做什么',
        '参数': [{'名称': '输入文本', '类型': '文本', '必填': True, '默认值': None, '说明': '待处理文本'}],
        '返回': '结果型',
        '错误码': ['参数不合法'],
    }],
    说明='示例支持库的能力说明',
)
print(结果.成功, 结果.错误码)
"
```

生成内容（九要素）：`能力定义.json`（**唯一可编辑事实源**）、`包声明.json`、`能力契约/参数契约.json`、
`依赖锁.json`、`配置契约.json`、`权限契约.json`、`实现/{子进程入口,提供者}.py`、`验证场景引用.json`、
`说明/使用说明.md`、`__init__.py`（中文公开入口 + 注册能力）、`完整性摘要.json`，
另加测试骨架 `测试中心/支持库/测试_<名称>.py`。

模板自带防御：**输出目录已存在文件就拒绝覆盖**（返回已存在清单）、路径逃逸拒绝、能力重名拒绝、
第三方只许声明为外部工具/受管（真要用第三方必须单独支持库或适配层翻译层）。

## 三、模块模板

```python
unset PYTHONPATH
python3.14 -c "
import sys; sys.path.insert(0, '.')
from 开发工具.组件规范.模块模板生成器 import 生成模块模板
结果 = 生成模块模板(
    模块名='示例模块', 类型='基础模块',
    能力清单=[{'能力id': '示例模块.示例能力', '中文名称': '示例能力', '说明': '…',
              '参数': [], '返回': '结果型', '错误码': ['参数不合法']}],
    依赖清单=[{'能力': '支持库.某包.某能力', '版本': '>=1.0.0'}],
)
print(结果.成功, 结果.错误码)
"
```
类型只允许 `基础模块|功能模块`；实现骨架里**不 import 支持库/提供者/第三方/核心**，
一律经 `获取能力调用器().调用能力(...)`（唯一调用入口，哲学：统一对外与调用接口）。

## 四、生成之后必须做的四件事

1. **填实现**：`实现/提供者.py`（或者模块的 `实现/<模块名>.py`）里写真实逻辑，替换占位；错误码只写实现里真实存在的失败码（`结果.失败("…")` 字面量），不许虚列。
2. **编译派生物**：`python3.14 -m 开发工具.契约编译.能力定义编译器`（定向编译，只编译本次改的包）——契约、能力搜索数据、Agent 查询数据、包声明能力清单、完整性摘要都从 `能力定义.json` 生成，**生成物禁手改**。
3. **重算摘要**：用 `开发工具/组件规范/完整性摘要.py` 重算本包（父包也要重算，否则父包摘要不闭合）。
4. **验证（定向，不跑全量）**：
   - `校验能力定义` → 必须 0 问题；`组件合规` → 全项通过；
   - `python3.14 -m 开发工具.公开调用完整性门禁` → 六环一致无违规；
   - `python3.14 -m 测试中心.开发工具.测试_唯一版本` → 版本恒等于唯一版本；
   - 真实功能验证用 HTML 经 `GET/POST` 打已编译产物（并发跑全量请求），看真实状态码与返回值。

## 五、版本与命名铁律

- **契约唯一、组件各自版本**：契约只有一套，契约版本事实源是 `公共契约/版本规则/契约版本.py`；
  而**支持库/模块/能力各自有自己的迭代版本号**（新包从 `1.0.0` 起），按自身迭代展示，不强制与契约版本对齐。
  契约版本由编译器统一注入，包/能力版本取自 `能力定义.json` 自己写的值。
  守卫测试：`python3.14 -m 测试中心.开发工具.测试_契约版本唯一`。
- **版本不对齐不失败**：上游带版本请求时，回报「请求版本 / 当前版本 / 差异原因」；没有强制参数差异就放行，
  只有依赖声明的运算符约束（`>=1.0.0`）、必填参数、契约硬要求不满足才报错。
- **全中文命名**（变量/函数/类/文件/目录/注释/文档），只保留 ID、OCR、LLM 这类人人认识的缩写。
- **不用甲乙丙丁和中文数字**当分类/占位名（哲学第 19 条），用一眼能懂的名字＋阿拉伯数字：示例提供者、循环模块1、契约齐全组。

## 六、常见坑（踩过的）

1. **模板拒绝覆盖**：目标目录或测试文件已存在就整体失败——先清干净再生成，不要手工搬文件绕过。
2. **父包摘要会不闭合**：新建/改动子包后只重算子包，父包（如 `支持库/后端/办公文档支持库`）也要重算，否则全树扫描报不闭合。
3. **说明书与能力定义会漂移**：`说明/使用说明.md` 的生成器与仓内历史文件格式不一致时会拒绝覆盖，改完能力定义后要一并核对说明书错误码表。
4. **漂移检测的判据**：检测器按「无既有契约」重算比对，会把手写保留键（`中文名称`/`名称`/人工调用示例）当成差异；剔掉保留键后比对为 0 属正常，别被红字骗着去改契约。
5. **临时脚本不留库**（哲学第 17 条）：脚手架、探针脚本用完即删，底座只留干净状态。
