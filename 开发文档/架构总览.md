## 一、平台是什么（一句话）

**一个与任何业务项目完全平级的系统级底座**：业务方不导入平台的任何实现，只经**唯一网关**按**能力 id** 调用；
平台内部怎么装、怎么路由、怎么换实现，业务方不感知。

## 二、分层与依赖方向

方向只有一个：**从上往下调用，绝不反向**。

```mermaid
flowchart TB
    subgraph 调用侧["调用侧（业务项目 / 数字员工 / 外部合作方）"]
        A1["业务代码<br/>只处理统一结果：成功 / 值 / 错误码 / 错误说明"]
        A2["HTML · GET · POST"]
    end

    subgraph 绑定["项目适配层（唯一绑定层）"]
        B1["只绑定：模块版本 · 配置 · 权限 · 路径 · 密钥引用 · 中文别名<br/>不得调用支持库 / 提供者 / 实现源码"]
    end

    subgraph 组合["模块库（组合流程）"]
        C1["薄模块门面：只保存能力 id + 契约版本<br/>不静态导入支持库 / 提供者"]
    end

    subgraph 受理["运行核心（唯一权威）"]
        D1["唯一能力注册表"]
        D2["唯一提供者路由"]
        D3["唯一调用证据链"]
    end

    subgraph 原子["支持库（原子能力 + 第三方边界）"]
        E1["一个第三方发行包 = 一个支持库 + 一个受管提供者<br/>只做参数/返回/错误转换与资源释放"]
    end

    F["第三方：数据库 · 服务器 · DLL · 操作系统 · 外部协议"]

    A1 --> B1 --> C1 --> D1 --> D2 --> E1 --> F
    A2 -.->|唯一网关| D1

    禁1["禁止：sys.path / __path__ / 动态导入 / 全局单例拼接两个源码树"]
    D1 -.-> 禁1
```

**为什么这样切**（每条都对应一条硬规则）：

| 规则 | 目的 |
|---|---|
| 支持库只做原子能力，一个第三方包只归属一个支持库 + 一个受管提供者 | 换第三方只动一处 |
| 模块只组合能力 id，不静态导入支持库 | 支持库可单点升级，模块不用改 |
| 项目适配层只绑定版本/配置/权限/路径/密钥引用 | 换项目只改绑定，不动平台 |
| 运行核心只有一个注册表、一条路由、一条证据链 | 公开能力重复注册直接失败，避免"两条腿" |
| 第三方强制英文只留在适配层，业务语义一律中文 | 中文命名不影响换第三方 |

## 三、一次能力调用的真实全链路

下面是**代码里的真实顺序**（`网关核心.py::处理` → `_执行`），不是理想设计：

```mermaid
sequenceDiagram
    autonumber
    participant 调用方
    participant LG as 本地网关<br/>(HTTP，工作线程预算 64)
    participant GW as 网关核心
    participant RL as 限流器<br/>(五维固定窗口)
    participant BC as 后端核心
    participant CN as 连接器<br/>(进程内 / HTTP)
    participant PV as 提供者<br/>(受管执行单元)

    调用方->>LG: POST /网关/调用（能力id + 参数 + 身份 + 凭证）
    LG->>GW: 处理(网关请求)
    Note over GW: ① 生成/沿用 请求id；回报「请求版本 / 当前版本 / 差异原因」<br/>版本不一致**兼容放行**，只有强制参数不满足才失败
    Note over GW: ② 操作白名单（允许操作表）→ 未知操作
    Note over GW: ③ 权限（操作权限表）→ 权限不足
    GW->>RL: ④ 进入请求（项目 / 用户 / 能力 / 任务 / 提供者）
    RL-->>GW: 不通过 → 限流
    Note over GW: ⑤ _执行：操作参数校验 → 按操作分发
    GW->>BC: ⑥ 调用能力（参数按该能力的参数声明逐个校验）
    BC->>CN: ⑦ 运行核心注入的唯一能力调用器
    CN->>PV: ⑧ 锁定提供者与受管执行单元
    PV-->>CN: 结果
    CN-->>GW: 统一结果（成功 / 值 / 错误码 / 错误说明）
    Note over GW: ⑨ 异常 → 公开错误码收口（KeyError→能力不存在、<br/>PermissionError→权限不足、ValueError→参数不合法…）
    GW->>RL: finally 离开请求（释放并发计数）
    GW-->>调用方: 统一信封（含 耗时毫秒）
```

**读这张图要记住的三件事**：

1. **限流是"进入/离开"成对的**，`finally` 里必归还；不归还就会把并发额度吃死。
2. **参数校验发生在网关边界**，用的是能力自己声明的参数表 —— 没声明类型 = 没有可执行承诺，放行；**声明了就必须过**。
3. 所有底层异常都在网关收口成**公开错误码**，业务方永远看不到裸异常。

## 四、从源码到制品到验收

这是"改变怎么安全上线"的链路，也是本平台唯一的正式验收口径：

```mermaid
flowchart LR
    S["源码树<br/>公共契约 / 支持库 / 模块库 / 运行核心 / 平台控制面 …"]
    K["编译器<br/>AST 重写顶层导入<br/>拒绝符号链接 · 受控路径写入"]
    P["稳定产物<br/>平台客户端-&lt;摘要16&gt;"]
    ID["制品身份三件<br/>制品摘要.json<br/>完整性摘要.json<br/>编译清单.json"]

    H["HTML 黑盒<br/>对制品 GET/POST，并发 32"]
    M["发布门禁<br/>唯一判定"]
    GATE["门禁内其它项<br/>语法编译 · 死链 · 缓存无源码 · 摘要自洽 · 真实调用矩阵"]

    S --> K --> P
    P --> ID
    P --> H
    P --> M
    M --> GATE
    H --> EV["验证证据"]
    GATE --> EV
    EV --> R{"通过？"}
    R -->|是| ACT["激活指针切换<br/>（只切不可变旧制品）"]
    R -->|否| BLOCK["阻断<br/>非零退出码"]
```

**三条硬约束**：

- **产物是不可变的**：验证时不许往制品里写任何东西（运行态走受管缓存）——
  这条正是"制品摘要前后不一致"要守的底线。
- **回滚只切指针**：换回旧制品即可，禁止恢复源码分支或翻转废弃标记。
- **验收只看真实 HTTP**：编译通过 ≠ 能用；必须经 HTML 黑盒对**已编译产物**发真实请求。

## 五、能力从哪来（四条路径）

```mermaid
flowchart TB
    NEED["一个需求"]
    Q["能力搜索：先确认**全局唯一**，没有同义能力"]
    NEED --> Q
    Q --> T1["支持库<br/>单一原子动作 / 绑定一个第三方"]
    Q --> T2["模块库<br/>要组合多个能力完成一段流程"]
    Q --> T3["技能库<br/>要落盘 / 续跑 / 人审的脚本编排"]
    Q --> T4["平台控制面<br/>平台自身治理（目录 / 策略 / 制品 / 发布 / 证据）"]

    T1 --> PKG["包九要素<br/>包声明 · 参数契约 · 能力定义 · 权限契约<br/>资源预算 · 能力数据 · 验证场景 · 说明 · __init__"]
    T2 --> PKG
    T3 --> PKG
    T4 --> PKG
    PKG --> COMP["统一编译器（只编本次变更的小单元）<br/>检查契约 · 依赖 · 边界 · 登记"]
    COMP --> REG["能力登记（公开能力全局唯一）"]
    REG --> HOT["热接入生效（不重启网关）"]
```

**选层的唯一判据**（一句一条）：

- 一次调用就出结果 → **支持库**
- 要落盘 / 要续跑 / 要人审 → **技能库**
- 单一动作、不组合 → 支持库；**要组合** → 模块库

## 六、资源与失败（句柄体系）

长任务、文件、进程这类"有归属的资源"统一走**句柄**，不靠端口号或进程名盲杀：

```mermaid
stateDiagram-v2
    [*] --> 有效: 申请（登记归属：项目 / 所有者 / 能力）
    有效 --> 续租: 续租（延长租约）
    续租 --> 有效
    有效 --> 已过期: 心跳超时
    已过期 --> 已回收: 回收（按登记的归属回收）
    有效 --> 已回收: 主动关闭（幂等）
    已回收 --> [*]
```

- **回收按状态机登记的归属**，不按端口号盲杀 —— 这是硬规则。
- 重复关闭是**幂等**的（不提前失败）；句柄不存在才报「句柄无效」。
