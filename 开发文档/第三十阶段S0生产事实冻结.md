## 三、冷启动定义

全新 Python 进程、清空项目源码 `PYTHONPATH`、无测试预注册、无历史全局单例、只使用已安装制品与声明配置：
装配→注册→调用全链路成立。任何经 `sys.path` 拼接、包 `__path__`、源码目录、测试预注册、直接导入 `实现/` 或全局状态残留跑通的链路均不算完成。

## 四、幂等定义

同一包 id、版本、契约摘要、实现摘要完全一致可重放（重复装配结果一致）；任一不同必须冲突失败且不留半装配状态。

## 五、成功定义

能力确实经过生产注册表调用并返回统一结果+完整调用证据（请求id、模块版本、能力id、支持库包id、提供者版本、制品摘要、成功/失败、资源释放结论）。
仅导入、仅目录存在、直接调用实现、测试注入调用器均不算成功。

## 六、强制验收目标（本阶段）

1. 37 个正式支持库逐包权威 13/13；发布门禁删除"债务披露放行"。
2. 11 个正式模块逐能力：声明=注册=搜索=客户端可见。
3. 全新进程冷启动制品装配+调用成功；反向破坏（删包声明/注册入口/契约/锁/实现任一项）生产链失败。
4. 唯一注册表/唯一提供者路由/唯一调用器注入点；测试直接导入实现或预注册无法假绿。
5. 客户端制品一致性成为正式发布门禁检查点，反向篡改阻断。
6. 提供者异常/超时/取消/崩溃后线程/进程/端口/临时目录/句柄零残留。

## 七、对外开发接入（S0.1 新增）

平台面向**开发**（Agent 开发业务项目、开发者写业务代码），提供"发现 + 执行"两段式接入。

```text
开发闭环
┌──────────────┐    ┌───────────────┐    ┌──────────────┐
│ MCP 能力发现  │    │ 执行底座三通道  │    │ 结果+证据链  │
│（使用声明）   │───►│ 选其一         │───►│             │
└──────┬───────┘    └───────┬───────┘    └──────┬───────┘
       │                   │                     │
 capability_search   ①HTTP REST               统一结果
 capability_read     POST /能力执行        {成功,值,错误码,
 参数/返回/示例       ②MCP capability_execute   错误说明}
                     ③本地 import 读取文件      + 完整证据链
```

### 7.1 MCP 定位 = 能力发现与使用声明（易语言式"使用声明"）

MCP（`system_engineering_toolkit`，HTTP 8766）不是唯一执行通道，而是**开发期能力发现**：

- 列出平台有哪些能力、每个能力的参数/返回/错误码/调用示例（`capability_search` / `capability_read`）；
- Agent 开发时经 MCP 找到对应能力、知道怎么调、然后用底座执行；
- 语义等价于易语言的"使用声明"——先声明有哪些东西、怎么用，再实际调用。

### 7.2 执行底座 = 三通道（都要做）

| 通道 | 形态 | 隔离性 | 适用 |
|---|---|---|---|
| HTTP REST | `POST http://127.0.0.1:8766/能力执行`，body `{"能力id":"文件系统.读取文件","参数":{...}}`，返回 `{成功,值,错误码,错误说明}` | 完全隔离（调用者不知平台内部） | 任何语言、任何服务、云端/本机 |
| MCP 执行 | MCP 加 `capability_execute` 工具，Agent 对话内直接执行能力 | Agent 侧隔离 | Agent 开发项目 |
| 本地同级 | 支持库/模块库复制到本地项目，`from 支持库.后端.文件系统 import 读取文件; 结果 = 读取文件(文件路径=...)` | 本地独立（不依赖平台服务） | 下载到本地做同级功能调用 |

三通道**复用同一能力注册表与唯一能力调用器**，返回同一统一结果格式（成功/值/错误码/错误说明）+ 完整调用证据链；禁止为任一通道绕过注册表/调用器另起执行路径。

### 7.3 本地/云端不敏感

三通道的底层是同一套装配与调用事实；本地（复制到本机）与云端（平台服务运行中）只是部署形态差异，调用语义一致。

### 7.4 开发工具链属性

对外接入面向**开发过程**（Agent 开发、业务项目集成），不是单次调用场景：
能力搜索→查看契约→调用执行→结果与证据链，形成开发闭环；平台自身仍是与业务项目平级独立的工程底座。
