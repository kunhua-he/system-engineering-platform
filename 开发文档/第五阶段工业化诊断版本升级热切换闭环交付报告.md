## 三、日志模型（运行事件/）

统一运行事件（事件模型.py）：17 种事件类型（调用开始/成功/失败、参数校验失败、配置错误、依赖解析失败、提供者不可用/启动失败、生命周期变化、版本切换、升级成功/失败、回滚开始/成功/失败、资源释放、模块卸载）。

每条事件 20 字段：事件id/时间/追踪id/项目id/包id/能力id/模块id/版本/契约版本/提供者/生命周期状态/操作名称/成功状态/错误码/错误说明/是否可重试/耗时/配置来源/依赖摘要。

- 事件结构统一（唯一模型，无第二套）
- 失败信息不可丢失；异常转稳定错误码（不输出裸字符串）
- JSONL 结构化日志（事件日志.py）：查询/过滤/错误码聚合/最近失败
- **脱敏**（脱敏工具.py）：密钥片段正则替换 + 敏感配置名脱敏 + 大文本摘要截断（>100 字符）
- 日志写入失败不破坏主调用（返回 False + 降级告警计数）

- 状态流转：待诊断→已定位→修复中→待回归→已修复→已关闭；**已忽略必须填原因+有效期**（不能永久隐藏）

维修闭环：失败事件 → 诊断定位 → 关联能力和版本 → 关联验证场景 → 复现输入 → 针对性验证 → 修复 → 回归 → 关闭记录（失败记录状态机落地）。

## 五、版本并存机制（版本系统/版本注册表.py）

- 同一包多版本并存（模块库.文件管理@1.0.0/1.1.0/2.0.0）
- 版本包不可覆盖（同键注册失败）
- 每版本独立：完整性摘要（sha256 内容寻址前16位）/契约版本/验证状态/发布时间/引用项目/可回滚版本
- 项目依赖锁决定实际版本（版本注册表与依赖锁定独立）
- 新版本发布不影响旧项目（引用项目列表隔离）
- 删除保护：引用扫描（引用项目/运行实例/回滚任务三重检查）

## 六、契约兼容规则（版本系统/契约兼容.py）

兼容：内部修复/性能提升/增加可选参数/增加返回字段/非破坏性错误说明
不兼容：修改必填参数/删除参数/修改返回结构/删除能力/删除错误码/改变错误码语义/改变资源所有权/改变同步异步流式语义

- 检查结果四选一：兼容/不兼容/需要适配器/无法升级
- 不兼容必须升契约主版本（是否必须升主版本 标记）

## 七、适配器规则（版本系统/兼容适配器.py）

适配器只允许：参数名称/结构转换、返回值转换、错误码转换、旧行为兼容、版本兼容提示
禁止：新业务流程/读私有实现/绕过注册表/永久无引用保留/隐藏不兼容

声明：适配器id/来源契约版本/目标契约版本/支持范围/弃用时间/验证场景；`适用于()` 判定来源→目标版本对。

## 八、热切换流程（版本系统/热切换.py）

安装新版本 → 完整性校验 → 依赖和契约校验 → 中立宿主验证 → 项目装配验证 → 影子启动 → 健康检查 → 灰度运行 → 切换激活映射 → 观察错误和耗时 → 确认成功 → 旧版本进入弃用期。

**切换失败自动回滚**：立即停止新版本流量（激活映射恢复旧版）、保留失败证据（回滚记录表）、保留新版本供诊断、不删除旧版本、生成自动回滚记录（回滚id/时间/能力id/恢复版本/原因）。

**灰度策略**：立即切换/按项目/按提供者/按请求/比例/手动（灰度指标表按能力@版本）；观察指标：成功率/失败率/错误码分布/平均耗时/超时率/资源占用/提供者健康；失败率>5% 或 超时率>10% 触发自动回滚。

**状态切换**（状态切换.py）：无状态（文本处理/数据交换/文件读取/只读查询等）按请求切换；有状态（数据库/任务队列/长连接/窗口/进程/事务/会话/缓存/句柄）先排空（停止接收新请求→等待旧任务完成→关闭旧资源→导出迁移状态→启动新版本→恢复状态→健康检查→开放新请求）；**无法证明状态可迁移时禁止进程内热替换**，改新旧提供者并行+路由切换。

## 九、版本弃用与清理（版本系统/弃用清理.py）

状态：已发布→灰度中→已激活→已弃用→停止新装配→停止新调用→等待清理→已卸载。

卸载前置条件（七项全满足）：无项目依赖/无运行中任务/无连接和句柄/无待迁移状态/无待处理失败记录/无回滚窗口/已超过弃用期限——任一不满足拒绝并列出未满足项。

卸载撤销清单（八项）：激活映射/路由/任务/事件监听/权限/注册表项/临时文件/外部资源。
