### 2.1 N7：仓库根白名单按位置推根（根因）

- **真源**：`支持库/适配层/Git提供者/实现/仓库根白名单.py::底座仓库根()` 原实现 `Path(__file__).resolve().parents[4]`。
- **现场**：网关 40007 的 launchd `WorkingDirectory` 指向制品稳定路径，那份拷贝的 `parents[4]` = **制品根**
  ⇒ 白名单 = [制品根, 系统临时目录]，**源码树不在其中** ⇒ 对源码树的任何提交都被判 `路径越界`。
- **实测（修复前）**：`版本控制支持库.Git操作.提交`（仓库路径=源码树，路径列表=[开发文档/未完成事项.md]）

- **修法**：改为**向上找最近一个含 `.git` 的祖先目录**（worktree 里 `.git` 是文件，故目录/文件都认）。
  制品拷贝位于源码仓 `工程缓存/` 内、自身无 `.git` ⇒ 命中**源码仓根**，源码树与制品两种跑法拿到同一个仓库根。
  安全边界不变（仍只放行「跑着的这份代码所在的那个仓」+ `工作区允许提交根` 显式加白 + 系统临时目录）。

**三类原因，只有第一类是「能力真缺失」：**

1. **真缺口（已修）**：`Git操作.提交` 在源码树被 `仓库根白名单` 判 `路径越界`（见 §2.1）
   ⇒ 那 7 次 git 终端调用里，提交类**没有 MCP 出口**。同一处还有第二个坑：`热接入` 比对的是自己那份拷贝，
   源码侧改动它看不到（已在 工具姿势 写明：源码侧改动必须重建制品 + 重启）。
2. **一次被拒后没重试**：会话里有一条 MCP 调用回 `missing required argument(s): 项目根`（薄壳身份校验参数），
   随后下一条就直接回落终端 `git status --short`。**正确姿势是补齐参数重试，不是换腿**。
3. **手顺漂移（能力其实都有）**：`grep`/`ls`/`tail`/`ps`/`rm` 这类「顺手就敲」的动作占 **51%（25/49）**，
   MCP 侧对应能力全都在。**注**：其中 4 次 `background=true` 的长命令是**纪律本身要求**的
   （工具姿势「>15 秒一律后台化」，用驱动方的后台机制），不算缺口。

**结论**：终端不是必需的。这一轮「一直用终端」＝**一个真缺口（提交白名单）拖出习惯性回落 + 一次参数错误没重试**。
修掉真缺口后，同一批工作（改文件 → 定向验证 → 制品重建 → 重启 → 取证 → 提交 → 落盘）基本全部经 MCP 完成；

② **>15 秒的门禁跑**（工具姿势硬线要求用驱动方后台机制）。
