## 一、`执行命令` 的 shell 语法静默失效（子代理偏好终端的机械根因）

### 1.1 归因更正：不是「没有 shell 腿」，是「默认档静默失效」

任务信写的是「`执行命令` 无外壳」。现场核对后**归因要更正**：shell 腿**早在 2026-09-23 就存在** ——
`经shell` 形参（默认 `假`）＋ 唯一实现 `公共契约/运行时/平台适配/进程分叉.经shell命令表()`
（POSIX `/bin/sh -c`、Windows `cmd /c`），`启动进程`/`执行命令` 两条腿都已接上。

真正的缺口是**默认档（`经shell` 留空/假）遇到 shell 语法时既不报错也不给对结果**：

| 现场 | 改前读数（`执行命令("ls /tmp 2>&1 | head -3")`） |
|---|---|
| 退出码 | `1` |
| 错误输出 | `ls: |: No such file or directory` |
| 标准输出 | **未过滤的完整 `/tmp` 目录**（原值 24,244 字符） |
| 调用方感受 | 「跑成功了，但结果不对」—— 既没报错也没给对结果 |

根因：`拆分命令文本()` 把 `2>&1` / `|` 拆成**普通 argv 项**原样交给 `ls`。
`经shell=真` 时同一条命令 `退出码 0`、标准输出正好 3 行 ⇒ 两条路差别巨大而默认档沉默。

### 1.2 改法（华哥口径「未对齐就报，不许静默」＋「有统一节点就切统一节点」）

1. **新增唯一节点** `公共契约/运行时/平台适配/进程分叉.shell语法问题(命令) -> str`：
   扫描**未加引号**的 shell 专有语法，命中即返回**原因文本**（空串=放行），形状与
   `_解析超时秒` / `_解析经shell` 同款；已补进 `平台适配/__init__.py` 的 import 与 `__all__`
   （新原语必须同时进公开面，与既有各次补列同一处置）。
2. **两条直启腿接同一判据**（`启动进程`、`执行命令`）：`经shell` 留空/假时先过该节点，
   命中即回 `参数不合法` ＋ 可照抄的处置（「要 shell 语义请传 经shell=真」）。
   `执行命令集` 逐条转调 `执行命令`，**自动同源**，未另写一份。
3. `沙箱执行命令` **不加**：它本身固定 `/bin/sh -c`，天然是 shell 形态。
4. 契约说明同步：`能力定义.json`（`执行命令` 能力说明 ＋ `命令` 形参说明、`启动进程` 能力说明）
   与 `__init__.py` 注册说明。

**判定口径（保守，宁少报不误伤）**：只认未加引号的 `|`、`||`、`&&`、`;`、`>`、`>>`、`<`、
`` ` ``、`$(`、`${`、换行；**不报**裸 `&`（URL 查询串）、`$变量`、通配 `*`/`?`、引号本身；
引号内的同名字符一律不报。

## 三、`正则搜索` 超预算丢正文留元信息 —— **真缺陷，已修**

### 3.1 归因更正：缺陷不在 `内容检索.py`，在**薄壳的裁剪腿**

任务信把落点写在 `内容检索.py`（也正是 R-26 持租约的那条路径）。现场核对后**归因要更正**：
`内容检索` 只负责产出正文，**「超预算留谁丢谁」的判据在薄壳**（`开发工具/薄壳/薄壳服务.py`
的 `_裁剪值` / `_兜底裁剪`）—— 那是全平台唯一的裁剪节点。所以本件**不需要动 `内容检索.py`**，
与 R-26 的租约**不冲突**（这也解释了为什么 R-26 修完路径解析后本症状依旧）。

现场链路（上限 6000，真调用）：

```
原字符数 7273 → 回指针 + 缩影
缩影 = {"引擎": "rg", "搜索根": "."}          ← 正文整段消失
丢弃说明 = 字典丢尾键（丢 5 个）               ← 丢的是「尾」，而正文恰好排在第 3 位
```

根因：`_兜底裁剪` 按**原序从前往后留、装不下就停** ⇒ `引擎`/`搜索根`（两条元信息，24 字符）
先占住预算，正文 `匹配列表`（约 6,500 字符）一进来就超限 ⇒ 当场 `break`，
**后面的键（含正文）全部丢掉**。而 `_缩到限内` 救不了：`命令`（rg argv，几十条短串）
与 `匹配列表` 的 `文本` 多在叶子下限之下，缩不动。

### 3.2 改法（华哥口径「正文/结果优先留，元信息先丢」）

1. **新增唯一节点 `元信息键`**（`薄壳服务.py`）：`{命令, 引擎, 搜索根}`。
   判据写死在注释里：**丢了它，正文仍能推出同一事实**（`命令` 是本次 rg argv 的回显、
   `引擎` 恒为 `rg`、`搜索根` 是入参 `根目录` 的复述）。
2. **`_省元信息(值)`**：超预算时**先省掉元信息键、再缩正文**。为什么必须在「缩」之前：
   元信息是回声、且多数**不可缩**（短 argv 逐条都在叶子下限之下）⇒ 留着它等于拿正文的
   预算装回声。
3. **`_正文优先(值)`**：给 `_兜底裁剪` 的字典分支定**保留顺序**（正文在前、元信息在后）。
   万一省掉元信息仍装不下，被丢的也先是元信息，不再是正文。
4. 省掉元信息是**有痕**的：`丢弃说明` 明写 `已省略元信息键：引擎、搜索根、命令`
   （华哥口径「未对齐就报，不许静默」）。

**未动 `内容检索.py`**；`元信息键` 是**全平台一份**，不新增第二套判据。

## 四、传参口径统一：薄壳 `返回上限字符` ↔ 能力 `最大字符`

### 4.1 口径表（统一后的**唯一**说法，已写进 0 跳工具描述）

| 参数 | 层 | 语义（唯一） | 默认 | 边界 |
|---|---|---|---|---|
| `返回上限字符` | 薄壳（所有能力通用） | **信封**字符上限：本次回给你的 JSON 字符上限 | `2000`（唯一事实源 `工具清单.默认返回上限字符`）；`0`=不限 | **不解除**能力自身的内容截断 |
| 能力自身形参（如 `读取文件.最大字符`、`允许大文件`） | 能力 | 该能力**自己产出**的字符上限 | 各自契约 | 要全量须**同传**它（`最大字符=0` 或 `允许大文件=真`） |

本批踩坑现场（两次）：传 `返回上限字符=0` 想拿全量，实际仍只回 1,993 字符
（`读取文件` 的 `最大字符` 默认 2000 先裁了一次，且提示「续取：起始行=82」）。
⇒ 已在 `工具清单.py` 的 `capability_call` 描述里把这条关系写死，调用方不必再猜。

### 4.2 `全量回执` 触发阈值与默认上限**解耦**

- 改前：触发条件写死「值 > 上限字符」⇒ **阈值就是** `默认返回上限字符`，默认档一改、
  「什么时候换形态」也跟着改（两件事绑成一个旋钮）。代价：默认档 2000 下任何 2KB 出头的
  返回值都被整包换成「指针 + 缩影」，调用方必须再发一次取回（任务信记本批 10 次、各多一轮）。
- 改后：新增独立常量 `回执触发字符数 = 默认返回上限字符 * 4`（**实测读数 = 8000**，
  与默认档 2000 无关）。
  - 值 > 阈值：照旧整包换「指针 + 缩影」（大件）。
  - 值 ≤ 阈值（中等超限）：**不换形态**，说明只留必要键、省下的额度全给 `值` ——
    形状与指针形态**逐字同形**（`取回` 仍在），只是 `值` 大得多。
- 顺带把 `取回` 串里那段 ~90 字符的括号解释压成一句（它同样吃 `上限字符` 预算）。
- **兼容性**：`测试中心/开发工具/测试_薄壳返回可控.py::test_调用侧默认裁剪生效` 用的样本是
  20,000 字符 > 8,000 ⇒ 仍走指针形态，断言（`值裁剪键` 不在、`取回` 在、总长 < 20000）**不受影响**。
