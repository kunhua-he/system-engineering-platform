### 每轮注入的第二块：`instructions`

上面 4 块是**工具面**（描述 ＋ schema ＋ 工具名）；此外 `initialize` 回包里还**一次性**下发一段 `instructions`
（逐轮固定 ⇒ 上游命中缓存；不占工具面那 2,000 字符的天花板）。改完长这样：

```text
一切动作优先走 MCP 能力，用终端算旁路。
参数名用契约真名，写错会被剔除。
类型（唯一源 公共契约/基础类型/类型表.py）：
  文本型=UTF-8 字符串；整数型/长整数型=整数，范围见参数说明；单精度数型/双精度数型=小数；
  逻辑型=真/假；列表型=数组；字典型=自由键值，结构见 ① 回的数组样例；
  JSON值型=JSON 可解析值；日期时间型=ISO8601 字符串；字节型/字节集型=base64；
  结果型={成功,值}；空值型=null。
数组＝参数表该列非空即收数组，按行序对位传值，空位留 ''。
回包＝成功回正文（无值回 1）；失败回 -1 ＋ 错误码/错误说明。
常用动作（命令 + 传参）：
  10 秒内任务  capability_call{能力id=…, 数组=[…]}
  10 秒外任务  capability_call{能力id=…, 数组=[…]} 回 任务id；查/取消 同传 任务id
  开工登记    capability_call{能力id=开工编排.开工即占, 数组=[项目根, 任务, [修改路径]]}
  改文件前    prompts/get{name=开工}
  收工        capability_call{能力id=开工编排.收工释放, 数组=[[租约id]]}
```

**每轮注入合计**：工具面 1,074 ＋ `instructions` 574 ＝ **1,648**（天花板 2,000，余 352）。

**按需取、不自动注入**：`prompts` 两条（`开工`／`收口`）。

**待裁**：删掉 `操作` 后，「某能力的参数结构」没了查询入口 —— 那是原 `操作=1 能力详情` 的活。
现暂定「看 ① 回的数组样例」；若不够，得补一条能力（如 `能力目录.能力详情(能力id)`）。

## 十二、③ 实测附录（依据、判据、成本）

### 回包规则与依据（③ 的实现口径）

| 规则 | 值 | 依据（实测） |
|---|---|---|
| 第 1 行 | `<绝对路径>:<起>-<止>  #已验证` | 够定位、够引用；id／种类／签名等机器字段不回 |
| 代码块 | 紧跟其后，整体缩进 4 空格 | 不加 `┌│└` 框：同样 4 条省 168 字符 |
| 单条上限 | 60 行，超出标 `…（余 N 行）` | 11,847 节点：中位 10 行／P90 41／P95 67 |
| 默认条数 | **4**（原 50） | 一条 ≈ 570 字符；50 条 ≈ 2.5 万字符会撑爆 |

### 保鲜流程（`#已验证` 怎么来的）

```text
查索引 → N 条
 ├─ N ≥ 1 → 逐条试算：索引原文 ＋ 标记，走 文本补丁.应用精确替换（写入=假，18 ms/条）
 │            ├─ 全过   → 返回（每条带 #已验证）
 │            └─ 有不过 → 开窗 sync → 重查 → 再验
 │                         └─ 仍不过 → 如实回报（真异常，绝不冒充已验证）
 └─ N = 0  → 全仓内容哈希兜底（34 ms，只读）→ 有改动就 sync → 重查
```

### 判据与授权

| 判据要点 | 值 |
|---|---|
| 判据成本 | 逐条 18 ms；全仓哈希 34 ms —— **都只读、都不要授权** |
| 授权 | 只在真同步那一刻给：`开工即占(.codegraph)` → `临时解锁树` → `codegraph sync` → `收工释放` 回锁 |
| 复用 | 试算走既有腿 `文件系统支持库.文本补丁.应用精确替换` 的「唯一匹配校验」，不另立判据 |
| 标记落点 | 只进回包文本，**不写进源文件** |
| 判据口径 | 与索引器一致：**内容哈希**；不许用 mtime（实测 49 个假阳性，见下） |

### sync 成本实测（增量；不必做「只索引一个文件」）

| 变化量 | 耗时 | 说明 |
|---|---|---|
| 0 个文件 | **0.27 / 0.27 / 0.29 秒**（连跑 3 次） | 地板价 ＝ 全仓 13.5 MB 读一遍算哈希（34 ms）＋ node 启动与扫描 |
| 510 个文件（2 天积压） | **6.26 秒** | 加 66／改 441／删 3 |
| 边际 | **≈ 12 ms / 文件** | ⇒ 改 1 个文件 ≈ 0.3 秒，与地板价同量级 |

- `codegraph sync` **没有单文件开关**（`sync [path]` 只接项目路径），但它**本来就是增量的** —— 只处理内容变了的文件，「只更新那一个」的等价效果就是 0.3 秒。
- `sync` **不索引 `.md`**：实测改完本文档，它照样回 `Already up to date` ⇒ 只有代码改动触发同步。
- 判据**不是 mtime**：49 个文件 mtime 与索引记录差 22 天、内容一个没变，sync 一次都没重索引（`indexed_at` 仍停在 2026-08-01）⇒ 触发条件是内容哈希。
- 锁态闭环实测：租约认领时 `.codegraph` 自动解开，`收工释放` 后立刻回 `uchg`，再跑 sync 当场 `unable to open database file`。

## 十五、自换新壳加金丝雀（2026-09-25 02:2x，开工ID `开工-20260925-022007-809b`）

### 15.1 根因：换壳换到了一个「编译得过、但起不来」的壳

## 十六、换壳族收口：副本项目根 ＋ fd 2 观测口（2026-09-25 02:5x，开工ID `开工-20260925-025255-5034`）

### 16.1 副本为什么会被拒（根因不是「脚本入口准入」）

§15.4-3 记的「子进程被 `脚本入口准入` 拦掉」只对了一半：真正的拒绝来自**项目根解析**。
薄壳按 `__file__` 推项目根，两条推导**只在生产那个层级才同解**：

| 位置 | 推导 | 生产（`<仓>/开发工具/薄壳/`） | 平铺副本（`<临时>/薄壳/`） |
|---|---|---|---|

| `工具清单.py:20` | `__file__.parents[2]` | `<仓>` | `<临时>/..` |

**这是夹具的错，不是产线的错**：生产里薄壳永远在 `<仓>/开发工具/薄壳/`。

| **续查入口** | **缺** | `任务查询` 只是薄壳内部操作（`薄壳内部操作` 里的 `操作="任务查询"`），**没注册成能力**；能力面上没有「按 任务id 查」的注册能力 ⇒ agent 拿到 任务id 也**无处可查** |
| ★ **能力任务终态可见性** | **缺陷，两发可复现** | 两发 `静态编译` 的任务都 **20 秒**跑完（运行库已是 `状态=失败`），薄壳却把有界等待**跑满 100 秒**；对照同样走 `_走异步腿` 的 `执行命令`（25 秒任务）**25.5 秒**就正确收尾 ⇒ 轮询机制没问题，**只这条能力任务看不到终态** |

### 17.2 口径落点

「异步腿」不是一条腿，是**三段**：① 机制（通）／② 谁负责改腿（腿② 原先没接）／③ 到期后怎么续查（没有入口）。
把三段混成一句「异步腿不能用」，就会去改网关或去删 `操作` —— 而真因在后两段。
