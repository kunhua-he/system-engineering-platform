## 二、根因（本轮实测定位到**机制层**，前序只到「受管路径没租约」）

1. `git worktree add` 在工作区根放的是 `.git` **文件**（内容是 `gitdir: …/.git/worktrees/<名>`），
   **不是目录**。
2. `公共契约/运行时/仓库只读锁._推断仓库根` 的判据是 `(当前 / ".git").exists()` ——
   **文件也算** ⇒ 工作区根被算成「仓库根」。
3. 于是 `公共契约/运行时/写入授权.受管相对路径` 把工作区里的 `修复目标.txt` 判成
   **受管路径**（仓库内 + 不命中豁免前缀 + 不是平台自管生成物）。
4. `_应用补丁` → `文件系统支持库.文件操作.写入文件` → `仓库只读锁.临时解锁` →
   `_要求写入授权` ⇒ 没有任何活跃租约覆盖 ⇒ `PermissionError` ⇒ 能力回 `越界`。

## 三、裁决：为什么走「自行认领租约」而不是「放宽判据」

**先排掉三条看似更省事的路，逐条给理由（都实测过）**：

- **「受管＝只判本平台仓库」**（把 `推断仓库根(目标)` 与本仓根比对）：**不可行**。
  `测试中心/公共契约/测试_写入授权.py` 的夹具就是**假仓库**（`工程缓存/测试临时/…/假仓库`，
  带 `.git/` 目录），判据必须把它的 `目标.py` 判成受管 —— 判据的域**有意**是「任何仓库的 tracked 面」，
  收窄会当场打穿那条回归锁（反向三拍 ①无租约必须报红）。
- **「只判/跳过 `git worktree`（`.git` 是文件）」**：能治本场景，但要动
  `_推断仓库根` —— 它同时是 `仓库只读锁._上下文锁态` 的判据（「祖先链上的锁属于本仓库还是仓库外」），
  动它等于给内核锁那条腿换口径，风险与收益不匹配。
- **「把工作区挪进 `工程缓存/` 借豁免前缀」**：等于**新起第二套豁免机制**，
  正是华哥明令禁止的形状（「有统一节点的全部切成统一节点」）。

**结论**：这 3 例**不是假红**。工作区里就是目标仓库 tracked 文件的真实检出，写它就是改事实源，
本来就该被授权 —— 缺的是**写者没被授权**。故按裁决走：写者自行认领，写授权与租约**同源**。

**为什么不由测试侧认领**：写入授权与租约必须同源，把纪律塞进测试＝把判据外包给调用方。
