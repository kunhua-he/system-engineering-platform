```
=== 丙#丁，前缀「丙」已存在为目录 ===
失败: OperationalError : unable to open database file
```

### 结论

- **报告的风险表述「路径含中文时会解析失败」——不成立**（实测中文路径裸写完全正常，`mode=ro` 也照常生效）。
- **真实缺陷在另外两个字符 `#` 和 `?`**（不是中文）：`#` 被 URI 当作 fragment 起点、`?` 被当作 query 起点，路径被静默截断到前缀，**而且不抛异常**。URI 变成了 `file:/…/含`，SQLite 于是**现场新建**了一个名为「含」的空库并打开它 —— 真实库的表全部丢失，而 `PRAGMA integrity_check` 对该空库照样返回 `ok`。
- **比报告更严重的一点（实测新发现）**：`?` 被当作 query 起点后，**连 `?mode=ro` 这段一起被吞掉**，URI 里再无任何 query 参数，`mode=ro` 只读模式**完全失效且不报错** —— 写探针 `CREATE TABLE 写探针` 成功落盘（见上表 `含#/裸写`、`含?/裸写` 两行 `★失效(可写)`）。对「损坏恢复」这条路径，这意味着它可能以**可写**方式打开一个**错误的**库。
- **对「损坏恢复」这段代码的具体后果**：拿到空库 → `integrity_check` 返回 `ok` → 判定「库完好」→ **真实损坏被掩盖**，且备份恢复分支永不触发。这是「静默误判」类缺陷，比抛异常危险。
- **但触发前提目前未在现场成立**：核对了 `权威状态.py:207` `self.数据库路径 = self.存储目录 / "权威状态.db"`，实例化入口 `运行核心/资源协调/服务.py:66` 传的是 `self.存储目录 / "状态"`；全仓 grep 未发现把 `#`/`?` 放进存储目录或项目根的写法。**所以这是「潜在缺陷」而非「现行故障」—— 定级按潜在缺陷，不要按现网事故。**
- **建议修法**：`f"file:{quote(str(self.数据库路径))}?mode=ro"`（`urllib.parse.quote`，默认 `safe='/'` 正好适配文件 URI）。顺带给项目根路径加一条「存储路径禁含 `#`/`?`」的启动自检，比依赖调用方自律更可靠。
- **归属簇**：D 簇（`权威状态.py` 在改）。**转交时请一并纠正 D 簇的报告口径：不是中文路径，是 `#`/`?`；且危害是「只读失效 + 空库通过完整性校验」，不是「解析失败抛错」。**
