## 五、本轮新发现的底层缺陷（已登记，未修）

1. **`执行命令` 无外壳 —— 「子代理偏好终端」的机械根因（高价值）**
   `系统核心支持库.进程管理.执行命令` 的 `命令` 声明为文本型，但实现按 **argv 拆**、**不过 shell**：`&&`、`|`、`2>&1`、`unset` 全不生效，且**静默**（退出码/错误输出不像语法错）。
   实测：`ls -la /tmp/r16/ 2>&1 | head -20` ⇒ 错误输出 `ls: 2>&1: No such file or directory`、`ls: |: No such file or directory`；`cd <仓库根> && git status` ⇒ 退出码 0 但什么都没跑。
   ⇒ 凡命令需要 shell 语法（含通用纪律明令的 `unset PYTHONPATH`），agent **只能回终端**；而通用纪律第 31 条又要求「不得用终端取」——两条纪律**互相打死**。这是「子代理偏好终端」的机械根因，不是偏好问题。
   建议：`执行命令` 统一按 `sh -c <命令>` 跑（权威节点唯一），或加 `走外壳`（默认真）并在返回里回带实际执行形态。

2. **`写入授权` 只在一条写腿上 —— 同一判据两处实现（绕过口子）**
   `文件系统支持库.文件操作.写入文件` 会判「是否被活跃写租约覆盖」（实测：本会话租约过期后写盘回 `越界：… 没有任何活跃写租约覆盖`）。
   但 `文件系统支持库.文本补丁.批量应用精确替换` **无此闸**：本批在 `模块库/开工编排/说明/使用说明.md` 由**另一会话**（`开工-20260924-124258-e24a`，租约id `1942c70d01c9408f`）持活跃租约期间，本会话的批量补丁**写入成功**（`全部成功=true`）。
   ⇒ 同一件事（写盘授权）两套判据，绕过口子成立。建议：把「写入授权」收敛为**唯一节点**，两条写腿都调它。

3. **薄壳级 `返回上限字符` 与能力级 `最大字符` 同名不同义**：`读取文件` 的体量参数叫 `最大字符`。本批踩 3 次，每次多一条 `被忽略参数` 噪声（回声救回来了，但白跑）。

4. **`全量回执` 阈值 ≈ 2,000（与薄壳默认上限耦合）**：本批 **10 次**调用（能力详情／开工准备探针／文档检索／grep／补丁回执）因超阈值被换成回执指针，各多付一轮 `读取文件(回执行区间)`。建议阈值与默认上限解耦（或 ≤8,000 内联）。

5. **`能力搜索` 返回体重复键**：每条同时回 `名称`/`中文名`/`中文名称`（三同）、`提供方`/`提供者`（二同）、`包名称`（＝`包id` 尾段），且 `说明` 常与 `一句话说明` 逐字相同。本批 15 条命中里三同键占 3/15 键位，属可直接省的体量。

6. **`正则搜索` 体量裁剪丢正文、留元信息（本轮实测两次踩到）**
   `文件系统支持库.内容检索.正则搜索` 超预算时按「丢尾键」裁剪，而它返回体里**最长的是 `命令`（rg 完整 argv，约 800 字符，纯调试用）**、**最短的是 `匹配列表`（正文）**。实测两次：`原字符数 2262 → 裁剪后 30`、`丢弃说明=叶子缩到下限仍超限，已字典丢尾键（丢 5 个）`，结果 `匹配列表` **整段消失**，只剩 `引擎`/`搜索根` ⇒ **agent 拿不到任何命中行，这次检索等于白跑**（本批两次核验都因此多付一轮）。
   建议：给该能力声明**键优先级**（`命令` 最先丢、`匹配列表` 最后丢），或把 `命令` 改成 `含命令=真` 才回。
