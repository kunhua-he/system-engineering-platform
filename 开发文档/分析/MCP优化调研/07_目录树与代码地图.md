## 一、结论摘要（先给答案）

1. **aider 的 repo map 不是「目录树」，是「按 PageRank 排序的符号摘要」**：用 tree-sitter 的 tags 查询抽 `def`/`ref`，建 `networkx.MultiDiGraph`，跑 `nx.pagerank(weight="weight", personalization=...)`，再把节点排名按出边权重摊回「(文件, 符号)」，最后用**二分查找**逼近 token 预算（`get_ranked_tags_map_uncached`）。它给我们的启示是**「排序 + 预算 + 二分」三件套**，而不是「树」本身。
2. **我们要的「一棵带忽略规则和深度限制的树」在业界是成熟且极小的实现**：`modelcontextprotocol/servers` 的 filesystem server 里 `directory_tree` 工具就是一个 `readdir(withFileTypes)` 递归 + `minimatch` 排除，源码不到 80 行，返回 `{name, type, children[]}` JSON。**这是最值得直接照搬的一件**。
3. **12.4 秒的 `find` 与 0.07 秒的 `rg` 的差距，本质是「有没有忽略规则 + 有没有单进程遍历」**：aider/repomix/gitingest 三家都各自维护了一份「默认忽略清单」（`.git`、`node_modules`、`__pycache__`、锁文件……），并在遍历时套用；repomix 还额外用 globby 走 git 感知排序。**我们的 `文件管理.列出文件` 目前只有单层、无忽略规则、无深度限制**（见第二节原文）。
4. **token 预算不能靠"估"，要靠真实 tokenizer**：gitingest 用 `tiktoken.get_encoding("o200k_base")`，aider 用模型自带 `token_count`（>200 字符时采样外推），repomix 走 `gpt-tokenizer`。三家的做法都指向：**返回体里必须带一个「这个结构大概多少 token」的数字**，LLM 才知道该不该继续下钻。
5. **可直接当依赖用的候选**（许可证/体积/Python 兼容，详见第五节）：
   - `pathspec`（gitignore 语义，纯 Python，MIT）——**最推荐**；
   - `tiktoken`（已在本机 Python 生态内，gitingest 在用）；
   - tree-sitter 系（`tree-sitter` + `tree-sitter-language-pack`）——**重量级，仅当要做符号级地图时才引入**；
   - ctags（GPL-2.0，二进制）——**许可证与部署形态都要掂量**。

## 二、本项目 E1 现状（真源原文，非记忆）

节点 E1 的原话是「只有单层『列出目录』，没有『树』；实测 `find` 一棵树 12.4 秒，`rg` 只要 0.07 秒」。

真源 `模块库/文件管理/能力定义.json`（第 313–364 行，`文件管理.列出文件`）：

- 能力id：`文件管理.列出文件`，版本 `1.0.0`，中文名「列出文件」
- 说明原文：**「列出目录下条目名称（排序），返回 结果[名称列表]」**
- 参数：**只有 1 个** —— `目录路径`（文本型，必填，说明「待列出目录绝对路径」）
- 返回：`结果型`，值结构 `{成功: 逻辑型, 值: 列表型}`
- 错误码：`目录不存在` / `目录读取失败` / `提供者不可用`

**契约层面的三个缺口（对着上面原文逐条比）**：

| 缺口 | 现状 | 业界对应做法 |
|---|---|---|
| 无深度 | 参数里没有任何深度字段 | `directory_tree` 递归；repomix/gitingest 全树 + 忽略 |
| 无忽略规则 | 参数里没有任何排除字段 | `directory_tree.excludePatterns`；repomix `defaultIgnoreList`；gitingest `DEFAULT_IGNORE_PATTERNS` |
| 无类型/无 token 估算 | 返回 `值` 是裸 `列表型`（只有名字） | `directory_tree` 返回 `{name,type,children}`；gitingest 摘要里带 `Estimated tokens` |

⇒ **E1 不是"慢"这一个问题，是"契约里根本没有树这个概念"**。慢只是没有忽略规则后的必然结果（12.4 秒的 `find` 是把 `.git`/`工程缓存` 一起走了一遍）。

### 3.1 `Aider-AI/aider` —— repo map（本方向最对口）

- 地址：https://github.com/Aider-AI/aider
- star：约 49k（取证：`curl -s https://img.shields.io/github/stars/Aider-AI/aider.json`）
- 许可证：Apache-2.0
- 关键文件：`aider/repomap.py`（867 行）、`aider/queries/tree-sitter-language-pack/<语言>-tags.scm`、`aider/special.py`、`aider/models.py::get_repo_map_tokens`
- 本机源码路径：`/Users/hekunhua/.hermes/cache/scratch/开源调研/07/aider/`

#### （1）符号抽取：tree-sitter tags 查询，def/ref 两类

`get_tags_raw(fname, rel_fname)`（第 279–363 行）流程：

1. `lang = filename_to_lang(fname)` → `get_language(lang)` / `get_parser(lang)`（来自 `tree_sitter_languages` 或 `tree-sitter-language-pack`，见文件头 `USING_TSL_PACK`）；
2. 读 `aider/queries/<pack>/<lang>-tags.scm`，`Query(language, query_scm)` 跑 `parser.parse(...)` 的根节点；
3. 捕获名按前缀分类：`name.definition.*` → `kind="def"`，`name.reference.*` → `kind="ref"`，其余丢弃；
4. 产出 `Tag(rel_fname, fname, name, kind, line)`。

查询文件本身极小，例如 `python-tags.scm` 全文：

```scheme
(module (expression_statement (assignment left: (identifier) @name.definition.constant) @definition.constant))
(class_definition name: (identifier) @name.definition.class) @definition.class
(function_definition name: (identifier) @name.definition.function) @definition.function
(call function: [ (identifier) @name.reference.call
                 (attribute attribute: (identifier) @name.reference.call) ]) @reference.call
```

**兜底机制（值得抄）**：若某语言只给出 `def` 没有 `ref`（源码注释明说 cpp 就是这种），就用 Pygments 的 `Token.Name` 词法 token 全部当 `ref` 补回去（第 347–363 行）。

#### （2）建图与排序：PageRank + 加权边

`get_ranked_tags(...)`（第 365–574 行）：

- 数据：`defines: {符号 → {文件}}`、`references: {符号 → [文件]}`；只保留**同时被定义又被引用**的符号（`idents = set(defines) & set(references)`，第 468 行）。
- 图：`G = nx.MultiDiGraph()`，边方向是 **referencer → definer**（第 514 行 `G.add_edge(referencer, definer, weight=use_mul * num_refs, ident=ident)`）。
- **权重乘子（`mul`，第 487–514 行）——这是"排序"的全部秘密**：

| 条件 | 乘子 |
|---|---|
| 符号被用户**在聊天里提到**（`mentioned_idents`） | × 10 |
| 符号是 snake/kebab/camel 命名**且长度 ≥ 8** | × 10 |
| 符号以 `_` 开头（私有） | × 0.1 |
| 该符号**被 >5 个文件定义**（低频价值） | × 0.1 |
| 引用方文件**在 chat 里**（当前正在改的文件） | 额外 × 50 |
| 引用次数 | 取 `math.sqrt(num_refs)` 做压缩，防止高频低价值提及压过一切 |

- 无引用的定义加自环 `weight=0.1`（注释说明是为了兼容 tree-sitter 0.23.2 的 ruby 解析差异）。
- **个人化向量**：`personalize = 100 / len(fnames)`；文件在 chat 里 +personalize，文件在 `mentioned_fnames` 里取 `max`，**路径分量或文件名命中 mentioned_idents 也 +personalize 一次**（第 424–445 行）；然后 `nx.pagerank(G, weight="weight", personalization=..., dangling=...)`（第 520–525 行）。
- **摊回定义**：把每个源节点的 rank 按出边权重比例分摊到目标 `(文件, 符号)` 上累加（第 533–545 行），排序得到 `ranked_definitions`；**chat 里已有的文件会被 `continue` 跳过**（第 556–557 行，因为它们整份已在上下文里，不需要摘要）。

#### （3）token 预算：二分查找逼近 + 15% 容差

- **预算从哪来**（`aider/models.py::get_repo_map_tokens`，第 782–789 行）：`map_tokens = max_input_tokens / 8`，再 `min(…, 4096)`、`max(…, 1024)`；用户可用 `--map-tokens` 覆盖（`main.py` 第 964–967 行）。
- **没有 chat 文件时放大视野**（`get_repo_map`，第 120–132 行）：`target = min(max_map_tokens * map_mul_no_files, max_context_window - 4096)`，其中 `map_mul_no_files` **默认 8**（构造函数默认值，第 56 行）⇒ 空聊天时会尝试给到接近上下文上限的树。
- **二分查找**（`get_ranked_tags_map_uncached`，第 629–706 行）：

```python
middle = min(int(max_map_tokens // 25), num_tags)   # 初值：按 token 预算/25 估"每个符号约 25 token"
while lower_bound <= upper_bound:
    tree = self.to_tree(ranked_tags[:middle], chat_rel_fnames)
    num_tokens = self.token_count(tree)
    pct_err = abs(num_tokens - max_map_tokens) / max_map_tokens
    ok_err = 0.15                                     # 误差 <15% 就收工
    if (num_tokens <= max_map_tokens and num_tokens > best_tree_tokens) or pct_err < ok_err:
        best_tree, best_tree_tokens = tree, num_tokens
        if pct_err < ok_err: break
    if num_tokens < max_map_tokens: lower_bound = middle + 1
    else:                           upper_bound = middle - 1
    middle = int((lower_bound + upper_bound) // 2)
```

即：**在"取前 N 个符号"上二分**，每轮真的渲染一次再数 token，允许 15% 超/欠。这是"预算内选节点"的完整机制。

- **token 计数本身也做了省算**（`token_count`，第 89–101 行）：< 200 字符直接交给模型 tokenizer；否则抽 100 行样本，按 `sample_tokens / len(sample_text) * len_text` 外推。
- **渲染**（`to_tree`，第 748–784 行）：按 `sorted(tags)` 分组，同文件输出 `文件名:\n<TreeContext 摘要>`，每行**截断到 100 字符**（防 minified js 撑爆）。
- **缓存**：`.aider.tags.cache.v{CACHE_VERSION}` 目录（第 43 行，`CACHE_VERSION` 当前 3/4 分语言包），`refresh` 支持 `auto|always|files|manual`（第 57、592–608 行）。
- **特殊文件优先**：`filter_important_files(other_rel_fnames)`（`aider/special.py`）结果被 **prepend 到 ranked_tags 最前面**（第 656–662 行），保证 `README`/构建文件这类"没符号但重要"的文件先入选。

**⇒ 对我们的直接可搬项**：不是整个 PageRank（我们暂时没有"改哪些文件"的 chat 上下文），而是
① 先给「重要文件」白名单置顶（README/说明/能力定义.json）；
② 按"名字长度 ≥ 8 / 被引用次数 / 目录深度"给一个可解释的权重；
③ 用**二分 + 真 token 计数**逼近预算，而不是拍一个 `max_files`。

### 3.2 `tree-sitter/tree-sitter` —— 符号解析底座

- 地址：https://github.com/tree-sitter/tree-sitter
- star：约 27k；许可证：MIT；本机体积 7.1M（`--depth 1`）
- 机制：C 核心 + 各语言独立 grammar 仓库，运行时用 S-expression 查询（`.scm`）在语法树上做模式匹配，产出带位置信息的捕获。
- 在本方向里的位置：**aider 与 repomix 都用它，但用法完全不同**——
  - aider 用它做 `def`/`ref` 抽取 → 建引用图 → PageRank（见 3.1）；
  - repomix 用它做**签名压缩**（见 3.3）。
- 对我们（Python 3.14 后端）的代价：`tree-sitter` 有官方 Python binding（`pip install tree-sitter`），但**每种语言要单独装 grammar 包**（aider 干脆依赖 `tree-sitter-language-pack` 打包合集）。装 3–5 种语言的体积与编译成本，远超"给 LLM 一棵树"的需求。

**判断：本阶段不该引入 tree-sitter**。我们的需求是「目录树 + 忽略规则 + token 预算」，符号级地图是**下一级需求**（对应 D1「改 1 个能力要同步 N 个文件」那种"谁引用了谁"的问题），届时再引入更划算。

### 3.5 `sourcegraph/scip` —— 代码智能索引格式（符号级，远期）

- **对我们的价值**：如果要"一次拿到全仓符号表"，`ctags -f - --output-format=json --fields=+n -R <目录>` 是**单进程 C 实现，比 Python 遍历快一个量级**；但 ① GPL-2.0；② 需额外安装二进制；③ 对我们的"目录树"需求**过重**。**建议：仅在"符号级地图"立项时评估，不进本轮。**

### 3.8 `modelcontextprotocol/servers` 的 filesystem server —— 现成的「目录树」MCP 工具

- 地址：https://github.com/modelcontextprotocol/servers（`src/filesystem/`）
- star：约 91k（整仓）；许可证：GitHub 未识别出单一 SPDX（仓库内各 server 分目录各自声明，`filesystem` 目录为 MIT）
- 本机源码：`/Users/hekunhua/.hermes/cache/scratch/开源调研/07/servers/src/filesystem/index.ts`

`directory_tree` 工具的**真实契约原文**（第 547–561 行）：

```
title: "Directory Tree"
description: "Get a recursive tree view of files and directories as a JSON structure.
  Each entry includes 'name', 'type' (file/directory), and 'children' for directories.
  Files have no children array, while directories always have a children array (which may be empty).
  The output is formatted with 2-space indentation for readability. Only works within allowed directories."
inputSchema: { path: string, excludePatterns: string[] (optional, default []) }
outputSchema: { content: string }
annotations: { readOnlyHint: true, openWorldHint: false }
```

实现（第 570–587 行）：`fs.readdir(validPath, { withFileTypes: true })` 递归，对每个条目算 `relativePath`，用 `minimatch(relativePath, pattern, { dot: true })` 匹配；**非通配模式会三种写法都试一遍**：精确/`**/pattern`/`**/pattern/**` —— 也就是「写 `node_modules` 就能同时命中该目录本身与其下全部内容」。返回 `TreeEntry {name, type, children?}`，`JSON.stringify(tree, null, 2)`。

**这是与 E1 逐字对应的现成实现**：递归 + 排除模式 + 类型标注 + JSON 结构 + `readOnlyHint` 注解（只读语义）。
