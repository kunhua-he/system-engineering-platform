### 交叉复核结论

**原结论「整组回收无宽限期」→ 不成立。**

精确表述（三层）：

1. **有没有传宽限秒：没有显式传。** `独立进程_账本.py:227` 是 `进程终止.强制结束子进程(组长进程id)`，只有位置参数，未传 `宽限秒`。

```python
    def _包内模块表(self, 包根: Path) -> dict[str, tuple[int, str, int, int]]:
        """取 sys.modules 里「住在该包根下的全部模块」：键 → (对象标识, __file__, mtime纳秒, 字节数)。

        归属判据只有一条（哲学 1.1）：模块 `__file__` 解析后落在包根内。入口模块按
        `spec_from_file_location` 载入，其 `__file__` 就是包根下的 入口.py，同样命中；
        聚合壳包的包根含子包文件，子包模块也一并命中（与热接入弹模块的口径一致）。
        """
        import sys
        表: dict[str, tuple[int, str, int, int]] = {}
        for 键, 模块对象 in list(sys.modules.items()):
            文件路径 = getattr(模块对象, "__file__", "") or ""
            if not 文件路径:
                continue
            try:
                真实路径 = Path(文件路径).resolve()
                if not 真实路径.is_relative_to(包根):
                    continue
                状态 = 真实路径.stat()
            except (OSError, ValueError):
                continue
            表[键] = (id(模块对象), str(真实路径), 状态.st_mtime_ns, 状态.st_size)
        return 表
```

```python
                Path(文件).stat()
            except OSError as 错误:
                说明.append(f"模块源文件现场取不到状态: {文件}（{错误}）")
                continue

            if 旧对象标识 is not None and 旧对象标识 == 新对象标识:
                说明.append(f"模块对象未换新（{文件} 仍是重载前那个对象，旧代码仍在场）")
        for 文件 in sorted(set(旧文件对象) - set(新文件对象)):
            # 文件还在盘上却不在场 = 被连带弹出后没重新载入（依赖它的上层包会拿到残缺包）；
            # 文件已从盘上消失则是「代码真删了模块」，不算未生效。
            if Path(文件).is_file():
                说明.append(f"模块重载后不在场（文件在盘上却未重新载入）: {文件}")
        return (not 说明), 说明
```

- `后端核心/后端核心.py:189-210` 新增一个「包内类/函数对象表」（键 → `(id(类对象), 限定名)`），与 `_包内模块表` 同一份 `__file__` 归属判据（哲学 1.1，不另建一套口径）。

### 代价

- 1 文件，约 20-30 行（新增 `_包内类对象表()` + `_自证重载已生效` 内一轮对账 + 说明文案）。
- 若要顺带在热接入入口把「持住旧对象」的包单独标红（区别于「模块没换新」），再加 1 文件约 5 行。

### 风险

- **误报面大**：正常重载后，新类对象 id 必然与旧不同；判据必须区分「旧 id 出现在**包外**持有方」与「旧 id 只在本包内被替换」——后者是期望行为。若按「旧 id 是否还存在于任何模块」判，会把每一次正常重载都判成未生效（自证恒假），比不判更糟。
- `id()` 复用：对象被回收后 id 可能被新对象复用。判据必须**同时**比对 `(id, 限定名, __file__)` 三元组，不能只比 id（`_包内模块表` 已经是这个思路：`id + 路径 + mtime + size` 四元组）。
- 反向依赖闭包（`_包依赖序`，`后端核心.py:299-303`）已经排了「依赖方在被依赖者之后重载」，第四条判据若与它冲突（依赖方重载完又持住新对象），会产生**顺序性误报**；判据应在**全部目标包重载完成后**统一跑一轮，而不是每包重载后立即跑。

- 网关级蓝绿：**≥2 文件**（`启动运行核心网关.py` + 端口移交 + 可能改 `停机编排`），数十行，属新增能力而非改造。

### 风险

- **粘性键必须唯一**：`热切换.py:358-359` 明写 `状态可迁移=假` 时「并行运行 + 路由切换（**不停止旧进程**）」——旧进程继续活着。若此时再叠灰度分流，同一能力会**同时有两个进程可服务**；分流若无请求级粘性（同一会话/同一 key 固定落同一版本），有状态能力直接崩。
- **灰度比例表 当前 0 读取者，加读取者即改运行态语义**：`热切换.py:208` 的注释已经把这个状态记为「历史缺陷二」并保留原样。改成真分流前，需先确认 `说明/灰度口径.md` + 决策记录 0018 的口径是否同步修订，否则会出现「代码分流了但权威口径说没分流」的新一轮不一致。
- **`_真实回滚` 有界但只保最近 1000 条**（`热切换.py:393-394`）：真分流后回滚频次可能上升，1000 条上限下早期回滚证据会被挤掉；证据保全需求高时需外移落盘（当前是进程内 `回滚记录表`）。
- **第 7 步的观测是 `成功=真` 硬编码**（`热切换.py:344`：`指标库.观测(能力id=能力id, 版本=新版本, 成功=真, 耗时毫秒=10)`）——它写进指标库的是**构造出来的成功样本**，不是真实调用结果。若将来按 `灰度指标库.聚合` 的样本量做分流决策，这批样本会污染判据。
