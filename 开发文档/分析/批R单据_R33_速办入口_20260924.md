## 2. 入口形态（不新增第 4 个 MCP 工具）

薄壳对外仍是 3 个工具（`capability_search` / `capability_call` / `tool_catalog`）。速办挂在 `capability_call` 的 `操作` 上：

```
capability_call(操作="速办", 意图="<看文件|查文件|写文件|跑命令>", 参数={...短参数})
```

短参数表（**渲染自唯一事实源**，`渲染速办短表()` 现算）：

```
看文件=路径[+区间]；查文件=模式[+范围+文件模式]；写文件=路径+内容；跑命令=命令[+经shell]。
```

| 速办意图 | 派生自（常用意图） | 转发到（权威能力） | 短参数 → 契约参数 |
|---|---|---|---|
| 看文件 | 读文件 | `文件系统支持库.文件操作.读取文件` | `路径`→`文件路径`；`区间`→`起始行`＋`结束行` |
| 查文件 | 内容检索 | `文件系统支持库.内容检索.正则搜索` | `模式`→`模式`；`范围`→`根目录`（缺省 `.`）；`文件模式`→`文件模式` |
| 写文件 | 写文件 | `文件系统支持库.文件操作.写入文件` | `路径`→`文件路径`；`内容`→`内容` |
| 跑命令 | 跑命令 | `系统核心支持库.进程管理.执行命令` | `命令`→`命令`；`经shell`→`经shell` |

★ 速办表里**一个能力 id 都不写**：`首选能力` 一律现查 `常见意图首选能力` ⇒「速办表与映射表不一致」在结构上不可能发生（换落点只改上面那张表）。逐条一致的机器对照在 `测试_薄壳速办.py::唯一事实源测试`。
