## 1 归因：认领腿与回锁腿的调用链（为什么缺口是必然产物）

### 1.1 认领腿（开窗）

```
开工编排.开工即占
  └─ 平台控制面.能力目录.申请文件租约            实现/文件租约申请.py:204
       ├─ 存储.新租约(...)                       文件租约存储.py:549（构造活跃记录）
       └─ 解锁认领路径(...) → 公共契约/运行时/仓库只读锁.py:318 解锁供写入(目标 ＋ 父链)
```

⇒ **认领成功的那一刻就解锁「目标 ＋ 父链」**（待建路径要连父链一路放开到第一个已存在的祖先，否则新文件根本建不出来）。

### 1.2 回锁腿（关窗）—— 唯一一处

```
（唯一动作）平台控制面/能力目录/实现/文件租约维护.py:144 回锁终结路径(...)
    └─ 公共契约/运行时/仓库只读锁.py::回锁(绝对路径, 连父链=该收父链(...))
```

它只被两个入口调用：

```
· 释放文件租约      收工释放（显式：调用方/人工发起）
· 回收过期文件租约  懒回收（自动）
```

懒回收有三个唤醒点（都是「本来就有的点」，不新造周期调度器）：

```
① 认领前顺手回收    实现/文件租约申请.py（懒回收过期租约）
② 仓库只读锁.查询   公共契约/运行时/仓库只读锁.py::查询（未锁非空时才回收）
③ 资源账本维护循环  运行核心/资源协调/句柄服务.py（顺手回收过期租约）
```

### 1.3 为什么「会话结束」在改前必然留下缺口

`是活跃` 的口径 = 「状态活跃 **且** 未过期」。于是：

```
· 一条租约的到期是**时间的函数、不是事件**：会话（进程）早就没了，只要没到点，
  它在账上仍是「活跃占用」⇒ 回收腿**判不出**它是无主的；
· 认领解锁的是「目标 ＋ 父链」，而回锁只在上面那一条腿 ⇒ 会话异常结束时，
  窗口继续开着，且缺口恰好落在「要提交的那些路径」上；
· 实测现场（本任务事实源）：`文件租约.json` 里 9 条 `状态=活跃`、所有者是两条已结束
  会话的开工ID ⇒ `仓库锁.py --查看` 未锁 15（9 路径 ＋ 6 父目录）
  ⇒ 下一批提交被 `pre-commit` 判据一拒。
```

★ 归因结论：**缺口 = 回收责任没人接**（不是资源不够）。修法只能是「给回收腿补一条『所有者还活着吗』的事实」，而不是放宽判据，也不是在 `pre-commit` 里加豁免。

## 2 修法：唯一回锁腿补第三半（判据一处、动作一处）

### 2.1 开窗那一侧登记「谁开的」

`平台控制面/能力目录/文件租约存储.py::新租约` 新增一键 `所有者进程号`（缺省 = 本进程 `os.getpid()`；显式给定时以它为准，供代认领 / 取证用）。**老记录没有这一键 ⇒ 回收腿不判**（不新造事实）。

### 2.2 回收判据从「两半」变「三半」（同一次回锁）

`平台控制面/能力目录/实现/文件租约维护.py::回收过期文件租约` 的判据取并集：

```
到点      过期时间 已到
停摆      心跳停摆超过 阈值（默认 900 秒）
进程消失  所有者进程号 > 0 且 系统进程不存在(它)      ← 本次新增

三条任一命中 ⇒ 状态改「已过期」⇒ **同一次** 回锁终结路径(...) 逐条回锁（含父链）
```

探活走**统一节点**：`运行核心.进程身份.系统进程存在`（它再下沉到 `公共契约` 的跨平台收口 `进程终止.进程存活`）；本模块**不裸调** `os.kill`，也不自写第二套探活。

失败方向是 **fail-safe（不许误收）**：老记录无 `所有者进程号`、或值不是正整数 ⇒ 不判；探活取不到结论时统一节点按「存在」回真 ⇒ 只会**晚**收（到点兜底），不会误收回别人正在用的窗口；进程号被复用同样只会晚收。

### 2.3 为什么不是「再加一条回锁腿」

华哥口径「有统一节点的全部切成统一节点，不许组件自己内置一份」⇒ 三半**同一条腿、同一次回锁**。`pre-commit` 是**消费端**（它只读 `查询()` 的 `缺口数`），回收是**生产端**；把回收塞进钩子就是第二条腿（哲学 1.2：同一件事两套实现即缺陷）。三个唤醒点自动同时获得第三半，不必各自改一遍。
