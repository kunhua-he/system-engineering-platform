## 二、路径传参口径（唯一，全文一句）

> **普通路径参数一律写「项目根相对路径」（posix、不带 `..`）；只有 `项目根` 这类基准参数写绝对路径。绝对路径在普通路径参数上永久兼容。**

- **为什么是「相对优先」而不是「绝对优先」**：`修改路径`（列表型）与全部租约/登记/证据面**本来就是项目根相对路径**；相对路径可移植（换机器/换用户不失效）、可对账、不把本机路径写进证据。选绝对优先会同时改掉这四处既有口径，且与 `开工编排.开工即占`「显式拒绝绝对路径」正面冲突。
- **为什么基准类必须绝对**：`项目根`/`仓库根`/`源码根`/`受控根目录`… **本身就是解析基准**，写相对会落到环境变量 `系统平台_项目根` 或 cwd —— 那是「基准漂移」，不是「路径写法」。
- **行为层不改**：华哥 2026-09-22 裁决「绝对/相对都要能用」仍然成立（`_归一化路径族参数` 只做「相对→按生效根拼绝对」，绝对原样）。本批统一的是**规范写法**（agent 只记一句），不是收紧兼容性。

### 8.6 N8：网关 fd / POSIX 信号量泄漏 —— 根因与设计（**先出设计再动手**）

**实测（主会话 03:3x）**：网关 PID `71733`（子代理 03:29 重启后 `96 fd / 0 PSXSEM`）⇒ **6 分钟**后 **`144 fd / 40 PSXSEM`**；`launchctl limit maxfiles` 软限 = **256**。

**两个数不在同一口径上（根因）**：

1. 设计上界：`运行核心/任务调度/任务进程.py:85 任务表历史上限 = 64`；
2. 同一文件 `:288` **自己写明**「连同它的句柄被永久引用（**约 12 个 fd/条**）」⇒ 设计上界需要 **64 × 12 = 768 fd**；
3. 进程实际预算：**256**。

⇒ **设计允许的滞留量是进程预算的 3 倍**，必然在约 21 条任务后撞上 `[Errno 24] Too many open files`（子代理 03:2x 实拍正是这一条）。批F「只治了触发条件、没治产生点」的判断成立：产生点是**释放只在驱逐时发生**（`_释放任务句柄` 只被 `_驱逐` 调），而 `任务表历史上限` 这个上界**与 fd 预算脱钩**。

**设计（三条，按哲学选）**：

- **D1（首选，单一节点）**：`任务表历史上限` **不再写死 64**，改为**由进程 fd 预算推出** —— 启动时读 `resource.getrlimit(RLIMIT_NOFILE)` 软限，`历史上限 = max(1, (软限 − 常驻余量) // 每条 fd 数)`；「每条 fd 数」与「常驻余量」都取自**既有资源管理节点**（`平台控制面/资源监督.py` 的预算口径），**不另写一份**。判据件：把软限设成 256 跑 N 条任务，要求「未超限」且「`历史上限` 随软限变化」。
- **D2（并行，放大器）**：网关 launchd plist 补 `SoftResourceLimits.NumberOfFiles`（256 是 macOS 默认，对常驻服务过小）。与 D1 是**两个面**（一个治滞留量、一个给余量），不互斥。
- **D3（可选，治产生点）**：已收敛且已移出活动账本的任务，其 `取消事件`/`进程组就绪事件`（4 个 PSXSEM）**不再被任何判据读**，可在**收敛时**就置 `None`，只把 `进程.close()` 留到驱逐（docstring 已解释 `close()` 为何必须留到驱逐）⇒ 把「每条 12 fd」压到「每条 1–2 fd」。

**为什么本批不直接改**：这属**句柄生命周期**改动，按本仓既定口径须**先落设计再动手**；且 D1 的「每条 fd 数」要接既有资源管理节点，须先定该节点的预算口径。
