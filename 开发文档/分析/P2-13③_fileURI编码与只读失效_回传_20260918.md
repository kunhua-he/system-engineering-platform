### 复用了什么（记忆包要求「先查有没有现成原子能力」）

查了、也查完了，结论是**要合并、不是要复用**：

- **平台已有的唯一口径**是 `运行状态监督/实现/只读状态库.py:42`
  `sqlite3.connect(Path(库文件).resolve().as_uri() + "?mode=ro", uri=True, timeout=5.0)`，
  并有 `运行状态监督/说明/设计说明.md:76` 把它写成**成文口径**（「唯一构造口径」）。
  **但它盖不住这个缺陷**：它 `resolve()` 后直接把 `?mode=ro` 拼在 URI 后面，
  同样的截断问题原样存在。所以「复用」在这里等于把 bug 一起复用。
- `支持库/后端/代码解析支持库/代码地图/实现/只读连接.py:24` 的 `只读URI()` 用的是
  `路径.resolve().as_uri() + "?mode=ro&immutable=1"` —— 同一个写法，同样没盖住；
  且它对代码地图（外部只读资料）是对的，**不能**搬到权威状态：`immutable=1` 断言
  「文件不会变」，而权威状态是 **WAL 活库**，正在追加的 WAL 在 immutable 连接下读不到
  （会把活跃内容误判成缺失）。这一条已写进 `只读库URI()` 的 docstring，防后人照搬。
- 全仓 `urllib.parse.quote` 的用法（20 处）都在 HTTP/URL 面（`HTTP连接器`/`网关`/`远程镜像`），
  没有一处是文件 URI 面，无法直接复用。
- **所以本次把口径提到 `权威状态.py` 模块级（`只读库URI`），并保持它在 `损坏恢复` 里的落点。**
  `只读状态库.py` 是否也切到这条口径，不在「允许修改」内，请看 §6.3。

### 为什么用 `as_uri()` 而不是报告建议的 `quote(str(路径))`

`Path.as_uri()` 是标准库里「路径 → file URI」的**现成能力**，除 `#`/`?`/空格/百分号外还管
`.`/`..` 规范化与 `quote` 的 `safe` 字符；而报告建议的 `quote(str(路径))` 默认 `safe='/'`，
在 Windows 反斜杠与冒号上会走偏（记忆包「先查平台是否已有原子能力」的同一精神：
标准库已有就别手搓）。`as_uri()` 要求绝对路径，故先 `resolve()`。

### 「空库也 ok」这个掩盖怎么拆的

`_校验目标库()` 顺序**必须在** `integrity_check` **之前**，判据先精后宽：

1. `os.path.samefile` 比 **inode + 设备号** —— 「是不是同一个文件」的精确答案，
   同一文件的不同写法（软链接、`/var` 与 `/private/var`、`..` 段）全判等；
2. 任一侧不存在时降级比**规范化路径双向包含**（`abspath`/`realpath` 各一份，任一命中即算等）。

**为什么不像记忆包建议的那样只比 `实际路径 == 期望路径`**：本机 `/var/folders/...`
与 SQLite 自报的 `/private/var/folders/...` 就是同一条路径的两种写法（实测已复现），
纯字符串相等会**恒不等** ⇒ 判红 ⇒ 走备份覆盖分支。判红的后果是**拿旧备份盖掉好库**，
所以判据必须「既不放过错误库、也不冤枉正确库」；用 inode 身份比字符串相等更精确且无假红。

判红抛 `sqlite3.DatabaseError`（不是 `RuntimeError`）：语义就是「这个连接不可信 ⇒
当作数据库不可用」，**复用既有**「损坏 → 备份恢复」分支，不新增未处理异常类型。
