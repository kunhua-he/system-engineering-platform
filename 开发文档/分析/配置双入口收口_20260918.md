## 二、定性依据（六条，全部可现场复算）

### 依据 1（决定性）：分层口径不允许合并

`运行核心/依赖防火墙.py::允许依赖表`（层向口径唯一事实源，进发布门禁）：

```
"支持库":     {"公共契约"}                 # 只许依赖 公共契约
"项目适配层": {"公共契约", "运行核心"}      # 不许依赖 支持库
```

- 把提供者层并进 `项目适配层/配置适配/` ⇒ 该包要 import `支持库` ⇒ **越层依赖**，门禁判红；
- 把门面层下沉进 `支持库/适配层/` ⇒ 把「项目」概念（项目配置目录、项目段覆盖）带进
  「第三方边界翻译层」⇒ 破坏「适配层只做第三方翻译」的口径。

⇒ **合并的前提是改分层口径本身（层表 + 头注释镜像块 + 预留授权体检），不是改两行 import。**
代价远大于收益，且不属本批允许修改范围。

### 依据 2：读的不是同一份数据，交付的不是同一件事

| | `支持库/适配层/提供者配置读取/`（提供者层） | `项目适配层/配置适配/`（门面层） |
|---|---|---|
| 数据源 | `支持库/适配层/提供者配置/提供者配置.json`（**外部协议配置一份**） | `项目适配层/项目配置/*.json` + 支持库默认值 + 环境配置 + 显式覆盖 |
| 交付 | 按**能力 id** 取配置段（供提供者路由/初始化） | 五层合并结果 + 来源追踪表 + 校验报告 |
| 合并 | **无**（不合并、不解释业务语义） | 有（固定顺序，fail-closed） |
| 校验/来源追踪 | **无** | 有（未知项/必填缺失/类型错误/明文密钥） |

两者都读 JSON，但**读的是不同来源、交付的是不同产物**。

### 依据 3：包级公开能力面**不交集**（收口的直接目标）

```
提供者层 __all__  = ["读取提供者配置", "获取能力配置"]
```

**无一个同名公开符号。**
