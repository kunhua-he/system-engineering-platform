# 系统工程平台 · 调用接入指南

> 文档性质：面向调用者（业务项目 / Agent / 开发者）的接入说明。
> 范围：能力发现、三通道执行、验证与发布。唯一事实源见 `开发文档/第三十阶段S0生产事实冻结.md`。

## 总体流程

```text
        ┌─────────────── 开发闭环 ───────────────┐
        │                                        │
   MCP 能力发现                          执行底座（三通道选一）
  （易语言"使用声明"）                     │
        │                                   ├── ① HTTP REST
   capability_search                        │      POST /能力执行
   capability_read                          ├── ② MCP 执行
   列出能力 / 参数 / 返回 / 示例              │      capability_execute
        │                                   └── ③ 本地同级
        └───────────────► 调用能力 ◄────────      import 读取文件
                                │
                                ▼
                     统一结果 + 证据链
              {成功, 值, 错误码, 错误说明}
```

## 一、平台能做什么

平台把通用能力原子化、服务化：文件处理、文档转换、媒体处理、数据库访问、
外部程序调用等，统一经**能力注册表**登记，经**唯一能力调用器**调用，全链路
留证据。调用者不必关心底层实现与第三方细节。

- 37 个正式支持库（原子能力 + 第三方提供者）
- 11 个正式模块（组合流程样板）
- 148 条聚合契约能力

## 二、能力发现（MCP，易语言"使用声明"）

先经 MCP 找到能力、看参数/返回/示例，确定怎么调：

### 1. 搜索能力

```bash
python3.14 开发工具/能力搜索/能力搜索器.py --能力 读取文件
# 或 MCP：capability_search
```

示例输出：

```
能力id: 文件系统.读取文件
名称: 读取文件
参数: 文件路径:文本, 编码:文本
返回: {'类型': '结果', '值结构': {'值': '文件文本内容'}}
调用示例: 文件系统.读取文件(文件路径=支持库/后端/文件系统/包声明.json, 编码=utf-8)
```

### 2. 查看能力契约

用 `capability_read`（MCP）或读 `能力契约/参数契约.json` 确认参数/返回/错误码。

## 三、执行底座（三通道选一）

**必须经能力调用器执行**，禁止直接导入 `实现/` 目录或绕过能力调用服务。
三通道复用同一注册表与调用器，返回同一统一结果 + 证据链。

### ① HTTP REST（完全隔离，任何语言可调）

```text
POST http://127.0.0.1:8766/能力执行
body: {"能力id": "文件系统.读取文件", "参数": {"文件路径": "xxx", "编码": "utf-8"}}
返回: {"成功": true, "值": "文件内容", "错误码": "", "错误说明": ""}
```

> 状态：接口规划中（唯一文档 S0.1 已定义，落地进行中）。

### ② MCP 执行（Agent 对话内直接执行）

```text
capability_execute（需 角色/开工/白名单 校验）
```

> 状态：接口规划中（唯一文档 S0.1 已定义，落地进行中）。

### ③ 本地同级（下载到本地，易语言式中文调用）

支持库/模块库复制到本地项目后，直接 `import` 中文函数一行调用：

```python
from 支持库.后端.文件系统 import 读取文件
结果 = 读取文件(文件路径="公共契约/能力契约/契约.py", 编码="utf-8")
if 结果.成功:
    print(结果.值)
```

> 当前已可用入口（统一开发入口，命令行/Python 复用同一实现）：

```bash
# python3.14 开发工具/开发入口.py 操作 参数JSON
python3.14 开发工具/开发入口.py 搜索能力 '{"关键词":"读取文件"}'
python3.14 开发工具/开发入口.py 查看契约 '{"能力id":"文件系统.读取文件"}'
python3.14 开发工具/开发入口.py 真实调用能力 '{"能力id":"文件系统.读取文件","参数":{"文件路径":"公共契约/能力契约/契约.py","编码":"utf-8"}}'
```

成功调用返回统一结果并附**证据链**（请求 id、模块版本、能力 id、支持库包 id、
提供者版本、制品摘要、成功/失败、资源释放结论）。

### 统一结果格式

```text
成功    布尔：是否成功
值      成功时的返回值
错误码  失败时的机器可读错误码
错误说明 失败时的人类可读说明
```

底层异常不得直接泄漏；错误码与说明由能力契约定义。

## 四、项目接入流程（新项目）

1. **项目适配层声明**：在 `项目适配层/项目声明/` 声明项目（版本、配置、权限、路径、密钥引用与项目别名）。
2. **依赖锁定**：`项目适配层/依赖锁定/` 锁定依赖版本。
3. **模块绑定**：`项目适配层/模块绑定/` 绑定要用的模块版本。
4. **配置合并**：`项目适配层/配置适配/` 合并项目配置。
5. **运行入口**：`项目适配层/运行入口/` 提供项目运行入口。

示例：`示例项目/适配层示例/运行入口/运行.py` 是最小运行样板。

## 五、MCP 网关接入（Agent / 工具）

平台以单一 MCP 网关对外：`system_engineering_toolkit`（HTTP Streamable）。

> **MCP 定位**：用于**能力发现与使用声明**（`capability_search` / `capability_read`
> 列出能力、参数/返回/示例），等价易语言"使用声明"；**执行走三通道底座**，
> MCP 不承载第二套执行路径。

### 启动

```bash
./MCP工具箱/启动HTTP服务.sh        # 默认端口 8766
./MCP工具箱/启动HTTP服务.sh 8767   # 指定端口
```

### 配置

```jsonc
// opencode.json
{
  "mcp": {
    "system_engineering_toolkit": {
      "type": "remote",
      "url": "http://127.0.0.1:8766/mcp/"
    }
  }
}
```

### 工具分组

| 分组 | 工具 | 用途 |
|---|---|---|
| 上下文 | `project_context` | 项目身份、代码地图状态、可信证据、最近成功验证 |
| 能力发现 | `capability_search` / `capability_read` | 搜索/查看能力（易语言"使用声明"）；执行走底座三通道 |
| 代码地图 | `codegraph_explore` | 符号、源码、调用链定位 |
| 协作 | `development_start` / `temporary_context` / `register_task` / `collaboration_status` / `delivery_closeout` | 开工、上下文、协作状态、收口 |
| 验证 | `verify_and_record` / `verification_plan` / `validate_verification_command` / `judge_verification_result` | 验证计划、命令校验、结果判定、证据入账 |
| 反馈 | `mcp_feedback` / `feedback_status` / `feedback_review` | 使用反馈闭环 |
| 发布 | `run_release_gate` / `check_release_evidence` / `generate_release_evidence` / `switch_active_pointer` / `dependency_arbitration` | 发布门禁、证据、指针切换、依赖裁决 |
| 治理 | `workspace` / `test_resource` / `task_observation` / `tool_catalog` | 工作区、测试资源、任务观测、工具目录 |

### 接入约定

- 第一条调用必须是 `project_context`，核对项目名称与根目录。
- 使用后提交 `mcp_feedback`（五字段，无问题填"无"），否则不能记录成功验证。
- 验证用 `verify_and_record`，仅退出码 0 记成功证据。
- 禁止使用其他仓库的 MCP、记忆、代码地图或验证证据。

## 六、验证与发布

### 常规验收

```bash
python3.14 测试中心/运行测试.py              # 常规层
python3.14 测试中心/运行测试.py --范围 慢速    # 慢速（强杀/压力/真实外部提供者）
python3.14 测试中心/运行测试.py --范围 全部    # 顺序执行全部
```

- 唯一验收入口是 `测试中心/运行测试.py`；零测试、导入失败、未解释跳过、
  缓存假绿均判失败。
- 阶段并行默认开启；环境敏感阶段（真实进程/网关/浏览器/发布门禁/慢速层）
  永不并行。
- 全量验证持有 flock 互斥锁，禁止并发重复启动。

### 正式发布

```bash
python3.14 开发工具/发布门禁/运行发布门禁.py
```

发布门禁是正式发布唯一判定，只有"通过/阻断"两种结果；独立脚本未被发布
入口调用等同门禁不存在。

## 七、接入约束（红线）

1. **全中文命名**：变量、函数、类、文件、目录、注释一律中文；仅语言关键字、
   框架标准属性、第三方、操作系统与外部协议强制英文时保留英文。
2. **只允许 Python 标准库**：第三方依赖必须封装在 `支持库/适配层/` 对应提供者。
3. **禁止绕过能力调用器**：不直接导入 `实现/`、不拼接 `sys.path`、不注册
   测试预注入调用器。
4. **禁止读取业务项目数据**：不导入、不引用任何业务项目代码/数据库/配置/测试。
5. **跨包调用只经公开契约与包级中文入口**。

## 八、常见问题

- **能力返回 `未装配`**：能力必须由加载器装配后调用，禁止直接导入支持库/
  提供者绕过能力调用服务。
- **搜索不到能力**：先确认能力已登记（能力注册表），再检查关键词。
- **验证被锁拒绝**：已有全量验证运行中，等它结束或用 `--测试文件` 做工作包验证。
