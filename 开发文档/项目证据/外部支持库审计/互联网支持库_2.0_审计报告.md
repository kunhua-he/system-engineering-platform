## 2. 命令清单与契约

## 3. 资源与生命周期

```text
未连接
  -> ConnectFTPServer / ConnectSmtpServer / RasDial
  -> 已连接（全局隐式会话）
  -> 执行操作
  -> DisconnectFTPServer / DisconnectSmtpServer / RasHangUp
  -> 已关闭
```

HTTP `GetHttpFile` 是单次调用，底层 `InternetReadFile` 句柄在函数内部关闭。FTP、SMTP 和拨号连接则是进程/支持库级隐式状态，不向调用者返回句柄；若忘记断开，资源会一直占用到进程结束。附件也是全局集合，依赖“添加—发送/清空”的顺序。该模式可作为历史行为参考，但不能直接作为本项目的生命周期契约。

## 4. 与本项目支持库边界对照

当前项目已有正式支持库 `支持库/后端/网络请求`，公开能力为 `网络请求.发送请求` 与 `网络请求.构建查询串`，默认使用 Python 标准库，包含 SSRF 拒绝、超时、响应大小上限、取消标记和统一 `结果` 返回。其入口和契约见：

```text
支持库/后端/网络请求/包声明.json
支持库/后端/网络请求/能力契约/参数契约.json
支持库/后端/网络请求/实现/网络请求.py
```

### 4.1 重复封装判定

| 外部能力 | 当前项目对应能力 | 判定 | 处理建议 |
|---|---|---|---|
| HTTP 读文件 | `网络请求.发送请求` | **部分重复** | 不新增 `HTTP读文件`；如需字节集专用入口，应扩展同一网络请求支持库的唯一能力契约，而不是新建互联网支持库 |
| 代理设置 | 当前网络请求没有持久代理命令 | **未重复** | 代理应成为请求参数/配置契约，不采用外部库的全局隐式设置 |
| FTP 上传/下载/目录操作 | 当前正式支持库未发现 FTP 能力 | **未重复** | 未来单独的 `FTP` 支持库；每次调用显式句柄或自动释放，不能把 FTP 塞进通用 HTTP 支持库 |
| SMTP 发信/附件 | 当前正式支持库未发现 SMTP 能力 | **未重复** | 未来单独的 `SMTP` 支持库；附件集合必须句柄化/调用作用域化 |
| Windows 拨号网络 | 当前正式支持库未发现 | **不引入** | 平台特定、历史价值低；除非明确需求，不进入跨平台底座 |
| 查询串编码 | `网络请求.构建查询串` | **完全重复** | 保留当前唯一能力，不复制外部命令 |

模块库不得直接引入外部 DLL、`CInet` 或 `CSMTP*`；若未来需要，模块只能请求能力 id，由运行核心路由至对应支持库/受管提供者。

## 5. 可蒸馏内容

1. **元数据驱动 IDE**：每条命令同时保存机器名、中文显示名、长说明、返回型、参数顺序、默认值、输出参数和分组。当前项目可将这些字段映射为能力契约和前端组件属性面板。
2. **必填优先**：外部库把地址/路径/正文等必填参数放在前面，端口、凭证、模式、超时等默认参数放后面，适合当前“必填前置、可选后置”规范。
3. **输出集合声明**：`FTP目录列表` 明确返回数量并填充多个并行数组；当前底座应把它建模为统一值对象中的数组集合，禁止隐式修改调用方变量。
4. **统一命令分域**：SMTP、HTTP、FTP、拨号分成独立命令组；本项目应保持支持库原子能力边界，不复制一个含所有网络协议的“大杂烩库”。
5. **静态库符号显示内部对象**：`CInet`、`CSMTPConnection`、`CSMTPMessage` 等说明了实现对象的自然拆分，但这些对象不应直接暴露给正式代码。

## 6. 不应引入的内容

- 32 位 Windows-only PE 和旧 VC/MFC 运行时；本项目运行时要求跨平台 Python 标准库边界。
- 全局隐式 FTP/SMTP/RAS 会话；会造成句柄、连接、附件状态泄漏和并发串扰。
- 明文 FTP、旧 SMTP AUTH、GB2312 默认编码、旧 IE User-Agent；不得作为新协议默认值。
- 直接把 UI 标签窗口句柄传入网络支持库；状态必须通过事件/进度结果回传，前端核心自行绑定页面或窗口。
- 用返回空文本/逻辑型表达失败；本项目必须统一为 `成功、值、错误码、错误说明`，底层异常不得泄漏。
- 外部库的 `SetProxyName` 全局设置；代理应是请求级参数或受控配置，避免跨请求污染。
- `FTP目录列表` 以多个可变数组作为输出参数的隐式写入方式；应返回不可变结构并带元素上限。
