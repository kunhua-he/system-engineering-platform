## 3. 判据与 fail-closed

- **只增不改**：当前 id 集 ⊇ 基线 id 集；基线有、当前无 = 删/改名 → **判红**。
- **允许但留痕**（契约变更是合法行为，只报不留）：
  - 已存 id 的**内容指纹**变化（owner 包 `能力定义.json` 里该能力条目规范化 JSON 的 sha256[:16]，覆盖 参数/返回/错误码/行为/提供者 全字段）；
  - **归属包**变化；
  - **新增** id（「只增」的合法方向）。
- **fail-closed（核心）**，五种形态一律判红、绝不静默放行：
  1. 基线文件**缺失**；2. 基线**不可读**（坏 JSON/编码/权限，带异常类型）；3. 基线**形状非法**（非对象／条目缺失或为空 —— 空基线不是通过）；4. **扫描面为空**（0 条能力 id，空集不是通过）；5. 某 id 的 **owner 包能力定义取不到指纹**（判不出 ≠ 通过）。
- `首次出现` 字段用「本次冻结时快照」语义：679 条 id 的历史首现无法逐条从 git 可靠还原，写假提交号等于造假证据。
- 门禁**不自改基线**：重建必须显式 `--冻结`。
