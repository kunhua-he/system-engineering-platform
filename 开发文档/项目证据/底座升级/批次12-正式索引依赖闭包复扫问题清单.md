# 批次 12：正式索引依赖闭包复扫问题清单

## 流程图

```text
正式包索引接入
  -> 快速编译全工作区
  -> 模块依赖能力解析
  -> 发现 Provider 能力不在公开 owner
  -> 固定 7 个依赖闭包失败
  -> 下一批修复内部 Provider 解析边界
```

## 当前失败

命令：`python3.14 开发工具/快速编译/运行快速编译.py --范围 工作区`

退出码：`10`。

发现 7 个模块/模块依赖无法解析：

| 包 | 依赖能力 |
|---|---|
| 模块库.OCR | `OCR识别.识别图片` |
| 模块库.图像处理 | `图像解码.解码图像` |
| 模块库.媒体处理 | `FFmpeg媒体.检查提供者` |
| 模块库.媒体转写 | `转写.检查可用性` |
| 模块库.文档生成 | `PDF隔离提供者.校验PDF` |
| 模块库.文档解析 | `PDF文本表格.解析PDF` |
| 模块库.自修复工具 | `Git操作.检查提供者` |

## 根因判断

正式索引正确地不把 `支持库.适配层.*` Provider 能力登记为公开 owner，但依赖闭包解析没有第二个“内部受管 Provider 能力索引”。模块组合流程必须能够通过受管 Provider 的内部能力 id 闭包，而正式业务公开 owner 仍不能被 Provider 抢占。

下一批要求：建立同一索引内的“内部 Provider 能力解析”路径，仅供包依赖闭包使用；禁止它出现在公开 owner、用户能力搜索和模块公开能力冲突表中。补齐 7 个真实依赖闭包回归测试，不能把失败改成跳过。

本批未修改源码；生命周期审计仍全绿，演示产物为编译器 `1.2.0`。
