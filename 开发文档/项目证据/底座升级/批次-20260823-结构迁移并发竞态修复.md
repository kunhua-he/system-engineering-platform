# 批次：结构迁移并发竞态修复

## 流程图

```text
发布门禁真实失败
  -> 并发结构迁移复现
  -> 定位 SQLite DDL 中间 schema 竞态
  -> 迁移初始化对可恢复 schema 错误有界重试
  -> 单测 + 40 轮并发回归
  -> 发布门禁全量验证
```

## 失败证据

正式发布门禁首次运行失败：

```text
test_多进程同时首次初始化 / test_多进程同时升级同一旧库
RuntimeError: 结构迁移失败 1.1.0→1.2.0: no such table: 锁
```

根因是历史迁移步骤在 `BEGIN IMMEDIATE` 内使用 `sqlite3.executescript`。该 API
可能隐式提交事务，使多个进程在锁表重建期间交错执行，暴露中间 schema。

## 代码落点

- `运行核心/权威状态.py::_初始化`：对 `no such table`、`database is locked` 和
  `database table is locked` 做最多 4 次、递增等待的重试。
- 其它迁移错误仍立即抛出；不吞掉数据损坏、约束错误或未知异常。

## 验证

- 结构迁移定向测试：6/6 通过。
- 结构迁移测试连续 40 轮通过。
- `python3.14 -m py_compile 运行核心/权威状态.py`：退出码 0。
- `git diff --check`：退出码 0。
- 正式发布门禁：退出码 0，172 个测试通过，发布状态“通过”。

## 剩余风险

本批保留历史迁移脚本结构，仅对可恢复竞态增加有界重试；后续若新增 DDL 迁移，
应优先改为单条 `execute` 并保持事务内执行，避免继续依赖 `executescript` 的隐式
提交行为。
