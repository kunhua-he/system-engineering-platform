# 批次 11：正式索引依赖闭包修复

## 流程图

```text
正式包声明
   |
   v
唯一正式包索引
   |-- 正式支持库/模块库发现（排除 _模板 与非生产包）
   |-- 公开能力 owner（不含适配层 Provider）
   |-- 内部依赖能力 owner（仅依赖闭包使用）
   v
快速编译 / 独立项目编译
   |-- 模板显式引用阻断
   |-- Provider 依赖闭包展开
   v
依赖锁与独立制品
```

## 落点

- `开发工具/项目编译/正式包索引.py` 是正式包发现、公开 owner、内部 Provider 能力 owner 和依赖闭包的唯一实现。
- `开发工具/快速编译/运行快速编译.py` 只做包契约检查并调用索引；工作区不再扫描 `模块库/_模板`，并执行同一依赖闭包校验。
- `开发工具/项目编译/项目编译器.py` 只通过索引解析 owner/闭包；旧私有函数保留为单一实现的转发入口，不再复制 DFS 逻辑。
- 适配层 Provider 能力只写入 `依赖能力所有者`，不会进入公开能力 owner、能力搜索或公开冲突表。
- `模块库._模板` 及其能力不会进入索引、owner、依赖锁或制品；显式引用 fail-closed。
