# 批次 11：正式包索引与演示制品收口

## 流程图

```text
批次10架构审计
  -> 模板越界 / 制品版本漂移 / 编译入口重复解析
  -> 唯一正式包索引
  -> 两个编译入口接入同一索引
  -> 模板显式引用反向阻断
  -> 演示产物用当前编译器重编
  -> 定向验证 + 发布门禁
```

## 代码落点

- `开发工具/项目编译/正式包索引.py`：唯一负责正式支持库/模块库发现、非生产包排除、能力 owner、冲突和显式引用阻断。
- `开发工具/快速编译/运行快速编译.py`：只调用正式包索引，不再自行扫描包 owner。
- `开发工具/项目编译/项目编译器.py`：只调用正式包索引，模板和非生产包不会进入依赖闭包或制品。
- `示例项目/可双击演示/产物文件夹/20260822-demo/`：删除旧 1.1.0 产物并使用当前 `1.2.0` 编译器重新生成。

## 验证

- 项目编译器反向测试：6/6 通过。
- 快速编译工作区：退出码 0，52 个正式结果，无 `_模板`。
- 页面/项目编译定向测试：12/12 通过。
- 演示制品清单：`编译器版本=1.2.0`，无 `模块库._模板`。
- 正式发布门禁：退出码 0，172 个测试通过，发布状态“通过”。
- 未使用 V3 MCP，未占用 4780。

## 剩余风险

快速编译和独立项目编译仍是两个用户动作，但包发现、能力 owner 和正式包边界已经只有一个机器事实源；后续若新增包类型，必须扩展正式包索引，不得在入口内重新实现扫描逻辑。
