## 仍然存在的问题

### P1：公开能力搜索绕过正式包索引，仍暴露模板能力

证据：

- `MCP工具箱/公开能力.py:180-194` 的 `_全部能力` 直接对 `支持库` 和 `模块库` 执行 `rglob("包声明.json")`，没有调用 `开发工具/项目编译/正式包索引.py`。
- 复现：

  ```bash
  python3.14 - <<'PY'
  from pathlib import Path
  from MCP工具箱.公开能力 import 搜索公开能力
  结果 = 搜索公开能力(Path('.'), '模板', 1000)
  print([(项['包id'], 项['能力id']) for 项 in 结果 if '模板' in str(项)])
  PY
  ```

  退出码 `0`，仍返回 `('模块库._模板', '_模板.示例能力')`。另一个命中是正常的“组件控件.绑定组件事件”，不是模板包。

影响：公开能力 API 会把非生产模板呈现给 IDE/Agent，调用方可见目录与编译/运行时索引不一致；若后续按搜索结果构造项目，会在编译阶段才失败。应改为正式索引的能力所有者/包表，保留排除原因用于显式错误，不让模板进入搜索结果。

### P1：轻代码页面模型能力目录绕过正式包索引，仍接受模板能力

证据：

- `开发工具/轻代码前端编辑器/页面模型.py:35-50` 的 `_读取能力目录` 对四个根目录递归读取全部 `包声明.json`，未排除 `_模板`。
- 复现：

  ```bash
  python3.14 - <<'PY'
  from 开发工具.轻代码前端编辑器.页面模型 import _读取能力目录
  print(sorted(x for x in _读取能力目录() if '模板' in x))
  PY
  ```

  退出码 `0`，输出包含 `_模板.示例能力`。

影响：页面校验器可能接受绑定模板能力的页面 JSON；独立编译器随后阻断，形成 IDE 预览/编译语义漂移。应改为调用正式包索引的能力表，并对被排除能力给出明确“非生产能力”错误。
