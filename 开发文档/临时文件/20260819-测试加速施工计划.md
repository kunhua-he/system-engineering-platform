| 场景 | 改造前 | 改造后 |

> **重要回退决策（审计后）**：文件级缓存"改小文件只重跑受影响文件"方案**已回退**。
> 原因：模块库/支持库测试依赖加载器装配的**整阶段环境**（能力调用器需装配后才能调用），
> 单文件子进程跑会破坏装配导致原本通过的测试假失败（实测 `测试_样板模块.py` 单文件跑 6 失败 2 错误，
> 整阶段跑通过，错误 E未装配）。文件级缓存的函数与测试**保留**（供单文件工作包模式使用），
> 但**不再接入阶段主流程**——稳定性优先，宁要可靠的整阶段跑，不要有假失败风险的"秒级"。
> 阶段缓存（全命中 0.25s）+ 阶段并行（全量 256s）是当前稳定基线。

修复项：两个已知基线失败（测试_协作状态 test_零残留、测试_能力搜索覆盖率 test_字段缺失）已随本计划修复 `5ff341a`。

## 第 2~4 层要点（第 1 层验证通过后启动）

### 第 2 层：阶段并行 + 全局并发预算
- 主进程唯一 ThreadPoolExecutor 扁平化（max_workers = os.cpu_count()），阶段与文件统一为叶子任务。
- 失败即终止（_终止进程组 + cancel 未启动任务）；断点写"阶段顺序表下标最小真实失败"；区分真实失败与被终止。
- 移除 32 上限（同步改 测试_零测试门禁.py:128 断言为 ≤ os.cpu_count()）。
- 阶段子进程 teardown（临时根/资源清单）；输出按序回放。
- 新增 `--并行阶段` 参数；`--继续` 沿用断点并行策略（保守先串行）。
- 慢速层表述修正：`--范围 慢速/全部` 均执行。

### 第 3 层：文件级缓存 + audit hook + git 指纹 + GC
- audit hook：装于每测试文件独立子进程；pyc 规范化回源 `.py`；TMPDIR 排除；fd 型 open 忽略；按路径去重；网络事件标弱依赖；stat 静态扫描标弱依赖；弱依赖 TTL ≤3600s；记录文件自身不触发审计。
- 依赖判据：测试前已存在 + 被读（或读事件排除 TMPDIR），替代有矛盾的"写后读回"。
- git 指纹：一次 `git ls-files -s -z` + `git status --porcelain -z` 建映射；干净文件取 hash 截断 16 位；untracked 必须参与目录摘要（防假绿）；路径统一仓库根相对。
- GC：按引用 + 按访问时间双策略，与文件级缓存同步落地。

### 第 4 层（评估后决定）
- 慢测试先行：依赖补充优化 5 耗时画像，无画像按文件大小兜底。
- watch：删除"预热 import 缓存"与"依赖图"；只做调度（检测变化→查文件级缓存依赖表→调度独立子进程）；双向 flock 互斥；有界队列；pid/空闲超时/信号停止。默认降级为可选项。

## 跨层守则
1. 每层改动最小化，只动本层必需；不做超出该层的重构。
2. 每层独立验收（定向测试 → 常规全量），有 bug 先回写主方案文档再修代码。
3. 环境敏感阶段（真实进程/网关/浏览器/发布门禁/慢速层）永不并行。
4. 缓存原子写是并行前提，第 1 层必须先完成。
5. 先全局并发池，再放开 32 上限（资源必须有界铁律）。
6. 假绿防线五层逐层落实，审计 hook 禁装常驻/主进程。
