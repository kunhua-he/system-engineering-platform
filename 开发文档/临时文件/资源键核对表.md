### "静态契约 71s → 20-30s" 预期校准

**结论：仅做文件级并行（8 个同键文件整文件串行）时，20-30s 预期不成立，需并行数 ≥16 且同键组内进一步拆分。**

估算（参考 20260819-测试加速方案.md:20 静态契约 71s / 624 测试）：

- 串行基线 71s。若并行数 8（补优化1 复用工作包机制）：39 可并行文件 ≈ 5 批，取单文件最慢（FFmpeg 视频生成 / Pillow 43 测试 / PDF 渲染系，实测级约 3~8s）→ 并行批耗时 ≈ 5×8 ≈ 40s；8 个同键文件串行 ≈ soffice 5×(1~3s) + psycopg 3×(无服务时 5s 超时≈5s) ≈ 20~30s → **总 ≈ 60~70s，几乎不降**。
- 并行数 16：可并行批 ≈ 3×8 ≈ 24s + 同键串行 20~30s ≈ **45~55s**。
- 达到 20-30s 的必要条件：
  1. **同键组内按测试拆分**：soffice 键只串行受影响的 1~2 个测试（其余 pptx/docx/xlsx 纯 Python 测试并入并行池）→ soffice 键压缩到 ≈2s；psycopg 键只在有驱动+有服务时触碰端口（无服务时 5s 超时一次即可复用/skip 语义）→ 5432 键压缩到 ≈5s。
  2. 并行数 ≥16（方案默认 os.cpu_count() 全核，M3 满足）。
  3. 慢文件（FFmpeg/Pillow/PDF 系）不互相同批，性能敏感键文件优先调度。
- 项目装配 71s / 93 测试：7 文件全可并行 → 最长单文件（示例项目 2 测试各跑一次完整装配 ≈ 数秒 / 第十一阶段 10 进程栅栏 ≈ 4s 等待）→ **20-30s 预期成立**（≈ 最长文件耗时 + 启动开销）。

## 五、结论段

1. **必须串行（无）**：三阶段均未发现必须整体串行的文件；真实进程阶段仅 2 个测试类必须同键串行。
2. **可并行（39 静态契约文件 + 7 项目装配文件 + 50 真实进程测试）**：纯计算/只读契约/独立临时目录（mkdtemp/TMPDIR）/独立子进程（强杀目标=自身创建）全部可并行，可复用 `运行测试.py` 的工作包并行机制（独立进程 + 独立 TMPDIR + 进程组隔离 + teardown）。
3. **同键分组串行**：
   - 静态契约：**soffice 键** 5 文件（演示文稿/文字文档/文档转换/系统探针/表格文档）组内串行、组间可与其并行；**5432 端口/测试数据库键** 3 文件（psycopg2/pg8000/psycopg）组内串行。若按测试粒度拆分（推荐），每组只有 1~2 个真实触碰资源键的测试，其余可并入并行池。
   - 真实进程：第六阶段 Test真实子进程 7 测试（共享 cls.进程 有顺序依赖+超时断言）串行；Test密钥引用 4 测试（os.environ 共享键）串行。
4. **附加约束**：
   - 性能敏感键（0.5s/0.2s 超时断言、timeout=60 夹具、5s 真实连接超时、超时强杀）：已并入串行组的除外，建议不与其他重 CPU 文件同批。
   - 示例项目 2 测试**禁止测试级并行**（共享写 工程缓存 固定文件），仅允许文件级并行。
   - 第十一阶段写工作树 `运行核心/_违规样例.py`：文件级独立进程下风险最低，测试级并行须避免。
   - 第六阶段 Test发布门禁（执行门禁 真实进程=True）：并行前需确认门禁不写发布账本/激活指针；若写则归串行。

## 六、剩余风险

1. psycopg×3 在"驱动已装 + 本机有 postgres 服务"环境下，test_真实连接查询事务 会真实并发连 127.0.0.1:5432/postgres（只读 SELECT 1，默认连接数上限内安全）；无服务时 5s×3 超时等待是耗时主源，建议缓存/复用失败语义。
2. soffice 是否真为"单实例"取决于本机 LibreOffice 配置目录锁行为；实测确认前按任务信给定前提（单实例）保守分组。
3. 静态契约与项目装配的测试数（624/93）为方案口径，本表按 `def test_` 计数约 626/94，差异来自口径（方案可能排除/包含某文件），不影响并行结论。
4. 第五阶段 Test提供者隔离 的 `wait(timeout=3)` 与第六阶段子进程 wait 为终止等待语义，非 CPU 竞争敏感，已判可并行；若实测偶发超时需复核。
