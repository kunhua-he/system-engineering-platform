## 主方案：非环境敏感阶段并行（按 CPU 核数）

8 个非环境敏感阶段（静态契约/组件合规/结构迁移/权威状态/资源并发/平台控制面/反向破坏/项目装配）同时并行执行——并行数 = `os.cpu_count()` 全部核心（如 Mac Studio M3 96G，有多少核用多少核，不设 8 上限），保留手动 `--并行数` 覆盖；环境敏感阶段（真实进程/网关/浏览器/发布门禁/慢速层）保持串行——涉及固定端口、强杀目标、发布指针、真实强杀语义，并行会破坏稳定性。慢速层不参与常规范围，仅在 `--范围 慢速/全部` 时按原逻辑执行。

> **阶段×资源键核对表（并行准入）**：8 个非敏感阶段"非环境敏感"≠"资源独立"，实现时须为每个阶段逐项核对资源键（纯计算/只读/独立临时目录/共享目录/外部程序/固定端口/发布指针），输出"该阶段纯计算/只读/独立临时目录"的结论写进实现说明，粒度对齐 AGENTS.md"并行按资源键判定"；核对未通过不并行。

## 必备配套：缓存原子写

`工程缓存/验证缓存.json` 是整体覆盖写，并行时多进程互相覆盖（实测并行后缓存只剩 5 个阶段——机制：8 个并行进程各以 `--阶段 X` 跑完整主函数，各自"读旧缓存 → 写回整个 dict"无锁覆盖，最后写者赢，丢失其他进程写入，若并行前缓存恰有 4 个旧阶段则 8 进程各写回 5 项、最终只剩 5 项）。改为每阶段独立文件 `工程缓存/验证缓存/{阶段名}.json` + 写临时文件后 `os.replace`，天然无并发冲突；**读取端同步改造**：`读取缓存` 与 `计算断点续跑阶段` 改为聚合读取 `工程缓存/验证缓存/*.json` 合并为 dict，否则写入端分文件后读取端仍是单文件、缓存形同虚设。

> **缓存模型关系（两阶段演进）**：阶段级独立文件（本步骤）是"并行防覆盖"的**中间态**；补充优化 3 的文件级缓存（每测试文件一个 json）是**最终形态**，落地后**取代**阶段级缓存，阶段命中逻辑不再用"整阶段一条"的缓存，而是聚合其下全部测试文件缓存。两者是演进关系不是共存关系，落地顺序：先阶段级（最小改动解锁并行）→ 再文件级（最终形态）。
>
> **缓存结构版本**：文件级缓存落地时须 bump `缓存结构版本`（现 2.0.0，运行测试.py:53），损坏/缺字段自动失效机制复用现有逻辑。**文件级缓存落地后不得再读旧阶段缓存路径**（旧 验证缓存.json / 验证缓存/{阶段名}.json 应清理），否则旧阶段缓存与文件级缓存并存产生两套失效路径。

## 补充优化 2：真实进程低风险部分并行

真实进程 174~185s（全量 344s 中占比；另有单独高负载环境实测上限 286s，两者不同测量口径）是最大瓶颈。不全部并行，只把"纯独立子进程 + 独立临时目录、无固定端口、无共享强杀目标、无单实例外部程序"的测试挑出来并行（÷CPU 核数预计这部分约 200s 级上下降到 ~30s 级），其余串行。逐测试核对资源键（含外网访问 → 串行或禁止），核对通过才并行。

### 机制

```
① 每测试文件一个独立缓存 json（内容寻址，O(1) 查找）：
   工程缓存/验证缓存/文件/{测试文件路径哈希}.json
   内容 = 测试数 + 耗时 + 实测依赖文件清单及摘要 + 成功标志

② 依赖用运行时实测（标准库 sys.addaudithook 观测），不靠静态分析猜：
   测试真实执行时打开/读取/扫描过哪些文件、目录
   （os.listdir/os.scandir 事件同样记录）→ 全部记入缓存
   （静态 import 分析只作补充，观测不到的动态导入不猜，标记保守）

   ⚠ 依赖判据（修正）：只把"测试开始前已存在 + 本次运行被读"的文件计入依赖；
   测试自身在临时目录（TMPDIR/mkdtemp/工程缓存/验证运行）内创建的产物不计入
   （内容变化是测试自身行为，不触发失效）；读事件路径排除临时根。
   写入产物不计入依赖，避免自引用假失效。
   审计的 open 事件把 `__pycache__/X.cpython-*.pyc` 规范化为源 `X.py`
   （去 __pycache__ 段、去 .cpython-* 后缀、.pyc→.py），依赖清单恒存 .py，
   否则 pyc 新鲜时只 open .pyc、改源码不失效 → 假绿。
   fd 型 open 事件（path 为 int，subprocess 管道产生）一律忽略。
   网络事件（socket.connect 等）记录并标记弱依赖。
   os.stat/os.path.exists 等存在性探测不触发 audit 事件 → 静态扫描测试源码
   命中 `exists()/is_file()/getsize()` 即标记弱依赖。

③ 命中判定 = 测试文件摘要 + 实测依赖文件摘要表 + 引擎摘要 + 环境摘要
   全部一致才命中，任何一项不符即失效重跑

④ 改 1 个文件 → 查各缓存里的依赖清单 → 只有"实测读过该文件"的测试失效
   （通常 3~10 个），其余 600+ 全命中

⑤ 失效的测试文件并行跑（按 CPU 核数）→ 每个 1~5s → 总耗时 5~10 秒

⑥ 首次运行无依赖记录（缓存不存在）→ 该文件必须全量真实执行一次，
   记录依赖后才可被后续命中；"首次全量之后才生效"

⑦ 审计记录必须有界：每个 open/listdir 事件都入记录，量大会撑爆内存与磁盘；
   记录文件设大小上限（如 200KB/文件 ≈ 1300~2000 条事件），超出截断并标记
   该文件"弱依赖"；**上限按"去重后的不同文件数"计**——同一文件多次 open 只记
   一次（import 平台代码会 open 数百文件，不按路径去重则常规测试全落入弱依赖）。
   审计 hook 内只追加内存列表，记录文件写入放在测试结束（避免记录动作自身
   触发 open 事件递归污染）。遵守项目"资源必须有界"铁律。
```

> 弱依赖有效期（TTL）：弱依赖测试缓存有效期 ≤3600 秒，与现有 7 天 `运行证据有效秒` 区分；
> 子进程审计未实现前，真实进程阶段**不进文件级缓存**（沿用环境敏感短效缓存），避免 7 天命中假绿。

> 子进程观测边界：audit hook 只观测本进程文件事件，子进程内读的文件父进程观测不到。
> 因此凡"启动子进程型"测试（真实进程阶段 57 个测试基本全是）都会落入弱依赖兜底
> → 缓存有效期大幅缩短，改动时可能仍整阶段重跑。处理：优先给子进程注入审计并回传
> 记录（子进程启动时带 `--记录文件访问` 写共享记录文件）；未实现前，真实进程阶段维持
> 环境敏感短效缓存，预期表按此口径，不把 5~10 秒推广到真实进程阶段。

### 假绿防线（层层兜底）

诚实结论：**数学上不存在"100% 不假绿"的缓存**——唯一绝对的是每次全量重跑。但可以把假绿概率压到"工程上不可达"，靠五层防线：

1. **依赖是实测记录，不是猜测**：测试运行期真正打开/读取/扫描过的文件、目录被审计记录；没读过的文件改了不会导致误失效，也不会误命中。依赖判据 = 测试前已存在 + 被读，临时根产物排除；pyc 规范化回源 `.py`（见机制②），避免假失效与假绿双向缺陷。
2. **文件级内容摘要双向钉死**：依赖文件内容变了必失效、没变必命中，无模糊地带
3. **观测不到的极端情况保守兜底**：C 扩展读文件（import 含 C 扩展库 → 弱依赖）、子进程内再读文件（子进程审计未实现前 → 弱依赖）、网络资源（socket.connect 事件 → 弱依赖）、stat 存在性探测（静态扫描源码 → 弱依赖）等审计覆盖不到/探测不到的行为 → 该测试标记"弱依赖"，缓存有效期 ≤3600 秒 + 强制环境摘要，**宁多跑、不错过**
4. **测试文件自身 + 验证引擎 + Python 版本/依赖锁/外部程序**摘要，任何变化全部失效。外部程序清单须覆盖实测引用（git/sqlite3/ps/soffice/tesseract/textutil/ffmpeg/ffprobe/docker/lsof/security/sw_vers，按 shutil.which + audit Popen 事件收集；psql 保留但优先级靠后）；**非环境敏感阶段同样校验环境摘要**（现仅环境敏感阶段检查，需放开），否则外部程序升级后静态契约等阶段仍命中旧缓存 → 假绿。
5. **门禁语义不变**：零测试、导入失败、未解释跳过、缓存假绿检测仍全部失败；发布只有通过/阻断

## 补充优化 4：并行数自适应 CPU 核数（已并入主方案）

并行数默认 = `os.cpu_count()` 全部核心（Mac Studio M3 96G 有多少核用多少核），保留手动 `--并行数` 覆盖；所有并行点（阶段并行 / 文件级并行 / 真实进程部分并行 / 慢测试先行调度）统一按此分配，不设 8 上限。

> **全局并发预算（防止嵌套并行失控）**：阶段并行（8 阶段）× 阶段内文件并行（补充优化 1）× 真实进程部分并行（补充优化 2）不得各自独立计算并行数，否则 8 × N 进程爆炸、反向冲垮机器。**实现形态（推荐）**：主进程唯一全局 `ThreadPoolExecutor`，阶段与文件统一为**扁平叶子任务**提交（任务携带阶段标签），`max_workers = 全局预算`，预算即并发硬上限、8×N 结构上不可能；慢测试先行调度即在池内按耗时降序提交。**"总并发"指同时运行的子进程数峰值 ≤ 全局预算**，非累计启动数。多阶段同时到达时排队等待而非全部启动。

> **与现有代码冲突（实现时必修）**：现有 `计算并行数` 硬上限 `min(32, os.cpu_count())`（运行测试.py:268）。改为 `上限 = os.cpu_count()`（保留"并发有界"语义、取消 32 魔数；**先落全局并发池，再放开上限**，否则违反"资源必须有界"铁律）。M3 Ultra 32 核下两者等价，改动风险低。需同步修改 测试_零测试门禁.py:128 断言 `assertLessEqual(计算并行数(100,0), 32)` 为 `≤ os.cpu_count()`。
>
> **能效核策略**：默认 `os.cpu_count()` 全部逻辑核（含能效核）；排除能效核仅作可选开关且默认关闭——超时类测试已串行化，能效核慢不影响正确性，且排除反而降低并行度（32→24）。

## 工程化补充：与文件级缓存叠加的四个方向

### 1. git 指纹复用（省掉全仓哈希开销）

现在每次跑测试，判定缓存命中前要把所有相关文件读一遍算 sha256——即使全部命中，光哈希就要花时间。实现：一次 `git ls-files -s -z` 建全部已跟踪文件 index blob hash 映射 + 一次 `git status --porcelain -z` 取 dirty/untracked 清单（**不逐文件 subprocess rev-parse**）；干净文件（在 ls-files 且不在 status）直接取映射值免读盘，dirty/untracked 现场 sha256 兜底（`:路径` 对 dirty 取到旧 index 版本、对 untracked 报错，两者都会缓存误判）。

> 必须保留的假绿链路：目录摘要继续 `rglob` 枚举，**untracked 新文件必须参与摘要**（现场哈希），否则新增源码文件不被感知 → 目录摘要不变 → 缓存误命中假绿。路径统一换算仓库根相对（`cwd=系统根`，不依赖 cwd）；指纹算法统一截断 16 位（git hash 是 SHA-1 40 位，与 sha256 混用会致键抖动，只致失效不致假绿）。

### 2. 常驻守护进程 + watch 模式（秒级反馈，降级为可选）

**修正（审计后）**：删除"预热解释器 + import 缓存 + 依赖图"——import 平台代码实测仅 ~0.1s，不是冷启动瓶颈；且"预热 import 缓存"固化旧代码 → 基于旧代码出证据 = 假绿（项目已有 8766 旧网关静默服务旧行为的前车之鉴），audit hook 也禁装常驻进程。watch 只做**调度层**：检测文件变化 → 查文件级缓存实测依赖表 → 调度独立子进程（复用 `--内部测试文件` + TMPDIR 注入），自身零代码状态、不跑测试、不装 hook、不建静态依赖图（依赖判定唯一来源 = 文件级缓存实测记录）。**降级为步骤 5（文件级缓存）稳定后评估的可选项**——先修 `运行环境摘要` rglob 全仓扫描（收窄定点 glob，"代码没动"1.36s → ~0.4s，性价比最高且无需新机制）。

> 约束：① **双向 flock 文件锁互斥**（工程缓存/watch.lock；`运行测试.py` 手动全量入口必须检查同一把锁——现状无任何全量互斥，需同步加），违反 AGENTS.md"已有全量运行时禁止重复启动"会双进程抢端口/数据库；② 文件连续变化需防抖 + 排队，队列必须有界（如 64 条，超限合并为"待全量"）；③ 守护进程生命周期有界：pid 文件（原子写+退出清理）+ 空闲超时自动退出 + SIGTERM/SIGINT 优雅停止 + 停止子命令；④ 标准库轮询（快照 stat mtime_ns+size，间隔 0.3~0.5s），**严禁每轮 rglob**；启动建一次文件快照清单，新增文件靠目录 mtime 检测重建。

### 3. 慢测试先行调度（墙钟再压缩）

并行时慢的测试先启动、快的填缝（类似 make -j 调度器）：按实测耗时排序，最慢的先占满核，墙钟逼近理论最优。

### 4. 共享内容寻址缓存（ccache 式）

验证结果按"测试文件 + 依赖指纹"内容寻址存储，任何分支、任何缓存目录 O(1) 复用同一份证据——不删缓存、不互相覆盖、换分支不失效。

> 缓存回收（GC）：内容寻址缓存只增不删，测试文件改名/删除/重构后旧缓存成孤儿永久占盘。需定期清理：按访问时间淘汰（如 30 天未命中删除），或按引用关系删除已不存在的测试文件对应缓存，遵守"资源必须有界"铁律。

## 失败与断点语义（并行后的门禁规则）

1. **并行阶段失败**：非敏感 8 阶段并行中任一阶段失败 → 立即终止其余仍在运行的并行阶段（终止进程组 + cancel 未启动任务），不再执行后续环境敏感阶段，整体返回非零。**前提：失败/被终止阶段不写成功缓存**（现状满足，仅 `wasSuccessful()` 才写）——这是 `--继续` 向前回退精确性的基石。
2. **多阶段同时失败**：终止后收集全部已失败的并行阶段（含终止前已完成并失败的部分；**被终止阶段退出码非零但属信号杀死，不计入"失败阶段"**），断点记录**第一个失败阶段 = 阶段顺序表中下标最小的真实失败阶段**；`--继续` 续跑时按"第一个失败阶段及之后"回退（其余在断点前完成且证据有效的并行阶段可复用，断点结构需扩展记录"已完成阶段"）。断点写入用**首个失败者仲裁**（失败时间戳比对/首个写者锁），避免后写覆盖先写。
3. **`--阶段` 波次语义不变**：`--阶段` 用于合并波次，保持固定顺序串行（AGENTS.md 要求）；全量验收（常规/全部）默认 8 阶段并行。如需对指定阶段并行，新增显式开关 `--并行阶段`（仅限非敏感阶段；与 `--继续`/`--测试文件` 互斥；`--范围 慢速` 不可用），不改变现有 `--阶段` 语义。`--并行数` 从工作包专用扩展为全局并行规模，与 `--阶段`（波次串行）组合时忽略并行数。
4. **`--继续` 并行策略**：沿用断点记录时的并行策略（保守实现可先串行）。阶段子进程化须配套临时根/资源清单/teardown（参照工作包模式 `_运行单文件子进程`），并行阶段输出每阶段独立文件、结束按序回放。
5. 门禁语义不变：任一失败、零测试、导入失败、未解释跳过、缓存摘要/结构校验均返回非零。

## 验证分级与并行共存

- **工作包**（`--测试文件`）：现有多文件并行，不受影响。
- **合并波次**（`--阶段`）：保持固定顺序串行，不受影响（AGENTS.md 要求）。
- **阶段收口**（常规全量）：8 非敏感阶段并行 + 环境敏感阶段串行。
- **正式发布**（`--范围 全部` + 发布门禁）：常规部分可并行；**发布门禁与慢速层必须串行真实执行**（发布门禁内部调用 `运行测试.py` 已显式传 `--并行数 1`，不依赖"默认并行"行为漂移），发布判定不受并行调度影响。
- `--范围 慢速/全部` 均执行慢速层（`--范围 全部` = 常规 + 慢速层）；慢速层环境敏感（强杀/压力），在常规完成后串行执行，不参与并行。

## 落地步骤

> 中间态说明：步骤 1~4 基于阶段级缓存（中间态，解锁并行）；步骤 5 落地文件级缓存后**取代**阶段级缓存，步骤 1~4 的中间态机制由文件级缓存承接（详见"缓存模型关系"）。每步验收均以前一步为基础。

1. 缓存原子写：验证缓存.json → 验证缓存/{阶段名}.json；验收：并行后缓存 8 项齐全不覆盖。
2. 阶段并行：运行测试.py 并行执行 8 非敏感阶段；验收：77s、退出码 0、结果与串行一致。
3. 静态契约内部并行：按文件并行 624 测试；验收：结果与串行一致。
4. 真实进程部分并行：核对资源键后并行安全子集；验收：与串行完全一致。
5. 文件级缓存 + 实测依赖记录：**已回退执行接入（装配约束）**，函数库保留作单文件工作包工具；验收改为：阶段缓存 + 阶段并行稳定全绿。
6. 工程化补充四项（git 指纹 / watch 守护 / 慢测试先行 / 内容寻址缓存）：在 1~5 稳定后逐步叠加，每项独立验收。
7. 回归：全量 1091 测试通过，门禁语义不变（任一失败即非零退出码）。

## 预期效果

| 场景 | 现状 | 改造后 |
|---|---|---|
| 缓存全失效（大改动） | 344s | 253~275s |
| 改一个支持库文件 | 320s | 受影响阶段重跑（静态依赖增强精确失效，非秒级） |
| 代码没动 | 1.36s | 0.25s |

> 构成说明：`253~275s` = 阶段并行（非敏感 8 阶段并行）+ 环境敏感串行（真实进程 57 测试为大头）+ 慢速层（`--范围 全部` 时）。文件级缓存回退后，**"改小文件秒级"不成立**——改为"受影响阶段精确失效重跑"，稳定性优先。

## 风险与保障

1. 并行只限非环境敏感阶段 + 核对过的真实进程测试；端口/强杀/发布指针相关永不并行。
2. **全局并发预算**：阶段间/阶段内/真实进程并行共享一个并发池，总进程数 ≤ 性能核数，嵌套并行不得各自放大（防止进程爆炸冲垮机器）。
3. 缓存原子写保证并发安全；损坏缓存自动失效重跑（现有机制）。
4. **写入产物不计入依赖**，避免测试自引用假失效。
5. **真实进程依赖的文件改动**：子进程审计未实现前，该阶段仍可能整阶段重跑（~180s），预期表已按此口径标注。
6. 全量门禁语义不变：全部测试成功才返回 0；失败立即终止并行阶段、断点可续跑。
7. 每步独立验收通过后才进下一步，不一步到位。
