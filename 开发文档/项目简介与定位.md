# 系统工程平台 · 项目简介与定位

> 文档性质：正式项目简介（描述平台是什么、解决什么问题、架构哲学与未来方向）。
> 唯一事实源：`开发文档/唯一权威事实.md`；本简介与其一致。

## 一、一句话定位

系统工程平台是一个**与任何业务项目完全平级、完全独立的系统级工程底座**：
把可复用的能力原子化、服务化，交给上层业务项目经统一入口调用；平台自身负责
能力的装载、调度、资源、调用、治理与证据闭环，并强制第三方边界隔离。

只依赖 Python 标准库。

## 二、它解决什么问题

业务项目往往各自重复实现文件处理、文档转换、媒体处理、数据库访问、外部
程序调用等通用能力，导致重复造轮子、实现漂移、第三方依赖失控、无法统一
验证与审计。平台把这些能力收拢为**受管的能力体系**：

- **能力有单一权威**：每个能力在能力注册表登记，调用必须经过唯一能力调用器，
  全链路留证据（请求 id、版本、包、提供者、结果、资源释放结论）。
- **第三方被强制隔离**：任何第三方库、动态库、外部程序、数据库、DLL 都必须
  封装在支持库适配层的受管提供者内，主进程不直接导入不可控全局状态。
- **可装配可回滚**：依赖拓扑、版本锁、能力锁、提供者锁在装配前完成，
  失败零半装配；回滚只切换不可变旧制品与激活指针，不恢复源码。
- **验证可信**：唯一验收入口 + 发布门禁 + 证据账本，零假绿、零测试成功、
  资源必须有界，全部可核查。

## 三、架构哲学

```text
正式代码
  → 项目适配层、统一网关或统一能力服务
  → 模块公开能力（模块只保存能力 id/契约版本，不静态导入支持库/提供者）
  → 运行核心注入的唯一能力调用器 → 能力注册表解析支持库能力
  → 锁定提供者与受管执行单元
  → 数据库、服务器、DLL、操作系统、第三方库或外部协议
```

分层职责固定：

| 层 | 职责 |
|---|---|
| 公共契约 | 包声明、能力契约、基础类型、错误结构、生命周期、版本规则 |
| 支持库 | 原子能力、参数/返回/错误转换、资源释放；第三方边界在适配层 |
| 模块库 | 只组合公开能力完成流程，不直接连接第三方 |
| 项目适配层 | 绑定版本/配置/权限/路径/密钥引用与项目别名，不碰实现 |
| 运行核心 | 装载、调度、资源、调用、运行治理；唯一注册表/路由/调用证据链 |
| 平台控制面 | 需求登记、能力目录、包仓库、策略中心、发布管理、证据账本（唯一写权威） |
| 启动监督器 | 核心启动、资源限制、健康检查、版本切换与核心回退 |

统一公开结果固定包含：**成功、值、错误码、错误说明**。底层异常不得直接
泄漏到正式代码。

能力经统一能力入口调用、能力搜索器检索、说明书生成器产出使用说明、
契约编译器与组件合规校验契约一致性、发布门禁做正式发布唯一判定。

## 五、质量基线（已固化）

- **唯一验收入口**：`python3.14 测试中心/运行测试.py`；零测试、导入失败、
  未解释跳过、缓存假绿均判失败；发布只有"通过/阻断"。
- **发布门禁**：`python3.14 开发工具/发布门禁/运行发布门禁.py` 为正式发布唯一判定。
- **证据闭环**：MCP 使用反馈 → 成功验证 → 证据入账 → 收口登记，交付链完整才可验收。
- **测试加速**：阶段并行 + 阶段缓存原子写 + 静态依赖增强；全量 1093 测试全绿，
  代码未变全缓存命中约 0.25s。
- **并发有界**：全量验证持有 flock 互斥锁，禁止重复启动；环境敏感阶段缓存
  有效期 1 天；端口/强杀/发布指针相关永不并行。

## 六、对外开发接入

平台面向**开发**（Agent 开发业务项目、开发者写业务代码）。核心是 **HTTP 能力网关**，
MCP 只是网关上一层的可选适配。

```text
         HTTP 能力网关（核心底座）
  搜索能力   查看契约   执行能力
    │          │          │
    ▼          ▼          ▼
  调用方：Agent · 业务程序 · 任何语言
```

网关之上三种用法：

```text
      HTTP 网关
      ┌─┬─┬─┐
      ▼ ▼ ▼
  MCP 适配  本地同级  直接 HTTP
  （可选）  （复制本地）  （curl/任意语言）
```

网关提供纯 HTTP 接口（`GET /能力/搜索` 搜索、`GET /能力/契约/{能力id}` 查看契约、
`POST /能力/执行` 执行，全中文路由），执行返回统一结果（成功/值/错误码/错误说明）+
完整证据链。任何语言可直接调用，不依赖 MCP 协议。MCP 只是把网关包装成 Agent 工具的
可选适配层，无 Agent 场景可不用。本地同级指支持库/模块库复制到本地直接导入中文函数
调用，不依赖网关服务（用本地绝对路径，不绕 HTTP）。本地/云端只是部署形态差异，调用语义一致。

## 七、未来方向

方向按稳定性优先排序（先保正确与可信，再求能力与性能）：

1. **能力服务化与多项目接入**：支持库/模块库可直接下载复用（类似 GitHub
   复制本地），网关只负责"调用哪个模块"；用户可经网关用本机资源或复制到本地。
2. **受管提供者与第三方边界**：持续把不可控第三方/动态库/外部协议收拢进
   独立受管提供者，主进程保持纯净。
3. **验证可信度深化**：证据可信度由代码地图、当前 Git/工作区指纹与真实
   成功验证计算；随能力扩充持续加固假绿防线与资源有界。
4. **性能持续收敛**：阶段并行资源键调度、慢测试画像等已评估项，在稳定性
   保障前提下逐步落地。

## 八、不做清单

- 平台不承载任何业务项目代码、数据库、配置或运行数据。
- 不做函数/变量级缓存命中（动态语言静态分析不可靠，假绿风险）。
- 不做跨仓库 MCP/记忆/代码地图/验证证据复用。
- 不引入第三方 Python 依赖（一切第三方强制收进适配层提供者）。
