# 资源回收确认机制（唯一权威 · 2026-08-26 华哥口径）

> 华哥想法：句柄对应进程；进程暴毙时资源必须全部回收，不泄露。
> 核心链路：资源启动时登记 → 绑定句柄 → 句柄失效时核查资源是否已回收 → 没回收的补回收一趟。
> 本方案落盘为唯一权威，实施分批进行，出现的问题登记在第八节。

| # | 问题 | 位置 | 状态 |

## 二、方案：资源回收确认支持库（新增）

### 2.1 能力清单

| 能力id | 输入 | 输出 | 职责 |
|---|---|---|---|
| `资源回收确认.登记资源` | 句柄, 资源类型, PID, 端口, 资源路径, 清理函数名 | 登记id | 把资源绑定到句柄 |
| `资源回收确认.核查回收` | 句柄 | 回收清单 | 句柄失效时核查所有资源，未回收的补回收（幂等） |
| `资源回收确认.查询资源` | 句柄 | 资源清单 | 查看句柄绑定的资源（审计） |

### 2.2 资源类型

| 类型 | 检查方式 | 回收方式 |
|---|---|---|
| 进程 | PID 是否存活（os.kill(pid,0)） | killpg 杀进程组 |
| 端口 | lsof 是否监听 | 杀占用进程 / 等待释放 |
| SQLite连接 | 连接是否打开 | conn.close() |
| 临时文件 | 文件是否存在 | os.remove |

### 2.3 核查回收流程（幂等）

```text
核查回收(句柄)
  for 资源 in 句柄绑定资源表:
    存活 = 资源.检查()
    if 存活:
      资源.回收()          # 没回收的补回收一趟
      登记 已回收
    else:
      登记 已回收(本就无)  # 幂等：重复核查不报错
  返回 {回收清单, 已回收数, 未回收数}
```

## 三、实施批次

### 第一批：资源回收确认支持库（3 能力）
- 建 `支持库/后端/资源回收确认/`，三表（资源表/句柄绑定表/回收记录表）
- 登记资源：句柄 → 资源列表
- 核查回收：遍历资源，检查存活，未回收补回收

### 第二批：模型连接器接入
- `注册本地进程` 改为同时登记资源（PID/端口）
- `_终止本地进程` 改为调 `核查回收`
- 进程树回收：killpg（process_group）+ 端口清理

### 第三批：会话存储接入
- `释放句柄` 改为调 `核查回收`（关 SQLite 连接）
- `连接会话存储` 登记 SQLite 连接资源

### 第四批：统一接入 + 验证
- 超时回收 / 显式释放 / 进程暴毙 三条路径都走统一核查回收
- 验证：登记 → 释放 → 核查 → PID/端口/连接全回收

## 四、验收标准

1. 登记资源后，句柄绑定资源表有记录
2. 显式释放句柄 → 核查回收 → PID 已杀、端口已清、连接已关
3. 超时回收 → 同 2
4. 进程暴毙 → 句柄失效时核查回收补杀残留（幂等）
5. 重复核查回收不报错（幂等）

## 七、问题登记（实施中发现追加）

- Q1：`os.kill(pid,0)` 对 zombie 进程返回真（刚死的进程短暂视为存活）→ 修复：`_检查进程存活` 加 `ps -o state=` 排除 Z/X 状态（已修）
- Q2：shell 子进程（如 sleep）非进程组长，`killpg` 无效 → 设计边界：真实模型进程用独立进程组启动，`killpg` 杀整树；非组长降级单 kill（已处理）
- Q3：测试环境 zombie 无法被 waitpid 收割（父进程是 shell）→ 测试用真实模型进程验证即可（已记录）
