# jingyi-ec 架构建档

## 1. 项目定位

`jingyi-ec` 是精易科技公开的易语言通用模块源码仓库。核心交付物是一个易语言模块工程二进制文件 `精易模块v9.4.0[源码].e`，面向 Windows 易语言程序开发，封装大量文本、文件目录、网页/HTTP、窗口控件、进程线程、注册表、图片、编码、网络、压缩、COM、内存与汇编等常用能力。

仓库 README 的定位是“中文命令、统一格式、直接引用、快速开发”，并明确说明模块使用 Windows API 与易语言核心库、免费开源。源码内嵌模块注释进一步写明：`使用易语言核心支持库 + API完成`、`开源&永久免费`。这些是项目声明；下面的模块、调用链和依赖以当前 v9.4.0 工程文件中的可读元数据、命令备注、API 声明和仓库文件为证据。

本仓库不是一个 PHP/Python/Node 项目，也不是可在 macOS 上直接运行的服务。`.e` 文件以 `CNWTEPRG` 开头，是易语言工程/程序的二进制格式；当前仓库没有 `.ec` 工程文本、构建脚本、包管理文件或 CI 配置。源码文件不能按普通 UTF-8 文本逐行阅读，但其内部保存了 GB18030/GBK 可读的模块名、命令名、备注、类型名、API 名称和字符串常量，已对这些内容进行人工取证。

## 7. 主要数据流与调用链

### 7.1 HTTP/网页/DOM

```text
URL、请求头、Cookie、代理、请求体
  → 类_XMLHTTP / 网页_访问 / 网页_访问_对象
  → wininet.dll、urlmon.dll、shdocvw.dll、COM/OLE
  → HTTP 状态、响应头、响应字节集/文本/XML 对象
  → 类_DOM / 普通填表
  → 取元素、表单、文本框、按钮、链接、图片、DIV、SPAN、脚本与属性
```

源码中可直接取证的 `类_XMLHTTP` 方法包括“打开HTTP连接”“单独指定请求的http头”“获取响应的所有http头”“发送请求”“取消当前请求”“返回http状态码/状态文本”“将响应格式化为 Xml 文档对象”“返回服务器响应数据”“指定 readyState 改变时的子程序指针”。网页相关命令还覆盖标题、地址、源码、文本、Cookies、编码、文档大小、滚动条、表单和 DOM 元素操作。

Cookie 规则在 `bug和功能测试/网页_Cookie合并更新` 中明确：按前后顺序合并，后者覆盖前者；空值或 `deleted` 删除对应 Cookie。该文本是规则说明，是否与 v9.4.0 所有访问路径一致需以调用链进一步验证。

### 7.2 文件/目录/配置/注册表

```text
路径/文件名/属性/配置节
  → 文件/目录命令、类_内存配置项、注册表操作
  → kernel32/shlwapi/shell32/advapi32 API
  → 文本、字节集、时间、属性、句柄或逻辑结果
  → 可能产生文件系统、注册表或系统配置副作用
```

源码备注覆盖文件复制、移动、删除、重命名、枚举、时间、大小、是否目录、W 宽字符版本、目录监控队列，以及配置节/项目读写。`更新日志.txt` v9.4.0 还明确记录新增“目录_监控文件修改”“目录_监控文件修改W”“文件_枚举_队列”。

### 7.3 FTP/网络套接字

```text
服务器地址、端口、用户名、密码、被动模式、文件/目录
  → 类_FTP
  → wininet.dll FTP API；网络底层还声明 ws2_32.dll/iphlpapi.dll
```

`类_FTP` 相关备注包含连接状态、创建/删除目录、切换目录、删除/改名文件、上传、文件下载和进度下载。`bug和功能测试/FTP全功能测试.e` 内有 `FTP功能测试`、`FTP文件测试` 等窗口/过程字符串，并引入 `类_FTP`。

### 7.4 窗口/控件/输入

```text
目标窗口句柄或外部控件句柄
  → 窗口_*/外部树型框/外部超级列表框/菜单/键鼠命令
  → user32/comctl32/gdi32/atl 等 API
  → 控件文本、项目、选择状态、颜色、坐标、菜单、消息或回调
```

外部控件测试工程保存了“树形框句柄”“列表框句柄”“组合框句柄”、`树型框1`、`超级列表框1`、`组合框1`，并在 `_窗口1_创建完毕` 中初始化测试数据（根项目、子项目）。这证明测试工程至少覆盖外部控件句柄和项目操作路径；没有在当前 macOS 环境编译运行。

### 7.5 进程/线程/内存/HOOK/汇编

```text
进程ID/窗口句柄/地址/字节集/子程序指针
  → 进程、线程、内存、HOOK、InlineHook、汇编类
```

源码元数据明确出现 `ReadProcessMemory`、`WriteProcessMemory`、`VirtualAlloc`、`VirtualAllocEx`、`VirtualFree`、`VirtualFreeEx`、`CreateThread`、`TerminateThread`、`GetThreadContext`、`SetThreadContext`、`ZwWow64ReadVirtualMemory64`、`ZwWow64WriteVirtualMemory64`、`NtReadVirtualMemory` 等声明，并保存一组 x86 汇编指令包装命令（`MOV_*`、`PUSH_*`、`CALL_*`、`JMP_*`、比较/移位/循环等）。这属于强系统耦合能力，调用安全性、位数兼容性和释放责任不能在未运行验证前视为已保证。

### 7.6 图片/位图/GDI/GDI+

```text
文件/字节集/位图数据/图标句柄/像素坐标
  → 类_图片组操作类 / 类_位图操作 / 类_像素组 / 图片_* 命令

  → 位图结构、颜色表、像素、图标句柄、图片文件数据
```

源码中出现位图文件头、信息头、颜色表、扫描行对齐、像素读写、缩放、二值化、反色、轮廓、细化、分割、图像格式转换和照片拍摄日期等方法/结构体；测试目录提供 `1.bmp` 素材。

### 7.7 JSON/编码/校验/压缩

- `类_json` 提供解析、通用属性、属性值/数组等对象访问；`优秀小技巧分享.txt` 给出数字键 `"0001"` 通过 `JSON.取通用属性("['0001']", )` 访问的示例。
- 编码分组覆盖 ANSI、GB2312、UTF-8、Unicode、Big5、URL、JavaScript URL、USC2、Base64、十六进制和简繁转换。
- 校验/密码学元数据包括 MD2/MD4/MD5/SHA-256/SHA-512、HMAC、RC4、对称算法、CryptoAPI 相关命令；当前未运行验证安全语义或密码学正确性。
- RAR 命令备注声明依赖 `unrar.dll`，但仓库没有该 DLL；GZIP 方法 `网页_GZIP压缩`/`网页_GZIP解压` 声明依赖仓库内 `gzip.dll`，并要求 DLL 放在程序根目录。

## 8. 接口边界

### 8.1 易语言调用接口

主模块以易语言公开子程序、类、类成员、常量、自定义类型和回调为接口。代表性命令包括：

## 12. 风险与后续复核点

1. **二进制源码可读性风险**：`.e` 不是普通文本，当前建档依据工程内字符串和元数据；后续如需逐函数证明，应在 Windows 易语言环境打开工程并导出/截图或编译验证，不能只依赖字符串扫描。
2. **API/位数风险**：大量 `ntdll`、远程内存、汇编、HOOK、结构体和指针操作依赖 Windows 版本、进程位数、调用约定和对齐；必须分别验证 x86/x64。
3. **外部 DLL 风险**：RAR 明确依赖仓库不存在的 `unrar.dll`；GZIP 依赖 `gzip.dll` 且源码备注要求放在程序根目录，部署时必须核对导出函数和位数。
4. **IE/COM 风险**：`普通填表`、`类_DOM`、`类_XMLHTTP` 使用 IE/COM/OLE/ActiveX 相关组件；新 Windows 版本的 IE 状态、权限、区域设置和安全策略可能改变行为。
5. **资源释放风险**：源码备注多次要求释放内存、句柄、字节流、图片、线程和外部指针；静态存在不能证明所有异常路径均释放。
6. **网络行为风险**：HTTP、Cookie、代理、FTP、GZIP、外网 IP 等命令会产生外部网络副作用；本轮没有访问网络或执行测试。
7. **历史版本混淆风险**：`历史文件/` 内有大量 v5.7.1–v9.3.0 工程。更新日志可作演进线索，不能替代 v9.4.0 主工程证据。
8. **测试覆盖风险**：仓库提供的是手工/示例易语言工程，没有发现可在当前环境执行的自动化测试入口；测试工程存在不等于测试通过。
9. **浅克隆风险**：当前 Git 只有 1 个可见提交，无法完成完整历史演进、贡献者或回归定位。
