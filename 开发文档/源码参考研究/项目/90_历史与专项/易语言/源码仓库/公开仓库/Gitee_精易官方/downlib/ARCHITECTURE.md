# downlib 架构档案

## 1. 项目定位

`downlib` 是一个面向易语言支持库 ABI 的 C++/Visual Studio 工程，库名为“网络传送支持库”，版本元数据为 `3.1.0`，GUID 为 `80CF4A6B3E09425bA57935A3A0E4C473`。它向易语言 IDE/运行时登记下载、FTP 上传及 FTP 辅助命令和自定义数据类型。

重要边界：当前仓库是“支持库接口/元数据骨架”，不是完整的下载协议实现。`downlib_cmdDef.cpp` 中虽然登记了 HTTP、FTP、MMS、RTSP 等能力说明，但 66 个命令实现函数的函数体均未调用网络、文件或线程 API；非空内容仅是从 `pArgInf` 取出参数的局部变量。因此“支持哪些协议”是命令元数据中的产品说明，不能当作当前源码已经实现的运行能力。

## 2. 真实入口与总体流程

动态库入口是导出函数 `GetNewInf`，由 `Source_downlib.def` 导出；`DllMain` 只执行标准加载/卸载分支，不做初始化。易语言系统通过 `LIB_INFO` 获取命令表、命令函数指针表、自定义类型、常量表和通知函数。

```text
易语言 IDE / 运行时
        |
        | LoadLibrary(.fne/.dll) + GetNewInf()
        v
+----------------------------+
| downlib_dllMain.cpp        |
| GetNewInf -> LIB_INFO       |
| DllMain（空加载/卸载钩子）  |
+----------------------------+
        |
        +--> g_DataType...      5 个自定义数据类型
        +--> g_cmdInfo...       66 个命令元数据
        +--> g_cmdInfo..._fun   66 个命令函数指针
        +--> g_ConstInfo...     0 个预定义常量
        +--> ProcessNotify...  系统通知桥接
        v
+----------------------------+
| downlib_cmdDef.cpp         |
| downlib_<name>_<index>...  |
| 当前为参数读取骨架/空实现   |
+----------------------------+
        |
        v
易语言调用结果（当前实现未写入 pRetData，未执行网络/文件传送）

静态编译路径：
downlib_static.vcxproj
        | __E_STATIC_LIB
        v
复用同一组 cmdDef/fnshare 源文件
        | 通知返回命令函数名、通知函数名、依赖库名
        v
易语言静态编译器装配
```

## 4. 动态库与静态库工程边界

### 4.1 动态库

`downlib.vcxproj` 将 `elib/fnshare.cpp`、`downlib_cmdDef.cpp`、`downlib_const.cpp`、`downlib_dllMain.cpp`、`downlib_dtType.cpp`、`downlib_cmdInfo.cpp` 编译为 `DynamicLibrary`。工程列出 `Debug/Release × Win32/x64`，使用 `v141` 工具集和 Windows SDK `10.0.15063.0`。Win32 配置定义 `__E_FNENAME=downlib`，并通过 `Source_downlib.def` 输出 `GetNewInf`；Win32 的目标扩展显式为 `.fne`，x64 配置未显式设置该扩展。

动态模式下（未定义 `__E_STATIC_LIB`）：

- `include_downlib_header.h` 暴露常量、命令、函数指针、参数和数据类型全局数组；
- `downlib_cmdInfo.cpp` 生成命令/参数元数据；
- `downlib_dtType.cpp` 生成数据类型元数据；
- `downlib_dllMain.cpp` 生成 `LIB_INFO`、函数指针数组和 DLL 通知分支；
- `GetNewInf()` 返回静态 `LIB_INFO` 地址。

### 4.2 静态库

`downlib_static/downlib_static.vcxproj` 将同一批源码以 `StaticLibrary` 编译。Win32 Debug/Release 定义 `__E_STATIC_LIB; __E_FNENAME=downlib`；x64 配置只定义 `_DEBUG/_LIB` 或 `NDEBUG/_LIB`，未显式定义 `__E_FNENAME` 与 `__E_STATIC_LIB`，这是一个需要后续在 Windows 工具链中复核的工程配置差异。

静态模式通过条件编译省略 DLL 专属的 `LIB_INFO`、命令元数据和数据类型元数据；`downlib_dllMain.cpp` 中保留 `downlib_ProcessNotifyLib_downlib`，并在通知中提供：命令实现函数名数组、通知函数名和依赖静态库列表。当前依赖列表返回 `"\0\0"`，即没有声明第三方静态库依赖。

## 5. 元数据与核心数据模型

### 5.1 `LIB_INFO`

`downlib_dllMain.cpp` 的 `g_LibInfo_downlib_global_var` 是运行时注册根对象，关键字段为：

| 字段 | 当前值/来源 | 含义 |
|---|---|---|
| 格式版本 | `LIB_FORMAT_VER` | 易语言支持库 ABI 格式 |
| GUID | `80CF4A6B3E09425bA57935A3A0E4C473` | 库跨版本稳定身份 |
| 版本 | 主 `3`、次 `1`、构建 `0` | 支持库版本 |
| 系统要求 | 易语言 `3.7`、核心支持库 `3.7` | 运行环境最低版本元数据 |
| 名称 | `网络传送支持库` | IDE 显示名 |
| 语言 | `__GBK_LANG_VER` | 中文/GBK 语言 ABI |
| 平台状态 | `_LIB_OS(OS_ALL)` | 声明所有 OS；但每个具体数据类型/命令又声明 `__OS_WIN` |
| 数据类型 | `g_DataType...` / count | 5 个自定义类型 |
| 命令 | `g_cmdInfo...` / count | 66 个命令 |
| 函数指针 | `g_cmdInfo..._fun` | 与 66 条命令按索引一一对应 |
| 通知 | `downlib_ProcessNotifyLib_downlib` | 必须存在的系统通知回调 |
| 常量 | `g_ConstInfo...` / count | 当前数量 0 |
| 依赖文件 | `NULL` | 动态库未声明附加依赖文件 |

### 5.2 命令登记表

`downlib_cmd_typedef.h` 的 `DOWNLIB_DEF(_MAKE)` 是命令的单一来源；同一宏分别展开为函数声明、函数指针数组、函数名数组和 `CMD_INFO`。索引必须保持稳定，因为对象方法表直接保存命令索引。

共 66 条命令，均声明为 `__OS_WIN`：

- 全局命令 `0–2`：`网络通讯设置`、`设重试时间`、`取总下载速度`。
- 隐藏保留命令 `3–18`：`备用命令2-1` 至 `备用命令17`。
- `下载对象`方法 `19–33`：`增加新任务`、`停止指定任务`、`继续下载任务`、`增加线程`、`减少线程`、`限制速度`、`取下载速度`、`取已下载长`、`取任务数据`、`取重试次数`、`取对象信息`、`取线程信息`、`取任务数据项`、`取本地文件路径`、`设新文件名`。
- 隐藏/析构命令 `34–39`：`备用命令23` 至 `备用命令27`、`下载对象析构函数`；索引 39 带 `CT_IS_OBJ_FREE_CMD`。
- `FTP上传对象`方法 `40–47`：`上传文件`、`停止上传`、`限制速度`、`取上传速度`、`取已上传长`、`取重试数`、`设新文件名`、`取对象信息`。
- 隐藏保留命令 `48–53`：`备用命令29` 至 `备用命令34`。
- `FTP辅助对象`方法 `54–65`：`连接FTP服务器`、`断开FTP服务器`、`删除文件`、`文件改名`、`创建目录`、`删除目录`、`置现行目录`、`取现行目录`、`取目录列表`、`移动文件`、`执行FTP命令`、`取连接句柄`。

可见命令的说明声称覆盖下载任务控制、断点续传、速度限制、FTP 登录/文件管理/原始命令及连接句柄复用；但这些说明来自 `CMD_INFO` 元数据，当前函数体没有对应行为实现。

### 5.3 参数模型

`downlib_cmdInfo.cpp` 在非静态模式下登记 36 个 `ARG_INFO`，索引范围 `000–035`，被命令宏按起始偏移与参数数量引用。主要参数类型包括：

- 下载初始化：写入文件大小默认 `20480`、重连时间默认 `0`、重连次数默认 `0`；
- 任务控制：配置数据类型 `MAKELONG(0x04, 0)`、任务数据 `SDT_BIN`、执行方式；
- 传送控制：速度、线程信息数组、任务数据项查询的类型/类型参数、新文件名；
- FTP：服务器地址、用户名、密码、端口默认 `21`、日志回调、超时、删除/改名/目录/原始命令参数；
- 数组输出：文件名、文件属性（明确注明当前不支持）、文件尺寸、文件时间；
- 引用参数：任务数据和返回命令数据使用 `AS_RECEIVE_VAR` 等引用标志。

参数元数据中的默认值/回调约束用于 IDE 参数检查和帮助文本，不代表当前实现已经分配任务、传输数据或回调用户代码。

### 5.4 自定义数据类型

`downlib_dtType.cpp` 登记 5 个 `__OS_WIN` 类型：

| 索引 | 中文名 | 英文名 | 方法索引 | 成员 |
|---:|---|---|---|---:|
| 0 | 下载对象 | `Download` | `19–33, 39` | 隐藏成员 `文件句柄`/`DownFileHandle` |
| 1 | FTP上传对象 | `FtpUpload` | `40–47` | 隐藏成员 `文件句柄`/`DownFileHandle` |
| 2 | FTP辅助对象 | `FtpAssistant` | `54–65` | 隐藏成员 `文件句柄`/`DownFileHandle` |
| 3 | 任务参数 | `TaskParam` | 无 | 20 个成员 |
| 4 | 传送常量 | `DownConst` | 无，`LDT_ENUM` | 26 个枚举常量 |

`TaskParam` 的 20 个成员描述了类型、URL、本地文件路径、FTP 用户名/密码、默认线程数、速度、连接/发送/接收/线程超时、收发块大小、日志/交互回调、备用文件名、传送类型、类型区分串、代理服务器和 `Referer`。`DownConst` 以位值/消息值描述下载/上传、覆盖/续传/改名/跳过/被动选择，以及开始、结束、线程、日志、同名文件等通知消息。

## 6. 实际执行调用链

### 6.1 DLL 加载与命令分派

```text
LoadLibrary
  -> 导出表 Source_downlib.def::GetNewInf
  -> downlib_dllMain.cpp::GetNewInf
  -> &g_LibInfo_downlib_global_var
  -> 易语言读取 m_pBeginCmdInfo / m_pCmdsFunc
  -> 按命令索引调用 downlib_<EnglishName>_<index>_downlib
  -> 函数从 pArgInf 读取参数（少数函数）
  -> 当前未给 pRetData 写返回值，未改变任务状态
```

`g_cmdInfo_downlib_global_var_fun` 由 `DOWNLIB_DEF_CMD_PTR` 宏按同一索引顺序生成；因此命令表、函数声明、函数指针数组和对象方法索引之间存在强索引契约。

### 6.2 系统通知链

```text
易语言系统通知
  -> downlib_ProcessNotifyLib_downlib(nMsg, dwParam1, dwParam2)
  -> NL_SYS_NOTIFY_FUNCTION
       -> elib/fnshare.cpp::ProcessNotifyLib
       -> 保存 PFN_NOTIFY_SYS
       -> 首次调用 NRS_GET_PRG_TYPE 读取调试/运行类型
       -> 可选调用用户设置的 s_pfnuserNotifySys
  -> NL_FREE_LIB_DATA / NL_UNLOAD_FROM_IDE / NL_IDE_READY 等
       -> 当前分支空操作并返回 NR_OK
  -> 未知消息
       -> NR_ERR
```

动态库还直接处理 `NL_GET_CMD_FUNC_NAMES`、`NL_GET_NOTIFY_LIB_FUNC_NAME`、`NL_GET_DEPENDENT_LIBS`，分别返回静态命令函数名字数组、通知函数名字和空依赖列表。`fnshare.cpp::ProcessNotifyLib` 自身对这些查询只留注释/空分支；真正的返回由 `downlib_dllMain.cpp` 的外层通知函数完成。

## 7. 依赖与资源边界

- **编译时依赖**：仓库内 `elib/*.h` 与 `elib/fnshare.cpp`；Windows SDK/Win32 ABI；Visual Studio `v141` 工具集。`include_downlib_header.h` 通过 `lib2.h`、`lang.h`、`krnllib.h` 和 `downlib_cmd_typedef.h` 汇总接口。
- **运行时声明依赖**：`LIB_INFO.m_szzDependFiles = NULL`；静态通知 `NL_GET_DEPENDENT_LIBS` 返回双零字符串，未声明第三方静态库。
- **动态加载依赖**：宿主必须理解易语言支持库 ABI，并提供 `PFN_NOTIFY_SYS` 通知机制；导出接口只有 `GetNewInf`。
- **持久化**：当前源码没有数据库、配置文件、缓存、映射文件、任务文件或日志文件读写实现。元数据说明提到“映射文件模式”，但仓库内没有对应实现证据。
- **并发/网络/文件**：当前源码未出现 socket、WinHTTP/WinINet、FTP 客户端、线程创建、队列、文件句柄管理或断点存储调用。不能据此推断协议、并发模型、失败重试和资源释放已经存在。
- **安全边界**：参数元数据包含明文 FTP 密码参数和回调指针约定，但当前没有认证、凭据保护、TLS、权限、审计或输入校验实现。

## 10. 风险与后续复核点

1. **实现缺失风险（高）**：命令函数均为空/仅取参，必须确认是否应补入缺失的网络传输实现，或本仓库是否只是接口模板。
2. **平台声明不一致（高）**：`LIB_INFO` 使用 `OS_ALL`，命令和数据类型使用 `__OS_WIN`；项目说明中又提到 Linux，当前源码没有 Linux 工程或条件实现证据。
3. **静态 x64 配置风险（中）**：x64 静态配置没有显式设置 `__E_STATIC_LIB`/`__E_FNENAME`，可能导致与 Win32 静态配置不同的预处理结果。
4. **返回值未定义风险（高）**：多数函数没有向 `pRetData` 写入返回值；在宿主真实调用时可能产生未定义/错误结果。
5. **命令索引兼容风险（高）**：`DOWNLIB_DEF`、函数数组和 `s_dtCmdIndex...` 必须同步修改；插入/删除中间索引会破坏易语言项目兼容性。
6. **编码风险（中）**：源码同时包含 GBK/中文文本和 Visual Studio 工程；需在 Windows 编译器中复核源文件编码、字符串编码与 `__GBK_LANG_VER` 的一致性。
7. **协议/安全能力未证实（高）**：HTTP、FTP、MMS、RTSP、代理、回调、重试和断点续传均只有元数据说明，没有实现或测试证据。
8. **后续复核顺序**：先确认远程历史是否只有浅克隆的单提交；再确认是否存在对应上游完整实现/二进制；最后在 Windows 宿主中设计最小加载测试和每类命令的返回值测试。后续增量信息仍只更新本文件。

## 12. 第三轮：下载、网络、文件与平台底座的归属裁决

### 12.1 本轮先固定的事实边界

本仓库不能作为“已有下载引擎”接入平台。第三轮静态复核确认：

- `downlib_cmd_typedef.h:32-46` 的命令说明声称 HTTP/FTP/MMS/RTSP 下载、停止/继续、线程调整、速度限制、任务数据和断点；`downlib_cmd_typedef.h:53-78` 还声称 FTP 上传、登录、目录操作、原始命令和连接句柄。
- `downlib_cmdInfo.cpp:18-26`、`54-73` 只登记写入块大小、重连时间/次数、线程数、连接/收发/线程超时、收发块大小、代理和 `Referer` 等参数元数据；`downlib_dtType.cpp:54-73` 只登记 URL、本地路径、续传类型、回调和传送策略等数据成员。
- `downlib_cmdDef.cpp:160-184` 的新增/停止/继续任务函数只取参数；`188-206` 的增减线程/限速函数没有调度逻辑；`217-277` 的查询/任务数据/路径/改名函数没有写返回值；`329-377` 的 FTP 上传/停止/限速函数同样没有传送逻辑；`441-550` 的 FTP 登录、断开、目录、命令和句柄函数仅取参数或为空。
- 源码静态扫描未发现 socket、WinHTTP/WinINet、FTP 客户端、线程创建、文件流读写、临时文件、断点文件、重试循环或取消令牌调用。`downlib_dllMain.cpp:7-24` 的 `DllMain` 为空，`101-178` 的通知处理只做 ABI 转发，`134-137` 的 `NL_FREE_LIB_DATA` 为空。

因此下表中的“归属”是**平台第三轮的装配裁决/目标契约**，不是把命令说明冒充为本仓库实现。当前 `downlib` 只吸收到“易语言 ABI 适配与历史契约来源”，不能吸收到网络或文件实现。

### 12.2 双入口、单运行链

如果平台同时保留易语言入口和 HTTP 能力网关，两个入口必须汇聚到同一套下载模块与运行核心，不能各自复制一套下载器：

```text
易语言调用
  -> downlib ABI 适配层（稳定命令索引、参数/回调转换；不直接做 I/O）
                                      \
                                       +-> 下载模块/统一任务入口
平台客户端 -> 统一 HTTP 网关（鉴权、契约、提交/查询/取消；不直接做 I/O） /
                                              |
                                              v
                                      运行核心：任务状态机
                                      句柄 + 租约 + 取消令牌
                                      并发调度 + 限速 + 重试预算
                                              |
                         +--------------------+--------------------+
                         v                                         v
                网络支持库/协议提供者                         文件支持库
          HTTP/FTP/MMS/RTSP 流、Range、响应                 文件流、临时文件、
          分类、连接/读写超时、协议级中止                 断点清单、锁、fsync、原子提交
                         \                                         /
                          +-> 统一事件/状态/证据 -> 网关响应或 ABI 回调
```

网关只负责可审计的公开契约：参数校验、授权、任务提交、状态读取、取消请求和事件订阅。它不应持有 socket、文件流或 OS 线程，也不应把一次 HTTP 请求的生命周期误当成下载任务生命周期。`downlib` 的对象命令若未来接入该链，只能在 ABI 适配层将 `下载对象`/`FTP上传对象` 映射为任务句柄，将 `停止指定任务`/`停止上传` 映射为运行核心取消命令。

### 12.4 下载、断点与文件流的责任拆分

1. **网络支持库只证明“网络侧可继续”**：它读取 URL、协议、请求范围、响应状态、实体标签/最后修改时间和实际可读字节；对 HTTP 只有在服务端明确返回合法 `206`/`Content-Range` 且实体身份匹配时才报告可续传。FTP/MMS/RTSP 应返回各自的偏移能力，不把 HTTP Range 语义硬套到其他协议。
2. **文件支持库只证明“本地侧可提交”**：它持有临时文件流、文件锁、断点清单和最终路径；每个范围写入必须有边界，短写/写后校验/`fsync`/原子替换由它负责。完成前不能把临时路径伪装成最终制品。
3. **运行核心决定“任务是否继续”**：它将网络能力、文件 checkpoint、任务状态、并发 worker、总截止时间和重试预算组合起来；断线后是重试当前范围、重新协商范围、降级单线程还是转失败，由运行核心根据错误类别、幂等性和剩余预算裁决。
4. **网关只表达“请求和结果”**：公开返回应至少区分 `任务已提交`、`进行中`、`已完成`、`已取消`、`可恢复失败`、`不可恢复失败`，不能在 HTTP 请求尚未完成时宣称文件已交付。客户端断开不自动等价于取消，必须由契约明确“请求取消”与“订阅断开”的区别。
5. `SDT_BIN` 任务数据（`downlib_cmdInfo.cpp:26,30,36-38`）若未来承载恢复信息，只能保存可验证的逻辑状态：源标识、临时制品标识、已完成范围、实体校验信息、任务代次、策略和校验摘要；禁止序列化原始 socket、线程、文件 OS 句柄或回调指针。当前源码没有该序列化格式，不能声称已有可恢复断点。

### 12.5 并发、临时文件、重试和取消的单链路规则

| 主题 | 运行时顺序 | 失败时的权威动作 |
|---|---|---|
| 并发分段下载 | 运行核心先根据文件长度/服务端能力切分范围 -> 为每个范围申请租约 -> 网络支持库建流 -> 文件支持库按范围写入 -> checkpoint 原子更新 | 范围重叠、租约冲突或服务端不支持时禁止静默覆盖；降级策略必须写入任务状态 |
| 动态增减线程 | 网关/ABI提交“目标并发度” -> 运行核心只在安全边界调整 -> worker 完成当前有界读写后退出/新增 | 不强杀持有文件写锁的 worker；到达硬截止仍未退出则进入资源回收/残留审计 |
| 临时文件 | 文件支持库在目标文件同一文件系统创建唯一临时目录/文件和 checkpoint -> 写入、校验、fsync -> 原子 rename | 创建、写入、校验或 rename 任一步失败都不得发布最终路径；保留可恢复证据或隔离残留 |
| 网络错误重试 | provider 返回结构化错误（连接失败/读超时/5xx/限流/认证/范围不匹配等） -> 运行核心检查幂等性、次数、退避、截止时间 -> 重新建流/继续范围 | 预算耗尽返回可重试但未完成或最终失败；不由网关循环重发，不把 401/403/404/非法 Range 当普通重试 |
| 主动取消 | 网关/ABI发取消命令 -> 运行核心原子置取消状态并传播 token -> provider 中止阻塞 I/O -> 文件支持库停止写入、flush/checkpoint -> 释放 worker/锁/租约/句柄 | 取消结果只能在所有可中止资源已确认或进入残留回收状态后落账；不得返回成功 |
| 宿主崩溃 | 重启时运行核心先扫描任务、句柄、租约、临时文件、checkpoint -> 回收死亡 owner -> 校验 checkpoint 与实体身份 -> 恢复或标记不可恢复 | 任何无 owner 的 socket/worker/文件锁/临时目录必须有回收证据；当前仓库无崩溃恢复实现 |

## 13. 句柄、租约与资源所有权

### 13.1 对现有 `DownFileHandle` 的裁决

`downlib_dtType.cpp:30-49` 在 `下载对象`、`FTP上传对象`、`FTP辅助对象`内都登记名为 `DownFileHandle` 的隐藏 `SDT_INT` 成员；`downlib_cmd_typedef.h:78` 的“取连接句柄”说明又要求该句柄可在 FTP 上传和下载对象之间复用。静态事实只有“存在一个 ABI 整数槽位和复用意图”，没有句柄表、分配器、引用计数、关闭函数、代次校验或跨对象安全检查。

平台落点不能直接把这个整数当作 Windows `HANDLE`、socket 或 CRT 文件描述符。若未来接线，适配层应把它转换为**不透明逻辑句柄**，由运行核心句柄表保存：

| 状态 | 允许动作 | 终态规则 |
|---|---|---|
| `CREATED` | 绑定任务/连接及 owner | 未成功绑定不能对外返回 |
| `ACTIVE` | 借用网络流或文件流，查询状态 | 每次借用校验 owner、项目、代次和租约 |
| `CLOSING` | 拒绝新借用，等待已有操作退出 | 只能由持有者或治理器推进 |
| `RELEASED` | 不允许任何动作 | 旧句柄永不复活，重复释放幂等并留证 |
| `EXPIRED/RECLAIMED` | 不允许继续 I/O | 崩溃/超时回收后必须换新句柄/代次 |
| `INVALID` | 返回稳定句柄错误 | 不得把无效整数传给 provider |

句柄表记录至少应包括 `句柄id`、资源类型、创建者/当前 owner、项目范围、任务id、代次、创建时间、最后活动时间、租约截止、底层 provider 引用和释放证据。网关只传逻辑句柄；易语言 ABI 的 `SDT_INT` 只作兼容表示，不获得底层 OS 资源所有权。

### 13.2 租约模型

租约用于解决“任务/连接/文件临时被谁持有”和“宿主消失后如何回收”，不是网络支持库的重试计数器。建议最少区分：

- **任务租约**：运行核心调度权；有心跳、空闲超时和硬截止。
- **网络连接租约**：连接可被一个或多个明确授权的任务借用；关闭/过期时禁止新请求。
- **文件写租约**：目标或临时制品的写入权；并发范围必须按不重叠区间或同一任务序列化。
- **网关请求租约**：只覆盖一次提交/查询/取消请求，不得绑死下载任务；请求断开不改变任务状态，除非契约显式指定取消。

租约状态建议为 `ACQUIRED -> RENEWED -> RELEASE_PENDING -> RELEASED`，异常路径为 `EXPIRED -> RECLAIMED`。续租必须带 owner 和代次，过期租约不能被旧 worker 续活；清理必须先使句柄不可借用，再中止 I/O，再关闭底层资源，最后删除租约记录。当前 `downlib` 没有任何租约或心跳实现，以上属于平台待建契约。

## 14. 资源生命周期与释放矩阵

### 14.1 统一释放顺序

对于一次下载/上传任务，成功、业务失败、主动取消/超时、宿主崩溃四种终态都应走同一可审计释放闭环：

```text
停止接收新工作
  -> 原子冻结任务状态/取消令牌
  -> 等待或中止网络读写 worker
  -> 关闭响应体、socket、协议连接
  -> 停止文件写入并 flush/fsync（可恢复失败另存 checkpoint）
  -> 发布最终文件，或隔离/标记临时文件
  -> 释放文件锁与网络/文件句柄
  -> 释放租约并记录 owner/代次/结果
  -> 回收 worker/线程与回调引用
  -> 事件、失败原因、残留扫描结果落账
```

`NL_FREE_LIB_DATA`当前为空（`downlib_dllMain.cpp:134-137`），析构命令 `DownFreeCmd` 当前为空（`downlib_cmdDef.cpp:320-325`），所以不能把“宿主通知卸载”或“对象有析构命令”当作释放已经实现的证据。

### 14.2 资源释放责任表

| 资源 | 创建者 | 持有者/借用者 | 正常完成 | 业务失败 | 取消/超时 | 崩溃/强杀 |
|---|---|---|---|---|---|---|
| HTTP/FTP连接、响应体、socket | 网络支持库 | 运行核心任务；共享时由连接租约约束 | 关闭响应；连接按复用策略归还或关闭 | 关闭当前流，按错误类别决定连接是否可复用 | 取消 I/O，硬截止后强制关闭并验证无 worker 持有 | 新进程按 owner/租约扫描并关闭孤儿连接 |
| 文件流、范围写锁 | 文件支持库 | 运行核心范围 worker | flush/fsync 后关闭；只在校验通过后发布 | 关闭并保留/隔离临时文件及错误证据 | 停止新写，落 checkpoint，关闭流和锁 | 扫描无 owner 锁，回收后检查临时文件与 checkpoint 一致性 |
| 临时文件/目录 | 文件支持库 | 任务租约 | 原子 rename 后删除临时元数据 | 保留可恢复状态或按保留策略清理 | 不得误删可续传数据；标记 `CANCELLED` | 清理死亡任务残留，不能删除仍被活跃 owner 持有的目录 |
| checkpoint/任务数据 | 运行核心+文件支持库 | 运行核心 | 最终状态与校验摘要原子落账 | 记录失败类别、已完成范围和可恢复性 | 记录取消代次和可继续条件 | 先读权威状态，再决定恢复/隔离；禁止使用未校验旧数据 |
| worker/线程/取消令牌 | 运行核心 | 运行核心调度器 | worker退出并回收 token | 异常路径 join/回收 | cancel→有界等待→强制终止/残留告警 | 新进程按 pid/owner 识别死亡 worker |
| 网关请求、回调函数指针 | 网关/ABI适配层 | 单次请求或事件订阅 | 返回/解除订阅，释放回调引用 | 返回稳定错误并解除引用 | 请求取消与连接断开分别处理 | 进程重启清理订阅；不能调用已失效宿主指针 |
| 逻辑句柄/租约 | 运行核心 | owner 任务/授权借用者 | `RELEASED`，写释放证据 | 进入关闭后释放 | 过期/取消不可新借用，完成回收 | `RECLAIMED`，旧句柄不可复活 |

## 15. 失败矩阵与结果语义

下表是第三轮应固定的失败分类；它是未来平台契约，不是当前 downlib 已实现的错误码。当前源码只在命令说明中出现“成功返回真/失败返回假”或 `-1`，没有统一错误对象和可重试字段。

| 场景 | 归属 | 是否可重试 | 必须保留的状态/证据 | 对外结果 |
|---|---|---:|---|---|
| URL 为空、协议不支持、端口/参数非法 | 网关预校验 + 网络支持库 | 否 | 原始参数摘要、拒绝原因 | `INVALID_ARGUMENT/UNSUPPORTED_PROTOCOL` |
| DNS、连接拒绝、网络不可达 | 网络支持库分类，运行核心裁决 | 有预算且任务未过截止时间时可 | 尝试次数、退避、最后网络错误 | `NETWORK_UNAVAILABLE`，可恢复则 `RETRYING` |
| 连接/发送/接收超时 | 网络支持库产生，运行核心消费 | 仅在幂等且预算足够时 | 超时阶段、耗时、尝试次数、取消状态 | `TIMEOUT` 或 `RETRYING` |

### 20.4 取消、临时文件、析构与释放

停止下载/上传函数没有取消状态、取消令牌、I/O 中止或停止确认；没有任务 owner、连接租约、文件锁、临时文件名、checkpoint、残留扫描或崩溃恢复记录。`downlib_DownFreeCmd_39_downlib` 的析构命令为空，`DllMain` 的进程/线程加载卸载分支只 `break`，`downlib_ProcessNotifyLib_downlib` 的 `NL_FREE_LIB_DATA`、`NL_UNLOAD_FROM_IDE` 和 `NR_DELAY_FREE` 分支也为空。`elib/fnshare.cpp` 仅保存系统通知函数、读取运行类型并转发用户通知，不拥有下载资源。

因此当前不存在可回读的正常完成、失败、取消、超时或宿主崩溃释放路径。不能因为存在析构命令索引、`DownFileHandle` 字段或释放通知名称，就推断网络连接、文件流、线程或临时目录会被释放。未来补实现至少要验证停止接收新工作、传播取消、终止/等待 I/O、关闭协议资源、落 checkpoint、提交或隔离临时文件、释放锁/句柄/线程的顺序，并验证重复析构和宿主卸载。

### 20.5 测试现状与验证缺口

目标目录没有匹配 `test`/`Test` 的源码或测试工程，也没有 CI、模拟 HTTP/FTP 服务、临时目录夹具、断线注入、磁盘错误注入、线程/句柄扫描或 Windows 宿主测试。当前环境为 macOS，不能运行工程声明的 Visual Studio `v141`/Windows SDK 构建。

2. 66 个命令是否按 ABI 正确返回布尔、整数、文本、二进制或对象结果。
