# 系统工程平台 · 模块库权威总览

> 本文件是系统工程平台模块库的唯一目录与职责说明。项目总架构、通用底座边界和验收定义以 `项目说明.md` 为上位权威；支持库原子能力以 `支持库总览.md` 和各包内契约为事实源；本文件只维护模块的领域职责、组合关系、公开能力和具体流程。每个模块的实际目录树、逐命令参数和返回值落在该包 `说明/目录树与命令.md`。
>
> 模块库面向所有软件开发场景：桌面程序、Web 服务、业务系统、自动化工具、数据/文档/媒体程序、智能代理以及后续其他应用。模块不是智能代理专属组件，也不是第三方库的简单别名。

## 一、实际盘点

当前正式模块共 **11 个**，公开组合能力共 **46 项**。另有 `模块库/_模板`，只用于创建新模块，不属于生产模块。

| 模块类型 | 模块 |
| --- | --- |
| 基础模块 | OCR、图像处理、媒体处理、文件管理、文档读取、简单窗口、网页分析 |
| 功能模块 | 媒体转写、文档生成、文档解析、自修复工具 |
| 非生产模板 | `_模板`，仅供复制，不装配、不注册、不对外发布 |

## 二、模块库解决什么问题

支持库解决一个原子动作，模块库解决一个完整领域流程。模块库的唯一价值是让调用方不需要自己拼接多个支持库、处理多个错误码或管理底层资源。模块内部同一个私有纯逻辑子项可以直接调用；模块调用支持库、模块调用模块、支持库调用其他区域能力或任何跨进程/跨包调用时，必须经过 HTTP 中间件网关 API，不能直接 import 或共享内部对象。模块只拿到契约生成的客户端，不拿支持库实现。

```text
调用方
  → 模块公开能力
  → 模块校验统一输入
  → HTTP 中间件网关（被动发现目标模块/支持库）
  → 网关状态机与资源租约
  → 按请求调用一个或多个支持库原子能力
  → Provider/系统库/标准库执行
  → 模块统一结果、错误和产物
  → 调用方
```

模块库必须遵守：

- 一个领域流程只有一个模块入口和一个流程负责人；
- 模块只能通过 HTTP 网关调用支持库公开能力，不能导入第三方库、提供者实现或实现目录；
- 多个 Provider 的差异必须在支持库和运行核心内收口，不能让模块产生多条执行链；
- 模块对外返回统一结果，不把底层异常、临时路径、进程号、句柄或第三方对象泄露出去；
- 模块本身不拥有提供者生命周期，但必须声明一次性、租约或缓存资源需求；
- 一个模块的每个公开能力都必须能追溯到包声明、参数契约、依赖能力和验证场景。

```text
        ▼

        │ 统一值、错误码、可重试、产物和证据
        ▼
调用方获得返回参数
```

## 五、基础模块

### 5.1 OCR

**路径：** `模块库/OCR`　**包 id：** `模块库.OCR`

**职责：** 将图片路径或图片字节交给 Tesseract 提供者，统一返回文字或词级结果；不直接加载 Tesseract，不自行管理外部进程。

**公开能力：**

- `OCR.识别图片文字`：图片路径与图片字节二选一，返回文本或词列表；
- `OCR.识别图片文件`：按文件路径识别文字；
- `OCR.可用性检查`：返回版本、最低版本是否满足、语言列表、数据目录和语言数量。

```text
图片路径/图片字节 + 语言 + 词级开关
  → 模块检查输入二选一约束
  → 唯一能力调用器调用 OCR识别.识别图片
  → Tesseract 提供者探测命令/语言包
  → 受控外部进程识别
  → 输出上限/超时/取消/退出码处理
  → 返回文本或词级列表
```

边界：工具缺失、版本不兼容、语言包缺失、超时、取消和输出超限必须返回明确错误；不能把“有包声明”当作 OCR 可用。

### 5.2 图像处理

**路径：** `模块库/图像处理`　**包 id：** `模块库.图像处理`

**职责：** 提供通用图像处理流程，统一处理受控文件读取、图像解码、尺寸和像素边界、图像变换以及结果编码。

**公开能力：**

- `图像处理.分析图像文件`；
- `图像处理.生成占位图`；
- `图像处理.识别图像格式`；
- `图像处理.生成缩略图`；
- `图像处理.图像EXIF转置`；
- `图像处理.透明背景合成`；
- `图像处理.计算感知哈希`；
- `图像处理.缩放图像`；
- `图像处理.重编码图像`。

```text
图像路径/图像字节
  → 文件系统支持库读取受控二进制
  → Pillow 提供者解码并检查格式、像素数和大小
  → 按能力执行统计/识别/缩放/转置/合成/哈希/重编码
  → 结果编码为统一图像产物
  → 清理字节缓冲和提供者临时资源
  → 返回图像字节、格式、尺寸、摘要或错误码
```

图像伪装、损坏、超大像素、未知格式和输出过大必须在模块结果中显式区分；模块不把 Pillow 对象交给调用方。

### 5.3 媒体处理

**路径：** `模块库/媒体处理`　**包 id：** `模块库.媒体处理`

**职责：** 统一组织 FFmpeg 的媒体探测、音轨提取、转码和抽帧能力。

**公开能力：** `媒体处理.检查提供者`、`媒体处理.探测媒体`、`媒体处理.提取音频`、`媒体处理.转码`、`媒体处理.抽取帧`。

```text
媒体路径 + 目标操作
  → 检查格式、大小、最大时长和输出上限
  → 调用 FFmpeg 提供者
  → 必要时先 ffprobe 探测流/时长/尺寸
  → 启动受控 ffmpeg 进程组
  → 读取输出并限制字节数
  → 超时/取消时终止整个进程组
  → 清理临时文件和端口
  → 返回媒体产物或统一错误
```

模块只允许契约声明的格式和编码参数，不向调用方暴露命令行拼接；损坏媒体、无音轨、超长媒体和提供者不可用分别返回不同错误。

### 5.4 文件管理

**路径：** `模块库/文件管理`　**包 id：** `模块库.文件管理`

**职责：** 为所有通用程序提供更容易使用的文件门面，把文件系统和资源管理的原子能力组合成一组稳定的文件操作。

**公开能力：** 读取、写入、复制、移动、删除、列出、受控二进制读取、读取头部字节、流式创建摘要。

```text
文件路径/受控根目录/相对路径
  → 路径边界与大小校验
  → 调用文件系统公开能力
  → 大文件按块调用资源管理摘要能力
  → 写入自动创建父目录；删除不存在按契约幂等
  → 临时文件登记、失败清理、摘要返回
  → 返回文本、字节、名称列表或摘要
```

模块不能提供无限制的任意路径访问；受控二进制能力必须在根目录内解析相对路径。

### 5.5 文档读取

**路径：** `模块库/文档读取`　**包 id：** `模块库.文档读取`

**职责：** 面向纯文本文件提供轻量阅读门面，不承担 PDF、DOCX、XLSX、PPTX 的格式解析。

**公开能力：** `文档读取.读取正文`、`文档读取.提取标题`、`文档读取.计算段落数`、`文档读取.结构化读取`。

```text
文本文件路径
  → 文件系统读取正文
  → 文本处理按行分割和去空白
  → 首个非空行作为标题
  → 统计非空段落
  → 数据交换序列化结构化结果
  → 返回正文/标题/段落数/序列化文本
```

格式复杂的文件必须转到文档解析模块，不能在文档读取模块中偷偷增加多个第三方解析器。

### 5.6 简单窗口

**路径：** `模块库/简单窗口`　**包 id：** `模块库.简单窗口`

**职责：** 组合窗口描述和状态描述，提供平台无关的窗口定义与状态流转模型；当前不负责真实渲染。

**公开能力：** 创建窗口、打开窗口、关闭窗口、传递参数、获取窗口描述。

```text
窗口编号/标题/尺寸/属性
  → 窗口描述支持库创建并校验定义
  → 状态描述支持库初始化关闭状态
  → 打开/关闭/传参请求
  → 按允许流转表校验状态
  → 返回新状态和窗口描述
  → 项目适配层再绑定实际前端宿主
```

模块不创建真实窗口、不持有窗口句柄、不绑定 macOS/Windows/Linux 控件。

### 5.7 网页分析

**路径：** `模块库/网页分析`　**包 id：** `模块库.网页分析`

**职责：** 将网页标题和正文提取组合成一次调用，供桌面程序、Web 服务、自动化工具和智能代理复用。

**公开能力：** `网页分析.提取网页信息`。

```text
HTML 内容
  → 网页解析提取标题
  → 网页解析剔除 script/style 并提取正文
  → 空白归一化与最大长度截断
  → 统一返回标题+正文
```

它只分析已取得的 HTML；网络请求、URL 安全和 SSRF 防护属于网络请求支持库，不在本模块重复实现。

## 六、功能模块

### 6.1 媒体转写

**路径：** `模块库/媒体转写`　**包 id：** `模块库.媒体转写`

**职责：** 统一音频和视频转写入口，把 MLX Whisper 的模型配置、受管子进程和转写结果隐藏在模块/支持库内部。

**公开能力：** `媒体转写.转写音频文件`、`媒体转写.转写视频文件`、`媒体转写.检查可用性`、`媒体转写.获取模型版本`。

```text
音频/视频路径 + 配置 + 超时 + 取消令牌
  → 模块判断媒体类型
  → 视频转写转入音频转写公开能力
  → MLX Whisper 提供者检查模型配置
  → 隔离子进程加载模型并转写
  → 输出上限、超时、取消、进程组回收
  → 清理临时音频/媒体资源
  → 返回文字、模型信息或明确错误
```

未配置模型返回“未配置模型”；模型缺失、提供者崩溃、超时和取消不能返回空文本冒充成功。

### 6.2 文档生成

**路径：** `模块库/文档生成`　**包 id：** `模块库.文档生成`

**职责：** 为不同格式提供一个统一生成入口，调用方只选择目标格式和内容结构。

**公开能力：** `文档生成.生成文档`。

```text
目标格式 + 统一内容块
  → 模块按格式选择文字文档/表格文档/演示文稿/PDF 生成能力
  → 对应提供者生成产物
  → 生成后校验 OOXML ZIP 或 PDF 头尾/重开
  → 创建产物摘要、媒体类型和诊断
  → 清理临时文件和内存缓冲
  → 返回统一生成产物
```

模块不让调用方分别学习四套生成库；若某格式没有对应能力，返回格式不支持，不自动调用未登记的第三方库。

### 6.3 文档解析

**路径：** `模块库/文档解析`　**包 id：** `模块库.文档解析`

**职责：** 按文件格式选择解析能力，把 PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX 统一成平台通用文档。

```text
输入文件/制品
  → 文件类型识别和大小边界
  → 按格式选择唯一解析路线
       ├─ PDF → PDF 文档/隔离提供者
       ├─ DOC/DOCX → 文字文档/文档转换
       ├─ XLS/XLSX → 表格文档/文档转换
       └─ PPT/PPTX → 演示文稿/文档转换
  → 旧格式需要时进入受控临时目录转换
  → 解析段落、表格、幻灯片、备注、图像和来源位置
  → 统一为通用文档结构
  → 安全释放临时目录和提供者
  → 返回通用文档或明确错误
```

这是文档系列的唯一流程负责人。上层业务不得分别直连 PDF、DOCX、XLSX、PPTX 解析库，否则会产生多条文档链路和不同结果结构。

### 6.4 自修复工具

**路径：** `模块库/自修复工具`　**包 id：** `模块库.自修复工具`

**职责：** 把工作区、精确修改、定向验证、提交、回滚和资源清理组合成受控修复流程；它是通用开发基础能力，不只服务智能代理。

**公开能力：** 创建修复工作区、验证修复、回滚修复、获取当前提交哈希。

```text
目标仓库/允许修改目录/修复内容
  → Git 提供者检查仓库和版本
  → 创建独立 worktree 和唯一运行目录
  → 只允许指定路径修改
  → 运行定向验证并检查内容摘要
  → 成功才允许最小提交
  → 失败则清理工作区和临时资源
  → 需要撤销时 git revert；需要合入时 cherry-pick
  → 冲突自动 abort，恢复干净状态
  → 返回提交、分支、摘要、验证和剩余风险
```

模块不能绕过 Git 提供者直接删仓库文件、重写历史或把未验证修改标为成功。

## 七、模块间组合关系

模块之间原则上不直接互相调用；需要复用时通过支持库公开能力或更高层明确登记的领域模块组合，避免模块环依赖。

```text
文件系统/资源管理/数据交换/文本处理
  ├─ 文件管理
  ├─ 文档读取
  └─ 自修复工具

Pillow 提供者 + 文件系统
  └─ 图像处理

FFmpeg 提供者
  ├─ 媒体处理
  └─ 媒体转写的前置媒体处理路线（需要时）

MLX Whisper 提供者
  └─ 媒体转写

PDF/文字/表格/演示文稿/文档转换
  ├─ 文档解析
  └─ 文档生成

Tesseract 提供者
  └─ OCR

网页解析
  └─ 网页分析

窗口描述 + 状态描述
  └─ 简单窗口
```

## 八、模块资源和错误边界

模块不拥有第三方资源，但必须把资源需求传给运行核心：

| 模块资源类型 | 平台处理方式 |
| --- | --- |
| 纯文本、集合、时间计算 | 进程内有限计算，按请求结束释放 |
| 文件、临时目录、产物 | 受控根目录、大小上限、临时登记、摘要和最终清理 |
| FFmpeg、LibreOffice、Tesseract | 独立进程组、超时、取消、输出上限和退出码检查 |
| Pillow、PyMuPDF、密码签名 | 受管提供者隔离，主流程不直接持有原生扩展对象 |
| MLX Whisper、本地模型 | 模型配置探针、按需启动或有界缓存、显存/内存/超时预算 |
| Git 工作区 | 独立 worktree、路径白名单、冲突中止、清理和状态回读 |
| 窗口描述 | 只保存平台无关字典，不持有真实窗口句柄 |

有状态资源不由模块直接持有。模块只能声明需要数据库、浏览器、模型、媒体、设备或其他会话型能力；调用方选择保持状态时，网关返回固定六位数字的不透明句柄，后续通过 HTTP 携带句柄调用。句柄只是外部精准查询键，不跨模块共享模块内部对象；每个模块仍在自己的 owner 内完成增删改查和领域状态推进。不接收句柄则执行完成后自动释放。关闭或异常时由网关内部运行核心负责回滚、排空、线程 join/进程组终止和零残留核对。模块不能把连接池、游标、线程、队列、第三方对象或真实 PID 传给调用方。

网关提供通用的 `资源状态`、`资源续租`、`资源关闭` 操作，只返回句柄生命周期信息，不代替模块业务查询。需要定位上一模块产生的批次时，下一模块只接收 `资源句柄` 参数，在自己的 owner 内做精准查询，不重新扫描全部物理资源。

每个模块都必须能说明四种终态：

```text
正常完成
  → 结果正确，产物可校验，临时资源释放或进入有界缓存
业务失败
  → 返回稳定错误码，不吞错，不留下临时资源
超时/取消
  → 真实停止当前执行，回收进程组、队列、目录和句柄
提供者崩溃
  → 监督器识别退出，模块只返回提供者崩溃，不伪造成功
```

## 九、模块扩展规则

新建模块前必须先回答：

1. 这是已有模块的扩展，还是确实不存在的新领域流程；
2. 能力是否已经存在于支持库或其他模块；
3. 谁是唯一模块负责人，公开入口是什么；
4. 输入、输出、错误、可重试和资源生命周期如何定义；
5. 哪些 Provider 被组合，是否会造成重复链路；
6. 正常、失败、超时、取消、崩溃分别如何回收；
7. 生产验证如何经过真实注册表，而不是测试预注册或直接导入实现。

新增模块必须具备：

```text
包声明.json
能力契约/参数契约.json
实现/内部编排
说明/使用说明.md
验证场景引用.json
完整性摘要.json
包级中文入口
```

模块不能直接复制一套第三方库适配逻辑；如果发现底层能力缺失，应先新增或升级支持库，再由模块组合。

## 十、验证和唯一事实源

- 本文件维护模块清单、功能边界和流程；具体字段仍以各模块的 `包声明.json`、`能力契约/参数契约.json` 为准。
- `模块库/_模板` 不计入正式模块，不得被能力搜索器、注册表和客户端制品发布。
- 只验证模块入口导入，不验证真实支持库返回，不算模块通过。
- 模块验收至少覆盖声明、注册、搜索、真实调用、错误转换、产物校验和资源释放。
- 任何模块公开能力重复注册、依赖缺失、契约摘要变化或提供者冲突，必须在装配前失败，不允许半装配。
- 本文件数量发生变化时，必须同步更新 `项目说明.md` 和 `支持库总览.md` 的交叉引用关系；不能另建平行模块目录。

## 十一、源码研究后的模块选择裁决（2026-08-22）

第二轮对 `instructor`、Graphiti、Hindsight、Mem0、MaxKB、QAnything、DeepSeek-Harness 和 Prefect 的源码核对进一步确认：模块库不应按开源项目名称扩张，而应按“跨原子能力的领域流程”收敛。

```text
原子 Provider/系统边界
  → 支持库：schema、解析、存储、向量、图、模型、错误转换
  → 模块：记忆流程 / 知识库 RAG 流程 / 媒体蒸馏流程
  → 运行核心：任务、租约、队列、超时、取消、崩溃和证据
```

模块候选必须同时满足：有统一输入和输出、组合至少两个公开支持库能力、有中间状态或失败分支、能定义四种终态、能经过唯一注册表真实调用。只有一个 Provider 调用的能力留在支持库；需要跨请求状态或重资源的能力由模块声明，由运行核心创建执行单元，模块不持有底层对象。

当前候选裁决：

| 流程候选 | 是否进入模块库 | 依据 |
|---|---|---|
| 结构化输出 Provider 适配 | 否，留在支持库 | `instructor` 的核心是 schema/handler/retry/stream 原子转换，不是业务流程 |
| 记忆写入→反思→检索→投影 | 待核模块候选 | Graphiti/Hindsight/Mem0 暴露跨存储、时间有效性和版本投影，需先确定原始证据 owner |
| 文档摄取→解析→切分→索引→召回 | 待核模块候选 | MaxKB/QAnything/RAGFlow 都证明是领域流程，但必须收敛为一个规范链 |
| Session/FlowRun 持久化与恢复 | 否，属于运行核心 | DeepSeek-Harness/Prefect 的任务状态、worker 和恢复语义不是业务模块能力 |

在候选模块完成需求确认、能力搜索、复用决策、契约、资源预算、装配计划和验收工作包前，本文件不新增正式模块数量，也不把开源仓库直接复制为平台模块。
