# 测试拆分与按包验证方案

> 本文件规定系统工程平台的测试组织和验证选择规则。它不新增业务能力，也不替代
> `开发文档/项目说明.md`、包内 `能力契约/` 或 `AGENTS.md`；当测试入口与本文件不一致时，
> 以本文件的“一个包一个入口、集成只引用入口、变更驱动缓存”规则修复实现。

## 目标流程

```text
源码/契约变更
      │
      ▼
变更归属解析 ──► 支持库包 / 模块包 / 核心基础设施 / 外部环境
      │                         │
      │                         ├─ 无相关变更 → 读取包级成功证据
      │                         │                 ├─ 指纹一致 → 跳过
      │                         │                 └─ 指纹失效 → 执行该包入口
      │                         │
      │                         └─ 有相关变更 → 执行该包入口
      ▼
包级测试入口（一个包一个入口，独立工作区、独立证据、独立退出码）
      │
      ├─ 支持库：契约/注册/公开入口/原子行为/资源释放
      ├─ 模块库：契约/能力 id/流程组合/失败传播/公开入口
      └─ 外部提供者：只在声明为慢速或外部验证时执行
      │
      ▼
集成测试入口（唯一一个）
      │ 只并行引用已登记的包级入口，不复制测试用例、不重新扫描实现
      ▼
结果账本：包级证据 + 集成证据 + 未验证原因
      │
      └─ 发布门禁：只接受退出码 0 且证据指纹匹配；任何缺证据均阻断
```

## 目标目录和登记

每一个正式支持库或模块必须拥有一个独立入口文件，入口文件不是实现的复制品，只负责
装载该包的测试类并输出统一结果。

```text
测试中心/
  包测试/
    支持库/
      支持库_后端_网络请求.py
      支持库_核心_类型转换.py
      支持库_适配层_MySQL提供者.py
    模块库/
      模块库_文件管理.py
      模块库_文档读取.py
  集成测试/
    运行集成测试.py          # 唯一集成入口
    集成清单.json             # 只登记包入口，不登记测试类
  包测试登记.json             # 唯一包 id → 入口 → 资源键映射
```

`包测试登记.json` 每项固定字段：

```json
{
  "包id": "支持库.后端.网络请求",
  "包目录": "支持库/后端/网络请求",
  "测试入口": "测试中心/包测试/支持库/支持库_后端_网络请求.py",
  "测试类型": "支持库",
  "资源键": ["纯计算", "临时目录"],
  "外部验证": false,
  "依赖包": [],
  "状态": "已登记"
}
```

规则：

1. `包id` 必须来自包声明，不能由测试文件名推断；一个包只能登记一个入口。
2. 入口必须能独立运行，测试实现仍放入口文件或测试中心的对应包目录，禁止从另一个
   包测试文件复制或导入测试类。
3. 测试只能从包级公开入口调用；禁止导入 `实现/`、Provider 内部对象或工程缓存候选实现。
4. 支持库测试原子能力逐项覆盖：参数、统一结果、错误码、资源释放、重复调用和并发边界。
5. 模块测试只验证能力组合、状态流转、失败传播和公开入口；模块不得因底层 Provider 不可用
   写空结果伪装成功。
6. `_模板`、适配器内部目录和未带 `包声明.json` 的目录不进入正式包测试清单；需要验证时使用
   开发工具或适配层专用测试，不冒充正式包证据。

## 变更驱动缓存

包级成功证据的缓存键必须包含：

```text
包目录摘要
+ 包声明/能力契约/依赖锁摘要
+ 测试入口摘要
+ 入口静态依赖文件摘要
+ 测试引擎摘要
+ Python/操作系统/架构摘要
+ 外部依赖摘要（仅外部验证包）
```

选择规则：

| 变更 | 必须重跑 |
| --- | --- |
| 包实现、包级契约、包声明、依赖锁、包公开入口 | 该包测试入口 |
| 被该包入口静态或运行时引用的公共契约/运行核心 | 所有受影响包入口，再跑集成入口 |
| 仅其他无依赖包变化 | 不重跑本包；读取有效包级证据 |
| 测试入口或测试引擎变化 | 受影响入口；测试引擎变更默认全包入口失效 |
| 外部环境/依赖版本/真实服务变化 | 只失效声明了该资源键的包；不可把外部未验证写成成功 |
| 文档、说明书、工程缓存变化 | 不触发包行为测试；若影响门禁扫描则触发对应门禁测试 |

证据必须记录 `成功`、`测试数`、`退出码`、`包指纹`、`依赖摘要表`、`资源清理结果`、
`未验证原因`。只有成功且所有指纹匹配才允许跳过。失败、零测试、导入失败、未解释跳过、
清理失败和证据缺字段都不能命中缓存。

## 集成入口边界

集成入口只做三件事：

1. 读取 `包测试登记.json`，校验包声明、入口路径和包指纹一致。
2. 按资源键分批并行调用包级入口；固定端口、数据库、发布指针、外部服务仍串行。
3. 汇总包级退出码和证据，生成一个集成结果；不重新加载包测试类，不复制包测试逻辑。

集成入口不得：

- 递归扫描 `测试中心/**/测试_*.py` 作为正式测试集合；
- 通过阶段匹配表把多个包拼成一个测试套件；
- 因为某包已有缓存就把它从登记中删除；
- 将“未执行”“外部不可用”“缓存损坏”统计成成功；
- 允许包测试入口之间共享固定临时目录、数据库或端口。

## 迁移顺序和落点

### 第一步：登记和对账

新增 `测试中心/包测试登记.json` 生成/校验工具，逐一对账 41 个支持库和 12 个模块：

- 缺入口：阻断，不自动把聚合测试文件当作多个包的证据；
- 多入口：阻断，要求合并为一个权威入口；
- 无测试：阻断并标记“未覆盖”，不能假绿；
- 测试引用实现目录：阻断。

### 第二步：包级入口

先迁移公开支持库和模块，再迁移适配层 Provider。每个入口可独立执行：

```bash
python3.14 测试中心/运行测试.py --测试包 支持库.核心.类型转换
python3.14 测试中心/运行测试.py --测试包 模块库.文件管理
```

上述命令只运行一个包入口，并写入 `工程缓存/验证缓存/包/` 下的独立证据。

### 第三步：唯一集成入口

```bash
python3.14 测试中心/集成测试/运行集成测试.py
python3.14 测试中心/集成测试/运行集成测试.py --仅变更
python3.14 测试中心/集成测试/运行集成测试.py --包id 支持库.后端.网络请求
```

旧的阶段聚合入口只保留为迁移期兼容诊断，不再作为“每包已验证”的证据来源；迁移完成后
由发布门禁拒绝没有包级证据的阶段缓存。

### 第四步：门禁收口

发布门禁必须检查：

- 每个正式包恰好一个入口；
- 每个入口最近成功证据与包/依赖指纹匹配；
- 集成入口只引用登记入口；
- 未覆盖包、失效缓存、零测试和清理失败均阻断；
- 既有失败仍显示原始包入口和测试名，不被集成汇总隐藏。

## 验收标准

本方案完成的可验证标准：

1. 修改单个支持库时，默认只运行该支持库入口及其明确受影响的公共依赖包，不运行 630 个
   静态契约测试。
2. 修改单个模块时，默认只运行该模块入口和受影响支持库入口。
3. 未修改包且指纹、环境和证据有效时，运行器输出“跳过（证据有效）”，不启动测试进程。
4. 集成测试只启动登记入口；任何未登记测试文件不会被隐式执行。
5. 任一包入口失败时，集成入口非零退出并保留该包的原始失败输出。
6. 本次既有媒体处理失败在迁移后仍能被单独命令稳定复现：不能通过分包改变结果。
