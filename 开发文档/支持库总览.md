# 系统工程平台 · 支持库权威总览

> 本文件是系统工程平台支持库的唯一目录与职责说明。项目总架构、分层边界、验收定义以 `项目说明.md` 为上位权威；本文件只维护支持库的实际盘点、公开能力、调用流程、提供者 边界和资源责任。
>
> 盘点依据：当前工作树各支持库的 `包声明.json`、`能力契约/参数契约.json`、包级入口与说明文件。未在本文件中列出的目录，不得凭目录名称推断为正式支持库。

## 一、实际盘点

当前正式支持库共 **38 个**，公开能力共 **151 项**。按职责分为：

| 类型 | 数量 | 职责 |
| --- | ---: | --- |
| 前端描述支持库 | 5 | 只描述组件、窗口、状态、资源和文件选择，不负责真实渲染 |
| 后端标准库原子支持库 | 14 | 使用 Python 标准库完成文件、文本、数据、文档和资源原子操作 |
| 第三方/系统适配 提供者 | 19 | 将外部库、系统命令、模型或数据库驱动封装为统一能力 |

`模块库/_模板` 是新模块复制模板，不计入正式支持库；模板不能被生产注册表装配。

## 二、支持库在平台单链路中的位置

支持库不直接面向业务流程，也不让调用方直接 import 第三方实现。每个支持库拥有一组原子能力和一份能力契约；跨支持库、跨模块的调用必须经 HTTP 网关和唯一能力调用链，同一个子项内部才允许直接调用；运行核心负责装配、提供者路由和资源治理。

```text
调用方
  → HTTP 网关：能力 id + 契约版本 + 参数
  → 运行核心：注册表查找/版本锁/提供者选择/资源预算
  → HTTP 网关转发到支持库公开入口
  → 标准库原子实现 或 受管 提供者
  → 统一结果：成功/值/错误码/错误说明/可重试/证据
  → HTTP 网关返回
```

第三方或高风险能力的内部链路：

```text
能力契约
  → 支持库公开入口
  → 提供者请求适配
  → 独立进程组或受控本地调用
  → 第三方库/系统命令/模型/数据库
  → 结果转换
  → 退出码/错误码/资源释放证据
```

支持库只负责原子能力；它不能：

- 直接编排文档解析、媒体转写等领域流程；
- 被正式代码绕过公开入口直接导入 `实现/`；
- 自己维护第二套注册表、网关、业务状态或错误码体系；
- 把“包声明存在”冒充真实 提供者 可用；
- 把底层异常、堆栈或凭据直接泄露给调用方。

## 三、统一支持库调用契约

所有跨边界支持库能力都通过 HTTP 和同一结果模型对外表达；同一个子项内部可以直接调用私有函数和热循环：

```text
请求
  请求编号
  能力编号
  契约版本
  参数
  截止时间
  幂等键（需要时）
  资源预算（需要时）

返回
  success
  value
  error_code
  error_message
  retryable
  evidence
  resource_release
```

一次性原子能力的默认流程：

```text
接收参数
  → 校验参数/路径/大小/格式
  → 通过网关调用原子实现或启动提供者
  → 读取返回值/退出码
  → 转换为统一结果
  → 释放临时文件、句柄、进程和提供者
  → 返回结果与释放结论
```

有状态或高成本提供者的流程：

```text
申请执行单元
  → 提供者监督器启动或命中受控缓存
  → 返回不透明 执行单元id/租约id
  → 多次调用能力
  → 显式释放或空闲 TTL 到期
  → 排空/停止/清理
  → 验证进程、端口、临时目录、句柄、显存零残留
```

有状态能力默认采用“一资源一执行单元”：数据库连接、浏览器、模型上下文、动态库、设备会话等由一个受管进程或受控线程独占真实资源，公开入口只返回不透明 `执行单元id/租约id`。连接池、线程池或缓存如果存在，只能是该执行单元内部实现，不能把池对象、连接对象、线程对象或驱动对象暴露给调用方；关闭句柄必须触发排空、资源释放、owner 退出和零残留核对。

## 四、前端描述支持库（5 个）

这些包只输出平台无关的描述模型，不启动窗口、不创建真实控件、不负责渲染。真实前端宿主以后只能通过公开描述模型和运行时适配层接入。

| 包 | 路径 | 功能与具体流程 |
| --- | --- | --- |
| 基础组件描述 | `支持库/前端/基础组件描述` | `创建组件定义` 生成组件 id/类型/属性/空事件列表 → `校验组件属性` 检查必填字段和属性类型 → `声明事件` 追加并去重事件 → 返回平台无关组件字典 |
| 文件选择描述 | `支持库/前端/文件选择描述` | 传入扩展名、多选、起始目录 → 创建文件选择描述 → 校验必填字段和扩展名列表 → 供前端宿主转换为实际文件选择器 |
| 状态描述 | `支持库/前端/状态描述` | 传入窗口 id 和初始状态 → 创建状态及空流转记录 → 每次状态变更按允许流转表校验 → 合法才返回新状态 |
| 窗口描述 | `支持库/前端/窗口描述` | 传入窗口 id/标题/宽高/默认属性 → 创建定义 → 校验字段和尺寸 → 可序列化为 JSON → 反序列化后再次校验 |
| 资源描述 | `支持库/前端/资源描述` | 传入资源 id/类型/来源/引用计数 → 创建资源描述 → 校验引用字段非空 → 交给前端宿主或资源治理层处理 |

前端描述的边界：

```text
业务模块请求窗口/组件描述
  → 描述支持库生成平台无关字典
  → 模块返回描述
  → 项目适配层绑定具体前端宿主
  → 前端核心负责真实渲染
```

标准库原子包的共同资源规则：

```text

原子写入 → 临时文件 + fsync + rename
并发状态 → 资源短锁/CAS，不依赖全局单例
```

### 提供者 统一生命周期

```text
提供者 声明
  → 环境/版本探针
  → 运行核心选择执行策略
  → 按需启动或命中有界缓存
  → 接收一次 HTTP 能力请求
  → 返回值/错误码/退出码
  → 排空并释放句柄、临时目录、端口、进程组、显存
  → 写入调用与释放证据
```

四种终态必须分别验证：

| 终态 | 支持库必须证明 |
| --- | --- |
| 正常完成 | 结果正确；一次性 提供者 已释放；缓存 提供者 有明确 TTL/owner |
| 业务失败 | 稳定错误码；临时文件、连接、句柄不泄漏 |
| 超时/取消 | 真实终止进程组；队列排空；端口和临时目录回收 |
| 提供者 崩溃 | 退出码/信号可见；监督器完成回收；不得向调用方伪造成功 |

## 七、支持库与模块库的依赖方向

```text
前端/业务调用方
  → 模块库公开能力
  → 运行核心唯一能力调用器
  → 支持库包级公开入口
  → 标准库原子实现或 提供者
  → 第三方库/系统命令/模型/数据库
```

禁止反向依赖：

```text
支持库 -X→ 模块库
支持库 -X→ 业务项目
提供者 -X→ 平台权威状态
正式代码 -X→ 支持库实现目录/第三方包
```

同一第三方发行包只能归属一个 提供者；同一原子能力只能有一个能力 id 和一个契约 owner。不同实现若要并存，必须在同一契约下登记为 提供者 策略，不能形成多条业务调用链。

## 八、线程、句柄和有状态资源边界

支持库不得自行发明第二套线程/任务状态系统。线程控制、进程组、执行单元、租约、取消、超时和资源回收由运行核心统一负责；支持库只声明资源需求和提供原子执行动作。

```text
支持库请求有状态能力
  → 运行核心创建唯一执行单元
  → 返回不透明句柄
  → 后续 HTTP 请求携带句柄
  → 同一 owner 内部串行或按契约并发
  → 关闭/超时/崩溃
  → 回滚、排空、join/终止、释放、残留检查
```

数据库支持库可以在 owner 内部使用真实连接或连接池，但必须保证事务固定在同一物理连接；外部只传连接租约。普通小结果直接返回，超出上限才返回受管制品引用。

## 九、验证与维护规则

- `包声明.json` 是包发现入口；`能力契约/参数契约.json` 是对外参数、返回和错误契约。
- `说明/` 是使用说明，不得覆盖契约事实；源码和真实验证优先于 README 宣称。
- 仅导入、仅目录存在、测试预注册或 mock 返回不算生产成功。

- 当前总数和能力总数以本文件开头的现场盘点为准；数量变化时先更新本文件与 `项目说明.md`，再更新导航文档。
