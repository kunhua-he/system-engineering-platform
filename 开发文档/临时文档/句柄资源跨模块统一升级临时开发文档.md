# 句柄资源跨模块统一升级临时开发文档

状态：本轮已按清单实现并通过验证；本文件保留为实施记录，不与正式契约并行定义第二套规则。

## 一、扫描结论

```text
外部 HTTP 请求
  → 本地网关读取 句柄/获取句柄
  → 网关核心构造请求上下文
  → 后端核心调用能力
  → 能力实现只收到 参数
```

已存在：

- `公共契约/句柄体系.py`：资源句柄、读取句柄、修改事务句柄、任务句柄、会话句柄和失效状态；
- `运行核心/权威状态.py`：句柄、租约、资源版本、事务、引用计数和回收证据持久化；
- `运行核心/资源协调/服务.py`：快照读取、修改事务、版本比较、提交、回滚和句柄失效；
- `运行核心/统一网关/本地网关.py`：已经读取 HTTP 请求中的 `句柄` 和 `获取句柄`；
- `运行核心/统一网关/网关核心.py`：成功结果中可提取返回句柄。

当前缺口：

- 后端核心调用实现使用 `实现.调用(**参数)`，没有把请求句柄作为统一受控参数注入；
- 句柄返回依赖每个实现自行把 `句柄` 放进返回字典，网关没有统一创建/校验/续租/关闭资源句柄；
- 没有统一的“资源句柄解析为受管输入”的公开调用器，上传模块和分析模块无法只凭句柄复用同一批资源；
- 没有统一的资源句柄生命周期动作（状态、续租、关闭、过期、跨项目/所有者拒绝）HTTP 契约；
- 现有文档描述了句柄原则，但没有给出“上传批次 → 分析模块”的可执行公共契约。

## 二、本轮只实现一个模型

句柄不是文件路径，也不是 Python 对象；它是网关签发的不透明查询引用，不把模块内部对象跨边界共享：

```text
资源句柄
  → 资源id + 版本/快照 + 所属项目/所有者 + 租约
  → 资源注册表校验
  → 网关把句柄解析为本次模块内部 CRUD 所需的精准查询条件
```

一次性能力默认不产生句柄。只有能力契约声明 `资源句柄返回` 或调用方明确请求保持资源时，才签发句柄。

## 三、统一公开操作

所有操作仍然进入 `POST /网关/请求` 或 `POST /网关/调用`，不为上传、分析或文件资源增加第二个网关：

| 操作 | 必填参数 | 返回 |
| --- | --- | --- |
| `资源状态` | `句柄` | 有效/已失效、资源类型、版本、租约截止；不返回真实路径 |
| `资源续租` | `句柄` | 新租约截止时间 |
| `资源关闭` | `句柄` | 关闭和回收结果；重复关闭幂等 |
| `调用能力` | `能力id`、业务参数；资源能力另含 `句柄` | 统一结果；资源能力可返回新句柄 |

每个模块仍然内置自己的增删改查、状态机和数据 owner；能力参数中如需定位某一批次，只使用 `资源句柄` 字段作为精准查询条件。模块不得接收真实路径、文件对象、数据库连接、游标、进程号或第三方对象作为跨边界资源引用。

## 四、上传/分析最小流程

```text
上传.创建批次
  → 资源句柄
上传.加入文件（资源句柄，文件内容或受管制品引用）
  → 批次计数/摘要
上传.完成批次（资源句柄）
  → 可读资源句柄
分析.执行（资源句柄，分析参数）
  → 分析结果或结果制品引用
资源.关闭（资源句柄）
  → 句柄失效、临时目录/索引/租约回收
```

下一个模块收到句柄后，在自己的 owner 内执行一次精准查询，不重新扫描全部物理目录。网关可以提供通用状态/结果查询，但不代替模块业务 CRUD。句柄只能在项目、所有者、版本和租约有效时使用；过期、跨项目、跨所有者、版本冲突和资源不存在必须明确失败。

## 五、实施清单

1. 在统一调用上下文增加受控句柄字段，并由网关注入能力调用；能力实现只能通过公共上下文/资源查询器读取。
2. 增加唯一资源句柄服务：签发、解析、状态、续租、关闭、过期回收和回收证据；它只维护外部引用，不实现模块业务 CRUD。
3. 在网关增加 `资源状态`、`资源续租`、`资源关闭`，沿用统一结果和现有权限/限流/审计链；状态查询只返回通用状态，不返回模块私有数据。
4. 增加资源句柄参数类型与错误码：句柄不存在、句柄已失效、租约过期、跨项目拒绝、跨所有者拒绝、资源版本冲突。
5. 增加一个最小受管文件批次能力作为真实验证样板，验证创建、加入、完成、跨能力读取、关闭和异常回收；不把上传业务流程复制到其他支持库。
6. 更新支持库总览、模块库总览、底座能力命令规范、项目说明和网关调用示例；明确“模块内置 CRUD，句柄只是精准查询键”，删除与最终契约冲突的旧句柄说明。
7. 只运行受影响的句柄/资源/网关测试，随后运行一次正式发布门禁；任何“返回句柄但无法解析或释放”的路径必须阻断。

## 六、验收标准

- A 模块返回资源句柄，B 模块只传资源句柄即可在自己的 owner 内精准查询 A 标识的批次；
- B 不访问 A 的实现目录、真实临时路径或第三方对象；
- 句柄查询不替代 A/B 模块自己的增删改查和状态机；
- 句柄状态、租约、权限和版本校验在网关统一发生；
- 关闭、过期、异常、进程死亡后句柄不可复活，资源无残留；
- 默认不拿句柄时仍保持一次性调用和自动释放；
- 同一资源能力只有一个公开能力 id 和一份参数/返回契约；
- 真实调用、错误分支、跨所有者拒绝、版本冲突和零残留均有测试证据。
