# 43 · 文件级占用租约落地（多会话抢同一文件）

## 阶段一：开始前

### 问题

多个会话（人 + 智能体）在**同一个仓库**里同时开发时，只有**能力级**占用租约（`claim_capability`），**文件级没有**。后果：

- A 会话读旧内容 → B 会话改 → A 写回 → **B 的改动被静默覆盖**；
- 而且通常改到一半才发现，返工成本高。

`development_start` 收到的"修改路径"当前**只用于生成验证计划**，不登记占用、不做冲突检测。

### 现状澄清（写方案前先核实，避免照搬别的平台）

- 本仓 8766 管理端真实注册 **45 个工具**，其中**没有** `file_operation` / `file_occupancy_query` / `tool_job_submit`（那些是华世王镞_v3 的工具）；`文件系统支持库.文本补丁` 能力存在但**未暴露为 MCP 工具**。原《多会话并行开发规约》引用了 v3 工具名，已按本仓真实工具面改正。
- 本仓**有两套占用机制**：
  1. `平台控制面/能力目录/服务.py` → DB `占用租约` 表，**有**心跳/过期/回收（供 `统一入口` 创建组件用）；
  2. `MCP工具箱/支持库协作.py::登记能力占用` → `工程缓存/能力占用/*.json`，**无**心跳/过期（供 `claim_capability` 用）。
- 真实库 `工程缓存/平台控制面/权威状态.db` 已在 **1.4.0**，`占用租约` 表（含活跃唯一索引 `ON 占用租约(能力id) WHERE 状态='活跃'`）**已存在**。

### 方案：复用 DB `占用租约`，零建表、零迁移

新增 `MCP工具箱/文件租约.py`，把文件当租约主体塞进**现成的** `占用租约` 表：

- `能力id` 列 = `"文件::<仓库相对路径>"`，`领域` 列 = `"文件"` → 与真实能力租约键空间隔离，互不污染；
- 四动作 **原样委托** `能力目录.服务`：`申请占用` / `续租` / `释放占用` / `回收过期占用`；
- **全成功才开工**：一批路径里任一被占 → 已成功的立即释放并整体拒绝，回带占用者与占用开始时间；
- 过期回收同时覆盖能力租约与文件租约，**不会死锁**。

接线（`MCP工具箱/项目服务.py`）：

1. `development_start`：拿到"修改路径"后先批量申请文件租约，成功才返回上下文；失败返回拒绝。
2. `delivery_closeout`：成功后自动释放本工作包持有的全部文件租约。
3. 新增工具 `file_lease`（查询 / 续租 / 释放 / 回收过期），补上"查询文件占用"这一缺环。

### 同批一并激活

- **B8 收口指纹**：修复**已在源码**（`项目服务.py::_运行验证` 218-229 行已同时写 `工作区指纹` 与 `指纹`，回归测试 `测试_协作状态.py::test_生产者形状证据可收口且旧形状被阻断` 已补），只是卡在"改了入口模块、必须重启 8766 才生效"。本次一并激活。
- **热加载边界**：新增工具（`file_lease`）与入口接线**不在**热加载覆盖范围（热加载只覆盖"改实现"，且不重载入口自身），故本批**必须重启一次 8766**；已按纪律凑批，不随改随重启。

### 调用方式

`file_lease` 工具（MCP 协议名，中文名「文件占用租约」）：

```
operation = "查询"      可选 paths=["a.py"]        → 列出活跃文件租约（不传 paths 列全部）
operation = "续租"      lease_ids=["...","..."]    → 长任务刷心跳
operation = "释放"      lease_ids=[...]  evidence="..."  → 手动释放
operation = "回收过期"                              → 扫掉心跳超 300 秒的占用
```

开工与收口**不需要手工调 `file_lease`**：`development_start` 传 `modified_paths` 即自动申请，`delivery_closeout` 成功即自动释放。

**实测二：B8 收口全链路（开工→登记→反馈→验证→收口）**

`development_start`（2 路径）→ `register_task` → `mcp_feedback` → `verify_and_record`（`测试中心.MCP工具箱.测试_文件租约`，退出码 0）→ `delivery_closeout`：

- 开工即申请到 **2 条**文件租约；
- 验证证据**同时携带** `工作区指纹`（64 位 `0782a958…`）与 `指纹`（16 位 `5a58b12e135b9974`）→ **B8 算法不一致已消除**；
- 收口返回 **`成功: true`**（不再是 `EVIDENCE_MISMATCH`），生命周期「完成」，并回带 `文件租约释放: {释放数量: 2}`；
- 收口后查询文件占用 **0 条** → 自动释放闭环成立。

**顺序坑（记录备查）**：`verify_and_record` 有前置反馈门禁，**必须先 `mcp_feedback` 再 `verify_and_record`**，反过来会被拒（「本次任务尚未提交 MCP 使用反馈，不能记录成功验证证据」）；`delivery_closeout` 的 `五件套路径` **不能为空**，否则 `REGISTRATION_FAILED`；未 `register_task` 则收口报 `TASK_NOT_FOUND`。完整链路：**开工 → 登记 → 反馈 → 验证 → 收口**。
