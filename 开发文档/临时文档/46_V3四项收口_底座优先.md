### 保留理由（**不是没做，是判据不足**）

**① 数据库连接池**——两个前置未决，任一个猜错都要返工：

1. **同步 / 异步分叉**（审计「未解疑问 1」）：V3 现用 SQLAlchemy **async** engine（`asyncpg`/`psycopg` async）。底座要给的池必须与之一致，否则 V3 侧不是「一个文件薄壳化」而是**2416 处调用点改造**。底座 `平台控制面/提供者/数据库提供者.py` 的现成池是**纯标准库同步池**（`queue.LifoQueue`），抄过来直接给 V3 就是形态不符。→ **要华哥一句话：底座给同步池（V3 侧转接）还是补异步池（底座新增异步提供者）**。
2. **本机无 PostgreSQL 服务，做出来无法验证**：实测无 server 进程、PgBouncer 6432 空转、`pg.log` 停在 2026-08-22。底座铁律「不信任自述，必须现场实测」，**不可验证的池 = 不可交付**。→ 且启动/修复他的数据库服务属共享基础设施，不在本批授权内。

**② 能力注册表**——硬约束未解除，动它必炸：

- 决策 `0007` 原文：引用面 **127 处**，硬删即 127 处直接炸；收口顺序固定为「① 补底座原子能力 → ② 逐模块薄壳化 → ③ 停止注册 → ④ 机制层合并删除」。
- 其前置清单（持久化事件总线 / 上下文压缩 / 记忆蒸馏 / 图像生成 / SSRF 校验 / 代码语法索引 …）是**跨月能力群**，非本批可闭合。**机制四件套一行未动**，符合 0007。
