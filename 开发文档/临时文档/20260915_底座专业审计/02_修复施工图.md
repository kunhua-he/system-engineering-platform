## 一、并发与资源现实（实测）

| 项 | 值 | 来源 |
|---|---|---|
| Hermes 子代理并发上限 | **300** | `~/.hermes/config.yaml:464 max_concurrent_children: 300` |
| 子代理层深 | 3 | 同上 `max_spawn_depth: 3` |
| 单子代理硬超时 | 1800 秒 | `child_timeout_seconds: 1800` |
| 本机 | 32 核 / 96GB，load ~9.6 | `sysctl` / `uptime` |

**结论：并发不靠 CPU 决定，靠「文件域是否互不重叠 + 是否共享外部资源」决定。**
本轮实测的上限约束：
- 固定端口（40007/8766）与发布指针、LibreOffice/FFmpeg/Tesseract 等外部工具 → **必须串行**；
- 同一包内文件、`能力定义.json`/`包声明.json`/`完整性摘要.json`/`依赖契约.json`、网关表、门禁文件 → **必须串行**；
- 不同包/不同目录的独立文件 → **可并行**。

**建议并发度**：每批 **6–8 路**（子代理），必要时上 10–12 路；不按 300 上限满跑，因为收口要人工现场验收，且过高的并发会把「共享文件冲突」的排查成本放大。

### 共享文件热点（实测：按 15 份报告的文件提及频次统计）

| 共享文件 | 被几份报告提到 | 处置 |
|---|---|---|
| `能力定义.json`（全仓 106 份） | **9 份** | 每包**单一属主**；包级产物串行收口 |
| `开发工具/发布门禁/运行发布门禁.py` | **9 份** | 串行单点（批次5 独占） |

| `包声明.json`（全仓 112 份） | 8 份 | 随包串行 |
| 各包 `__init__.py`（注册元数据） | 8 份 | 随包串行；**网关别名表另属串行** |
| `MCP工具箱/项目服务.py` | 7 份 | 批次1 内⑥⑦⑧**组内串行**（同文件） |
| `运行核心/依赖防火墙.py` | 5 份 | 串行单点（批次5） |
| `后端核心/后端核心.py` | 4 份 | 串行单点 |

→ **并发硬规则**：同一行内的文件，任一时刻只允许一个执行者；跨批次的收口产物（摘要、依赖锁、契约版本、注册表）统一放在**该批末尾串行做**。

```text
批次0  冻结全局口径（必须最先做，全平台一致性的前提）

       → ①在 进程管理 包、②③在 网络通信/出站安全、④在 文件系统/文件操作、⑤在 系统核心/环境变量、
         ⑥⑦⑧在 MCP工具箱（同目录多文件，需组内串行）

批次2  运行态生效（串行，单点）
       重启 40007（确认无在跑任务）→ 重启 8766 → 重跑行为对照探针（重试调度 实际错误码 应返回 false）

批次3  资源与有界（4 路并行 + 1 串行）
       26 个 SQLite 连接点按包分 3 路（会话存储 / 工具执行 / 检查点恢复）
       事件日志有界化 1 路；权威状态回收器接线 = 串行（与批次4 共享 权威状态.py）

批次4  契约与注册口径（按包并行，网关表串行）
       注册元数据类型名/必填补齐（多包，各自独立）→ 网关别名表 + `声明一致` 校验器接线（串行）

批次5  门禁接线与判据修正（串行，共享门禁文件）
       依赖防火墙补技能库与第三方清单 / 发布门禁补接 复用审计+平台控制面防火墙 /
       反向破坏验证接线 / 漂移检测与能力定义编译器加 __main__ 防护

批次6  测试体系（按文件并行 + 2 项串行）
       僵尸测试修复、假绿用例改写（每文件一路）→ 聚合入口重建 + 全量可导入性检查（串行）

批次7  死代码/未接线（并行删改 + 串行收口）
       零引用模块逐个「删 or 接线」→ 摘要级联重算 + 依赖锁重生成（串行）

批次8  文档与结构（串行，唯一事实源）
       项目说明.md 当前事实重写 + 未完成事项.md 已修条目删除 + 口径表 / 制品仓库 12 份收敛 +
       三套摘要权威化 / __pycache__+空目录清理挂到构建收尾

收口   一次全量验收（串行，只跑一次）
       重编译 → HTML 黑盒全量 → 发布门禁 → 真实 HTTP 探针复核 → git 提交
```

**串行铁律**：批次0、2、5、8 与最终收口 **必须单线**；其余批次内部按「文件域不重叠」并行。

## 三、每类修复的验收口径（分层，不跑全量 unittest）

| 层级 | 用在 | 命令 |
|---|---|---|
| L1 定向编译/契约 | 改任何包内文件后 | `python3.14 -m py_compile <受影响文件>` + `开发工具.契约编译.能力定义编译器`（只读比对）+ 漂移 unittest |
| L2 定向 unittest | 改测试或被改包的测试 | `python3.14 -B -m unittest 测试中心.<受影响模块>` |
| L3 真实 HTTP 探针 | 网关/能力行为类 | 经 40007 `POST /网关/调用` 的正反例（含类型拒收、句柄失效、错误码） |
| L4 HTML 黑盒全量 | 每批合并后 | `python3.14 -m 开发工具.HTML验证.验证器 --制品 <编译产物> --并发 32` |
| L5 发布门禁 | 只在上线前 | `python3.14 开发工具/发布门禁/运行发布门禁.py`（只跑一次） |

**每个包内文件改动 → 必须同步**：包版本 → 重编译契约 → 摘要级联 → 依赖锁，否则门禁必红（已踩过的坑）。
