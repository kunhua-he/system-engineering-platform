## 一、问题：父会话报的「文本型不拒非文本」没有复现，真因不是文本型

只读定位 + 40007 真实调用（凭证 `html-blackbox-verifier`，进程为 HEAD 代码）：

| 真实调用 | 结果 |
|---|---|
| `重试调度` `实际错误码=123`（整数，声明文本型） | **HTTP 400** `参数不合法：…参数 实际错误码 必须是 文本型` |
| 同上 `12.5` / `true` / `null` / `["x"]` | 全部 **HTTP 400** 同口径 |
| `重试调度` `实际错误码="123"`（**文本**） | **HTTP 200**，`是否重试=false`，原因「白名单未命中：实际错误码 123…」——**这是正确的** |
| `重试调度` `重试模式=1`（声明文本型） | **HTTP 400** 必须是 文本型 |
| `任务提交` 同一能力传整数 | **HTTP 400**（两个入口同一套规则） |
| `数据操作支持库.类型转换.整数转文本` `整数="不是数字"` | **HTTP 400** 必须是 整数型 |
| `重试调度` `最大重试次数="三"` | **HTTP 400** 必须是 整数型 |

结论两条：

1. 「文本型漏校 / 静默当文本接受」在 HEAD **不成立**：报文里的 `实际错误码=123` 原样是字符串 `"123"`，是合法文本，返回 200 正确。**假发现的来源是审计探针自己的期望写错了**（`验收探针集.py` 第 66 行把合法文本标注成「类型错」，期望 400）。已把该行改成「合法文本 → 应 200 且不命中」，并**补一条真正的负向探针**（整数 `123` → 应 400）。
2. 反方向（整数型 ← 文本）本来就拒，不代表正方向就对称——**对称性要按「声明了类型是不是都校验」来量**。

## 二、真裂缝：网关类型表只有 7 类，其余类型 fail-open

`公共契约/基础类型/类型表.py` 的正式类型表有 **16** 类；网关校验表只覆盖 7 类
（逻辑型/文本型/列表型/字典型/JSON值型 + 4 个数值型），**声明了却谁都不校验**的有：
`字节集型 / 数值型 / 空值型 / 资源引用型 / 句柄型 / 日期时间型 / 结果型 / 字节型`。
运行时注册里真实存在的参数槽位（静态扫描，`支持库/**/__init__.py`）：

- `字节集型` 17 处：`图像处理支持库.图像解码.*`（`字节`）、`OCR识别支持库.OCR识别.识别图片`（`图片字节`）
- `数值型` 3 处：`并发控制支持库.占用容量.等待秒`、`lane完成.退避秒`、`主体串行完成.退避秒`
- `空值型` 1 处：`大语言模型支持库.模型连接器.注册本地进程.进程对象`
- `资源引用型` 1 处：`OCR识别支持库.OCR识别.识别图片.取消事件`
- `句柄型` 1 处：`前端/桌面宿主.调用插件.调用函数`

**500 的真实证据**（40007 当前进程，改前代码）：

```
并发控制支持库.占用容量  参数 {"闸门名":"x","等待秒":"abc"}
→ HTTP 500  错误码=占用失败  说明=could not convert string to float: 'abc'
```

类型不符没在边界拦住，直接把脏值丢给实现，实现抛 `TypeError`，最后露成 500——
既不是 `参数不合法` 也不是 4xx，正是「两端不对称」的下游代价。

## 三、修法：唯一校验点等宽 + 契约编译薄委托

1. **唯一校验点**：`运行核心/统一网关/网关核心.py` 抽出模块级 `校验能力参数(能力id, 声明参数, 参数)`，
   `网关核心._能力参数错误` 退化成「查注册表拿声明 + 委托」的薄壳（签名与返回不变）。
   - 类型表补成与 `类型表.py` **等宽**：新增 `字节型 / 字节集型 / 日期时间型 / 资源引用型 / 句柄型 / 结果型 / 空值型 / 数值型`。
   - **未知类型 fail-closed**：报 `参数不合法：…参数 X 声明了未知类型 Y`，不再静默放行（注释里早就写了这个意图，实现没落地）。
   - **未声明类型不拦**（没有类型承诺）；实测全仓 0 个参数缺 `类型` 字段。
   - `字节集型` 收 `bytes/bytearray/memoryview`、冻结对象 `{"类型":"字节集型","base64":…}` 或 base64 文本——与 `本地网关._解码JSON值`（还原成 bytes）和实现层口径一致。
   - **显式 `null` 不等于「未提供」**：与文本型既有口径一致，要省略就别传这个键。
2. **契约编译侧同源**：`开发工具/契约编译/契约编译器.py::生成网关参数校验` 原来自带一套
   `整数/文本/逻辑型` 三类型表（还用历史短名）——等于「每个能力各写一遍校验」，正是裂缝来源。
   已改成生成**薄委托**，调 `校验能力参数`，不再有第二套类型表。
   - 踩坑记录：生成的是 **Python** 源码，声明必须用 `repr`，用 `json.dumps` 会把 `true/false/null` 写进去，生成的文件一 `exec` 就 `NameError`（轻检第 3 段抓到）。
