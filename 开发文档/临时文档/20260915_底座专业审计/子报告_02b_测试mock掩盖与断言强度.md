## A. mock 掩盖生产路径

### A.0 全量分布

- patch 调用点 **183** 个，分布在 **41** 个测试文件。
- `mock.patch.object(...)` **97** 个（占 53%）—— 这是**直接改被测对象自己的方法**，风险最高的一类。
- `autospec` / `create_autospec` / `spec=`：**0 个**。所有 patch 都是「裸桩」，签名漂移、参数改名、返回值结构变化都不会让测试红。
- 其中 patch 目标落在生产模块的 **40** 个（下表全列）。

### A.1 阻断级：patch 掉被测对象自身 → 断言 mock 被调过

**位置**：`测试中心/运行核心/测试_外部版本探针统一.py:58, 68, 134, 145, 170, 179, 192, 197`（同文件共 9 个 patch 点）

- L58 `test_探测外部应用版本经系统探针`：`mock.patch("支持库.适配层.系统探针.检查系统工具", return_value=_成功探针("26.2.2.2"))`，然后
  `self.assertEqual(探针函数.call_count, 2)`。
- L68 `test_环境指纹详情含统一版本`、L134 `test_探针超时明确失败`、L145 `test_退出码非零明确失败`、L170/179 `test_探针版本漂移证据失效`、L192/197 `test_探针失败后证据失效不伪造` 同型。
- 该文件类 docstring 自己写着：**「探测外部应用版本 经 系统探针 获取版本（patch 生效即证明）」**（L53-54）——把「patch 打进去了」当成测试通过的条件，这是本类问题的自我承认。

**为什么是假绿**：
`检查系统工具` 是**生产探针的入口本身**（同一个文件里 L184 `test_真实退出码非零失败` 直接调它，说明它就在生产命名空间）。把它替换掉之后，测试验证的只剩「环境指纹 会把探针返回值塞进结果字典」这一层**格式化逻辑**。
- 探针真的超时/真的拿不到版本/返回结构变了/命令行参数拼错了 —— 只要桩返回的是 `探针结果(True, ...)`，测试就是绿的。
- `assertEqual(探针函数.call_count, 2)` 是**纯 mock 调用计数**：它只证明代码调了两次被替换掉的东西，不证明这两次调用带了正确的工具名、正确的命令行、正确的超时。
- `autospec=False` 意味着桩连签名都不校验：生产把 `检查系统工具(工具名, 命令, 超时秒=...)` 改成 `(工具名, 命令, 超时秒, 重试次数)`，这 8 个测试全绿。
- L122 `test_工具缺失明确失败` 里 `self.assertFalse(值.startswith("/"))` 是**恒真装饰性断言**：任何不以 `/` 开头的字符串（含伪造的纯数字版本号）都通过。注释写的是「不以路径冒充版本」，实际拦不住任何非路径型的伪造。

**不能发现的真 bug**：任何发生在 `支持库/适配层/系统探针` 内部的缺陷（真实命令拼写、退出码解析、超时实现、编码处理），以及调用点参数传错。

**怎么修**：
1. 保底保留 L184 那种**真实调用**用例，并把本文件的 patch 只用于「构造探针返回值的各种边界」，不要 patch 探针本体；
2. 若要 patch，必须 `autospec=True` 并额外断言 `探针函数.assert_any_call(...)` 的关键参数（工具名/命令/超时），把「调了」升级为「怎么调的」；
3. 把 `assertFalse(值.startswith("/"))` 换成 `assertRegex(值, r"^失败:")` 或显式失败标记集合成员判定。

### A.2 阻断级：把「删除动作」本身 mock 掉，再断言 mock 没被调用

**位置**：`测试中心/第一批维修/测试_统一编译器.py:61-77`（L69 与 L70 两个 patch 点）

```python
with mock.patch("开发工具.项目编译.项目编译器.校验输出目录", side_effect=ValueError("最终边界变化")) as 校验:
    with mock.patch("开发工具.项目编译.项目编译器.shutil.rmtree") as 删除:
        with self.assertRaisesRegex(ValueError, "最终边界变化"):
            _准备输出目录(项目, 输出)
校验.assert_called_once_with(项目, 输出)
删除.assert_not_called()
self.assertTrue(哨兵.is_file())
```

**为什么是假绿**：测试名是「**rmtree 前执行最终校验且失败时不删除**」。
- `shutil.rmtree` 被替换成 mock，测试期间**不可能发生真实删除**，所以 `哨兵.is_file()` 恒真、`删除.assert_not_called()` 只能证明「代码没走到那个名字的对象上」。
- 如果生产代码改用 `os.remove` / `pathlib.unlink` / `from shutil import rmtree as _r` / 自己写递归删除 —— 真实删除会发生，但 `删除.assert_not_called()` **仍然通过**，哨兵文件也正好在临时目录里被真删了却不影响断言（`self.assertTrue(哨兵.is_file())` 会红，这点救了它一半；但若生产改成「先删子文件再告警」就会漏）。
- 更要命的是 `校验输出目录` 也被 patch 成 `side_effect=ValueError`：**「最终校验能拦住」这件事本身没被验证**，只验证了「校验抛错时调用方不往下走」。
- 另有一个**测试副作用**：`mock.patch("...项目编译器.shutil.rmtree")` 会改动 `shutil` 模块对象上的 `rmtree`，**对整个进程全局生效**；测试块内若发生异常退出顺序异常，屏蔽范围可能外溢到其它用例。

**怎么修**：不 patch `shutil.rmtree`，改用**真实的临时目录 + 真实删除**，断言「哨兵文件确实还在磁盘上」；把 `校验输出目录` 的 patch 换成构造一个**真实会触发 `ValueError` 的输入**（该文件 L40-60 已有这种真实边界用例，可以复用同一套夹具）。

### A.3 重要级：patch 生产「流式生成对话」，测试名却写「真实」

**位置**：`测试中心/第一批维修/测试_节点M2_40007流式网关接线.py:70, 97, 128, 159`（`from ... import patch` 直接 patch 生产符号）

- L70 `test_同一40007服务返回真实SSE增量和完成事件`：`patch("支持库.后端.大语言模型支持库.模型连接器.流式生成对话", side_effect=假流式生成对话)`，桩里手写 yield 三个事件；断言 `内容` 里含 `event: 增量事件`、`"文本":"你"`、`模型调用.call_count == 1`。
- L97 `test_上游错误按失败终态返回且不调用普通生成`、L128 `test_生成参数经HTTP透传到流式连接器`、L159 `test_不传生成参数时不向下传这四个键` 同型。

**为什么是假绿**：
- 名字里的「**真实**SSE」只对网关这一侧成立；**模型连接器这一侧是桩**。生产 `流式生成对话` 真实实现里的事件字段名（`类型`/`文本`/`完成原因`）与桩完全由测试作者手写，**生产改名或改结构不会让这些测试红**——因为桩是手抄的，不是从生产导出的契约。
- L128「生成参数经HTTP透传到流式连接器」这句断言的是**当次 mock 收到的参数**（在桩函数体里 `assertEqual(参数[...])`），**没有真实验证 HTTP body**。P2 报告若声称「流式链路端到端验证过」，这里给不出证据。
- 4 个用例全是桩，**没有任何一条走真实 模型连接器 的流式路径**。

**怎么修**：加一条真正启动本地 HTTP 假后端（`http.server` 起在临时端口）+ 真实 模型连接器 的端到端用例；至少补一条 `真实 流式生成对话 的产出事件字段集 == 契约字段集` 的契约一致性测试，让桩与生产绑定。

## B. 只验证导入 / 形状（无真实调用）

判定口径：测试体内断言只有 `hasattr` / `callable` / `isinstance` / `inspect.*`，且**没有对被测对象的真实调用**。共 8 条命中，其中 **5 条真实调用数 = 0**。

| 重要 | `测试中心/模块库/测试_媒体转写.py:331` | `test_公开入口导出检查可用性` | `assertTrue(callable(入口函数))` | **0** |

**原样证据**（`测试中心/支持库/测试_浏览器自动化支持库.py:64-68`）：
```python
def test_包入口不暴露Provider实现对象(self) -> None:
    from 支持库.后端 import 浏览器自动化支持库
    self.assertFalse(hasattr(浏览器自动化支持库, "浏览器自动化提供者"))
    self.assertTrue(callable(浏览器自动化支持库.注册能力))
```

**为什么是假绿**：`callable(X)` 对**任何函数对象、任何抛异常的函数、任何返回 `None` 的桩**都为真。
- 生产把 `注册能力` 改成 `def 注册能力(): raise NotImplementedError` 或 `def 注册能力(): pass`，`test_公开入口导出检查可用性`（`媒体转写.py:331`）与 `媒体转写.py` 里同型入口测试**全绿**。
- `测试_包入口不暴露Provider实现对象` 的名字承诺的是「不暴露」，但 `hasattr` 只检查**一个写死的属性名**；生产换一个属性名暴露实现对象（例如 `_提供者`、`提供者类`），测试照样绿。
- `测试_模型协议别名.py:131` 的 `assertIsInstance` 只校验容器类型，不校验「别名表与连接器取值一致」这个名字承诺的**值一致**。

**怎么修**：
1. 形状测试要么删，要么升级为「导入 + **真调一次** + 断言返回值关键字段」（本仓大量文件已有此范式，可抄）；
2. `hasattr` 白名单式反断言改用 `assertEqual({n for n in dir(模块) if not n.startswith("_")}, 预期公开名集合)`，把「不暴露」变成可枚举；
3. 加一条门禁：`测试中心/` 内凡测试体 `assertTrue(callable(...))` 且无其它真实调用的用例，计入待修清单（本次已用脚本扫出，见「本次实际跑过的命令」）。

## C. 测试名与断言不符

**口径**：抽出测试名里的强主张关键词（拒绝/禁止/不存在/缺失/失败/阻断/回滚/幂等/并发/超时/归档/删除），比对身体里的真假期望。
命中「名字含强主张 + 存在弱断言」**188 条**，逐条读不现实，以下给**已逐条读过的典型**与**判定规则**。

判定规则（从弱到强）：
1. **最弱（阻断）**：名字声称 A 被拒绝/被拦截/失败，身体里**根本没调用 A 的生产路径**，而是在测试里重写一遍逻辑再断言自己的重写 —— 见 C.1。
2. **次弱（重要）**：名字声称拒绝/失败，断言只到 `assertTrue(结果.成功)` 这一层布尔标志（且 `成功` 字段由生产自己填）—— 生产把 `成功` 恒设为 `True` 也能绿；本类在 `测试中心/平台控制面/` 与 `测试中心/支持库/测试_*(提供者).py` 里成片出现（如 `测试_制品与资源.py:34,54,89,97,124,192,203`、`测试_补修阻断.py:66,223,251,269`、`测试_文档生成.py:115,177,213,253,288,307`）。
3. **最弱装饰（建议）**：`assertNotEqual(值, "未知")`、`assertFalse(值.startswith("/"))` 这类**语义注释型反断言**，拦不住任何真实伪造。

### C.1 阻断：断言对象是测试自己的重写，生产拒绝路径从未被调用

**位置**：`测试中心/加载器/测试_加载器.py:36-45`

```python
def test_重复包id被拒绝(self):
    发现 = 发现全部(系统根 / "支持库", 系统根 / "模块库")   # ← 结果被丢弃，只为了拿 发现结果 类型
    from 运行核心.加载器.包发现.发现器 import 发现结果
    结果 = 发现结果()
    包1 = 从字典构建({...,"包id": "重复包",...})
    包2 = 从字典构建({...,"包id": "重复包",...})
    结果.声明列表 = [包1, 包2]
    包id出现 = {}
    for 声明 in 结果.声明列表:
        包id出现[声明.包id] = 包id出现.get(声明.包id, 0) + 1
    self.assertTrue(任何冲突 := any(次数 > 1 for 次数 in 包id出现.values()))
```

**为什么是假绿**：
- 断言的是**测试自己写的 `包id出现` 计数逻辑**——两个同名 `包id` 必然让 `any(次数 > 1)` 为真，这条断言**数学上不可能为假**。
- 生产的「重复包 id 被拒绝」路径（`发现全部` 真扫到两个同 id 包时应报错）**一次都没被触发**：`发现 = 发现全部(...)` 的返回值在函数体里**从未被使用**。
- 删掉生产 `发现器` 里所有重复检测代码，这条测试**依然绿**。这是本报告里最纯的假绿。

**怎么修**：用 `tempfile` 造一个迷你系统根，写两个包声明同 `包id`，调 `发现全部(迷你根/"支持库", 迷你根/"模块库")`，断言 `发现.成功 is False` 且 `发现.问题列表` 里含「重复包id」。同文件 `测试中心/加载器/测试_装配锁与幂等.py:17-190` 已有现成的「迷你系统根 + 写临时包」夹具，可直接复用。

### C.2 阻断：测试名承诺唯一性，身体里没有任何唯一性断言

**位置**：`测试中心/加载器/测试_加载器.py:31-34`

```python
def test_能力id唯一(self):
    发现 = 发现全部(系统根 / "支持库", 系统根 / "模块库")
    self.assertTrue(发现.成功)
```

**为什么是假绿**：名字是「**能力id唯一**」，断言只有「发现成功」。
- 生产出现两个包声明同一 `能力id` 时，只要不再抛异常（比如改成「后者覆盖前者 + 记警告」），`发现.成功` 仍可能为 `True` → 测试绿，**能力 id 被静默覆盖**。
- 这条测试能红的唯一情形是「发现失败」，与「能力 id 是否唯一」**没有任何对应关系**，属于典型的「名字比断言大」。

**怎么修**：断言 `len({(声明.包id, 能力.能力id) for 声明 in 发现.声明列表 for 能力 in 声明.能力})` 与其扁平原长度相等（或断言生产给出的冲突列表为空）。**注意**：这条修复会立刻暴露真实数据 —— 需要先跑一次确认当前仓库是否真的唯一（本次未跑，列入「未确认项」）。

### C.3 重要：名字含「拒绝/失败/阻断」，断言只到布尔 `成功` 字段

**位置示例**（成片）：
- `测试中心/平台控制面/测试_制品与资源.py:89` `test_未签名包拒绝安装` —— 这一条**实际写了有价值的断言**（`assertFalse(安装成功)` + `assertIn("未签名", 消息)`），是本类里较好的；但同文件 L34 `test_包仓库拒绝覆盖不可变版本` 的断言是 `assertTrue(成功)` / `assertTrue(成功2)`，**未对第二个「成功」的语义做负面断言**。
- `测试中心/公共契约/测试_句柄资源预算.py:16` `test_绑定资源超过上限拒绝`：弱点 `assertTrue(成功)`，而该文件 L37 才出现真实值断言 `assertEqual(体系.回收证据表[0]['句柄id'], 10)`。
- `测试中心/平台控制面/测试_工作包11_消费者契约注册表.py:70,79,88,98,108,117`：6 条 `test_*漂移导致门禁阻断`，断言均为 `assertTrue(结果['数据']['是否阻断'])` —— **只断言「是否阻断」这一个布尔位**，不断言**哪一项漂移被识别出来**、错误码是什么。生产把「是否阻断」改成「只要有一个消费者不匹配就置 True」也能绿，而漏报/误报的具体漂移类型无法被发现。
- `测试中心/支持库/测试_文档生成.py` 有 **5 个同名** `test_最小有效文件与签名`（L177、L213、L253 等，分布在不同的 `TestCase` 类里），每个都只断言 `assertTrue(结果.成功)` —— **同名不同类，读测试报告时无法区分是哪一条**，且断言强度统一为最低。

**为什么是假绿**：`结果.成功` / `结果['成功']` / `结果['数据']['是否阻断']` 都是**生产自己填的布尔字段**。一个「永远填 True」或「填错语义」的实现无法被这类断言发现；测试实际验证的是「字段存在且为真」，不是「拒绝/阻断逻辑正确」。

**怎么修**：负面场景必须断言**可区分的结构**——错误码（`assertEqual(结果.错误码, "未签名")`）、问题列表内容（`assertIn("漂移字段: 超时秒", 结果.问题列表)`）、以及**副作用未发生**（目标文件/注册表项确实不存在）。本仓已有正确范式可抄：`测试_制品与资源.py:97` 之后、`测试_工作包08_可信仓库元数据.py:51/72` 的多层断言。

### C.4 建议：装饰性反断言

- `测试中心/运行核心/测试_外部版本探针统一.py:126-129`：注释「失败标记不是伪造版本」，断言 `assertNotEqual(值, "未知")` 与 `assertFalse(值.startswith("/"))`。前者只排除一个字面量，后者对任何非 `/` 开头字符串为真。
- 修法：改为 `assertRegex(值, r"^(失败:|未知:)")` 或断言值 ∈ 显式允许集合。
