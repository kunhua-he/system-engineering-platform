# 唯一 HTTP 执行面收口与旁路治理

## 发现的问题

- 主网关正式业务入口已经是 `POST /网关/调用`，但历史旁路仍使用独立 POST：浏览器宿主 `/api/调用`、HTTP 服务支持库 `/调用`、轻代码编辑器 `/工程/请求`。
- 流式服务虽使用 `/网关/流式`，但原先没有复用统一凭证和审计边界。

## 解决方案

- 浏览器宿主改为纯静态页面；页面配置网关地址和能力 id 后，只向 `POST /网关/调用` 转发，不再接收 Python 回调；原 `/api/调用` 真实 404。
- HTTP 服务支持库保留为受管 Provider RPC，改用 `/内部/能力调用`，必须带协议头 `X-Internal-Call: 1`；原 `/调用` 和旧 `/能力/调用` 真实 404。业务代码不得使用该内部路径。
- 轻代码编辑器保留工程控制面能力，改用 `/内部/工程请求`，必须带 `X-Internal-Call: 1`；原 `/工程/请求` 真实 404。
- 流式服务默认要求凭证；创建和取消均经过同一凭证校验，并记录有限审计摘要（路径、请求 id、能力 id、结果和错误码），不保存凭证、参数和响应正文。

## 实际结果

- 浏览器宿主实现、包级入口、能力契约、包声明、说明、示例和测试已同步。
- HTTP 服务支持库实现、内部 RPC 标记、测试和说明已同步。
- 轻代码编辑器前端请求、服务端路由、内部标记、说明和真实子进程测试已同步。
- 流式 HTTP 默认 fail-closed、认证、取消认证和审计已同步；测试夹具显式使用 `要求凭证=False`。
- 浏览器宿主与 HTTP 服务支持库工作包：2 个测试文件全部退出码 0。
- 编辑器内部 HTTP、浏览器宿主、HTTP 服务支持库、流式安全和第八阶段流式生产测试：5 个测试文件全部退出码 0。
- 前后端核心示例真实退出码 0；静态编译和包完整性摘要已重新生成。

## 当前边界

- 本轮未宣称整个系统已完成“唯一网关”发布门禁；主网关真实 HTTP 集成矩阵、Provider 多进程池、LibreOffice 资源池和发布门禁运行时证据仍按 `05-09_蒸馏现状与HTTP迁移剩余项.md` 后续批次处理。
- 阶段常规全量首次枚举 184 个测试文件，7 个文件失败；已知的 `测试_零测试门禁.py`（20/20）和 `测试_环境缓存并行.py`（10/10）单独串行重跑通过，初步判定全量聚合时存在缓存/嵌套验证干扰，待串行全量复验。
- 内部控制面/Provider RPC 可以存在独立 HTTP 路径，但必须有明确内部命名、协议标记和权限边界，不得作为业务执行入口。

## 调用方式

- 浏览器宿主：`启动网页服务(标题, 页面说明, 网关地址, 能力id, 端口, 自动打开)`。
- HTTP Provider：`GET /健康`；内部调用 `POST /内部/能力调用` + `X-Internal-Call: 1`。
- 轻代码编辑器：内部调用 `POST /内部/工程请求` + `X-Internal-Call: 1`。
- 流式服务：`POST /网关/流式` 或 `/网关/流式/取消`，生产默认携带 `Authorization: Bearer <凭证>`。
