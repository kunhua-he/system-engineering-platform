## 我的工作流程（开发→验证→发布，每条怎么走）

> 这是小马仔执行本任务的固定流程，华哥先看这条。理解对了再往下做。

```text
【一、日常开发一个模块/组件/能力】

修改代码
  ↓
① 跑编译器（只编译这个小单元，绝对不跑全量）
    开发工具/项目编译/项目编译器.py
    → 检查：能力登记了吗？契约对吗？依赖闭合吗？边界越线了吗？
    → 通过：生成这个小单元的编译产物
    → 失败：改代码 → 重编译（循环，直到编译通过）
  ↓
② HTML 黑盒验证（对编译产物发真实请求）
    开发工具/HTML验证/验证器.py（新组件）
    → 启动编译产物
    → 按 验证场景.json 对产物发 GET / POST
    → 只看 HTTP 状态码 + 返回的 成功/值/错误码/错误说明
    → 功能正常 → 继续下一个
    → 功能异常 → 按 编译/路由/参数/能力/Provider 定位，回去改
  ↓
③ 证据落盘（每次验证都留）
    请求、返回、状态码、耗时、资源释放
    绑定当前工作区指纹（提交+工作区摘要）
```

```text
【二、一批功能改完（合并波次）】

本批涉及的所有小单元都各自编译+验证通过后
  ↓
把本批的编译产物一起启动
  ↓
HTML 验证器对整批产物做一次并发验证（多线程）
  ↓
全部绿 → 本批完成
有红 → 只修红的单元，再回到【一】循环
```

```text
【三、一个阶段完成（阶段收口）】

本阶段所有批次都通过后
  ↓
编译本阶段全部小单元 → 生成完整阶段制品
  ↓
HTML 验证器并发跑全量（HTML 可以跑全量！多线程，1万线程都不怕）
  ↓
全部绿 → 阶段收口完成
有红 → 看具体哪个能力红 → 针对性修 → 回到【一】
```

```text
【四、正式发布（发布门禁，只跑一次）】

阶段收口全部通过
  ↓
编译最终制品
  ↓
发布门禁 = HTML 黑盒验证全量 + 制品检查 + 发布事务
（门禁不再重复跑旧的 1125 个测试，改为对最终制品发真实 HTTP 请求）
  ↓
通过 → 发布
失败 → 回到对应环节修
```

### 我执行时的铁律（对照检查）

1. 编译器只编译小单元 + 检查合规 —— **绝对不跑全量**，不代替功能验证
2. HTML 验证器对已编译接口发请求 —— **可以全量、多线程并发**
3. 我只认 HTTP 状态码 + 返回值 —— 不看源码内部，不猜后端实现
4. 测试中心脚本（`测试中心/运行测试.py`）—— 新链路可用后**退役**，门禁改走 HTML 验证
5. 每个支持库/模块的 `验证场景引用.json` —— 验证场景的输入来源，我不猜参数
6. 每次验证都要落证据、绑工作区指纹 —— 不伪造、不拿旧证据冒充

### 我遵守的分级验证节奏

```text
小改动 → 只编译小单元 + 定向验证（几秒）
一批功能 → 受影响单元合并并发验证（几十秒）
一个阶段 → 阶段制品全量 HTML 并发验证（几分钟）
正式发布 → 发布门禁只跑一次（最终判定）
```

## 落点结论（2026-08-29 已核实代码现状）

### 统一编译器 = 已存在，无需新建

`开发工具/项目编译/项目编译器.py`（v1.2.0）已是全局唯一编译器，承担：

- 制品登记：提交、版本、契约指纹、依赖指纹、完整性摘要

### 编译产物 = 已存在

`工程缓存/制品仓库/平台客户端制品/平台客户端-<提交>/平台客户端/` 已有实体：

- `前端/编译页面/index.html`（编译后的页面）

### 缺的核心 = 「HTML 黑盒验证器」（全新组件，本任务主产出）

现有编译产物启动器只提供「网关+页面」，**没有验证能力**：
- ❌ 不能自动对编译产物发起 GET/POST 并发请求
- ❌ 不能自动判定「功能正常/异常」（只看 HTTP 状态码+返回值）
- ❌ 不能自动记录证据（请求、返回、状态、耗时、资源释放）

**落点：** `开发工具/HTML验证/`（新目录，与项目编译平级）
- `验证器.py`：核心验证引擎（启动制品 → 并发请求 → 判定 → 证据）
- `验证场景.json`：每个能力的验证场景（能力id、GET/POST、参数、预期状态码/错误码）
- `验证页.html`：浏览器可视化的验证入口（华哥可肉眼看到每个能力绿/红）
