## 二、本批结论摘要

- **直接删**：0 个
- **AI 直接调能力**：0 个
- **落模块库**：2 个 → `capability_search`、`capability_read`（收口进 `模块库/能力目录/`，同时收编 `开发工具/能力搜索/能力搜索器.py` 与 `开发工具/开发入口.py` 的并行实现）
- **落技能库技能包**：7 个 → 全部 `_guide`（7 收 1，合并为技能包「开发指南投递」）
- **留薄壳**：1 个 → `tool_catalog`

计数：**0 删 / 2 落模块库 / 7 落技能 / 1 留薄壳 = 10**。

### 真重复（代码为准）
1. **能力检索三份实现**：`MCP工具箱/公开能力.py:214/226`（MCP 用）、`开发工具/能力搜索/能力搜索器.py:250`（14 字段，最全，带 CLI）、`开发工具/开发入口.py:29`（`搜索能力`）。三份逻辑重叠、字段不一致，**底座 538 个能力里没有任何一个承载「能力检索」**（已全表核对 `能力定义.json`，无同名/同义能力）。→ 应落 `模块库/能力目录/` 收口。
2. **7 个 guide 完全同源**：全部走 `角色权限.py:39 获取角色指南` → `角色权限.py:26 网关说明`，输出仅 `工具` 字段回显名字，其余逐字相同。角色体系移除后已是死壳。

### 真缺口
1. **「按名称投递开发文档」的底座入口不存在**：当前 `_guide` 返回的是无用的单网关说明，而真实开发流程文本散落在 `开发文档/*.md`。底座**已有文档读取原子能力**——`模块库.文档读取.读取正文`（读任意文件正文）+ `支持库.后端.文件系统支持库.文件操作.读取文件`——但**没有**「指南名 → 文档路径」的收敛入口。这正是 7 个 guide 应收敛成的那个技能包。
2. **`release_guide` 描述与行为不符**：描述承诺「审核、激活和回滚流程」，实现只回单网关说明；发布流程实际在 `开发工具/发布门禁/*`，无任何工具/能力把它投递给 AI。
