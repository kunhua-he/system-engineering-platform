**缺什么（全表核对，非抽样）**：`版本控制支持库.Git操作` 全部 11 个能力为 —— 检查提供者、创建工作区、查询工作区、关闭工作区、提交、回滚、挑拣合入、当前状态、获取当前提交哈希、校验分支名、建议分支名。
**`git switch`（切换分支）与 `git merge`（合并分支）确实没有能力承载** → 与 `03_总表与处置.md:147` 的判断一致，本批**独立复核确认**。

**不能映射的入参**：
- `force`（关闭工作区强制）→ 能力无对应参数。
- `paths` 为空时的 `git add -A` 全量提交 → 能力 `路径列表` 必填，无等价路径。
- `task_id` → 能力的 `新路径`/`分支名` 都是显式入参；旧工具的 `工作区根/任务id` 与 `codex/任务-{标识}` 命名约定属于 MCP 侧封装，**能力层不体现**（谁直调谁得自己守这个约定）。

- **提交/合并的仓库根白名单**（`工作区管理.py:55-86` 的 `_提交根白名单`/`_校验提交根`，默认只放行底座仓库根 + 系统临时目录，环境变量 `工作区允许提交根` 加白）→ 能力层无此防护，直接裸调 `提交` 能力会**丢失越界提交保护**（`工作区管理.py:73-77` 注释写明这正是修复前的漏洞）。
