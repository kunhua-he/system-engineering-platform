## 三、目标架构（一次性收口后的唯一形态）

```text
AI 客户端（Claude Code / opencode / Hermes）
      │  MCP（只 1 个元工具：调用能力；如可行走 stdio，无监听端口）
      ▼
MCP 薄壳（无业务语义、无独立端口、无第二入口）
      ▼
唯一网关 40007（已有凭证 / 审计 / 错误码 / 并发治理）
      ▼  调用能力(能力id, 参数)
技能库（技能包 = 固定工作流，六件套）
      ▼  受控执行沙箱（技能库.受控执行.运行技能包）
支持库 / 模块库（538 个原子能力）
```

**收敛判据（对 50 个工具逐个套用）**：

1. 与已有原子能力重复 → **直接删**，AI 直接调能力（第 10 条）
2. 真工作流（多步 + 有先后 + 需固化）→ **落成技能库技能包**
3. 纯宿主 / 会话态（与能力无关的临时状态）→ **优先删**（第 11 条「空转即杀」）
4. 只读查询类（能力目录 / 契约 / 文档）→ **留薄壳**

## 四、编号体系收敛（全库唯一一套）

**规则**：全库只有一套条款编号 = `开发文档/项目说明.md` 的 **第 1–36 条**
（1–6 编译器与验证铁律、7–24 设计哲学、25–27 能力唯一性、28–31 底座 0 加密 0 限制、32–36 底座自我完备）。

**收敛前实测病因**：16 份文档 148,557 字符；同一个 `项目说明.md` 内有 **5 套平行编号**；
全库「第 1 条」出现 **17 处**、「第 2 条」**14 处** → 引用「第 N 条」无法唯一定位。
