## 一、装配跳过包（实测）

实测命令与输出：

```
python3.14 -c "from pathlib import Path;from 后端核心.后端核心 import 后端核心;
b=后端核心(Path('.'));b.启动();print(b.状态快照())"
```

| 项 | 实测值 |
|---|---|
| 启动 | 成功 |
| 状态 | 运行中 |
| 能力数 | 611 |
| **装配跳过包** | **`[]`（0 个）** |

**结论：本次装配 0 个包被跳过，无“静默降级”命中。**

但“0 个”不等于“机制无风险”，实测出三条结构性事实：

### 1.1 跳过闸门的触发条件（代码实证，本次 0 命中）
`运行核心/加载器/生命周期管理/管理器.py:115-160` `_单包级预检()` 只判 5 类“半成品包”问题，命中即**只告警 + 跳过、不阻断全平台**：

1. 包目录不存在
2. 包声明未声明 `入口` 字段
3. 入口路径越界/不可解析
4. 依赖锁内容为空或非法
5. `能力契约/参数契约.json` 不可读（不存在 / 非 JSON 对象 / `能力契约` 不是列表）

跳过会写 `装配跳过包` 并打到 stderr（`后端核心/后端核心.py:136-143` 打印装配告警），同时回滚该包生命周期并落跳过证据（`记录跳过证据`），**告警不丢**——这一点实现是到位的。

### 1.2 跳过清单会被“模板复用”重放
`后端核心/后端核心.py:34-35、122-129`：`_装配模板` 与 `_装配跳过包` 是**模块级全局**。第二个 `后端核心` 实例复用首次装配模板时，跳过清单按首次结果原样回放。设计意图是“告警不丢”，但意味着**跳过清单永远是首次装配的快照**，进程内后续变更不会被重新探测。

### 1.3 装配链完全不看 `生命周期契约.json`（本路最重要的结构发现）
全仓 `.py` 中读取 `生命周期契约.json` 的位置，只有两处**开发工具**和一处测试：

| 位置 | 用途 |
|---|---|
| `开发工具/发布门禁/运行发布门禁.py:753` | 仅当能力参数含“进程”类型时校验 |
| `开发工具/依赖生命周期审计/审计核心.py:124/159` | 独立只读审计工具 |
| `测试中心/开发工具/测试_依赖生命周期审计.py:101` | 审计工具自身的测试 |

**装配器、运行核心、提供者注册表、支持库后端包装层，没有任何一处读取或执行 `生命周期契约.json` 的 `停止入口`。**
后果：7 个提供者缺 `生命周期契约.json`（见第二节）在装配期**零告警**；契约里写的“停止入口”在运行时**无人调用**，只有静态门禁才看。

### 2.2 “缺契约”的 7 个提供者恰好是最需要契约的
`资源预算.json` 实测：这 7 个提供者**全部申报了 `子进程上限`**（FFmpeg 2 / Git 2 / LibreOffice 8 / MLXWhisper 1 / PDF隔离 2 / Tesseract 2 / textutil 2）。
即：**拥有外部进程的头号风险源，恰恰是生命周期契约缺位的全部 7 个**。这是全路最该收口的一处结构性错位。

### 2.3 为什么审计工具没报出来（“假通过”机理）
`审计核心.检查停止入口()`（L145-177）是**宽松兜底**：
- 先扫 `实现/*.py` 里**函数名含**「停止/关闭/释放/终结/终止」的任意函数 → 命中即通过；
- 未命中再看契约里 `资源模型 == "调用内临时资源"` 且释放策略含证据词。

实测运行 `开发工具/依赖生命周期审计` → **17 个全部“通过”**（含 7 个无契约者，因为它们在 `实现/` 里都有 `_终止进程组` 或 `关闭会话` 这类函数）。
**契约缺位被实现层的函数名兜住了，审计面看不见契约缺失**——这正是“契约名不副实 / 名存实亡”的静默通道。
