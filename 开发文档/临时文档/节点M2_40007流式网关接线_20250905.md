# 节点 M2：40007 同一网关接入真实模型流式

## 工作流程

1. 先读取 `本地网关.py`、`流式HTTP.py`、安全边界、网关核心、启动脚本和 M1 报告，确认流式请求必须进入现有 40007 服务，不能另起第二业务网关。
2. 先新增固定本地 HTTP 夹具测试并运行 RED；再在本地网关内接入有限流式管理器和 M1 包级入口。
3. 流式路由只接受模型连接器生成对话能力、整数句柄、非空消息列表和逻辑真值 `流式输出=true`；不调用普通 `生成对话`，不把普通 JSON 包装成流。
4. 逐事件输出 SSE，使用同一 HTTP 网关的监听、凭证、请求体、线程和连接诊断边界；能力调用 `/网关/调用` 保持原样。
5. 跑 M2、既有流式安全、M1、H、模型协议和模型 HTTP 测试，再做语法与差异校验。

## 调研落点

- `运行核心/统一网关/本地网关.py` 是 40007 的唯一标准库 HTTP 服务，原来只在 `do_POST` 放行 `/网关/调用`，虽然安全配置已列出 `/网关/流式`，实际没有分支。
- `运行核心/统一网关/流式HTTP.py` 已有 `HTTP流式管理器`，可以提供有界事件队列、并发上限、超时、取消、断开清理和 SSE 格式；其原独立服务器不是本次生产入口。
- M1 已在平台模型连接器包级公开 `流式生成对话`，从有效整数句柄读取协议、URL和密钥，调用 Provider SSE，不聚合普通结果。
- 因此本节点落点为：`本地网关服务器` 内延迟创建 `HTTP流式管理器`，流式路由生产函数调用模型连接器包级入口；没有新增服务、端口、执行腿。

## 具体修改

### 1. 同一 40007 服务增加流式分支

`本地网关服务器` 初始化时创建一个与普通服务共享并发上限的 `HTTP流式管理器`。`do_POST` 在同一处理类内识别 `/网关/流式`，其他普通调用继续进入原 `/网关/调用` 分支。

### 2. 请求边界

流式请求允许字段为：

```text
能力id、参数、句柄、请求id、最大事件数、最大持续秒
```

固定能力为：

```text
大语言模型支持库.模型连接器.生成对话
```

HTTP 层严格拒绝：

- 客户端伪造项目/用户/会话/任务身份；
- 顶层句柄和参数句柄不一致；
- 非 1 到 999999 的整数句柄；
- 空消息列表；
- `流式输出` 不是逻辑真值；
- 未知顶层字段。

- 流式请求路径为 `/网关/流式`；客户端主动取消使用同一服务的 `/网关/流式/取消`，按请求 id 进入管理器取消和清理，不创建第二服务。
- 同一服务的安全路径表已同时登记两个流式路径。

### 3. 真实事件链

```text
POST 40007 /网关/流式
  ↓
本地网关同一处理线程与安全边界
  ↓
HTTP流式管理器（有限事件/时间/并发）
  ↓
模型连接器.流式生成对话
  ↓
Provider真实SSE增量
  ↓
逐事件 text/event-stream
```

事件映射：

```text
Provider 类型=增量 → SSE 增量事件
Provider 类型=完成 → SSE 完成事件并结束
Provider 类型=错误 → SSE 失败事件并结束
```

上游错误不会伪造成完成；通道结束回调和管理器清理保持原有唯一收口。
