# 节点G：平台连接契约补齐

## 工作流程（本节点允许直接执行）
- 修改入口：仅 `支持库/后端/大语言模型支持库/模型连接器/` 包内实现、包级注册参数、契约/能力定义/能力搜索/说明/包摘要；仅在 `测试中心/第一批维修/测试_模型连接器通用协议.py` 补本节点 unittest。
- 约束：连接LLM不接受连接阶段`流式输出`；`流式输出`只保留在生成对话；chat/res别名归一、非流式请求和40007流式未装配错误保持不变。
- 超时裁决：采用当前实现的 1800 秒作为唯一默认句柄超时，避免改变当前运行口径；同步实现、包声明、能力定义、参数契约、能力搜索数据、说明书和完整性摘要。
- 验证节奏：先运行本节点测试基线；先加未知连接参数、生成流式和默认超时一致性测试并确认 RED；再修改最小实现和全链路契约，确认 GREEN；最后运行定向 unittest、JSON/摘要一致性校验和 git diff 边界校验。
- 证据落盘：本文件记录变更、命令、退出码、摘要校验和剩余阻断；不修改支持库、网关、数据库、Hermes 或其他仓库。

## 发现的问题
- 连接LLM实现签名当前会因未知连接参数自然抛出 TypeError，但契约各层需要明确不登记`流式输出`；生成对话已经保留该参数并在未装配 SSE 时返回结构化错误。
- 实现和能力定义末尾已有 1800 秒申报/默认，但包声明、能力定义、参数契约、能力搜索和说明书的部分默认值/说明仍写 300 秒，存在跨层漂移。

## 解决方案
- 增加测试证明连接阶段传入`流式输出`被拒绝，生成对话流式仍走既有40007结构化错误，默认句柄超时实现与所有包契约字段一致为1800。
- 更新包内所有相关契约和说明，重新生成/校验 `完整性摘要.json`。

## 影响范围
- 仅模型连接器包、节点G测试和本节点报告。

## 实际结果
- 采用 1800 秒：实现原有默认常量和包声明末尾申报均为 1800，统一包声明参数、能力定义、参数契约、能力搜索数据、说明书和包级注册参数；不改 300 秒的模型进程 `--sleep-idle-seconds` 或资源预算字段，它们不是句柄默认超时。
- 连接阶段保持无`流式输出`参数；实现函数签名对该未知关键字抛出 `TypeError`，不会创建连接或发出 HTTP 请求。
- 生成对话继续保留`流式输出`；true 时保持 `流式能力未装配`、40007、非伪造完成结果的既有结构化错误；非流式请求继续发送 `stream: false`；chat/res 别名归一未改。
- 完整性摘要：`17` 个文件逐项 SHA-256 校验，`0` 个不匹配。
- 定向 unittest：`python3.14 -m unittest 测试中心.第一批维修.测试_模型连接器通用协议 测试中心.第一批维修.测试_模型连接器HTTP`，`16` 项通过，退出码 `0`。
- 语法校验：模型连接器包入口、实现和节点测试 `py_compile` 通过，退出码 `0`。
- JSON/摘要校验：包内 JSON 全部可解析，摘要 `17/17` 一致，退出码 `0`。
- 允许修改边界核对：仅模型连接器包、`测试中心/第一批维修/测试_模型连接器通用协议.py`、本报告发生改动；未改支持库、网关、数据库、Hermes 或其他仓库。

## 调用方式
- 连接：`连接LLM(模型=..., url=..., 协议="chat" 或 "res")`；连接阶段不得传`流式输出`。
- 生成：`生成对话(句柄, 消息列表, 流式输出=False)`；`流式输出=True` 当前返回结构化 `流式能力未装配`。
- 默认句柄超时：未显式传`超时秒`时为 `1800` 秒；持续调用会重置沉默计时，可续租或显式释放。
