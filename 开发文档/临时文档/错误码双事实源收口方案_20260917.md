# 错误码「两张手写表 = 双事实源」收口方案（2026-09-17）

**结论一句话**：两张表的**键集**早就有门禁管住了（不是双事实源）；真正的双事实源是
**说明表里 250/337 条文案其实是状态码的机械派生、却被逐条手写固定**，改一处忘另一处
时调用方会拿到 413 却被告知「能力内部执行失败」。本方案已落地「派生规范 + 门禁判据⑤」，
把这条漂移从**无机制可见**变成**发布门禁直接变红**。对外错误码/状态码/文案**一个字没改**。

## 二、定性：权威源到底在哪里（逐个来源核实）

| 候选来源 | 实测结论 |
|---|---|
| `运行核心/统一网关/本地网关.py::公开错误码状态映射` | ✅ **权威**。码 → HTTP 状态码，337 码；本地网关发响应时按它定状态码（缺键回落 500） |
| `运行核心/统一网关/网关核心.py::公开错误说明表` | ⚠️ **派生视图**，不是源。337 码；实测 = 派生结果（0 差异） |
| 全库 `能力定义.json::错误码`（1536 份） | ➖ **上游声明面**。去重出 338 个「错误码」字段值，其中 **14 个是字段说明字符串/非码**（如「列表型」「文本型，拒绝时的稳定错误码（预算不完整）」「HOST_UNAVAILABLE」「统一」），**2 个是真码**（`文件已被占用`、`租约不存在`）—— 正是当前门禁红的 2 条；真声明码 ⊆ 状态映射码由判据①固定 |
| `公共契约/错误结构/错误结构.py` | ➖ **真子集**。只有 35 个 `错误码_XXX` 常量名（网关边界 + 适配层），不含 337 码里其余 302 个 → **不足以当权威源** |
| `开发工具/契约编译/消费者契约.py::全局错误码` | ➖ **真子集**。固定 12 稳定操作的鉴权类码（越权操作/会话过期/角色未授予/未知角色…） |
| `平台控制面/能力目录/消费者契约注册表.py` | ➖ 消费者契约的解析/登记方，自身不定义码 |

### 表内 337 码的可推导性（严格实测）

- **能从 `能力定义.json` 推导**：**322 / 337**
- **推导不出**：**15** → 事件负载超限、外部不可访问、契约不存在、契约版本不兼容、操作不存在、
  方法不允许、未知路径、权限不足、热接入失败、请求结构错误、调用已取消、资源释放失败、
  路由不存在、限流、需求未确认。
  这 15 个是**网关/本地网关自己实现里直接产生的码**（路由层拒答、网关装配失败、句柄/限流边界），
  权威源只能是网关自身。

> 所以「大部分表内码能从契约推导」这个假设**只对 322/337 成立，且那 322 个的契约是
> 声明面而非口径源** —— 状态码口径与文案口径只在网关这一侧。**权威源 = `公开错误码状态映射`。**

### 真正的双事实源：文案 ↔ 状态码（判据②看不见的那条）

把说明表按「文案 == 码 + 状态码模板」严格比对：

| | 条数 |
|---|---|
| 严格等于模板（**可派生**） | **250** |
| 手写（含独立信息） | **87** |

模板只有 7 条（状态码 → 一句话）：
`400` 调用方输入或状态不满足要求 · `404` 目标对象不存在 · `409` 既有状态冲突 ·
`413` 超出资源/长度/配额上限 · `500` 能力内部执行失败 · `503` 依赖的提供者或环境不可用 ·
`504` 等待上游超时。

250 条文案里承载的全部信息就是「这个码属于哪一类失败」——**这个事实状态映射已经写了一遍**。
于是：

- 改状态码不改文案 → 调用方拿到 413，文案却说「能力内部执行失败」；
- 判据② 只比键集 → **全绿**；
- 判据①④ 也不响 → **全绿**。

**这就是批评者说的「双事实源」的确切落点。**

## 三、方案（已落地）

### 3.1 权威源与派生关系（收口后的口径）

```
状态映射（唯一权威，本地网关.py）
   │  码 → HTTP 状态码
   ├── × 状态码文案模板（7 条）      ──┐
   └── + 手写例外文案（87 条，唯一源）─┴──►  公开错误说明表（派生视图，网关核心.py）
                                             不动一个字，仍为 337 字面量
```

分工：
- **码 → 状态码**：`公开错误码状态映射`（不变）
- **状态码 → 一句话分类**：`状态码文案模板`（新，7 条，派生规范里）
- **模板说不出的独立信息**：`手写例外文案`（新，87 条，**逐字搬运，未改一字**）
- **说明表**：不再是「手写字面量」，而是「派生结果 + 被门禁固定」的产物

### 3.2 落点的文件

| 文件 | 动作 | 说明 |
|---|---|---|
| `开发工具/错误码文案派生.py` | **新增**（337 行） | 派生规范的唯一落点：7 条模板 + 87 条例外 + `派生说明表()` + `校验()` + CLI |
| `开发工具/公开调用完整性门禁.py` | **修改**（+47 行，纯新增） | 新增判据⑤接线 `检查错误说明派生(根)`；模块/docstring 同步说明。既有判据①②③④ 一字未动 |
| `运行核心/统一网关/*.py` | **未改** | 一个字符没动 —— 错误码/状态码/文案是契约，本路不改对外行为 |

**为什么规范放在 `开发工具/` 而不是 `网关核心.py`**：门禁读表走的是
**AST 字面量**（`读取模块字面量字典`），`公开错误说明表` 必须保持字面量 dict；把派生
放到 import 期会把表变成计算值、门禁就读不到，等于把判据废掉。派生规范属于**校验期**
资产，`开发工具/**` 正是任务划定的校验器域。

**为什么复用现成机制而不是新开一道门**：判据①②④ 已经在
`检查错误码登记()` 里、已经被 `运行发布门禁` 接入、已经有 28 条单测。判据⑤ 接在同一处，
零新增接线、零新增发布链路改动。

### 3.3 判据⑤ 的六条子判据（全部 fail-closed，无一条是「放宽」）

1. 状态映射源 / 说明表源读不到 → 判红（不许把「读不到」说成「不违规」）
2. 状态映射里每个码都要能派生（有模板，或已登记例外）→ 派生不出即判红
3. 说明表逐码逐字 == 派生结果 → **改一处忘另一处在此现形**
4. 例外文案的码必须在状态映射里 → 防例外表留孤儿
5. 例外文案与说明表逐字一致 → 例外表就是这些码的文案唯一源
6. **例外登记不得多余** → 状态码有模板、说明表文案恰等于模板的码不得占例外位 → 防例外表腐朽

守卫：比对对象是**真仓库契约源**。临时夹具根（单测只写两份最小表）没有派生规范，
按根守卫跳过；真仓库侧读不到派生规范模块即判红。

### 3.4 不能落地的部分，如实说明

- **15 个网关自身码 / 322 个声明面码** 无法从任何契约推导出**状态码口径**，权威源只能是
  `公开错误码状态映射`。这一半**天然没有「自动生成」的余地** —— 状态码是华哥裁决过的
  契约决策（「谁的责任」定级），不是可推导事实。所以本方案的目标不是「消灭手写」，
  而是**把「键集 + 文案」这两类可校验的一致性收进门禁，把手写面压到只剩「状态码定级」
  这一个真正需要人裁决的点**（337 → 338 条目里，需要人写的是 337 个状态码 + 87 条例外文案）。
- **判据⑤ 只对模板覆盖的 250 条生效**。401/403/405/410/429/502 这 6 个状态码下的 12 个
  码文案互不相同（403 下 危险命令/危险路径/越权操作/角色未授予 各说各的），状态码说不出
  差异 → 只能进例外表。这 87 条**必须手写**，方案不假装它们能生成。
- **当前 3 条门禁红未修**：`文件已被占用`、`租约不存在`、`写回压缩结果失败` 需要写进
  `公开错误码状态映射`，那会**改变这 3 个码的对外 HTTP 状态码**（从回落 500 改成裁决值），
  属对外行为变更，按本路硬约束「不得改变对外行为」**留待华哥裁决**，本路不擅自登记。
  精确改法见 §5。

## 七、剩余风险

1. **例外表与说明表在 87 条上仍是两份文本**：判据⑤③⑤ 保证逐字一致，但改动要动两处。
   收口方向（未做，需华哥点头）：把 `公开错误说明表` 改成 `--写入` 生成物 —— 门禁读 AST
   字面量不受影响，人工只改「例外表 + 状态码」。**本路未做**，因为它把 337 行生成文本
   写回受保护文件，风险高于收益。
2. **判据⑤ 的根守卫**：临时夹具根跳过判据⑤（沿用仓内既有 idiom）。理论上「把真仓库搬到
   别处再跑」会跳过；实务上发布门禁传的就是真仓库根，不受影响。
3. **3 条存量门禁红未修**（§3.4），且 `test_真实扫描如实输出` 是存量红 —— 两件都需要华哥
   先裁决「`文件已被占用`/`租约不存在`/`写回压缩结果失败` 各自该定几级」。
4. **例外表里 87 条的手写面还能压**：其中 **43 条是「码：分类说明」式的模板变体**
   （如 `句柄失效：句柄不存在或已失效`）、**21 条文案极短**（如 `能力不存在`、`未知路径`、
   `内部错误` 这类只重复码本身）。要降级它们得先给出更细的分类模板（网关自身码一套、
   声明面码一套），属另一轮，本路不动 —— 因为调整模板会**改写 87 条对外文案**，
   违反本路「不得改变对外行为」。
