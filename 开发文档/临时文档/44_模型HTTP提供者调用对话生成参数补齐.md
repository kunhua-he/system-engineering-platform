# 44 模型HTTP提供者.调用对话 生成参数补齐（重启后暴露）

开工id：`ed3f03140636435e`
任务：修复 40007 全链路 LLM 调用 TypeError。

## 阶段一：发现的问题

### 现象

40007 网关重启后，任何 LLM 生成调用（`生成对话`）一律失败：

```
{"成功": false, "错误码": "模型调用失败",
 "错误说明": "LLM 调用异常: 调用对话() got an unexpected keyword argument '温度'"}
```

`连接LLM` 正常返回句柄，`生成对话` 必挂。V3 `底座提供商.对话` 因此恒返回 `{"error": ...}`。

### 根因

调用链：

```
生成对话(句柄, 消息列表, …, 温度, 最大令牌数, 工具, 响应格式, 附加请求头)
  → _调用模型(句柄, "LLM", {8 个键})            ← 模型连接器/实现/模型连接器.py:326
  → 调用函数表["LLM:云端"]                       ← 注册模型HTTP提供者() 写入
  → 模型HTTP提供者.调用对话(配置=…, **参数)      ← 适配层/模型HTTP提供者.py:408
```

`注册模型HTTP提供者()`（`大语言模型支持库/__init__.py:44` 在导入时调用）把
`模型HTTP提供者.调用对话` 注册为 LLM 本地/云端调用器，**优先级高于连接器自带的
`_HTTP调用模型` 兜底**。但 `调用对话` 的签名只有 `(配置, 消息列表, 系统提示词, 流式输出, 附加请求头)`，
收不下 `温度/最大令牌数/工具/响应格式` → `**参数` 展开即 TypeError。

**这是提交既有缺陷，非本次改动引入**：`git diff d7a7bcb a155e4e -- 支持库/适配层/模型HTTP提供者.py`
显示 `调用对话` 原签名（d7a7bcb）就没有这四个生成参数。

### 为什么之前没暴露

`运维脚本/热接入.py` 重载 `模块库`/`支持库/后端` 时会重新执行
`模型连接器/实现/模型连接器.py`，把模块级 `调用函数表` 重置为 `{}`，但**不会**重跑
`大语言模型支持库/__init__.py`（注册发生在该文件导入时）。于是热接入后 `调用函数表` 为空，
`_调用模型` 落到 `_HTTP调用模型` 兜底 —— 而 `_HTTP调用模型` 是完整正确的实现，
所以热接入态下一切正常，缺陷被掩盖。**首次冷启动（重启）即引爆。**

### 影响范围

- 40007 全部 LLM 生成调用（`生成对话`）不可用；
- 依赖 40007 的薄壳化第五章 5.2-③（会话亲缘性）真实 HTTP 验收被阻断；
- 向量/重排不受影响（`调用嵌入(配置, 文本)` / `调用重排(配置, 查询, 文档列表)`
  与连接器传入的键完全一致）。

## 解决方案

把 `模型HTTP提供者.调用对话` 补齐到与 `_HTTP调用模型` **同一协议契约**
（`_HTTP调用模型` 文档串本就自称「与受管 Provider 保持同一协议契约」，实际未达成）：

1. 签名补 `温度/最大令牌数/工具/响应格式`；
2. 载荷按协议映射：`codex_responses → temperature / max_output_tokens / tools / text.format`；
   `chat_completions → temperature / max_tokens / tools / response_format`；
3. 响应归一化复用连接器公开函数 `归一化对话响应`（函数内延迟导入，避免环形导入），
   产出 `内容/思考/工具调用/结束原因` 并与既有 `回复/用量` 并存。

不动 `_HTTP调用模型`，不改连接器签名，不改 `注册模型HTTP提供者`。

## 影响范围

- 仅 `支持库/适配层/模型HTTP提供者.py` 一个文件；
- 该文件不被任何 `完整性摘要.json` 收录（已 grep 确认），无需重算包摘要。

## 阶段二：实际结果

### 落地改动

`支持库/适配层/模型HTTP提供者.py`：

1. 新增 `_归一化响应(数据) -> dict`（第 408 行），函数内延迟导入
   `大语言模型支持库.模型连接器.归一化对话响应`，避免环形依赖；异常吞掉返回空字典。
2. `调用对话` 签名补齐 `温度/最大令牌数/工具/响应格式`，并加类型校验；
   载荷按协议映射：

   | 参数 | chat_completions | codex_responses |
   |------|------------------|-----------------|
   | 温度 | `temperature` | `temperature` |
   | 最大令牌 | `max_tokens` | `max_output_tokens` |
   | 工具 | `tools` | `tools` |
   | 响应格式 | `response_format` | `text.format` |

3. 成功返回 `{回复, 用量, 内容, 思考, 工具调用, 结束原因}`，与 `_HTTP调用模型` 逐键一致。
4. `流式输出=True` 仍返回「流式能力未装配」失败（40007 网关未装配模型 SSE 传输，
   流式走 `流式调用对话` 独立通道），不伪造完成结果。

### 调用方式（不变，对外契约零改动）

底座内部：`注册模型HTTP提供者()` → `注册调用器("LLM","本地"/"云端", 调用对话)`，
调用方经 `模型连接器.生成对话(句柄, 消息列表, …, 温度, 最大令牌数, 工具, 响应格式, 附加请求头)`
传参，无需任何调整。

### 验证

1. **进程内**：`/tmp/进程内验.py` —— 假上游回显，`调用对话(配置, 消息列表, 温度=0.3,
   最大令牌数=64)` 成功，返回键集含 `内容/思考/工具调用/结束原因/回复/用量`。
2. **真实 HTTP 非流式**：经 40007 `生成对话` → 回显上游，`内容=回显应答`，
   出站头 `x-conn=conn-val`、`x-session-id=knowledge-gptstore:…` 均存在。
3. **真实 HTTP 流式**：`/网关/流式` SSE，事件数 4，增量 `流甲`/`流乙`，
   完成原因 `stop`，出站头 `x-conn=conn-stream`、`x-session-id=…`、`accept=text/event-stream`。
   （此前文档标注的「流式路径已过期，直到重启」告警就此关闭。）
4. **V3 验收套件**：`测试中心/后端服务/其他测试/网关测试/测试_底座提供商会话亲缘性.py`
   `9 passed`，门禁 true。
