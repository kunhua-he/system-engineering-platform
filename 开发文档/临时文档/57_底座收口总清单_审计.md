## 三、兼容性审计（华哥点名：底座兼容性够不够）

**结论：不够。** 现在有三处「多传/少传一个字段就失败」的硬点，加上一处版本严格相等——正是「后面一改又是全改」的根源。

### 3.1 现场证据

| # | 硬点 | 现场位置 | 实际行为 | 后果 |
|---|---|---|---|---|
| C1 | **入参未知字段直接拒绝** | `运行核心/统一网关/网关核心.py:247-267` | `未知字段 = set(参数) - 允许字段` → 非空即回「参数不合法：操作 X 不支持字段 Y」 | 上游**多传一个字段**就 400；连「非必填字段透传」都被拒 |
| C2 | **内部返回必须完整满足信封** | `运行核心/能力调用/唯一能力调用.py:139`（必填 `{成功,值,错误码,错误说明}`）；`网关核心.py:161-173/478` | 实现返回的字典缺任一键 → `返回结果不符合契约`（502） | 实现**少一个键**就整条链路失败（YAML提供者那次就是这么炸的） |
| C3 | **对外信封键固定且被读取侧要求齐全** | `运行核心/能力调用/进程内连接器.py:11`、`HTTP连接器.py:164` | 固定 7 键 `{成功,值,错误码,错误说明,句柄,请求id,耗时毫秒}`，读取侧按**必填字段**校验 | 底座**少发一个键**，外部调用方就报错（多键无妨、少键必炸） |
| C4 | **版本严格相等** | `项目适配层/依赖锁定/锁定校验.py:97`、`传递闭包.py:189/199/222/272-274`、`运行核心/运行环境管理器/强制校验.py:147-201`、`运行核心/资源协调/服务.py:299` | 「不相等即失败」 | 与哲学第 21 条正面冲突（版本不对齐默认放行） |
| C5 | **无别名/弃用机制** | 全仓无 | 能力改名/下线 = 旧调用方直接失败（任务提交前还校验能力存在性） | 任何重命名都是一次全改 |

### 3.2 一次性扩宽方案（扩完冻结：只增不删不改）

1. **入参宽松**（改 C1）：**未知字段一律忽略**，不再拒绝；只有「必填参数缺失」与「类型不符」才失败，错误说明点明**字段名与期望类型**（第 15 条：失败必须明确）。
2. **返回信封只增不改不删**（固 C2/C3）：信封固定 7 键，**禁止少发**；新增信息只许**追加键**，旧键语义永不改；内部实现的返回**缺键自动补默认**（`成功=False/值=None/错误码=""`）而不是判违约——「缺键」不该等于「契约违约」。
3. **非必填参数只增不改**：新增非必填参数**不得**影响旧调用；**新增必填参数**才算破坏性变更 → 必须走「新能力 id 或版本门槛 + 差异回报」，不许原地改旧能力。
4. **版本口径落地**（改 C4，哲学第 21 条）：回报**请求版本 / 当前版本 / 差异原因**；无强制约束则放行，只有强制参数不满足才失败。
5. **协议冻结 + 别名映射**（补 C5）：操作名、参数名、返回键**一次性冻死**；以后只增不删、不改名；确需改名时走**一张静态别名表**（一处维护，旧名永久可解析）。
6. **对外只留 HTML 一条路**：调用方只做 `GET/POST 能力调用` 与取结果；装配、协议、重试、句柄、缓存、落库全部在底座内部完成，不暴露给调用方（第 10 条：同一入口，不给第二条腿）。

### 3.3 兼容性验收（扩宽后必须能证明）

- 正向：同一请求**多传 3 个未知字段** → 仍 200 且结果不变。
- 正向：实现返回**只给 `成功`+`值`** → 仍 200（缺键补默认，不再判违约）。
- 正向：带**旧版本号**请求 → 200，且响应里能读到「请求版本/当前版本/差异原因」。
- 负向：**必填参数缺失**、**类型不符**、**强制约束不满足** → 明确失败并点名字段（这三类必须仍然报错）。
- 回归：现有全部能力的正向黑盒场景（HTML 并发）全绿。

## 四、运行数据库定盘（华哥：底座要有自己的 DB，别什么都是写文件）

**现状（现场）**：`工程缓存/` 下同时存在**库文件**与**散落状态文件**两套做法——
库：`会话存储.db`、`记忆库.db`、`检查点.db`、`嵌入缓存.db`、`大语言模型支持库.嵌入缓存.db`、`制品仓库/平台客户端状态/权威状态.db`；
文件：`任务状态/`、`作业状态/`、`协作状态/`、`能力占用/`、`失败记录/`、`发布证据/`、`HTML验证证据/`、`核心快照/`、`需求登记/`、`清理失败证据/`……

**定盘（我的裁决，华哥已授权）**：
1. **运行态一律入库**：任务/作业/协作状态/能力占用/检查点/会话/缓存索引这类**可查询、需原子更新**的东西，全部落表，不再各写各的 JSON/JSONL。
2. **一个运行库 + 按域建表**：底座运行库统一放 `工程缓存/运行数据/底座运行.db`；**支持库允许有自己的专属表；确有隔离需要时允许自己的库文件**（华哥口径：每库自己的 DB 也行），但**库文件位置必须统一在本目录下、且一律经唯一 SQLite 支持库访问**（`支持库/后端/数据库连接支持库/SQLite数据库`），禁止各包自己 `open()`。
3. **证据类仍是文件**（不迁）：`HTML验证证据/`、`发布证据/`、`清理失败证据/` 是不可变证据，天生适合文件，保留。
4. **缓存类**：编译缓存/验证缓存/嵌入缓存 → 能进库的进库并带清理策略；`工程缓存/` 下历史残留（协作状态 21 个 JSON、各种 `*.txt`、`验证锁.lock`）随迁移一并清。
5. **不再新增文件式状态**：新需求要存运行态，只许加表；写文件必须给出「这是证据/缓存，不是状态」的理由（第 11 条：无结果的东西不该存在）。
