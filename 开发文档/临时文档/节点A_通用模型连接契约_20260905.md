## 发现的问题
- `连接LLM` 没有协议参数，连接配置也没有协议；请求固定走 `/chat/completions`。
- `生成对话` 没有流式输出参数；模型 HTTP Provider 固定发送 `stream: false`，流式请求没有明确失败契约。
- `codex_responses` 未实现；`/responses` 请求路径、请求体和错误映射没有测试。
- 40007 的统一 `/网关/调用` 返回固定统一结果，已有流式 HTTP 外壳不是模型能力的安全 SSE 传输链；流式请求不能静默降级为非流式。

## 解决方案
- 连接LLM 接受 `协议`，只允许 `chat_completions`、`codex_responses`，默认 `chat_completions`，写入句柄连接配置并在返回/状态中可观察。
- 生成对话接受严格逻辑型 `流式输出`，默认 `False`；协议决定请求路径和请求体，流式为真时返回结构化“流式能力未装配/待补网关流”错误，不发起伪造的非流式请求。
- 模型 HTTP Provider 与连接器内置回退调用器保持相同的两协议请求组装和统一错误契约。
- 测试只使用本地 `127.0.0.1` HTTPServer 夹具，覆盖非流式统一结果、codex 路径/请求体、错误状态和流式拒绝。
