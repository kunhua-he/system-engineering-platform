# 节点H：模型 Provider 上游 SSE 流式读取

## 工作流程（本节点直接执行）
1. 修改入口：仅 `支持库/适配层/模型HTTP提供者.py`、`测试中心/第一批维修/` 下节点H unittest、本报告；不触碰 40007、运行核心、V3、网关、配置、数据库或外部 URL。
2. TDD 节奏：先新增本地 `ThreadingHTTPServer` SSE 夹具和失败测试，运行定向 unittest 留存 RED；再在模型 HTTP Provider 内实现有限 SSE 事件迭代器；最后跑定向 unittest、`py_compile`、`git diff --check`。
3. 验证入口：`python3.14 -m unittest 测试中心.第一批维修.测试_节点H_模型Provider流式读取`；测试只绑定本机固定端口 `45108`，每个夹具结束显式 shutdown/close/join。
4. 事件契约：增量、完成、错误三类有限事件；上游 HTTP 错误、协议畸形、响应超限、超时和提前断开均转换成可消费的终态错误事件，不把 SSE 一次性当 JSON 读取。
5. 资源边界：连接使用 `with` 自动关闭；请求/读取受配置超时约束；流式总响应字节和单个事件字节均有上限；异常保留类型/说明到结构化终态；生成器关闭时释放上游响应。

## 发现的问题
- `支持库/适配层/模型HTTP提供者.py` 的 `调用对话` 只支持非流式 JSON；`流式输出=True` 明确返回“流式能力未装配”，没有 Provider 上游 SSE 读取原子能力。
- 同文件已有协议归一后的 `chat_completions` 与 `codex_responses` 请求构造和 `_端点`，可复用而不改变非流式路径。
- 现有 40007/网关流式外壳不是模型上游 SSE 读取器；本节点只能新增 Provider 内部事件迭代器，不能接线或伪造网关完成结果。

## 解决方案
- 新增同包可调用的 `流式调用对话`，按协议构造 `/chat/completions` 或 `/responses` 请求，固定发送 `stream: true` 和 `Accept: text/event-stream`。
- 用增量/完成/错误统一事件解析 chat choices delta、`[DONE]`、Responses `response.output_text.delta` / `response.completed` / error；对畸形 JSON、超限、超时、HTTP 错误和提前断开返回结构化错误终态。
- 保持 `调用对话` 及连接器/40007 路径不变；下一节点再把该迭代器纳入统一网关生命周期、取消、客户端写回和调用结果契约。

## 实际结果

### 事件格式
- 增量：`{"类型": "增量", "文本": "..."}`。
- 完成：`{"类型": "完成", "文本": "", "完成原因": "stop|completed", "用量": {...}}`。
- 错误：`{"类型": "错误", "错误码": "...", "错误说明": "...", "可重试": bool, ...}`；按场景附带`状态码`、`异常类型`、`上限字节`或`字段`。
- 函数返回有限迭代器；消费方应消费到终态或调用 `.close()`，迭代器的 `with` 作用域负责关闭上游响应。

### 资源与错误边界
- 默认上游请求/读取超时 `120` 秒，可由 `请求超时秒` 覆盖；读取循环使用单调时钟截止时间并收紧底层 socket 空闲超时。
- 默认流式总响应上限 `1 MiB`、单事件数据上限 `64 KiB`、事件数量上限 `10000`，均可由配置覆盖；超过即停止读取并返回错误终态。
- HTTP 401/403 返回`认证失败`；SSE `error`/Responses error 返回`上游错误`；畸形 JSON/字段返回`事件格式错误`；超时返回`超时`；完成事件之前 EOF/读取断开返回`上游断开`，不伪造完成。

## 二次回归修复：Chat 空 finish_reason

### 根因
真实 Chat SSE 首包可能带 `finish_reason: ""`。旧逻辑只判断值是否为字符串，把空字符串误当成完成原因，立即输出空完成事件并停止读取，后续增量全部丢失。

### 修复
`_流式事件内容` 现在只有非空字符串 `finish_reason` 才返回完成原因；空字符串按未完成处理。新增固定 SSE 回归夹具覆盖“首包空完成原因 → 后续增量 → stop 完成”。

### 实际验证
- TDD RED：新增用例返回空完成事件，按预期失败。
- GREEN：节点 H + 模型连接器通用协议共 `24 tests`，全部通过。
- M1 + M2 流式接线共 `14 tests`，全部通过。
- 40007 真实 res 链路：`HTTP 200`，返回 `4` 个增量事件合成“链路通畅”，`1` 个 `completed` 完成事件，释放句柄成功。
- chat 真实链路另行实测：上游日志显示 `429 Too Many Requests` 后 `503 Service Unavailable`，同一请求直打 8328 也为 `503 Service temporarily unavailable`；属于当前 cnwudi-hy3 上游限流/不可用，不是解析器错误。
