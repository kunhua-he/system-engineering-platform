# 节点C：协议别名归一化

## 工作流程（开工前）
1. 入口核对：读取节点A已提交的连接LLM、生成对话、模型HTTP提供者及本地测试夹具，确认协议当前保存、返回和请求路径行为。
2. 契约先行：在测试中心补充短值 `chat`、`res`、长值、默认值、非法值和生成请求路径测试，先运行并确认红灯，再修改实现。
3. 最小实现：连接LLM入口统一把四种合法输入归一为 `chat_completions` 或 `codex_responses`；内部配置、返回和查询状态只出现长规范值；非法值继续返回结构化参数错误。
4. 启动调用核对：检查节点A本地模型启动调用的参数签名与现有调用方；只有确认同一契约不匹配才做最小修正并补测试，否则不改。
5. 验证收口：定向 unittest（含红灯/绿灯证据）→ 受影响 Python 文件 `py_compile` → `git diff --check` → 提交独立 commit；不改主平台、V3、Hermes或外部账号。
