# 临时开发文档蒸馏：当前未解决问题

更新时间：2026-08-29

本文件只保留当前仍未完成、未充分验证或存在真实风险的项目。已修复问题不在此重复记录。

## P0：模块公开能力尚未统一走 HTTP 黑盒

模块实现和测试仍大量通过进程内 `获取能力调用器().调用能力`，只有文件管理切片已接入真实 HTTP。涉及 OCR、图像处理、媒体处理、媒体转写、文档读取、文档解析、文档生成、网页分析、简单窗口、自修复工具等。

- 实现落点：`模块库/*/实现/*.py`；应改为唯一 HTTP 客户端，经 `POST /网关/调用` 调用能力。
- 测试落点：`测试中心/模块库/测试_*.py`；现有进程内成功测试不能计入公开能力验收，应删除或降级为内部逻辑测试，新增真实网关、多线程、错误/超时/取消/资源释放集成测试。
- 现状证据：只有 `测试中心/模块库/测试_文件内容扩充.py` 启动真实网关并设置 HTTP 连接器。

## P0：对外 HTTP 执行面未收口为一个

当前仍存在多个独立 HTTP 服务或业务 POST：

- `运行核心/统一网关/流式HTTP.py`：独立流式执行与取消路径，未复用主网关凭证、项目/用户边界和审计。
- `MCP工具箱/能力网关.py`：独立能力搜索/契约服务，CORS `*`，无统一凭证/限流。
- `支持库/后端/HTTP服务支持库/实现/HTTP服务.py`：`/调用`、`/能力/调用` 直查函数执行，绕过网关契约。
- `支持库/前端/浏览器宿主/实现/浏览器宿主.py`：`/api/调用` 任意回调执行。
- `开发工具/轻代码前端编辑器/启动编辑器.py`：`/工程/请求` 可直接提交工程操作。
- `开发工具/项目编译/项目编译器.py`：另起 HTTP 服务并代理调用。

落点：只保留运行核心本地网关作为业务对外面；其余改为内部客户端/适配器或测试夹具，统一通过 `POST /网关/调用`（健康仅保留 `GET /健康`）。完成前不得宣称“单一网关”。

## P1：网关凭证与身份边界仍需完整收口

`运行核心/统一网关/本地网关.py` 已将 `禁止客户端身份` 默认收紧为 True，并通过网关回归；但 `要求凭证` 在未配置凭证环境变量时仍可匿名调用，生产入口尚未强制凭证，且需补跨入口身份注入/伪造负测。

落点：生产构造器默认 fail-closed；身份只能由已验证凭证/服务端会话注入；伪造字段固定返回 403，并补真实 HTTP 负测。同步更新示例和测试配置，不能靠调用方自觉传安全选项。

## P1：句柄、租约和进程身份未形成权威原子事务

`运行核心/资源协调/句柄服务.py` 创建时先保存句柄再保存租约，失败会留下有效句柄而无租约；保存时未传进程身份键，死亡进程清理无法匹配。状态查询优先使用进程内缓存，跨网关实例看不到 SQLite 失效/过期。

落点：句柄、租约、进程身份在同一 SQLite 条件事务中提交；失败整体回滚；关键状态/续租/关闭以权威库 CAS 为准，内存只作带版本缓存。

## P1：Provider 调用超时存在并发竞态

`运行核心/运行环境管理器/提供者生命周期.py` 并发调用时修改共享 `进程.调用超时秒` 后恢复，线程交错会令请求读取其他请求的超时预算。

落点：超时作为单次调用参数传入受管进程，或至少把属性读写与发送请求纳入同一调用锁；新增不同超时并发真实测试。

## P1：网络请求层安全边界仍不完整

- `支持库/后端/网络通信支持库/请求/实现/网络请求.py` 的 HTTP 错误、下载上限和超限截断文件清理已修复；仍需正式 HTTP 集成回归。
- `SSL验证=False` 仍可关闭 TLS 校验，必须纳入策略门禁或明确仅限受控本地场景。

## P1：知识检索/文档读取错误路径需 HTTP 回归

知识检索和文档读取的静默成功已改为失败透传并校验返回结构，但当前没有完整的真实网关故障集成测试；文档解析资源安全释放失败仍只记诊断并继续成功返回，需改为统一失败结果。

## P1：Provider/实现直导、mock 和 skip 混入公开验收

`测试中心/支持库/测试_*提供者.py`、`测试中心/模块库/测试_*.py` 仍有大量实现直导、`mock.patch` 和环境 `skipTest`。这些只能证明内部逻辑或外部环境缺失，不能证明 `/网关/调用`。

落点：拆分 Provider 生命周期、模块逻辑、HTTP 集成、外部依赖四类结果；公开能力缺 HTTP 集成或未解释 skip 时，发布门禁必须失败。

## P1：HTTP 集成覆盖门禁本身可被文本伪造

`开发工具/发布门禁/运行发布门禁.py` 已改为 AST 结构筛选，注释和普通字符串不能再直接命中；但 AST 仍只是静态候选证据，不能证明真实启动网关、发送 POST、校验响应和错误路径。

落点：改为运行时集成矩阵，逐模块启动唯一回环网关并真实 POST；服务端记录请求次数/能力 id，客户端校验成功、失败、超时、取消、句柄和资源释放；证据绑定当前工作区指纹。文本扫描只能作为漏测提示，不能作为通过条件。

## P2：其它已确认边界

- `支持库/后端/HTTP服务支持库/实现/HTTP服务.py` 的短读和未知方法响应已修复为有界 JSON 错误；该服务仍属于待收口的独立 HTTP 执行面。
- `测试中心/运行核心/测试_HTTP连接器.py` 的客户端超时后服务端 `BrokenPipeError` 仍会产生未捕获 stderr，测试虽绿但证据噪声未清理。
- `模块库/简单窗口/实现/简单窗口.py` 以进程内字典保存窗口状态，跨进程/多实例不一致；状态应迁移到网关核心受管资源。
- `运行核心/统一网关/流式HTTP.py` 请求头阶段和取消路径仍未纳入统一认证、限流和审计链。

## 本轮验证边界

- 已通过：运行器工作区超时/清理回归 5 项；网络请求层手工 HTTP 复现（503 明确失败、下载超限失败）；文档读取定向测试。
- 未通过或未完成：完整发布门禁；全模块 HTTP 集成矩阵；唯一网关收口；句柄租约原子事务；身份 fail-closed。

## 性能审计新增结论（2026-08-29）

- 原因已定位：慢速层中的 31 个文件此前大多串行；其中“残留审计”还会嵌套启动发布门禁，形成重复全量验证。
- 已落地调度改进：`测试中心/运行测试.py --并行慢速` 按资源族分组，独立临时根的慢速文件进入并行工作包；强杀、固定端口、共享数据库、发布指针、残留审计等文件继续串行。一次实测慢速批约 38 秒完成调度，未出现并行资源冲突；失败仍返回非零。
- 真实门禁仍被 10 个模块缺真实 HTTP 集成证据阻断；提速不能替代集成链路修复。
- 工程缓存属于可再生物；验证前应清理 `工程缓存/验证运行` 后再运行摘要更新，避免缓存残留源码被门禁判为污染。
