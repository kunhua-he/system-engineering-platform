### 2.2 底座统一调用铁律（华哥裁决）

- 所有能力只走 `调用能力(能力id, 参数)` 一个公开接口；网络边界统一 `POST /网关/调用`。
- 模块不得 import 支持库/提供者/实现目录；只持能力 id + 契约版本 + HTTP连接器。
- 统一返回 `成功/值/错误码/错误说明/可重试`；错误码中文；类型漂移立即拒绝。
- 传参类型铁律：一次传参必须用句柄；id 是句柄内的资源定位，只作二次传参。

## 三、目标方案（待华哥审核后开工）

### 3.1 分层设计

```text
新增能力（直播逐字稿，领域模块 = 组合现有公开能力）
        │  只持能力id + 契约版本 + HTTP连接器
        ▼
模块库.直播逐字稿          ← 新增（功能模块，组合编排，纯逻辑）
        │  经 HTTP连接器 调用能力(能力id, 参数)
        ▼
现有公开能力
  媒体处理.提取音频  → 视频抽音轨
  媒体转写.转写音频文件 → MLX Whisper 受管子进程转写
        │
        ▼
（领域编排需要的原子能力若缺失才新增支持库/提供者）
```

### 3.2 拟新增能力契约（模块库.直播逐字稿，草案）

| 能力id | 参数 | 返回 | 说明 |
|---|---|---|---|
| 直播逐字稿.转写媒体文件 | 文件路径(文本,必填)、输出目录(文本,必填)、分片秒数(整型,默认300)、重叠秒数(整型,默认15)、模型配置(字型)、附加术语(文本)、超时秒(双精度,默认7200) | 结果型{输出目录, 状态, 场次名, 原始逐字稿路径, 疑难清单路径, 已完成分片, 分片总数} | 一次调用：探测→提取音频→规划分片→逐片转写→断点续跑→产出原始逐字稿+疑难清单 |
| 直播逐字稿.检查可用性 | 超时秒 | 结果型{可用, 转写模型, 是否配置模型, ffmpeg} | 探测底层链路 |
| 直播逐字稿.读取项目状态 | 输出目录(文本,必填) | 结果型{状态, 阶段, 分片进度...} | 断点续跑查询 |
