# 45 沙箱执行命令失败路径崩溃修复

## 阶段一：问题 → 方案 → 影响范围

### 发现路径

2026-09-12 全包合规扫描（`开发工具/组件合规/合规测试包.py` 的 13 场景，作用于 `扫描正式包` 的 116 个正式包）时，
`系统核心支持库.进程管理.沙箱执行命令` 在「真实返回值」场景报：

```
缺必填参数调用异常（失败语义缺失）: name '来源' is not defined
```

### 问题现象

实现文件 `支持库/后端/系统核心支持库/进程管理/实现/进程管理.py` 的 `沙箱执行命令` 有 **6 处** `结果.失败(..., 来源=来源)`，
但该函数签名只有 `命令 / 工作目录 / 超时秒 / 输出上限字节 / 环境变量` 五个参数，**没有 `来源`**，模块内也没有 `来源` 常量。
同文件其余 21 处一律写字面量 `来源="进程管理"`（例如 `启动进程`、`执行命令`、`终止进程`），只有这一个函数引用了裸名。

后果——该能力**所有失败路径都抛 `NameError`，而不是返回失败结果**：

| 触发条件 | 契约承诺 | 实际行为 |
|---|---|---|
| 空/非文本 `命令` | `参数不合法` | 抛 `NameError` |
| 缺 / 空 `工作目录` | `参数不合法` | 抛 `NameError` |
| `工作目录` 不存在 | `目录不存在` | 抛 `NameError` |
| 非 macOS 平台（无 `sandbox-exec`） | `沙箱不可用`（fail-closed，不降级） | 抛 `NameError` |
| 命令执行超时 | `超时` | 抛 `NameError` |
| 执行过程抛异常 | `执行失败` | 抛 `NameError` |

其中「无沙箱平台 fail-closed」是该能力说明书明文承诺的安全语义（`包声明.json` 与能力契约的 `说明` 都写了
「无沙箱平台 fail-closed」），`NameError` 使这条承诺**在 Linux 上直接失效**。
成功路径（macOS + 合法参数 + 正常退出码）不经过上述分支，故长期未被发现。

### 判据：为何是真缺陷，不是工具误报

本次扫描对**父级聚合包**存在一类系统性误报：父包（如 `数据操作支持库` / `办公文档支持库` / `系统核心支持库`）
自身无 `能力契约/`，却经 `__init__.py::注册能力` 注册了全部子能力；合规器取不到父包契约 → 参数表为空 →
零参调用子实现 → 一律报 `missing N required positional arguments`。**这一类是误报，不动。**

`沙箱执行命令` 的 `NameError` 不同：

1. 它在**子包 `进程管理` 自己的契约下同样复现**（该契约有完整 5 个参数；只要 `命令` 留空即命中失败路径），与父包聚合无关；
2. `name '来源' is not defined` 不是缺参异常（缺参会抛 `TypeError: missing required positional argument`），
   而是**实现内部引用了未定义名字**——与工具怎么调用无关，任何调用方只要命中失败路径都会崩。

### 解决方案

1. **代码修复**：`来源=来源` → `来源="进程管理"`（6 处），与同文件其余函数口径一致。
2. **契约补齐**（使契约与实际行为一致，该能力此前缺项）：
   - `能力契约/参数契约.json` 的 `沙箱执行命令` 条目补 `返回` / `错误码`（`参数不合法` / `目录不存在` / `沙箱不可用` / `超时` / `执行失败`）/ `调用示例`；
   - `权限契约/权限契约.json` 补 `系统核心支持库.进程管理.沙箱执行命令` 条目（同包其余 7 个能力均有，格式为 `{"允许用户": ["*"]}`）。
3. **回归测试**：新增 `测试中心/支持库/测试_进程管理.py`，断言各失败路径返回失败结果（`结果.失败`，`成功=False`）而非抛异常。
4. **摘要重算**：按平台生成器重算 `进程管理` 与父级 `系统核心支持库` 的 `完整性摘要.json`。

### 影响范围

只动 `支持库/后端/系统核心支持库/进程管理/` 一个包，加一个测试文件。
不碰 `公共契约`、不碰网关、不碰同文件其它能力、不碰其它包。

### 未纳入本批（记录待办，不静默丢弃）

扫描命中但**本批不动**的三类，理由如下：

- **父包聚合误报**（`missing N required positional arguments`）：如上所述是合规器对无契约父包的调用方式问题，非缺陷。
- **13 场景的「契约元数据完整性」类**：`缺少 返回结构 / 错误码 / 可执行调用示例`、`公开能力缺权限声明`、
  `缺少 依赖契约/配置契约/资源预算.json/复用决策.json`。该类覆盖 40 个包，
  且 `开发工具/发布门禁/运行发布门禁.py:883` 明载「1.5 权威合规-逐包13/13 已移除（华哥裁决 2026-08-29：慢速审计不需要）」，
  即已裁决不在发布门禁内。**除本批顺带修的 `沙箱执行命令` 外，其余不在本批范围**，如需全量补齐另行立项。
- **「吞异常」4 处**（`会话存储.py` / `检查点恢复.py` / `进程管理.py` / `浏览器自动化提供者/执行器.py`）：
  逐处查看均为**尽力而为的清理容错**——`ALTER TABLE ... ADD COLUMN` 的幂等补列、错误处理中强杀进程组的 `try/except`，
  后随 `return` 或继续抛回原错误。合规器的正则无法区分「清理容错」与「吞掉业务异常」，属正则粗糙，非缺陷。

### 3. 契约补齐（与被修实现对齐）

- `能力契约/参数契约.json` 的 `沙箱执行命令` 条目补 `返回` / `错误码`（参数不合法 / 目录不存在 / 沙箱不可用 / 超时 / 执行失败）/ `行为` / `提供者` / `调用示例`，键序与同包其余 7 个能力一致（…参数 / 返回 / 错误码 / 行为 / 提供者 / 调用示例）。
- `权限契约/权限契约.json` 补第 8 条 `系统核心支持库.进程管理.沙箱执行命令` → `{"允许用户": ["*"]}`。

**交叉印证（关键）**：`说明/使用说明.md` 的 `沙箱执行命令` 段**早已列出完全相同的 5 个错误码**。
即本次是**契约落后于说明书**，错误码系从实现源码独立推导，与既有说明书逐字一致，非新造。
`行为.副作用` 取 `外部进程`（该能力真实派生 `sandbox-exec` 子进程），与全仓 5 个外部进程类能力
（FFmpeg/LibreOffice/textutil 提供者等）同一词表；`资源释放`=`子进程自动回收+临时输出文件自动清理`、

### 7. 遗留（本批不修，已登记）

- **同包另 3 个能力错误码未声明**：`启动进程` 缺 `启动超时`；`等待进程结束` 缺 `等待失败`/`超出限制`；
  `执行命令` 缺 `超出限制`。属「实现返回了契约未声明的码」，与 `说明/使用说明.md` 同向陈旧
  （说明书 `启动进程` 段还缺 `就绪地址`/`就绪超时秒` 两个参数）。全仓同类约 60 个能力，
  是**多产物同向漂移**，单点补会让三份产物更不一致，故整类另立一批。
- **`能力定义.json` 系统性漂移**：`开发工具.契约编译.能力定义编译器.校验能力定义` 全仓 101 包中
  **25 包 / 69 个能力**不达标；且契约版本实测跨 `1.0.0 / 1.1.0 / 1.2.0 / 1.3.0`，
  而 `生成能力契约` 硬编码 `1.0.0`、不产出 `中文名称`、缩进 1 —— **编译器已落后于磁盘产物**，
  全仓 0 个文件带其「生成标记」；`检测能力定义漂移` 仅在 `测试中心/开发工具/测试_能力定义编译器.py`
  的夹具上运行，从未作用于真实包，故该漂移不进任何门禁。**结论：磁盘产物为事实源，编译器为过期生成器**，
  故本批**不按编译器重生成**（会丢 `中文名称`、把契约版本降级为 1.0.0），也不手改 `能力定义.json`。
- **`依赖生命周期审计` 1 个提供者 2 条违规**：`支持库/适配层/YAML提供者` 缺 `能力定义.json`
  （缺健康探针）+ `实现/` 下无停止函数且无生命周期释放契约（缺停止入口）。
  17 个同类适配层提供者中**仅此 1 个**缺 `能力定义.json`，且该缺口从未被提交过（非本次引入）。
  补齐需**新增探针能力或生命周期契约 + 停止入口**，即新增公开能力面，属设计决策，另立一批。
