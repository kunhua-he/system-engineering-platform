# 编译产物深化第一批实施计划

> 目标：把当前“每次清理输出目录重新打包”的编译器，升级为“依赖闭包指纹 + 不可变版本产物 + 缓存命中 + 稳定指针”的第一版。
> 边界：只改系统工程平台底座；不改 V3；不改 40007、8866、8766 的职责；不做在线热补丁；不引入 PyInstaller/Nuitka。
> 验证级别：工作包 → 合并波次；本批不跑正式全量发布门禁，阶段收口时再统一执行。

## 单腿实施流程

```text
先写失败测试
  → 编译器计算目标依赖闭包指纹
  → 未命中时生成新的完整制品版本
  → 命中时直接复用完整制品
  → 候选.json（待验收）
  → HTML验证成功后通过 `--激活到` 原子写入 `当前.json`
  → HTML验证器按制品目录或当前指针启动同一个制品
  → 真实HTTP验证
  → 定向回归
```

## 本批明确不做

```text
不在线修改正在运行的产物
不把直连地址接入正式发布证据
不新增第二业务执行网关
不把源码工作区总指纹作为运行时依赖
不把缓存索引作为能力注册事实源
不改 V3
```

## 任务一：先补编译器缓存契约测试

**文件：**
- 修改：`测试中心/第一批维修/测试_统一编译器.py`
- 目标实现：`开发工具/项目编译/项目编译器.py`

**测试内容：**

1. 同一项目、同一编译目标、依赖内容不变，第二次编译返回缓存命中和相同制品指纹。
2. 修改页面 JSON 后，第二次编译返回新制品指纹，旧版本目录仍存在。
3. 手工修改缓存制品后，完整性检查失败，不得命中缓存。
4. 当前指针只指向通过生成的制品版本。
5. 缓存目录不包含测试中心、开发文档和源码工作区缓存。

**验证命令：**


## 任务二：实现依赖闭包指纹和不可变版本目录

**文件：**
- 修改：`开发工具/项目编译/项目编译器.py`
- 复用：`开发工具/项目编译/正式包索引.py`
- 复用：`开发工具/项目编译/工作区指纹.py`

**实现边界：**

1. 从当前 `计算影响闭包()` 的能力、模块、页面结果继续向包目录和运行时目录展开。
2. 对实际会复制进制品的文件逐个计算 `sha256`。
3. 将项目id、编译目标、依赖闭包文件表、编译器版本和运行时版本组成制品指纹。
4. 缓存目录使用项目根路径摘要隔离不同项目，避免同名项目互相命中。
5. 新版本先写入临时目录，摘要完成后原子改名为制品指纹目录。
6. 已存在且摘要一致的版本直接命中，不重新复制和生成。
7. 输出目录作为部署镜像；缓存版本目录作为不可变事实，输出复制必须采用临时目录后原子替换。
8. 写入 `候选.json`，只保存待验收制品的指纹和版本路径；HTML验收成功后才由 `--激活到` 写入 `当前.json`，不保存业务数据。
9. 运行时来源提交/工作区指纹只写入来源元数据，不参与制品运行判断。
