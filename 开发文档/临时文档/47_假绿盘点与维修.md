# 47 假绿盘点与维修

## 阶段一：问题 → 方案 → 影响范围

### 任务背景

华哥口径：本平台的**真测试只有两个**——① 编译（`开发工具/组件合规/合规测试包.py` 的 13 项强制场景，单侧合规检查）；
② 前端 HTML 并发批量测试（集测，验证传参与取回）。其余 `测试中心/` 下的用例属临时性。
本任务：盘出**假绿**（声称检查通过、实际没验证到东西）与 bug，逐处维修。

### 假绿判据

1. 空跑：检查集合为空仍报「全部通过」。
2. 取错字段/恒空：判据字段名与实际数据不符，条件恒短路。
3. 非期望类型静默通过：`isinstance(x, dict) and ...` 塞进推导条件，x 非 dict 时推导结果为空 → 误判通过。
4. 名实不符：注释/文案声称验证 A，代码实际验证 B 或什么都没验证。
5. 反向检查恒真：声称验证并发/异常，实际跑最平凡的单次成功路径。

### 方案

- A：`_场景依赖` 改取 `能力` 字段，复用 `_提供者锁定` 的真实定位（消除同文件重复实现）。
- B、C：非期望类型显式判失败（把 `isinstance` 从推导条件里提出来前置校验）。
- D：先在真实包上测量「成功路径返回失败」的实际数量，据结果决定是否收紧判定。
- E、F、G、H：逐处按「名实相符」修——要么让代码真做它所声称的事，要么让文案如实描述。

## 阶段二：实际结果 → 调用方式

### 一、A~D（组件合规 13 项场景）

| # | 实际改法 | 证据 |
|---|----------|------|
| A | `_场景依赖` 改**按声明形状分别核验**：依赖契约实际有三种形状——① 能力项（`能力`/`版本`）→ 交 `_提供者锁定` 校验锁到真实提供者；② 包id项（`包id`/`版本`）→ 经 `发现全部` 的真实包声明确认包存在；③ 外部依赖项（`模块名`/`名称`，如 Python 标准库 sqlite3）→ **如实排除在系统内包发现核验范围之外**，不冒充通过也不误判失败。三者皆无的项判失败。文案按实际口径输出（能力 N 项/包 N 项/外部 N 项）。 | 改前 `依赖.get("包id")` 恒空 → `if` 恒短路 → 依赖场景对任何包都零检查。**中间踩坑**：第一版只认 `能力` 字段，跑全仓 110 包比对发现 **74 全通过 → 70**，4 个包（SQLite数据库/图像处理/文件管理/网页浏览）被误判红——它们的依赖契约分别用 `包id` 与 `模块名` 形状。改回三形状后逐包比对**场景集合零差异**。 |
| B | `_场景权限`：`权限契约` 顶层非对象（如 `[]`）**前置判失败**并点名实际类型，`isinstance` 不再塞进推导条件。 | 改前非 dict 时 `缺失权限` 恒空 → 报「N 个能力全部有权限声明」。 |
| C | `_场景结构` 资源预算：`资源预算.json` 顶层非对象**前置判失败**，缺失项检查只在确认是对象后执行。 | 同上，改前恒通过。 |
| D | 成功路径判定**维持「非空返回」不判成功标志**，并在代码里写明原因（本场景是编译期合规检查，最小参数在无外部资源环境里跑，文件/服务类能力必然返回 `失败(...)`；改判成功标志等于把编译检查变成环境检查，环境不齐就整包变红）。同时把失败路径的“成功标志提取”抽成 `_成功标志()`：**非统一结果不再被当成成功**。 | 返回文案 `真实调用 N 个能力全部非空返回` 与判定口径一致，无夸大；`_成功标志` 对普通 dict 业务数据返回 `None`，而不是旧的“非 dict 即不算成功、dict 无 `成功` 键即算失败”混口径。 |

### 二、E/F（`第十四阶段门禁.py`）

- **E 双迁移互斥**：改为**真并发**——同一存储目录起两个线程迁移，`编排.步骤延迟秒=0.25` 制造交叠窗口，断言「结果恰好 2 条、推进数恰好 1、每条只能是 推进/复用/冲突」。连跑 3 次稳定 `并发:['推进','复用'](推进1)`，即真实验证了“第二个必须复用或冲突、不可能两个都推进”。
- **F 二阶恢复**：原名「二阶恢复强杀」全程不 spawn/kill 任何进程，与 `权威状态门禁._强杀持锁恢复`（真强杀）重复且名实不符 → 更名 `_项6_二阶恢复幂等`，判定项名 `第十四阶段-二阶恢复幂等`，文档串如实描述“幂等性，不含强杀”。

### 三、G（`测试_发布门禁收敛.py` 名实不符）

测试声称验证「门禁逐包真实调用合规器 13/13」，但 `执行逐包权威合规` 已按 2026-08-29 裁决**从发布链移除**（发布只认 HTML 黑盒验证）——该测试是 import 了函数单独跑，**门禁接不接都绿**。

**修法：不改生产链（裁决是刻意的），只如实描述**——文件与类文档串写明“本文件只证明 合规器 与 MCP合规 两边口径一致，不能当作门禁仍在做逐包合规的证据”，并把 `门禁` 字样的判定名/断言文案统一改成 `逐包合规器`。11/11 仍绿。

### 四、H（`运行发布门禁.py` 第三方访问声明 空集放行）

**实测**：稳定激活制品 `工程缓存/制品仓库/平台客户端环境/平台客户端` **不含 `支持库/` 目录** → `校验第三方访问声明` 在发布路径上**恒定走空集分支**，永远报「无需第三方访问声明」；同时在 `支持库/后端/文档转换支持库/*` 里**真有 3 份依赖锁**（命名不含「提供者」，落在审计口径之外）。

**修法（不动通过/失败语义）**：
1. 依赖锁存在但**没有任何包/直接依赖条目** → 直接点名「访问声明不可核验」，不再 `continue` 静默跳过；
2. 支持库/适配层 下 0 提供者时，**不再断言「未声明第三方依赖」**：若制品整体不含 `支持库/` 目录，如实报「本项声明核验对本制品为空」；若含，则报出「适配层外另有 N 份依赖锁不在本项核验范围」。

**未改通过/失败语义，属待华哥裁决项**：制品不含 `支持库/` 时本项是否该直接判红（见下「需华哥定夺」）。

### 六、已判定、**不修**（附理由）

1. `验证门禁.py::_检出收集错误` 的 `re.search(r"\bERROR", 文本)` 大小写敏感。**不修**：改为大小写不敏感会把 pytest 明细输出里的**测试名**（如 `test_error_recovery`）当成收集错误 → 正常run 变红。收集失败在 pytest 下退出码非 2 即非 0，退出码这道主闸已拦死；`errors=` 分支已覆盖小写形态。
2. `验证门禁.py::_检出未解释跳过` 的 `原因` 分支过宽（输出里任何位置出现「原因」二字即认定所有跳过都“有解释”）。**本批不修**：收紧必须按**行**配对（跳过行自带原因），而 pytest 不开 `-rs` 时只在汇总行打印 `N skipped`、根本不列原因 → 收紧了会把大量**合法**的 pytest 跳过判成未解释跳过、制造假红。需先确认 `测试中心/运行测试.py` 的 pytest 调用参数，见「需华哥定夺」。
3. `协作状态.py` 收口指纹不含命令/环境（同一文件同一提交、换个命令跑出的证据指纹相同）。属**绑定偏弱**，非假绿（不声称验证了命令/环境），保留。
4. `运行核心/依赖防火墙.py` 的子串排除集合。保留：其排除项是刻意的实现细节集合，未发现假绿路径。
