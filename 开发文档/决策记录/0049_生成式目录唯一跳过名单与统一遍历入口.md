# 生成式目录的唯一跳过名单与统一遍历入口

> 状态：现行
> 日期：2026-09-19
> 触发：华哥原话「一个命令六七分钟……这些生成出来的东西，不能列个名单？直接在一开始就跳过？我要的是无论任意时候，都需要可以跳过，就类似于 github 上传的时候可以选择跟踪和不跟踪那样子」

## 背景

全仓从系统根出发的 `rglob` 会**先枚举 31 万条目，再在 Python 层按路径过滤**。
实测分布：

| 面 | 条目数 | 占比 |
|---|---|---|
| `工程缓存/`（编译缓存/制品仓库/提供者运行环境/HTML验证证据/运行数据…，9.3G） | 314,386 | **97.5%** |
| 其余 16 个被跟踪的顶层源码目录合计 | 8,063 | 2.5% |

即 **97.5% 的枚举纯属白做**。实测两处代价：

| 场景 | 改前 | 改后 |
|---|---|---|
| `发布门禁.校验占位代称防回潮` | **202.6 秒**（310,072 条） | **11.1 秒**（3,334 份） |
| `单文件自查 --全仓` | 全枚举同量级 | **7.7 秒**（1,014 个 .py） |

两次都验证了**文件集合逐条完全一致**（1014 = 1014、3325 = 3325、零差异）——
所以这是**纯代价问题，不改判定结果**。

更深的问题不是慢，而是**名单有 8 份且互不相同**：

| 文件 | 名单内容 |
|---|---|
| `运行核心/依赖防火墙.py::排除片段表` | `pycache/__pycache__/工程缓存/测试中心/示例项目/开发文档` |
| `开发工具/复用审计/能力调用图审计.py::审计剪枝目录表` | 同上（抄的） |
| `开发工具/发布门禁/运行发布门禁.py::_占位代称跳过目录` | `工程缓存/.git/__pycache__/归档/参考资料/node_modules/制品仓库/编译缓存/提供者运行环境` |
| `开发工具/项目编译器.py::忽略目录` | `__pycache__/.pytest_cache/.ruff_cache/工程缓存`（**连 `.git` 都没有**） |
| `开发工具/快速编译/单文件自查.py::排除目录` | 又一份 |
| `开发工具/项目编译/工作区指纹.py::固定排除目录` | 又一份（含 `开发文档/项目证据`） |
| `技能库/技能/交付收尾/scripts/交付收尾.py::排除片段表` | 又一份（含 `完整性摘要.json`/`项目证据`） |
| `开发工具/验证门禁/门禁公共.py::剪枝目录表` | 从依赖防火墙转引 |

改一处不知道别处 —— 这是**第二事实源**的标准形态。

## 决策

**一张表 + 一个入口 + 一条门禁，三件都在唯一位置。**

1. **唯一名单**：`公共契约/正式根.py::生成式目录表`（顶层常量，不落任何其它文件）
   ```
   生成式目录表 = {工程缓存, .git, __pycache__, .pytest_cache, .ruff_cache, .mypy_cache,
                  .codegraph, node_modules, .venv, venv, 归档, 参考资料}
   ```
2. **统一遍历入口**：`公共契约/正式根.py::遍历源码(根, *, 后缀, 层名表, 剪枝=真)`
   —— `os.walk` **进目录即剪枝**，不产出再过滤。与既有 `枚举包声明路径` /
   `枚举包目录` 同族（本文件本来就是「哪些目录算正式面」的唯一事实源）。
3. **防回潮门禁**：`开发工具/验证门禁/全枚举门禁.py` —— AST 扫出「接收者绑定为整棵
   系统根」的 `rglob/glob/iglob` 即判红；已接进 `运行验证门禁.py`（统一入口）与
   `开发工具/开发编译口/编译口.py` 的门禁清单（阻断级）。

**剪枝开关语义**：默认 `剪枝=真`；确需扫生成式目录的少数场景（`工程缓存回收`、
`提供者环境回收`、制品校验类）显式传 `剪枝=假` —— **允许，但要写出来**。

## 考虑过的其他做法

1. **旁路文件夹（两个同根目录，项目代码与生成物彻底分家）** —— 否决。
   代价：`工程缓存` 在 **371 行 / 134 个文件**里被硬编码引用，全部要跟着改；
   且会给底座引入**第二套路径体系**（与「单一事实源」「不制造第二腿」直接冲突）。
   收益与「一张表 + 一个入口」相同，代价高一个量级。
2. **把 `工程缓存/` 改名成 `.工程缓存`（加点号，靠工具链默认忽略）** —— 否决。
   同样牵动那 371 处；且「点号开头」只是**约定俗成**的忽略，`os.walk` 照样会走进去，
   真正省下枚举仍要靠剪枝。收益不增加、代价不小。
3. **每一处 rglob 各自加 if 判断** —— 否决。这正是现状（8 份名单）的成因：
   改一处不知道别处，且新写的代码不会自动遵守。
4. **强制剪枝不可关（连显式参数都扫不到生成式目录）** —— 否决。
   `工程缓存回收`/`提供者环境回收` 的工作对象**就是**生成式目录本身，
   强制关闭会把它们打死。故用 `剪枝` 开关 + 门禁豁免标记双保险。

## 后果

- 好处：全仓遍历从「31 万条 / 200 秒级」降到「8 千条 / 秒级」；
  名单从 8 份收敛到 1 份；新写的代码由门禁自动拦住，**不依赖任何人记得**。
- 代价与限制：
  - 门禁是**静态 AST 判据**：只认「接收者绑定为整棵系统根」这一形态。
    运行期传入的根（`配置.项目根.rglob(...)` 扫业务素材）不判 —— 这是有意的放宽，
    因为那类扫的不是本仓生成式目录面。
  - 豁免靠行级标记（`全枚举豁免：` + 理由含「剪枝」或「需扫生成式」），
    与人自觉有关，故意写豁免仍能绕过（与 `依赖门禁豁免：` 同族、同一局限）。
  - `工程缓存` 内若出现真实源码仍需人工处理：剪枝是**按目录名整体跳过**，
    不做内容判别。

## 验证方式

```bash
# ① 等价性：剪枝前后文件集合必须完全一致
python3.14 -c "
import sys; sys.path.insert(0,'.')
from pathlib import Path
from 公共契约.正式根 import 遍历源码
根=Path('.').resolve()
新={p for p in 遍历源码(根, 后缀=('.py','.json','.md'))}
旧={p for p in 根.rglob('*') if p.is_file() and p.suffix in ('.py','.json','.md')
     and not any(段 in {'工程缓存','.git','__pycache__'} for 段 in p.relative_to(根).parts)}
print('一致:', 旧==新, len(旧), len(新))"

# ② 门禁自身：绿 → 注入真病必红 → 撤销回绿（三拍）
python3.14 开发工具/验证门禁/全枚举门禁.py          # 期望 0
#   （往 开发工具/验证门禁/ 放一个 `系统根=Path(__file__).resolve().parents[2]` +
#    `系统根.rglob("*.py")` 的样本，再跑 → 期望 1；删掉样本 → 期望 0）

# ③ 接线生效：编译口五态里出现「重复腿与旁路」项且为绿
python3.14 -m 开发工具.开发编译口.编译口 --变更
```
