## 共同病根：写入方给了参数，中间层收了却不用

四处独立故障，根因是同一个模式 —— **参数在某一层被"收下但没用"**，
症状全都伪装成别的问题（硬件不够 / 提示词不好 / 模型不行），排查时极易跑偏。

### ① 连接器吞掉「超时秒」（两个连接器）

`进程内连接器` / `HTTP连接器` 的构造默认 `默认超时秒 = 10.0`；模块层调连接器时
写的是 `连接器.调用能力(能力id, 参数)`，**没传 `超时秒=`** → 一律回落 10 秒。
转码/提取音频/媒体转写真实耗时是分钟级 → 必然判「超时」；而超时**不取消执行线程**
（Python 无法强杀，见 `超时执行.py` 既定立场）→ 每次误判留下一个仍在跑的 ffmpeg。

**症状链**：8 路配置 2 分钟累积 30 个残留 ffmpeg / 成功数 0 → 媒体引擎被占满 →
后续请求才真的报 `-22 Invalid argument` → 看门狗反复拉起 → 越滚越多的死循环。

**修复**：两个连接器在 `超时秒 is None` 时**回落到参数里的「超时秒」**（能力参数本就是
调用方的时限意图），显式传入仍优先；网关侧两个默认值 `10` → `1800` 与启动脚本对齐。
**一处修复覆盖全部 12 个漏传的模块**（OCR/图像处理/媒体处理/媒体转写/文件管理/
文档生成/文档解析/文档读取/简单窗口/网页分析/网页浏览/自修复工具）。

### ② 精校裁决没传「enable_thinking」

`生成对话` 支持 `chat_template_kwargs`（底座 2026-09-16 已加），但
`精校裁决.py` 的两处模型调用没传 → Qwen3.6-27B 默认开思考 → token 全进
`reasoning_content`、`content` 返回空串 → 底座判「模型调用失败」。

**症状**：质检报告里写「裁决失败 N 个窗口」，**不报模型错误**，容易误判成提示词问题。

**修复**：裁决的两处调用显式传 `chat_template_kwargs={"enable_thinking": False}`。

### ③ 启动命令硬编码 `-c 8192`

`_构建本地启动命令` 里 `命令 = [..., "-c", "8192", ...]` 写死，调用方给的
「上下文长度」完全没进启动命令。

**症状**：llama-server 侧日志 `E srv send_error: task id = N, error: Context size has been
exceeded.`，而调用方只看到「模型 HTTP 返回 500」→ 直接被误判成模型能力不足。

**修复**：按调用方给的「上下文长度」启动，未给或非法保持 8192（行为不变）。

### ④ 「上下文长度」在连接层就被丢掉

即使 ③ 修好也无效 —— `连接LLM` 调 `启动本地模型` 时写的是
`参数={"协议": 协议}`，**上下文长度在这一层就没进「参数」**，下游根本取不到。

**修复**：`参数={"协议": 协议, "上下文长度": 上下文长度}`。

**只有 ③④ 一起修，实例才会真的以 `-c 32768` 启动**（实测：修复前
`PID 94621 | -c 8192`，修复后 `PID 3244 | -c 32768`）。

## 被否决的做法

1. **在业务脚本里自己调 llama-server / 自己算超时**——第二执行腿，违反唯一入口；
2. **把模型上下文改小、把裁决窗口再切碎**——那是拿调用方迁就底座缺陷，
   且会牺牲逐字稿的跨窗上下文质量（不该由业务侧承担）；
3. **给超时执行器加强制终止**——Python 无法安全强杀线程，注册杀不掉的终止器属于撒谎；
4. **只改连接器默认值（10 → 大）**——掩盖断链，且静默改变其他所有调用方的行为。

## 验证（真实 HTTP + 真实模型，非推断）

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 转码 151MB / 209MB 源 | 10.1s 判超时、ffmpeg 残留 1 | **26.0s / 39.9s 成功，残留 0** |
| 生产转码任务首批（16 路） | 807 失败 / 0 成功 | **16 成功 / 0 失败 / 0 孤儿** |
| 精校裁决（19.5 分钟真实场次） | 裁决失败 3 窗口、未导出 | **裁决失败窗口 0、质检通过、导出 20230 字节** |
| 模型实例上下文 | `-c 8192` | **`-c 32768`** |
| 精校质检 | 长度比 1.03 / 数字保留率 1.0 / 通过=false | **长度比 1.155 / 数字保留率 1.0 / 通过=true** |

直接调模型验证参数本身有效（排除"模型不行"的误判）：
```
不带 enable_thinking:  finish_reason=length, content='',        reasoning_content='Thinking Process...'
带 enable_thinking=False: finish_reason=stop,   content='我是由阿里巴巴通义实验室…'
```

## 调用方注意事项

- 能力参数「超时秒」现在**同时是调用层时限**，必须 ≤ 网关请求超时（默认 1800）；
- 长耗时能力显式给足（压缩存档档实测 30 分钟长视频单文件约 12 分钟）；
- 本地推理模型**一律显式关思考**（Qwen3.6/gemma-4 实测默认开），否则拿到空 content；
- 需要长上下文的场景显式传「上下文长度」，并在**连接时**就给（它是启动期参数，
  连接后再改无效——实例已按旧参数启动）。
