# 方案文档生命周期规范立规与互踩收敛

> 最后更新：2026-09-18
> 口径：实测（数字与引用面现场核实，取证命令随文给出）
> 维护者：决策记录

## 一、华哥原话（本次裁决的起因）

> 「互踩的就提前收敛一下。 设计哲学是有声明周期或者是完善周期的；文档不能互相踩。
> 因为文档互相踩的情况下，会十分麻烦。 这个需要说清楚的」

## 二、现场实测：互踩不是假想问题

**2026-09-18 现场实测**：`开发文档/方案/` 共 **27 份** md，其中

- **4 份同时写「全仓批次编排」且各自自称权威**：
  `底座升级方案.md`（H1 写「唯一权威」）、`底座大版本升级方案_20260918.md`（写「唯一主线」）、
  `底座扩容总纲_一次性做透_20260917.md`（有「五、批次与依赖」+「六、待华哥拍板」）、
  `三条裁决总执行方案_20260918.md`（写「编排入口」）；
- **批次编号有三套互不相识的体系**并存：`P0–P9` / `批次 1–5` / `批 0–批 5` / `第 0 批–第 4 批`；
- **27 份里只有 3 份有状态声明**，其余无法判断是「生效」还是「历史」。

**后果**：新会话（或下一个人）**无法判断以哪份为准**；本次收敛时若不逐条核实，
会把仍存在的活当「历史」一起埋掉。

## 三、决定

### 3.1 立规：`开发文档/规范/方案文档生命周期规范.md`

| 条款 | 内容 |
|---|---|
| **铁律** | 方案文档是**过程件、不是事实源**；事实源仍是 `项目说明.md`（当前是什么）/ `未完成事项.md`（还欠什么）/ `决策记录/`（为什么）。方案只可**引用**，不得复述并另立数字 |
| **五态** | 起草 / 生效 / 已完结 / 已取代 / 已废弃；**头部必须有 `> 状态：` 声明**；无状态声明者**不得作为派活依据** |
| **编排唯一入口** | 全仓任何时刻**只允许一份**「编排入口」；换入口时旧入口**同批**改为「已取代」且**不得再留批次表** |
| **互踩五形态** | 编排冲突 / 自称唯一 / 主题重叠 / 同数不同值 / **隐形债**（子方案有待办但债务清单无登记）|
| **4.5 强制** | **子方案不得作为待办的唯一落点**：立项同批必须在 `未完成事项.md` 登记；标「已完结」前须确认施工项已销项 |

## 四、被否决的做法（防后人重走）

| 被否决 | 理由 |
|---|---|
| **把三份旧方案直接删掉** | 它们含**外部依据精读**（cosmic-ray / LitmusChaos / kyverno / please / Nix 等）与**建设期阶段表**，是有价值的历史；删了就找不回「当时怎么想的」。改为**标状态 + 保留正文** |
| **只标「已取代」不核实未闭合项** | 本次实测：不核实会埋 **5 条活**（其中 2 条确认仍存在）。**必须先抢救登记再标取代** |
| **判据用 `grep '唯一入口'` 扫全文** | 实测**报出 22 份假阳性**（把每份子方案状态行里「见 `执行编排_唯一入口_…`」的合规**引用**当成了「自称」）⇒ 判据必须**只扫 H1 标题行** |
| **状态判据只查「有没有 `> 状态：`」** | 实测：写成 `> 状态：已删除` 也能骗过存在性检查 ⇒ 必须**校验取值 ∈ 五态** |
| **给方案文档另建一套「版本号」** | 与已有决策记录/哲学空间重复；**状态声明已足够**表达生命周期 |
| **在子方案里维护「全仓批次」** | 这正是互踩的根源；**子方案只写「本件事的批次」，全仓批次只在唯一入口** |
