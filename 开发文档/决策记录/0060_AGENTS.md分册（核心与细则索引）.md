# 0060 AGENTS.md 分册（核心 + 细则索引）

> 裁决：华哥 2026-09-22（原话：「内容未必要丢失，但是需要用索引去找。否则的话每次几万字符直接就给炸圈了」）
> 背景：实测 Codex 收到的 AGENTS.md 只到 **16.3K 字符**就被截断（尾部断在半个字），后 2/3 规则——含《铁律》《文档与归档规则》——**Agent 根本看不见**

## 决策

AGENTS.md 按「是否每次开工都要」分册，**规则一条不删、移出内容一字未改**：

| 册 | 文件 | 字符 | 内容 |
|---|---|---|---|
| 核心 | `AGENTS.md` | 12,763 | 强制开工协议 / 定位 / 单腿铁律 / 验收 / 铁律 / 验证 + 细则查询关键词表 |
| 细则 | `开发文档/规范/项目细则.md` | 11,384 | 项目 MCP 与代码地图 / 单一网关与子代理继承协议 / 唯一分层方案 / 目录约定 / 文档与归档规则 / 每个支持库必备 |

- 原 23,311 → 新 12,763 字符（降 45.2%），**全部落进实测注入窗口内**
- 细则查法写在 AGENTS.md 首部（关键词表），走 `项目文档支持库.查询索引`
- 细则分册已入项目文档索引（实测：「子代理 任务信 继承协议」命中 11 块）

## 被否决的做法

| 做法 | 为什么否决 |
|---|---|
| 整份 AGENTS.md 索引化 | 硬规则必须每轮可见；索引化后 Agent 不知道规矩存在，等于无规则 |
| 删掉低频规则 | 华哥明确「内容未必要丢失」；且规则是审计基线，删了没法追溯 |
| 把规则压成摘要 | 摘要会丢判据与取证命令，规则失去可执行性 |

## 同批一条实测事实（回答「md 载入能不能精炼」）

**结构性精炼对现有文档无效**：项目说明.md / AGENTS.md / README.md / 当前流程图.md 做「折叠连续空行 + 去行尾空白 + 去首尾空行」后仅省 **0.0%–0.1%**。
字符多不是空白废话造成的，是内容本身啰嗦。要真降字符只能改文档本身，或做语义摘要（底座不做，会丢信息）。

**有效的是索引**（实测同一查询词）：索引·标题档 2,042 字符 / 简介档 6,533 / 内容档 35,080，而整份载入 项目说明.md 是 59,695 字符。
