# 0047 不合并「依赖锁相同的提供者环境」：保住环境目录 ↔ 提供者id 一一对应

> 最后更新：2026-09-18
> 口径：设计决策（起因是**实测**发现两份相同依赖的环境各占 2.8GB）
> 维护者：小马仔
> 状态：生效

## 一、决策

**不合并。** 即使两个提供者的依赖锁逐字段相同（除标识字段），其环境仍**各自独立保留**。

- 保留「`提供者运行环境/<提供者id>/<环境摘要>/`」的**一一对应**关系不动；
- 不为省磁盘去共享/软链/复用同一份环境；
- 该 2.8GB 的冗余**是已知代价，接受**。

## 二、★ 现场事实（实测，2026-09-18）

清旧环境时发现（`开发工具/提供者环境回收.py` 的副产品）：

| 项 | 实测 |
|---|---|
| `转写`（`支持库/后端/转写支持库/转写`） | 现用环境 2.8GB |
| `MLXWhisper提供者`（`支持库/适配层/MLXWhisper提供者`） | 现用环境 2.8GB |
| 两者依赖锁 | **除 `提供者id` / `生成时间` 外逐字段完全相同** |
| 两者 site-packages 包清单 | `diff` 无输出 = **完全一致** |

即：同一套依赖（mlx-whisper 0.4.3 / mlx 0.31.2 / numpy 2.4.4 / torch 2.13.0 / huggingface_hub 1.11.0）
被建了两份环境，可省约 2.8GB。

## 三、为什么不合并（理由）

1. **一一对应是排查环境问题的唯一把手**：环境目录名里的 `<提供者id>` 让人能直接从
   磁盘上的目录反查"这是谁的、由哪份依赖锁生成"；一旦两提供者共享一份环境，
   该目录归谁名下就变得任意 —— 出问题时"这份环境是给谁建的"要靠翻代码推断。
2. **`提供者id` 参与摘要计算是既有机制，不是缺陷**：`计算环境摘要(依赖锁, 提供者id)`
   把它算进指纹（`环境管理器.py`）。改这个机制属**对外行为变更**，收益（2.8GB）与代价
   （改机制 + 全量环境重建 + 对应门禁）不成比例。
3. **分层不同，不该因磁盘耦合**：两者分属 `支持库/后端/转写支持库` 与 `支持库/适配层`。
   共享环境会在两个不同层的提供者之间引入隐式耦合（一方改依赖锁会牵动另一方）。
4. **优化方向应指向真冗余，不是这个**：本轮已清掉的是**真正的垃圾**（43 个历史旧环境，
   省 5.0GB —— 那些是依赖锁变化后的残留，谁也不在用）；这 2.8GB 是**现用环境的设计性冗余**，
   性质不同。

## 四、被否决的做法（防止后人重走）

| 做法 | 否决理由 |
|---|---|
| 软链共享同一份 site-packages | 两个提供者的解析路径会互相影响；一个升级依赖即静默污染另一个 |
| 摘要只算依赖锁、不算提供者id | 需改既有机制 + 全量重建；且会让「谁的依赖变了」不再能由目录名分辨 |
| 保留 N 份历史环境只留 1 份（已落地） | 这条**已做**（`开发工具/提供者环境回收.py`，只留现用摘要）—— 与本决策不冲突：清的是**没人用的旧版本**，留的是**每个现用提供者各自那份** |

## 五、复现与取证

```bash
# 看两份环境是否相同
diff <(ls 工程缓存/提供者运行环境/转写/*/lib/python3.14/site-packages/) \
     <(ls 工程缓存/提供者运行环境/MLXWhisper提供者/*/lib/python3.14/site-packages/)
# 看依赖锁差多少
python3.14 -c "
import json
a=json.load(open('支持库/后端/转写支持库/转写/依赖锁.json',encoding='utf-8'))
b=json.load(open('支持库/适配层/MLXWhisper提供者/依赖锁.json',encoding='utf-8'))
[a.pop(k,None) for k in ('提供者id','生成时间')]
[b.pop(k,None) for k in ('提供者id','生成时间')]
print('除标识字段外完全相同:', json.dumps(a,sort_keys=True,ensure_ascii=False)==json.dumps(b,sort_keys=True,ensure_ascii=False))"
# 看当前有哪些旧环境可清
python3.14 开发工具/提供者环境回收.py
```

## 六、影响范围

- **无代码改动**（本决策即"不动"）；
- `开发工具/提供者环境回收.py` 的行为不受影响：它只按「现用摘要」判，本决策保留下来的
  两个现用环境都属"现用"，不在可删之列（实测复跑：旧版本 0 个）。
