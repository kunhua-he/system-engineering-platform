# 0051 开工即占接开工ID与乐观锁指纹归一

- 日期：2026-09-19
- 触发：华哥问「不同开工 ID 会自动建 github 独立工作区吗？撞车文件有乐观锁对吧？」
- 结论：**不建 worktree**（遵 `多会话并行开发规约.md` 第二章裁决）；**乐观锁补齐并实测**。

## 一、worktree 为什么不做（已有裁决，不重复实现）

`开发文档/规范/多会话并行开发规约.md` 第二章已否决「复制一份（工作树/克隆）」：
平台是「网关 40007 + 能力注册表 + 数据库 + 编译产物」一体的，**副本里跑起来的服务仍只认主目录，
验证根本没法做**，且最终合并照样冲突。华哥问「会不会影响开发进度」——
worktree 会**同时拖慢验证与合并**，与「保证开发进度」的目的相反，故不做。
正确路径是规约已有的**第三条路：同仓 + 分区认领 + 写前校验**。

## 二、乐观锁：零件早已在场，本次把它接到开工入口

**实测推翻规约两条过期结论**（原文说「尚无公开原子能力」「机制三当前不存在」）：

| 规约旧说法 | 实测（2026-09-19） |
|---|---|
| 文件租约申请/续租/释放尚无公开原子能力 | **六个能力全在场**：申请/续租/释放/回收过期/查询/留言 |
| 心跳与过期回收当前不存在 | `回收过期文件租约` 在场，租约带 `持有秒`（实测缺省 300 秒） |

因此本次不新建任何机制，只做**接通**（哲学 1.3「结果唯一即收口」）。

## 三、改了什么（全部在 `模块库/开工编排`）

1. `开工即占` 接开工 ID：入参新增 `开工ID`（不传即当场生成，**与 `开工准备` 同一入口同口径**），
   返回值新增 `开工ID`——不管开工成功还是被挡都回带，收工按它提交。
2. `开工即占` 新增 `校验指纹`（逻辑型，缺省 假）：真 时把声明指纹一起交给底层，
   声明与现场不一致即**整体不开工**（错误码 `内容已变更`）。缺省 假 = 老行为逐字不变。
3. `修改路径` 兼容 `{"路径": …, "指纹": …}` 认知条目；**边界校验仍逐条执行**，
   不许因为「多了个指纹」绕过安全判据。
4. **指纹格式归一**（`_归一指纹`）：底层标准格式是 `sha256:<64位小写hex>`；
   调用方常用裸 `hexdigest()`，直接比对必然误判「内容已变更」。
   裸 64 位 hex 自动补前缀；`不存在`/`目录`/`不可读:…` 等底层常量原样透传，**不做猜测性改写**。

## 四、验证（经唯一网关 40007 真实调用，非单元自证）

| 场景 | 期望 | 实测 |
|---|---|---|
| ① 会话1 先占 | 已开工=真 + 回带开工ID + 租约id | ✅ `开工-20260919-154412-7374` |
| ② 会话2 抢同一路径 | 已开工=假 + 回报占用者 | ✅ 「活跃租约属 会话1（租约id=…），过期时间 …」 |
| ③ 会话1 收工释放 → 会话2 再占 | 放行 | ✅ 释放 1 条，会话2 再占成功 |
| ④ 错指纹 + 校验指纹=真 | 被拦 | ✅ 错误码 `内容已变更`，回带两侧指纹 |
| ⑤ 正确指纹 + 校验指纹=真 | 放行（不误伤） | ✅ 已开工=真 |

**合计 9/9 通过**。编译 6 份派生问题 0、包体检无缺项、热接入 `已注册能力数=701`。

## 五、被否决的做法（避免后人重走）

- **不做 worktree/克隆隔离**：无集成环境，验证做不了（规约第二章）。
- **不新增第二套租约**：六个底层能力已在场，只接通不重造。
- **不在底层容错裸 hex**：格式归一放在**开工入口**（哲学 8.2 加模式变量），
  底层 `指纹是否一致` 保持严格相等——底层放宽会让「真的被改过」也悄悄放行。
- **不默认开 `校验指纹`**：缺省 假，避免老调用方（只传路径字符串）被新闸门误伤。
