# 0032 借用 §8.2 十九项待裁的裁定：十六项哲学自裁、三项真需华哥

> 状态：**现行** ｜ 2026-09-17
> 起因：华哥「哪一些是要我拍板的？应该我的设计哲学应该是有的吧？」
> **结论：19 项里 16 项哲学本来就有答案**（此前把它们列进「待你裁决」是维护者的疏漏 —— 哲学第 12 条给的授权是「按哲学判断，哲学不足才问」），
> 只有 **3 项**真无成文出口。以下逐条给裁定与依据。

## 二、真需华哥的 3 项（哲学确实无成文出口）

| # | 事项 | 为什么哲学判不了 |
|---|---|---|
| 20 | **能力 id 形态**：499 个裸族名 vs 5 个带包 id 前缀，两套并存 | 哲学 6.2 只管「命名一眼能懂」，**不管 id 的形态口径**；D-12 有「模块能力 id 改回本包前缀」的先例但不构成通则 |
| 22 | **7 件架构拓展 + 2 条边界预留**（统一配置加载器／Schema 迁移／请求 id 贯穿／任务队列上限／能力分类树／结构化日志／租户 id 预留；权威状态接口抽象／任务执行器接口抽象） | 属**产品范围决策**（要不要长这些功能），不是技术债；哲学第 4 条「不做」清单已明确「不扩能力数量」，故不能自裁为「做」 |
| 23 | **卡点 D：样本＝接口义务，还是先放未来** | 哲学 12.5 已写「样本是接口义务是当场红」，但外部材料主张「故障注入先放未来」——**两者是对立主张，哲学只能定「已采纳哪条」，不能定「何时全面铺开」**；铺开范围与优先级属排期决策 |
