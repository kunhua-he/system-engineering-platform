# 0017 快照校验「快照不存在」的判定口径：未命中不是失败

> 状态：现行
> 关联：`平台控制面/快照校验/实现/提供者.py`、`平台控制面/快照校验/说明/设计说明.md`、
> `开发工具/HTML验证/场景加载.py`（能力全覆盖判据）、`开发文档/决策记录/0016_验证场景越界用例口径.md`

## 背景

统一验收时 HTML 黑盒验证器的**能力全覆盖判据**报红：`平台控制面.快照校验.校验状态兼容范围`
**没有正向目标步骤**（662 个公开能力里唯一的缺口）。

深挖发现这个能力**写不出正向步骤**，原因是硬的：

- `实现/提供者.py` 里该函数**唯一的成功分支**前置条件就是「库里有这条快照记录」；
- 而**全机没有任何公开能力能创建核心快照记录**——662 个公开能力里不存在「创建快照」（`平台控制面/核心快照管理` 包不存在）；
  唯一写入口是平铺文件 `平台控制面/核心快照.py::创建快照`，其全仓唯一调用点是 `平台控制面/提供者/版本兼容.py`（包内实现）；
- 本机全部可达的 `权威状态.db`（源码仓内 4 处 + `~/Library/Caches/系统工程平台/运行缓存` + 制品自带）**「核心快照」表行数全部为 0**。

于是该能力在只读场景里**只能返回失败**，而验证器要求正向步骤必须 `预期成功=true`：
写 `成功=true` 会运行期红，写 `成功=false` 会加载期被覆盖判据 blocked（自相矛盾）。

同时发现一个**实现与自身文档冲突**：该分支返回 `_失败("读取记录失败", "核心快照不存在: …")`，
而本包 `说明/设计说明.md` 明确写着：

> **没命中不是失败**：`查询核心快照` 未命中返回 `成功=True` + `是否命中=false` + `记录=null`，
> 与「读取失败」严格区分（这正是 A-1 要治的「内部故障与被测缺陷不可区分」）。

且 `读取记录失败` 在这里属**错误码误标**：说明写「不存在」、码写「读取失败」，调用方分不出「库坏了」还是「记录没有」。

## 决策

**把「快照不存在」由失败改为结构化成功，与同包兄弟能力统一口径。**

- `实现/提供者.py`：`记录 is None` 分支返回 `结果.成功结果({允许回滚: false, 说明: "核心快照不存在: <id>",
  快照状态兼容范围: "", 目标状态结构版本: <目标>, 回滚许可: false, 迁移方式: ""})`；
  `读取记录失败` **只留给真正的库读错误**（该函数上方 `_读快照记录` 返回的错误、以及同包另两处真失败）。
- 场景补第 4 个正向目标步骤（传不存在的快照id + 显式目标版本，断言结构化返回），只读、不写任何状态。
- 依据：快照不存在时，「目标版本能否回滚」的**真实回答本来是否定的**，属**判定结论**而非内部故障。

## 考虑过的其他做法

1. **在包内放 `验证夹具/权威状态.db` + 用 `$动态: 夹具文件复制` 拷进受管临时目录**（不改产品行为）——**否决**。
   `开发工具/HTML验证/动态值.py::_展开动态值` 里 `夹具文件复制` 的 `目标` 是**文件路径**、返回值也是该**文件**的绝对路径；
   而 `存储目录` 参数要的是**目录**。要靠"某个未用文本参数"承载复制动作，本包**没有语义相符的槽位**
   （对比：`支持库/适配层/Git提供者` 用的是语义相符的 `行` 参数，不是硬凑）。且引入二进制状态夹具后，
   权威状态库结构一变夹具就失配，是长期负债。
2. **登记为显式缺口 / 写 `豁免正向场景` 声明** —— **否决**。
   环境里那条豁免通道（`能力定义.json::外部依赖.豁免正向场景`）是给「依赖底座之外的上游服务且当前不可用」用的，
   本能力不属此列；且会让发布门禁**永久红**，与「门禁全绿才发布」冲突。
3. **场景内造状态（前置步骤调「创建快照」）** —— **否决（此路不通）**。
   662 个公开能力里没有任何创建快照的能力；本包 `复用决策.json` 也明确写着
   「创建快照/签名快照/健康检查（影子启动）属写类与执行类动作，**不在本轮能力面**」。
4. **保留现状（不改实现，另想办法过门禁）** —— **否决**。
   实现与本包设计说明**直接冲突**；且错误码误标让「内部故障」与「判定结论」不可区分，正是本包设计说明点名要治的问题。

## 后果

- 好处：同包三个只读判定能力（`查询核心快照` / `校验核心快照` / `校验状态兼容范围`）**口径三者一致**；
  调用方能区分「库坏了」与「记录没有」；不需要夹具、不引入二进制资产；场景步骤是干净的只读步骤。
- 代价与限制：**这是一次对外行为变更** —— 传不存在的快照id 由「HTTP 400 + `读取记录失败`」
  变为「HTTP 200 + `允许回滚=false` + 说明」。已核验影响面：
  ① 全仓**无消费者**依赖旧行为（除注册与文档外无调用方）；
  ② **无任何场景断言过该能力的失败**（它的场景步骤此前根本不存在）；
  ③ `本地网关.py:140`/`网关核心.py:379` 那条 `读取记录失败 → 400` 的映射与场景断言**不受影响**
  （那是 `平台控制面.平台状态.读取记录` 的**真读失败**，本能力仍保留该码用于真失败）。
  回退方式：把该分支还原为 `_失败("读取记录失败", …)` 并删掉场景第 4 步即可。
