## 问题

V3 网关的「适配层」（`后端服务/应用层/网关/适配器/`，**529 行**）在做一件事：
**把各家模型的原始响应归一化成统一结构**。

```text
原始响应（三选一）                      →  统一结构
└─ codex_responses（object=response）  →  {内容, 思考, 工具调用, 结束原因, 用量}
└─ chat_completions（choices[0]）      →  同上
└─ ollama（message.content）           →  同上
```

这属于「**模型细节怎么处理**」，按华哥口径应**下沉底座**，由底座统一承担，
而不是每个业务项目各写一套。

## 设计要求（第 1 步）

在底座 `大语言模型支持库.模型连接器` 新增**两个纯计算能力**（无状态、可热接入）：

### 能力 1：`归一化对话响应`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `原始数据` | 字典型 | 是 | 模型原始响应 JSON |
| `包含思考` | 逻辑型 | 否（默认 假） | 是否提取思考内容 |

**返回 `值`**：`{内容: 文本型, 思考: 文本型, 工具调用: 序列型, 结束原因: 文本型, 用量: 字典型}`

**自动判别三种格式**（与 V3 现实现一致）：
- `object == "response"` 或 `output` 是列表 → codex_responses 解析
- 存在 `message.content` → ollama 解析
- 存在 `choices` → chat_completions 解析

### 能力 2：`归一化流式分块`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `分块` | 字典型 | 是 | 流式单块 JSON |
| `包含思考` | 逻辑型 | 否（默认 假） | 是否提取思考 |

**返回 `值`**：`{类型: 文本型, 内容: 文本型, 工具调用: 序列型, 用量: 字典型}`

## 实施顺序（SOP）

1. 底座实现两能力 + `__init__.py` 注册 + 三处 JSON + 版本 + 完整性摘要
2. **热接入**（不重启 40007）
3. **真实 HTTP 验证**：用三种格式的真实响应各测一次 + 流式分块测试
4. V3 适配器改调底座（保持 `模型响应`/`流事件` 外壳，内部改调）
5. V3 侧回归对账（基线 = 现状）
6. 确认无回归后，删除 V3 各适配器文件（`适配器基类` 的纯归一化部分）

## 边界说明

**不放进底座的部分**（V3 业务，保留）：
- 模型名 → 适配器 的映射策略（`适配器注册表`）——属 V3 的模型路由业务
- 会话亲缘性、多账号轮询、认证恢复——V3 的账号池业务
- 视觉预处理、画像链、结构化输出——V3 业务编排

**理由**：底座的职责是「把模型响应变成统一结构」这个**机制**；
「用哪个模型、怎么轮询账号、拿结果做什么」是**策略**，属调用方。
