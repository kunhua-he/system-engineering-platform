## 三、#178 裁决：**接受该特例，并把它写进本条**（选报告的第①项）

判据（为什么这不是「第二条腿」，符合哲学 1.2 / 7.4）：

- **只有一条传输腿**：流式与非流式都从同一个 HTTP 入口进、同一个 `流式管理器` 出，
  差别只在「事件逐个写出 vs 聚合成 JSON」，不存在两条并行的执行路径；
- **没有第二套实现**：`流式生成对话` 与 `生成对话` 共用同一 Provider、同一校验、
  同一连接句柄体系（`实现/模型连接器.py` 内同源）；
- **有界与治理齐全**：事件数上限、持续秒上限、断开清理、审计留痕都在 `流式路由面.py` 内，
  并不因为绕过注册表面少任何一环。

**接受的代价（如实写明，不许包装成干净）**：这条进口**不经能力注册表**，
因此 `公开调用完整性门禁` 的六环一致性**看不见它** —— 它是一处**登记在案的豁免**。
豁免的到期条件：**当契约具备「可流式返回」的正式类型时，本特例立即改走注册表**
（届时把本条状态改为「已变更」，不得保留两条并存）。

## 五、#179 处置：**履行哲学 9.5 第②项的举证义务**（一行代码修，不加护栏）

`trust_remote_code=True` 本身**不是缺陷**，理由：底座面向本地私有部署，
9.5 明确「安全是**相对安全**，由用户自行拿捏；全通用标准是用户拥有绝对自主权」，
9.5③ 只把「防系统性破坏的底线护栏」列为必须项 —— 执行模型仓库内 Python 属于
**用户自选模型的可信度问题**，不是底座该替用户做的决策（9.1/9.2/9.3 同源：
底座不做隐私/安全限制）。**故不新增路径白名单**（那正是 9.5① 禁止的「牺牲通用性」）。

但 9.5② 要求「任何安全机制必须在宣言与说明书里如实写明『这是相对安全』，
**不许包装成绝对边界**」—— 原实现在 `:29,:31` 直接裸写 `trust_remote_code=True`，
**未提任何风险**，属**举证缺位**。处置 = 补一段模块级风险声明（写明：
该开关会执行模型仓库内任意 Python、前置保护是上游三层供应链守卫、底座不做路径白名单、
需要更严边界请自行只用可信模型目录），并把 `--host` 的
「仅回环、暴露到 0.0.0.0 即无鉴权」一并写明。
