# 0052_缺陷热点巡诊工具 + 门禁基线「收口重建」（不做新旧映射）

## 一、背景（华哥 2026-09-19 原话）

> 「低频的就拆不拆都无所谓了，除了大文件，小文件也是，高频的都统计一下，然后拆分一下。
> 看看是哪一些代码是经常 bug 的」
> 「没有现成工具；那就研发一个高效的工具。」
> 「怎么会有新旧之分，你现在这么处理一下就行。**这一批次收口了，你就应该把新旧的观念给删掉了，
> 把旧的要不删掉，要不处理好。只保留一套路径。新旧变成了两套了**」

## 二、决策 1：新增 `开发工具/缺陷热点巡诊.py`（正式工具，不是临时脚本）

**为什么做**：此前「哪块易错」只能凭印象，拆分优先级只能看行数。行数大但从不返工的
不该优先拆，改一次修三次的才该拆——但没有工具量化「返工」。

**口径**（全部来自真实 git 历史，不采样不估算）：

| 指标 | 定义 | 为什么这么定 |
|---|---|---|
| 修复类提交数 | 提交标题命中 修/bug/红项/纠/回退/坏/漏声明/漂移/不一致/失败/挂掉/崩塌/返工/补丁 | 保守取值，口径可被逐条复核 |
| 修复率 | 修复类提交 ÷ 该文件总提交 | 高修复率＝**天生易错**，而非只是改得多 |
| 热度 | 修复类提交 × 当前行数 | **返工频率 × 返工成本**，排序主判据 |
| 根因类 | 标题二次归纳（契约与类型/门禁与判据/文档漂移/生成物同步/并发与竞态/路径与编码/超时与性能/跨平台） | 看错都错在哪一类，指向系统性病灶 |

**关键实现选择**：一次 `git log --no-merges --name-only --format=%x01%s` 拿全历史，
而不是「每文件跑一次 git log」——后者在千次提交规模下慢两个数量级。

**产出**：stdout 报告 + `工程缓存/运行数据/缺陷巡诊/<时间戳>.json`（自动对比趋势）
+ `--html` 自包含网页。已接入「现成工具」清单（`任务类型规范.json` 通用纪律·工具姿势）。

## 三、决策 2：门禁基线在**每批收口时重建**，不做新旧路径映射 ★

**暴露路径**：`权威状态.py`（1613 行）拆成 6 个文件后，编译口的「重复腿与旁路」判红：
两个新文件里的 `sqlite3.connect` 被报「新增」。

**第一版修法（已否决并撤销）**：在 `门禁公共.判定` 里加「搬迁继承」——同一 `(规则, 详情)`
从旧文件搬到新文件时继承「存量」身份，并对无关新增/叠加新增/详情变更做反向验证（6 场景）。

**华哥裁决**：这个方向本身就是错的。

> 「怎么会有新旧之分……**只保留一套路径。新旧变成了两套了**」

**为什么否决（三条硬理由）**：
1. **在门禁里维护新旧映射 = 让门禁同时承载两套口径** —— 哲学 12.1「同一行代码只能一个
   结论」的反面；以后每批拆分都要维护映射，越积越厚，终成第二事实源。
2. **继承机制天然是「放宽判据」**，任何放宽都会成为未来真新增的洗白通道（实测：第一版
   一对一没问题，加「抽公共件」通道后反向验证场景②当场失败 → 判据被自己证明不可靠）。
3. **正确做法更简单**：基线的作用是「冻结债务、只减不增」；**拆分完成后按当前真实状态
   一次性重建**，旧键自然消失、新键自然登记，全程只有一套路径。

**最终做法**：
- 批次收口时执行 `python3.14 开发工具/验证门禁/运行验证门禁.py --写基线`
  （统一入口把 `--写基线` 透传给三个检查器，各自只写自己的基线段）；
- **重建的前提**：该批次拆分全部完成、且已用真实命令确认「新命中的都是搬家、没有真新增」；
- 门禁代码保持原版，**不新增任何继承/映射逻辑**。

**被否决的做法（记录备查，防后人重走）**：
- ❌ 门禁内「搬迁继承 / 路径重键 / 新旧映射」——华哥否决，已 `git checkout` 还原；
- ❌ 子代理自行改基线文件——越界且会让其他并行路的验收失真（本轮实战踩到，已 steer 制止）；
- ❌ 直接重建基线而不先核实「全是搬家」——会把真新增一起洗白，等于关掉门禁。

## 四之二、顺带修掉的两个**存量缺陷**（不是本次拆分引入，但被拆分暴露）

1. **`模型连接基元.py` 的 `_归一化响应体` NameError** —— `_HTTP调用模型` 的 LLM 非流式
   分支调用该函数，但它住在 `实现/响应归一化.py`，从未导入本命名空间。
   拆前 HEAD 第 368 行同一写法（同一缺陷），子代理原样保留并写了「保真说明」。
   **判定：必须修** —— LLM 调用是主路径，留着就是「非流式调用必崩」的隐雷。
   修法：文件末尾补一条收口导入（与原文件同位，避开环形导入）。
   实测：`测试_模型连接器HTTP` 2/2 OK、`测试_模型协议别名` 10/10 OK、导入无环。

2. **两条测试滞后于实现**（拆前就是 `failures=2`）：
   - `测试_模型连接器通用协议::test_连接器契约默认超时…` 断言「所有能力 `超时秒` 都是
     1800」，但 `探测模型端点` 是**有意的小超时 15 秒**（交互式探针要快速失败；
     往前 3 个历史版本一直是 15）→ 改成「探针 15 / 其余 1800」。
   - 同文件 `test_连接LLM本地启动调用传入规范协议参数` 漏断言 `上下文长度`
     （拆前 HEAD 第 460 行实现就已带该键）→ 补进断言。
   实测：14/14 OK。

3. **测试锚点随代码搬家失效**：`测试_硬件画像与档位` 从 `本地网关.py` 读 `min(...)`
   字面量，而该行已搬到 `有界服务器.py:64` → 修测试读取路径。
   实测：27/27 OK。
