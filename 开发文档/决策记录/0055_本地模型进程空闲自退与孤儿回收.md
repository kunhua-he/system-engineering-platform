# 0055 本地模型进程空闲自退与孤儿回收

## 一、病根（实测，不是推断）

`支持库/后端/大语言模型支持库/模型连接器` 的启动命令里**早就有** `--sleep-idle-seconds 300`，
但它**只卸载权重、不退出进程** —— `llama-server` 进程仍活着并继续攥着约 6.5GB wired 显存。
父进程（网关）被重启或被 `kill -9` 之后，这个进程**连看守都没了**，永久占着显存：

```
launchctl kickstart -k → 旧网关进程消失 → llama-server 变 PPID=1 孤儿 → wired 显存不退
```

**华哥口径**（2026-09-19）：「拉起来之后，如果 5 分钟没人用，那就自动释放。」

## 三、验收证据（全实测）

- **空闲自退**：60 秒短阈值实测 —— 到点后 `pid 存活 = False`，`/health` 与 `/slots` 不再可达。
- **孤儿自愈**：父进程消失后，看守自己走到点 → `回收后 PPID=1 的模型孤儿数 = 0`。
- **不误杀对照服务**：同机另有对照进程存活，回收动作只按账本+启动时刻+端口锁定本代模型进程，
  `对照服务仍存活 = True`；40007 生产网关**未受任何影响**。
- **反例（世代不符时拒动）**：把账本启动时刻改错后回收 →
  `{"已回收": false, "原因": "进程启动时刻 '…22:38:30' 与账本 'Sat Jan  1 00:00:00 2000' 不符（世代不符，PID 可能已被复用），按归属纪律不动手"}`
  —— **宁可漏收，不许误杀**。
- **真源一致性**：包声明 `句柄超时秒=300` == 代码真源读值 `300` == 兜底常量 `300`。
- `py_compile` 两文件通过；`import 支持库.后端.大语言模型支持库.模型连接器` 通过；
  `全量重算摘要` 闭合。

## 四、被否决的做法（避免后人重走）

- **不做世代账本 + 定期对账**：华哥已定「空闲超时回收」这一条口径，再叠一层账本对账是第二实现。
- **不许按端口盲杀**：`lsof -i :端口` 命中就杀会误杀同端口的合法常驻服务（如 embedding 服务）。
  必须走「归属 + 世代」三重证据。
- **不把 idle 阈值设成「就绪等待」同一个量纲**：原实现两者共用 `有效超时`，
  把空闲阈值下调到 5 分钟会连带把就绪等待从 900 秒压到 300 秒 —— 大模型冷启动可能不够。两者必须分开。
- **不在看守里改 `--sleep-idle-seconds` 去「顺带解决」**：那只卸权重不退进程，正是本次病根本身。
