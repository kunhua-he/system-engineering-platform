# 占位代称门禁判据加宽（判据太窄＝门禁形同没接）

> 最后更新：2026-09-18
> 口径：实测（条数与文件清单均现场重跑；取证命令随文给出）
> 维护者：决策记录
> 状态：**已完结（2026-09-18）**

## 一、起因（华哥当场指出）

> 「怎么又出甲乙丙丁了？排查一下」

先查明：**主会话在写新测试时又用天干字当占位文件名**（形如「天干字.md」）—— 这是直接责任。
但更深的问题是：**门禁没拦住**，说明门禁本身有缺陷。

## 二、排查：判据太窄 ＝ 门禁形同没接

### 2.1 现场实测（判据对账）

| 判据形态 | 能拦什么 | 实测计数 |
|---|---|---|
| **旧判据** 天干字 + 分类字（双字组合） | **只拦双字组合**（形如「天干+支」「天干+项」） | **6 条** |
| **真实存量**（裸占位名：天干字.md / 变量天干字 / 写包(天干字, / 点分 id 末段） | — | **102 条 / 13 个文件** |

**漏报率 94%**。这就是「被指出后仍复发」的机制：**门禁对裸占位名根本不报警**，
能否拦住完全取决于有没有人肉眼发现。

### 2.2 逐样本对照（判据边界）

```
样本形态                    旧判据   新判据（单式「独立词素」）
天干字+分类字（双字组合）      拦       漏     ← 新式反而漏掉旧的能拦的
天干字.md（裸占位名）          漏       拦
变量天干字                    漏       拦
写包(天干字,                  漏       拦
→ 普通词（构词前缀「补」）      漏       漏     ← 不应拦
→ 普通词（补丁的名词化）        拦(误报)  漏     ← 旧式误报
```

**★ 举例说明的写法纪律（2026-09-18 实测踩坑）**：本文档首版**在举例里直接写了天干字**，
结果**被自己的新判据报为违规**（20 条）。判据无法区分「当占位名用」与「举例说明」，
故纪律是：**文档里举例时不得写出真实代称字，须用描述性写法**（本段即按此改写）。
这与「引用哲学条款原文」的处理同源 —— 规范要求的是「不得用作分类名或编号」，
**举例不是使用**，但机器判据判不出来，所以由写法纪律兜住。

**结论**：两种形态都要覆盖 —— 但**必须是一条判据**（见第四节被否决做法）。

## 三、决定

### 3.1 判据加宽为**单条正则 + 交替分支**（一条判据、两种形态、一种语义）

```python
# （判据源码见 `开发工具/发布门禁/运行发布门禁.py`：一条正则、两个交替分支 ——
#   分支1 天干字独立词素；分支2 天干字+分类字。此处不抄源码，避免文档与实现两处并存。）
_占位代称判据 = re.compile(分支1 | 分支2)
```

**语义只有一种**：把天干前四位当**代称**用。交替分支是**同一条判据的覆盖范围**，
不是两条判据、不是「兼容旧形态」。

### 3.2 判据自指段豁免（新增机制）

判据的定义、注释、docstring 里必然出现代称字样。**不豁免的话，判据会把自己报成违规** ——
2026-09-18 实测：加宽判据后门禁自己报 **72 条**，头两条就是判据正则本身。

**做法**：用一对标记 `#: <<占位代称判据自指段 起>>` / `止` 夹住该段，扫描时整段跳过，
并**在结论里上报豁免行数**（跳过面必须可见，不得静默当通过 —— 与既有口径一致）。

### 3.3 普通词排除要作用于**两个分支**

`补丁项` 的正则命中起点是「丁」（第二分支），其前一字正是「补」。
首版排除逻辑只作用于第一分支 ⇒ `补丁项` 被误报。已修为对匹配起点统一判前一字。

### 3.4 清零真存量

12 个文件、66 处真存量 + 我新写的 44 处，**全部改为「一眼能懂的名字 + 阿拉伯数字」**：

| 文件 | 改法 |
|---|---|
| `开发工具/验证_能力id冻结基线反向验证.py`（18 处） | 夹具包名末段由天干字 → `夹具包1/2`；变量名 → `示例包1` |
| `测试中心/公共契约/测试_数据类.py`（17 处） | 变量名 → `中文版实例/标准版实例`；字段名 → `首个字段/次个字段`；类名 → `简写版/带参版` |
| `测试中心/开发工具/测试_能力id冻结基线门禁.py`（13 处） | 同首条（夹具包名与变量名） |

## 四、被否决的做法（防后人重走）

| 被否决 | 理由 |
|---|---|
| **保留旧判据当第二条腿（写成两个并列判据 / "兼容旧形态"）** | **华哥当场指正**：哲学 **1.2 不保留旧腿** ——「同一件事存在两套以上实现即视为缺陷」「不保留兼容入口/兼容壳」。**判据加宽时必须合并成一条**，不得并列两条 |
| **只加宽、不管自指** | 实测加宽后门禁自己报 72 条（判据正则 + 说明注释），把真存量淹没在噪声里 |
| **豁免自指但不报豁免行数** | 违反既有口径「跳过面必须可见」；静默豁免等于判据偷偷缩小扫描面 |
| **直接把 `补丁项` 也当违规** | 它是普通词（`补丁` 的名词化），拦它是误报；正确做法是显式排除构词前缀 |
| **把存量写进基线当「债务冻结」蒙过去** | 哲学 6.2 要求这类代称**清零**，且门禁配置态是「干净通过」（基线 0）；写基线＝把违规合法化 |
| **只在文档里再写一遍「别用天干代称」** | 哲学 13.1：判据在、门禁不调即纸面规则。**上次就是这么复发的** |
