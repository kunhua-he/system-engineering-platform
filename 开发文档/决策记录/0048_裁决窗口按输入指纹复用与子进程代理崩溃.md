## 一、裁决窗口复用：从「写了不读」到「按输入指纹复用」

### 现象

`全自动精校` 一直把每个裁决窗口的结果落到 `缓存/08_裁决/窗口_NNNN.json`，**却从不读回**。
长场次（80–98 分钟、10–29 个窗口）单轮裁决十几到几十分钟，且几乎必然有个别窗口碰上瞬时
超时或句柄回收 → 整场判失败（质检门禁正确拦下）→ 下次重跑**又从第 1 窗开始**，
可能再碰上新的瞬时失败 → **收不了口**。实测同一场次反复失败十余小时。

### 改法（按方案 2a 的口径：键取**输入指纹**）

新增 `精校裁决.窗口输入指纹()`，覆盖所有影响输出的入参：

```
底稿文本 / 疑难说明 / 证据文本 / 术语表 / 提示词（含输出结构与附加要求）/ 前置提示词
```

- **刻意不含** 区间id 与时间范围：它们是定位信息，内容相同即结论相同；
  而窗口切分随分段变化（实测同一场次从 10 窗变成 26 区间），拿时间范围做键会让复用
  全部落空、每轮重跑全部窗口 —— 这正是本轮先走的一段弯路。
- 指纹**两侧同参调用**（写入侧 `裁决窗口` 与复用侧 `取可复用` 都算同一个函数、同一组参数），
  否则永远命不中。特别注意：底稿取 **窗口的原始底稿**，不取两阶段流程里的「工作底稿」
  （那是前置精校的**产物**，复用判定侧拿不到）。
- `_读已有裁决` 按键为「输入指纹」建索引；旧产物无该字段 → 跳过（自然重算一次并写入指纹，
  即方案所说「首次跑无收益」）。
- 质检报告新增 `裁决窗口复用: {复用: N, 重跑: M}`，让复用情况可诊断。

### 真实验收（均在开发槽 48001）

| 用例 | 期望 | 实测 |
| --- | --- | --- |
| 同输入连跑两次 | 全部复用、产物内容逐字节相同 | **复用 10 / 重跑 0**；正文 sha256 一致（差异仅文件头「生成时间」元信息行） |
| 改动一个窗口的输入（清空其输入指纹） | 只重算该窗，其余复用 | **复用 9 / 重跑 1** |
| 整场耗时 | 复用时从分钟级降到秒级 | 复用完 **20 秒**完成（对比：全量重算跑 25 分钟仍超时） |
| 质检 | 通过 | `通过=true`、长度比 1.1264、数字保留率 0.9391、异常残句 0 |

## 二、fork 子进程 + macOS 系统代理探测 → 任务整体 SIGSEGV

### 现象

长任务改走网关「任务提交」后，任务**秒崩**，状态 `崩溃`、`错误说明: 工作进程异常退出（退出码 -11）`。

### 根因（崩溃报告栈顶实测定位）

```
_scproxy.cpython-314-darwin.so | get_proxy_settings
  ← SystemConfiguration / CFPreferences
libsystem_trace.dylib | _os_log_preferences_refresh      ← 崩点
异常: EXC_BAD_ACCESS / SIGSEGV
```

macOS 的 `urllib` 默认经 `_scproxy` 读系统代理设置，而该路径（`SCDynamicStoreCopyProxies`
→ `CFPreferences`）在 **fork 出来的子进程 + 多线程**下非线程安全，直接段错误。
任务系统在 POSIX 上用 `fork` 起子进程，模型连接器在其中走 HTTP → 必然触发。

### 改法

按底座**已有**的正确写法绕开系统代理（`ProxyHandler({})`）——`运行核心/能力调用/HTTP连接器.py`
与 `支持库/适配层/模型HTTP提供者.py` 早就这么写了，缺的只是这几处：

| 落点 | 原写法 | 现写法 |
| --- | --- | --- |
| `模型连接器._HTTP请求` | 裸 `urllib.request.urlopen` | `build_opener(ProxyHandler({})).open` |
| `模型连接器._等待本地健康` | 裸 `urlopen`（**且每 0.5 秒循环**，最易触发） | 同上 |
| `模型探针.请求` | 裸 `urlopen` | 同上 |

语义等价：本机模型端点（`127.0.0.1`）本就不该走代理。

## 三、顺带修正的两处（本轮自查发现）

1. **`连接LLM` 只改声明没改函数签名**：上一轮只往能力定义/参数契约/入口注册加了两参数，
   Python 函数签名没加 → `TypeError: 连接LLM() got an unexpected keyword argument`。
   **改契约必须同时改实现签名**，否则声明与实现不一致、调用直接失败。
2. **`报告` 变量误写成 `report`**：新加的诊断字段用了英文变量名 → 整场 `NameError`。
   全中文命名铁律不是形式问题，写错就是运行期报错。

## 被否决的做法

- **用「区间id + 时间范围」做复用键**（本轮先走的弯路）：窗口切分会变，
  时间范围对不上就让复用全部落空；而只对时间范围又有把「底稿已变」的旧结果错当新结果用的风险。
  内容指纹两种错都能挡住。
- **指纹取两阶段流程里的「工作底稿」**：那是前置精校的产物，复用判定侧拿不到，指纹永不相等。
  指纹必须取**输入**而非中间产物。
- **放宽质检门禁**（允许「裁决失败 N 个窗口」交付）：否决，未精校内容混入交付稿属静默降级。
- **给 urllib 设 `no_proxy` 环境变量代替 `ProxyHandler({})`**：否决，那是全局副作用，
  且不如在调用点显式声明意图可靠。
