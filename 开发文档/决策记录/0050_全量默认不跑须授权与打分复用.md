# 0050 全量默认不跑须授权，检查项按打分复用

## 背景

日常改动一度被全量验收（`发布门禁 --测试真跑` / `跨平台部署验证` / 全量 unittest）拖住：
一次把 CPU 打满、单项实测 527.6 秒，代码量再涨就「跑一趟就中招」。而绝大多数检查项
**历史上从不出错**，每次都真跑是纯浪费。

华哥 2026-09-19 两条裁决（原话）：

> 「大全套是大版本的时候才跑，等于说全量。默认无授权禁止跑全量，这个是强制需要弹出弹窗
> 才能跑的，默认不跑。直接走 F5 编译就完事了。静态能过，然后正向反向能过，基本上就没什么
> 大毛病。」

> 「这些本来底层就有。或者是加上一个缓存分。基本上从来不出错的，直接就复用缓存就好了。
> 就是一个打分机制。」

约束：不许为此新造第二套令牌/审批机制（哲学 1.3 结果唯一即收口、7.4 统一调用接口铁律）。

## 决策

**① 全量默认拒绝，须授权才跑。** 日常开发一律走静态编译（`开发工具.开发编译口.编译口
--变更`）；全量入口（发布门禁 `--测试真跑`、跨平台部署验证）加**入口闸门**——默认拒绝并
给出「改走静态编译」的中文说明。

**② 授权状态复用唯一现成腿。** 授权判定读 `系统核心支持库.权限审批` 的规则表「全量验收」，
默认 `询问`（＝不放行）；华哥授权后经 `权限审批.登记规则` 置 `允许`。**不新造令牌、不留
环境变量后门**；取不到授权腿时 fail-closed（判拒绝）。

**③ 检查项按「打分 + 复用」判定能否跳过。** 新增原子能力 `数据操作支持库.度量.判定可否复用`：
按历史成功率打分，三档判定（≥0.98 可复用 / 0.90~0.98 抽样执行 / <0.90 必须执行）。
两条硬边界：**样本不足**（默认 <3 条）与**指纹不一致**（输入/制品已变）一律真跑。

## 考虑过的其他做法

1. **只写文档纪律、不加入口闸门** —— 否决。哲学 11.1 已判定「已装未用等于没装」：
   靠人记得住不许跑，等于没拦。必须入口拦。
2. **新造一套全量授权令牌（环境变量 / 命令行 flag / 单独配置文件）** —— 否决。
   项目已有 `权限审批` 腿（允许/拒绝/询问 三态），再造一套＝第二条腿，违反 1.3/7.4。
3. **把全量端口默认关掉、需要时改代码打开** —— 否决。改代码开闸＝每次都要动源码，
   且留下「谁改的、什么时候开的」无从追溯；规则表登记可追溯、可收回。
4. **让每个门禁项自己决定要不要跑（各写各的跳过判断）** —— 否决。跳过判据会散落成
   多份「各自为政」的实现，正是重复腿的成因；收口成一个原子能力，谁要跳过都调它。

## 后果

- 好处：日常改动不再被全量拖住；从不出错的项直接复用，只对分数低/指纹变了的项真跑；
  全量何时跑、谁授权的，规则表里可查、可收回；跳过必须带「为什么可跳」的证据，不静默。
- 代价与限制：① 授权是**进程内规则表**，网关/进程重启即回默认 `询问`（＝再次要求授权）；
  ② 打分复用能力只做**判定**，真正的「跳过执行」要由各门禁项自己调用它并落实
  （本决策只提供判据，不替门禁项改行为）；③ 历史记录需要各门禁自行累积，样本不足时
  一律真跑（安全侧默认）。

```bash

export PATH=/Library/Developer/CommandLineTools/usr/bin:$PATH; export PYTHONPATH=$PWD; unset PYTHONPATH

from 支持库.后端.数据操作支持库.度量 import 判定可否复用

```
