# 0043 成熟度阶梯：L2 已强、L3 闭环优先、L4 后置

> 最后更新：2026-09-18
> 口径：设计决策 + 实测定位（依据审计报告 §9，本批只落决策）
> 维护者：小马仔

## 一、决策

用 L0–L5 阶梯定位本项目，并**明确阶段目标**：当前个人本机阶段**把 L3 闭环就非常稳，L4 不必现在做**。

## 二、定位（审计实测）

| 级别 | 本项目 | 依据 |
|---|---|---|
| L0 能跑 | ✅ | — |
| L1 能重复地跑 | ✅ 基本达成且强 | 环境自检 fail-closed、依赖锁、环境指纹、平台准入（边界：仅 macOS/arm64） |
| L2 能证明自己对 | ✅✅ **最大亮点** | HTML 黑盒、发布门禁、契约漂移门禁、完整性摘要、故障注入、反向验证纪律、不可变制品+激活指针+回滚 |
| L3 出事能自己收敛 | 🟡 **大部分强、但没闭环** | P0-1 跨重启资源身份缺失、P0-2 异常路径竞态、B4 无优雅停机、B5 幂等失忆、B6 睡眠唤醒未重校准 |
| L4 能被别人长期依赖 | 🔴 **基本空白** | 多租户鉴权/隔离/配额、可观测、就绪探针、备份恢复演练（见 0042） |
| L5 能规模化与交接 | ⚪ 当前不必追 | 留好「只换端口实现」的接缝即可 |

## 三、L3 闭环清单（本批正在做）

P0-1（世代账本 + 启动 reaper）、P0-2（删超时排空改单读者）、P1-3/P1-4（执行形态分流）、
P1-5（锁外回收）、P1-6（错误码取代文案判据）、B4（优雅停机）、B5（幂等持久化）、
B6（睡眠唤醒重校准）、B3（就绪门）。

## 四、L4 清单（后置，见 0042）

多租户数据面、可观测三件套（健康/就绪/指标，证据账本已是现成 trace 与计量源）、
备份恢复演练（RPO/RTO）、容量基线与基准（B2）。

## 五、新增的成熟度短板（B1–B9 摘要）

- **B1 上帝文件**：8 个核心文件 7306 行，拖累可演进与可交接 → 按职责拆分、对外门面不变（本批最后一波做）。
- **B2 无性能基准**：速度只能靠感觉争论 → 建基准工具，纳入发布前对比。
- **B3 只有活探针无就绪门** → 分 `/存活 /就绪 /健康`。
- **B4 缺优雅停机**（`daemon_threads=True`、无 SIGTERM 处理）→ 停机状态机与 P0-1 收尾链复用。
- **B5 幂等表纯内存** → 副作用类幂等键落 SQLite。
- **B6 睡眠/时钟跳变未重校准** → 经过时间统一 monotonic、落盘用墙钟、唤醒检测触发复查。
- **B7 有备份无恢复演练** → 一键演练并定期跑。
- **B8 端到端背压待核对** → 逐层断言「满 → 明确拒绝码 + 可重试 + 退避提示」。
- **B9 模型二进制的供应链** → 固定版本 + 哈希校验 + 来源白名单，纳入制品治理。

## 六、阶段目标

**个人本机**：L3 闭环（本批）+ B5/B6/B3 → 打磨 P1/P2。
**真要服务商化**：再投 L4，顺序按 0042。
**L5 不追**：只需保证状态都在端口/SQLite 之后、网关自身无状态，把接缝留对。
