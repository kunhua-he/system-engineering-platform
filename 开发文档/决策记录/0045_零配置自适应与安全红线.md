## 决策

让部署者「装上就跑」：**不配置也能安全跑在合理默认值上**，同时保留可选配置与清晰诊断。
做法＝补一层「**硬件画像 → 离散档位 → 默认参数**」的纯函数映射，
把「环境感知（指纹/探针）」与「事后保护（容量熔断）」连起来。

## 二、★ 铁边界：参数三分类（哪些能自动，哪些绝不）

| 类别 | 参数 | 策略 |
|---|---|---|
| **A 可全自动** | HTTP 工作线程、网关并发上限、超时执行器线程数、任务池活动数/排队深度、非模型提供者池、队列/缓存容量；**模型实例数/上下文长度/量化档位（按统一内存，价值最大）** | 硬件画像 → 档位默认 |
| **B 保守默认 + 可覆盖** | 内存高水位/容量熔断阈值（按可用内存比例 + 固定 headroom）、各类超时、限流窗口 | 画像给保守默认，允许 Profile/用户覆盖 |
| **C 绝不自适应** | **监听地址、鉴权开关/凭证/TLS、租户隔离与权限范围、允许路径表/沙箱边界、数据目录/激活指针、部署形态 Profile、是否启用对外服务** | 任何硬件档位**不得**自动放开 |

**★ 红线要做成反向测试**：喂入「检测到多网卡/大内存/类服务器画像」，断言系统**仍然**只监听回环、仍然要求鉴权
—— 硬件画像永远不能成为放开安全边界的理由。

## 三、六条机制（避免「自适应本身变成新不稳定源」）

1. **离散档位，不做连续黑盒调参**（PID/机器学习式实时调参会破坏可复现性）。
2. **探测与决策分离成纯函数**：探针只产出不可变画像；`按画像定档位(画像, 部署形态)` 无副作用，
   测试喂假画像断言输出即可（模拟的是输入数据，**绝不触达真实装配/写删路径**）。
3. **保守默认 + 预留余量**：个人 Mac 非独占，内存预算按可用内存保守比例 + 固定 headroom，
   目标函数是「不损害整机稳定前提下的合理高水位」，不榨干机器。
4. **运行时只做「向下」自动保护**，向上扩容谨慎（模型重载几十秒，宜惰性 + 滞回避免抖动）。
5. **三层覆盖、来源可见**：内置档位 ← 部署 Profile ← 用户配置；启动日志与诊断端点展示
   「画像 / 档位 / 每个最终值 / 由哪层决定」。
6. **探测轻量、只读、无重型副作用、结果缓存**：不得为「测性能」而加载模型/占显存。

## 四、价值最大的落点：模型实例数与内存预算

> 可开实例数 = floor((可用统一内存 × 安全比例 − 预留 headroom) / 单实例占用)
> 单实例占用 ≈ 量化权重大小 + KV/上下文缓存 + 运行余量

依据：MLX 类引擎**单进程一次只服务一个请求**，并发靠多 worker 进程 —— 与本项目
「常驻提供者进程池 + 任务系统」方向一致。

## 五、零新增第三方依赖的取法（守标准库铁律）

`os.cpu_count()`；macOS `sysctl hw.memsize`（经收口层）、Linux `/proc/meminfo`；
`platform.machine()` 判 arm64；`shutil.disk_usage()`；Metal 用 `system_profiler SPDisplaysDataType`
（较慢、**全程只调一次并缓存**），不确定按「无 Metal」保守降级（fail-closed）。
★ 口径：现有 `系统探针.读取系统内存` 用 psutil（第三方 try-import 降级），与「只准标准库」有张力 ——
psutil 若保留必须登记为「适配层可选依赖、缺失即降级」，不得成为事实必需。
