# 0059 读取文件体量门禁（精炼限长与偏移续取）

> 裁决：华哥 2026-09-22（原话：「查询或者是明确大返回的，就直接限定 2000 个字符上限，多了的，就偏移查询」）
> 背景：Codex 维修底座时 6.7 分钟烧 1904 万 tokens、触发 8 次压缩被中断；网关日志全程 200 OK（不是上游打爆的）

## 决策

`文件系统支持库.文件操作.读取文件` 默认带体量门禁（只增的可选参数）：

| 参数 | 默认 | 语义 |
|---|---|---|
| 最大字符 | 2000 | 默认路径下本次返回的字符上限（0 = 不限） |
| 精简 | 真 | 默认路径下做结构性精炼（折叠连续空行 / 去行尾空白 / 去首尾空行） |
| 允许大文件 | 假 | 真 = 跳过精炼与限长，放行全量 |

- 未显式分段：先结构性精炼，再按 最大字符 限长
- 超限：回前 2000 字符 + 一行续取提示（带续取的**原文起始行**）—— **不失败、不静默**
- 显式传 起始行/结束行：视为调用方自行控量，**不精炼、不限长**（偏移值查询无限）

## 理由（实测）

`开发文档/项目说明.md`（133KB）：改前 61,120 字符全量返回（一次灌 4.5 万 token）→ 改后 1,991 字符 + 续取提示，**降 96.7%**。

Codex 侧（rollout 2026-09-22 20:57 场次）：23 次读文件、同一文件读 9 遍、光读文件 49.5 万字节 ≈ 155K tokens；107 次模型请求 × 平均 178K tokens = 1904 万 tokens / 6.7 分钟。根因是「每次工具调用都重发完整上下文」× 「大文件全量返回」。

## 被否决的做法

| 做法 | 为什么否决 |
|---|---|
| 超限直接失败（错误码 内容超限） | 华哥 2026-09-22 改定为「回前 2000 + 偏移续取」：先看核心，要更多再取；失败会让调用方多付一次往返 |
| 大输出落盘 DB + 返回切片 | 《MCP与能力网关升级总方案》§六 已否决 L4：落盘引入新存储 + 清理策略，稳定性不达标 |
| 语义精炼（删「废话」） | 删错即丢信息且不可逆；底座只做结构性处理，语义判断不归底座 |
| 返回结构改成 {文本, 已截断, 总行数} | 值类型由文本变对象会破坏 187 处既有调用方（契约值结构冻结） |

## 一条必须留痕的实测事实

**结构性精炼对当前底座文档几乎无效**：项目说明.md / AGENTS.md / README.md / 当前流程图.md 精炼后仅省 0.0%–0.1%。
这些文档字符多**不是空白废话造成的，是内容本身啰嗦**。要真降字符只能改文档本身，或做语义摘要（底座不做）。
