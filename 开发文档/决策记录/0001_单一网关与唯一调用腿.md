# 0001 单一网关与唯一调用腿
<!-- 机器管理｜类型：决策记录｜生成器：开发工具.MD文档生成 -->


## 背景

平台早期为支持库、模块、核心分别留有调用入口，出现同一能力有多条执行腿、状态分叉、权限边界说不清的问题。华哥要求对外只留一条腿。

## 决策

- 对外只保留一个业务执行网关（40007）；所有能力不论对外暴露还是被模块、能力、项目调用，一律经同一个 `调用能力(能力id, 参数)` 接口。
- 进程内连接器与网络连接器只在装配层区分，调用方不感知来源。
- 禁止第二入口、旁路和直连内部实现；发现即删除或改回唯一链路。

## 考虑过的其他做法

- 按支持库各留一个网关：否决。会产生分叉状态，权限与版本无法统一裁决。
- 允许模块直连内部实现以省一次转发：否决。跳过了契约校验、指纹校验和权限边界。
- 保留旧入口做兼容：否决。兼容层会长期存在并成为事实上的第二条腿，直接废弃并用真实 404 验收。

## 后果

- 好处：权限、版本、指纹、错误语义只有一处需要维护和验证。
- 代价与限制：网关是单点，必须常驻并具备退出自动恢复能力；跨进程调用有一次转发开销。

## 验证方式

- `开发文档/项目说明.md` 的「唯一调用腿（当前冻结）」章节。
- 真实 HTTP 调用走 `127.0.0.1:40007`；旧入口应返回 404 而非降级成功。
