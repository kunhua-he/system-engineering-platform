## 决定一：PostgreSQL 只保留唯一一套同步池，不新增异步提供者

对外唯一能力面（5 个，句柄传参）：

```text
连接数据库(连接串, 连接池大小, 超时秒) → 数据库句柄
查询数据库(数据库句柄, SQL, 参数, 超时秒)
事务执行数据库(数据库句柄, SQL列表, 超时秒)
连接池状态(数据库句柄)
关闭数据库连接(数据库句柄)
```

判据（华哥 2026-09-14：「结果一致、底座唯一」）：

1. 底座运行核心是**同步多线程模型**（网关同步、任务系统 fork），底座内部再引入 asyncio 池会形成**两套并发模型** → 底座不干净；
2. 异步池只能是同步池的**包装**（同一实现的传输形态，不是第二套能力），包装应放调用侧（V3 是 async 世界，经唯一网关 HTTP 调用）；
3. 两种形态最终落到同一池、同一批连接、同一失效替换与句柄回收 → **行为一致**。

被否选项：新增异步提供者（形成第二套并发模型）；保留旧连接串能力作兼容入口（第二条腿，华哥明确否决）。

## 决定二：旧四条连接串能力直接删除，不留兼容

`连接 / 查询 / 事务执行 / 关闭` 的**实现、注册、契约、说明书段落、复用决策引用**全部删除，不保留兼容壳或旧名别名。理由：旧能力是新池的等价物，保留即「多条轮子并行」，后续必然分叉；调用方只有两条路 —— 走新链，或明确失败。

## 决定三：并发上限用「许可 = 借出权」语义

- 池的并发上限由**信号量**统一约束：`借出` 取许可、`归还` 释放许可、`关闭` 释放空闲连接的许可；连接新建数另受池大小约束。
- 反例（本轮真实踩过）：许可若按「连接存在」计数，空闲连接会长期占满许可，池会在连接池未满的情况下**卡死**（实测 288 次调用只成功 3 次并超时）。
- 由此产生的规则：借出连接数在任何时刻都必须 ≤ 最大连接数，且 `空闲 + 借出 == 已创建`；这两条已写成回归断言。

## 决定四：句柄类型不符一律 `参数不合法`

契约冻结字段类型，类型不符由**网关在该层直接拒绝**（实测 `超时秒` 传整数 5 → 400「必须是 双精度数型」）。因此能力内部也遵循同一口径：非整数句柄 → `参数不合法`；整数但不存在/已失效 → `句柄失效`。此前 `查询数据库` 与 `关闭数据库连接` 对同类输入给出不同错误码，属契约不一致，已统一。

## 决定五：anthropic 走第三协议，映射复用适配层唯一实现

- 协议枚举：`chat_completions` / `codex_responses` / `anthropic_messages`（短值 `anthropic`），两处镜像表由既有测试断言一致。
- 端点归一与载荷构造**只在适配层实现一次**（`归一模型端点` / `构造anthropic载荷`），连接器复用，不另写映射，避免两层分叉。
- 认证按协议规范走 `x-api-key` + `anthropic-version`；请求头前置校验 latin-1，非 ASCII 直接 400 而不是让异常逃逸。
- 工具名按协议规范前置校验（上游对中文工具名会返 502，属可避免的假失败）。
