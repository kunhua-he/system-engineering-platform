## 唯一调用腿（当前冻结）

```text
所有对内、对外、模块、项目、验证场景的业务能力执行
        → 调用能力(能力id, 参数)
        → 唯一能力调用服务
        → 唯一能力注册表/提供者路由
        → 受管执行单元
```

- **唯一业务执行入口**：`调用能力(能力id, 参数)`。
- **外部入口**：`POST /网关/调用`；MCP只负责把工具请求转到这个入口。
- **内部入口**：模块、项目适配层和验证器仍调用同一个唯一能力调用服务，不得直连注册表、Provider或实现目录。
- **HTTP连接器、进程内连接器、Provider生命周期管理**：只是运行核心的内部装配和资源治理，不是业务调用方可见的第二条腿；两者最终都必须回到唯一能力调用服务。
- **流式调用**：`/网关/流式`只是同一能力调用的流式传输外壳，不得复制一套能力注册、参数校验或执行语义。
- **平台控制面操作**：负责需求、权限、编译、发布和证据；其中“调用能力”操作必须转交唯一能力调用服务，不能另行执行。
- 能力搜索和契约查询只读，不属于能力执行入口。

本项目不保留同一能力的多套公开门面、测试专用执行器、浏览器自有执行语义或静默降级。发现调用路径不一致时，以本节和统一能力调用服务为准收口。

同一职责的内部实现也不得复制：相同能力必须合并为一个实现；不同能力若共享底层逻辑，应抽到唯一支持库；第三方能力只能经唯一Provider适配。当前代码中仍存在的历史包装或重复执行面，只能视为待收口债务，不得继续新增或作为新的正式入口。

# 编译与验证

```text
源码 / 契约 / 依赖
  → 统一编译器（目标依赖闭包指纹）
  → 命中缓存或生成新的不可变版本制品
  → 当前.json 选择稳定制品
  → HTML验证器启动制品并发起真实HTTP请求
  → 验证通过后才允许正式激活
```

编译器默认缓存目录为 `工程缓存/编译缓存/`，重复编译同一项目和目标且依赖内容未变化时直接命中；修改依赖后生成新的完整制品版本，旧版本保留用于回滚。可用 `--强制重新编译` 忽略缓存，使用 `--缓存根目录` 指定隔离缓存位置。

HTML验证器既可以接收显式制品目录，也可以接收编译器生成的稳定指针：

```bash
python3.14 -m 开发工具.HTML验证.验证器 --制品 <制品目录> --激活到 <制品部署目录>/当前.json
python3.14 -m 开发工具.HTML验证.验证器 --制品指针 <制品部署目录>/当前.json
```

第一条命令验证候选制品，只有验证成功才激活 `当前.json`；第二条命令只验证已经激活的稳定版本。HTML正式验证只启动 `运行入口/启动.py`，不直接读取开发源码；`--直连地址` 只用于开发诊断，不进入正式发布证据。


```bash
# 正式发布主判定：HTML 黑盒验证器（编译产物真实 HTTP，能访问能拿到数据 = 通过）
python3.14 -m 开发工具.HTML验证.验证器 --制品 <编译产物目录>
# 可选：显式覆盖场景级并发，范围 1 到 64；默认按 CPU 动态计算
python3.14 -m 开发工具.HTML验证.验证器 --制品 <编译产物目录> --并发 32
# 服务模式：浏览器可视化验证页 http://127.0.0.1:45081/
python3.14 -m 开发工具.HTML验证.验证器 --制品 <编译产物目录> --服务 45081
# 发布门禁（HTML 黑盒验证 + 制品检查 + 发布事务）
python3.14 开发工具/发布门禁/运行发布门禁.py
```

开发期回归只运行本次改动对应的独立模块，不产生正式发布证据：

```bash
python3.14 -m unittest 测试中心.第一批维修.测试_HTML验证器
```

HTML 黑盒验证器单实例默认使用**动态端口**（`--端口 0`，由操作系统分配，制品句柄回收即释放端口，无固定端口占用竞态；华哥裁决 2026-09-08）；显式 `--端口` 仅用于诊断，端口冲突明确报错不静默换端口。多实例模式使用端口池 `45080-45180`，一次部署 N 个制品进程、各自独立端口、连接器按实例路由，实例间零端口竞争；发布门禁也使用动态端口 `0`，不占用固定端口，句柄回收即释放。场景之间默认按 CPU 动态并发（范围 1 到 64，本机 32 核默认 32），`--并发` 可显式覆盖；场景内前置→目标→清理仍严格串行，非线程安全外部提供者按资源键独占。验证器只认编译产物的真实 HTTP 状态码 + 返回值（成功/值/错误码/错误说明/请求id/耗时），不读取源码内部。验收以 HTML 高并发批量验证为唯一全量（unittest 只做开发期定向小单元冒烟，禁止全量）。

### 2. 搜索和调用能力

```bash
python3.14 开发工具/能力搜索/能力搜索器.py --能力 读取文件
```

统一调用铁律（华哥裁决 2026-08-30）：**所有能力无论对外暴露，还是被模块、能力或项目调用，调用方都只允许使用同一个 `调用能力(能力id, 参数)` 公开接口。** 进程内连接器与 HTTP 连接器只在装配层区分，调用方不得感知来源；禁止另开第二入口、旁路或直连内部实现。能力搜索和契约查询是只读发现接口，不属于能力执行入口。

HTTP 能力入口：

```text
GET  /能力/搜索
GET  /能力/契约/{能力id}
POST /网关/调用
```

请求和返回字段以 `公共契约/HTTP路由契约.json`、包内 `能力契约/` 和统一结果为准。

浏览器宿主只提供静态页面；页面执行转发到配置的统一 `POST /网关/调用`，自身不提供业务执行 POST。受管 HTTP Provider 使用内部 `POST /内部/能力调用`，轻代码编辑器使用受标记保护的 `POST /内部/工程请求`，二者都不是业务能力入口。流式服务使用 `/网关/流式`，生产默认要求凭证并记录有限审计摘要。

公开能力、跨模块、跨进程和跨项目调用，正式验收以真实 HTTP 黑盒请求为主：请求没有返回、返回结构或字段类型漂移、错误码不符合预期、业务值不正确，均直接判为失败。只保留少量无法通过公开 HTTP 合理验证的纯逻辑和协议底层测试，不为每个公开能力复制一套进程内单测。

### 2.5 统一编译与 HTML 黑盒验证（华哥裁决 2026-08-29）

开发、验证与发布固定为两条主线：

```text
第一条主线：统一编译链
  修改模块/组件/能力
    → 全局唯一统一编译器（开发工具/项目编译/项目编译器.py，唯一编译器）
    → 检查这个模块/组件到底做了什么（能力登记/契约/依赖/边界）
    → 只编译这个小单元，生成可运行编译产物
    → 产物登记：提交、版本、契约指纹、依赖指纹、完整性摘要

第二条主线：HTML 黑盒功能验证
  HTML 验证页（开发工具/HTML验证/验证页.html）
    → GET/POST 直接请求编译产物（python3.14 -m 开发工具.HTML验证.验证器 并发请求）
    → 只看真实 HTTP 返回值：状态码、成功、值、错误码、错误说明、请求id、耗时
    → 功能正常/异常直接可见；异常按 编译/路由/参数/能力/Provider 定位修复
```

铁律（华哥拍板）：

1. **编译器绝对禁止跑全量**：编译器只编译小单元 + 检查合规，不代替功能验证，不调用测试中心。
2. **HTML 可以跑全量**：HTML 访问的都是已编译好的接口，多线程并发请求（1万线程都不怕，只要电脑性能扛得住）。
3. **后端怎么实现，HTML 不需要知道**：只认编译产物的真实 HTTP 返回，不读取源码内部。
4. **统一调用接口铁律**：所有能力无论对外暴露还是内部被调用，只允许走 `调用能力(能力id, 参数)`；HTTP、进程内、本地或远程差异只存在于装配层，模块不得新增专用调用方法、第二入口或旁路。
5. **测试中心总运行器已移除**：发布门禁只认 HTML 黑盒验证；保留的独立回归文件只用于开发期 TDD，无权写正式发布成功证据。
6. 每个支持库/模块的 `验证场景引用.json` 是验证场景的输入来源，验证器按场景驱动，不猜参数。

落点（唯一新组件）：

- `开发工具/HTML验证/验证器.py`：24行CLI唯一入口，只解析参数并调用验证应用；正式命令使用 `python3.14 -m 开发工具.HTML验证.验证器`。
- `开发工具/HTML验证/` 职责模块：常量、场景模型、验证报告、制品事实、场景加载、路径安全、端口池、制品进程、HTTP请求、返回判定、动态值、场景执行器、单实例验证、多实例制品池、验证证据、验证服务和验证应用；模块单向依赖，单文件均不超过160行。
- 每个正式包的 `验证场景引用.json`：可执行输入、预期业务值、副作用读回和负向场景的唯一来源；验证器按制品摘要生成隔离场景集合
- `开发工具/HTML验证/验证页.html`：浏览器可视化验证入口（每个能力绿/红一眼可见）
- 发布门禁：`开发工具/发布门禁/运行发布门禁.py` 的「测试全部通过」项改为调用 HTML 黑盒验证器

端口策略（华哥裁决 2026-08-29 固定端口、2026-09-08 动态端口）：

- **HTML 黑盒验证器单实例默认动态端口：`--端口 0`**（操作系统分配，启动器自报 `127.0.0.1:实际端口`，验证器解析真实端口；制品句柄回收即释放，无固定端口占用竞态，背靠背验证零冲突）
- 显式 `--端口 45080` 仅用于诊断；端口冲突时验证器明确报「端口占用」，不静默换随机端口
- 直连模式连已运行制品时，端口由制品启动时确定（启动器打印 `127.0.0.1:端口`），验证器按该地址直连
- `4780` 是宿主代理保留端口，任何应用不得监听（见 `公共契约/运行时/端口策略.py`）

MCP 是治理工具层，不是只读 HTML 审计的前置条件。MCP 不可用时，仍可直接对已编译制品执行真实 HTTP 黑盒验证；HTML 结果不能替代治理账本或正式发布证据。

## 选择支持库还是模块库

- 原子能力、单一第三方/系统边界、参数和错误转换：放支持库。
- 多个公开能力组合成业务流程：放模块库。
- 项目配置、权限、路径、版本和密钥引用：放项目适配层。
- 装配、调用、租约、超时、取消、释放和证据：由运行核心统一管理。
- 正式调用方只能经过统一 `调用能力(能力id, 参数)` 接口；包级公开入口只负责能力注册与装配，不作为调用方的第二执行入口。调用方不能导入 `实现/`、Provider 或第三方库。

### 支持库与第三方引用库的分层（华哥裁决 2026-08-27）

- **支持库 = 唯一的调用能力**：对外暴露统一中文能力接口，面向业务调用方；只做参数校验、编排和结果转换，不直接 import 第三方库。
- **第三方引用库（提供者） = 封装任何第三方**：只负责把第三方库/系统/外部协议汉化成稳定接口；不对外暴露，只受支持库门面调用。
- **唯一归属约束**：同一业务能力只允许一个正式公开owner；第三方引用库只能作为受管Provider存在，不得再次登记为公开owner或对外提供第二门面。
- **落地约束**：第三方引用库在 `支持库/适配层/` 下（受管Provider），或在 `支持库/后端/` 下以 `*提供者` 命名且不对外作为公开owner；支持库和模块只保存能力id与契约版本，经唯一能力调用服务执行。

## 当前不可用或不应使用

- `模块库/_模板`：仅模板，不是正式能力。
- `工程缓存/`：仅生成物、日志、摘要、受管制品和 Provider 环境；不作为源码导入路径。
- `开发文档/源码参考研究/`：只读研究资料，不是正式包、运行时或能力目录。
- 直接调用包内实现、复制第二套网关、把流式 `调用id` 当资源句柄：均不受支持。

## 资源与项目适配

- 资源句柄是不透明查询键，由网关登记、授权、关闭并记录回收结果；不传递第三方对象、线程、连接或模块内部对象。
- 文件、目录、进程、临时目录和句柄都必须先登记，终态统一释放；原子写入使用临时文件、同步和替换，冲突返回版本冲突，不覆盖他人结果。
- 项目适配层只负责项目声明、模块绑定、版本/权限/路径和密钥引用；配置按默认值、项目文件、环境变量、启动参数、请求覆盖的顺序合并，敏感值不得写日志。
- 受管 Provider 缺失、版本不符、超时、取消、输出超限或资源未释放时，能力返回明确不可用/失败结果，不把“声明存在”当作可用。
- 资源释放统一返回三态：`已结束并已释放`、`结束请求已发出但未收敛`、`未找到且已幂等`。未收敛时保留权威资源账本和重试入口，不失效句柄、不启动替代资源，也不伪装成功；只有确认进程/线程结束并完成管道、临时目录等核对后，才删除记录并失效句柄。

## 记忆与项目状态边界

- **记忆支持库独立于大语言模型**：记忆是连接SQLite记忆库的独立能力；模型连接器只作为向量生成的上游能力，不改变记忆支持库的owner归属。
- 当前正式记忆包：`支持库/后端/记忆支持库/`，能力以其`包声明.json`、`能力定义.json`、`能力契约/参数契约.json`和正式索引为准；当前登记写入、追加、完成、删除、搜索、最近、列出、生成标识8项能力，不把未登记的“计划记忆”当成当前能力。
- **状态机不等于状态库**：`公共契约/句柄体系.py`及运行核心负责句柄、租约、资源生命周期和回收；项目协作状态、验证证据、文件账本等是运行治理数据，不能因为都使用SQLite或状态字段就合并为同一个记忆/状态能力。
- 外部项目普通记忆读写已核实为底座客户端薄壳；项目自身状态 SQLite 属于各自治理事实源，不作为普通记忆第二实现。
- 记忆能力若调用模型生成向量，调用方仍必须经统一`调用能力(能力id, 参数)`；禁止记忆实现直接导入模型连接器形成第二条执行路径。能力声明中的副作用必须如实区分读操作和写操作。

## 传参类型：句柄与 id（权威类型，防越过）

> 2026-08-26 华哥裁决，唯一权威类型约定。所有能力一次传参必须遵循，防止直接传 id 绕过能力进程。

### 1. 句柄 = 万能参数（一次传参必须用）

- **句柄指向「模块/支持库的某一个能力的进程/实例」**，由连接器创建返回。
- 多个连接 = 多个句柄，各自精准命中对应进程（如同时连 10 个库 = 10 个句柄）。
- 调用形式：`能力(句柄, 资源参数…)` —— 句柄是第一参数，定位能力进程。
- 句柄由 `公共契约/句柄体系.py` 管理：生成值为 1～999999 的整数；字符串仅兼容固定六位数字格式。状态机负责创建/有效/失效、租约、超时自动释放和显式释放（幂等）。

### 1.5 句柄超时（华哥口径，权威）

- **沉默超时**：句柄 N 秒无人调用 → 状态机主动回收并终止进程（会话存储/连接型）；不是常驻。
- **持续使用重置**：一直有人调用，每次调用都重置超时倒计时（永不静默过期）。
- **模块主动申报**：每个会启动句柄的支持库/模块必须申报「句柄超时秒」（它自身需要多久），写在 `包声明.json` 的 `句柄超时秒` 字段。
  - 常驻型（会话存储/模型连接）：申报大值（默认 1800 秒 = 30 分钟）。
  - 短暂型（word 读取、重排、删除守卫、模板渲染等）：申报小值（如 60 秒），用完自动过期。
  - **不申报 → 默认 30 分钟（1800 秒）**。
- **手动释放**：用户随时可调 `释放句柄` 立即终止（幂等）。
- **超时语义**：沉默到期 = 状态机主动退出进程（不是进程暴毙；暴毙是另一回事）。

### 2. id = 数据库主键（只作二次传参）

- **id 是句柄内的资源定位**（如 会话id、输入id、表主键），在句柄已指向能力进程后使用。
- **一次传参禁止直接传 id 绕过句柄**：直接传 id 等于跳过能力进程的治理/租约/生命周期，直连内部，视为多条腿，禁止。
- 正确：`执行SQL(句柄, sql语句)`、`会话存储.追加消息(句柄, 会话id, …)`。
- 错误：不拿句柄，直接 `执行SQL(连接id, …)` 绕进数据库内部。

### 3. 判定规则

| 场景 | 一次传参 | 二次传参 |
|---|---|---|
| 首次接触某能力实例 | 必须：连接器返回句柄 | — |
| 已持句柄、定位具体资源 | 句柄（第一参数） | id（资源定位） |
| 直接传 id 不传句柄 | ❌ 禁止（绕过能力进程） | — |

### 4. 落地范围

- 新增连接器型能力（会话存储、模型连接器、数据库等）一律：连接器返回句柄 → 操作持句柄 + 资源 id。
- 能力契约中的资源句柄统一使用整数型；句柄由句柄体系登记、授权、租约、释放和失效，不能把第三方对象或内部连接直接作为参数传递。
- 违反判定的调用直接返回 `句柄失效` 或 `参数不合法`，不降级执行。
- **资源回收由状态机统一维护（华哥口径 2026-08-26）**：会启动句柄的模块/支持库，启动时调 `句柄体系.登记资源()` 把资源（PID/端口/连接/临时文件）绑定到句柄；句柄失效（超时/释放/进程暴毙）时，状态机自动 `核查回收()` 所有绑定资源——杀进程树（killpg）、清端口、删文件、关连接，不旁路拼独立回收能力。连接器本身不再各自实现回收逻辑。

## 开发运维避坑规则（2026-09-05 实测沉淀）

以下规则是多次摸索/踩坑后确认的，供 Agent 开发时直接遵循，不必重新探索：

### 1. 包声明铁律（全平台装配/发现的硬约束）

- 任何 `包声明.json` 的 `类型` 字段**只能写** `模块`/`基础模块`/`功能模块`/`支持库` 之一；
  写成 `Provider` 等会让发现器崩（`ValueError: 包类型不合法`）。适配层 `*提供者` 包的类型是 `支持库`。
- 任何 `包声明.json` 的 `依赖` 字段**必须是对象数组** `[{"能力":"...","版本":">=1.0.0"}]`；
  写成字符串数组 `["包id"]` 会让依赖解析崩（`AttributeError: 'str' object has no attribute 'get'`）。
- 新增能力必须带完整参数契约；半成品（只有 能力id/名称 无参数）会破坏能力注册。

### 2. Python 运行环境

- 平台正式命令统一 `python3.14`（homebrew，`/opt/homebrew/bin/python3.14`）。
- **跑平台命令前必须 `unset PYTHONPATH`**：Hermes 会话的 PYTHONPATH 会污染，
  导致 import 到 hermes venv 3.11 的包（pydantic_core/langsmith 等）报错。
- bash 不认中文变量名：`中文变量=值 命令` 会失败（"not a valid identifier"）；
  传中文环境变量用 `env '变量名=值' 命令`。
- `python3.14 -m py_compile` 检查语法；中文模块名测试必须用 `python3.14 -m unittest 测试中心.模块路径`，
  unittest discover 不认中文文件名。

### 3. 新增模块/支持库的标准流程

1. 先落盘开发文档（`开发文档/临时文档/NN_*.md`）说明落点与契约。
2. 参照现有同类包（如 `模块库/媒体转写`、`支持库/后端/转写支持库`）复制配套文件结构：
   `包声明.json`/`能力契约/参数契约.json`/`依赖契约/`/`权限契约/`/`配置契约/`/`能力数据/`/`说明/`/`验证场景引用.json`/`验证场景/`/`能力定义.json`/`实现/`/`__init__.py`。
3. 类型名用正式口径：`文本型`/`整型`/`双精度数型`/`字典型`/`列表型`/`逻辑型`（不是 `文本`/`整数`/`字典`）；
   返回统一 `结果型`。
4. `能力数据/能力搜索数据.json` 参数必须与契约一致（有对称门禁检查）。
5. 完整性摘要用官方工具生成：`开发工具/组件规范/组件规范.生成完整性摘要`，不手写。
6. 测试放 `测试中心/模块库/测试_XX.py`，用 unittest。若并发线有半成品包阻断全树装配，
   测试可改手动装配（只注册本模块依赖的包到能力注册表 + `注册能力调用器`），不依赖 `后端核心.启动()` 全树。

### 4. 模块组合支持库：调用器 vs HTTP连接器 两套模式

- **模块库 有两种调用底层的方式**，新增模块前先看同类：
  - 旧模式（媒体转写/媒体处理）：`设置HTTP连接器(HTTP连接器(...))` 注入，`_调用支持库` 走连接器。
  - 新模式（知识检索/直播逐字稿，官方模板生成器默认）：直接 `获取能力调用器().调用能力(能力id, 参数)`，
    运行核心装配时注入，无需手动设连接器。
- 能力注册表 + `注册能力调用器(唯一能力调用服务(注册表))` 是进程内测试/调用的标准装配。

### 5. 测试与验证节奏

- 小改只跑定向 unittest；同批改动跑受影响波次；阶段收口才全量；发布才跑门禁。
- 全树装配测试（`后端核心.启动()`）会扫 `支持库/` + `模块库/` 全部包声明，
  **任何并发线的半成品包都会让它失败**——这是环境问题不是你的代码问题，用手动装配规避并记录。
- 能力搜索器 `python3.14 开发工具/能力搜索/能力搜索器.py --能力 <词>` 可确认能力注册与契约。
- 正式索引验证：`开发工具/项目编译/正式包索引.py` 的 `构建索引`/`能力所有者表` 查 owner 唯一与冲突。

### 6. HTTP 网关调用（唯一入口）

- 唯一对外端口 **40007**，唯一执行入口 `POST /网关/调用`，body `{"操作":"调用能力","能力id":"...","参数":{...}}`。
- 凭证走请求头 `X-System-Credential: <值>` 或 `Authorization: Bearer <值>`；**凭证必须纯 ASCII**（中文经 HTTP 头损坏 → 401）。
- 网关严格类型校验：`超时秒` 等双精度参数必须传 `30.0` 不是 `30`；类型不符返回 `参数不合法`。
- 健康检查 `GET /健康` 也需凭证头。

### 7. 多 Agent 并发开发同一仓库

- 同一仓库多会话并行时：先 `git status` 看工作树有没有别的会话的未提交内容再动手，避免覆盖。
- 共享文件（LaunchAgent plist、`开发文档/项目说明.md`、`运行核心/启动运行核心网关.py`）改动前先备份。
- 发现对方半成品破坏全树（类型/依赖格式错、空实现包）时：改合规并加 ⚠️ 铁律备注，不替对方实现业务。
- 40007 端口/plist 冲突排查见「网关常驻与运维」章节。

## 网关常驻与运维（业务执行网关 40007）

40007 是唯一对外业务执行网关（`POST /网关/调用`），由 launchd 常驻管理（配置文件 `~/Library/LaunchAgents/com.huashi.gateway-40007.plist`）。

### 常驻配置（LaunchAgent）

```text
配置文件：~/Library/LaunchAgents/com.huashi.gateway-40007.plist
运行入口：运行核心/启动运行核心网关.py
WorkingDirectory：~/Documents/Agent/PHP/系统工程平台（必须是正式平台目录，勿指向 -live 副本）
凭证：    环境变量 系统库网关凭证（当前值 html-blackbox-verifier，必须纯 ASCII）
模型：    环境变量 MLXWhisper提供者_模型路径 / MLXWhisper提供者_模型名（已配 whisper-large-v3）
日志：    /tmp/网关40007.log（stdout）/ /tmp/网关40007.err（stderr）
```

> **⚠️ macOS 26.5 实测（2026-09-05）**：本机 launchd 的 KeepAlive 自动重启与 RunAtLoad 中途触发**均不可靠**
> （SIGKILL 网关后等 2 分钟不会自动拉起；`<true/>` 和 `{SuccessfulExit:false}` 两种写法都试过）。
> **可靠拉起命令是 `launchctl kickstart gui/$(id -u)/com.huashi.gateway-40007`**（100% 成功）。
> 因此网关崩溃后需要手动 kickstart，或加外部守护（每 30 秒探活 40007，挂了就 kickstart）。

### 启停与重启命令（macOS 26 实测有效）

```bash
# 重启（改代码/换凭证/异常后）——推荐：kickstart -k（先杀旧再拉起，约 15 秒完成）
launchctl kickstart -k gui/$(id -u)/com.huashi.gateway-40007

# 完全重新加载（plist 改动后）：bootout + bootstrap
launchctl bootout   gui/$(id -u)/com.huashi.gateway-40007
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.huashi.gateway-40007.plist
launchctl kickstart gui/$(id -u)/com.huashi.gateway-40007

# 查看状态（第二列 PID，0=正常退出码，非 0=上次异常）
launchctl list | grep huashi.gateway-40007
# 服务详情（runs/state/环境变量核对）
launchctl print gui/$(id -u)/com.huashi.gateway-40007

# 看日志
tail -50 /tmp/网关40007.log /tmp/网关40007.err
```

> **不要用 `launchctl load/unload`**（旧命令在 macOS 26 报 "Load failed: 5: Input/output error"）；
> 用 bootout/bootstrap/kickstart 三件套。

### 健康检查与手工临时启动

```bash
# 健康检查（需凭证）
curl -s http://127.0.0.1:40007/健康 -H 'X-System-Credential: html-blackbox-verifier'

# 临时前台启动（调试用，不经过 launchd）
cd ~/Documents/Agent/PHP/系统工程平台
unset PYTHONPATH   # 必须！否则 Hermes venv 3.11 包污染
env '系统库网关凭证=html-blackbox-verifier' python3.14 运行核心/启动运行核心网关.py
```

### 端口唯一性 ⚠️ 多会话冲突警告

40007 是唯一对外业务执行网关端口，**全机只能有一个实例监听**。多 Agent 会话并发开发时：
- 其他会话若把 plist 的 WorkingDirectory 改成自己的 `系统工程平台-live-*` 副本再起 40007，
  会让 launchd 网关装配的是副本能力集（缺正式目录新增能力），**排查时先查 `lsof -p <网关PID> | grep cwd` 确认工作目录**。
- 网关报 "端口占用或监听地址不可用" 而 `lsof -iTCP:40007` 为空时 = 有另一会话/进程刚释放端口或正在抢，
  用 `netstat -an | grep 40007` + `ps -eo pid,ppid,command | grep 启动运行核心网关` 全查。
- 改 plist 前先备份：`cp xxx.plist xxx.plist.bak_$(date +%Y%m%d_%H%M%S)`；改后必须 bootout+bootstrap+kickstart 才生效。
- 验证 launchd 实例装配了哪些能力：`curl /健康` 看能力数 + 直接 `POST /网关/调用` 试调目标能力，不要只看进程在跑。

## 能力唯一性与拼积木哲学（2026-09-09 华哥裁决，底座权威）

**总纲**：所有人（含 V3 等上层业务）不学架构、不看底层，只调 40007 网关拼积木。每个能力只保留**一个权威结果**，杜绝旁路。

### 三重铁律

1. **借鉴机制逻辑，不照搬项目结构**：参考全球顶级 Agent 源码（Hermes/Coze/Dify/OpenClaw/OpenHands/OpenCode/DeepSeek/TencentDB）时，只提炼工程化机制思想（消息幂等去重、SSE 占位消息、会话压缩血缘、记忆分层写入、防死循环阈值提醒等），不搬它们的目录/类/框架。
2. **能力唯一权威，杜绝旁路**：不管"权威唯一级能力"还是"原理不同但目的一致"的变相旁路，一律只保留一个结果。发现第二套实现（无论来源）即收口删除。
3. **原子能力精而不杂**：能参数化成一个能力的绝不分家；不搞几百几千个重复底子；每个原子能力必须定义清楚（输入/输出/存储格式/错误码），宁精勿滥。

### 唯一性判定四级框架

```
候选机制
  ├─ ① 同名同类型            → ✅ 合并增强（收口，不建第二套）
  ├─ ② 底子不同但格式一样     → 🔀 加「模式」变量：if 1=模式A / 2=模式B / 3=模式C…
  │     （输入/输出/存储格式一样、目的一样）   用户只选模式号，不感知内部差异
  ├─ ③ 底子有同类但缺原子点   → 🔧 增强现有支持库（补能力，不建新库）
  └─ ④ 真正确认真空缺        → 🆕 才允许立项新建（严格底座规范）
```

第②类落地：同一能力 id，参数加「模式」，实现内 `if 模式==1: 实现A elif 模式==2: 实现B`；输入/输出/存储格式完全一致，用户只传模式号——不新增能力 id、不暴露内部差异、不产生重复底子。示例：工具并发调度（`调度模式=1串行/2并行/3滚动池`）、循环软护栏（`护栏模式=1提示/2硬杀/3静默`）、快照（`快照模式=1复制/2git裸仓`）。

### 上层业务（V3 等）的边界

- 上层一律 `调用能力(能力id, 参数)`，不 import 实现、不复制逻辑、不维护第二套。
- 上层项目各自的哲学写各自权威文档，本哲学只约束底座能力治理；双方分开落盘、分开验收。

### 底座 0 加密 0 限制（2026-09-09 华哥裁决，底座权威）

**总纲**：底座本质是支持全部开发者的模块库，自身**不需要**隐私/安全/合规判断。底座能力**完全 0 加密、0 限制、0 业务假设**——只保证：可用、稳定、可靠、确定性。

1. **0 加密**：能力不内嵌任何加密、假名化、脱敏、掩码逻辑（不 HMAC 主体、不白名单字段、不截断内容）。传入什么记录什么，原文存储。
2. **0 限制**：能力不做业务侧限制（如\"只记元数据\"\"不记内容\"\"元数据≤64字符\"）。调用者传什么就用什么。
3. **隐私/安全是上层业务的事**：V3 等业务端涉及隐私、风险、合规时，由**业务端主动要求并自理**（在调用前脱敏、在结果后加安全层）。底座不做任何\"为了隐私而限制\"。
4. **确定性优先**：同样的输入 → 同样的输出；能力行为可预期，不因环境/调用方不同而改变。

> 例：审计账本能力只做\"记录事件+上限修剪\"，不判断该不该记、不加密主体；V3 若要求审计脱敏，在 V3 侧对传入字段先处理再调用。配置变更指纹只算改前/改后指纹并记录，不判断敏感值。
