2. 三、一次能力调用的真实全链路

sequenceDiagram
    autonumber
    participant 调用方
    participant LG as 本地网关<br/>(HTTP，工作线程预算 64)
    participant GW as 网关核心
    participant RL as 限流器<br/>(五维固定窗口)
    participant BC as 后端核心
    participant CN as 连接器<br/>(进程内 / HTTP)
    participant PV as 提供者<br/>(受管执行单元)

    调用方->>LG: POST /网关/调用（能力id + 参数 + 身份 + 凭证）
    LG->>GW: 处理(网关请求)
    Note over GW: ① 生成/沿用 请求id；回报「请求版本 / 当前版本 / 差异原因」<br/>版本不一致**兼容放行**，只有强制参数不满足才失败
    Note over GW: ② 操作白名单（允许操作表）→ 未知操作
    Note over GW: ③ 权限（操作权限表）→ 权限不足
    GW->>RL: ④ 进入请求（项目 / 用户 / 能力 / 任务 / 提供者）
    RL-->>GW: 不通过 → 限流
    Note over GW: ⑤ _执行：操作参数校验 → 按操作分发
    GW->>BC: ⑥ 调用能力（参数按该能力的参数声明逐个校验）
    BC->>CN: ⑦ 运行核心注入的唯一能力调用器
    CN->>PV: ⑧ 锁定提供者与受管执行单元
    PV-->>CN: 结果
    CN-->>GW: 统一结果（成功 / 值 / 错误码 / 错误说明）
    Note over GW: ⑨ 异常 → 公开错误码收口（KeyError→能力不存在、<br/>PermissionError→权限不足、ValueError→参数不合法…）
    GW->>RL: finally 离开请求（释放并发计数）
    GW-->>调用方: 统一信封（含 耗时毫秒）

4. 五、能力从哪来（四条路径）

flowchart TB
    NEED["一个需求"]
    Q["能力搜索：先确认**全局唯一**，没有同义能力"]
    NEED --> Q
    Q --> T1["支持库<br/>单一原子动作 / 绑定一个第三方"]
    Q --> T2["模块库<br/>要组合多个能力完成一段流程"]
    Q --> T3["技能库<br/>要落盘 / 续跑 / 人审的脚本编排"]
    Q --> T4["平台控制面<br/>平台自身治理（目录 / 策略 / 制品 / 发布 / 证据）"]

    T1 --> PKG["包九要素<br/>包声明 · 参数契约 · 能力定义 · 权限契约<br/>资源预算 · 能力数据 · 验证场景 · 说明 · __init__"]
    T2 --> PKG
    T3 --> PKG
    T4 --> PKG
    PKG --> COMP["统一编译器（只编本次变更的小单元）<br/>检查契约 · 依赖 · 边界 · 登记"]
    COMP --> REG["能力登记（公开能力全局唯一）"]
    REG --> HOT["热接入生效（不重启网关）"]
