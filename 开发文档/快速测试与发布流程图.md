# 系统工程平台：统一编译与 HTML 功能验证流程

> 两幅图只保留两条主线：
>
> **统一编译器负责“编译出来的东西对不对”；HTML GET/POST 负责“运行起来的功能对不对”。**

---

## 一、现状：源码测试、编译、门禁和功能验证混在一起

```text
┌──────────────────────────────────────────────────────────────┐
│                         开始开发                             │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 修改模块 / 组件 / 支持库 / 网关 / 页面                         │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
                    ┌──────────┴──────────┐
                    │ 先验证哪一层？靠人工 │
                    └──────────┬──────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 直接导入源码、实现目录、Provider 或测试夹具                    │
│ 部分测试走进程内调用，部分测试走 HTTP，入口不统一               │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 单独跑模块测试 / 支持库测试 / 核心测试                         │
│ 测试证明的是局部源码逻辑，不一定证明最终编译产物能运行           │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 编译制品                                                         │
│ 编译器检查、包复制、依赖闭包、运行入口和完整性检查分散在多处       │
│ 同一套规则可能被不同脚本重复执行                                 │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 再跑阶段收口                                                     │
│ 1125 个测试 / 多个测试文件 / 真实 Provider / 外部工具             │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 再跑发布门禁                                                     │
│ 发布门禁内部再次测试、编译、检查 HTTP、制品、依赖和资源            │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
                    ┌──────────┴──────────┐
                    │ 功能到底正常吗？     │
                    └──────────┬──────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 有时看源码测试结果，有时看内部返回，有时看门禁日志                 │
│ 没有固定规定“直接请求最终产物并看返回值”                          │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 问题出现时难定位：                                                │
│ 是源码问题？编译问题？依赖问题？运行入口问题？还是 HTTP 功能问题？   │
└──────────────────────────────────────────────────────────────┘

现状的根本问题：

    源码验证 ─┐
    编译验证 ─┼─ 多套入口、重复检查、职责混在一起
    阶段测试 ─┤
    发布门禁 ─┘

    最终用户真正使用的是“编译产物”，
    但功能判断没有统一通过 HTML GET/POST 直接请求产物。
```

## 二、更新后：全局唯一编译器 + HTML 直接请求编译产物

```text
┌──────────────────────────────────────────────────────────────┐
│                         开始开发                             │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
┌──────────────────────────────────────────────────────────────┐
│ 修改一个模块 / 一个组件 / 一组相关能力                         │
│ 本次改动形成一个明确的小编译单元                                 │
└──────────────────────────────┬───────────────────────────────┘
                               ▼
╔══════════════════════════════════════════════════════════════╗
║                 第一条主线：统一编译链                         ║
╠══════════════════════════════════════════════════════════════╣
║                                                              ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ 全局唯一统一编译器                                      │  ║
║  │ 所有模块、组件、能力和项目都遵循同一套编译规则             │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ 编译器读取：                                             │  ║
║  │ 模块/组件声明、能力契约、依赖、配置、权限、资源预算         │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ 编译器检查：                                             │  ║
║  │ 这个模块或组件到底做了什么？                               │  ║
║  │ 能力是否登记？参数/返回是否符合契约？依赖是否闭合？          │  ║
║  │ 是否越过模块边界？是否引用了不该引用的实现？                 │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║                    ┌────────┴────────┐                       ║
║                    │ 编译检查通过？   │                       ║
║                    └────────┬────────┘                       ║
║                       否     │     是                         ║
║                       ▼      │                                ║
║                 立即修复编译问题│                                ║
║                              ▼                                 ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ 只编译这个小单元                                          │  ║
║  │ 生成可运行编译产物：模块、组件、能力入口、配置和依赖          │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ 产物登记                                                   │  ║
║  │ 提交、版本、契约指纹、依赖指纹、完整性摘要、运行地址           │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║                  编译产物交给第二条主线                       ║
║                                                              ║
╚═════════════════════════════╪════════════════════════════════╝
                              ▼
╔══════════════════════════════════════════════════════════════╗
║                 第二条主线：HTML 功能验证链                    ║
╠══════════════════════════════════════════════════════════════╣
║                                                              ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ HTML 测试页 / 本地 HTML 测试器                            │  ║
║  │ 不导入源码，不调用内部实现，不猜内部状态                     │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ HTML 通过 GET / POST 直接请求编译产物                       │  ║
║  │ GET：页面、健康、查询、能力契约                             │  ║
║  │ POST：能力调用、参数提交、业务动作                           │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ 只看真实 HTTP 返回值                                      │  ║
║  │ HTTP 状态码、成功、值、错误码、错误说明、请求 id、耗时          │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║                    ┌────────┴────────┐                       ║
║                    │ 返回值符合预期？ │                       ║
║                    └────────┬────────┘                       ║
║                       否     │     是                         ║
║                       ▼      │                                ║
║            直接看到失败并定位问题│                                ║
║            编译 / 路由 / 参数 / 能力 / Provider                  ║
║                              ▼                                 ║
║  ┌────────────────────────────────────────────────────────┐  ║
║  │ 功能通过                                                   │  ║
║  │ 记录 HTTP 请求证据：请求、返回、状态、耗时、资源释放             │  ║
║  └──────────────────────────┬─────────────────────────────┘  ║
║                             ▼                                ║
║                    当前小单元验证完成                         ║
║                                                              ║
╚═════════════════════════════╪════════════════════════════════╝
                              ▼
                    ┌─────────┴─────────┐
                    │ 是否继续开发？    │
                    └─────────┬─────────┘
                       是      │      否
                       └───────┘      ▼
                              ┌──────────────────────────────┐
                              │ 最终交付                                      │
                              │ 复核当前编译产物 + HTML 功能证据 + 发布信息     │
                              └──────────────────────────────┘
```

更新后的职责边界：

```text
统一编译器：检查“这个模块/组件编译出来是否合规”
HTML GET/POST：检查“编译出来的真实功能是否正常”

编译器不负责替代功能测试
HTML 测试不负责读取源码内部
发布门禁不再重复执行已经完成的每一个局部动作
```

更新后的最小工作单元：

```text
改一个小模块或组件
    ↓
统一编译器编译这个小单元
    ↓
生成编译产物并启动
    ↓
HTML GET/POST 直接请求编译产物
    ↓
看返回值判断功能
    ↓
通过：继续下一个小单元
失败：直接定位并修复
```

最终原则：

```text
全局只有一个编译器
全局只有一套编译规则
功能只认编译产物的真实 HTTP 返回
```
