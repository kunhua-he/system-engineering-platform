## 二、分级验证纪律（禁止每个小改动重复跑全量）

1. **步骤 0**：`python3.14 -m 开发工具.环境自检` —— 先确认本机能不能跑，有不支持项就别往下走。
2. **定位影响范围**：读目标包的 `说明/设计说明.md` 与能力契约；找能力面用薄壳 `capability_search`。
3. **冻结工作包**：同一目标的改动放一个包；动手前登记临时开发文档，写明**允许修改目录**与回退方式。
4. **按级跑，不越级**：
   - **小改动** → 只跑受影响的编译器检查与契约检查 + 该包定向冒烟；
   - **一批同类** → 跑受影响波次；
   - **全部工作包完成** → 才跑一次 HTML 高并发全量；
   - **正式发布前** → 编译制品 + `运行发布门禁`。
5. **验收必须走真实 HTTP**。**禁止**用缓存命中、单测全绿、文本匹配或子代理自述冒充真实通过。
6. **收工**：`git add` **只加自己改的文件**（**禁止 `git add -A`**）；提交信息写清「改了什么 / 为什么 / 怎么验的」；
   改了包必须跑 `全量重算摘要`，全仓判据为「不闭合 0/N」。

## 三、资源释放（统一遵循）

```text
请求结束 → 有界等待 → 必要时强杀 → 确认进程/线程已结束 → 关闭管道和临时资源 → 删除权威记录
```

- **未收敛必须保留账本**；禁止伪装成功、先删记录、或先启动替代进程。
- 资源回收**按状态机登记的归属**处理（资源指纹 / 归属），**禁止按端口号盲杀**。

## 四、任务记忆包（派活强制注入，2026-09-18 华哥裁决）

> 华哥原话：「底座不是开发了个临时记忆吗？为啥不强制注入一下？这个应该是作为开发的时候，
> 可以注入一下这个进去的才对吧？例如说你执行的任务的**开工 ID** 的那种。**不做什么限制，
> 只是单纯的可以统一一个任务的记忆**。」

**判据**：每个派给子代理的任务信**必须**含 `开工ID` 与「已核实事实包」；**缺任一项即任务信不合规，不得派出**。

**做法**（不新增能力，用既有件——`工程缓存/` 本就可删可重生，属临时运行态）：

1. 主会话派活前，把该任务要用的**已核实事实**写成一份记忆包，落到
   `工程缓存/任务记忆/<开工ID>.md`。内容固定五段：
   ① 开工ID + 目标一句话；② **允许修改目录**（文件级独占）；③ **已核实事实包**（路径/行号/契约字段名/样板文件/已跑过的取证结论）；
   ④ **可直接复制执行的验收命令与期望**；⑤ 边界与禁做（不 `git add`/`git commit`、不跑全量重算摘要等）。
2. 任务信里写清三件：`开工ID`、记忆包的**绝对路径**、以及「开工第一步读它」。
3. 子代理读完再动手；**发现记忆包与现场不符时如实回报**，不许默默按记忆包硬做。

**为什么强制**：实测教训（2026-09-18）——同一批任务里，子代理把**绝大部分时间花在重新探索**上
（grep 全仓、翻目录、采样统计分布），而这些事实主会话**都已经查过**，却只写了一句
「你要自己再现场确认一次」。一个 30 分钟任务里前 25 分钟在重走主会话走过的路，最后撞超时熔断。
**记忆包把「探索」从每个子代理手里收回到主会话一次**。

**与 12.3③ 的关系**：子代理仍必须现场复核（不许盲信记忆包），但复核是**快速验证**（对照一两条命令），
不是从零探索。两者不冲突：记忆包给**假设**，子代理当场**验证**假设。

**不做限制**：记忆包就是一份普通 md，不设权限、不加密、不建表、不引入新状态机——
目的只是「**统一一个任务的记忆**」，让同一任务的主会话与子代理看到同一份事实。

### 任务信的两条写法禁令（2026-09-18 实测，本轮 7 个超时任务的共同根因）

**禁令一：不要在任务信里引用哲学条款号**（如「按 9.5 / 14.1 / 1.3 口径修」）。
实测：一条 SSRF 修复任务，子代理把任务信里的 `9.5 / 14.1 / 1.3 / 2.x` 逐个去查原文，
**6 次探索、0 次动手**，1800s 全耗在「找哲学文档 → 读条款 → 再查目录约定 → 再查跨包门禁」上。
正确做法：**把条款的结论直接写成一句话操作指令**（如「校验后固定该 IP 并绑到连接，保留 Host/SNI」），
不写条款号、不让子代理去读哲学。

**禁令二：任务信里出现「你要自己再现场确认一次 / 先探明 / 先去定位」的，一律改成给答案。**
这些措辞等于把主会话该做的探索转包给子代理。实测：同一批里凡带这类措辞的任务，
前 25-30 分钟都在重走主会话走过的路。**判据：任务信里每一句「去查/去探/去确认」，
主会话都要先自问「这个答案我是不是已经有了」——有就直接写进事实包。**

**唯一例外**：确需子代理现场判断的**业务/设计取舍**（如「两个 schema 哪个更完整」），
那要写成**两个选项 + 主会话的倾向 + 判断依据**，而不是「你自己看着办」。
