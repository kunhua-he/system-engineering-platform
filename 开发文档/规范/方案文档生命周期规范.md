## 〇、这份规范管什么

**方案文档（`开发文档/方案/` 下的 `*.md`）从「立项」到「归档/删除」的全生命周期**，以及
**多份方案同时存在时谁说了算**。

**为什么要这份规范（华哥 2026-09-18 指示原话）**：

> 「互踩的就提前收敛一下。设计哲学是有声明周期或者是完善周期的；文档不能互相踩。
> 因为文档互相踩的情况下，会十分麻烦。」

**现状事实证明这不是假想问题**：2026-09-18 实测 `开发文档/方案/` 有 **27 份** md，其中
**4 份都写了「批次编排」且各自自称权威**（`底座升级方案.md` 标题写「唯一权威」、
`底座大版本升级方案_20260918.md` 写「唯一主线」、`底座扩容总纲` 有「五、批次与依赖」+
「六、待华哥拍板」、`三条裁决总执行方案_20260918.md` 写「编排入口」）。
后果：**新会话不知道该以哪份为准**，批次编号出现两套（`批0–批5` 与 `第0批–第4批`）。

## 一、铁律：方案文档不产生第二事实源

**方案文档是「过程件」，不是「事实源」。**

| 层级 | 谁是事实源 | 方案文档的定位 |
|---|---|---|
| 当前是什么（架构/能力/口径/数字） | `开发文档/项目说明.md` | 只可**引用**，不得复述并另立数字 |
| 还欠什么（待修/待决） | `开发文档/未完成事项.md` | 只可**引用**，不得另立债务清单 |
| 为什么这么定（取舍） | `开发文档/决策记录/` | 只可**引用**，不得替代决策记录 |
| 怎么走（顺序/批次/编排） | **唯一一份**：见第三节「编排唯一入口」 | 其余方案**不得**再写批次编排 |

**判据**：一份方案文档里若出现「批次 + 依赖 + 顺序」表格，而它不是当前编排入口 → **违规**。

## 二、生命周期（五态，与门禁五态同形制）

| 态 | 含义 | 文档头部标记 | 允许的动作 |
|---|---|---|---|
| **起草** | 正在写，结论未定 | `> 状态：起草` | 任意改 |
| **生效** | 已批准，待执行或执行中 | `> 状态：生效（<日期>）` | 按方案执行；**改动须留痕** |
| **已完结** | 全部落地并验收 | `> 状态：已完结（<日期>，提交 <短hash>）` | **只读**；结论已并入权威文档 → 按第六节处置 |
| **已取代** | 被新方案或新裁决替代 | `> 状态：已取代 → 见 <新方案文件名>` | **只读**；不得据其派活 |
| **已废弃** | 判定不做 | `> 状态：已废弃（<日期>，理由一句话）` | **只读**；理由保留（防重复提议） |

**强制要求**：**每份方案文档头部必须声明状态**（与元信息头并列一行）。
没有状态声明的方案文档，**不得作为派活依据**（判据：`grep '^> 状态：'`）。

## 三、编排唯一入口（同一时刻只允许一份）

**全仓任何时刻，只允许一份「编排入口」文档**，它回答：「现在按什么顺序做什么、下一批是什么」。

- **当前编排入口**：`开发文档/方案/执行编排_唯一入口_20260918.md`
  （它在正文第一节即声明自己是编排入口，并列出子方案索引）。
- **换入口的规矩**：新编排入口生效时，**旧入口必须同批改为 `> 状态：已取代 → 见 <新文件名>`**，
  且**不得再把批次表留在正文**（改为一行指引）。
- **子方案不得自建编排**：子方案只写「本件事怎么落」，不写「全仓批次顺序」。
  需要顺序时**引用**编排入口，不复制。

## 四、互踩的四种形态与判据（照此自查）

| 形态 | 判据（可机器扫） | 处置 |
|---|---|---|
| **编排冲突** | 多份文档含「批次 + 依赖 + 顺序」表 | 只留编排入口，其余删表改为指引 |
| **自称唯一** | 正文出现「唯一权威 / 唯一主线 / 编排入口 / 唯一入口」的文档 > 1 份 | 保留真正的唯一者，其余改措辞并指向它 |
| **主题重叠** | 两份文档写同一件事的落地方案（如都写「配置加载器怎么改」） | 合并到主题归属者，另一份改为引用 |
| **同数不同值** | 两份文档对同一量给出不同数字且都没标取证时间 | 一律改为「引用 `项目说明.md` 的数据行」，不各自写数 |
| **★ 隐形债**（2026-09-18 现场实测新增） | **子方案里写了「待办/待修/施工项」，但 `未完成事项.md` 没有对应登记** | **当场把活登记进债务清单**，子方案只留「怎么做」 |

### 4.5 子方案不得作为待办的唯一落点（强制）

**现场教训（2026-09-18 实测）**：把 `底座升级方案.md` 标为「已取代」时，逐条核实其未闭合项，
发现 **4 条活**（包扫描事实源分叉 / 资源上限 / 身份边界 / 聚合注册异常）**都没在 `未完成事项.md` 登记**；
再查 `结构债处置方案_20260916.md`，其 `R1–R8` 里 **R5 的两条也没登记**（实测 `支持库/核心/` 空壳仍在、
`底座升级方案.md` 6 处死路径仍在）。**若不是这次收敛，这些活会随子方案一起被当成"历史"埋掉。**（该三份已于 2026-09-20 蒸馏后删除；此处作教训留存。）

**判据（此后一律照做）**：

1. **子方案只写「本件事怎么落」**（落点 / 步骤 / 验收判据）；**待办状态以 `未完成事项.md` 为唯一权威**；
2. **方案立项的同批**，必须在 `未完成事项.md` 登记条目（哪怕只占一行 + 指向子方案）；
3. **方案标「已完结」前**，确认其全部施工项在债务清单已销项或已转登；
4. **收敛/取代任何方案时**，逐条核实其未闭合项 → 抢救登记 → 才能标取代（本次已按此抢救 5 条活）。

**自查命令**：

```bash
# 子方案里写了施工项但清单无登记的（人工确认「施工项」判读）
for f in 开发文档/方案/*.md; do
  n=$(grep -c '待修\|待办\|未落地\|本项目\*\*待\|施工项' "$f" 2>/dev/null)
  [ "$n" -gt 0 ] && echo "$(basename $f): $n 处待办字样"
done
grep -c '^| ' 开发文档/未完成事项.md   # 债务清单条目数，与上面对照
```

```bash
# ① 自称唯一的文档：只看 H1 标题行（★ 只匹配标题，不匹配正文引用 —— 正文引用是合规的）
#    期望：只有 1 份（编排入口）

for f in 开发文档/方案/*.md; do
  grep -qE '^> 状态：\*\*(起草|生效|已完结|已取代|已废弃)' "$f" || echo "状态非法/缺失: $f"

```

**★ 判据必须只扫 H1 标题**（2026-09-18 反验实测的教训）：首版判据写 `grep -l '唯一入口' 开发文档/方案/*.md`，
结果**把每份文档状态行里「批次顺序见 `执行编排_唯一入口_…`」的合规引用也匹配成"自称"**，
一次报出 **22 份假阳性** ⇒ 判据本身失效（哲学 12.5：判据自己也要有「不应被触发」的样本）。

**合法 vs 违规（必须区分，否则会误删合法内容）**：

| 情况 | 判定 | 例 |
|---|---|---|
| **H1 标题自称「唯一」** | **违规** | `# 系统工程平台 · 底座升级执行计划（唯一权威）` |
| 状态行/正文**引用**「见 `执行编排_唯一入口_…`」 | **合规** | 22 份子方案状态行 |
| 子方案内**本件事**的分片/分批（如「裸布尔迁移 10 批」） | **合规** | `裸布尔迁移分批方案_20260917.md` |
| 子方案写**全仓**批次顺序表 | **违规** | 被取代的三份 |

∴ **子方案可以有「本件事的批次」，不能有「全仓的批次」。**

## 六、收口动作（方案完结时）

方案到「已完结」态时，**同批**做三件事（缺一不可）：

1. **结论并入权威文档**：当前事实 → `项目说明.md`；待办 → `未完成事项.md`；取舍 → `决策记录/`；
2. **本文件按体例处置**：
   - 仍被引用（如子方案被新编排入口索引）→ 保留，标 `已完结`；
   - **不再被引用且结论已并入** → 移入 `开发文档/归档/<年月>_<主题>/`（照体例规范第八节）；
   - **纯过程记录、无留档价值** → 删除（哲学 1.6 同源：不留第二份并列件）。
3. **清引用**：`grep -rn '<文件名>' 开发文档/ AGENTS.md README.md` —— 有引用则改指向或删除，
   **不留悬空引用**（AGENTS.md 硬规则「规范不得指向已删除的东西」）。
