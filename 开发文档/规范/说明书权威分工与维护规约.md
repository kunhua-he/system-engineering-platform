## 一、这份规约管什么

**管**：包级 `说明/使用说明.md` 的三个问题——① 哪一份能重新生成、从哪个入口生成；② 哪一份禁止生成器覆盖；③ 说明书、契约、实现三方打架时听谁的。

**不管**：说明书写什么内容（那是各包自己的事）、包级三件套的必备条件（那是 `Markdown 文档体例规范.md` 第四节）。

**用途**：后续 Agent 读完本文件，即可对**任意一本说明书**判定「该不该手改 / 能不能重生成 / 三方不一致听谁的」，不需要再翻历史争论。

> 术语说明：**生成物类／人工类**是本项目的血统分类名（出处 `新建支持库与模块指南.md` 9.1），**取代早前用无意义占位代称的写法**——分类名必须一眼能懂，禁用天干代称（哲学 6.2）。本文沿用。

### 1.1 命令环境（铁律）

本文件所有取证与验收命令**一律用 `python3.14`**，跑前 `unset PYTHONPATH`：

```bash
unset PYTHONPATH && python3.14 -V     # 本机实测：Python 3.14.4
```

项目全线使用 3.14；`python3` 在本机**另有版本**（实测 `python3 -V` → `Python 3.11.15`，非 3.14），**行为不同**，用错解释器会得到不可复现的结论。另：macOS **无 `timeout` / `gtimeout`**，需要限时请用 `python3.14` 脚本内的超时参数。

## 三、生成物类：唯一生成入口与落点

### 3.1 唯一生成入口

| 角色 | 路径 |
|---|---|
| **入口文件** | `开发工具/说明书生成/说明书生成器.py` |
| **一键脚本** | `开发工具/说明书生成/运行生成.py` |
| 契约解析（同源） | `开发工具/契约编译/聚合契约解析.py` |
| 包发现 | `运行核心/加载器/包发现/发现器.py` |

**同名不同物（D-13 消歧）**：`支持库/后端/组件规范支持库/实现/说明书生成器.py` 与上者**不是重复实现**，两侧输入源、产出形态、调用方全不同，**不得互相转调、不得互相删除**：

| 维度 | 生成物类入口（`开发工具/说明书生成/`） | 组件规范侧（`组件规范支持库/实现/`） |
|---|---|---|
| 输入 | `包声明.json` + 唯一聚合契约 | `能力定义.json` + `能力契约/参数契约.json` + `能力数据/能力搜索数据.json` + `验证场景引用.json` |
| 首行形态 | `# 名称（包id）` | `# 名称 使用说明` |
| 章节画法 | `## 能力` + `### 能力名（\`能力id\`）` | `## 能力清单`（表格）+ `## 能力id（中文名称）` |
| 能力面 | 一键脚本 + 测试中心断言 | 经 `组件规范支持库.生成说明书` 能力对外注册 |
| **覆盖策略** | **直接 `write_text`，无拒绝覆盖** | `校验输出目标` **拒绝覆盖已有文件** |

**覆盖策略的差异决定了本文最重的一条禁令**：生成物类入口会静默覆盖，组件规范侧会拒覆盖。

### 3.2 唯一落点（铁律）

1. 一键脚本 `运行生成.py` 的**硬编码输出目录是 `工程缓存/说明书/`**，**不是包内 `说明/`**。实测该目录当前**不存在**（未运行过；`ls 工程缓存/说明书` → No such file or directory）。
2. **绝不能把生成器指向包内 `说明/`**：生成物类入口**不设拒绝覆盖**，指向包内即等于批量有损覆盖。
3. 生成器**只能在 `/tmp` 或 `工程缓存/` 之类可再生区落盘**；**唯一落点由调用方显式指定**，禁止把「包内 `说明/`」当默认落点。
4. 生成物类入口另由 `生成目录说明书(声明列表)` 产出 `# 系统能力目录` 形态注册物。**现行登记物**：`开发文档/规范/能力目录说明书.md`（首行「本文件由 说明书生成器 生成（唯一事实源：包声明 + 能力定义 + 聚合契约），请勿手改」，`:5` 写「共 **138** 份包声明」）。**该份是生成物，禁止手改**，份数变了必须重跑生成器刷新。

### 3.3 生成器覆盖范围（实测边界，必须知道）

生成物类入口的包发现走 `发现全部(支持库根, 模块库根)`，其中 `扫描目录` 有**聚合库子域跳过**规则（`发现器.py:46-53`）：

> 形如 `后端/<聚合库>/<子域>/包声明.json` 且**该目录没有 `能力定义.json`** → 跳过。
> 聚合库名表 = `{系统核心支持库, 大语言模型支持库, 办公文档支持库, 文件系统支持库, 数据操作支持库, 网络通信支持库}`

**实测后果**：上述 **6 个聚合父包**（`支持库/后端/{办公文档,大语言模型,数据操作,文件系统,系统核心,网络通信}支持库`）**没有 `能力定义.json`**，因此**不在发现范围内、生不出一份对应说明书**。这 6 份包内说明书**永远不能靠生成器重生成**，只能人工维护（见第六节 6.2 末项）。

**实测份数**：发现 **135** 包 → 写出 **136** 文件（135 包 + 1 份 `能力目录说明书.md`）。

## 四、人工类：人工权威，禁覆盖

### 4.1 白名单是唯一机器清单

**文件**：`../项目证据/说明书白名单.json`（其「唯一真源」字段指向 `新建支持库与模块指南.md` 第九节）
**取值**：`白名单[].路径`

**铁律**：

1. **白名单是文件级、不是段落级**——一条命中即**整文件禁覆盖**。
2. **重生成前必须先核白名单**；命中即停手，改走人工补齐。
3. **混血包将来若确需重生成，必须先做行级合并**（保手写行、只刷生成行），不许整文件重写。
4. **人工类按平台现行格式人工维护**：新能力段落照既有格式补齐，实测返回逐字来自真实调用，**不许写「任意／无调用示例」占位**。

### 4.2 白名单类别（四类，实测 34 条）

| 类别 | 条数 | 含义 | 处置 |
|---|---|---|---|
| 人工类 | 25 | 整本人工写 | 生成器不得覆盖 |
| B混血包 | 6 | 有生成行 + 手写区（白名单记 `手写区行数`） | 禁整文件重生成；重生成前须行级合并 |

| 生成物类·词汇行已人工改写 | 2 | 外观是生成物类，但**词汇行上有人工改写** | 生成器不得覆盖（整文件） |

## 五、三方权威链（吵起来看这条）

```text
说明书 = 调用口径权威（给人看，唯一「调用口径以本文为准」的承载位）
契约   = 机器可读副本（包内 能力契约/参数契约.json 等）
实现   = 最终事实
三方不一致时：以【实现】为准，并同步另两方。
```

**口径边界（防误用）**：

- **契约只是「副本」，不是「真源」**：契约落后于实现时，**改契约、不动实现**。
- **说明书落笔前的争论按本条裁决**，不必等先改哪一方。
- **版本行滞后不算缺陷**：契约未变时，「说明书版本行落后于 `包声明.json`」按决策记录 `0020` **不计缺陷**——**不要**为刷新版本行去重生成整本说明书（会顺带抹掉手写区）。

**史实教训**：曾因 `返回字节` 字段三方不一致引发反复争论。实测该字段在 `支持库/后端/媒体处理支持库/FFmpeg媒体` 三方**本就一致**（`能力定义.json:251`、`包声明.json:103`、`能力契约/参数契约.json:268`、说明书 `:48` 全部为「返回字节:逻辑型」），生成物类生成器也如实保留。**争论的根因不是数据错，是三方分工没落纸**——本条即为此而设。

## 九、被否决的做法（写在这里防止重犯）

| 做法 | 为什么被否决 |
|---|---|
| 对全部说明书批量重生成 | 实测有损：37 份会变（25 份人工类／混血 + 12 份生成物类已漂移），人工类人工资产与混血手写区被格式覆盖 |
| 把生成物类入口的落点默认成包内 `说明/` | 生成物类入口**不设拒绝覆盖**（直接 `write_text`），指向包内即等于批量覆盖；组件规范侧虽会拒覆盖，但两侧同名容易误调 |
| 只看签名句判断「可重生成」 | D 类含签名句但**词汇行有人工改写**（隐藏覆盖）；6 大聚合父包也在「生成物类」里但生成器产不出，必须实跑生成器 + `difflib` 对账 |
| 把白名单当段落级 | 白名单是**文件级**；混血包按段落刷会抹掉手写行 |
| 为「版本行滞后」重生成整本说明书 | 契约未变时版本行滞后不算缺陷（决策记录 `0020`）；重生成会顺带抹掉手写区 |
| 手改 `开发文档/规范/能力目录说明书.md` | 生成物（「请勿手改」），份数／内容一律重跑生成器刷新 |
| 三方不一致时按契约改实现 | 契约是**机器可读副本**；以实现为准，同步另两方（第五节） |
| 用 `python3` 跑本文取证命令 | 本机 `python3` 非 3.14，行为不同；一律 `unset PYTHONPATH && python3.14`（1.1） |
