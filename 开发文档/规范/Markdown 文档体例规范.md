# Markdown 文档体例规范

> **这份规范管什么**：全仓 Markdown 怎么写。章节层级、必备要件、包级说明三件套、引用写法、编号、归档。
> **不管什么**：文档里写什么业务事实（那是 `开发文档/项目说明.md` 的事），也不管源码里怎么注释。
> **适用面**：全仓 `*.md`。**三类豁免**：`工程缓存/`（可再生的编译产物）、`开发文档/参考资料/`（外部项目笔记，按各项目原样保留）、`开发文档/归档/`（历史件，不再参与规范约束）。
>
> 建账依据：2026-09-17 全仓 614 份 md 实测体检。取证命令随条款给出，数字必须现场重算。

## 一、章节层级（一条铁律）

**一个文件只有一个一级标题（H1）。章节用 H2，子节用 H3。**

判据：`grep -c '^# ' <文件>` 必须等于 1。

为什么：多个 H1 会让目录树、锚点、页内跳转全部错位；读者在长文里定位不到自己在哪一层。

| 层级 | 用途 |
|---|---|
| H1 | 文件标题，全文件唯一 |
| H2 | 章节（对应目录里的一栏） |
| H3 | 章节内的条目 |
| H4 及更深 | 仅在表格/清单确实需要时使用，不允许再分章节 |

**现役反例（存量待收口，不是写法示范）**：`开发文档/哲学总账.md` 8 个 H1、`开发文档/目标定义_什么是OK.md` 7 个 H1、`开发文档/项目说明.md` 2 个 H1。这三份把 H1 当章节用了。
**正例**：`开发文档/决策记录/` 32 份全部是 1 个 H1 + 6 个 H2，可以直接照抄这个画法。

## 二、代码块围栏必须配对

**围栏（```）必须成对闭合。** 未闭合时，其后全文会被当成代码块，**目录、锚点、渲染全部错乱**——这是实际缺陷，不是风格问题。

判据：文件内行首围栏数必须为偶数。

```bash
grep -c '^[[:space:]]*```' <文件>   # 必须为偶数
```

**实测存量（2026-09-17）**：`支持库/后端/大语言模型支持库/模型连接器/说明/设计说明.md` 有 41 个围栏（奇数），第 68 行 ` ```python ` 开块后缺闭合，导致第 70 行的正文说明被吞进代码块。**已修复为 42（配对）**，备份 `.bak_20260917_fence`。

**关于代码块内的 `#`**：围栏内的行首 `#` **是受保护的**，GitHub 与主流渲染器不会把它当标题，**不构成缺陷，不需要改**。
（本条早期版本误把它写成缺陷，2026-09-17 实测纠正：`README.md` 27 处、`模型连接器/设计说明.md` 20 处、`项目说明.md` 15 处围栏内 `#` **全部在围栏内**，只有 1 处是真正的围栏未闭合。）

> 唯一需要留意的情况：**未闭合的围栏**会让后面的真标题也被当代码（表现为"文档后半段全变成灰底"）。遇到这种症状先查本条判据。

## 三、文件头元信息（权威文档与包级说明必备）

**权威文档和包级说明的开头必须有这三行**，给「实测还是历史快照」一个固定承载位：

```text
> 最后更新：2026-09-20
> 口径：[实测 | 历史快照]
> 维护者：[模块名 / 角色]
```

- **口径**只能写这两值之一。写「实测」就必须在正文给出取证命令；写「历史快照」就必须写明快照时点。
- 决策记录、归档件、参考资料不要求元信息头（它们按自身体例）。

依据：`AGENTS.md` 已要求「权威文档里的数字必须标清实测还是历史快照」，但此前**没有规定写在哪**，导致只能散在正文里。本条就是补这个位。

**★ 适用范围更正（2026-09-20 实测，此前写错）**：本节早期版本把「包级说明」也写成三行头必备 —— **与现场不符且方向错了**。
全仓实测：**358 份包级 `说明/*.md` 里 0 份有三行头**，而它们**另有自己的、更合适的画法**：

| 文件 | 实际头部（实测原文） | 为什么这样更好 |
|---|---|---|
| `说明/使用说明.md` | `- 类型：支持库` / `- 版本：1.0.3` / `- 入口：__init__.py` / `- 权威分工：**调用口径以本文为准**` | 这是**生成物**（由能力契约产出），信息是**包事实**不是文档时点 |
| `说明/设计说明.md` | `> 本文是该库的**设计哲学与边界权威**：…` / `> 调用口径——…以同目录 \`使用说明.md\` 为准` | 讲**两份说明的分工**，比「最后更新」对读者更有用 |

1. **三行头只适用于「权威文档 7 份 + 根 `README.md`」**（`项目说明` / `未完成事项` / `当前流程图` / `架构总览` / `主开发文档` / `哲学总账` / `目标定义_什么是OK` + `README.md`）。
2. **包级说明按第五节的血统规范走**（生成物类骨架 / 人工类），**不要求、也不应**加三行头 ——
   它是**生成物**，版本与内容随契约编译刷新；硬加「最后更新」会立刻过期，反而制造漂移（撞 3.1）。
3. **判据同步**：`Markdown 文档体例判据.json` 的「元信息头」判据**已带 `仅权威文档: true`** —— 与更正后的口径一致，**无需改判据**。

> 这条更正本身是 3.1 的实例：把「文档时点」硬套到「随契约刷新的生成物」上，就是设计了一种**必然过期**的写法。

### 3.0 ★ 三行的固定句式（2026-09-20 立，止「这里一点那里一点」）

**问题（2026-09-20 全仓实测）**：三行**内容齐全的有 54 份、缺的 115 份**；更严重的是**同一行的写法各写各的** ——
「口径」这一行实测出现两类画风：

| 画风 | 实例（实测原文） | 问题 |
|---|---|---|
| **合规（一句话）** | `> 口径：**实测**（plist 现场读取 + 制品结构现场核实）` | ✅ 一眼看出实测还是快照 |
| **跑偏（写成长解释）** | `> **数字口径**：本文件的数字是**结构性描述**，不是跨时点绝对值 —— …`<br>`> **统计口径与重测绘时机（2026-09-17 定）**：三态判定的统一口径 = ① …` | ❌ 把「口径」当小标题写段子，机器判据读不到，人也要翻半天才知道是实测还是快照 |

**固定句式（此后一律照此写，不再自创）：**

```text
> 最后更新：YYYY-MM-DD（可附一句时点限定，如「审计报告落盘当天」）
> 口径：实测 | 历史快照（实测须紧跟取证命令的位置或指向；历史快照须写快照时点）
> 维护者：<文档职责名，不写人名>
```

**判据**：
1. 三行**都必须以 `> ` 开头**、**键名逐字**为 `最后更新` / `口径` / `维护者`，**冒号用全角 `：`**。
2. `口径` 行的**值以 `实测` 或 `历史快照` 开头**，其后可跟括号补充（限一句）；**不得**把这一段改写成多行小标题或长篇解释。
3. 需要写长口径说明的，**另起一节**（H2），不要塞进元信息头。
4. **适用面**：权威文档 7 份 + 根 `README.md` + 包级 `说明/*.md`。方案 / 分析 / 交付记录 / 决策记录**不要求**（按自身体例），但也**不得发明第二种元信息头**。

**取证命令（口径 + 计数，引用前现场重跑）：**

```bash
python3.14 -m unittest 测试中心.支持库.测试_项目文档支持库   # 判据与规范一致性断言
```

> 计数类数字（多少份齐全、多少份缺）**不写死在本文**：按第三节总则第 1 条，只留口径与命令。

### 3.1 ★ 会变的数字不得写死在权威文档正文（2026-09-18 立，依据哲学 12.4②）

**问题（实测复发型）**：`项目说明.md` 的「能力数 / 包数 / 装配数 / 制品版本」写死了 09-17 的绝对值，
并发建包让它们**逐分钟失效** —— 同一份文件里出现 `140` 与 `141`、`1–13` 与 `1–14` 两套数自相矛盾；
外部审计一次就核出**成片漂移**。这不是笔误，是**写法本身会持续制造错误**。

**判据（照哲学 12.4②：「子项正文只写结论 + 判据，过程叙述、实测数字一律放决策记录」）**：

| 允许写在正文 | 禁止写在正文 |
|---|---|
| **口径**（这个数怎么算、算哪些集合） | **会随提交/建包变化的绝对值**（能力数、包数、装配数、制品版本、行号） |
| **取证命令**（右列那种一行可复算的命令） | 历史时间线（「21:4x → 128 包；23:56 → 634 能力」这类流水） |
| **当前实测值 + 明确的「同刻一致」限定**（可选，且必须紧跟取证命令） | 旧件的结论记在新件上（如旧制品的黑盒成绩） |

**硬要求**：
1. 会变的量，**一律写成「口径 + 取证命令」**；确需给当前值，必须同句写明「本表只保证与取证命令同刻一致」。
2. **历史时间线、旧值对照、过程叙述 → 直接删**（历史由 git 保留），不在正文留「已作废」划线段。
3. **行号类引用不得抄写**：写「`文件:行号` 前先现取」或直接写 `grep -n` 命令，防止改动后行号漂移成假事实。
4. 同一量**只在一处给数字**，其他文档一律**引用**（见 `方案文档生命周期规范.md` §「同数不同值」）。

**为什么写进规范而不是靠人记得**：这是**复发型**缺陷 —— 只要还允许写死绝对值，下一轮建包必然再次全表失效（哲学 14.3：反复犯错的开发要补底层）。

### 3.2 ★ 生成区与人工区：文档由生成器出，人只填内容（2026-09-20 立）

**华哥 2026-09-20 口径（原文两条）**：

> 「你要不这样子，**先定义好所有文档撰写的格式。生成器先弄好**，然后再根据生成器的
> 固定格式，然后一点一点的去看 md，然后手动的去修到对应的格式？」
>
> 「**你规范了生成器，后面应该是围绕着生成器去出文档才对。**」

第二句是第一句的修正：**不是「手写 md 再让生成器校验」，是「生成器去出文档」**。
生成器是文档的**生产者**，人只在它划定的区域里写内容。

**每份「格式可派生」的文档分两区**：

| 区 | 内容 | 谁写 | 判据 |
|---|---|---|---|
| **生成区** | 元信息头、派生数据（账目/清单/索引/计数）、固定骨架 | **只有生成器**，人不得手改 | 跑生成器后 `git diff` 为空；非空即有人手改过 |
| **人工区** | 需要人的判断的内容（条目正文、结论、取舍理由） | 人写，生成器**原样保留** | 行级合并时人工行零丢失；丢了即生成器缺陷 |

**落地机制（沿用说明书生成器已验证的做法）**：

1. **唯一生成器**：一类文档一个生成器入口，`--写盘`（出文档）/ `--校验`（核验漂移）两个形态。
2. **边界可识别**：生成区起止用固定句式（如首行 `> 最后更新：`、段末固定标题）或显式标记，
   **机器必须能无歧义切出**；切不出即 fail-closed 报错，不许猜。
3. **人工区零丢失自检**：写盘前比对人工行集合，丢一行即**拒绝写盘**（与
   `开发工具.说明书生成.合并重生成` 同款哨兵）。
4. **接门禁**：生成器进编译口或发布门禁（阻断），改文档没跑生成器即判红。

**反例（本仓实测，两次返工）**：`开发文档/未完成事项.md` 顶部账目**曾手写**，
与正文实数两次对不上（`71 vs 52`、`合计 52 vs 分区和 49`）⇒ 手写汇总本身就是缺陷源。
现已改为统一生成器 `开发工具.MD文档生成 --类型 债务清单` 出账目块 + 元信息头，标题行明写「机器生成，禁止手改」。

**新增文档时的顺序（华哥口径，不得颠倒）**：

```text
① 定格式（本规范：章节层级 / 元信息头 / 生成区与人工区边界）
② 弄生成器（按①的固定格式产出）
③ 逐份对齐存量文档 —— 能派生的交给生成器刷，只剩人工判断的部分留人工区
```

**被否决的做法**：先手写文档、再补一个「校验器」去事后检查 —— 那是**只修了一半**
（源头仍是手写），下一次照样漂移；必须**两边都归一**（生成器出 + 门禁核验同源）。

## 四、包级说明三件套

每个带 `包声明.json` 的包，`说明/` 目录下的文件固定为：

| 文件 | 是否必备 | 内容边界 |
|---|---|---|
| `使用说明.md` | **必备** | 调用口径权威：能力、参数、返回、错误码、调用示例 |
| `设计说明.md` | **必备** | 设计权威：本包是什么、不是什么、管什么、不管什么、为什么这样切、失败如何表达 |
| `目录树与命令.md` | 条件必备（见下） | 本包目录树 + 常用命令 |

**`目录树与命令.md` 的必备条件**（此前无规则，这是缺口）：满足任一条即必须写——

1. 包内有 `实现/` 之外的可执行入口（命令行、脚本、子进程入口）；
2. 包需要**独立运行**（不经统一网关调用，如模板生成器、验证器、门禁）；
3. 包涉及**外部工具或外部进程**（`适配层/*提供者`）。

**当前实测**：143 个 `说明/` 目录中 67 份有 `目录树与命令.md`。分布为 支持库 55 / 模块库 12 / 平台控制面 0 / 运行核心 0。
按本条条件，`平台控制面` 15 个包、`运行核心` 3 个包**均不满足**（都经统一网关调用、无独立入口），故不要求补——**它们缺得合法**。

**禁止**：在 `说明/` 下另起第四种文件名。已知的 6 处历史偏离（`资源管理说明.md`、`灰度口径.md`、`限流边界说明.md`、`待补能力清单.md`、`适配层/说明/README.md`、`MySQL提供者/说明/目录树与命令.md` 单文件）**按历史保留，不要求改名**；新建包一律不得再起别名。

## 五、使用说明的两种血统

`使用说明.md` 存在两套骨架，**生成物类是唯一标准**：

| 血统 | 判据句 | 份数 | 章节画法 |
|---|---|---|---|
| **生成物类（标准）** | 含「权威分工：**调用口径以本文为准**」 | 116 | `## 能力` + `### 能力名` |
| 人工类（历史） | 不含该句 | 24 | `## 能力清单`（表格）+ `## 各能力名` |

**规则**：

1. **新建包的说明书一律用生成物类骨架**（由生成器产出）。
2. 存量人工类 24 份 + 混血 6 份 + 词汇行改写 2 份，**共 32 份已登记在 `开发文档/项目证据/说明书白名单.json`**，处置为「生成器不得覆盖」，**不做批量重生成**（实测有损：`FFmpeg媒体` 说明书里唯一正确的 `返回字节` 会被抹掉）。
3. 白名单是**文件级、不是段落级**：混血包将来重生成必须先做**行级合并**（保手写行、刷生成行）。
4. 两套生成器**都不是现存说明书的权威生产者**：`开发工具/说明书生成/` 的输出目录是 `工程缓存/说明书/`（不是包内 `说明/`）；唯一落点必须由调用方显式指定。
5. **三方权威链**：`说明书 = 调用口径权威（给人看） ｜ 契约 = 机器可读副本 ｜ 实现 = 最终事实`。三方不一致时**以实现为准**，并同步另两方。

取证：

```bash
rg -l "调用口径以本文为准" --glob "说明/使用说明.md" | wc -l
```

## 六、引用与链接写法

**两条硬规则**：

1. **链接文字必须等于目标文件名**（含日期后缀），不允许简写。
   反例：文字写 `方案/项目总纲重写方案.md`，实际文件是 `项目总纲重写方案_20260917.md` —— 链接能点开，但按文字找文件找不到。
2. **相对路径按本文件所在目录解析**，不用仓库根相对路径（避免搬迁后全库失效）。

**归档类文件不得被权威文档正文链接引用**（`AGENTS.md` 既有条款）。历史上 `开发文档/主开发文档.md` 的文档地图把 `归档/` 列为链接，与这条冲突，已按本条收口。

`开发文档/方案/` 下的每一份都必须在 `开发文档/主开发文档.md` 的 C 栏登记；新增方案未登记即视为找不到的文档。

## 七、编号

| 对象 | 规则 |
|---|---|
| 决策记录 | 四位递增、**不复用**。**允许跳号，缺号即从未存在过**——不允许回收空缺号 |
| 哲学条款 | 主条编号全局唯一，废止的子项**留空不重排**（重排会让全仓引用失效） |
| 哲学条数的声明 | **只在一处声明**（`开发文档/项目说明.md` 的《设计哲学》段），其余文档一律引用、不复述数字 |
| 其他文档的列表 | 不得使用裸编号，必须带类别前缀（步骤 / 坑 / 条目 / 检查项 / 用例 / 批次 / 规则） |

## 八、归档

**归档只保留一个顶层 `开发文档/归档/`，按 `年月_主题` 命名。**

三类内容允许进归档：

1. 历轮取证与历史（正文已收口到权威文档、原文需留档备查的）；
2. 已被取代的阶段资料（旧快照、旧清单、切换步骤）；
3. 已完结审计的原始报告。

**口径澄清（消解历史冲突）**：早期「不做本地归档，GitHub 才是归档」（哲学 1.7）指的是**成品与制品不进本地归档库**——每次交付的产物直接上传 GitHub，不在本机堆积旧制品。**与本节不矛盾**：本节管的是**文档历史**，1.7 管的是**成品与制品**。两者边界如下表：

| 对象 | 处置 |
|---|---|
| 成品、制品、安装包、构建产物 | 不进本地归档，直接上传 GitHub，本机旧的直接删（哲学 1.7） |
| 文档历史（取证记录、历轮快照、完结审计报告） | 进 `开发文档/归档/`，按 `年月_主题` 组织 |

**归档件不作为派活依据**，也不得被权威文档正文链接引用。正文需要引用历史时，写「见 Git 提交」而非链接归档文件。

## 十、被否决的做法（写在这里防止重犯）

| 做法 | 为什么被否决 |
|---|---|
| 对全部说明书做批量重生成 | 实测**有损覆盖**：`FFmpeg媒体` 说明书里唯一正确的 `返回字节` 会被生成物抹掉 |
| 把「不做本地归档」判据写成「仓库中不存在归档目录」 | 天然难以机器判定，且与文档历史留档需求直接对撞；已改为「只保留一个顶层归档目录」 |
| 用脚本批量重写全部 Markdown 的层级 | 会破坏代码块内 `#` 注释的语义、误改引用文字；文档收敛必须**一份一份看、一份一份验证** |
| 在 `说明/` 下按主题另起文件名 | 会让「包级规范」变成找不到的规范；历史偏离保留，新建禁止 |
