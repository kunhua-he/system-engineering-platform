# Markdown 文档体例规范

> **这份规范管什么**：全仓 Markdown 怎么写。章节层级、必备要件、包级说明三件套、引用写法、编号、归档。
> **不管什么**：文档里写什么业务事实（那是 `开发文档/项目说明.md` 的事），也不管源码里怎么注释。
> **适用面**：全仓 `*.md`。**三类豁免**：`工程缓存/`（可再生的编译产物）、`开发文档/参考资料/`（外部项目笔记，按各项目原样保留）、`开发文档/归档/`（历史件，不再参与规范约束）。
>
> 建账依据：2026-09-17 全仓 614 份 md 实测体检。取证命令随条款给出，数字必须现场重算。

---

## 一、章节层级（一条铁律）

**一个文件只有一个一级标题（H1）。章节用 H2，子节用 H3。**

判据：`grep -c '^# ' <文件>` 必须等于 1。

为什么：多个 H1 会让目录树、锚点、页内跳转全部错位；读者在长文里定位不到自己在哪一层。

| 层级 | 用途 |
|---|---|
| H1 | 文件标题，全文件唯一 |
| H2 | 章节（对应目录里的一栏） |
| H3 | 章节内的条目 |
| H4 及更深 | 仅在表格/清单确实需要时使用，不允许再分章节 |

**现役反例（存量待收口，不是写法示范）**：`开发文档/哲学总账.md` 8 个 H1、`开发文档/目标定义_什么是OK.md` 7 个 H1、`开发文档/项目说明.md` 2 个 H1。这三份把 H1 当章节用了。
**正例**：`开发文档/决策记录/` 32 份全部是 1 个 H1 + 6 个 H2，可以直接照抄这个画法。

## 二、代码块围栏必须配对

**围栏（```）必须成对闭合。** 未闭合时，其后全文会被当成代码块，**目录、锚点、渲染全部错乱**——这是实际缺陷，不是风格问题。

判据：文件内行首围栏数必须为偶数。

```bash
grep -c '^[[:space:]]*```' <文件>   # 必须为偶数
```

**实测存量（2026-09-17）**：`支持库/后端/大语言模型支持库/模型连接器/说明/设计说明.md` 有 41 个围栏（奇数），第 68 行 ` ```python ` 开块后缺闭合，导致第 70 行的正文说明被吞进代码块。**已修复为 42（配对）**，备份 `.bak_20260917_fence`。

**关于代码块内的 `#`**：围栏内的行首 `#` **是受保护的**，GitHub 与主流渲染器不会把它当标题，**不构成缺陷，不需要改**。
（本条早期版本误把它写成缺陷，2026-09-17 实测纠正：`README.md` 27 处、`模型连接器/设计说明.md` 20 处、`项目说明.md` 15 处围栏内 `#` **全部在围栏内**，只有 1 处是真正的围栏未闭合。）

> 唯一需要留意的情况：**未闭合的围栏**会让后面的真标题也被当代码（表现为"文档后半段全变成灰底"）。遇到这种症状先查本条判据。

## 三、文件头元信息（权威文档与包级说明必备）

**权威文档和包级说明的开头必须有这三行**，给「实测还是历史快照」一个固定承载位：

```text
> 最后更新：2026-09-17
> 口径：[实测 | 历史快照]
> 维护者：[模块名 / 角色]
```

- **口径**只能写这两值之一。写「实测」就必须在正文给出取证命令；写「历史快照」就必须写明快照时点。
- 决策记录、归档件、参考资料不要求元信息头（它们按自身体例）。

依据：`AGENTS.md` 已要求「权威文档里的数字必须标清实测还是历史快照」，但此前**没有规定写在哪**，导致只能散在正文里。本条就是补这个位。

## 四、包级说明三件套

每个带 `包声明.json` 的包，`说明/` 目录下的文件固定为：

| 文件 | 是否必备 | 内容边界 |
|---|---|---|
| `使用说明.md` | **必备** | 调用口径权威：能力、参数、返回、错误码、调用示例 |
| `设计说明.md` | **必备** | 设计权威：本包是什么、不是什么、管什么、不管什么、为什么这样切、失败如何表达 |
| `目录树与命令.md` | 条件必备（见下） | 本包目录树 + 常用命令 |

**`目录树与命令.md` 的必备条件**（此前无规则，这是缺口）：满足任一条即必须写——

1. 包内有 `实现/` 之外的可执行入口（命令行、脚本、子进程入口）；
2. 包需要**独立运行**（不经统一网关调用，如模板生成器、验证器、门禁）；
3. 包涉及**外部工具或外部进程**（`适配层/*提供者`）。

**当前实测**：143 个 `说明/` 目录中 67 份有 `目录树与命令.md`。分布为 支持库 55 / 模块库 12 / 平台控制面 0 / 运行核心 0。
按本条条件，`平台控制面` 15 个包、`运行核心` 3 个包**均不满足**（都经统一网关调用、无独立入口），故不要求补——**它们缺得合法**。

**禁止**：在 `说明/` 下另起第四种文件名。已知的 6 处历史偏离（`资源管理说明.md`、`灰度口径.md`、`限流边界说明.md`、`待补能力清单.md`、`适配层/说明/README.md`、`MySQL提供者/说明/目录树与命令.md` 单文件）**按历史保留，不要求改名**；新建包一律不得再起别名。

## 五、使用说明的两种血统

`使用说明.md` 存在两套骨架，**甲支是唯一标准**：

| 血统 | 判据句 | 份数 | 章节画法 |
|---|---|---|---|
| **甲支（标准）** | 含「权威分工：**调用口径以本文为准**」 | 116 | `## 能力` + `### 能力名` |
| 乙支（人工权威，历史） | 不含该句 | 24 | `## 能力清单`（表格）+ `## 各能力名` |

**规则**：

1. **新建包的说明书一律用甲支骨架**（由生成器产出）。
2. 存量乙支 24 份 + 混血 6 份 + 词汇行改写 2 份，**共 32 份已登记在 `开发文档/项目证据/说明书白名单.json`**，处置为「生成器不得覆盖」，**不做批量重生成**（实测有损：`FFmpeg媒体` 说明书里唯一正确的 `返回字节` 会被抹掉）。
3. 白名单是**文件级、不是段落级**：混血包将来重生成必须先做**行级合并**（保手写行、刷生成行）。
4. 两套生成器**都不是现存说明书的权威生产者**：`开发工具/说明书生成/` 的输出目录是 `工程缓存/说明书/`（不是包内 `说明/`）；唯一落点必须由调用方显式指定。
5. **三方权威链**：`说明书 = 调用口径权威（给人看） ｜ 契约 = 机器可读副本 ｜ 实现 = 最终事实`。三方不一致时**以实现为准**，并同步另两方。

取证：

```bash
rg -l "调用口径以本文为准" --glob "说明/使用说明.md" | wc -l
```

## 六、引用与链接写法

**两条硬规则**：

1. **链接文字必须等于目标文件名**（含日期后缀），不允许简写。
   反例：文字写 `方案/项目总纲重写方案.md`，实际文件是 `项目总纲重写方案_20260917.md` —— 链接能点开，但按文字找文件找不到。
2. **相对路径按本文件所在目录解析**，不用仓库根相对路径（避免搬迁后全库失效）。

**归档类文件不得被权威文档正文链接引用**（`AGENTS.md` 既有条款）。历史上 `开发文档/主开发文档.md` 的文档地图把 `归档/` 列为链接，与这条冲突，已按本条收口。

`开发文档/方案/` 下的每一份都必须在 `开发文档/主开发文档.md` 的 C 栏登记；新增方案未登记即视为找不到的文档。

## 七、编号

| 对象 | 规则 |
|---|---|
| 决策记录 | 四位递增、**不复用**。**允许跳号，缺号即从未存在过**——不允许回收空缺号 |
| 哲学条款 | 主条编号全局唯一，废止的子项**留空不重排**（重排会让全仓引用失效） |
| 哲学条数的声明 | **只在一处声明**（`开发文档/项目说明.md` 的《设计哲学》段），其余文档一律引用、不复述数字 |
| 其他文档的列表 | 不得使用裸编号，必须带类别前缀（步骤 / 坑 / 条目 / 检查项 / 用例 / 批次 / 规则） |

**实测缺口**：决策记录 `0010` 全历史不存在（已查 `git log --all --diff-filter=A`），按本条属**合法跳号**，不需要补。

## 八、归档

**归档只保留一个顶层 `开发文档/归档/`，按 `年月_主题` 命名。**

三类内容允许进归档：

1. 历轮取证与历史（正文已收口到权威文档、原文需留档备查的）；
2. 已被取代的阶段资料（旧快照、旧清单、切换步骤）；
3. 已完结审计的原始报告。

**口径澄清（消解历史冲突）**：早期「不做本地归档，GitHub 才是归档」（哲学 1.7）指的是**成品与制品不进本地归档库**——每次交付的产物直接上传 GitHub，不在本机堆积旧制品。**与本节不矛盾**：本节管的是**文档历史**，1.7 管的是**成品与制品**。两者边界如下表：

| 对象 | 处置 |
|---|---|
| 成品、制品、安装包、构建产物 | 不进本地归档，直接上传 GitHub，本机旧的直接删（哲学 1.7） |
| 文档历史（取证记录、历轮快照、完结审计报告） | 进 `开发文档/归档/`，按 `年月_主题` 组织 |

**归档件不作为派活依据**，也不得被权威文档正文链接引用。正文需要引用历史时，写「见 Git 提交」而非链接归档文件。

## 九、怎么检查（本条为**只报告**，暂不阻断）

对全仓 Markdown 跑以下四项，输出问题清单，**只报告不阻断**（待存量收口干净后再评估是否升级为发布门禁项，升级与否按「门禁结论五态」另行裁决）。

| 检查项 | 判据 |
|---|---|
| 单 H1 | `grep -c '^# ' <文件>` = 1（豁免：`归档/`、`参考资料/`） |
| 围栏配对 | 文件内行首围栏数为偶数 |
| 包级三件套 | 带 `包声明.json` 的包必须有 `说明/使用说明.md` + `说明/设计说明.md` |
| 链接可达 | 内部相对链接 `[]()` 的目标文件必须存在 |
| 引用文字一致 | 链接文字必须等于目标文件名 |

## 十、被否决的做法（写在这里防止重犯）

| 做法 | 为什么被否决 |
|---|---|
| 对全部说明书做批量重生成 | 实测**有损覆盖**：`FFmpeg媒体` 说明书里唯一正确的 `返回字节` 会被生成物抹掉 |
| 把「不做本地归档」判据写成「仓库中不存在归档目录」 | 天然难以机器判定，且与文档历史留档需求直接对撞；已改为「只保留一个顶层归档目录」 |
| 用脚本批量重写全部 Markdown 的层级 | 会破坏代码块内 `#` 注释的语义、误改引用文字；文档收敛必须**一份一份看、一份一份验证** |
| 在 `说明/` 下按主题另起文件名 | 会让「包级规范」变成找不到的规范；历史偏离保留，新建禁止 |
