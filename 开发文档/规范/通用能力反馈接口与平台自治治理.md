## 一、目标

能力平台只负责三件事：

条目 1：提供稳定、版本化、可发现的通用能力；
条目 2：管理 Provider、进程、模型、句柄、资源和发布；
条目 3：接收调用方提交的结构化能力反馈，并由平台 Agent 负责分析、修复、验证和发布。

能力平台不读取调用方源码、业务数据库或业务内部状态，不为任何一个调用方复制专属逻辑。

## 二、平台边界

平台对外只暴露：

- 能力搜索与契约查询；
- 能力执行 HTTP 接口；
- 流式能力 HTTP 接口；
- 能力反馈登记 HTTP 接口；
- 反馈查询与处理状态 HTTP 接口；
- 健康检查和运行诊断接口。

平台内部可以有支持库、模块库、Provider、运行核心和控制面，但这些都是平台内部实现，不成为调用方依赖。

调用方只能依赖：

```text
能力id
+ 契约版本
+ 参数类型
+ 返回结构
+ 错误码
+ HTTP 接口
```

## 三、能力反馈接口

### 3.1 登记反馈

```http
POST /平台/能力反馈
```

请求体：

```json
{
  "来源系统": "调用方标识",
  "来源版本": "调用方版本或提交号",
  "请求id": "原始请求编号",
  "能力id": "能力标识",
  "契约版本": "1.0.0",
  "错误码": "提供者不可用",
  "错误说明": "真实错误说明",
  "HTTP状态码": 503,
  "请求摘要": {},
  "响应摘要": {},
  "复现标识": "可选幂等键",
  "优先级": "普通"
}
```

响应：

```json
{
  "成功": true,
  "值": {
    "反馈id": "反馈编号",
    "状态": "已登记",
    "是否重复": false
  },
  "错误码": "",
  "错误说明": "",
  "请求id": "请求编号"
}
```

### 3.2 查询反馈

```http
GET /平台/能力反馈/{反馈id}
GET /平台/能力反馈?状态=已登记&能力id=能力标识
```

查询结果只返回反馈记录和处理状态，不返回密钥、完整业务正文或调用方数据库内容。

### 3.3 更新处理状态

平台 Agent 使用内部受控入口更新：

```http
POST /平台/能力反馈/{反馈id}/状态
```

允许状态：

```text
已登记
已确认
修复中
待验证
已修复
已关闭
无法复现
重复反馈
```

状态迁移必须记录：处理者、时间、原因、关联提交、验证证据和发布制品。

## 五、平台 Agent 处理流程

```text
反馈登记
  ↓
字段/能力/契约校验
  ↓
按能力id和错误码聚类去重
  ↓
读取平台内部实现、Provider状态和运行日志
  ↓
复现请求
  ↓
判断：契约问题 / Provider问题 / 资源问题 / 环境问题 / 调用方参数问题
  ↓
最小修复
  ↓
定向测试
  ↓
真实 HTTP/HTML 黑盒
  ↓
资源回收和制品校验
  ↓
发布门禁
  ↓
更新反馈状态和关联证据
```

平台 Agent 不因为反馈量大而复制调用方逻辑，不把业务项目代码搬进底座，不为单一调用方写专属分支。

## 六、统一错误分类

平台公开错误码保持平台级、稳定、可聚合：

```text
能力不存在
参数不合法
契约不匹配
权限不足
提供者不可用
资源不足
超时
取消
进程崩溃
返回格式错误
返回超限
能力执行失败
```

错误说明可以包含诊断信息，但不得泄漏密钥、内部绝对路径、数据库连接串或第三方认证信息。

## 七、资源与反馈的关系

反馈登记不能替代资源清理。

能力失败时，平台必须保证：

- 句柄进入终态；
- 子进程和进程组被回收；
- 临时文件和临时目录按契约清理；
- 监听端口释放；
- 流式通道关闭；
- 清理失败被单独记录并可查询。

反馈记录只能引用资源清理证据，不得把“已登记反馈”当作“资源已释放”。

## 八、版本与发布

能力契约版本、Provider版本、正式制品摘要和反馈修复提交必须分开记录：

```text
反馈id
→ 修复提交
→ 定向验证证据
→ HTML/HTTP证据
→ 制品摘要
→ 发布门禁结果
```

能力内部实现升级但契约不变时，可以做小版本发布；能力参数、返回、错误码或资源语义变化时，必须升级契约版本并保留兼容策略或明确废弃旧版本。

## 九、平台自身验收

平台反馈接口必须用真实 HTTP 验收：

检查项 1：合法反馈登记成功；
检查项 2：重复反馈正确去重；
检查项 3：非法能力id被拒绝；
检查项 4：缺少必填字段被拒绝；
检查项 5：超大摘要被拒绝；
检查项 6：~~敏感字段被脱敏~~（**已变更 2026-09-15**：按第 9 条 1 项底座不脱敏 → 改为「原文存储可按回读核对」）；
检查项 7：查询可读回登记记录；
检查项 8：状态迁移记录完整；
检查项 9：未授权调用被拒绝；
检查项 10：服务重启后记录仍可读；
检查项 11：反馈接口故障不影响能力执行接口的统一错误返回；
检查项 12：不产生第二套能力注册表或第二套 Provider 执行腿。

## 十、完成标准

满足以下条件后，平台反馈能力才算完成：

- 反馈接口契约已冻结；
- 反馈记录有唯一持久化事实源；
- 去重、认证、限流、大小上限已验证；~~脱敏~~（**已变更**：按第 9 条 1 项取消，改为原文存储核对）；
- 平台 Agent 可以从登记反馈定位到能力、Provider和制品；
- 修复、验证、发布、状态回写形成闭环；
- 平台源码不包含任何具体业务项目名称或项目专属分支；
- 平台只通过公开能力契约接收调用方信息。

## 十一、禁止事项

- 不为单个调用方建立专属数据库表；
- 不把调用方的业务字段加入通用能力契约；
- 不读取调用方项目源码来决定平台运行逻辑；
- 不允许调用方直接写平台数据库；
- 不用模型自由文本覆盖错误码和状态机；
- 不因反馈接口失败而静默改变能力执行结果；
- 不保留第二执行网关或旁路 Provider。
