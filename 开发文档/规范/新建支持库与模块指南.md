# 新建支持库与模块指南

> 结论先给：**代码模板有三个（必须用），专门讲流程的 md 原来没有，这份就是**。
> 模板落点：`支持库/后端/组件规范支持库`（原 `开发工具/组件规范/` 已整体下沉为正式支持库包，旧路径 `开发工具.组件规范.*` 已不存在——实测 `import` 抛 `ModuleNotFoundError`）。
> 从**包级公开入口**导入即可：`生成支持库模板`、`生成模块模板`、`生成技能模板`、`生成快照清单模板`（实现文件在同包 `实现/` 下，**禁止跨包直接 import 实现目录**，依赖防火墙会拒）。
> 三个都是「Python 函数调用」，**没有命令行参数**；生成即完整骨架，不手搓。
> 只有 `生成模块模板` 另外注册成了网关能力 `组件规范支持库.生成模块模板`（可经 40007 调用）；模板类函数一律在**能 import 本包**的进程内调用。

## 一、先判断该建什么（分层归属固定，第 2 条 1 项）

| 你要做的东西 | 落到哪 | 判据 |
| --- | --- | --- |
| 最小原子能力（连接池、句柄、重试、编码转换…） | `支持库/后端/<某支持库>/<包名>` | 一个包只做一件事，可被无数模块复用 |
| 把第三方库翻译成中文能力（psycopg、ffmpeg…） | `支持库/适配层/<提供者>` | 支持库内部调用提供者＝门面→提供者，不算跨模块 |
| 独立进程/服务/动态库/外部接口（PostgreSQL、FFmpeg、Git） | 声明为**环境依赖**（适配层声明层分段） | 需要版本+入口+端口+健康探针+启停+降级 |
| 组装能力（多能力组合成一个业务动作） | `模块库/<模块名>` | 只经 `获取能力调用器().调用能力(能力id, 参数)` |
| 固定工作流（先做什么后做什么） | `技能库` 或 Agent 技能 | 不新增底座能力 |
| 前端描述类 | `支持库/前端/<描述>` | 只描述，不执行 |

**结果唯一即收口（第 1 条 3 项）**：同一个目的已经有支持库了，就别新建第二个——保留最全面的那个，把其余的蒸馏进去。

## 二、支持库模板（九要素一次到位）

```python
unset PYTHONPATH
python3.14 -c "
import sys; sys.path.insert(0, '.')
from 支持库.后端.组件规范支持库 import 生成支持库模板
结果 = 生成支持库模板(
    输出目录='支持库/后端/示例支持库/示例包',
    包id='示例支持库.示例包',
    名称='示例包',
    能力清单=[{
        '能力id': '示例支持库.示例包.示例能力',
        '中文名称': '示例能力',
        '说明': '一句话说清这个能力做什么',
        '参数': [{'名称': '输入文本', '类型': '文本型', '必填': True, '默认值': None, '说明': '待处理文本'}],
        '返回': '结果型',
        '错误码': ['参数不合法'],
    }],
    说明='示例支持库的能力说明',
)
print(结果.成功, 结果.错误码)
"
```

生成内容（九要素）：`能力定义.json`（**唯一可编辑事实源**）、`包声明.json`、`能力契约/参数契约.json`、
`依赖锁.json`、`配置契约.json`、`权限契约.json`、`实现/{子进程入口,提供者}.py`、`验证场景引用.json`、
`说明/使用说明.md`、`说明/设计说明.md`、`复用决策.json`、`资源预算.json`、
`__init__.py`（中文公开入口 + 注册能力）、`完整性摘要.json`，
另加测试骨架 `测试中心/支持库/测试_<名称>.py`。

模板自带防御：**输出目录已存在文件就拒绝覆盖**（返回已存在清单）、路径逃逸拒绝、能力重名拒绝、
第三方只许声明为外部工具/受管（真要用第三方必须单独支持库或适配层翻译层）。

## 三、模块模板

```python
unset PYTHONPATH
python3.14 -c "
import sys; sys.path.insert(0, '.')
from 支持库.后端.组件规范支持库 import 生成模块模板
结果 = 生成模块模板(
    模块名='示例模块', 类型='基础模块',
    能力清单=[{'能力id': '示例模块.示例能力', '中文名称': '示例能力', '说明': '…',
              '参数': [], '返回': '结果型', '错误码': ['参数不合法']}],
    依赖能力清单=[{'能力': '文件系统支持库.文件操作.读取文件', '版本': '>=1.0.0'}],
)
print(结果.成功, 结果.错误码)
"
```
类型只允许 `基础模块|功能模块`；实现骨架里**不 import 支持库/提供者/第三方/核心**，
一律经 `获取能力调用器().调用能力(...)`（唯一调用入口，第 7 条 4 项 统一调用接口铁律）。

生成内容：`包声明.json`、`能力契约/参数契约.json`（S0.1 聚合格式）、`依赖契约/依赖契约.json`、
`配置契约.json`、`权限契约.json`、`验证场景引用.json`（v1）、`实现/<模块名>.py`、
`__init__.py`（中文公开入口 + 注册能力）、`说明/使用说明.md`、`说明/设计说明.md`、
`复用决策.json`、`资源预算.json`、`完整性摘要.json`，
另加测试骨架 `测试中心/模块库/测试_<模块名>.py`。

> **模块不生成 `依赖锁.json`**（模块不许有第三方依赖，仓内铁口径：依赖锁存在 ⟺ 有第三方依赖）；
> 支持库侧同理——只有真的声明了第三方依赖时才生成锁，这是唯一生成器的判定，不是漏项。

## 四、生成之后必须做的五件事

模板只产出**结构正确**的骨架；下面 1–3 项是「作者手写」责任，4 项是「编译器派生」责任，5 项是验收。
**逐件写清模板已产什么、还缺什么、谁负责补**——照着做就不会出现「以为模板给了、其实没有」。

| 文件 | 模板是否已产 | 谁负责补 |
| --- | --- | --- |
| `能力定义.json`（支持库） | 已产（占位能力） | **作者手写**：唯一可编辑事实源，改完必须重编译 |
| `包声明.json` / 各契约 | 已产（占位） | 作者按真实能力补；`能力契约/参数契约.json` 由编译器重生成 |
| `实现/提供者.py` / `实现/<模块名>.py` | 已产（骨架，返回未实现/占位值） | **作者手写**（步骤 1） |
| `说明/使用说明.md` | 已产 | 作者按真实能力核对（生成器刷新见 9.1 血统判定） |
| `说明/设计说明.md` | 已产（**设计权威骨架 + 「待填写」占位**） | **作者手写**（步骤 1.5）：写成空话等于没有设计权威 |
| `复用决策.json` | 已产（**只给结构，`搜索词`/`候选能力id` 留空**） | **作者手写**（步骤 1.5）：真跑一次能力搜索后填 |
| `资源预算.json` | 已产（**保守默认值，十项必需键齐全**） | 作者按真实依赖链核对（步骤 1.5） |
| `验证场景引用.json` | 已产（**v1 格式：`契约版本` + 空引用列表**） | **作者手写**：引用列表为空过不了门禁，必须补 `验证场景/*.json` 并引用 |
| `能力数据/`（`能力搜索数据.json`、`Agent查询数据.json`） | **模板不产** | **编译器派生**（步骤 2）：从 `能力定义.json` 生成，**禁手改** |
| `验证场景/`（场景正文） | **模板不产** | **作者手写**：场景正文是业务事实，编译器与模板都不许代写 |
| `完整性摘要.json` | 已产 | 步骤 3 重算（模板产的是生成期快照，改完内容必须重算） |

### 步骤 1：**填实现**

`实现/提供者.py`（或者模块的 `实现/<模块名>.py`）里写真实逻辑，替换占位；错误码只写实现里真实存在的失败码（`结果.失败("…")` 字面量），不许虚列。

### 步骤 1.5：**填齐模板产的三件「待作者补」文件**（新增，2026-09-18）

这三件模板**已经生成**，但生成的是**结构 + 占位**，不是结论。验收（`组件合规`）会按下面判据逐件看：

- **`复用决策.json`**：`搜索词` 与 `候选能力id` 模板里**都是空列表**（不预置「已查无重复」结论）。
  按 `开发工具/能力搜索/能力搜索器.py` 真跑一次搜索后填进去；查无命中也要写下搜过的词并在
  `待填写.候选能力id` 里说明「未命中」——**空列表与「没查过」无法区分**，`组件合规` 的结构场景会判红（S0 缺项阻断）。
  > 注意：支持库模板会附 `搜索词建议`，模块模板另附 `依赖能力说明`（已声明依赖，**不算搜索结果**，不能顶替 `候选能力id`）。
- **`资源预算.json`**：模板给的是**保守默认**（支持库＝带子进程档；模块＝组合层，`子进程上限` 为 0），
  **是默认不是实测**。按真实 IO 面（网络/文件/进程/内存）核对后调整；十项键名必须与
  `平台控制面/资源监督.py::资源监督器.必需预算键` 逐字一致（缺项被 `组件合规`／发布门禁判红）。
- **`说明/设计说明.md`**：设计权威。模板给的是**七节骨架**（是什么/不是什么/管什么/不管什么/
  为什么这样切/失败如何表达/被否决的做法），带 `**待填写**` 的位置必须逐条改成真实内容——
  写成空话或直接删节，等于这个包没有设计权威（`Markdown 文档体例规范.md` 第四节把它列为包级三件套**必备**项）。

**`验证场景引用.json` 只给了 v1 空壳**：模板直产的已经是合法 v1 格式（`契约版本: 验证场景/v1` +
空引用列表），**不再需要手改格式**；但**引用列表为空同样过不了 `组件合规` 结构场景**
（「验证证据为空」）——作者要补 `验证场景/*.json` 场景正文并在此引用（见步骤 4 与坑 6）。

### 步骤 2：**编译派生物**

调 `开发工具.契约编译.能力定义编译器` 的 `编译能力定义(定义文件, 包目录, 包 id, 包名称, 包类型, 依赖, 实现模块)`（定向编译，只编译本次改的包）。
  > ⚠️ **不要写 `python3.14 -m 开发工具.契约编译.能力定义编译器`**——该模块**没有 `__main__` 块**，这么跑退出码 0 但什么都不编（静默无效，2026-09-15 实测）。
  > ⚠️ **编译器已不再生成 `验证场景引用.json`**（`生成验证场景引用` 恒返回 None，见 `能力定义编译器.py`）——
  > 场景引用是**包级结构**，由模板直产 + 作者手写维护；`能力数据/`（`能力搜索数据.json`、`Agent查询数据.json`）才是编译派生物。——契约、能力搜索数据、Agent 查询数据、包声明能力清单、完整性摘要都从 `能力定义.json` 生成，**生成物禁手改**。

### 步骤 3：**重算摘要**

跑 `python3.14 -m 开发工具.全量重算摘要`（一次扫遍**全部正式根**，凡「磁盘 ≠ 重算」一律重算——聚合父包登记了子包文件，只算自己那一个包必然漏父包、报「不闭合」）。只想先看差异加 `--只报`。
  > 实测（2026-09-16）：`python3.14 -m 开发工具.全量重算摘要` 输出 `全部闭合：无可重算项`，退出码 0。
  > 旧的 `支持库/后端/组件规范支持库` 的 `生成完整性摘要` 能力 已随目录下沉，**不要再引用该路径**。

### 步骤 4：**验证（定向，不跑全量）**

   - `校验能力定义` → 必须 0 问题；`组件合规` → 全项通过；
   - `python3.14 -m 开发工具.公开调用完整性门禁` → 六环一致无违规；
   - `python3.14 -m 测试中心.开发工具.测试_契约版本唯一` → 版本恒等于唯一版本（实测：`Ran 4 tests … OK`，退出码 0）；
   - `python3.14 开发工具/验证场景体检.py` → 场景引用与场景正文两层判据都过（见坑 6）；
   - 真实功能验证用 HTML 经 `GET/POST` 打已编译产物（并发跑全量请求），看真实状态码与返回值。

## 五、版本与命名铁律

- **契约唯一、组件各自版本**：契约只有一套，契约版本事实源是 `公共契约/版本规则/契约版本.py`；
  而**支持库/模块/能力各自有自己的迭代版本号**（新包从 `1.0.0` 起），按自身迭代展示，不强制与契约版本对齐。
  契约版本由编译器统一注入，包/能力版本取自 `能力定义.json` 自己写的值。
  守卫测试：`python3.14 -m 测试中心.开发工具.测试_契约版本唯一`。
- **版本不对齐不失败**：上游带版本请求时，回报「请求版本 / 当前版本 / 差异原因」；没有强制参数差异就放行，
  只有依赖声明的运算符约束（`>=1.0.0`）、必填参数、契约硬要求不满足才报错。
- **全中文命名**（变量/函数/类/文件/目录/注释/文档），只保留 ID、OCR、LLM 这类人人认识的缩写。
- **不用无实义的序次类汉字和中文数字**当分类/占位名（第 6 条 2 项），用一眼能懂的名字＋阿拉伯数字：示例提供者、循环模块1、契约齐全组。

## 六、常见坑（踩过的）

坑 1：**模板拒绝覆盖**：目标目录或测试文件已存在就整体失败——先清干净再生成，不要手工搬文件绕过。
坑 2：**父包摘要会不闭合**：新建/改动子包后只重算子包，父包（如 `支持库/后端/办公文档支持库`）也要重算，否则全树扫描报不闭合。
坑 3：**说明书与能力定义会漂移**：`说明/使用说明.md` 的生成器与仓内历史文件格式不一致时会拒绝覆盖，改完能力定义后要一并核对说明书错误码表。
坑 4：**漂移检测的判据**：检测器按「无既有契约」重算比对，会把手写保留键（`中文名称`/`名称`/人工调用示例）当成差异；剔掉保留键后比对为 0 属正常，别被红字骗着去改契约。
坑 5：**临时脚本不留库**（第 1 条 6 项）：脚手架、探针脚本用完即删，底座只留干净状态。
坑 6：**模板产的 `验证场景引用.json` 是「合法 v1 空壳」，不是「已能用的场景」**（2026-09-18 校准）：
- 旧描述「模板生成的是编译器已废弃的 3 键旧格式，必须手改成 v1」**已不成立**——两个模板现在都直产
  `{"契约版本": "验证场景/v1", "验证场景引用": []}`，**格式不用改**。
- 但**引用列表为空，`组件合规` 结构场景照样判红**（「验证证据为空（验证场景引用 列表必须非空）」）。
  作者必须补 `验证场景/*.json` 场景正文（严格四键：`场景id`/`前置步骤`/`目标步骤`/`清理步骤`，
  `目标步骤` 至少一步）并在 `验证场景引用.json` 里引用它（形如 `{"场景文件": "验证场景/正向场景.json"}`）。
- 两层判据都要过才算合格：`开发工具.HTML验证.场景加载._解析场景引用`（读引用）**和**
  `_解析多步骤场景`（校验步骤断言）。只跑第一层会得到「0 不合格」的假绿。一律用
  `python3.14 开发工具/验证场景体检.py` 判（判据不复制、不猜，直接调用验证器自己的解析链）。

坑 6b：**★ 场景正文的完整写法（2026-09-18 实测补齐；此前只写「严格四键」，缺的每一条都让我试错一轮）**：

> 补这段的起因：新加两条能力后，我按「严格四键」写完场景，**连续 6 轮**被门禁打回
> （绝对路径 → `$动态` 写法 → 缺成功用例 → 失败用例不算覆盖 → 400…），
> 违反哲学 **3.1**（同一现象两次失败必须停手做原理级调查）与 **3.3**（先补文档再改代码）。
> 根因就是本节缺了下面这些**可执行规则**，只能靠试错发现。**照本节写可一次通过。**

**① 门禁要的不是「有四键」，而是「有成功目标步骤」**（最容易漏的一条）
　HTML 黑盒要求**每个正式公开能力至少有一个真实成功的目标步骤**；
　**只写失败用例（期待 `成功: false`）不算覆盖** —— 它会报
　`缺少真实成功目标场景` / `正式公开能力全集 != 正向目标步骤能力全集: 缺目标=[…]`。
　⇒ 每个新能力**必须有一条会成功的目标步骤**；边界/失败用例是**额外**的，不能替代。

**② 参数里禁止静态绝对路径**（判据真源 `开发工具/HTML验证/路径安全.py`）
　报错形如 `场景 X 禁止静态绝对路径或路径逃逸`。任何形如 `/tmp/x`、`C:\x`、含 `..` 的字面值都不行。
　⇒ 一律改用受管动态路径，且**必须是字典形式**（不是字符串！）：

```json
"参数": { "根目录": { "$动态": "受管临时路径", "相对路径": "集合判据工作区" } }
```

　**★ 这里踩过坑**：写成字符串 `"$动态:受管临时路径.相对路径=X"` 会被判成
　「静态绝对路径」并报**同一个错**，看不出是写法问题。允许的 `$动态` 类型与字段**必须逐字匹配**
　（`允许字段` 在 `路径安全._校验动态声明`）：

| `$动态` 取值 | 必须带的字段 |
| --- | --- |
| `受管临时路径` / `受管临时目录` | `相对路径` |
| `制品根` | `相对路径` |
| `夹具文件复制` | `来源`、`目标` |
| `步骤返回` | `步骤id`（必须是**前序**步骤）、`JSON路径` |
| `环境变量` | `名称` |

　多带一个字段、少带一个字段都会被判「动态值声明不合法」。

**③ 要真造文件就写「前置步骤」**（不能只靠参数指向一个不存在的文件）
　需要判据文件、规则文件这类输入时，用前置步骤真写：

```json
"前置步骤": [
  { "步骤id": "写入判据文件", "能力id": "文件系统支持库.文件操作.写入文件",
    "参数": { "文件路径": { "$动态": "受管临时路径", "相对路径": "集合判据工作区/判据.json" },
              "内容": "{\"判据版本\":\"1.0.0\",…}", "编码": "utf-8" },
    "预期": { "成功": true, "状态码": 200, "返回断言": { "值": true } } }
]
```

**④ 断言写法**（`返回断言` 的等价通道见 `开发工具/HTML验证/单步场景.py`）
　`值类型`（16 个正式类型名之一）/ `必需字段` / `字段类型` / `关键值`（最强）/ `包含`。
　`关键值` 的键是**在返回值里取字段的路径**；**钉值本身必须写 `{"$": 值}`**（`$` = 值本身）。

**⑤ 期望失败用例的写法**：
```json
"预期": { "成功": false, "状态码": 400, "返回断言": { "错误码": "根目录不存在" } }
```

　**★ 状态码不能猜，必须查真源**（我在这里错了 3 轮，是 3.1 违规的直接后果）：
　**错误码 → HTTP 状态码是逐码映射**，真源 = `运行核心/统一网关/本地网关.py` 的
　`公开错误码状态映射`（与 `网关核心.公开错误说明表` 逐码一一对应）。**权威写法是查表**：

```bash
python3.14 -c "
import sys; sys.path.insert(0,'.')
from 运行核心.统一网关.本地网关 import 公开错误码状态映射 as M
print(M.get('你的错误码', '未登记！'))"
```

　全仓既有失败用例的**事实分布**（统计自 `支持库/**/验证场景/*.json`）：
　**400 → 17 个**（绝大多数）/ 200 → 3 个 / 404 → 4 个 / 409 → 4 个。
　**规律**：错误码映射为 400 时，**即使能力内部失败，网关仍返回 400**（不是 200）。
　「能力级失败经网关包成 200」是**错的**（我原先这么写，导致 7 轮 400 != 200）。
　⇒ **默认写 400**，除非该错误码在映射表里明确是别的值（如 `文档不可读` → 404）。

**⑥ 自查**：写完先跑 `python3.14 开发工具/验证场景体检.py`（两层判据都过），
　再 rebuild 制品跑 HTML 黑盒 —— **不要只跑体检就以为通过**（体检过 ≠ 黑盒过，
　黑盒还要求「成功目标步骤覆盖全部公开能力」这一条，体检不判它）。
坑 7：**模板产的三件新文件是「结构和占位」，不是「已验证的结论」**：`复用决策.json` 的
`搜索词`/`候选能力id` 留空是**故意的**（不预置「已查无重复」结论，避免把门禁变成假绿）；
`资源预算.json` 是**保守默认**不是实测；`说明/设计说明.md` 带 `**待填写**` 的位置必须真填。
三件都按第四节步骤 1.5 处理，别当成「模板给了就完事」。

## 七、独立运行的工具/脚本怎么合法调能力（踩过：E未装配）

`获取能力调用器()` **只在已被加载器装配的进程内可用**。用 `python3.14 -c` 或 `python3.14 -B 脚本.py`
直接跑时进程冷启动，调用器状态是「未装配」，直接调用会抛：

```text
公共契约.能力契约.调用器.能力调用器状态异常: [E未装配] 能力调用器状态=未装配:
能力调用器未注入且无惰性装配钩子：模块必须由加载器装配后调用，禁止直接导入支持库/提供者绕过能力调用服务
```

对号入座三种情形，**不要自己造第四条腿**：

| 情形 | 合法做法 |
| --- | --- |
| 包内实现（支持库/模块/技能，运行时已被装配） | 直接 `获取能力调用器().调用能力(能力id, 参数)` —— 唯一合法入口 |
| 独立开发工具/脚本需要真调能力 | 先经 `后端核心` 装配再调；范例：`开发工具/开发入口.py`、`开发工具/统一验证/统一验证器.py`<br>`from 后端核心.后端核心 import 后端核心`<br>`后端 = 后端核心(系统根); 后端.启动()`<br>`结果 = 后端.调用(能力id, 参数)` |
| 模板生成器这类**纯文件工具** | **不调能力**：只写文件，把「校验 / 索引 / 执行」写进返回的「下一步」，由调用方按唯一入口去调（结果唯一即收口，不重复实现别人的逻辑） |

> 本指南是活文档：凡是「照着本指南做、运行却报错」的情况，按 `开发文档/项目说明.md` 第 3 条 3 项
> **先回填本指南、再修代码**，并在本节点名缺口，而不是只改代码了事。

## 八、装配期的单包隔离（架构项A，2026-09-15）

**为什么要写这一节**：以前「一个包半成品」会让**整个平台装配中断**——一个新包写坏一个文件，别人全部停工。
现在装配按**包级隔离**：单个包自己的半成品问题只影响它自己。

### 8.1 只跳过该包（其余包照常装配，写 `跳过包列表` 告警）

| 情形 | 阶段 |
| --- | --- |
| 包声明没有 `入口` 字段 / 入口路径越界 / 入口文件不存在（实现缺失） | 装配前预检 |
| 依赖锁内容为空或非法（`检查依赖锁内容` 报错） | 装配前预检 |
| `能力契约/参数契约.json` 读不出来 | 装配前预检 |
| 入口装配中途报错（含该包实现自己导入失败） | 入口装配 |
| 该包依赖的能力由「已被跳过的包」提供 | 依赖级联 |
| 装配后检查发现该包声明的能力没全部注册 | 装配后检查 |

入口装配失败时会**先卸载该包已注册的能力**再跳过——不留「能力在、结果是半成品」的中间态。

### 8.2 仍整体阻断（fail-closed，不许降级成跳过）

- **跨包真冲突**：两个包抢同一能力 id（重复注册）→ 整体失败并回滚，不留半装配。
- **发现阶段唯一性**：包 id 重复、能力 id 重复。
- **环境依赖硬门禁**：适配层第三方提供者**完全缺少** `依赖锁.json`、提供者环境未就绪。
- 依赖缺失 / 版本冲突 / 多提供者冲突 / 装配锁漂移。

### 8.3 零包底线

若所有包都被跳过（0 个装配成功）→ **判整体失败**（平台一个能力都不可用，这不能算「装配成功只是有告警」）。

### 8.4 怎么确认自己没被跳过（新包自检三步）

1. 改完重编译：`契约编译` + `完整性摘要` 重算（父包也要重算，见坑 2）；
2. 跑一次装配，看返回的 `跳过包列表` **必须为空**（每项格式：`已跳过 <包id>｜<阶段>｜<原因>`；被跳过的包在 `生命周期记录` 里留有回滚留痕）；
3. 经 HTML 黑盒验证器对编译制品发真实 HTTP 请求，看真实返回值——**这才是正式验收**。

> 口径提醒：装配隔离只保证「坏包不连坐」，**不等于**坏包没问题；被跳过的包必须修好，`跳过包列表` 长期非空按缺陷处理。

## 9. 运行态路径必须走唯一解析器（禁止裸拼 `工程缓存`）

**规则**：任何**会在运行时落盘**的目录/文件默认值（状态库、运行数据库、快照根、制品仓库根、签名密钥目录、
证据目录、健康/容量证据文件，统称「运行态路径」）**只有一个合法来源** ——
`公共契约/运行时/运行缓存.py` 的 `解析运行缓存根(...)` / `解析运行数据根(...)`。
**禁止**以下三种写法：

| 禁止写法 | 为什么错 |
|---|---|
| `Path("工程缓存/…")`（裸相对字符串） | 相对 **cwd** 解析；制品进程 cwd = 制品根 → **写进不可变制品** |
| `Path(__file__).resolve().parents[N] / "工程缓存"` | 制品里 `parents[N]` 落到制品内的包层 → 同样写进制品 |
| `os.environ.get("系统底座_工程缓存根", "工程缓存")` | 缺环境变量时回落裸相对 → 制品态仍写进制品 |

**唯一合法写法**：

```python
from 公共契约.运行时.运行缓存 import 解析运行缓存根, 解析运行数据根

根 = 解析运行缓存根(<该文件所属的某层根>)        # 通用运行态
库 = 解析运行数据根(<该层根>) / "xxx.db"          # 运行数据库（＝ 运行缓存根 / 运行数据）
```

**为什么必须**：解析器会 ① 识别制品运行（`系统根.name == "平台客户端"`）并**拒绝**缓存根落在制品内；
② 环境变量 `系统底座_工程缓存根` **显式优先**（发布门禁的受管缓存正是靠它把运行态挪到制品外）；
③ 源码态回落 `<系统根>/工程缓存`，**与旧写法同义**（所以迁移是**零行为变更**，不是行为调整）。

**硬要求**：
- 迁移后**源码侧解析结果必须逐字不变**；
- 验收必须给 **伪制品 + 伪源码双布局真实 import 对照**，证明「修复前制品态真写进制品、修复后落制品外，
  且源码态前后逐字相同」——只给源码态证据**不算验收**。

**2026-09-17 实测教训（这是一类成批缺陷，不是单点）**：同一模式在仓库里有 **11 处**实现落点
（清单与验证见提交 `01d14074`），且真实已安装制品里留下了**两种污染形态**的铁证：
`<制品>/工程缓存/平台控制面/{权威状态.db + 20+ 个证据 json}`、
`<制品>/平台客户端/工程缓存/制品仓库/{平台客户端状态/权威状态.db, 可信仓库校验探测/根私钥.pem}`。
**发现一处必须全仓同类扫描**（`rg '/ *"工程缓存"'` + `rg 'parents\[[0-9]\]'`），不要单点修。

**适用范围边界（防止误判为缺陷，2026-09-17 全仓复查后定）**：
本约束管的是**会在制品内运行**的层（`公共契约` / `运行核心` / `平台控制面` / `支持库` / `模块库` / `启动监督器` / `项目适配层`）。
以下位置的 `系统根 / "工程缓存"` 是**合规**的，**不要当缺陷改**：
- **源码侧工具**：`开发工具/**`（发布门禁、编译器、体检器、说明书生成、轻代码编辑器、工程缓存回收…）与
  `客户端/构建平台客户端.py` —— 它们的 `系统根` 就是**源码根**，解析结果永远在源码树内，与"制品运行"无关；
- **注释与文档**里引用旧写法作为**反例说明**的（如 `平台控制面/统一入口.py` 与
  `平台控制面/包仓库/平台客户端制品.py` 的 docstring）；
- **门禁主动设置** `系统底座_工程缓存根` 环境变量（那是受管缓存的**正确用法**，不是违规回落）。

**2026-09-17 复查结论**：制品运行态根缺陷家族**已清零**——源码面 `rg` 裸相对 / `parents[N]` / env 缺省回落三种模式，
残余全部落在上述边界内（注释与源码侧工具）；**41 个文件已统一走唯一解析器**。

> 同源症状识别：发布门禁 `待验证制品字节不变`（新增 `<制品>/工程缓存/…`）、`制品.摘要绑定`（文件数 +1）、
> 以及「**写进去的登记，后续查不到**」（写方走裸相对、读方走解析器 → 不是同一个库）——三者同根，一并排查。

## 九、说明书治理（生成物类/人工类血统、重生成禁令、口径）

> **结论并入自 2026-09-17 的说明书存量漂移治理底稿**（底稿按「结论并入权威后即删」删除，历史见 Git）。
> **这一节是包级 `说明/使用说明.md` 的唯一规范处**，别处不得复述。

### 9.1 血统判据（机器可判）

```
生成物类：含生成器签名句 ——「权威分工：**调用口径以本文为准**」（由 `开发工具/说明书生成/说明书生成器.py` 固定产出）
人工类：不含该句；两套生成器均不覆盖，按平台现行格式人工维护
混血包          ：同一份文件里既有生成行、也有人工手写段
```
**取证**：`rg -l "调用口径以本文为准" --glob "说明/使用说明.md" | wc -l`（含＝生成物类）。

### 9.2 铁律（三条，都来自实测）

1. **禁止对全部说明书做批量重生成** —— 实测证明是**有损覆盖**：`FFmpeg媒体` 说明书里唯一正确的 `返回字节` 会被生成物抹掉；
   人工类人工资产与混血包手写区会被格式覆盖。
2. **重生成前必须先核白名单**（机器清单落 `开发文档/项目证据/说明书白名单.json`）：白名单是**文件级、不是段落级** ——
   混血包将来重生成**必须先做行级合并**（保手写行、刷生成行）。
3. **两套生成器都不是现存说明书的权威生产者**：`开发工具/说明书生成/` 的输出目录是 `工程缓存/说明书/`（**不是**包内 `说明/`）；
   包内另有 `实现/说明书生成器.py`。**唯一落点必须由调用方显式指定**，否则会产出第二份影子说明书。

### 9.3 三方权威链（吵起来看这条）

```
说明书 = 调用口径权威（给人看）｜契约 = 机器可读副本｜实现 = 最终事实
三方不一致时：以【实现】为准，并同步另两方。
```

### 9.4 判定方法与口径纪律

- **识别人工改写必须实跑生成器 + `difflib` 对账**（不跑生成器识不出「词汇行上的人工改写」）。
- **正式口径**：自查脚本的启发式口径（110/26）**不等于**正式白名单口径（108/28）；
  引用说明书数量/漂移数一律用**正式白名单口径**，不要把脚本的启发式数字写成结论。
- 版本行口径见决策记录 `0020`：**契约未变时「版本行滞后」不算缺陷**。
