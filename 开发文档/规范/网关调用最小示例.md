本文件只说明外部程序如何通过 HTTP 调用支持库和模块。完整参数、返回字段、错误码和资源预算，以 `能力详情` 返回的能力契约为准。

## 地址

```text
http://127.0.0.1:40007
```

网关默认只监听本机回环地址。远程部署时使用实际网关地址和端口，不使用代理端口 `4780`。

## 凭证（每一步都要带，先设一次）

网关默认**要求凭证**：任何请求（含 `GET /健康`）不带凭证头一律返回
`401` + `权限不足 / 访问凭证缺失或无效`（2026-09-16 实测：无凭证 `GET /健康 -> 401`，带凭证 `-> 200`）。

凭证只从受控环境变量 `系统库网关凭证` 加载，不写入 HTML、代码仓库或日志。
**bash 不支持中文变量名**，脚本里必须用 ASCII 中转名；本机默认从 40007 的 launchd plist 读：

```bash
# 本机实测可用（值是 22 位短令牌；不要写进任何会被提交的文件）
TOKEN="$(plutil -extract EnvironmentVariables.系统库网关凭证 raw -o - ~/Library/LaunchAgents/com.huashi.gateway-40007.plist)"
```

下面所有 `curl` 示例都假设已经设好 `$TOKEN`，请求头统一为：

```text
Authorization: Bearer <凭证>
```

## 第一步：读取目录

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"能力目录","参数":{}}'
```

首次只返回支持库、模块库、包名称、简介和能力数量，不加载全部命令正文。目录默认分页，每页 20 个包；返回 `总包数`、`偏移`、`限制`、`下一偏移` 和 `是否完成`，把 `下一偏移` 传回即可继续读取。

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"能力目录","参数":{"偏移":20,"限制":20}}'
```

也可以用 `GET /健康` 检查网关状态（同样要带凭证头：无凭证实测返回 `401`）。

## 第二步：查看包和能力

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \

  -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"包详情","参数":{"包id":"模块库.文档读取"}}'
```


## 第三步：调用能力

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "操作":"调用能力",
    "能力id":"文档读取.结构化读取",
    "参数":{"文件路径":"/tmp/a.md"}
  }'
```

`/网关/调用` 是唯一执行入口；项目不做 `/网关/请求` 兼容。模块和支持库都使用同一套入口，不直接暴露各自端口。

## JavaScript 调用

```js
const response = await fetch("http://127.0.0.1:40007/网关/调用", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer " + token        // 缺这一行一定拿 401（凭证获取同上节）
  },
  body: JSON.stringify({
    操作: "调用能力",
    能力id: "文档读取.结构化读取",

const result = await response.json();
```

```json
  "句柄": null,

  "请求版本": "",

```

## 调用方只需记住的四条兼容口径

规则 1：**多传字段不会失败**：顶层字段、操作参数、能力入参里的**未知字段一律忽略**（网关在边界剔除，不会转给实现）。
   上游先升级、底座后升级都不影响。
规则 2：**只有两类会报错**：**必填参数缺失** 与 **参数类型不符**（错误码 `参数不合法`，错误说明点名字段与期望类型）。
   其余情况都放行。
   - 类型校验按**平台正式类型表**（`公共契约/基础类型/类型表.py`）**等宽执行**，在网关**唯一校验点**做，能力实现里不重复写：
     `文本型` 只收文本，`整数型` 只收整数（`3` 不是 `"3"`，布尔不算整数），`双精度数型` 收 `30.0` 不是 `30`，
     `字节集型` 收 `bytes` / 冻结字节集对象 / base64 文本，`空值型` 只收 `null`。
   - **显式 `null` 不等于「未提供」**：要省略参数就**不要传这个键**，传 `null` 按类型不符拒绝。
   - 参数**声明了平台不认识的类型**时一律 `参数不合法`（fail-closed）：宁可明确报错，也不静默放行成「谁都不校验」。
规则 3：**版本不一致不失败**：请求可带 `请求版本`（旧名 `契约版本` 仍永久可用）；返回里会告诉你
   `请求版本` / `当前版本` / `版本差异`。**只有强制约束（如依赖声明 `>=x.y.z`）不满足才失败**。
规则 4：**信封只增不减**：新增字段只会**追加**，旧的键语义永不变；调用方不用跟着改。

## 调用方实测踩坑（2026-09-16 直播存档压缩实战）

规则 2 已经点明「`双精度数型` 收 `30.0` 不是 `30`」，实战中还踩到下面两个，属于**调用方侧**的坑，不是底座问题：

1. **URL 里的中文路径必须百分号编码**。`POST http://127.0.0.1:40007/网关/调用` 这条路径含中文，`curl` 会自己编码，但 Python `urllib.request.urlopen` **不会**，直接抛
   `'ascii' codec can't encode characters in position 6-7`——看起来像编码/凭证问题，其实是 URL 没编码。
   正确写法：

   ```python
   import urllib.parse
   网关地址 = "http://127.0.0.1:40007/" + urllib.parse.quote("网关/调用")
   ```

   或直接用 `curl`（实测无此问题）。请求体里的中文不需要编码，`Content-Type: application/json` + UTF-8 即可。
   Python 侧同样**必须自己加 `Authorization: Bearer <凭证>` 请求头**（`urlopen` 不会自动带）。

2. **`整数型` 受 int32 上限约束**。传 `4294967296`（2³²）会被判 `参数不合法：… 必须是 整数型`，报错文案指向类型而不指向范围，容易误判成类型写错。
   需要大上限时用 `2147483647`（int32 上限）；`媒体处理.转码` 的 `最大输出字节` 就属此类，存档压缩场景传 214748364 或 2147483647 均可。

3. **长视频处理不要用同步调用**：一场 30 分钟 1080p 转码实测 380 秒，已接近同步调用体验上限。>10 分钟量级的作业按上一节「提交 → 轮询 → 取消」走。

## 长任务：提交 → 轮询 → 取消

超过十几秒的活不要用同步调用硬扛，走网关**任务三操作**（注意这是**网关操作名**，不是能力 id；2026-09-16 实测三者都在 `运行核心/统一网关/网关核心.py` 的允许操作表内）：

```bash
# 提交（当场拿任务id）
curl -X POST http://127.0.0.1:40007/网关/调用 -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"任务提交","能力id":"模块库.直播逐字稿.全自动精校","参数":{"源文件路径":"/abs/a.mp4"},"超时秒":1800}'

# 轮询（状态：等待中/运行中/成功/失败/已取消/超时/崩溃）
curl -X POST http://127.0.0.1:40007/网关/调用 -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"任务查询","参数":{"任务id":"0fbdd772a0784792"}}'

# 取消
curl -X POST http://127.0.0.1:40007/网关/调用 -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"任务取消","参数":{"任务id":"0fbdd772a0784792"}}'
```

任务状态与账本由底座内部维护（运行态落在底座运行库里），**调用方不需要知道底座怎么存、怎么跑**。

## 句柄

首次成功调用由网关生成整数句柄并写入权威状态账本；后续请求只能填入此前返回的整数句柄。句柄不是模块内部对象；释放或沉默超时后账本标记为已失效，再次调用直接返回 `句柄已过期`。

查询句柄状态：

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"资源状态","句柄":428101,"参数":{}}'
```

关闭句柄：

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"资源关闭","句柄":428101,"参数":{}}'
```

`资源续租` 的参数为 `{"句柄":428101,"租约秒":300}`。句柄必须是整数且来自网关返回值；过期、跨项目或跨所有者时，网关明确拒绝。网关只返回生命周期状态，不替代模块业务查询。

## 改完能力后让网关生效：热接入（不重启进程）

改了（新增/变更）包之后**不要重启网关**，发一条 `热接入` 即增量装配：

```bash
curl -X POST http://127.0.0.1:40007/网关/调用 -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"操作":"热接入"}'
```

2026-09-16 实测返回：`{"新增包":0,"变更包":1,"卸载包":0,"成功包":["支持库.后端.媒体处理支持库.FFmpeg媒体（变更）"],"失败包":[],"已注册能力数":625}`，耗时 316.85 毫秒，网关进程未重启。语义与失败回退见 `开发文档/决策记录/0008_能力更新走热接入不重启网关.md`。

## 凭证从哪来（汇总口径）

- 网关侧：只从受控环境变量 `系统库网关凭证` 加载（`运行核心/统一网关/安全/安全边界.py`），缺失即 `401`，fail-closed。
- Agent/客户端侧：MCP 客户端经 `MCP_GATEWAY_TOKEN` 插值注入（`开发工具/薄壳/网关转发.py` 只认这一个环境变量名，缺失返回 `网关凭证缺失` 且不转发）；config 文件里不写明文。
