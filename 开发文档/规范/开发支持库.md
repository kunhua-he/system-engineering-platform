开发本项目，从头到尾要走的节点，按顺序摆成一条线。

**每个节点分两栏写**：

## 二、逐节点展开

### ① 环境自检 ❌

进门先自检，确认这台机器能不能跑本项目。命令一条：

```bash
python3.14 -m 开发工具.环境自检
```

**能用的**：自检本身好使 —— 九大项逐项探，说不支持就真的不支持，不糊弄。

**不能用的**：本机当前**过不了**，两项不支持，同一个根：`支持库/适配层/Swift编译器提供者/依赖锁.json` 里 Python、操作系统、CPU 三个字段是空串。后果是**一个能力都没装配出来（能力数 0）**，按 README「部署」第 3 步的判据 —— **这台机器就是跑不起来**。工作树里 Swift 提供者那一波在途改动留下的尾巴，依赖锁没重建。

实测原文：

```text
项 3 依赖锁一致性   1/34 份与当前环境不一致
        Python: "" → 3.14.4 ｜ 操作系统: "" → macOS ｜ CPU: "" → arm64
项 8 装配冒烟       0.9s 内装配未过：提供者环境校验失败（装配阻断）
        ⇒ 能力数 0：一个能力都没装配出来，不能算能跑；状态「故障」
```

修法是自检自己给的（还没执行）：

```bash
python3.14 -m 开发工具.重建依赖锁 --写入 --全部
```

### ② 开工准备 ❌

正式动手前的第一步，一次调用把该知道的都告诉你：改哪些路径、Git 什么状态、代码地图能不能用、这个任务该守哪些规范、有没有别人正在改同一份文件。返回一个**开工ID**，后面写任务记忆、提交都挂它。

**能用的**（三件）：

- **路径边界校验** —— 传越界的路径当场拒绝，不是悄悄跳过
- **通用纪律** —— 七段（哲学纪律、命令环境、工具姿势、提交纪律、改完必做、效率达标线、派活纪律）无条件返回，取不到就报，不静默省略
- **文件租约实况** —— 查不出来如实说「未查询」，绝不回落成「没人占用」放行

**不能用的**（五件，逐条）：

**第一件：第一次调用必错。** 顶层传了「项目根」，它不往下透传，照样报缺参数；得在 `参数` 里再传一次才行。容易被误判成「这个能力坏了」。

**第二件：工作区指纹永远是空的。** 实现里直接写死 `工作区指纹 = ""`，跳过了调用 —— 而现成的实现就在 `开发工具/发布门禁/发布治理.py` 里躺着（算变更清单 + 每个变更文件的真实字节 sha256）。是真缺陷，不是缺能力。

**第三件：代码地图的「可用」判不了真假。** 它只看 `.codegraph` 目录在不在。而现成的能力（`代码地图提供者.查询项目地图状态`）能告诉你地图什么时候建的、有多少文件、**有多少变更还没同步进去** —— 实测这个数是：新增 7、修改 10、删除 5，**地图确实已经过期了**。所以它报「可用」，实际是过期状态。

**第四件：任务类型匹配不到「调研/审计」。** 字典里只有七类（加新能力、改能力契约、写验证场景、修缺陷、改文档、派活与验收、拆超长文件）。传「调研开工第一步信息完整性」进去，命中零类、拿到零条规范。

**第五件：两个撒谎的地方。** 一是「缺失原子能力」那块是**写死的静态清单**，不现场探测，报的四项现在全部已经不成立（详见下面那张对照表）；二是返回里实际有的四块（`开发流程`、`开发流程提示`、`强规范提示`、`强规范是否截断`）**契约里没声明** —— 漏掉的恰恰是强制四步开发流程。

那四项「缺失」的现场对照：

| 它说缺 | 现场实际 |
|---|---|
| 发布治理.当前工作区指纹 | 实现就在 `开发工具/发布门禁/发布治理.py:108`，只是没登记成能力 |
| 验证证据.读取成功记录 | 就是开工编排自己的私有函数（`开工编排.py:220`），不是「只能自己拼」 |
| 代码地图.查询状态 | **能力早就登记了**：`代码地图提供者.查询项目地图状态` |
| 开工编排.验证计划 | **能力早就登记了**：`测试支持库.验证计划` |

**零项是真缺口。** 撒谎的源头是 `模块库/开工编排/实现/开工编排.py:71` 那个硬编码的 `待补能力清单`，从已经删掉的旧组件抄来的，此后没再动过。

### ③ 开工即占 ✅

真要动文件，就不能只「准备」，得**原子认领**这一批路径 —— 谁先拿到谁先改，任一条件被别人占着就整体不开工，并告诉你被谁占了。同一份文件也能上锁。

**能用的**：整节好使。实测认领一份文件，返回「已开工=真」+ 租约id + 认领数 1。

**不能用的**：无。

### ⑥ 编译口 ⚠

改完任何文件，第一动作就是它：一条命令跑完影响面清单、生成物核对、静态规则全查、定向测试点名。

**能用的**：整节好使，十五项检查项全跑得动，约 28 秒。

**不能用的**：会报两条红，**但都不是你的改动引入的** —— 全指向工作树里在途的 Swift 提供者那波：

- **公开调用完整性** —— Swift 提供者实现侧产生的「签名失败」「编译失败」两个错误码没登记状态映射
- **防回潮·反向破坏** —— 13 个破坏场景通过 12，没拦住的那一条，抛出来的异常正文就是 ① 里那条依赖锁装配阻断

另外两类不会算成红、但要看明白：

- **只报不改的存量**：契约漂移判红 0 条，但存量漏声明 126 条、实现默认值差异 156 条 —— **存量冻结，只减不增**
- **只报告类**：测试伪装门禁（1 处用例断言全是弱断言，可能永远绿）、md 查重（全仓 873 对相似，榜首 0.99 全是同模板同源件，属噪声）

判你自己的改动干不干净，用这个跑法：

```bash
python3.14 -m 开发工具.开发编译口.编译口 --文件 <你改的文件>
```

实测结论：摘要全闭合、契约漂移 0 条、规范漂移 0 条、拒绝手写 md 通过。

### ⑦ 定向测试 ✅

**能用的**：只跑编译口点名的受影响模块，不跑全量。


**不能用的**：无。但要记住「测试体系门禁」那个通过**只限快速级** —— 它明确声明「④ 真跑级未执行，本通过不含任何用例执行结论」，别把它当成用例真的跑过了。

### ⑩ 文档收口 ✅

**能用的**：全项目的 md 只走一个生成器，人改也走它（写草稿 → 生成器校验落盘），不直接写文件。

```bash
# 改正文

# 按类型刷整份

```

**不能用的**：无。实测落盘返回「人工正文经生成器写入」，退出 0。

### ⑪ 提交 ✅

**能用的**：先看全貌（有没有别人的文件），只加自己改的，提交信息带上开工ID。

```bash
git status --short                      # 先看全貌
git add <只加自己改的>                    # 禁 git add -A
git commit -m "<开工ID>: 改了什么/为什么/怎么验的"
```

**不能用的**：无。但切记 `commit` 也要带精确路径 —— 索引是全局共享的，只 add 自己文件却跑不带路径的 commit，会把别人已暂存的文件一起提交（实测复发过两次）。

**不能用的**：无。

## 三、出错往哪查

### 编译口红项

```text
摘要闭合      → 改过包内文件没重算（跑全量重算摘要）
契约漂移      → 契约 ↔ 实现/产物不一致（改契约没重编译，或实现没跟上）
公开调用完整性 → 说明书缺能力段 / 错误码没登记
能力id冻结基线 → 能力id 被改名或删除（只增不改）
验证场景体检   → 场景文件不合格
重复腿与旁路   → 同动作双路径 / 调用腿不唯一 / 技能库绕网关 / 平台判断越界
测试体系门禁   → 测试不可导入 / 零测试 / 未解释跳过
防回潮·反向破坏 → 13 类破坏没被拒绝（判据失效）
参数可用性     → 参数缺失/不可用
规范漂移      → 规范里的路径/命令指向失效
债务清单      → 账目与正文实数不一致（改了正文没刷账）
目录树与命令   → 树块与同包摘要不一致
拒绝手写md    → 本轮改动的 md 没有机器印记
md查重       → 多份 md 字面相似（降噪器，不是裁决器）
```

### 网关/调用失败

```text
非本平台项目根 → 项目根没传/不是目录/缺 AGENTS.md 或 开发文档/项目说明.md
网关凭证缺失   → 环境变量「系统库网关凭证」没设
网关不可达     → 40007 没起（launchctl 看进程）
能力不存在     → 能力id 写错，或写成工具名
参数不合法     → 参数与契约不符（双精度传 30 不传 30.0；缺参/多余参数）
              ❌ 顶层「项目根」不自动透传，须在 参数 里再给一次
提供者不可用   → 环境自检（依赖锁指纹不符 / 模型未配置）
```

**关于「直连 Python 调能力报 `[E未装配]`」—— 这不是缺陷。** 哲学第 7 条明写：执行原子能力的唯一方式就是请求底座拿返回，上层不需要 import 底座内部实现。直连被拒是**刻意的安全边界**，定位问题照走 40007 网关，不要试图给直连开后门。
