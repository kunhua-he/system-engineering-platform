## 二、逐节点

### ① 环境自检 ❌

**它是什么**：进门第一件事，确认这台机器能不能跑本项目。

**怎么走**：`python3.14 -m 开发工具.环境自检`

| ✅ 能用的 | ❌ 不能用的 |
|---|---|
| 自检本身好使 —— 九大项逐项探，说不支持就真不支持 | 本机当前过不了，两项不支持，同一个根：`支持库/适配层/Swift编译器提供者/依赖锁.json` 的 Python、操作系统、CPU 三字段是空串 |
| | 后果：**能力数 0**，一个能力都没装配出来 |
| | 按 README「部署」第 3 步判据 —— **这台机器跑不起来** |
| | 来源：工作树里 Swift 提供者那一波在途改动，依赖锁没重建 |
| | 修法（未执行）：`python3.14 -m 开发工具.重建依赖锁 --写入 --全部` |

### ② 开工准备 ❌

**它是什么**：正式动手前第一步，一次调用给全上下文 + 开工ID。

**怎么走**：`⬛ 开工编排.开工准备`　参数 `{项目根, 任务, 修改路径}`

| ✅ 能用的 | |
|---|---|
| 路径边界校验 | 越界当场拒，不悄悄跳过 |
| 通用纪律 | 七段无条件返回，取不到就报，不静默省略 |
| 文件租约实况 | 查不出就说「未查询」，不回落成「没人占用」放行 |

| ❌ 不能用的 | 坏在哪 | 现场证据 |
|---|---|---|
| 顶层「项目根」不透传 | 第一次调用必错，易误判成「这能力坏了」 | 顶层传了照样 400「缺少必填参数 项目根」 |
| 工作区指纹恒为空 | 实现里写死 `工作区指纹 = ""` 跳过调用 | `开工编排.py:364`；而实现在 `发布治理.py:108` 躺着 |
| 代码地图「可用」判不了真假 | 只看 `.codegraph` 目录在不在 | 实测真状态：待同步变更 = 新增 7／修改 10／删除 5 ⇒ 已过期 |
| 任务类型匹配不到「调研／审计」 | 字典仅七类，传「调研…」进 ⇒ 命中 0 类、0 条规范 | 七类 = 加新能力／改契约／写验证场景／修缺陷／改文档／派活与验收／拆超长文件 |
| 「缺失原子能力」是写死的静态清单 | 非现场探测，报的四项**零项是真缺口** | `开工编排.py:71` 死字面量，抄自已删的旧组件 |
| 19 块里 4 块契约没声明 | 漏掉的恰是强制四步开发流程 | 漏：`开发流程`／`开发流程提示`／`强规范提示`／`强规范是否截断` |

**那四项「缺失」的现场对照**：

| 它说缺 | 现场实际 |
|---|---|
| 发布治理.当前工作区指纹 | 实现就在 `开发工具/发布门禁/发布治理.py:108`，只是没登记成能力 |
| 验证证据.读取成功记录 | 就是开工编排自己的私有函数（`开工编排.py:220`） |
| 代码地图.查询状态 | **能力早就登记了**：`代码地图提供者.查询项目地图状态` |
| 开工编排.验证计划 | **能力早就登记了**：`测试支持库.验证计划` |

### ③ 开工即占 ✅

**它是什么**：真要动文件就得原子认领这批路径，任一被占则整体不开工并回报占用者。同一份文件也能上锁。

**怎么走**：`⬛ 开工编排.开工即占`　参数 `{项目根, 任务, 修改路径, 开工ID}`

| ✅ 能用的 | ❌ 不能用的 |
|---|---|
| 整节好使 —— 实测返回「已开工=真」+ 租约id + 认领数 1 | 无 |

### ④ 动手前先查 ✅

**它是什么**：改代码之前先查有没有现成承载，别重复发明。

| ✅ 能用的 | ❌ 不能用的 |
|---|---|
| 查全仓既有承载（改完代码要重建索引） | 无 |
| 查这个坑踩过没有 | |
| 查哲学条款怎么说的 | |
| 查这条待办修好没有（`▷ 开发工具/派活前核验.py`） | |

### ⑤ 改代码 ✅

**它是什么**：真正动手的三条路。

| ✅ 能用的 | 怎么走 | ❌ 不能用的 |
|---|---|---|
| 建新包 | 走模板生成器，不手搓 | 无 |
| 改契约 | 只编辑 `能力定义.json`（唯一可编辑事实源），派生物由 `▷ 契约编译器` 生成 | |
| 改实现 | 改 `实现/<包名>.py` | |

### ⑥ 编译口 ⚠

**它是什么**：改完任何文件的第一动作 —— 影响面 + 生成物核对 + 静态规则全查 + 定向测试点名，约 28 秒。

**怎么走**：`▷ python3.14 -m 开发工具.开发编译口.编译口 --变更`

| ✅ 能用的 | ❌ 会报的红 | ⚠ 不算红但要看明白 |
|---|---|---|
| 十五项检查全跑得动 | **公开调用完整性**：「签名失败」「编译失败」两错误码未登记状态映射 | 存量冻结（只减不增）：契约漂移判红 0，存量漏声明 126／实现默认值差异 156 |
| 只想查自己的：`--文件 <你改的文件>` ⇒ 摘要全闭合／契约漂移 0／规范漂移 0／拒绝手写通过 | **防回潮·反向破坏**：13 场景过 12，没拦住那条的异常正文 = ①里那条依赖锁装配阻断 | 测试伪装门禁：1 处弱断言（可能永远绿）；md 查重：全仓 873 对相似（噪声） |

> 两条红**都不是你的改动引入的** —— 全指向工作树里在途的 Swift 提供者那波。

### ⑦ 定向测试 ✅

**它是什么**：只跑编译口点名的受影响模块，不跑全量。

**怎么走**：`▷ python3.14 -m unittest 测试中心.<层>.<包>`

| ✅ 能用的 | ❌ 不能用的 |
|---|---|
| 好使 | 无 |
| **要记住**：测试体系门禁的「通过」只限快速级 —— 它自己声明「④ 真跑级未执行，本通过不含任何用例执行结论」 | |

### ⑧ HTML 全量黑盒 ✅

**它是什么**：全项目唯一允许跑「全量」的地方。

**怎么走**：`▷ python3.14 -m 开发工具.HTML验证.验证器 --并发 32`

| ✅ 能用的 | ❌ 不能用的 |
|---|---|
| 对已编译制品发真实 GET/POST，多线程并发；只看 HTTP 状态码和返回值，后端怎么实现它不管 | 无 |

### ⑨ 摘要重算 ✅

**它是什么**：改过包内文件必跑，父包会级联。

**怎么走**：`▷ python3.14 -m 开发工具.全量重算摘要`

| ✅ 能用的 | ❌ 不能用的 |
|---|---|
| 判据是硬口径：**「全部闭合：无可重算项」**，不是「不闭合 1/N 也算过」 | 无 |

### ⑩ 文档收口 ✅

**它是什么**：全项目 md 只走一个生成器，人改也走它。

| ✅ 能用的 | 怎么走 | ❌ 不能用的 |
|---|---|---|
| 改正文 | `▷ … --人工改 --文件 X --正文文件 草稿 --写盘` | 不许直接手写 md 文件 |
| 按类型刷整份 | `▷ … --类型 <类型> --写盘` | |

### ⑪ 提交 ✅

**它是什么**：先看全貌，只加自己改的，提交信息带上开工ID。

| ✅ 能用的 | 怎么走 | ⚠ 要记住 |
|---|---|---|
| 好使 | `▷ git status --short` → `▷ git add <只加自己改的>` → `▷ git commit -m "<开工ID>: …"` | `commit` 也必须带精确路径 —— 索引全局共享，不带路径会把别人已暂存的带进来（复发过两次） |

### ⑫ 收工释放 ✅

**它是什么**：按租约 id 清单释放，让别人能接着改。

**怎么走**：`⬛ 开工编排.收工释放`　参数 `{租约id清单, 原因}`

| ✅ 能用的 | ❌ 不能用的 |
|---|---|
| 返回 释放数／释放清单／幂等清单；实测释放 1 份，状态「已释放」 | 无 |

## 三、编译口红项怎么查

| 红项 | 意思 |
|---|---|
| 摘要闭合 | 改过包内文件没重算 |
| 契约漂移 | 契约 ↔ 实现/产物不一致 |
| 公开调用完整性 | 说明书缺能力段／错误码没登记 |
| 能力id冻结基线 | 能力id 被改名或删除（只增不改） |
| 验证场景体检 | 场景文件不合格 |
| 重复腿与旁路 | 同动作双路径／调用腿不唯一／技能库绕网关／平台判断越界 |
| 测试体系门禁 | 测试不可导入／零测试／未解释跳过 |
| 防回潮·反向破坏 | 13 类破坏没被拒绝（判据失效） |
| 参数可用性 | 参数缺失／不可用 |
| 规范漂移 | 规范里的路径/命令指向失效 |
| 债务清单 | 账目与正文实数不一致 |
| 目录树与命令 | 树块与同包摘要不一致 |
| 拒绝手写md | 本轮改动的 md 没有机器印记 |
| md查重 | 多份 md 字面相似（降噪器，不是裁决器） |

## 四、网关／调用失败怎么查

| 现象 | 意思 |
|---|---|
| 非本平台项目根 | 项目根没传／不是目录／缺 `AGENTS.md` 或 `开发文档/项目说明.md` |
| 网关凭证缺失 | 环境变量「系统库网关凭证」没设 |
| 网关不可达 | 40007 没起 |
| 能力不存在 | 能力id 写错，或写成工具名 |
| 参数不合法 | 与契约不符（双精度传 30 不传 30.0；缺参／多余参数） |
| ↳ 其中一个坑 | ❌ 顶层「项目根」不自动透传，须在 `参数` 里再给一次 |
| 提供者不可用 | 依赖锁指纹不符／模型未配置 |
| ↳ 直连 Python 报 `[E未装配]` | ✅ **不是缺陷** —— 哲学第 7 条刻意的安全边界，照走 40007，别给直连开后门 |
