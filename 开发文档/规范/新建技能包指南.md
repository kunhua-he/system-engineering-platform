## 一、先判断该建什么（分层归属固定，第 2 条 1 项）

| 你要做的东西 | 落到哪 | 判据 |
| --- | --- | --- |
| 最小原子能力（连接池、句柄、重试、编码转换…） | `支持库/后端/<某支持库>/<包名>` | 一个包只做一件事，可被无数模块复用 |
| 把第三方库翻译成中文能力 | `支持库/适配层/<提供者>` | 门面→提供者分层，不算跨模块 |
| 组装能力（多能力组合成一个业务动作） | `模块库/<模块名>` | 只经 `获取能力调用器().调用能力(能力id, 参数)` |
| **固定工作流（先做什么后做什么）** | **技能库（技能包）** | **只组合已有能力，不新增底座能力** |
| 前端描述类 | `支持库/前端/<描述>` | 只描述，不执行 |

两条硬判据（先自问，再动手）：

规则 1：**结果唯一即收口（第 1 条 3 项）**：同一个目的底座**已经有**了能力或技能 → **直接调，不要包装第二个**。
   典型错法：为「读文件 / 写文件 / 编译 / 摘要 / 提交」各写一个技能——这些底座已有原子能力，**直接调能力就完事**。
规则 2：**空转即杀（第 1 条 4 项）**：没有真实结果的技能不许建；验证用例为空 = 拒收。

## 二、技能包六件套（结构固定，缺一件即 `结构不完整`）

| 文件 | 职责 | 谁看得到 |
| --- | --- | --- |
| `SKILL.md` | Agent 读的提示词（说明 + 参数 + 用法 + 验证用例） | Agent |
| `契约.json` | 参数契约：`能力标识/名称/分类/版本/执行入口/路径/参数/返回` | Agent 据此组参，执行器据此校验 |
| `工作流.json` | 步骤：`入口脚本` + `步骤[{步骤,说明}]` | **只给执行器，不返回给 Agent** |
| `依赖.json` | `解释器`（固定解释器）+ `标准库` + `第三方`（应为空）+ `项目模块` | 执行器审计用 |
| `验证声明.json` | `契约版本`（`技能验证/v1`）+ `用例[{说明,参数,预期}]`，**至少 1 条** | 验收与质检 |
| `scripts/<入口脚本>.py` | 桥接脚本：stdin JSON 进，stdout JSON 出 | 沙箱执行 |

## 三、技能根目录与索引（谁传、谁派生）

- **技能根目录由调用方传入**：技能库是通用的，不认识任何具体项目；V3 传自己的 `模块库/Skills`，其他项目传自己的目录。根目录里必须有 `索引.json`。
- **索引只由能力派生**：`技能库.技能索引.生成索引`（`技能根目录` + `写回索引`）扫各技能 `契约.json` → 写回 `索引.json`。
  **生成器不写索引**（不重复实现别人的逻辑）；批量生成完**统一调一次**，不要每生成一个就扫一遍。
- **解析技能包按索引白名单**：索引里没有的标识 → `技能未找到`；索引与契约不一致 → 拒收。所以改完契约必须重跑 `生成索引`。

## 五、生成之后必须做的四件事

步骤 1：**填实现**：替换 `scripts/<入口脚本>.py` 里 `主流程()` 的占位回执，写真实逻辑。
   失败要在 stdout 打 `{"成功": false, "错误码": "...", "错误说明": "..."}`，不要静默。
步骤 2：**对齐用例**：`验证声明.json` 的 `预期` 必须与真实返回**逐键一致**（照实测形状写，不许照印象写）。
步骤 3：**结构校验**：调 `技能库.技能包.校验技能包`（`技能根目录` + `技能标识或路径`）→ `值.通过 == true`。
步骤 4：**真实验收（不跑不算完）**：调 `技能库.受控执行.运行技能包` 真跑一次，看真实返回；再调 `技能库.技能索引.生成索引` 写回索引。

```bash
unset PYTHONPATH
python3.14 -c "
import sys; sys.path.insert(0, '.')
from 后端核心.后端核心 import 后端核心
from pathlib import Path
后端 = 后端核心(Path('.').resolve())
装 = 后端.启动()
快照 = 后端.状态快照()
问题 = []
if not 装.成功: 问题.append('装配失败（' + str(装.错误码) + '）：' + str(装.错误说明))
if 快照['能力数'] <= 0: 问题.append('能力数为 ' + str(快照['能力数']) + '：一个能力都没装配出来')
if 快照['装配跳过包']: 问题.append('有 ' + str(len(快照['装配跳过包'])) + ' 个包被跳过：' + '；'.join(快照['装配跳过包']))
print('[装配冒烟] 状态=' + str(快照['状态']) + ' 能力数=' + str(快照['能力数']) + ' 跳过包=' + str(len(快照['装配跳过包'])))
if 问题:
    for 项 in 问题:
        print('[装配冒烟] 失败：' + 项, file=sys.stderr)
    sys.exit(1)
print('[装配冒烟] 通过：装配成功、能力数 > 0、无跳过包')
根 = '<技能根绝对路径>'
print(后端.调用('技能库.技能包.校验技能包', {'技能根目录': 根, '技能标识或路径': '示例.文本统计'}).值)
print(后端.调用('技能库.受控执行.运行技能包', {'技能根目录': 根, '能力标识': '示例.文本统计', '参数': {'文本': '测试'}}).值)

"
```

块首 8 行是**真断言**：`结果.成功` 为假、`能力数 <= 0`、`装配跳过包` 非空，任一即把原因逐条打到 stderr 并以 **exit 1** 结束；旧写法是启动结果直接打印、不看退出码——装配整体失败或有包被跳过时照样打印并返回 0，会让人误判成装配成功（同款冒烟见 README「部署」第 3 步）。

**真实返回形状（实测，别照印象写断言）**：

- `校验技能包` → `值 = {通过, 技能目录, 来源, 缺失}`
- `运行技能包`（两种情况，2026-09-15 现场实测，别照印象写断言）：
  - **运行级失败**（技能未找到 / 结构不完整 / 审计未通过 / 注入失败 / 超时 / 输出超限 / 脚本非零退出 / 输出格式错误）→
    信封 `成功 = false`，看 `错误码`、`错误说明`、`详细信息`（审计失败时 `详细信息.违规` 逐条给出违规）。
  - **脚本正常退出（码 0）且 stdout 是 JSON 对象** → 信封 `成功 = true`，`值 = {<脚本 stdout 的键…>, 耗时秒}`
    —— 脚本 stdout 的键是**直接展开**在 `值` 里的，不再多套一层；平台还会**剔除脚本自己的 `成功` 键**，
    所以 `值.成功` 不存在。脚本自报失败时信封仍然是 `成功 = true`，**真实成败看 `值.错误码`（非空即脚本侧失败）**。
  - 实测样例：示范技能 stdout 打 `{"字符数": 7, "词数": 2}` → `值 = {"字符数": 7, "词数": 2, "耗时秒": 0.03}`；
    自报失败脚本 stdout 打 `{"成功": false, "错误码": "夹具自报失败", "错误说明": "…"}` →
    `值 = {"错误码": "夹具自报失败", "错误说明": "…", "耗时秒": 0.026}`（信封 `成功 = true`）。
- `生成索引` → `值 = {数量, 能力列表, 跳过}`

## 六、合法调用方式（踩过：`E未装配`）

`获取能力调用器()` **只在已被加载器装配的进程内可用**；`python3.14 -c` 冷启动直接调会抛
`[E未装配] 能力调用器未注入且无惰性装配钩子`。对号入座：

| 情形 | 合法做法 |
| --- | --- |
| 技能脚本内部要用底座能力 | **默认不行——技能脚本只能纯标准库**：实测 `技能库/后端/技能库/实现/技能库.py:336-348` `_审计导入` 的分支顺序是「硬禁止 → 调用方 `禁止导入前缀` → 其余非标准库一律拦截」，所以**任何非标准库导入都会被拦**，`禁止导入前缀` 只是换个报错文案。要用底座能力只有两条路：①（推荐）由**调用方**执行完把结果当参数传进技能；②调用方显式传 `可调能力白名单`，脚本经注入的合成模块 `技能底座能力` 走唯一网关调用白名单内的能力（见第七章） |
| 独立工具/脚本要真调能力 | 经 `后端核心` 装配：`后端核心(系统根).启动()` → `后端.调用(能力id, 参数)` |
| 纯文件工具（如模板生成器） | **不调能力**，把调用步骤写进返回的「下一步」 |

## 七、技能脚本要用底座能力：`可调能力白名单`（2026-09-15 新增）

默认（不传 `可调能力白名单`，或传空列表 `[]`）技能脚本**只能纯标准库**，行为与历史版本完全一致。
确需让脚本自己取底座数据时，由**调用方**在白名单里显式授权，脚本经平台注入的合成模块
`技能底座能力` 走**唯一网关**（`POST http://127.0.0.1:40007/网关/调用`，操作=调用能力）真实调用：

| 项 | 口径 |
| --- | --- |
| 入口参数 | `运行技能包` 的 `可调能力白名单`（列表型，可选，默认 `null`），元素是**真实存在的能力 id**（先 `python3.14 开发工具/能力搜索/能力搜索器.py --能力 <词>` 确认） |
| 默认行为 | 空 = 只能标准库。脚本 `from 技能底座能力 import …` 会被拦：`脚本审计未通过`，`详细信息.违规 = ["禁止导入非标准库模块: 技能底座能力"]` |
| 注入物 | 平台把合成模块 `技能底座能力` 写进临时目录（`技能底座能力注入-*`，跑完即删）→ 进子进程 `PYTHONPATH` 首位 → **只对这 1 个模块名放行导入** |
| 脚本写法 | `from 技能底座能力 import 调用底座能力, 查询白名单` → `调用底座能力(能力id, 参数, 超时秒=None)` |
| 调用返回 | `{"成功","值","错误码","错误说明","状态码","请求id"}`；`状态码` = 网关 HTTP 状态码，`请求id` = 网关信封请求 id，`0` = 本地就拒了、**没发 HTTP** |
| 越权 | 白名单外的能力 id 一律 `能力不在白名单`，不发 HTTP、不降级 |
| 凭证 | 只读环境变量 `系统库网关凭证`（不写代码、不回传、不打日志）；白名单非空但进程环境里没有它 → 启动脚本前就 `能力调用凭证缺失` |
| 网关地址 | 默认 `http://127.0.0.1:40007`，可用环境变量 `技能库_网关地址` 覆盖（只支持 `http://主机:端口`） |
| 刻意不放 | 第三方库（`requests` → `禁止导入模块`）、命令执行与进程派生（`os.system` → `禁止调用`）、项目模块导入与调用方 `禁止导入前缀`（→ `禁止导入项目模块`） |

**错误码三层**（哪一层报错就在哪一层看）：

1. **平台信封**（`运行技能包` 的 `错误码`）：`参数不合法 / 目录不存在 / 技能未找到 / 结构不完整 / 工作流无效 /
   缺少入口脚本 / 脚本路径逃逸 / 脚本读取失败 / 脚本审计未通过 / 非法环境变量 / 启动失败 / 超时 /
   输出超限 / 脚本非零退出 / 输出格式错误 / 脚本执行失败 / 能力调用凭证缺失`。
2. **合成模块**（脚本内 `调用底座能力` 返回里的 `错误码`，随脚本回执出现在 `值` 里）：`能力id不合法 /
   能力不在白名单 / 网关凭证缺失 / 网关凭证非ASCII / 网关不可达 / 网关地址不合法 / 网关返回格式错误`。
3. **网关信封**（原样透传）：`权限不足`（凭证缺失/不对）、`参数不合法`、`能力不存在`（运行态注册表没有该 id）、`超时` 等。

## 八、受控执行的安全边界（全部 fail-closed）

| 边界 | 做法 |
| --- | --- |
| 解释器 | 固定为本进程解释器，调用方不能指定命令或解释器 |
| 参数/返回 | stdin JSON 进，stdout JSON 出 |
| 超时 | 超时后 `killpg` 连孙进程一并回收 |
| 输出 | stdout 超上限立即终止 → `输出超限` |
| 环境 | 只透传白名单（`PATH/LANG/LC_ALL/HOME/USER/TMPDIR/TZ/PYTHONUTF8/PYTHONDONTWRITEBYTECODE`），传白名单外变量直接拒绝 |
| 路径 | 技能目录、入口脚本、工作目录必须在技能根目录内 |
| 资源 | `RLIMIT_CPU` / `RLIMIT_FSIZE` |
| 导入审计 | AST 静态审计：禁 `shell=True`、`eval/exec/compile`、`__import__/importlib`、`subprocess/os` 命令执行、第三方库 → `脚本审计未通过` |
| 可调能力白名单 | 默认空（只能标准库）；非空时只放行平台注入的合成模块 `技能底座能力`，**其他非标准库导入仍一律拦截**；白名单外能力 id 拒绝；不放第三方、不放进程派生、不放项目模块 |

`运行技能包` 错误码全表（信封层）：`参数不合法 / 目录不存在 / 技能未找到 / 结构不完整 / 工作流无效 /
缺少入口脚本 / 脚本路径逃逸 / 脚本读取失败 / 脚本审计未通过 / 非法环境变量 / 启动失败 /
超时 / 输出超限 / 脚本非零退出 / 输出格式错误 / 脚本执行失败 / 能力调用凭证缺失`

## 九、铁律与常见坑

条目 1：**技能不新增底座能力**：技能只做「工作流组合」，原子逻辑属于支持库；能直接调能力就**不要包装技能**。
条目 2：**验证用例不许空转**：没有用例 = 拒绝生成；用例必须有真实 `预期`，且与实测返回一致。
条目 3：**依赖只留标准库**：技能脚本按设计只依赖标准库（第三方库不属于技能）；确需底座能力时**唯一入口**是
   调用方传 `可调能力白名单` + 注入的合成模块 `技能底座能力`（第七章），**禁止每个技能包各自复刻一套
   底座能力判定/HTTP 调用代码**（那等于第二套底座实现）。
条目 4：**改契约必须重跑索引**：否则索引与契约不一致 → `技能未找到`。
条目 5：**临时脚本不留库**（第 1 条 6 项）：探针、一次性搬迁脚本用完即删，只留正式代码与权威文档。
条目 6：**全中文命名**，禁用无实义的序次类汉字与中文数字当分类/占位名（第 6 条 2 项）。
条目 7：**报错必须回填文档**（第 3 条 3 项，一次命中）：凡是「照本指南做、运行却报错」，
   先判定本指南哪一段没写清（缺段落 / 缺真实返回结构 / 只有结论没步骤），**补完本指南再修代码**。
