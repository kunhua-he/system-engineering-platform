## 一、两个运行槽（唯一权威定义）

**腿只有一条**（哲学 1.2）：一个源码主干、一套核心、一条发布管线。
**槽有两个**，区别只在「跑什么代码」，不在「跑哪套逻辑」。

| | 开发槽（dev） | 稳定槽（stable） |
|---|---|---|
| 跑什么 | 源码工作区（可变、可崩） | 激活指针指向的**不可变制品** |
| 端口 | `系统底座_网关端口=其他值`（**永不占 40007**） | **固定 40007** |
| 缓存/数据 | `系统底座_工程缓存根=<受管临时路径>` | `系统底座_工程缓存根=<正式缓存根>` |
| 谁能改 | 开发者随时改源码 | 只有「发布 → 激活」能原子切换 |
| 谁在用 | 开发/调试/验证 | **在线服务与调用方（V3、HTML 验证器等）** |

**铁律**：
1. **40007 永远跑激活制品**（切换执行方案见 `方案/稳定槽切换执行方案_20260918.md`）。
2. **开发只在开发槽**：改源码要生效，必须走「发布 → 门禁 → 激活」，不许直接重启 40007 让源码生效。
3. 切换不停机：停收新请求 → 有界排空 → 整组回收常驻提供者 → 原子切指针 → 起新件 → `/就绪` 通过才放流量。

## 二、开发槽正确启动方式（**不加第二条腿**）

入口**只有一个**：`运行核心/启动运行核心网关.py`。它通过环境变量参数化，**不新增脚本、不新增装配路径**。

```bash
# 开发槽示例（独立端口 + 独立缓存根，绝不碰 40007 与正式数据）
unset PYTHONPATH
cd <工程根>
系统底座_网关端口=48001 \
系统底座_工程缓存根=<受管临时路径> \
系统底座_提供者环境根=<受管临时路径> \
系统库网关凭证=<本地凭据> \
/opt/homebrew/bin/python3.14 -u 运行核心/启动运行核心网关.py
```

**★ 实测（2026-09-18）**：热缓存根 3 秒起来、装配 **686 个能力**；真实 `POST /网关/调用` 成功；
SIGTERM 整组回收后端口无残留、进程数回基线、40007 未受任何影响。

**回滚/回收**：必须**按进程组**回收（`killpg`），不得按端口盲杀（哲学见「资源回收确认机制」）。

## 三、环境变量总表（实测盘点，28 项）

### 3.1 控制运行槽与路径（★ 最常用）

| 变量 | 作用 | 缺省 |
|---|---|---|
| `系统底座_网关端口` | 网关监听端口 | `40007` |
| `系统底座_工程缓存根` | **运行缓存根显式覆盖**（必须是绝对路径；制品运行时拒绝指回制品内部） | 制品态 → `~/Library/Caches/系统工程平台/运行缓存`；源码态 → `<工程根>/工程缓存` |
| `系统底座_提供者环境根` | 提供者（模型等）环境根 | 同上语义 |
| `系统库网关凭证` | 网关调用凭证（**只从环境变量读，不打印、不落盘**） | 无（缺失即 `网关凭证缺失`） |

### 3.2 分域目录覆盖（默认都在运行缓存根下）

`系统库事务目录` / `系统库仓库目录` / `系统库任务目录` / `系统库审计目录` /

## 四、★ 安全边界：哪些变量**不得**自动放开

按决策 0045，以下属**绝不自适应**类，任何硬件画像/档位都不许改写：
**监听地址**（当前硬编码 `127.0.0.1`，不可从环境变量覆盖）、
鉴权开关与凭证、TLS、租户隔离与权限范围、允许路径表/沙箱边界、
数据目录/激活指针、**部署槽 Profile**、是否启用对外服务。

**反向测试**：喂入「多网卡 / 大内存 / 类服务器画像」，断言系统**仍然只监听回环、仍然要求鉴权**。

## 五、维护规则

1. **新增环境变量必须同时改本表**（本表是唯一总表；散落各文档的说明不构成事实源）。
2. 变量命名统一 `系统底座_` / `系统库_` 前缀，全中文。
3. 读取一律 `os.environ.get`，**禁止**裸相对路径回落（见 `新建支持库与模块指南.md` 坑表）。
