### ② 开工准备 ❌

**这个节点干嘛的**：正式动手前的第一步。一次调用把该知道的都告诉你 —— 改哪些路径、Git 什么状态、代码地图能不能用、这个任务该守哪些规范、有没有别人正在改同一份文件。返回一个**开工ID**，后面写任务记忆、提交都挂它。

**能用的（三件）**：

- **路径边界校验** —— 传越界的路径当场拒绝，不是悄悄跳过
- **通用纪律** —— 七段（哲学纪律、命令环境、工具姿势、提交纪律、改完必做、效率达标线、派活纪律）无条件返回，取不到就报，不静默省略
- **文件租约实况** —— 查不出来如实说「未查询」，绝不回落成「没人占用」放行

**不能用的（五件）**：

**第一件：第一次调用必错。** 顶层传了「项目根」，它不往下透传，照样报缺参数；得在 `参数` 里再传一次才行。容易被误判成「这个能力坏了」。

**第二件：工作区指纹永远是空的。** 实现里直接写死 `工作区指纹 = ""`，跳过了调用 —— 而现成的实现就在 `开发工具/发布门禁/发布治理.py` 里躺着（算变更清单 + 每个变更文件的真实字节 sha256）。是真缺陷，不是缺能力。

**第三件：代码地图的「可用」判不了真假。** 它只看 `.codegraph` 目录在不在。而现成的能力能告诉你地图什么时候建的、有多少文件、**有多少变更还没同步进去** —— 实测这个数是：新增 7、修改 10、删除 5，**地图确实已经过期了**。所以它报「可用」，实际是过期状态。

**第四件：任务类型匹配不到「调研/审计」。** 字典里只有七类（加新能力、改能力契约、写验证场景、修缺陷、改文档、派活与验收、拆超长文件）。传「调研开工第一步信息完整性」进去，命中零类、拿到零条规范。

**第五件：两个撒谎的地方。** 一是「缺失原子能力」那块是**写死的静态清单**，不现场探测，报的四项现在全部已经不成立（见下表）；二是返回里实际有的四块（`开发流程`、`开发流程提示`、`强规范提示`、`强规范是否截断`）**契约里没声明** —— 漏掉的恰恰是强制四步开发流程。

那四项「缺失」的现场对照：

| 它说缺 | 现场实际 |
|---|---|
| 发布治理.当前工作区指纹 | 实现就在 `开发工具/发布门禁/发布治理.py:108`，只是没登记成能力 |
| 验证证据.读取成功记录 | 就是开工编排自己的私有函数（`开工编排.py:220`），不是「只能自己拼」 |
| 代码地图.查询状态 | **能力早就登记了**：`代码地图提供者.查询项目地图状态` |
| 开工编排.验证计划 | **能力早就登记了**：`测试支持库.验证计划` |

**实测复核：4 项里 2 项已有对外能力入口**（`代码地图提供者.查询项目地图状态`、`测试支持库.验证计划`，经能力详细均返回存在），
另 2 项（`发布治理.当前工作区指纹`、`验证证据.读取成功记录`）仍无对外能力入口。
即：清单既不是「全真缺口」，也不是「已全部修好」—— 它是**静态字面量**，与现场无关。
撒谎的源头是 `模块库/开工编排/实现/开工编排.py:71` 那个硬编码的 `待补能力清单`，从已经删掉的旧组件抄来的，此后没再动过。

### ⑥ 编译口 ⚠

**这个节点干嘛的**：改完任何文件，第一动作就是它 —— 一条命令跑完影响面清单、生成物核对、静态规则全查、定向测试点名。**实测：单项耗时合计约 40 秒**（大头是 md查重 13.9s + 参数可用性 6.7s + 重复腿与旁路 5.8s + 测试体系门禁 5.8s）。

**能用的**：十五项检查项全跑得动。

- **公开调用完整性** —— Swift 提供者实现侧产生的「签名失败」「编译失败」两个错误码没登记状态映射

另外两类不会算成红、但要看明白：**只报不改的存量**（契约漂移判红 0 条，但存量漏声明 126 条、实现默认值差异 156 条 —— 存量冻结，只减不增）；**只报告类**（测试伪装门禁 1 处弱断言、md 查重 —— 后者是**降噪器不是裁决器**：报的是字面相似候选，同义改写查不出来、同模板不同内容会报高相似，该不该合并由人看一眼决定）。

**能用的**：判据是硬口径 —— **「全部闭合：无可重算项」**，不是「不闭合 1/N 也算过」。

调 '{"操作":"调用能力","能力id":"系统核心支持库.进程管理.执行命令",

### ⑪ 提交 ✅

**这个节点干嘛的**：先看全貌，只加自己改的，提交信息带上开工ID。

**能用的**：好使。

**要记住的**：`commit` 也必须带精确路径 —— 索引是全局共享的，只 add 自己文件却跑不带路径的 commit，会把别人已暂存的文件一起提交（实测复发过两次）。

```bash
▷ git status --short                      # 先看全貌
▷ git add <只加自己改的>                    # 禁 git add -A（全文见 开发文档/规范/多会话并行开发规约.md 第九节）
▷ git commit -m "<开工ID>: 改了什么/为什么/怎么验的"
```

### ⑫ 收工释放 ✅

**能用的**：返回释放数、释放清单、幂等清单。实测释放一份，状态「已释放」。

**不能用的**：无。
