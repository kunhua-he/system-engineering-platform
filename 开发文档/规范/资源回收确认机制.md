## 一、设计

```
启动 → 状态机创建句柄 → 登记资源（PID/端口/连接/文件）绑定到句柄
  ↓
运行中 → 状态机监控（超时检测/探活）→ 超时/释放/进程暴毙
  ↓
失效 → 状态机统一核查回收所有绑定资源（killpg 进程树+端口清理+文件删除+连接关闭）
  ↓
幂等：重复核查不报错，资源已回收的标记已回收
```

## 二、落地位置

- 状态机实现：`公共契约/句柄体系.py` 的 `句柄体系` 类
- 内置方法：`登记资源()`、`查询资源()`、`核查回收()`（失效时自动调用）
- 连接器接入：`注册本地进程()` 登记资源到句柄
- 不新建独立支持库

## 三、验证

- 登记资源 → 失效 → 自动核查回收 → 进程已杀/端口已清/文件已删
- 重复失效/核查 → 幂等

## 四、版本

- v1.0.0（句柄体系内置，无独立库）
- 所有会启动句柄的模块/支持库 → 登记资源到状态机

## 五、当前实现边界

- `公共契约/句柄体系.py`负责内存句柄状态和绑定资源的核查回收；`运行核心/资源协调/句柄服务.py`负责权威SQLite账本、租约和跨实例恢复，两者是状态与持久化分工，不是两套回收算法。
- 异常回收和失效顺序已由资源句柄回归测试覆盖；本专题不重复维护债务状态。
