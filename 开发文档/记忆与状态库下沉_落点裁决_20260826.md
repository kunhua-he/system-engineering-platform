# 记忆与状态库下沉 · 落点裁决（2026-08-26 华哥口径）

> 华哥裁决：记忆支持库独立，跟 LLM 没关系。记忆本质是链接数据库的原子能力，
> LLM 只是调用记忆的上游，并非与 LLM 完全关联。
> 状态机是系统核心本质独立。每个地方先调研出落点再执行。

## 一、记忆支持库（独立）

- **落点**：`记忆支持库`（独立支持库，与 6 大聚合库平级）
- **来源**：V3 `数据存储/记忆工具.py`（645 行）+ `记忆迁移.py`（58 行）
- **本质**：链接 SQLite 数据库的原子能力（写入/搜索/最近/删除记忆）
- **LLM 关系**：LLM（大语言模型支持库）只是记忆的**上游调用者**，不归属 LLM
- **能力**：记忆写入/追加/计划/完成/删除/搜索/最近/列出 + 向量检索
- **依赖**：向量生成调 `大语言模型支持库.模型连接器.生成嵌入`（上游调用，非归属）
- **存储**：SQLite `工程缓存/记忆库.db`

## 二、项目状态库拆解（V3 一个文件混了 3 类）

V3 `数据存储/项目状态库.py`（676 行）实际是 3 类能力的混合，拆开落点：

| 表 | 本质 | 落点 |
|---|---|---|
| 项目记忆 / 记忆向量 | 记忆 | → 记忆支持库 |
| 开工任务 / 授权租约 / 文件占用 / 反馈 / 观测 / 工具调用 / 高风险操作 / 验证 / 交付 / 环境指纹 | 项目工作台运行状态 | → 系统核心支持库 |
| 文件身份 / 文件操作 / 文件事务 / 文件访问事件 / 文件账本基线 | 文件账本（CAS/污染检测） | → 文件系统支持库 |
| 契约迁移 / 测试身份 / 验证证据 / 依赖边 | 契约/测试治理 | → 系统核心支持库 |

## 三、状态机 vs 状态库

- **状态机**：句柄体系（系统核心支持库），管理资源生命周期 —— 已存在，本质系统核心 ✅
- **状态库**：V3 的 SQLite 项目状态（非状态机），拆解后分别归入记忆/系统核心/文件系统

## 四、下沉原则（华哥口径重申）

- 每个地方**先调研出落点**再执行
- 落点确定：底座已有 → 复用；底座没有 → 新建支持库/模块
- V3 改造：内部实现下沉底座 → V3 经 HTTP 网关访问 → 代码量减少、稳定性更高
- 唯一值铁律：所有支持库/功能/代码内部实现都唯一，不重复
