### 一.2 并行维修期禁止 `git add -A`（来自一次真实污染）

> **教训**：主会话用 `git add -A` 提交时，**子代理的反向验证正在跑**，其**刻意写入的变异值**
> 连同正常产出一起被提交进 HEAD。**代价：一次假红被短暂固化成「已验」状态 + 一路子代理中断本业。**
>
> **判据（此后一律照做）**：
> ① **提交一律用精确路径 `git add <文件>…`，禁用 `git add -A` / `git add .`**（并行维修期尤其）；
> ② 提交前 `git status --short` 核对清单 —— **出现不属于本次任务的条目就停手**，先问清来源；
> ③ **反向验证期间变异值就在工作区**，父会话此时提交 = **把假红固化成「已验」**。
>    正确姿势：**等子代理报「已还原」再提交**，或提交前 `git diff --cached` 逐文件确认无
>    `篡改` / `反向样本` / `临时` 字样；
> ④ **共享制品仓库在并行期也会竞态** —— 并行期**构建与黑盒验证应串行**，或各用独立制品目录。
