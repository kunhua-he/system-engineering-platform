### 发布门禁假红修正：`平台-提供者真实调用`（提交 `dc448f17`）

**根因（实测复现）**：不是值不同，是**包了一层**。

```
直接调用 → 值 = {"操作表": [...12 项], "数量": 12}
经提供者 → 值 = {"能力id": "门禁.真实能力", "值": {"操作表": [...], "数量": 12}}   ← 内层逐字节相同
```

**定性**：`平台控制面/提供者/注册表/能力定义.json` 明确声明该能力是**结果型（能力id、值）**——
「值：目标能力真实返回值」。所以**提供者按契约多包一层是对的**，是**门禁的断言比错了对象**
（拿「包装」比「裸值」，恒不相等）→ 假红。

**改法（不是放宽，是比对了对象且更强）**：按契约比两件事实 ——
① 包装内的目标值必须与直接调用**逐字相等**；② 包装的 `能力id` 必须是本次提供者 id。
**反向验证两条**：篡改包装内 `数量=999999` → 判假；把包装 `能力id` 写错 → 判假。
**同类断言已 grep 全仓**：仅此一处；`测试中心/测试_工作包01_普通用户视图.py:87` 的 `结果["结果"] == 42`
是**视图层**契约（`{成功,结果,错误码,处理建议}`），与提供者层的「结果型（能力id、值）」不同层不同契约，不需改。

### 溯源纠正：`HTML契约真实执行矩阵` 的「FFmpeg/Git 缺目标」是下游派生，不是真缺口
