## 一、可行性判定

**结论：`构建平台客户端制品` 作为 `包仓库` 能力「不成立」；本项能落地的正确形态是「3 条激活指针修复能力进 `包仓库` + 构建本体留在 `客户端/` CLI」。**

### 1.1 三条硬约束（实测）

1. **依赖方向不允许。** 构建逻辑必须调 `开发工具.项目编译.项目编译器`（`客户端/构建平台客户端.py:411` `生成可运行制品壳`、`:458` `生成来源元数据`）；而
   `允许依赖表["平台控制面"] = {公共契约, 支持库, 运行核心}`（`运行核心/依赖防火墙.py:89`）。实测：

   ```
   $ python3.14 -c "from 运行核心.依赖防火墙 import 审计依赖, 允许依赖表, 审计结果转清单; ..."
   审计文件数: 674 违规数: 0
   平台控制面 允许依赖: ['公共契约', '支持库', '运行核心']
   含 开发工具 作目标层的层: ['其他']
   ```

   把构建实现放进 `平台控制面/包仓库` 会产生**全仓第 1 条越层违规**；补 `允许依赖表` 又直接推翻裁决 H-6（`未完成事项.md:294`「不补表、走补能力面」）。

2. **目标层不可达。** 实测 `含 客户端 作目标层的层: []` —— 没有任何层的 `允许依赖表` 把 `客户端` 当目标层；且 `客户端/` 不在 `正式根名表`（`公共契约/正式根.py:23` 仅 `支持库/模块库/技能库/平台控制面/运行核心`）→ 在 `客户端/` 写 `包声明.json` 同样不被装配发现（与 C-5 对 `项目适配层` 的结论同构）。结论：在 `客户端/` 建包**既发现不了、也没人 import 得到**。

3. **语义越界。** `包仓库` 自述边界是「制品/候选包/可信仓库/生命周期这些仓库治理动作」（`平台控制面/包仓库/包声明.json:6`）；AST 前缀重写 + 制品壳生成 + 来源指纹属**发布流程编排**，不是仓库治理。

### 1.2 成立的形态（推荐）

`平台客户端制品接入` 上已有三个**公开方法**却**无能力面**（实测 `rg "诊断激活指针|重建激活指针|重置激活指针" --glob "**/能力定义.json"` → **0 命中**）：

| 方法 | 现场位置 |
|---|---|
| `诊断激活指针` | `平台控制面/包仓库/平台客户端制品.py:477-547`（返回 9 键诊断字典） |
| `重建激活指针` | `同文件:560-587` |
| `重置激活指针` | `同文件:589-613` |

这三条只依赖同包实现、零跨层，正是 D-17 ②「陈旧指针没有出口」缺的**调用面**；构建本体进不了能力面。

### 1.3 备选落点（不推荐）

能力 id 归 `包仓库`，实现用**子进程**按路径调 `客户端/构建平台客户端.py`（import 边为 0，防火墙不报）。代价：治理层反向耦合构建机脚本、能力契约必须声明「修改输入=true / 幂等=false / 取消=不支持」，单次调用写 4 处目录且耗时远超能力调用预算。**不推荐**，如需保留请华哥单独裁决。

### 4.2 是否会动激活指针

- **不带 `--安装`：不动激活指针，但会改写 `平台客户端制品/当前.json`**（`:575-589` 无开关）→ 构建**不是只读操作**。
- 带 `--安装`：经 `安装到环境` → `_写指针文件:463` 原子写 `环境/当前.json`，并经 `发布管理.激活`（CAS，版本/栅栏令牌 +1）。
- 现场实测**两个指针已经发散**：

  ```
  $ cat 工程缓存/制品仓库/平台客户端制品/当前.json
  {"摘要sha256": "cb1ca35a8525a029", "路径": "平台客户端-cb1ca35a8525a029"}     ← mtime 09-16 23:27
  $ cat 工程缓存/制品仓库/平台客户端环境/当前.json
  {"摘要sha256": "7ac9c97e93ddebc4", "制品目录": "平台客户端-7ac9c97e93ddebc4",
   "制品摘要": "40cb4560ee5ab088fe885ca5b6407a3c", "版本": 105, "栅栏令牌": 105}  ← mtime 09-16 22:55
  ```

  两者**文件名相同、字段 schema 不同**（`路径` ↔ `制品目录`），且 `平台客户端制品/` 下积压 **5 个** `平台客户端-<摘要>` 目录（最后清理时间早于最后一次构建）——纯构建不清垃圾。

### 4.3 失败时留下什么

- **AST 解析/反解析失败**（`:319-332`）：抛 `客户端构建错误`；`平台客户端构建/` 留半成品、`平台客户端-临时` 可能残留；**不写摘要制品目录，不动任何 `当前.json`**（制品仓库指针仍指上一次构建）。
- **构建中途失败**：`构建目录` 已被 `rmtree`（`:530-531`）→ 上一次中间副本已丢（源码在 git，可重建）。
- **`--安装` 失败**：`入库`/`安装到环境` 返回 False → `RuntimeError`（`:620`/`:623`）；此时 `平台客户端-<摘要16>` **已落盘**，而 `清理过期制品` 在成功路径之后（`:631-632`）**不执行** → 垃圾堆积。
- **激活失败**：`_回滚安装目录:355` 还原旧安装、保留旧指针，是设计好的安全回退。
- **与 D-17 的关系（口径需更正）**：`未完成事项.md:142` 记的 `检查激活指针()`「`:466-470` 只判源目录」与「没有任何公开出口」**已与当前代码不符**——`检查激活指针` 现在在 `:549-557`，改为转调 `诊断激活指针`（`:516-533`，按「源 / 已安装」**双边**判定），并且 `重建激活指针:560`、`重置激活指针:589` 两个修复出口**已实现**。仍然成立的只有「**调用面**没有出口」：CLI 仍只有 `--安装`（`:641`），三个方法**无能力 id、无 CLI 开关**（`结构债处置方案_20260916.md:226` 的判断仍然有效）。
