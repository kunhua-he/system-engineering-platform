## 三、统一后的唯一形态（定义）

**统一形态 = `<包id>.<能力名>`**（包 id 本身已是「根.域.子域」三段结构，能力 id 在其后追加能力名）。

依据：**681 条里已有 100 条正是这个形态**（`前缀 == 完整包id`，如 `启动监督器.健康监督.执行健康监督`
对应包 `启动监督器.健康监督`）—— 这不是新发明，是把**已经存在的正确形态**推广到全仓。

| 层 | 现在（254 条待改） | 统一后 |
|---|---|---|
模块库 | `网页分析.提取网页信息` | `模块库.网页分析.提取网页信息` |
模块库 | `图像处理.缩放图像` | `模块库.图像处理.缩放图像` |
支持库（后端） | `桌面宿主.启动桌面窗口` | `支持库.前端.桌面宿主.启动桌面窗口` |
适配层 | `Git提供者.创建分支` | `支持库.适配层.Git提供者.创建分支` |
技能库 | `技能库.技能包.校验技能包` | `技能库.后端.技能库.技能包.校验技能包` ★见下注 |

> ★ **技能库特例**：其包 id 是 `技能库.后端.技能库`，能力 id 是 `技能库.技能包.校验技能包`（3 段但不含包 id）。
> 统一后为 `技能库.后端.技能库.技能包.<能力名>`（4 段）。**6 条「其它」形态一并按此规矩归位。**

**命名规则（一句话）**：能力 id = 包 id + `.` + 能力名；**能力名保持中文、保持现名**（只补前缀，不改名字）。

## 五、配套门禁（防回潮，哲学 14.3「反复犯错的开发要补底层」）

统一完成后**必须同时接线**，否则一年后又是两套口径：

| 门禁 | 判据 | 落点 |
|---|---|---|
| **id 形态唯一性** | 条一条 `能力id` 必须 `== 包id + "." + 能力名`；不符即红 | 接进发布门禁防回潮循环（照 `说明书白名单联动` 范式） |
| **冻结基线重算** | 现有 `开发工具/能力id冻结基线门禁.py` 的基线按新 id 全量重算（旧 id 全部作废） | 同上 |
| **冲突自证** | `浏览器自动化` 这类「一族名两包」必须在统一后**不可能再出现**（判据即上表第 1 条） | 同上 |

**判据落点只有一处**：`运行核心/加载器/包发现/发现器.py` 已在做「能力 id 唯一性」检查 ——
**形态判据应加在同一处**（唯一事实源），门禁只调用它，**不另写第二份扫描**（哲学 1.3）。

## 六、风险与边界（诚实交代）

1. **这是全仓最大的一次改名**（254 条 id + 约 5100 处引用）。**唯一原则：不以「省成本」妥协** ——
   但**必须一次做透**，做一半比不做更糟（两套口径并存正是本次要消灭的问题）。
2. **旧 id 不保留别名**（华哥已裁「不要有第二条腿」）：迁移后旧形态**不存在**，
   任何仍按旧 id 调用的地方会**直接失败**（fail-fast），这正是我们要的 —— 不留静默降级。
3. **`浏览器自动化` 一族名两包**：迁移时该能力归属哪个包需按**实现落点**定（
   `支持库.后端.浏览器自动化支持库` 是正式支持库、`支持库.适配层.浏览器自动化提供者` 是提供者），
   属**需现场核实实现后定**的唯一一处，不按猜测改。
4. **编译产物（`工程缓存/`）不手改**：一律由编译器重算；摘要由 `全量重算摘要.py` 刷新。
5. **不改能力名本身**：本次只补前缀。任何「顺手改名」都属超范围，须另立裁决。
