
## 五之二、★ 前置修正：判据 ② 有一个识别缺口（**必须先修，否则接的是假阳性**）

```
【实测发现（2026-09-17 现场调用）】
    from 开发工具.复用审计.能力调用图审计 import 审计模块库
    报告 = 审计模块库()
    ⇒ 审计文件数 = 53 ｜ 违规数 = 1 ｜ 成功 = False

    那 1 条违规：
        文件   模块库/文档生成/__init__.py
        类型   漂移
        详情   声明:['文档生成.生成文档'] 契约:['文档生成.生成文档']
               注册:[]              ← ★ 注册集为空
               __all__:['生成文档']

【根因（已定位到函数）】
    `开发工具/复用审计/能力调用图审计.py` 的 `_入口能力(包目录)`：
        只从 AST 里收集两种形态的"能力id"：
            ① `注册表.注册(能力id="字面量", ...)`         → ast.Constant
            ② `注册表.注册(能力id=循环变量, ...)`         → ast.Name，且在 `循环映射` 里
        **不收集第三种**：`能力id=本模块能力id`（模块级常量变量）
        而 `模块库/文档生成/__init__.py` 正是第 ③ 种：
            L23  __all__ = ["生成文档", "设置HTTP连接器"]
            L25  本模块能力id = "文档生成.生成文档"
            L48  注册表.注册(能力id=本模块能力id, 参数=..., ...)
        ⇒ `本模块能力id` 既不是字面量、也不在 `循环映射` → **注册集 = 空**
        ⇒ 判据拿"空的注册集"去比"声明集" → 必然报"漂移"= **假阳性**

【为什么这很要紧】
    批 1 把这条判据接成强制门禁后，**发布门禁会立刻常年报红**，
    而红的原因是**判据自己认不出合法的包**，不是仓库真有问题。
    ⇒ 接了等于把假阳性钉成强制项 —— 这比不接更糟（会训练人忽略门禁）。

【修法（唯一正解：修判据的识别能力，不是放宽）】
    在 `_入口能力()` 里补第三种形态：收集模块级赋值 `名字 = "字面量"` 到一个映射，
    与既有 `循环映射` 同构；命中 `能力id=该名字` 时取其值。
    —— 概念上就是把现有的"循环变量映射"推广成"模块级常量映射"。

【明令禁止的修法（会变成放宽）】
    ✗ 把"注册集为空"直接当合法（会漏掉真的没注册的包）
    ✗ 把这条违规登记成豁免（哲学 12.4：唯一合法路径是修实现/修判据）
    ✗ 只在白名单里把 `文档生成` 排掉（同源问题会在下一个包复发）

【验收】
    修完后 `审计模块库()` 违规数 = 0，且**逐包核对**：
    随机挑 3 个"用模块级变量声明能力"的包，注册集均非空；
    再故意删掉一个包的 `注册能力()` 调用 → 判据必须仍然报红（证明没被放宽）。
【归口】
    这是**判据模块自身的缺陷**，按哲学 4.1 记在 `开发文档/未完成事项.md`；
    修它属"批 1 的前置"，不单列批次。
```
