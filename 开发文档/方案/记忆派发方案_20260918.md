# 记忆派发方案（临时派发记忆给子代理，返回句柄）

> 最后更新：2026-09-18
> 口径：实测（分层归属、既有能力、字段名均现场核实；未标"实测"处为设计意图）
> 维护者：记忆派发方案

需求来源：华哥 2026-09-18 原话

> 「你为啥不开子代理加速呢？一次性派发出去苦海维修不好吗？单线程干啥？拆成 10 分钟内的小任务派发出去。甚至你可以升级底座，项目记忆这里，可以临时派发记忆给子代理的那种，然后返回了句柄，子代理读取句柄就可以获取要工作的记忆。」

要件拆成三条：**① 临时派发**（不是永久授权）**② 返回句柄**（不是把内容塞进提示词）**③ 子代理凭句柄取记忆**。

---

## 一、先判：这是不是「重复造」

平台已有三件可直接复用的既有机制（实测）：

| 既有件 | 落点 | 本方案复用什么 |
|---|---|---|
| **句柄状态机**（创建→有效→失效，含超时/释放/回收/过期；句柄表有界：失效行留 200 条/300 秒） | `公共契约/句柄体系.py` | 句柄生命周期整体复用，**不另建一套派发状态** |
| **文件租约三段式**（申请→续租→释放/回收过期；参数含 `所有者`/`任务`/`持有秒`/`心跳超时秒`） | `平台控制面/能力目录`（`申请文件租约`/`续租文件租约`/`释放文件租约`/`回收过期文件租约`/`查询文件租约`） | 「临时持有 + 归属 + 到期回收」的**模式**照搬 |
| **记忆的归属维度**（`记忆支持库.写入记忆` 已有 `智能体`/`项目`/`标签` 字段；`搜索记忆` 支持 `项目` 过滤） | `支持库/后端/记忆支持库` | 取记忆快照只调既有能力，**不重造记忆检索** |

**复用决策结论**：需要**新增一个组合层能力面**，但原子能力全部复用既有件——不新建句柄体系、不新建记忆检索、不新建租约存储。新增的只有「把一次记忆查询的结果，按归属打包成一个有界、可回收、凭句柄可读的临时派发物」这段编排。

## 二、分层归属

```text
子代理 / 调用方
   ↓ 唯一网关 40007（POST /网关/调用，能力 id + 参数）
模块库/记忆派发            ← 组合层：派发 / 读取 / 回收 三段编排（唯一新增）
   ↓ 只经 获取能力调用器().调用能力(能力id, 参数)
支持库.后端.记忆支持库            ← 既有：取记忆快照（搜索记忆 / 列表）
公共契约.句柄体系                ← 既有：句柄生命周期与统一回收
支持库.后端.数据库连接支持库.SQLite ← 既有：派发表（运行态入库，唯一 SQLite 入口）
```

**为什么不放支持库**：派发要组合「取记忆 + 登记句柄 + 落库 + 到期回收」四步，是**流程**不是原子动作（哲学第 2 条）。
**为什么不放平台控制面**：平台控制面管的是目录/授权/发布/证据治理，不管「一次业务查询结果的临时投递」。
**为什么不塞进薄壳**：薄壳定位是「只做协议翻译，不实现业务逻辑」（`AGENTS.md`），加进去会带业务语义。

## 三、契约草案

| 能力 id | 参数 | 返回 | 说明 |
|---|---|---|---|
| `记忆派发.派发` | `项目`、`查询`、`条数`（默认 20，上限 100）、`持有秒`（默认 600，上限 3600）、`归属`（必填：子代理/任务 id） | `句柄`、`条数`、`到期时间`、`归属` | 按 `项目` 过滤取记忆**快照**，登记句柄并落派发表；返回句柄（子代理只拿句柄，不拿内容） |
| `记忆派发.读取` | `句柄`、`归属`（必填） | `记忆列表`、`条数`、`剩余秒` | 校验句柄有效 + 未过期 + **归属匹配**；不匹配返回 `权限不足`（防串读） |
| `记忆派发.回收` | `句柄`、`归属`、`原因` | `是否回收` | 提前释放；同时把派发表该行标记失效 |
| `记忆派发.回收过期` | `心跳超时秒` | `回收清单`、`回收数` | 批量回收过期派发（照 `回收过期文件租约` 口径） |

**快照语义（关键取舍）**：派发时**复制一份内容快照**，不是给引用。理由：子代理读到的是「派发那一刻」的固定内容，不受后续记忆增删影响——否则子代理的工作依据会在它干活期间被人改掉（同样的输入得不同结论）。

## 四、数据模型（运行态入库，不新增文件式状态）

库文件：`<运行数据根>/记忆派发库.db`（经 `公共契约/运行时/运行缓存.解析运行数据根`，**禁止裸拼 `工程缓存`**）。

```sql
CREATE TABLE IF NOT EXISTS 派发表(
  句柄 INTEGER PRIMARY KEY,        -- 与 公共契约.句柄体系 的句柄 id 同源
  归属 TEXT NOT NULL,              -- 派给谁（子代理/任务 id）
  项目 TEXT NOT NULL,
  条数 INTEGER NOT NULL,
  快照 TEXT NOT NULL,              -- 记忆条目快照（JSON 文本）
  派发时间 REAL NOT NULL,
  到期时间 REAL NOT NULL,
  状态 TEXT NOT NULL);             -- 有效 / 已回收 / 已过期
CREATE INDEX IF NOT EXISTS 派发表_归属 ON 派发表(归属, 状态);
```

## 五、有界与回收（平台铁律：所有资源必须有界）

| 资源 | 上限 |
|---|---|
| `持有秒` | ≤ 3600（超限即拒，不静默截断） |
| 单次 `条数` | ≤ 100 |
| 单归属并发有效派发 | ≤ 8 |
| 派发表总行数 | ≤ 2000（满即拒新派发，返回 `限流`，不静默丢旧行） |
| 快照总体积 | 单派发 ≤ 256 KB |

**回收三路**：① 调用方主动 `回收`；② 到期由 `回收过期` 批量清（可挂既有网关定时任务）；③ 句柄状态机失效时按归属统一回收（资源生命周期绑句柄，不旁路拼接独立回收能力——照 `公共契约/句柄体系.py` 既有口径）。

## 六、验收口径（真实 HTTP，不跑全量 unittest）

| # | 验收项 | 怎么验 |
|---|---|---|
| 1 | 派发返回句柄且不含内容 | 派发后回读：返回值里只有句柄/条数/到期/归属，**无记忆正文** |
| 2 | 凭句柄可读 | 用句柄读取 → 条数、内容与派发时刻一致 |
| 3 | **归属隔离** | 甲派发的句柄，乙拿去读 → `权限不足`（不得串读） |
| 4 | **快照不变** | 派发后修改/删除原记忆 → 用句柄读到的内容**与派发时逐字一致** |
| 5 | 到期回收 | 用极短 `持有秒` 派发 → 过期限时后读取 → `句柄已过期`；`回收过期` 能清 |
| 6 | 有界 | 超过单归属并发上限 / 表满 → 明确失败（中文码），不静默丢 |
| 7 | 反向验证 | 故意把归属校验去掉 → 第 3 项必须变红 |
| 8 | 摘要闭合 + 门禁 | `全量重算摘要` 全仓闭合；`公开调用完整性门禁` 无新增违规 |

## 七、待华哥裁决（只此二项，其余按哲学自裁）

| # | 待裁 | 选项 |
|---|---|---|
| 1 | **句柄类型**：复用既有「读取句柄」还是新增「记忆派发句柄」 | A（推荐）=新增类型，因为它的失效要连带清派发表，语义与只读句柄不同；B=复用读取句柄，改动小但两类语义混在一起 |
| 2 | **派发范围**：能不能派发「跨项目」记忆 | A（推荐）=只能派发调用方自己有权限的项目（与「企业微信按 UserID 分配资料范围」的既有口径一致）；B=允许跨项目（方便，但绕开了资料边界） |

## 八、明确不做（防后患）

| 不做 | 理由 |
|---|---|
| 把记忆正文直接塞进子代理提示词 | 那正是华哥要避免的：提示词会随派发次数膨胀，且无法回收、无归属、无有效期 |
| 新建第二套句柄/租约体系 | `公共契约.句柄体系` + 文件租约模式已够用，重造＝第二事实源（哲学 1.3） |
| 派发常驻有效（无到期） | 无有效期＝无界资源；派发物必须能自动回收 |
| 用文件记录派发状态 | 运行态一律入库（2026-09-15 定盘）；证据类才留文件 |
| 在派发时调用大模型做摘要 | 派发是投递动作，不是理解动作；要语义检索由 `搜索记忆` 自己带（默认还能 `仅关键词` 免 LLM） |
