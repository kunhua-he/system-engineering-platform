## 一、一句话定位（迭代后的准确版本）

**它是一套"给 Agent 用的能力操作系统"：单机私有部署一套 → 唯一网关 → 任何语言发 HTTP 传参调用。**

三个关键词，各对应一条设计红线：

| 关键词 | 含义 | 红线（违反即不算本平台） |
|---|---|---|
| **给 Agent 用** | 调用方是 Agent / 脚本 / 网页，不是终端用户 | 不追求 GUI、不追求"开箱即用给小白" |
| **能力操作系统** | 底座提供原子能力，**上层组合** | 底座不许塞业务语义（哲学第 2 条） |
| **单机私有部署** | 本机/内网跑一套，长期常驻 | 不按公网多租户设计（哲学 9.5「相对安全」） |

## 二、边界：明确不该做什么（这一节比"能做什么"更重要）

### 2.1 技术边界

```
✅ 该做：原子能力、统一契约、权限与租约、真实 HTTP 验收、可回滚发布、证据留痕
❌ 不该做：
   • 业务语义（会员/分红/门店 → 属 V3 等业务项目）
   • 公网多租户安全（不做沙箱、不做绝对隔离，语 9.5）
   • GUI 应用（提供 HTML 调用示例是上限，不做桌面客户端）
   • 替调用方做决策（底座给能力 + 证据，业务判断留给上层）
   • 加密/脱敏/掩码（哲学第 9 条 0 加密 0 限制 → 隐私是业务端的事）
```

### 2.2 契约边界（最容易越界的地方）

```
底座承诺：能力 id 稳定、参数/返回/错误码契约稳定、版本可查、失败明确
底座不承诺：值语义（同一输入一定同输出）—— 只在能力类别内承诺（见第六节）
```

### 2.3 边界上的灰色地带（需华哥裁决，已在方案里列）

| 灰色地带 | 两难 | 我的倾向 |
|---|---|---|
| **兼容映射**（旧错误键） | 哲学 1.2「不保留旧腿」 vs 真有外部依赖要兼容 | 允许，但**必须有到期版本 + 使用计数 + 删除条件**（不静默长期兼容） |
| **外部依赖不可用** | 哲学 2.2「依赖必须本地具备」 vs 上游挂了不该让底座永久红 | 用 `未核验 / 条件可用` 状态，**不得报"通过"** |
| **平台差异** | 已收口到 `平台适配.py`，但 Windows 路径类缺陷仍在（实测 C1） | 短期明确「只支持 macOS」，入口直接拦 Windows；要支持就建真实 Windows CI |

## 三、适应度：它适合谁、什么场景合适、什么场景不合适

### 3.1 适合（已经踩实的能力）

```
✅ 多项目共用一套能力（避免每个项目各造轮子）
✅ 需要真实证据链的场景（转码/转写/文档处理这类"结果可核对"的活）
✅ Agent 长期驻留、需要"做过什么"可追溯
✅ 单机或内网、数据不出机器（私有部署）
✅ 调用方语言混杂（PHP/Vue/Python/Java/易语言 —— README 已给范例）
✅ 需要"能力可搜"而不是"Prompt 里塞上百个工具 schema"（只有 3 个入口工具）
```

### 3.2 不适合（诚实说清，避免误用）

```
❌ 高并发公网 SaaS（SQLite 写串行 + 单机部署）
❌ 需要绝对安全隔离的多租户（设计上就是"相对安全"）
❌ 要求"装了就能跑、零配置"（需部署第三方依赖 + Python 3.14，见 README 第三方章节）
❌ 纯业务系统（该直接写业务，不该绕底座）
❌ 需要跨平台开箱即用（当前 macOS arm64 实测，Windows/Linux 有已知缺口）
```

### 3.3 当前成熟度定位（对齐报告的评价 + 我方核实）

```
架构设计：强（分层/契约/资源治理/进程隔离，报告也认可"上游水平"）
规则记录：强（哲学 12 条 + 27 决策记录 + 139 包说明）
结构化治理：中上（门禁体系已成规模）
门禁覆盖：中（★ 有判据、缺强制点 —— 已实测 B1）
反向证明：不足（★ 破坏试验不成体系）
时间维度原子性：不足（★ A1 嵌套事务之类）
⇒ 综合：**"架构验证完整、处于可靠性收口期"**（报告措辞准确，我认可）
```

## 六、往哪走：把"确定性"从绝对规则改成能力类别

这是报告2 提出、我认为最有价值的**哲学级修正**：

```
现状（哲学 9.4）：「同样的输入 → 同样的输出」写成了通用规则
问题：随机数 / 当前时间 / 网络请求 / 浏览器导航 / 大模型对话 —— 这类能力天然不满足

修法：把确定性分成四类，每类能力在能力定义里显式声明自己属哪类
  ① 纯确定性：相同显式输入 → 必须相同输出（可写断言）
  ② 可重放：返回中记录随机种子 / 时钟 / 模型版本 / 上游摘要（可复算）
  ③ 外部观测：只保证契约、错误语义与证据，不保证值重复（网络/浏览器）
  ④ 有副作用：额外声明幂等键、重放语义、状态版本
```
**收益**：这条改完，"验证该验到什么程度"就有依据了 —— 现在 264/742 个步骤只验形状（35.6%），
**其中一部分本来就是外部观测类、验不了值**，另一部分是真该补关键值。分类之后能精确分派。
