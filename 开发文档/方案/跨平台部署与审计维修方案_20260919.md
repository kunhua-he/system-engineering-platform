### 2.4 「不是缺陷（设计取舍）」——禁止后人误改

各份审计已单列，本件只登记**总原则**，明细见各报告 §「不是缺陷」节：

- 平台准入拒绝未实测平台（`平台适配.py:191-194`，2026-09-18 有意裁决）；
- Windows 上句柄目录返空元组、内存峰值抛不支持、进程组号返 `None`（均为「不假装有数据」）；
- 进程存活**刻意不用** `os.kill(pid,0)`（Windows 上那是 `TerminateProcess`，会误杀）；
- 环境自检在非支持平台永远退 1（诊断工具如实报缺，是正确语义）；
- 门面→提供者分层、模块经公开能力调用、测试样板豁免（合法分层，不是重复实现）。

## 三、第三轮维修纪律（照 12.1）

1. **并发靠平台文件租约硬锁**（`开工编排.开工即占`，**同一份文件也能上锁**）：谁先拿到谁先改、改完留日志；撞车有界等待重试。能并行就并行。
2. **全部修完前不跑验证**（只做 `py_compile` 语法合规 + 单文件轻检测）。
3. 每处修复**必须配反向验证**（故意弄坏一次、确认真变红），没有反向验证不算修好。
4. 只 `git add` 自己改的文件，`commit` 带精确 pathspec，提交后 `git show --stat HEAD` 核对。
5. **不主动推送远程**（华哥未在本任务授权推送）。
6. 修完统一跑一次：`编译口 --变更` → 定向 unittest → Linux 真机装配冒烟。
