## C1 · 能力调用图审计器「假阳性」——已复现，根因与报告不同

### 复现命令与真实输出

```python
from 开发工具.复用审计.能力调用图审计 import 审计模块库
r = 审计模块库()
# 审计文件数=53  违规=1
# ★ 文档生成/__init__.py:0 [漂移] 声明:['文档生成.生成文档'] 契约:['文档生成.生成文档'] 注册:[] __all__:['生成文档']
```

**确实复现到一条违规**（报告说它会在 `模块库.文档生成` 上误判，位置对）。

### 根因（与报告说法不同）

报告说是「对**常量能力 ID** 产生假阳性」；实读代码后，真实根因是：

```
`模块库/文档生成/__init__.py:25`  `本模块能力id = "文档生成.生成文档"`   ← 模块级变量
                            :45  注册表.注册(能力实现(能力id=本模块能力id, …))   ← 传的是变量名
审计器 `_入口能力()`（能力调用图审计.py:122-148）只认三种形态：
  ① 字符串常量          `isinstance(关键字.value, ast.Constant)`
  ② for 循环里的列表字面量（`循环映射`）
  ③ （无第三种）
⇒ 传**模块级变量名**时，`注册集` 抽不到 → 得到空集 `注册:[]`
⇒ 空集 ≠ 声明集 → 判「漂移」
```

**结论**：报告指出的**现象真**（该包被判漂移）；但**定性不准**（不是"常量能力 ID 假阳性"，而是"**模块级变量持有的能力 id 无法被常量折叠**"）。

### 这条的市场价值

```
同一形态在仓里不止一处：凡「先把能力 id 存成模块级变量、再传变量名注册」的包，
都会被误判漂移 → 属**审计器假红**，会持续制造噪音（也与门禁"假绿/假红"主题同源）。
修法两条（待裁决）：
  路线 A：审计器支持「模块级简单赋值常量折叠」（ast.Name → 查模块级 `ast.Assign` 的字符串常量）
          —— 增加审计器复杂度，但覆盖面最广
  路线 B：改包写法，注册时直接传字符串字面量 —— 改动面小，但要逐个包改，且违背"单一事实源"直觉
  我的倾向：**路线 A**（审计器本来就是为"看穿写法"存在的；让包为了迎合审计器改写法，
            等于让被审计者迁就审计者，与平台"补能力面、不改判据形状"的口径相反）
```

### 附带发现（同类风险，需登记）

```
`模块库/文档生成/实现/文档生成.py:20`  `格式到能力id = {...}` 是**模块级字典**，
调用点 `_调用支持库(能力id, 参数)` 传的是字典值 —— 这条路径**当前没被判违规**
（因为它不涉及"注册集"，只涉及"调用"），但**说明同类"变量持有能力 id"的写法是仓里通行做法**，
故路线 A 的价值比单点修复更大。
```

## C3 · DNS rebinding —— 机制已确证（代码级证据充分，未做伪造 DNS 实跑）

### 代码级证据链（三处，逐行可查）

```
① 校验侧（解析一次）：
   支持库/后端/网络通信支持库/出站安全/实现/出站安全.py:83
       socket.getaddrinfo(主机名, None, socket.AF_UNSPEC, socket.SOCK_STREAM)  ← 第一次解析
   支持库/后端/网络通信支持库/请求/实现/网络请求.py:69
       地址信息 = socket.getaddrinfo(主机, …)                                  ← 又一次解析（判定回环用）

② 连接侧（又一次解析）：
   网络请求.py:200  请求 = urllib.request.Request(地址, …)      ← 传给 urllib 的是**原始地址（主机名）**
   网络请求.py:230  响应对象 = 打开器.open(请求, timeout=超时秒)  ← urllib 内部**自己再解析一次**
   （POST 与 GET 两条路径同形：:200/:230 与 :369/:387）

③ 关键事实：**校验得到的 IP 从未被传给连接**
   —— 代码里没有「把已审核 IP 固定下来、让 socket 连那个 IP」的实现，
      也没有「连接建立后核对 peername 仍在允许集合」的回查。
```

### 机制判定

```
TOCTOU 成立：校验时的解析结果 与 连接时的解析结果 之间没有任何绑定。
伪造 DNS（第一次返公网 IP、第二次返 127.0.0.1）即可绕过 —— 报告给的复现路径与代码完全吻合。
```

### 为什么本轮没做实跑

伪造 DNS 需改 `/etc/hosts`、劫持解析或临时代理 —— **属有副作用的系统级操作**，
在本轮「不维修、只审计」的约束下不做。
**下一步（仍是只读）**：在隔离副本 + 容器/独立网络命名空间内做（不改本机 hosts），
或用一个「自定义解析器 + 直接调能力」的进程内样本证明"两次解析结果可不同"。

### 定性（需华哥确认）

```
这条**不是**"该不该做 SSRF 防护"的问题（本平台确有校验，说明"该做"已经做了），
而是"**防护做了却没绑住**" —— 属实现缺陷，**与哲学 9.5「相对安全」不冲突**：
9.5 说的是"不做绝对安全、不因安全而萎缩能力"，不是"允许校验形同虚设"。
```
