## 三、批 1 的精确改法（N1 + N2，最重的两条）

### N1：`资源繁忙` 登记 + 分支
1. `运行核心/统一网关/本地网关.py` 的 `公开错误码状态映射`：给 `资源繁忙` 登记状态码。
   **判据**：这是**可退避的资源问题**，不是服务端故障 ⇒ 用 **429**（`限流` 同级语义）；
   已有 `限流`→429，保持同族，**不新造 503**（503 会让上游把它当"服务不可用"）。
2. `运行核心/统一网关/网关核心.py` 的 `公开错误说明表`：补 `资源繁忙` 的中文说明。
3. 网关分支：**按错误码判定**（哲学 14.4 文案给机器判的用错误码），不许 `if "繁忙" in 说明`。
4. **反向验证**：构造 `资源繁忙` 返回 → 断言 HTTP **429** 且信封 `可重试=真`；把登记行删掉 → 断言**变红**（回到 500）→ 还原。

### N2：信封加 `可重试`
1. `网关核心.py:525/538/540-552` 的响应结构加 `可重试`（**逻辑型**，正式类型）；
   纯查询/成功响应填 `假`，可退避失败填 `真`。
2. **信封只增不改不删**（冻结面纪律）：新字段**追加**，不改既有键名与类型。
3. **反向验证**：断言 `资源繁忙`/`限流` 两类响应 `可重试=真`；`参数不合法` 类 `可重试=假`。
4. **契约同步**：`公共契约` 侧若有响应结构定义，同步补字段（**这是对外契约面变更，需华哥确认**）。
