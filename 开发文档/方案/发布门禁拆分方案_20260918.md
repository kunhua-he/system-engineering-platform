## 二、拆分方案（按职责簇，主文件只留调度）

### 目标结构

```
开发工具/发布门禁/
├── 运行发布门禁.py          # 主入口：只留 门禁项/门禁结果/检查() 登记器/主函数/串接调度（目标 ≤ 700 行）
├── 门禁基础设施.py          # 门禁项/门禁结果类 + 运行子进程/临时目录/注销 等公共件
├── 防回潮族.py              # 裸布尔 / 非正式类型名 / 英文错误码 / 占位代称 / 能力调用图 / 反向破坏
├── 契约族.py                # 契约声明一致（注册口径）/ 契约版本唯一 / 能力id只增不改 / 对外契约变更
├── 制品族.py                # 选择待验证制品 / 制品来源绑定 / 字节快照与未变 / 缓存环境 / 契约与HTML矩阵
├── 合规族.py                # 包结构完整 / 包声明合法 / 逐包权威合规 / 依赖锁与反向篡改 / 工程缓存无源码
├── 测试族.py                # 测试伪装 / 测试体系门禁 / 回归与慢速
└── 存量基线.json            # 已有（防回潮存量基线.json）
```

### 拆分原则（照 6.1 + 平台铁律）

1. **对外零变化**：`执行门禁(...)` 签名、`门禁结果` 结构、`门禁项` 字段、CLI 行为**逐字不变**；
   主文件对拆分出去的名字**重新导出**（`from 防回潮族 import *` 式显式列举，非 `*`）。
2. **不移动判据本体**：判据唯一性不能被拆分破坏 —— 例如 `校验裸布尔防回潮` 内部复用
   `_防回潮分桶判定` / `_防回潮检查`，这些**必须与调用方同文件或同族**，不能拆到别族。
3. **`检查()` 就地登记**：143 个检查项都调 `检查()`，它是**闭包**（依赖 `门禁项列表`）。
   拆出去的函数**不应自己持有 `检查`** —— 方案是**各族函数返回 `(名称, 通过, 详情)` 元组列表**，
   由主文件统一登记。**这是关键决策**：否则每族都要复制一份登记逻辑（违反唯一性）。
4. **一族一文件、文件 ≤ 800 行**；若某族超 800，按「判据族 / 执行族」再分。
5. **不新增执行腿**：拆出的族只是**同一进程内的函数**，不引入 HTTP/子进程。

## 三、执行顺序（风险从低到高）

| 步 | 动作 | 风险 | 验收 |
|---|---|---|---|
| S1 | 抽 `门禁基础设施.py`（`门禁项`/`门禁结果`/`运行子进程`/临时目录） | 低（纯搬运、无判据） | `py_compile` + `执行门禁` 冒烟 |
| S2 | 抽 `防回潮族.py`（6 个 `校验*防回潮` + 其私有件） | 中（有分桶基线读取） | 6 项各跑一遍 + 反向验证 |
| S3 | 抽 `制品族.py` | 中（涉及制品字节） | 4 项各跑 + HTML 黑盒 |
| S4 | 抽 `契约族.py` / `合规族.py` / `测试族.py` | 中 | 各自定向 |
| S5 | 主文件改为**族函数返回元组列表 + 统一登记** | **高**（改控制流） | **必须跑完整发布门禁 + 反向验证** |

**为什么把 S5 放最后**：S1–S4 是纯搬运（对外零变化可用 `git diff` 逐字证明），
S5 才动控制流 —— 把它单独成步，出问题时能明确回退到 S4 状态。

## 四、风险与不拆的判断

| 风险 | 处置 |
|---|---|
| **门禁自身故障会掩盖发布问题**（最严重） | 每步后跑**完整发布门禁**并比对逐项结论与拆分前一致；任一结论变化即回退该步 |
| 拆分引入循环导入 | 族文件**只 import 基础设施**，绝不 import 主文件；主文件 import 各族 |
| `检查()` 闭包无法跨文件 | 采用「族返回元组列表、主文件登记」形态（见原则 3） |
| 拆到一半发现真耦合 | **允许不拆**（照 `网关核心.py` 的先例：耦合过深就如实报告不硬拆） |
