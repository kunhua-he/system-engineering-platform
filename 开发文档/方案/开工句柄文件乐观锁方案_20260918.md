## 〇、一页结论

```text
缺口：文件租约只锁「路径」，不锁「内容」——A 会话认领后改了文件，B 会话拿到的
  租约冲突信息里**没有内容指纹**，无从判断「我在读的那份还是不是当初那份」。
  高并发下仍会踩同一个文件：A 改完后 B 基于旧内容改，静默覆盖。

补什么（三件，全部扩在既有文件租约里，不新造第二条腿）：
  ① 认领时登记**内容指纹**（每文件 sha256；文件不存在记 空串 = 新建）；
  ② **改后校验**：真写前比对当前指纹 vs 认领时指纹，不符即拒（`内容已变更`）并回报
     「谁改的、改成什么指纹、在哪条留言」；
  ③ **句柄留言**：改完在租约句柄留一条「我改了什么」（自由文本 + 自动附前后指纹）。
  另加 ③′ **句柄查询**：给文件路径查出「当前活跃租约 + 全部留言时间线」。

为什么这样做（哲学依据）：
  - 第 1 条 2 项（唯一化）：扩既有 5 条租约能力，不另起一套「锁服务」；
  - 第 5 条（契约只增不改）：全是**新增可选参数 + 新增返回键**，老调用逐字兼容；
  - 第 10 条 2 项（缺什么补什么）：这是补原子能力，不是补特例。
```

## 二、字段设计（只增不改）

### 2.1 租约记录新增四个键（老键一个不动）

| 新键 | 类型 | 含义 |
|---|---|---|
| `内容指纹` | 字典型 `{路径: 指纹}` | 认领时的每文件 sha256 十六进制；**文件不存在记 `""`**（表示「认领时它还不存在」，新建合法） |
| `留言` | 列表型 | 每次留言：`{时间, 留言人, 说明, 改前指纹, 改后指纹}`，只增不删 |
| `校验结果` | 文本型 | 最近一次改后校验的结论（`未校验` / `校验通过` / `内容已变更`） |
| `句柄id` | 文本型 | 与 `租约id` 同值（华哥叫「开工句柄」，留别名键便于语义对齐，老字段 `租约id` 继续在） |

### 2.2 入参新增三个（全可选，缺省=老行为）

| 能力 | 新参数 | 语义 |
|---|---|---|
| `申请文件租约` | `内容指纹`（字典型，可选） | 调用方算好的 `{路径: 指纹}`。**不给就由底层按文件现场算**（缺省即取证，最省调用方的心） |
| `申请文件租约` | `校验指纹`（逻辑型，尾参，默认假） | 给真时：`内容指纹` 为调用方声明的「我读到的那份」，与现场不符即拒（`内容已变更`） |
| `文件租约留言`（新增能力） | 见 2.3 | — |
| `查询文件租约` | `文件路径`（文本型，可选） | 给路径 = 只回该文件的活跃租约 + 留言时间线；不给 = 现有全表口径 |
| `查询文件租约` | `含留言`（逻辑型，默认假） | 是否在返回里带留言时间线（不带则只回计数，省 token） |

### 2.3 新增一条能力：`平台控制面.能力目录.文件租约留言`

> 「改完了，在句柄里留一句我改了什么」——这是华哥流程里明写的动作。

| 项 | 值 |
|---|---|
| 参数 | `租约id`（文本型，必填）、`留言人`（文本型，必填）、`说明`（文本型，必填）、`改后指纹`（字典型，可选）、`存储目录`（文本型，可选） |
| 返回 | `{已追加, 留言, 留言时间线, 校验结果}` |
| 副作用 | 在租约存储把留言追加进本租约记录（原子替换）；**只增不删** |
| 判据 | ① 只有**活跃**租约才能留言（过期/已释放 → `租约已失效`）；② `说明` 为空 → `参数不合法`；③ 留言后 `校验结果` 更新为「校验通过」或「内容已变更」 |

### 2.4 改后校验的触发点（关键）

「真写前校验」不能靠自觉 —— 落在**唯一的写盘原子能力**上（`文件系统支持库.文本补丁.应用精确替换`）已经支持 `预期文件摘要` 参数（乐观锁零件已在），本方案只补**租约侧的对照口径**：

- 调用方流程（写进规范）：`申请文件租约(带指纹)` → 改文件 → `文件租约留言(说明=我改了什么, 改后指纹=现场算)`；
- 若期间别人动过 → 写盘能力用自己的 `预期文件摘要` 拒掉；租约侧在**留言时**再对一次，不符即 `校验结果=内容已变更` 并把两份指纹都留进留言，**留痕不吞**。

## 三、华哥流程 ↔ 本方案对照

| 华哥原话 | 落点 |
|---|---|
| 「申请开工 ID 时把可能要改的文件绝对路径全写上去（顺手加个 MD5）」 | `申请文件租约(修改路径=[…], 内容指纹={…})`；不给指纹则底层现场算 |
| 「等于上了个乐观锁」 | 路径互斥（已有，实测 409）+ 内容指纹（本次新增） |
| 「B 会话申请时返回有几个文件撞车」 | 已有：409 `文件已被占用` + 冲突清单（占用者/开始时间/过期时间），本次再附**冲突文件的当前指纹** |
| 「改文件时先检查 MD5 是否改变，没变就上锁」 | 申请即上锁；`校验指纹=真` 时先核对声明指纹与现场一致才给锁 |
| 「改完解锁，并在句柄里留个留言我改了什么」 | `文件租约留言` + `释放文件租约` |
| 「另一个会话直接改，发现 MD5 没对上，就查一下之前的 md5 和现在的 md5」 | `查询文件租约(文件路径=…)` 返回该文件活跃租约 + **全部留言时间线**（含改前/改后指纹） |
| 「一个 HTML 请求就能查」 | 全部走 `POST /网关/调用`，任何接入方（含 HTML）一次请求即得 |

| 1 | 指纹用 MD5 还是 sha256？ | **sha256**。依据：项目既有口径统一用 sha256（`资源键表` 判据明写「`hash()` 带进程级随机盐」的教训），平台已有 `内容摘要` 能力用 sha256；MD5 是华哥口语，取「内容指纹」这个语义 |

| 3 | 留言能不能改？ | **只能增，不能改删**。依据：第 3 条（失败与报错必须留痕）；留言是审计链 |
