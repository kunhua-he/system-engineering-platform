## 四、逐层实施方案

### 第 1 层：规则可强制

```
现状问题
  ├→ 哲学有 5.3「契约变化必须升级版本」✓
  ├→ 判据模块有 ✓
  ├→ 单元测试有 ✓
  └→ 但发布门禁 0 命中 ✗  ← 靠人记得跑 = 不是强制点

改法
  ├→ ① 给每条规则登记三要素（判据/强制点/反向试验）
  ├→ ② 发布门禁接入测试体系门禁（真实调用，不是帮助文本）
  └→ ③ 缺强制点的规则 = 发布门禁报红

验收
  └→ 故意删掉一处强制点 → 门禁必须报红（证明"忘了接"能拦住）

外部依据
  ├→ pre-commit 反证：`git commit --no-verify` 可完全绕过本地钩子
  │      ⇒ 本地钩子不算强制点，必须在发布门禁（不可绕）层拦
  ├→ kyverno：`make verify-codegen` 判据原文 "exits cleanly with no git diff"
  └→ GitHub rulesets：官方有 `evaluate` 模式
          「runs but will not be required to pass」
          ⇒ 平台层就把"跑了但没拦"做成一等公民状态
```

### 第 2 层：生成物自动化

```
现状问题（卡点 A 的数学）
  ├→ 改 1 个源文件要手工联动 6 份生成物
  ├→ 139 包 ≈ 1900+ 个生成物文件
  └→ 884 提交里「修」184 +「修复」126 = 310（35%）是修自己

改法
  ├→ ① 生成物四件套
  │     · 输入指纹（这份生成物来自哪些输入的哪个版本）
  │     · 勿手改标记（文件头写明"本文件由 X 生成，勿手改"）
  │     · 版本（生成器版本，便于"改了生成器要全量重算"）
  │     · 复算判据（跑完生成器后 git diff 必须为空）
  ├→ ② 提交时自动重算（pre-commit 钩子做"自动"，发布门禁做"兜底"）
  └→ ③ 门禁校验：重算后无 diff，否则报红并指出"哪个输入变了"

验收
  └→ 手工改一份生成物 → 门禁必须报红

外部依据
  ├→ please（AGENTS.md 原文）：
  │      "Anything that changes what a target produces must be folded into its hash"
  │      ⇒ 生成物的 hash 必须包含所有影响它的输入
  │      + `plz autofix`（自动修复）+ `plz puku sync`（同步产物）
  ├→ OPA：`capabilities.json` 版本化快照 + 策略自带测试（`pr_check_test.rego`）
  └→ Nix：内容寻址 + 可复现构建（同输入必得同字节）
```

### 第 3 层：反向证明

```
现状问题（卡点 D）
  ├→ 正向步骤 1007 项，其中 264 项（35.6%）只验类型/字段形状，没验业务结果
  └→ 没有"故意弄坏 → 必须报红"的体系

改法
  ├→ ① 每个门禁配一个破坏试验用例（故意弄坏 → 必须红）
  ├→ ② 三拍验证
  │     · SoT（破坏前）：断言"本来是绿的"  ← 防假红
  │     · EoT（破坏后）：断言"确实红了"
  │     · 恢复后：断言"回到绿"          ← 防门禁粘滞
  └→ ③ 变异测试算子必须实现"样本"接口 + 元测试遍历（忘带样本 = 直接失败）

验收
  └→ 破坏试验自身也要进发布门禁（否则"证明体系"自己没人强制）

外部依据
  ├→ cosmic-ray：每个变异算子**必须实现 `examples()`**（样本是接口义务）
  │      + `test_operator_samples.py` 元测试自动遍历"所有算子 × 全部样本"
  │      ⇒ 忘带样本 = 元测试直接失败（不是另维护一张表）
  ├→ LitmusChaos 探针三模式：SoT / EoT / Edge
  │      ⇒ 光验"报红"不够，要先断言"本来是绿的"
  ├→ stryker-js 三档阈值：`high:80 / low:60 / break:null`
  │      ⇒ **break 默认 null = 不阻断，是显式配置** —— 用连续量+分档表达质量水位
  └→ policy-bot Simulation API：模拟"条件变了策略怎么判"，不写回真实状态
```

### 第 4 层：豁免自我检查（★ 本轮新发现）

```
现状问题
  ├→ 测试伪装门禁：存量 271 项，口径"只报告 + 不得增加"
  ├→ 公开调用门禁：存量 23 项
  └→ ★ 漏洞：修好的存量如果不删，会永远挂在计数里，没人发现它已经不需要了

改法（外部现成机制，直接照搬）
  ├→ ① 豁免必须带理由 → 无理由 = 报错
  └→ ② 已不再被触发的豁免 = 空转 = 报错要求删除
  └→ ③ 默认值分级：能机器判定的默认 error，需人判断的默认 off 可显式开启

外部依据（tach，第二批下载）
  └→ 配置原文：
        [rules]
        unused_ignore_directives = "error"           # 没被用到的豁免 = 报错
        require_ignore_directive_reasons = "error"   # 豁免必须带理由 = 报错
        unused_external_dependencies = "error"       # 声明了但没 import = 报错
     文档原文（三条，连默认值都分级）：
        · unused_ignore_directives (default: warn)
        · require_ignore_directive_reasons (default: off)
        · unused_external_dependencies (default: error)
     实现：src/config/rules.rs + src/checks/ignore_directive.rs
  ⇒ 这把「例外纪律」从"靠人自觉登记理由"升级成"机器强制"
```
