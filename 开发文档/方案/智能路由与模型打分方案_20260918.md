## 〇、华哥口径原样落地

### 0.1 华哥原话（本方案唯一需求来源）

```text
① 动态路由我倒是觉得可以新增一个原子能力，可以复用之前开发过的。

② 然后就是是否启动的问题。就是让用户选择，是否需要启动这个全智能的。

③ 然后这个里面需要加上算法。用户历史用过的所有模型，都需要做打分，
   这个会后台消耗 LLM 额度，需要给用户备注上。
   哪一个模型适合做什么任务，性价比，效率最高。这个还是有点复杂的。
   可以策划开做也行。

④ 本子上底座不涉及隐私的东西。但是可以给用户一个选择，让用户输入一个数据库的
   绝对路径或者是什么样的文件的绝对路径或者文件夹等。这样子这部分的关键词或者
   敏感信息等就可以让用户选择是否使用，也算是一个选项来说。

⑤ 但是整个底座框架，是不做隐私，安全等相关的问题。因为当限制越多，底座本身的
   兼容性就越差。底座只是做到大量兼容，多原子能力。怎么搭配是用户的选择。
```

```text

```

## 一、实测：打分的燃料在哪（关键发现）

### 1.1 ★ 结论：**燃料目前是空的**

打分要有「历史用过的模型」，就得有历史记录。现场核实：

| 数据源 | 实测 | 能否作燃料 |
|---|---|---|
| `会话存储.db` 会话表 | **0 行** | ❌ 空 |
| `会话存储.db` 消息表 | **0 行** | ❌ 空 |
| `会话存储.db` 成本统计列非空 | **0 行** | ❌ 空 |
| `底座运行.db` 六域表 | 有 `任务/作业/协作状态/能力占用/灰度观测/会话`，**无「模型用量」域** | ❌ 无此域 |
| 全底座能力目录搜「调用记录 / 用量统计 / 评分」 | **0 条命中** | ❌ 无此能力 |

**取证命令**：

```bash
python3 -c "
import sqlite3
c=sqlite3.connect('file:工程缓存/运行数据/大语言模型支持库.会话存储.db?mode=ro',uri=True)
print('会话表', c.execute('select count(*) from 会话表').fetchone()[0])
print('成本统计非空', c.execute('select count(*) from 会话表 where 成本统计 is not null').fetchone()[0])
"
```

### 1.2 由此推出的施工顺序（顺序不可颠倒）

```text
没有记录 → 打分无从算起 → 路由智能模式会永远返回「无数据」
⇒ 必须先把「记录」做出来，让真实调用把数据喂进去，
  打分才有燃料。这是 P0 与 P1 的硬依赖。
```

**⇒ 本方案把「记录用量」提为 P0**，而不是等它自然出现。

### 1.3 可复用的现成件（华哥「复用之前开发过的」）

| 已有件 | 复用点 |
|---|---|
| `模型连接器.探测模型端点` | 候选可达性探测（第一层硬门槛直接用） |
| `模型连接器.归一化对话响应` | 已能提取用量（`prompt_tokens`/`completion_tokens`、`input_tokens`/`output_tokens` 两套命名） |
| `SQLite数据库.写入运行态` / `查询运行态` | 唯一的运行态存取入口（不另开文件式状态） |

| 项 | 内容 |
|---|---|
| 能力 id | `大语言模型支持库.模型连接器.记录模型调用` |
| 参数 | `模型`（文本型，必填）<br>`任务类型`（文本型，选填，如 策划/日常/清洗/看图/生图）<br>`成功`（逻辑型，必填）<br>`耗时毫秒`（整数型，选填）<br>`输入令牌`（整数型，选填）<br>`输出令牌`（整数型，选填）<br>`成本`（双精度数型，选填）<br>`端点`（文本型，选填）<br>`备注`（文本型，选填） |

## 三、打分算法（可验证的部分才做）

### 3.1 ★ 先澄清一条口径（与前一版方案不矛盾）

| | 旧口径「不做」 | 本方案「要做」 |
|---|---|---|
| 对象 | **凭主观先验猜**「哪个模型更聪明」 | 凭**历史实测记录统计**「哪个模型在这个任务上成功率更高、更便宜、更快」 |
| 能否验证 | ❌ 无法自动判定 | ✅ 固定数据 → 固定分数，**可复现** |

⇒ 华哥要的「适合做什么任务、性价比、效率最高」**全部是可算量**，因此**可验证**，
不在「不可验证所以不做」之列。**这是本方案成立的理由。**

### 3.2 分数口径（四维加权，权重可配）

```text
对每个候选模型 m，在任务类型 t 下：

  样本数 n(m,t)          ← 低于「最少样本数」则不给分，只标注「样本不足」

  成功率  S = 成功次数 / n          ∈ [0,1]
  效率    E = 1 - min(平均耗时 / 基准耗时, 1)     ← 越接近基准越快越接近 1
  性价比  C = 1 - min(平均成本 / 基准成本, 1)     ← 越便宜越接近 1
  匹配度  M = 该任务类型下的样本占比                ← 该模型是否真做过这类活

  分数 = 权重成功率×S + 权重效率×E + 权重性价比×C + 权重匹配度×M
```

- **权重默认**：成功率 0.4 / 效率 0.2 / 性价比 0.3 / 匹配度 0.1（可经参数覆盖）。
- **基准耗时/基准成本**：取候选集合内的中位数（**相对比较，不写死绝对值**）。
- **样本不足**（`n < 最少样本数`）：**不给分**，如实标注——不编造、不默认满信心。

### 3.3 「全智能」到底智能在哪（可验证的清单）

| 层 | 做什么 | 是否耗额度 |
|---|---|---|
| 第一层 硬门槛 | 上下文超限排除、候选不可达排除（复用探针） | ❌ 不耗 |
| 第二层 统计打分 | 读历史记录 → 四维加权排序 | ❌ 不耗 |
| 第三层 LLM 辅助标注（**可选**） | 候选没历史数据时，让 LLM 按模型名/说明给**能力标签**（策划/日常/清洗…） | ✅ **耗额度，必须标注** |

⇒ 默认**只走前两层**（零额度）。第三层要显式打开，并在返回的 `额度说明` 里写明。

### 3.4 为什么要有「额度说明」这个字段

华哥：「这个会后台消耗 LLM 额度，需要给用户备注上。」
⇒ 返回体固定带 `额度说明`：**本次消耗/未消耗、消耗在哪一步、大约多少 token**。
不让调用方在不知情的情况下被消耗额度。

## 四、隐私：底座只给机制，判断权给用户

### 4.1 与哲学对齐（已核实原文）

`哲学总账.md` 第 9 条：

```text
9.3 隐私/安全是上层业务的事     判据 边界声明     状态 半强制
9.5 相对安全，不做绝对安全       判据 边界声明     状态 半强制
```

⇒ 华哥口径与哲学 9.3 **逐字一致**：底座不做隐私判断。

### 4.2 那「参考路径」是什么

```text
用户显式给一个绝对路径（数据库 / 文件 / 文件夹）
   ↓
底座只做一件事：读它、把它作为路由的一个可选输入维度
   ↓
★★ 底座全程不定义「什么是敏感」「什么是隐私」
   判断规则由用户自己的文件提供，底座只当执行器
   ↓
默认不给该参数 = 完全不涉及，零额外行为
```

| 项 | 设计 |
|---|---|
| 参数 | `参考路径`（文本型，选填）——**绝对路径**，数据库/文件/文件夹皆可 |
| 不给 | 完全不走这一步（默认） |
| 给了 | 底座读该路径 → 与任务描述做匹配 → 匹配结果作为**一个可选排序信号** |
| **底座不做的** | ❌ 不定义敏感词表 ❌ 不做隐私分级 ❌ 不拦截/不告警/不审计 |
| 谁定规则 | **用户**（规则在他给的文件里） |

### 4.3 明确记账（防后人误读为「底座做了隐私」）

> 本机制的本质是「**用户自带规则的可选输入**」，不是「底座的隐私能力」。
> 判据：把 `参考路径` 换成任意普通词表（如「品牌禁用词」），机制**完全一样可用**
> —— 说明它不是隐私专用件，而是通用的「外部规则输入」机制。

## 五、明确不做（记录理由，防重复提议）

| 不做 | 理由 |
|---|---|
| 底座内置隐私/安全分级 | 华哥：「**限制越多，底座兼容性越差**」；哲学 9.3 |

| 默认消耗额度 | 默认零额度；LLM 辅助必须显式打开且标注 |

## 六、验收判据

```text
P0 记录（可完整验证）：
  ① 记 3 条真实记录 → 查询回读，条数与内容逐字段一致
  ② 幂等：同 记录id 重复写 → 不产生重复行

  ⑤ 固定 10 条记录 → 汇总分数固定可复现（跑两次结果逐位相同）
  ⑥ 样本不足（n < 最少样本数）→ 如实标注，不编造分数
  ⑦ 分组正确：按任务类型分别汇总，不跨类型混算

P1 路由（只验可验证的）：
  ⑧ 保守模式（默认）：不读历史记录、不耗额度，只按硬门槛排序

  ⑩ 智能模式：同数据同输入 → 排序稳定；每项都带理由
  ⑪ 额度说明：默认路径写明「未消耗额度」；开 LLM 辅助时写明消耗
  ⑫ 参考路径：不给 → 行为与不给前逐字段相同；给了 → 只影响排序信号

真实 HTTP（唯一正式验收）：
  ⑬ 全部经 40007 网关 GET/POST 黑盒验证，不直调源码
```
