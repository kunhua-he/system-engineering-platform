# 视图「错误码 → 建议」口径说明（包级）

适用范围：`开发工具/统一能力入口/视图/*.py` 五个视图（普通用户视图 / 调用Agent视图 /
组件开发Agent视图 / 维护者视图 / 发布者视图）。

本文件回答三件事：**谁持有「错误码 → 建议」表**、**维护者/发布者视图为何没有该表**、
**视图侧本地拒绝码的中文取值口径**。三问的判据一律回生产实现与设计源头，不写死码表。

| 视图 | 表 | 设计源头（工作包「输出」口径） |
|---|---|---|
| 普通用户视图 | `错误码建议表` | 工作包01：「…结果和**处理建议**；不泄漏实现、密钥和内部日志」 |
| 调用Agent视图 | `错误说明表` + `建议操作表` | 工作包02：「…结构化错误和**建议操作**」 |

## 二、维护者视图 / 发布者视图「没有建议表」= **设计选择，非缺陷**

四条取证（逐条可复跑）：

1. **设计源头未要求**：`工作包清单.json` 工作包04（维护者视图）的输出口径是
   「依赖、提供者、资源、证据、冲突裁决、诊断和**回滚建议**；无签名发布权限」——
   这里的「建议」指 `维护者视图.回滚建议` 返回的**只读业务字段**（返回键 `建议`），
   不是「错误码 → 建议」映射层；工作包05（发布者视图）口径为「审核、签名、安装、
   灰度、激活、撤销、回滚；源码变化后旧签名失效」，**不含**任何建议要求。
2. **产出者侧根本没有建议字段**：`平台控制面/统一入口.py:117 执行操作` 的统一结果结构
   是 `成功/错误码/消息` + 业务字段（鉴权拒绝分支 `:123` 即
   `{"成功": False, "错误码": 拒绝码, "消息": "权限不足"}`）。两视图把失败原样外抛，
   属**如实透传产出结果**，不是漏了一层映射。补表等于在视图侧凭空造一层产出者没有的语义。
3. **实测对外失败结构分层**（本机真跑，2026-09-17）：
   - 维护者视图 `查看依赖(无效令牌)` / `回滚建议(发布不存在)` → 返回键
     `['成功','消息','错误码']`；发布者视图 `审核候选/撤销` 同 → 三键，**无建议字段**；
   - 普通用户视图 `调用能力` → `['可重试','处理建议','成功','消息','结果','错误码']`；
   - 调用Agent视图 `调用能力` → 含 `错误说明` + `建议操作`。
   前两个视图的服务对象是平台内部专业角色（维护者=角色等级 4、发布者=5），
   按错误码自行处置；后两个面向普通用户/调用 Agent，需要自助文案，故持有建议层。
4. **规避同一视图内的语义分裂**：维护者视图的「建议」已是业务语义（`回滚建议` 与
   返回键 `建议`）。再加一层「建议操作」，同一视图里两个「建议」含义分裂，
   阅读者无法区分「业务只读建议」与「错误处置建议」。

**结论：不补两张表。** 判定条件（将来若要变更）：必须同时
(a) 先改设计源头（工作包/包级说明）承认该层存在；(b) 表内中文键口径与
生产对外错误码对齐；(c) 按 `平台控制面/授权/说明/使用说明.md` 的
「消费侧视图的错误码→建议表须同时持有中文键与历史英文键」要求建表。
即：`授权/说明/使用说明.md` 那条要求是**以表存在为前提**的条件约束，
并未要求每个视图都必须建表——本判定与该要求不冲突。

## 三、错误码口径（决策 0003「对外错误只走中文」）

- 对外错误码与说明一律中文；视图侧**禁止自造英文码**。
- 视图**本地拒绝分支**（不经产出者的判定）的错误码，必须逐条回产出实现核准后取值；
  产出者仍是英文时**不得单边改名**（那会造出契约造假漂移），只能回报。
- 本包现状（2026-09-17 收口后，视图域内已无英文拒绝码）：

| 视图 · 分支 | 错误码 | 取值来源（产出者真实返回） |
|---|---|---|
| 发布者视图.审核候选 / 签名失效检查（制品缺失） | `制品不存在` | `平台控制面/统一入口.py` `_签名发布`；消费者契约「签名与发布」错误码 |
| 发布者视图.签名（密钥环无私钥） | `未导入签名密钥` | 同上 |
| 发布者视图.签名（包仓库签名失败） | `签名失败` | 同上 |
| 发布者视图.撤销（发布记录缺失） | `发布不存在` | `统一入口._回滚` 消息 + `运行核心/统一网关` 稳定码表；与 `维护者视图.py:125` 同码（`测试_工作包04_维护者视图.py` 已断言） |
| 发布者视图.签名失效检查（制品无签名） | `未签名` | `平台控制面/策略中心.py` `_签名判定`（公开能力 `平台控制面.策略闸门.判定签名策略` 实测 `错误码='未签名'`） |
| 调用Agent视图.搜索/查看/调用（无效令牌） | `会话不存在` | `平台控制面/授权.py:226/249`、`授权/实现/能力入口.py:154`；消费者契约 全局错误码 |
| 调用Agent视图.查看能力（令牌有效但能力id 缺失） | `能力必填` | `平台控制面/统一入口.py` `_查看能力` |
| 调用Agent视图.调用能力 | `能力不存在`/`提供者不可用`/`调用超时`/`调用失败` | `统一入口.py:367/369` + 注册表实现 |
| 调用Agent视图.搜索能力 | `未知操作`/`越权操作`/`会话过期`/`会话不存在`/`内部错误` | 全局错误码（鉴权 + 未知操作 + 内部异常兜底） |

- `会话不存在`：`调用Agent视图` 两表（`错误说明表` + `建议操作表`）此前缺该中文键，
  无效令牌时落兜底句（`搜索失败` / `请检查后重试`）＝文案降级；本批已补齐中文键，
  两表键集保持一致（`测试_视图错误码键一致.py` 的锁文件登记项同步清空）。
- 历史英文键（`PERMISSION_DENIED` / `SESSION_EXPIRED` / `CALL_TIMEOUT` /
  `CALL_FAILED` / `PROVIDER_UNAVAILABLE` / `RESOURCE_EXCEEDED`）在两张建议表内
  **保留不动**：仅供历史夹具/外部调用方传英文码时兜底，中文键才是当前生产口径
  （见 决策 0003 与 `平台控制面/授权/说明/使用说明.md`）。

## 四、回归守护与验证方式

- 守护测试：`测试中心/平台控制面/测试_视图错误码键一致.py`
  （三张表的键集判据 + 真实调用码命中 + 锁文件登记项双向约束，登记项现为空）。
- 相关回归：`测试中心/平台控制面/测试_工作包01_普通用户视图.py`、
  `测试_工作包02_调用Agent视图.py`、`测试_工作包04_维护者视图.py`、
  `测试_工作包05_发布者视图.py`。
- 跑法（项目根）：
  `export PATH=/Library/Developer/CommandLineTools/usr/bin:$PATH; unset PYTHONPATH;`
  `python3.14 -m unittest 测试中心.平台控制面.测试_视图错误码键一致`
- 判据方向（谁下次改错就拦谁）：表里出现生产不返回的码 → 红；生产可达码缺键 → 红；
  中文码落兜底句 → 红；历史英文键被误删或与中文键文案分裂 → 红；
  登记缺口仍在但已被修好 → 红（要求删登记项）。
