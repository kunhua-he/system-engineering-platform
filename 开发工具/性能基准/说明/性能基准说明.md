# 性能基准（B2）· 说明与实测锚点

【位置】`开发工具/性能基准/`
【口径】一律 `python3.14`；跑前 `unset PYTHONPATH`（本机 `python3` 是 3.9.6，会假绿）
【依赖】只用标准库：`time` / `statistics` / `json` / `threading` / `http.client` / `sqlite3`（经能力间接）
【边界】不引第三方（不引 pytest-benchmark）；不加载模型、不占显存；不碰正式运行库；
不到制品仓库、不调 HTML 黑盒验证器；不使用其他仓库的 MCP/记忆/代码地图/验证证据。

## 一、为什么要有它

平台此前**完全没有度量手段**，所以「每调用一线程开销」「网关空跑多少 QPS」「SQLite 写多少 TPS」
这类问题只能靠感觉争论。本工具把争论变成可复现、可对比、可落盘的数字。

## 二、文件职责

| 文件 | 职责 |
| --- | --- |
| `运行基准.py` | 命令行入口：解析参数 → 装配 → 跑场景 → 落盘 JSON + 中文摘要 + 可选对比 |
| `基准口径.py` | 「怎么量」的规矩：错误分类与退出码、参数校验、串行/并发采样、分位统计、落盘/读回、摘要渲染 |
| `基准环境.py` | 被测环境：最小包集装配、进程内 HTTP 网关、工程根与正式运行数据根解析、HTTP 最小请求 |
| `基准场景.py` | 四个场景实现 + 固定输入 + 场景名解析 |
| `结果对比.py` | 两次结果的配对对比（p50/p99/吞吐变化率） |
| `反向验证.py` | 反向验证：故意喂坏参数/坏输入 → 必须明确失败；正向断言（抖动、残留、未污染运行库） |
| `结果/` | 落盘的机器可读结果 JSON（每次运行一个新文件，可互相 `--对比`） |

## 三、四个场景与口径

### 1. 原子能力直调（热路径 p50/p99）
- 被测实现：`数据操作支持库.数据交换.反序列化JSON` / `.序列化JSON`（纯计算，标准库）
- 两条链路分别测：`唯一能力调用服务.调用能力` 与 `后端核心.调用`（后者多出运行上下文进出、
  活动请求计数、权限表查询 —— 差值即该层真实成本）
- **不给 `超时秒` ⇒ 同线程直调分支**（不建执行线程），是热路径最低开销形态
- 每次调用都断言返回值与固定输入一致，值不符即判场景失败

### 2. 网关空跑（QPS 与 p50/p99）
- 被测对象：**进程内回环测试服务器**（真实 HTTP 网关 + 网关核心 + 后端核心），
  回环地址 + 端口 0 自动分配 + 免凭证；**不起制品、不占制品仓库**
- 三项：`GET /健康`（纯网关空跑）、`POST /网关/调用`（全链路最小业务调用）、
  同一调用在 `--并发 N` 下的并发吞吐
- 也接受 `--网关地址 http://...` 打**外部已激活网关**（只发最小请求、只读轻量）
- 关键口径（写进结果注释）：网关响应带 `Connection: close`，样本含客户端建连开销（平台现状，
  非基准额外开销）；不带 `X-请求-id` 时网关幂等表不参与
- **限流必须显式放宽**：默认限流器是「单能力频率 200 次/10 秒」（QPS 上限约 20），
  基准要在一个窗口内打上千次同一能力 —— 不放宽只会量到 429。进程内网关把五处频率与
  单维度并发放宽到覆盖 `--轮数`，放宽取值如实写进结果注释 + `限流累计拒绝数`；
  对**外部网关**无法放宽，故命中 429 时明确失败（不把限流上限当成处理能力）

### 3. SQLite 写（TPS）
- 经唯一 SQLite 支持库 `数据库连接支持库.SQLite数据库.事务执行` 写入
  - 每次调用 1 条 INSERT（单语句事务）→ TPS
  - 每次调用 10 条 INSERT（同事务）→ TPS / 每行毫秒 / 每秒写入行数
- 库文件是**本次运行的独立临时库**，运行结束随临时目录删除
- **不污染正式运行库**：运行前/后对 `解析运行数据根()` 给出的正式目录做只读快照，
  两份快照必须一致（不一致即判场景失败），该结论写进结果 `附加结论`
- 写后经 `查询` 能力读回 `COUNT(*)`，行数与期望不符即判场景失败（不允许「写失败但 TPS 好看」）

### 4. 线程包装开销（直接回答「每调用一线程」之争）
- 同一能力、同一固定输入，唯一差别是 `超时秒` 是否给出：
  - 不给 ⇒ 同线程直调
  - 给出 ⇒ 经 `运行核心/能力调用/超时执行.py` 的执行器**新建一条执行线程**并等完成事件
- 另测**裸线程基线**（`threading.Thread.start()+join()` 空函数）= 纯线程创建/回收的地板价，
  用它把差值拆成「纯线程」与「准入闸门占用归还 + 完成事件等待 + 上下文在子线程重新进入」
- 另做**同线程直调复测**：复测 p50 与首测 p50 的相对偏差远小于差值，差值才可信
- 断言：场景结束时执行器「仍在运行残留数 = 0」且「累计超时次数 = 0」，否则判场景失败
  —— 不允许用泄漏的线程换好看的数字

#### 本次实测锚点（本机 macOS / python3.14 / `--轮数 2000 --预热 200 --重复 3 --并发 8`）

| 测量项 | p50 | p99 | 每秒次数 |
| --- | --- | --- | --- |
| 唯一能力调用服务.调用能力（反序列化JSON，无超时秒） | 0.0188 ms | 0.0335 ms | ≈ 51974 次/秒 |
| 后端核心.调用（反序列化JSON，无超时秒） | 0.0204 ms | 0.0351 ms | ≈ 47360 次/秒 |
| HTTP GET /健康（网关空跑） | 0.4478 ms | 1.1285 ms | ≈ 2008 次/秒 |
| HTTP POST /网关/调用（全链路） | 0.6244 ms | 1.2738 ms | ≈ 1446 次/秒 |
| HTTP POST /网关/调用（并发 8） | 4.9019 ms | 8.5794 ms | ≈ 1571 次/秒 |
| SQLite 事务执行（1 条 INSERT） | 0.6678 ms | 1.578 ms | ≈ 1256 TPS |
| SQLite 事务执行（10 条 INSERT，同事务） | 0.7384 ms | 2.2382 ms | ≈ 1211 TPS（≈12111 行/秒） |
| 同线程直调（无超时秒） | 0.0191 ms | 0.0358 ms | ≈ 49984 次/秒 |
| 经超时执行器线程包装（超时秒=5） | 0.0759 ms | 0.1676 ms | ≈ 11478 次/秒 |
| 裸线程基线（空函数 start+join） | 0.0275 ms | 0.0691 ms | ≈ 30771 次/秒 |

**「每调用一线程开销」的实测结论（可复现）**：

- 线程包装给每次调用增加 **≈ 56.6–76.4 微秒**（p50，三次/多次运行区间），
  即同线程直调 p50 × **约 4.0–5.0 倍**；串行吞吐从 ≈ 5.0 万次/秒降到 ≈ 1.1–1.2 万次/秒。
- 其中**纯线程创建+回收只占 0.36–0.48**（裸线程基线 p50 0.026–0.0275 ms ≈ 26000–27500 次/秒），
  其余是准入闸门（全局 + 每能力两把）占用/归还、完成事件等待、上下文在子线程重新进入。
- 该差值**不随并发放大成灾**：网关默认工作线程上限 256、执行线程全局上限 256，
  串行路径下占用恒为 1，不触发限流。
- 注意口径差异，别混用：`--轮数 50` 时差值约 0.076 ms，`--轮数 2000` 时约 0.057 ms
  （短采样里线程调度噪声占比重）。**比较线程开销一律用 `--轮数 ≥ 2000`**。

## 四、用法

```bash
# 全量基准（默认 轮数 2000 / 预热 200 / 重复 3 / 并发 8），结果落 开发工具/性能基准/结果/
unset PYTHONPATH && python3.14 开发工具/性能基准/运行基准.py

# 只跑线程包装开销，加大轮数看稳定值
unset PYTHONPATH && python3.14 开发工具/性能基准/运行基准.py --场景 线程包装开销 --轮数 20000

# 与上一份结果对比（可给多次）
unset PYTHONPATH && python3.14 开发工具/性能基准/运行基准.py \
  --对比 开发工具/性能基准/结果/基准结果-20260918-182155.json

# 打外部已激活网关（只发最小请求；该网关需已把限流放宽）
unset PYTHONPATH && python3.14 开发工具/性能基准/运行基准.py --场景 网关空跑 \
  --网关地址 http://127.0.0.1:8791 --轮数 500

# 反向验证（坏参数/坏输入一律明确失败 + 正向断言）
unset PYTHONPATH && python3.14 开发工具/性能基准/反向验证.py
```

主要选项：`--场景`（默认 全部，支持逗号分隔）、`--轮数`、`--预热轮数`、`--重复`、`--并发`、
`--抖动上限`、`--超时秒`、`--输出目录`、`--名称`、`--对比`、`--网关地址`、`--网关请求id 开|关`、
`--不做抖动自检`；`--帮助` 打印用法。

## 五、退出码（基准自身的失败语义）

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功（含抖动自检通过） |
| 2 | 参数错误：非法/越界/未知选项/未知场景/空场景名/结果文件不可读 |
| 3 | 场景失败：调用失败、返回与固定输入不符、行数读回不符、网关非 200、线程残留 |
| 4 | 口径失败：空样本统计、样本数不符、墙钟非正、抖动自检不通过（结果仍已落盘） |
| 5 | 落盘失败：输出目录不可用/不可写 |

**本工具不新增任何网关公开错误码** —— 新增公开码必须同时登记到
`运行核心/统一网关/本地网关.py` 的 公开错误码状态映射 与 `网关核心.py` 的 公开错误说明表，
而本任务只允许新增 `开发工具/性能基准/` 下的文件。因此基准的失败一律用**进程退出码 + 中文 stderr**
表达，不冒充公开错误码。

## 六、反向验证（`反向验证.py`，当前 36 项全通过）

覆盖的「故意弄坏」清单：

1. 坏参数 15 类（轮数 0/负数/超上限/非数字、预热超上限、重复 0、并发 1、抖动上限非数字、
   超时秒 0、未知场景、空场景名、网关地址非 http、网关请求id 非开/关、名称含路径分隔符、
   未知选项）→ 全部退出码 2
2. 输出目录不可写 → 退出码 5
3. 空样本统计 / 空样本分位 / 非数值样本 → 口径失败（**不返回 0 毫秒**）
4. 并发数 1 → 参数错误（不冒充并发吞吐）
5. 落盘到「文件下面的子目录」/「普通文件当目录」→ 落盘失败
6. 喂坏 JSON、调用不存在的能力、空返回 → 场景失败（不静默出 0）
7. SQLite 场景喂坏库路径 → 场景失败（不给 TPS）
8. 抖动自检对**确定性不稳定**的两轮（第一轮快第二轮慢）必须判不通过；
   且「抖动不通过 ⇒ 退出码 4」这条链路单独断言
9. 正向断言：真实跑一遍退出码 0、抖动自检通过、重复稳定性有明细、
   SQLite 场景证明正式运行数据根未被写入、行数读回一致、线程包装残留为 0 且差值 > 0

## 七、已知剩余风险

1. **数字受机器负载影响**：本机同时跑别的重任务时 p50 会漂。工具做了两重防线
   （两轮同输入抖动自检 + `--重复 N` 稳定性汇总），但抖动上限 0.35 是**宽容值**，
   不通过的判定是「不许下结论」，不是「被测对象有问题」。
2. **并发吞吐对样本量敏感**：墙钟含 `--并发` 条线程的启动与起跑同步，`--轮数` 太小会低估。
   已在结果注释里写明「建议 `--轮数 ≥ 500` 再读并发 QPS」。
3. **网关 QPS 含建连开销**：平台现状是响应带 `Connection: close`（`本地网关.py` 显式发送），
   故样本必然含 TCP 建连/断连；本工具**如实标注**但不消除它 —— 消除需要改网关（不在本任务范围）。
4. **进程内网关放宽了限流**：为测处理链路而非限流拒绝，进程内网关把频率/并发上限放宽；
   放宽取值全部写进结果注释。**外部网关无法放宽**，命中 429 即明确失败。
5. **SQLite 数字只代表默认 PRAGMA**：未改 `journal_mode`/`synchronous`，正式运行库若做过
   调优，数字不可直接套用。
6. **线程包装差值只反映串行路径**：并发下的线程调度、GIL 争抢、准入闸门竞争未单独度量
   （并发场景目前只覆盖网关；`超时执行器` 的并发拒绝路径未纳入基准）。
7. **不含 TLS / 公网往返 / 前端渲染**，也不是端到端业务链路（业务能力耗时由能力自身决定）。
8. 装配是**最小包集**（2 个纯计算包）：全量装配（全部支持库 + 模块库）的启动代价不在本基准口径内。
