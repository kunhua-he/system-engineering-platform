# 配置适配 · 设计说明

> 状态：**生效（2026-09-18 配置双入口收口）**
> 口径：实测（引用前重跑取证命令）
> 维护者：项目适配层/配置适配

## 一、这个包是什么

**项目门面层**：全仓**唯一**的「项目配置加载与合并」入口。
调用方只经本包读取项目配置，不感知配置来自文件/环境变量/提供者配置。

对外公开符号（`__init__.py`）：

| 件 | 公开符号 | 职责 |
|---|---|---|
| `配置读取.py` | `配置读取结果`、`读取JSON配置`、`读取配置目录` | 统一配置读取器 + 结果结构（含 配置/来源表/问题列表/警告列表） |
| `配置合并.py` | `合并配置`、`段级深合并配置`、`解析环境配置` | 固定五层覆盖顺序合并 + 段级深合并 + 环境配置文件解析 |
| `配置校验.py` | `校验配置`、`配置校验结果` | 未知项/必填缺失/类型错误报告 + 明文密钥检测（fail-closed） |
| `配置适配.py` | `配置结果`、`读取配置` | 项目配置目录（`项目配置/项目配置.json`）读写入口。**当前零调用方**（见 §四 待决） |

**覆盖顺序（固定，不得改动）**：支持库默认配置 → 项目默认配置 → 当前环境配置 → 外部提供者配置
→ 运行入口显式覆盖。每一步记录来源，最终产出 `合并配置 + 来源追踪表`。

**现役唯一消费方**：`启动监督器/健康监督.py::读取健康监督配置`（经该处落 健康监督周期/保留策略）；
另有 `开发工具/组件合规/合规测试包.py` 在合规用例内引用 `校验配置`。

## 二、与 `支持库/适配层/提供者配置读取/` 的分工（收口定性结论）

**定性：合法门面层 / 提供者层分层，不是「同一件事两套实现」——不合并。**

| 维度 | `项目适配层/配置适配/`（本包，门面层） | `支持库/适配层/提供者配置读取/`（提供者层） |
|---|---|---|
| 读哪份数据 | **项目**配置目录（`项目适配层/项目配置/*.json`）+ 支持库默认值 + 显式覆盖 | **外部提供者**配置（`支持库/适配层/提供者配置/提供者配置.json`），一份第三方/外部协议数据 |
| 交付什么 | 五层合并结果 + 来源追踪 + 校验报告 | 按**能力 id** 取配置段（供提供者路由/初始化） |
| 覆盖/合并 | 有（固定顺序，fail-closed） | 无（不合并、不解释业务语义） |
| 校验/来源追踪 | 有 | 无 |
| 公开符号 | `配置读取结果`/`读取JSON配置`/`读取配置目录`/`合并配置`/`解析环境配置`/`校验配置`/`配置校验结果` | `读取提供者配置`/`获取能力配置` |
| 层归属（`运行核心/依赖防火墙.py::允许依赖表`） | `项目适配层` → {公共契约, 运行核心} | `支持库` → {公共契约} |

**为什么不能合并（三条硬依据）**：

1. **分层方向不允许**（决定性）：`允许依赖表` 里 `项目适配层` **不允许依赖 `支持库`**。
   把提供者层并进本包 = 本包反向 import `支持库` = 越层依赖，发布门禁判红；
   把本包下沉进 `支持库` = 门面层把「项目」概念带进第三方翻译层，破坏「适配层只做第三方边界翻译」。
   合并的前提是先改分层口径（层表 + 头注释镜像块 + 预留授权体检），代价远大于收益。
2. **包级能力面不交集**：两边**无同名公开符号**（`读取JSON配置` 是同签名同名函数，但分属
   「提供者层内部原子件」与「门面层公开入口」，各自被本层消费者使用，不构成调用方二选一）。
3. **两边只有目录/文件撞名，没有职责撞车**：收口前 `支持库/适配层/配置读取/`（目录名）与
   `配置适配/配置读取.py` 撞名，是「看着像两套实现」的唯一来源；提供者层已改名
   `提供者配置读取`，歧义消除。

同类先例：`开发文档/方案/结构债处置方案_20260916.md` D-6（唯一实现 + 同名门面包）判为合法分层。

## 三、调用方契约（改本包前必读）

- 本包是**项目门面层，不是能力包**：无 `包声明.json`/`能力定义.json`，不进正式包索引
  （`开发工具/项目编译/项目编译器.py` 固定复制表不含本包；本包随 `项目适配层` 进项目侧）。
- **只允许经门面层读项目配置**：禁止实现代码偷偷读取任意配置文件；禁止未知字段静默接受；
  禁止缺失必填配置自动伪造默认值（`配置读取.py` 模块 docstring 原文口径）。
- 改动本包公开符号即改动 `启动监督器/健康监督.py` 的契约，须同批做反向验证
  （同一输入同一输出，见 `开发文档/分析/配置双入口收口_20260918.md` §四）。
