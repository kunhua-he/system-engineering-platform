# 健康监督（启动监督器.健康监督）设计说明（设计权威）

> 本文是本包的**设计哲学与边界权威**：它为什么存在、管什么、不管什么、失败如何表达。
> 调用口径——能力、参数、返回结构、错误码与调用示例——以同目录 `使用说明.md` 为准。

## 为什么有这个包

债务清单 **C-7**（2026-09-16 实测）：`启动监督器/` 有 2 个 py、**0 个 `包声明.json`**，
全仓含「健康」的能力 id = **0**。于是 `平台控制面/统一入口.py:107` 的
`注册健康检查(*, 包id, 检查函数)` 注册进去的检查函数**没有任何执行方**——
注册了、没人跑、也不会有告警。这正是「治理类动作缺少可调用面」的老毛病：
能力在进程内可见，经网关不可复现。

## 本包是什么

把 `容量基线` 的**只读与判定语义**切成可经网关调用的原子能力。事实唯一落
`启动监督器/容量基线.py`（必需基线字段 + 对照表 + 采样口径），本包只做
**能力边界校验与结果归一**。

| 能力 | 覆盖的既有动作 | 事实落点 |
|---|---|---|
| `执行健康监督` | `容量基线.声明基线` + `实测采样` + `对比基线` | 真实机器采样（只读） |
| `查询健康检查项` | `容量基线.必需基线字段` + `实测采样` | 同一事实源，不另立清单 |

## 管什么 / 不管什么

**管**：按调用方声明的容量基线跑一次真实采样并给出「健康 / 不健康」结论与超限项；
列出本监督面已注册的检查项与其条数。

**不管**（本轮明确排除，不是遗漏）：

- **超限处理链**（`停止接收` → `拒绝排队` → `排空` → `优雅释放` → `证据` → `熔断`）
  是执行类与写类动作：会真改运行态、真落 `工程缓存/启动监督器/容量基线证据.jsonl`，
  不在本轮只读/判定能力面；
- **周期探针**（`启动监督器/健康监督.py` 的 `系统提供者健康监督`）要起后台线程、
  跑子进程、写健康证据，同样不在本轮能力面；
- **本包不替调用方编造阈值**：`基线` 是必填参数，缺字段或非正数一律 `参数不合法`。

## 失败如何表达

- `基线` 不是字典、缺少必需字段、字段非正数 → `参数不合法`，原文透传
  `容量基线.声明基线` 的失败说明，**不吞异常、不用默认值伪装通过**。
- 采样项不可用（`ps`/`pgrep`/句柄目录不可用）不算崩溃：`容量基线.对比基线`
  会把它记为 `超限项`（带 `采样失败=true` 与 `错误说明`），`执行健康监督`
  归一为 `健康=false`——**采样失败绝不伪装成健康**。
- `查询健康检查项` 在采样整体失败时报 `采样失败`，**不返回半份清单**。

## 与旧实现的关系

`启动监督器/容量基线.py` 与 `启动监督器/健康监督.py` **一个字没改、也没删**——
它们是唯一语义实现。本包是它们的能力面，不是第二套实现。平铺文件是否包化（D-10）
单独立项，不在本包范围。

## 已知边界（如实记录，不做假绿）

`启动监督器/` **不在** `公共契约/正式根.py` 的 `正式根名表`（当前 5 根：
支持库/模块库/技能库/平台控制面/运行核心），因此本包**不参与装配发现**
（与债务 C-5 `项目适配层` 同类）。要让它进装配，需要把 `启动监督器` 加进
`公共契约/正式根.py:23 正式根名表`——该文件属公共契约域，本包不越域改。
本包自身按九要素建齐、契约已编译、摘要已闭合，进名表后即可被装配发现。

**同名遮蔽**：包目录 `启动监督器/健康监督/` 与既有平铺文件
`启动监督器/健康监督.py` 同名，Python 中**包优先于同名模块**，会让既有
`from 启动监督器.健康监督 import 系统提供者健康监督`（测试中心 3 处）失效。
本包在入口用 `__getattr__` **惰性回落**到那个平铺文件（装载细节见
`实现/兼容平铺模块.py`），平铺文件一个字未改，仍是周期探针与配置读取的唯一实现；
回归验证：`测试_健康监督` / `测试_健康配置` / `测试_提供者生命周期` 共 62 项通过。
根治办法是把平铺文件包化（D-10），单独立项。

## 设计哲学依据

第 1 条（干净底座与唯一化：同一件事不留两套实现，本包只是把既有动作收口到可调用面）、
第 10 条（治理类能力要补进对应的那个库：`注册健康检查` 无执行方，缺什么补什么）、
第 2 条 1 项（分层与归属固定：判定留在 `容量基线.py`，本包只做边界与归一）。
