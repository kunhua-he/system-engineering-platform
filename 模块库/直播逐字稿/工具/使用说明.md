# 直播逐字稿 · 批量队列工具

消费者侧调用工具：**不在模块内**，通过平台唯一网关 `POST http://127.0.0.1:40007/网关/调用`
调用 `直播逐字稿.全自动精校`，把整批录屏逐场跑成两份权威稿（还原稿 + 总结稿）。

## 文件

| 文件 | 作用 |
|---|---|
| `批量精校队列.py` | 批量队列：逐场出两份稿，断点续跑、失败重试、并发多场 |
| `安装或卸载队列常驻.py` | 把队列注册成 LaunchAgent 常驻（系统托管，不依赖终端会话） |
| `com.huashi.zizhugao-queue.plist` | LaunchAgent 定义（KeepAlive + RunAtLoad） |

## 用法

```bash
# 试跑最短 3 场（快速验证链路）
python3.14 批量精校队列.py --最短场次 3

# 全量（默认并发 2 场）
python3.14 批量精校队列.py

# 只跑某个主播目录 / 指定并发 / 指定重试次数
python3.14 批量精校队列.py --仅主播 03_河北 --并发场次 3 --重试次数 3

# 常驻（无人值守）
python3.14 安装或卸载队列常驻.py 安装
python3.14 安装或卸载队列常驻.py 状态
python3.14 安装或卸载队列常驻.py 卸载
```

## 设计要点（都是踩过坑后的选择）

1. **并发场次的依据**：GPU 只在**转写**阶段争用（约占一场三分之一时间），**裁决**阶段是在等远程模型，
   所以并行多场能提升总吞吐；默认 2，GPU 富余时可提到 3。
2. **句柄（模型连接）每场独立**：句柄默认 1800 秒无人使用即被回收，整批复用会在长批中途失效
   （实测报「句柄不存在」，整场判不通过）。
3. **失败重试 + 退避**：上游端点会间歇返回 503/超时。队列重试 3 次，模块内也会识别瞬时错误退避重试。
4. **断点续跑**：已有稿子默认跳过（`--强制` 可重跑）；缓存目录按「场次 × 模式」隔离，重跑只补缺。
5. **进度可查**：进度写 `005_批量进度.json`，日志追加 `005_批量日志.log`（脚本内定义为
   `<权威落点>/00_批量进度.json` 与 `00_批量日志.log`）。
6. **常驻而非挂终端**：批量任务要跑十几小时，挂在交互式会话上会被会话清理 SIGTERM 打断；
   LaunchAgent 由系统托管，异常自动拉起、重启机器也能回来。

```python

    "附加要求": "「斑」不能写成「班」……",          # 易错词校正、行业口径
}
```
