## 开工编排.开工准备（开工准备）

**说明**：开发统一开工入口：逐条做修改路径的项目根边界校验（越界即‘路径越界’失败），再取 Git 提交/分支/工作区状态、证据账本成功记录与代码地图可用性，返回开工上下文与缺失原子能力清单。 返回值另含 任务类型/强规范 两键：按「任务」文本把本次工作映射到底座任务类型字典，随开工上下文一并返回该类强规范，使接入方无需额外调用即可拿到本次任务的规范（只增字段，老键语义不变）；并现场查这批路径的文件租约实况，返回 撞车清单（别的会话正在改的路径）与占用者清单，让开工方在动手前就知道会不会撞车。

**参数表**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 任务 | 文本型 | 是 | None | 本次开工的任务说明 |
| 项目根 | 文本型 | 是 | None | 项目根目录绝对路径，同时是修改路径边界校验的根 |
| 修改路径 | 列表型 | 否 | [] | 本次拟修改的仓库相对路径清单，逐条做项目根边界校验 |
| 历史数量 | 整数型 | 否 | 3 | 返回最近 N 条成功验证证据（1-3） |
| 验证级别 | 文本型 | 否 | 工作包 | 工作包 / 合并波次 / 阶段收口 / 正式发布 |

**返回结构**：{'类型': '结果型', '值结构': {'项目': '字典型', '代码地图': '字典型', '证据可信度': '字典型', '最近成功验证': '列表型', '工作区快照': '字典型', '路径校验': '字典型', '文件租约': '字典型', '缺失原子能力': '列表型', '下一步': '列表型'}}（统一结果：成功/值/错误）

## 开工编排.开工即占（开工即占）

**说明**：开工即原子申请租约、全成功才开工（C-14 真自动门）：先做与 开工准备 相同的路径边界校验，再原子认领全部修改路径的文件租约；任一条被占用即整体不开工并如实回报占用者，绝不部分认领。返回 已开工/开工上下文/租约/失败原因。

**参数表**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 任务 | 文本型 | 是 | None | 本次开工的任务说明（同时作为租约归属凭据） |
| 项目根 | 文本型 | 是 | None | 项目根目录绝对路径，同时是修改路径边界校验的根 |
| 修改路径 | 列表型 | 是 | None | 本次拟修改的仓库相对路径清单；逐条做边界校验后整批原子认领 |
| 所有者 | 文本型 | 否 | None | 租约归属标识；留空由底层按任务推导 |
| 持有秒 | 双精度数型 | 否 | None | 租约时长（秒）；留空用底层默认 |
| 存储标签 | 文本型 | 否 | None | 租约存储标签；留空用底层默认 |
| 存储目录 | 文本型 | 否 | None | 租约存储目录；留空用底层默认 |

**返回结构**：{'类型': '结果型', '值结构': {'已开工': '真=全部路径已原子认领可开工；假=有冲突未开工', '开工上下文': '与 开工准备 同构的上下文', '租约': '含 状态/租约id清单/申请清单/认领数/说明', '失败原因': '未开工时说明冲突（含占用者与占用开始时间）'}}（统一结果：成功/值/错误码/错误说明）

| 文件已被占用 |
| 提供者不可用 |

**调用示例**：

```python
开工编排.开工即占(任务=值, 项目根=值, 修改路径=值, 所有者=值, 持有秒=值, 存储标签=值, 存储目录=值)
```

## 开工编排.取任务类型规范（取任务类型规范）

**说明**：按「本次任务」文本取底座任务类型字典里命中的强规范（只读投影）：双字滑窗子串匹配，不调大模型；只返回命中的几类（默认上限 3），不返回全量规范；未命中时如实返回空与提示，不捏造规范。

**为什么要它**：开发规范此前靠主代理记性注入子代理任务信，漏注入就必然重踩（实测连派 6 路全漏）。做成底座能力后，任何接入方（Hermes 或其他 Agent）调同一个入口即得同一份规范，不依赖某家客户端的记性。

**参数表**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 项目根 | 文本型 | 是 | None | 项目根目录绝对路径；字典按 开发文档/规范/任务类型规范.json 定位 |
| 本次任务 | 文本型 | 是 | None | 一句「我正要做什么」，用于映射任务类型 |
| 返回类数 | 整数型 | 否 | 3 | 最多返回几个命中类型（1-5）；超限按相关度截断并如实标 是否截断 |

**返回结构**：{'类型': '结果型', '值结构': {'任务类型': '每项含 任务类型/强规范/判据/原文位置/命中词/相关度', '是否截断': '命中类数超过上限时为真', '提示': '未命中或字典缺失时的可执行提示'}}（统一结果：成功/值/错误码/错误说明）

**错误码表**：

| 错误码 |
| --- |
| 参数不合法 |
| 文件不存在 |
| 提供者不可用 |

**调用示例**：

```python
开工编排.取任务类型规范(项目根=值, 本次任务=值, 返回类数=3)
```
> 示例为骨架需验证：能力搜索数据无现成示例，按参数自动生成。

**字典与扩展**：任务类型与强规范住在 `开发文档/规范/任务类型规范.json`（数据文件，改规范只改数据）。新增类型直接在该文件追加；未命中时本能力如实提示去补，不静默返回空数组冒充「无规范」。

**验证状态**：已纳入验证场景：开工编排.任务类型规范注入（装配）
