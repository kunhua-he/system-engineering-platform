## 返回结构

```json
{
  "成功": true,
  "值": {
    "模块目录": "/项目根/模块库/示例模块",
    "测试骨架": "/项目根/测试中心/模块库/测试_示例模块.py",
    "目标相对目录": "模块库/示例模块",
    "文件清单": ["模块库/示例模块/__init__.py", "模块库/示例模块/包声明.json", "……"],
    "文件数": 11
  },
  "错误码": "",
  "错误说明": ""

```

- `文件清单` 为相对 `项目根` 的稳定路径列表（生成器产出的模块包文件 + 测试骨架），生成后由 `文件系统支持库.文件操作.搜索文件` 真实遍历得到，不是拼装出来的预测值；
- `文件数` = `文件清单` 长度（含测试骨架）。

## 与 MCP 工具 `generate_module_template` 的关系

同一件事只有一个权威实现：模板文本仍由 `开发工具/组件规范/模块模板生成器` 产出，本能力是它的**唯一正规调用入口**（含路径边界校验、统一结果与验证场景）。
MCP 工具侧应改为调用 `调用能力(组件生成.生成模块脚手架, 参数)`，不再直接 import 生成器形成第二条腿。

## 使用步骤（生成之后必须做的四件事）

1. 填实现：`模块库/<模块名>/实现/<模块名>.py` 里把占位替换成真实逻辑（只经 `获取能力调用器().调用能力(...)` 组合支持库能力）；
2. 编译派生物：`开发工具.契约编译.能力定义编译器` 的 `编译能力定义(...)`（**不要用 `-m` 跑**，该模块没有 `__main__`，静默无效）；模板生成的 `验证场景引用.json` 是旧 3 键格式，需按 v1 手写；
3. 重算摘要：`支持库/后端/组件规范支持库` 的 `生成完整性摘要` 能力（父包也要重算）；
4. 验证：`校验能力定义` 0 问题 + `组件合规` 全项通过 + 定向 unittest；正式验收走 HTML 黑盒。

## 错误码与失败语义

| 错误码 | 触发条件 |
| --- | --- |
| 参数不合法 | 项目根/模块名/类型 非文本、能力清单为空或非列表、依赖能力清单非列表 |
| 目录不存在 | 项目根或支持库扫描根不存在（只读探测，不创建任何目录） |
| 路径逃逸 | 目标越出项目根（`..` 跳转、绝对路径、符号链接逃逸），或模块名含路径成分 |
| 已存在 | 模块目录或测试骨架已存在，拒绝覆盖（不部分覆盖、不静默跳过） |
| 类型不合法 / 能力重复 / 参数类型不合法 / 无提供者 | 由唯一生成器校验返回，原样透传 |
| 生成失败 | 生成器抛出未预期异常（本能力不向调用方抛异常） |
| 清单读取失败 | 脚手架已生成但清单读取失败；错误说明里带出模块目录，已写文件不删除 |
| 提供者不可用 | 唯一能力调用器未装配或支持库能力调用失败 |
