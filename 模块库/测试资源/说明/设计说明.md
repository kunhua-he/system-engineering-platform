# 测试资源 设计说明（设计权威）

> 调用口径（能力、参数、返回结构、错误码、调用示例）以同目录 `使用说明.md` 为准；本文只讲**设计**：为什么这样切、管什么、不管什么、失败如何表达。
> 包id：`模块库.测试资源` ｜ 类型：功能模块 ｜ 版本：1.0.1

## 本包是什么

把「测试临时资源的申请与回收」包装成一个**功能模块**：组合路径安全、资源管理、进程管理与文件系统四类公开能力，完成两件事——**申请**（登记 + 写清单）与**回收**（安全释放 + 进程句柄终止 + 失败证据）。

本模块内 **0 起进程、0 发信号、0 直接文件删除**：所有动作一律经 `获取能力调用器().调用能力(...)`（唯一调用入口），不自建执行腿。

## 本包不是什么

- **不是测试框架**：不收集用例、不跑断言、不出报告；它只管「测试用到的临时资源怎么登记、怎么收干净」。
- **不是通用资源管理器**：只服务测试场景，边界绑在 `工程缓存/` 之下，不面向生产数据。
- **不管进程的启动**：子进程由 `系统核心支持库.进程管理.启动进程` 启动并返回受管句柄，本模块只接受这个句柄去登记与终止。
- **不做越界删除**：越界资源在回收时**跳过并记录**，绝不越界删。

## 管什么 / 不管什么

| 管 | 不管 |
|---|---|
| 临时资源登记（文件/目录/子进程/端口/线程/句柄）+ 写清单 | 资源本身的内容与用途 |
| 资源边界校验（必须落在临时根内、临时根必须在 `工程缓存/` 下） | 临时根由谁创建（调用方传参） |
| 回收：安全释放 → 终止受管进程句柄 → 释放句柄 → 留失败证据 | 清理是否该保留（`保留` 参数由调用方决定，保留项计入保留数） |
| 子进程自杀面消除 | 任意第三方 pid 的登记（**只接受受管句柄**） |

## 为什么这样切

**理由一：为什么必须是模块，而不是支持库。**
它做的是**编排**（校验 → 登记 → 备份证据 → 释放），不是单一原子能力。按分层铁律，编排归模块库；四个原子动作分别由已存在的支持库提供，本模块不重复实现其中任何一个。

**理由二：为什么取消「自杀面」是本包的核心设计。**
早期实现直接用 `os.killpg` 回收子进程，存在**误杀自身进程组**的真实风险（测试进程把自己也带走）。现设计把这条路物理删除：

- 子进程只接受 `进程管理.启动进程` 返回的**受管句柄**，不再登记任意第三方 pid；
- 回收走 `进程管理.终止进程`（内部独立进程组 killpg）+ `进程管理.释放句柄`；
- **本模块内不存在 `os.kill` / `killpg` 调用**——不是"小心使用"，而是这个面在物理上不存在。

**理由三：为什么边界一律 fail-closed。**
测试资源最容易出的事故是「清理时删错东西」。因此：

- 临时根必须位于 `工程缓存/` 之下，且不能是 `工程缓存` 自身；
- 资源必须落在临时根内（经 `校验路径` 查符号链接逃逸）；
- 越界不"尽力而为"，而是**拒绝**：临时根越界 → `临时根越界`；资源越界 → `资源越界`。

**理由四：为什么保留「保留数」与「失败表」。**
回收的返回值必须能回答「这次收干净了没有」：`清理数`（真删了多少）、`保留数`（按 `保留` 参数留了多少）、`失败表`（哪些没收掉、为什么）。只报一个"成功"是无法审计的。

## 失败如何表达

统一结果（成功 / 值 / 错误码 / 错误说明）。

| 错误码 | 触发条件 |
|---|---|
| `临时根越界` | 临时根不在 `工程缓存/` 之下，或本身就是 `工程缓存` |
| `资源越界` | 申请的/待回收的资源不在临时根内（含符号链接逃逸） |
| `资源清理失败` | 回收过程有资源未清掉；`详细信息` 携带 `清理数/保留数/失败表/证据路径` |
| `提供者不可用` | 未装配（经 `获取能力调用器()` 抛错转统一失败） |
| `参数不合法` | 必填参数缺失或类型不符 |

**边界外的原则是 fail-closed**：宁可报错停下，也不"尽量删一点"——模糊的成功比明确的失败更危险。

## 生命周期覆盖

- **申请**：登记资源到清单 + 底座临时资源注册表（经 `登记临时资源` 能力），写清单用 `原子写入`，不留半行。
- **子进程**：登记的是**受管句柄**（整数型），不是系统 pid；句柄的生命周期由 `进程管理` 负责。
- **回收**：`安全释放`（经资源管理）→ 逐个终止受管句柄 → `释放句柄` → 写证据（成功与失败都留）。
- **终态**：回收完成后本模块不持有任何句柄；有界资源（线程/队列/句柄）均不跨调用存活。
