## 一、为什么有这个模块（需求来源）

需求id `d8066e8b479f495c`。华哥原话的口径是三件事加一件复用：

> 「符合规范的就落盘，不符合规范的就单独返回不合规范的方式……本地保存一份 md，然后要入库这个小 db 里面，这样子搜索速度比较快，后台单独拉一个线程去处理入库……这里需要加上一个项目登记的功能，这个是后台处理的。」

这四个能力就是本模块的全部对外面：**登记项目 / 写文档 / 查文档 / 查记忆**。

## 二、为什么分两层（支持库 + 模块），而不是一层做掉

| 层 | 管 | 不管 |
|---|---|---|
| `支持库.后端.项目文档支持库` | 切块、按判据校验正文、索引库读写、登记表读写（**原子动作**） | 目录是否存在、规范文件是否就位、写盘权限、入库时机 |
| `模块库.项目文档`（本包） | 边界校验、编排（校验→落盘→入库）、回退搜索、记忆委托 | 不重复实现任何原子动作 |

**为什么这么切**（哲学第 2 条：支持库＝原子，模块＝组合）：把「项目根目录存不存在」塞进支持库，会让这个原子能力带上项目语义，别的调用方（比如纯校验场景）就得多绕一圈；反过来把切块写进模块，会让模块里出现状态机代码、文件行数膨胀。分层的判据是「**这个动作脱离项目上下文还成立吗**」——切块成立，登记成立，但「校验项目根」不成立。

## 三、四个能力的边界与失败口径

### 3.1 登记项目

先校验（项目根存在 → 文档根存在 → 判据文件就位），**再**写登记表。顺序不能反：写进去才发现目录不存在，会让登记表里躺着无法使用的项目，之后所有查文档都会静默查空。

- 项目根不存在 / 文档根不存在 → `目录不存在`（400）。
- 幂等：同项目名覆盖更新，返回 `是否新增=false`；判定不靠记忆、靠登记表主键。

### 3.2 写文档（本模块最核心的一条）

**两段式**：

1. **校验规范（阻断）**：有阻断级违规范条目 → **不落盘**，直接把违规范清单放进失败结果的 `详情` 里返回。判据文件缺失 → `判据文件不存在`（400），**不假装通过**——无判据的「通过」是假绿，会让不合规文档一路落盘。
2. **落盘（同步、必须成功）**：走 `系统核心支持库.资源管理.原子写入`（临时文件 + fsync + rename）。落盘后**再确认目标真实存在**，不看写入返回值就宣布成功。
3. **入库（后台线程）**：非守护、单次执行、30 秒硬超时，完成即退出。

**文件是权威、索引是派生**：入库失败**不回滚**已落盘文件，只登记进待补清单（`<系统临时目录>/项目文档入库/项目文档待补入库.jsonl`）。理由：用户此刻已经拿到文件，入库是可重跑的派生数据；把它绑成事务会让人白等一次 IO，还会出现「文件在磁盘上但调用方被告知失败」这种更难处理的中间态。

**为什么不起常驻线程池**：哲学要求「所有线程、进程、队列必须有界」。常驻池的队列会跨调用存活，谁忘了关就是长期泄漏；单次线程 + 硬超时没有这个口子。

### 3.3 查文档

- 先查索引，命中即返回；**每条带 `可回溯` 标记**（索引记录的文件必须真实存在，否则标 `可回溯=false`，不返回假命中）。
- 索引**未命中时回退**到文档根内的正文正则搜索（`文件系统支持库.内容检索.正则搜索`），`数据来源` 字段如实标注「索引」还是「回退搜索（索引未命中）」。
- 回退也失败时，返回成功 + 空列表 + `回退说明`（写清失败原因），**不把「查不了」伪装成「查无此项」**。

### 3.4 查记忆

**委托** `记忆支持库.搜索记忆`（带 `项目` 过滤），本模块零实现。默认 `仅关键词=真`：结构化查询不付 LLM 代价，与支持库同哲学。

## 四、路径与安全

- 写文档的目标路径必须落在该项目文档根内，经 `系统核心支持库.路径安全.校验路径` 判定（含符号链接逃逸），越界返回 `路径越界`。
- 目标已存在且未声明 `覆盖=真` → `已存在`（409），**不静默覆盖别人的文档**。
- 项目根必须是绝对路径；相对路径直接拒绝（防止以进程当前目录为基准落盘）。
- 本模块 **0 直连第三方、0 直接文件 IO、0 直接 os 调用**：所有原子动作经唯一调用腿。

## 五、错误码

| 错误码 | 何时 |
|---|---|
| `参数不合法` | 必填缺失、正文空白、正文不符合规范（不落盘） |
| `目录不存在` | 项目根 / 文档根不存在 |
| `路径越界` | 文档相对路径越出文档根 |
| `已存在` | 目标文件已存在且未声明覆盖 |
| `判据文件不存在` | 规范判据文件缺失（不假装通过） |
| `项目未登记` | 查文档/写文档时项目不在登记表 |
| `索引库不可用` | SQLite 层失败 |
| `提供者不可用` | 能力调用器未装配 |

## 六、被否决的做法

| 做法 | 否决理由 |
|---|---|
| 入库失败回滚已落盘文件 | 见 3.2：文件是权威、索引是派生 |
| 判据文件缺失时当作「无需校验」放行 | 假绿：不合规文档会一路落盘 |
| 起常驻入库线程池 | 队列跨调用存活＝无界资源；平台要求线程必须有界 |
| 索引未命中就直接返回空 | 会让「没建索引」看起来像「项目里没有这个词」 |
| 本模块自己实现记忆检索 | `记忆支持库` 已有 9 个能力且带项目维度，重造＝第二事实源 |
| 在模块内直连 sqlite3 / open() | 违反统一调用接口铁律；原子动作必须经能力调用器 |
